# workflow-plan-brief — 도식 작업 지시서 작성법

지시서는 두 가지 역할을 동시에 한다: ① 작업자의 유일한 작화 입력 ② 검토자의 정합성 판단 기준(정본). 따라서 "캔버스에 보여야 할 모든 것"이 문구 그대로 들어가야 한다 — 지시서에 없는 것을 작업자가 그리면 결함이고, 지시서에 있는데 캔버스에 없어도 결함이다.

## 작성 절차

1. **스펙 확인**: `research/2026-07-0X-도식스펙-{대상}.md`가 있으면 그것이 1차 입력이다(§1 메인·§2 사이드·§3 근거·§4 미정의). 없으면 워크플로우 md(`research/2026-07-03-워크플로우-요구사항반영-*.md`)에서 직접 추출하되, 근거(REQ/QA/결정 번호)를 지시서 근거 표에 남긴다.
2. **캔버스 현황 조회**: get_figjam으로 기존 섹션 bounds·사이드 코드 사용 현황을 확인한다. 새 섹션 좌표는 `figjam-workflow-diagram` 스킬의 「새 섹션 배치」 절차로 계산한다.
3. **메인/사이드 분할**: 에이전트 정의의 분할 기준(예외 처리 / 저중요·고복잡)을 적용한다. 분할 판단이 애매하면(중요도 판단이 갈릴 때) 리더를 통해 사용자 확인을 요청한다 — 임의 확정 금지.
4. **지시서 작성**: 아래 템플릿. 라벨 한도(아이콘 ≤10자·헥사곤 ≤16자·스티키 ≤12줄)를 지시서 단계에서 맞춘다 — 작업자가 줄이게 두면 문구가 변형된다.

## 지시서 템플릿

```markdown
# 작업 지시서 — {NN}.{도메인명} ({메인|사이드 NN-S-X} / r{개정})
> 근거: {스펙·워크플로우 md 경로} · 작성: workflow-designer · {날짜}

## 1. 섹션·좌표
- 섹션명: `{정확한 섹션 이름}` / 신규 여부 / originX,Y = {값} / 예상 크기
- 그리드: 축 y={값}, 축 중심 간격 {값}, 체인 세로 스텝 {값}
- 클론 소스: Archive {id} · User {id} · Mobile {id} · Desktop {id} · File {id} ·
  Wallet {id} · Server {id} · Database {id} · Email {id} · HEXAGON(검정) {id} ·
  HEXAGON(회색) {id} · OR {id} · STICKY {id} · 사이드참조 DOCUMENT {id}

## 2. 메인 축 시퀀스 (색 규약: 시작=빨강·진행=검정·완료=파랑)
| 순서 | 노드 | 라벨(그대로) | 색/유형 |

## 3. 행위 체인 (작업자별)
| 부모 | 노드 유형 | 라벨(그대로) | 커넥터 색 |

## 4. 분기·조건 헥사곤 (전수)
| 위치(어느 선) | 문구(그대로) | 색(검정=조건/회색=위임) | 비고([가설] 여부) |
※ 분기 규약: 조건 라벨 없는 선 = 공통 수행으로 읽힌다. 조건부인 선에 라벨 누락 = 설계 결함.

## 5. MES 데이터 노트 (전문 그대로, KEY 라인 필수)

## 6. ERP 연계 (Database 위치 + 송수신 조건 헥사곤 문구 — 확정 규칙 위반 금지)

## 7. 미정의 마커·[가설] 지점
| 코드 | 위치 | 라벨 | 근거 미결(무엇을 기다리는가) |

## 8. 사이드 분리 목록 (메인 지시서에만)
| 코드(NN-S-X) | 내용 | 분리 사유(예외/저중요·고복잡) | 별도 지시서 |

## 9. 근거 매핑 (도식에 넣지 않음 — 검토·문서 정합용)
| 요소 | REQ/QA/결정 |
```

## 원칙

- **레인 점유표 (겹침 사전 방어 규칙 1, 지시 확정 2026-07-14)**: 메인 지시서에는 주흐름 축 단계별로 「그 레인이 점유할 x대역」(행위 체인·분기·조건 라벨·태그·경계 요소 포함 **실사용 폭**) 표를 넣고, **다음 축 노드의 x = 이전 레인 실사용 우측 끝 + 60 이상**으로 산정한다. 한 단계의 모든 행위·라벨을 정의한 뒤 다음 단계로 넘어간다 — 고정 그리드를 먼저 박고 라벨을 나중에 끼워 넣는 방식이 겹침의 근본 원인이다(02 회랑 사고). 간격 최소값·헤어핀 금지 수치는 figjam-workflow-diagram 「배치 그리드·간격 규칙」을 따르고, 인라인 라벨은 중점 예상 위치까지 지시서에 병기한다.
- **근거 없는 흐름은 지시하지 않는다.** 스펙·QA에 없는 연결이 "자연스러워 보여도" 미정의 마커로 지시한다. 가설로 그릴 부분은 라벨에 `[가설]`을 붙이게 한다.
- 도식에는 REQ/QA 번호를 넣지 않는다(§9는 지시서 전용).
- 사이드 코드는 기존 사용분(01은 A~I 사용 중)과 충돌 금지 — 조회 후 다음 문자.
- 메인과 사이드는 **별도 지시서**로 나눈다. 작업자가 한 번에 하나의 지시서만 수행하게 하는 것이 증분 검토(메인 검토 통과 후 사이드 착수)의 전제다.
