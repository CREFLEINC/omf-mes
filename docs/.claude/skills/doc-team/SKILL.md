# doc-team — 문서 작성·정합성 검증 오케스트레이터

**실행 모드: 서브 에이전트** (검증 담당자 + 작성 담당자 + 리더=본 세션). 팀(TeamCreate)이 아니라 서브 에이전트를 쓰는 이유: 흐름이 **검증 → (사용자 판단) → 작성**으로 순차이고 중간에 사람 게이트가 끼며, 두 역할이 **다른 모델**(검증 Opus 4.8 / 작성 Sonnet 5)을 쓴다. 동시 작업·실시간 통신이 없으므로 팀 오버헤드가 순손해다.

**공통 지식 베이스**: `.claude/skills/doc-consistency-checklist/SKILL.md` — 문서 지형도·마커 범례·정합성 5단계·확정기록 패턴·버전 규칙·작성 지시서 포맷. 리더와 두 에이전트가 모두 참조한다.

**모델 고정 (사용자 지시 2026-07-15 — 하네스 기본값 "전원 opus"를 사용자가 명시적으로 재정의)**: 검증 담당자 Agent 호출 `model: "opus"`, 작성 담당자 Agent 호출 `model: "sonnet"`.

**경계**: 이 하네스는 **문서(md) 내용의 작성·수정·정합성**을 다룬다. FigJam **캔버스 작화**는 `figjam-workflow-team` 소관이다. (캔버스 변경이 스펙 문서로 파급되는 경우는 그 하네스의 리더가 문서 정합을 처리한다.)

## Phase 0: 요청 유형 판별

1. **모드 판별**:
   - 질문·정리·조회("미결정 정리해줘"·"충돌 없는지 봐줘") → **Flow A(조회)** — 검증 담당자만.
   - 결정·기록·반영("N번을 XXX로 기록해줘"·"이 내용 반영해줘") → **Flow B(게이트-작성)**. 단, **단순 정정·확정**(단일 문서 1~2곳·신규 엔티티/규칙 없음·파급 없음·확정 뒤집기 아님)은 **경량 경로**(리더 직접 — 아래).
2. **기존 산출물 확인**: `_workspace/doc-team/` 존재 여부. 이전 검증/작성 보고가 있고 사용자가 그에 대한 후속(답변·수정)을 주면 **부분 재실행**(해당 에이전트만 재호출, 회차 `r{n}`). 새 주제면 새 `{run}` 폴더(`{날짜}-{주제}`).
3. **정본 범위 예측**(리더): 결정 성격으로 어느 문서군이 정본인지 가늠(consistency-checklist §1). 검증 담당자에게 시작점 힌트를 준다(강제 아님 — 검증 담당자가 grep으로 실측·확장).

## Flow A — 조회 (검증 담당자만)

1. 검증 담당자를 **조회 모드**로 스폰(`model: "opus"`). 입력: 사용자 질문 + 대상 문서군 힌트.
2. 검증 담당자가 문서 그래프를 읽어 `01_validation_{주제}.md`에 미결정·충돌·상태를 정리, 성격별 구분(고객 회신/현장 확인/내부 설계/사용자 결정).
3. 리더가 결과를 사용자에게 회신. **작성 없음.**

## Flow B — 게이트-작성 (검증 → 사람 게이트 → 작성)

1. **검증(게이트)**: 검증 담당자를 **게이트 모드**로 스폰(`model: "opus"`). 정합성 5단계 → 정합성 판정·추가 질문·(CLEAR면)작성 지시서를 `01_validation_{주제}.md`에 남기고 판정(CLEAR/BLOCK)을 반환.
2. **리더 분기**:
   - **BLOCK**(충돌 또는 추가 질문 있음) → 리더가 사용자에게 **표면화하고 대기**한다. 작성 담당자를 스폰하지 않는다. 사용자 답변이 오면 검증 담당자 재호출(부분 재실행).
   - **CLEAR** → 작성 지시서를 작성 담당자에게 넘긴다. **단, 파급 대상이 3개 문서 이상이거나 기존 확정을 뒤집는 변경이면, 작성 전에 파급 계획을 사용자에게 한 줄 요약·확인**한다(정본 문서에 광범위하게 쓰는 것은 되돌리기 어려운 행위). 단순 1~2곳 추가 기록은 바로 진행.
3. **작성**: 작성 담당자를 스폰(`model: "sonnet"`). 입력: 작성 지시서 경로. 작성 담당자가 지시서대로 편집(버전·변경 이력·집계·파급 전건 포함) → `02_write_report_{주제}.md`.
4. **리더 스팟체크**: 리더가 작성 결과의 핵심 편집이 실제 반영됐는지 표본 확인(잔존 구 서술 grep·버전/집계 정합). 앵커 불일치·누락이 있으면 작성 담당자 재호출.
5. **종료**: 최종 결과를 사용자에게 보고(반영 파일·버전·파급 요약).

## 경량 경로 — 단순 정정·확정 (리더 직접 + 자가 검증)

> 도입 근거: 2026-07-16 첫 후속(용어 "확인 불량=현장 발견" 확정)이 단일 문서 1곳 수정이라 검증·작성 2에이전트 스폰이 과잉이었다. FigJam 하네스의 경량 경로(리더 직접 + 검토 1회)와 동형 — 소규모 수정에 3왕복은 낭비다.

**조건 (전부 충족 시만)**: 단일 문서 1~2곳 · 신규 엔티티/규칙 없음 · 기존 확정 뒤집기 아님 · **파급 없음(grep으로 실측 확인)**. 예: 용어 통일·가정→확정 플래그 전환·오타·상태 표기 정정·변경 이력 보강.

**처리 (리더 직접)**: (a) grep으로 스코프·무충돌·무파급 확인 → (b) 편집(버전 bump·변경 이력 포함) → (c) 편집 후 grep 자가 검증. **검증 담당자·작성 담당자 스폰 생략.**

**에스컬레이션**: 스코프 확인(a) 중 파급 대상·충돌·추가 질문이 하나라도 나오면 **즉시 표준 Flow B(검증 담당자 게이트)로 전환**한다. 경량은 "이미 명백히 무충돌·무파급"일 때만 — 애매하면 Flow B.

**불변**: 경량이어도 버전·변경 이력·자가 검증(consistency-checklist §5)은 생략하지 않는다. 리더가 직접 쓰되 검증의 대체가 아니라 축약임을 잊지 않는다.

## 데이터 흐름 (파일 기반 정본)

```
_workspace/doc-team/{run}/
├── 01_validation_{주제}.md      검증 담당자 → 리더/작성 담당자 (판정·작성 지시서)
└── 02_write_report_{주제}.md    작성 담당자 → 리더 (작성 결과·반영 확인)
```
`{run}` = `{날짜}-{주제}`. 최종 메시지는 잘릴 수 있으므로 **파일이 정본**이다. `_workspace/`는 보존한다(감사 추적).

## 불변 원칙

- **검증이 작성보다 먼저.** 작성 담당자는 검증 담당자의 CLEAR 판정 + 작성 지시서 없이는 문서를 고치지 않는다.
- **검증 담당자는 읽기 전용**(문서 미수정), **작성 담당자는 지시서 밖 무작성**. 이 분리가 정합성 보증의 핵심이다.
- **리더 스팟체크**로 최종 확인 — 에이전트 최종 메시지만 믿지 않고 파일·grep으로 실측.

## 에러 핸들링

| 상황 | 처리 |
| --- | --- |
| 정본 문서 불명확 | 검증 담당자가 짐작 금지 → 리더 경유 사용자 확인 |
| 결정 근거(확정기록) 부재 | 검증 판정에 "확정기록 신설 선행"을 명시, 작성 전 사용자에 표면화 |
| 작성 지시서 앵커 불일치 | 작성 담당자 멈춤·보고 → 리더가 검증 담당자에 반려(문서가 바뀌었으면 재검증) |
| 에이전트 응답 없음 | 리더가 해당 역할을 포그라운드 서브 에이전트로 폴백(같은 정의·같은 파일 프로토콜) |
| 상충 데이터 발견 | 삭제하지 않고 출처 병기·`(기존 서술 폐기)`로 흔적 남김 |

## 테스트 시나리오

1. **정상 흐름(조회)**: "현재 PQC 미결정 사항 정리해줘" → Flow A → 검증 담당자가 문서 그래프 읽고 미결 성격별 정리 → 리더 회신. 작성 없음.
2. **정상 흐름(게이트-작성)**: "미결 3번을 '샘플 검사 % 설정'으로 기록해줘" → 검증 게이트 → CLEAR + 작성 지시서(개념데이터모델·WF03·확정기록) → 파급 3문서라 리더가 계획 확인 → 작성 담당자 반영 → 스팟체크 → 보고.
3. **에러 흐름(BLOCK)**: "생산LOT에 불량도 담기게 기록해줘" → 검증 게이트가 기존 확정("생산LOT=양품만", 2026-07-15)과 충돌 + `(기존 서술 폐기)` 대상임을 표면화 → BLOCK → 리더가 사용자에게 "이 결정은 기존 확정을 뒤집습니다" 확인 요청 → 작성 보류.
4. **경량 흐름(단순 확정)**: "'확인 불량'은 '현장 발견'과 같은 거야" → 리더 grep(해당 용어 단일 문서 1곳·파급 없음 확인) → 경량 경로 직접 편집(가정→확정·버전 bump·변경 이력) → grep 자가 검증 → 보고. 에이전트 스폰 없음. (grep에서 다른 문서 파급이 나왔으면 Flow B로 에스컬레이션.)
