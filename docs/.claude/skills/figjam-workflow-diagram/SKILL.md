# figjam-workflow-diagram — omf-mes 시스템 워크플로우 도식 제작

## 무엇인가 / 핵심 원칙

omf-mes 기획의 도메인별 업무 흐름을 **고객사(삼진엘앤디 비나) 최종 협의용** FigJam 도식으로 만든다. 6개 도메인: 01 자재창고 · 02 생산실행 · 03 품질관리 · 04 제품출하 · 05 설비툴 · (06 기준정보=미착수).

**핵심 원칙 3개 (전 도메인 불변):**
1. **근거 있는 것만 그린다.** 요구사항 명세서(REQ)·QA 확정기록·설계결정서에 근거가 있는 요소만 도식화. 근거 없는 지점은 그리지 말고 **미정의 마커(빨간 Email)**로 표시.
2. **근거 마커는 도식에 넣지 않는다.** REQ/QA/결정 번호는 스펙 문서 §3에만. 도식은 고객 협의용이라 깨끗하게.
3. **영역 분리.** 각 도식은 자기 도메인 안에서 끝낸다. 경계(다른 도메인 소관)는 그리지 말고 **경계 헥사곤으로 위임**("→ NN 도식"). 한 도메인 = 메인 구조도 + 사이드 구조도(복잡 예외).

## 새 섹션 배치 (GAP 방지 — 반드시 이 절차)

새 도메인 섹션을 캔버스 어디에 둘지는 **기존 섹션 bounds를 조회해 결정**한다(고정 원점 없음). 절차:

```js
// 기존 섹션들 조회 → 가장 아래 섹션 밑에 여유 두고 배치
const secs = figma.currentPage.children.filter(n=>n.type==='SECTION');
const info = secs.map(s=>({name:s.name, x:Math.round(s.x), y:Math.round(s.y), bottom:Math.round(s.y+s.height)}));
const lowest = Math.max(...secs.map(s=>s.y+s.height));
const originX = -1730, originY = lowest + 200;   // 기존 섹션들과 x 정렬, 아래로 200 간격
```

- 현재 섹션(2026-07 기준): `01.자재창고관리`(x=-1730,y=64) · `00.범례`(x=560,y=64) · `02.생산실행`(x=-1730,y=1900) · `02.생산실행-사이드`(x=-1730,y=4700). 도메인 메인은 x=-1730 열에 세로로 쌓고, 각 사이드는 그 메인 아래.
- **오케스트레이터가 이 originX/originY와 그리드(축 y=430·중심 간격 260·체인 세로 스텝 190)를 계산해 실행 브리프에 넣어준다** — 실행 에이전트가 좌표를 헤매지 않도록.

## 도식 문법 (범례 섹션과 일치)

- **가로 메인 축**: 상태 박스(Archive)와 작업자(User)를 교대 배열. **색: 시작=빨강 · 진행 중=검정 · 완료=파랑**(상태 박스 색은 아이콘 변형). 작업자는 "N. 역할".
- **행위 체인**: 각 작업자 아래로 세로 전개. 노드 유형 = Mobile(스캔/입력) · Desktop(화면) · File(문서·기록) · Wallet(목록 선택) · User(수동 확인).
- **MES 데이터 노트**: 행위 체인 끝 Server 아이콘 + 초록 스티키. 형식: `제목` + `KEY - <레코드 식별자>` + 기록 항목 목록 + `상태 : <값>`. **KEY 라인 필수.**
- **ERP 연계**: Database 아이콘 + 송수신 **조건 헥사곤**(예: "합격품 한정, G/R 송신"). 확정 규칙 위반 금지(예: 검사 결과는 ERP 비연계 → 화살표 그리지 말 것).
- **분기/조건**: 검정 헥사곤 라벨을 화살표 위에. 검증/합류 = OR(⊕) 노드.
- **미정의**: 빨간 Email + "미정의" + 라벨(예: "(U9) 자재 조달 경로"). 근거 없는 지점 전용.
- **경계 위임**: 회색 경계 헥사곤 "→ NN 도식"으로 다른 도메인에 넘긴다(그 흐름을 직접 그리지 않음).
- **커넥터**: `figma.createConnector()`, strokeWeight=4, `connectorLineType='ELBOWED'`, `connectorStart/End={endpointNodeId:id, magnet:'AUTO'}`. **색**: 검정 `{r:.117,g:.117,b:.117}`=주 흐름 / 회색 `{r:.702,g:.702,b:.702}`=대안·생략·회귀·위임 / 초록 `{r:.243,g:.608,b:.294}`=행위 체인·데이터 / 빨강 `{r:.741,g:.161,b:.082}`=시작.
- **배치 그리드(01·02 리듬)**: 새 도메인은 `figma.createSection()`으로 섹션 신설, 기존 섹션과 겹치지 않는 좌표(예: 아래로 y+간격). 축 아이콘 중심 간격 ~240–260px, 행위 체인 세로 스텝 ~180–190px. 노드·스티키 겹침 0.

## 작업 규칙 (스펙·도식 공통)

- **메인 vs 사이드**: 주 흐름·주요 데이터는 메인. 복잡 예외(반복·분기 많음·오독 위험)는 사이드 구조도로 분리하고 메인엔 진입 헥사곤만.
- **미정의 우선**: 애매하면 창작하지 말고 미정의 마커 + 스펙 §4에 등재 + (필요 시) QA 확정기록 §4 협의 대기에 질문으로 기록.
- **문서 정합**: 도식을 바꾸면 해당 스펙 문서(§1~§4)·필요 시 QA 확정기록을 같이 갱신(버전·변경 이력 포함).
- **라벨 길이**: 아이콘 라벨 ≤10자 · 헥사곤 ≤16자 · 스티키 ≤12줄. 한국어.
- **한도**: 메인 축 상태+작업자 ≤12, 행위 노드 총 ≤30. 초과 시 사이드로.

## 파이프라인 (계획 → 실행 → 검증 → 수정, 전부 별도 에이전트)

새 도메인 도식 1건 = 아래 순서. **각 단계는 포그라운드 에이전트**(백그라운드 워크플로우는 Figma 플러그인 연결 불안정). 브리프 전문은 `references/delegation-templates.md` 참조. **각 에이전트 단계 뒤에는 오케스트레이터의 「직접 조회 검증」이 반드시 낀다**(에이전트 최종 메시지는 잘려 오므로 믿지 말 것 — 함정 참조).

0. **오케스트레이터 준비**: 프리플라이트 → 스펙 Read로 이 도메인의 사이드 유무·경계 정책 파악 → 「새 섹션 배치」로 originX/originY 계산 → 클론 킷·그리드·좌표를 실행 브리프에 채워 넣기.
1. **스펙 (계획 에이전트)**: 근거 문서에서 도식 제작 스펙 작성 → `research/2026-07-06-도식스펙-0N-*.md`. (02~05는 이미 있으므로 **스펙 있으면 이 단계 스킵**.)
2. **작화 (실행 에이전트, 메인·사이드 각각)**: 스펙대로 섹션 생성. **먼저 §1 메인** 1회 → 오케스트레이터 조회 검증 → **스펙 §2에 사이드가 있으면** 별도 1회로 사이드(§2 없으면 메인만). 클론 킷·그리드·증분 빌드+자가 스크린샷.
3. **검증 (검증 에이전트)**: 캔버스와 스펙 전수 대조 → PASS/FAIL + 결함 목록(심각도별·노드 ID·수정 지시). 겹침·오연결·금지 규칙 위반·문구 불일치.
4. **수정**: 결함이 **1~2건 소규모·노드 ID 명확이면 오케스트레이터 직접**, **다건·구조 변경이면 수정 에이전트** → 재검증(PASS까지).
5. **문서 정합·상태 갱신 (오케스트레이터만)**: 도식이 스펙과 달라졌으면 스펙 §1~§4·필요 시 QA 확정기록 §4 갱신(버전·변경 이력). 미정의 마커 신설 시 스펙 §4 + QA 협의 대기 등재. **이 스킬의 진행 상태 표(위)를 ✅로 갱신.** (에이전트는 repo 문서를 못 건드리므로 정합은 항상 오케스트레이터 몫.)

## 함정 (반드시 알고 시작)

- **에이전트 최종 메시지 잘림**: 실행/검증 에이전트가 작업은 잘 하지만 최종 보고가 "Complete."로 잘려 옴. → 결과를 `use_figma` 직접 조회(노드 수·라벨·좌표)로 검증하라. 필요 시 트랜스크립트 JSONL에서 마지막 text 블록만 추출(전체 read 금지 — 컨텍스트 오버플로).
- **커넥터 바운딩박스 오보고**: FigJam 커넥터의 `.height`가 5000+로 잘못 보고됨. 섹션 높이 자동 맞춤 시 `k.y+k.height`에서 `type==='CONNECTOR'` 제외하고 계산할 것. 실제 렌더는 정상.
- **폰트 미로드 오류**: 스티키·헥사곤·인스턴스 라벨 텍스트 변경 전 `getStyledTextSegments(['fontName'])`로 현재 폰트 로드. `Cannot write to node with unloaded font` 방지.
- **clone-not-draw**: 절대 새 도형을 그리지 말 것. 기존 인스턴스 clone만. 스타일 통일의 유일한 보증.
- **증분 빌드**: `use_figma` 1콜당 논리 연산 ≤10. 축 → 체인 → 노트 → 헥사곤/커넥터 순으로 나눠 짓고 각 단계 스크린샷 확인.
- **스크린샷 판독**: `get_screenshot`은 URL+curl 반환. 다운로드 후 필요 영역만 crop(PIL)해 읽으면 토큰 절약. 커넥터 오보고 때문에 섹션 스크린샷이 세로로 크게 잡히면 콘텐츠 밴드만 crop.

## 흔한 실수

- 근거 없는 흐름을 "그럴듯해서" 그림 → 미정의 마커로.
- 다른 도메인 흐름을 도식에 직접 그림 → 경계 헥사곤으로 위임.
- 도식에 REQ/QA 번호 표기 → 스펙 §3에만.
- 상태 색 규약 무시 → 시작 빨강 / 완료 파랑 반드시.
- 에이전트 "완료" 보고를 믿고 검증 생략 → 직접 조회 검증 필수.
