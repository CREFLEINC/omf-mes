# workflow-review-checklist — 도식 검토 방법

판정은 **좌표 데이터(get_figjam)가 정본**이고 스크린샷은 보조다. 스크린샷은 축소 렌더에서 겹침·오연결을 숨기고, 커넥터 바운딩박스는 오보고된다 — 눈으로만 PASS를 주지 마라.

## 검토 절차

1. 입력 로드: 설계자 지시서 + 작업자 보고(노드 ID 맵) + `00.범례` 정의.
2. get_figjam으로 대상 섹션 전체 덤프를 받는다 (노드 유형·라벨·좌표·커넥터 연결).
3. 아래 3항목을 순서대로 검증한다. **3) 정합성이 최우선** — 겹침이 없어도 흐름이 지시와 다르면 FAIL이다.
4. 스크린샷 1장으로 육안 교차 확인(색·라벨 렌더·전체 인상).
5. 보고서를 쓰고 drawer에 전달한다.

## 1) 컴포넌트 겹침 (기준: 조건 헥사곤 외 겹침 0)

- **허용되는 겹침은 단 하나**: 플로우 라인(커넥터) 위에 얹힌 행위 조건 표시(조건 헥사곤). 그 외 노드·스티키·텍스트·도형 간 바운딩박스 교차는 전부 결함이다.
- 판정 방법: 덤프의 x,y,width,height로 쌍별 교차를 계산한다. **CONNECTOR는 계산에서 제외**(bbox 오보고). 스티키 높이는 소수점 포함 실값 사용.
- 커넥터 경로가 무관한 노드를 관통해 **다른 흐름으로 오독되는 배선**(예: A→C 선이 B 헥사곤을 가로질러 A→B→C처럼 보임)도 겹침 결함으로 잡는다 — 스크린샷에서 확인.
- **최소 간격 검증 (2026-07-14)**: 겹침 0에 더해 간격 하한을 확인한다 — 노드 가장자리 간 **≥40px** · 도형↔라벨/캡션 **≥16px** · 인라인 라벨이 얹힐 직선 구간 **≥ 라벨 폭+40px**. 미달은 m(겹침 유발이 임박한 밀집이면 M).
- **헤어핀 판정 (2026-07-14)**: 커넥터가 두 노드 간 최단 맨해튼 거리의 ~2배를 넘는 우회·되감기 경로를 그리면 결함(M). API가 라우팅 경로를 노출하지 않으므로 **crop 스크린샷 육안으로 판정**하고, 수정 지시는 간격 확장을 우선한다(자석 조정은 차선).

## 2) 범례 일치성

- 사용된 모든 아이콘·도형·색이 `00.범례`에 정의된 의미대로 쓰였는가 (시작=빨강/진행=검정/완료=파랑, 커넥터 검정=주 흐름/회색=대안·위임/초록=행위·데이터/빨강=시작).
- 분기 규약: **조건 라벨 없는 선 = 조건 무관 공통 수행**으로 읽힌다. 조건부여야 하는 선에 검정 조건 헥사곤이 없으면 결함(확정 규칙과 모순되게 읽히는 경우 심각도 C).
- 사이드 참조(빨간 테두리 문서 + NN-S-X 코드), 미정의(빨간 Email), `[가설]` 표기가 범례 용법과 일치하는가.
- 범례에 없는 새 표기가 등장하면 결함 — 표기를 없애거나 범례 등재를 요구한다.
- **텍스트 렌더 클리핑 검사**: 신규 생성 도형뿐 아니라 **텍스트가 갱신된 기존 도형(재코딩 헥사곤·태그·라벨 포함) 전부**에 대해 격리 스크린샷으로 문구 전문 렌더(말줄임 「…」 없음)를 확인한다. 고정폭 도형에 긴 문구를 넣으면 characters는 정상이어도 렌더가 잘린다 — 좌표 덤프로는 안 잡히는 결함이다. (근거: 2026-07-14 02 마이그레이션에서 신규 태그 3건 + 재코딩 헥사곤 1건이 같은 유형으로 클리핑 — 후자는 태그 한정 검사라 누락됨.)

## 3) 지시 정합성 (최우선)

지시서 §2~§8과 캔버스를 **전수 대조**한다. 표로 남긴다:

| 지시서 항목 | 캔버스 노드 ID | 판정(일치/문구불일치/누락/무근거추가/오연결) |

- 라벨·헥사곤 문구·데이터 노트 전문은 **글자 단위**로 비교한다(조사 하나 달라도 문구불일치).
- 커넥터 연결(start→end)이 지시서의 흐름 방향과 일치하는가.
- 지시서에 없는 노드가 캔버스에 있으면 "무근거 추가" — 작업자 창작은 심각도 C.
- KEY 라인 없는 데이터 노트, 미정의/[가설] 표기 누락도 여기서 잡는다.

## 보고 포맷 (`03_review_{대상}_r{회차}.md`)

```markdown
# 검토 보고 — {대상} r{회차} · 판정: PASS | FAIL
> 지시서: {경로} · 검토 방법: get_figjam 덤프 + 스크린샷

## 결함 목록 (FAIL 시)
| # | 심각도 | 항목(겹침/범례/정합) | 노드 ID | 내용 | 수정 지시 |
심각도: C(치명 — 오독·확정 규칙 위반·무근거 추가) / M(중 — 문구·색 불일치) / m(경 — 간격·정렬)

## 이전 회차 결함 해소 확인 (r2 이상)
| 이전 # | 해소 여부 |

## 정합 대조표 (§3 전수 대조 결과 첨부)
```

- C·M 결함이 하나라도 있으면 FAIL. m만 남으면 PASS(비고에 명시).
- 설계 결함(지시서 자체 오류)은 drawer가 아니라 **designer에게 이관**하고 보고서에 구분 표기한다.
- 같은 결함이 2회차에도 남으면 리더에 에스컬레이션.
