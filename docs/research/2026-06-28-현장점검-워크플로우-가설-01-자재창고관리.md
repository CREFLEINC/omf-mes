## 0. 사용법 · 범위 · 발견 방법

**이 문서의 위상**: 사전 정의 = *커버리지 체크리스트 + 현행 가설*. 현장에서 채우는 틀이 아니라 **반증할 가설**이다. 각 단계의 Medium·Pain은 전형적 제조 SME(종이·엑셀·레거시) 기준 추정이며, **UNIMES 제안서(벤더 To-Be)를 기준으로 삼지 않는다** — 단계 목록만 데이터모델에서 빌려오고, *현행이 실제 어떻게 도느냐*는 개방형으로 듣는다.

**범위(IN)**: 자재(원자재·부자재·외주품) 창고의 입고~보관~불출 사이클 — 발주 수신 · 입하 · 수입검사 · 입고(자재LOT 발행·적치) · 재고 보관 · 출고(생산 투입) · 재고이동 · 재고실사 · 반품(공급사) · 폐기.
**범위(OUT, 별도 워크플로우)**: 제품 출하·Picking&Packing·생산 실적·작업지시(W/O)·품질 검사 *내부 절차*. (단 경계로 맞닿는 지점은 🔗로 표시)

**발견 방법(현장)**: ① 1건 추적(실제 입하 1건을 입고→적치→출고까지 따라가기) ② 관찰(말이 아니라 실제 동작) ③ 실물·데이터 수집(거래명세서·재고대장 엑셀·라벨 실물·화면 캡처·DB 스키마+덤프). 각 단계 끝 **[Check(확인)]** 에 관찰·수집·질문 포인트.

**워크플로우 개요(가설)**
```
[ERP 발주(P/O)] ─수신→ S1
 공급사 납품 ─도착→ S2 입하  →  S3 수입검사(IQC) ─합격→ S4 입고(자재LOT·바코드) → S5 적치
                                   └불합격→ S10 반품(공급사)
 S4/S5 ─→ S6 재고 보관(가용/Hold)
   ├─ 작업지시 발 → S7 출고(생산 투입) ──→ [생산]
   ├─ → S8 재고이동(창고·Location 간)
   ├─ 주기 → S9 재고실사 → 차이 조정 → [ERP]
   └─ 불량·만료·손상 → S11 폐기(Scrap) ⚠갭
```

## S1. 발주 정보 수신 / 입하 예정 인지

- **Trigger(촉발)**: ERP에서 P/O(구매발주) 발행 / 공급사 납기 임박.
- **Actor(주체)**: 전산(ERP 연계)담당 · 물류(창고)담당.
- **Action(행위)**: 입하 예정(품목·수량·납기·공급사)을 파악·공유.
- **Input(입력)**: P/O(ERP), 발주잔량.
- **Medium(매체)** 🟡: *가설* — ERP 화면 조회 후 **엑셀/종이로 입하예정표 수기 작성** 또는 구두 공유. (열림↔갇힘: ERP는 시스템이나, 창고로의 전달이 엑셀·구두면 끊김)
- **Result(결과)**: 입하 예정 인지(상태변화 없음, 정보 전달).
- **Rule(선행조건·규칙)**: P/O 존재. P/O는 ERP 발행·MES 수신본(수정 불가) — ⚠ **D10**(P/O 소유 경계).
- **Exception(예외·선행조건 미충족)** 🟠: 예정에 없는 **무발주 도착**(긴급·샘플·무상 대체품)을 어떻게 *인지*하나(예정표에 없어 누락 위험). [확인] 무발주 도착 인지 경로·빈도.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 입하예정이 시스템에 안 떠서 공급사 도착을 *그때그때* 안다 / 발주잔량 추적 수기.
- **Boundary(경계)** 🔗: **ERP → 창고**. P/O는 ERP 정본. (지시 계층 = ERP)
- **Open-Issue(연계 미결)**: ⚠ D10(P/O 수신본 여부) · D18(ERP 연계 통신방식).
- **[Check(확인)]**: P/O를 창고가 *어디서* 보나(ERP 직접? 엑셀 사본?). 입하예정표 실물 수집. 발주잔량 어떻게 관리하나.

## S2. 입하 (공급사 도착 등록)

- **Trigger(촉발)**: 공급사 차량 도착 · 납품.
- **Actor(주체)**: 물류(창고)담당 (+공급사 기사).
- **Action(행위)**: 도착 등록, 납품수량·품목 1차 확인, 입하유형(자재/외주품/상품) 구분.
- **Input(입력)**: 공급사 거래명세서·납품서, P/O(대조용), 실물 자재.
- **Medium(매체)** 🟡: *가설* — **종이 거래명세서 수령 → 엑셀 입하대장 수기 입력** (체인). 바코드 스캔 여부 불명.
- **Result(결과)**: 입하 No 발생(?), 입하 등록. **상태변화**: '입하 대기' 재고는 아직 아님(수입검사 전).
- **Rule(선행조건·규칙)**: P/O 대비 수량 check. 외주품은 *제품입고 시점* 검사로 분기(⚠ 수입검사 외주품 분기).
- **Exception(예외·선행조건 미충족)** 🟠: ① **P/O 조회 안 됨/미연계**(ERP엔 있으나 창고 미수신·타이밍 갭) ② **불일치**(품목 상이·미등록 품목·수량 초과/부족·분할납품) ③ 거래명세서 누락. → **차단 vs 가입고(provisional) 후 사후 정합**? 승인 주체? 🔗 무발주=ERP 상위지시 없이 MES 입하 단독 → **3계층 nullable 상위지시 검증**. [확인] P/O 없을 때 실제 처리(반송/가입고/수기), 무발주 빈도·사유, 사후 ERP 매칭.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 거래명세서 종이 보관, 입하↔P/O 수량차 수기 대조, 외주/상품/자재 처리 경로가 담당자 경험에 의존.
- **Boundary(경계)** 🔗: **공급사 → 창고**. 입하 No 발번 주체? — ⚠ **B8**(입하 발번: 지시=ERP P/O / 작업지시=MES 입하 / 전표=후속 G/R).
- **Open-Issue(연계 미결)**: ⚠ B8(입하 발번) · 수입검사 외주품·상품 분기(데이터모델 C6 미결).
- **[Check(확인)]**: 도착 시 *최초 기록 매체*가 무엇인가(종이/엑셀/시스템). 거래명세서 실물·입하대장 엑셀 수집. 입하 No가 *찍히는지*, 찍힌다면 누가 채번하는지(MES? ERP? 수기?).

## S3. 수입검사 (IQC) 의뢰 / 수행 / 판정

- **Trigger(촉발)**: 입하 등록됨.
- **Actor(주체)**: 품질담당 (+물류담당 동석).
- **Action(행위)**: 샘플 채취 → 검사항목 측정 → 합/불 판정 → 성적서 발행.
- **Input(입력)**: 입하분, **검사기준(검사항목·UCL/LCL/Target)**, 공급사 성적서(Coa/Coc).
- **Medium(매체)** 🟡: *가설* — **종이 검사성적서 / 엑셀 검사대장**. 검사기준이 *어느 시스템*에 있는지 불명(품질 PC 엑셀? 레거시?).
- **Result(결과)**: IQC 합/불 판정, 성적서, 합격수량/불합격수량. **상태변화**: 합격→입고 대상 / 불합격→반품(S10).
- **Rule(선행조건·규칙)**: 검사 합격해야 입고. **IQC 합격이 자재LOT을 '생성'하나, 기존 LOT을 'Release'만 하나** — ⚠ **C4**.
- **Exception(예외·선행조건 미충족)** 🟠: ① **검사기준(검사항목) 미등록**(신규 품목) → 무검사 통과/임시기준? ② **보류·재검**(판정 불가) ③ **특채(조건부 합격)** — 불합격이나 사용 승인: 권한·기록? ④ 계측기 미검교정/고장 ⑤ 공급사 성적서 누락. [확인] 기준 없는 품목 처리, 특채 절차·권한·기록 매체.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 검사 결과 종이→엑셀 이중입력, 검사기준 버전관리 미흡, 성적서 수기 보관.
- **Boundary(경계)** 🔗: **품질 ↔ 물류**(수입검사 소유 C4 vs 입하 분기 C6). 검사 *기준*의 정본(ERP QM/MES/별도 QMS)? — ⚠ **B5**.
- **Open-Issue(연계 미결)**: ⚠ C4(IQC 소유·LOT 생성 vs Release) · B5(검사기준 정본·결과 연계) · B4(검사결과 헤더/라인).
- **[Check(확인)]**: 수입검사를 *품질 화면*에서 하나 *물류 입하 화면*에서 분기하나. 검사기준이 어디 저장되나(실물 확인). 합격 순간 *자재LOT이 새로 생기나*, 아니면 입하 때 이미 LOT이 있고 상태만 바뀌나 — **A1과 직결**.

## S4. 입고 (G/R) — 자재LOT 발행 · 바코드 · 재고 반영

- **Trigger(촉발)**: IQC 합격.
- **Actor(주체)**: 물류(창고)담당.
- **Action(행위)**: 합격품 입고 확정 → **자재LOT 발번** → 바코드/라벨 발행 → 재고 반영.
- **Input(입력)**: 합격 입하분, 입고수량.
- **Medium(매체)** 🟡: *가설* — **레거시/구 ERP 수기 입력 또는 엑셀 재고대장 가산**. 바코드 프린터 유무 불명. (이 단계가 *갇힘↔열림*의 핵심 분기)
- **Result(결과)**: **자재LOT 생성**(키=자재LOT No), 바코드, **재고 증가**(품목+LOT+Location). **상태변화**: 입하분 → 가용 재고(또는 Hold).
- **Rule(선행조건·규칙)**: **자재LOT 발번 주체 = MES vs ERP G/R** — ⚠ **A1**(가장 광범위한 미결). 1회 입고가 복수 LOT으로 갈리나(혼적/분할) — ⚠ **D12**.
- **Exception(예외·선행조건 미충족)** 🟠: ① **IQC 미완료인데 입고 필요**(긴급) → 검사 전 입고/가입고? ② **P/O 없이 입고**(무발주) → 자재LOT·재고·회계 처리? ③ LOT 채번 실패/중복 ④ **분할·혼적 입고**(1입고-다LOT, D12) 실제 흐름 ⑤ 적치 공간 부족. [확인] 검사 전·무발주 입고 허용 여부와 사후 정합, 가입고분 회계.
- **Pain/Wish(문제·요구)** 🟡: *가설* — LOT 채번이 수기/엑셀이라 중복·누락, 바코드 미부착으로 추적 불가, 재고대장 수기 가산 지연.
- **Boundary(경계)** 🔗: **MES ↔ ERP** 최대 충돌 지점. 입고=G/R(회계전표 성격) → 전표=ERP / 자재LOT 발행=MES 정본(우리 모델) but 원본 아키텍처는 ERP 도식 → **A1·B8 동시에 걸림**.
- **Open-Issue(연계 미결)**: ⚠ A1(자재LOT 발번) · B8(입고/G/R 3계층 발번) · D12(1입고-다LOT) · C4(합격→생성 vs Release).
- **[Check(확인)]**: **자재LOT 라벨 실물**과 **발번 화면**(ERP인지 MES인지 레거시인지)을 *같이* 본다(질문지 A1 지정 방식). 1입고가 여러 LOT으로 쪼개지는 실제 사례. 바코드 부착 여부·범위.

## S5. 적치 / 로케이션 배정

- **Trigger(촉발)**: 입고 확정.
- **Actor(주체)**: 물류(창고)담당.
- **Action(행위)**: 자재를 창고/Location/파렛트에 적치, 위치 기록.
- **Input(입력)**: 입고 LOT, 창고/Location 기준정보.
- **Medium(매체)** 🟡: *가설* — **구두/종이 위치표 또는 엑셀**. 창고 배치도 수기. Location 코드 체계 유무 불명.
- **Result(결과)**: **재고-Location 매핑**. **상태변화**: 재고가 특정 위치에 귀속.
- **Rule(선행조건·규칙)**: 창고유형(자재/제품/반제품/상품) 구분. 한 LOT이 여러 Location에 나뉘면 재고 행 다수 — ⚠ **B7**. 파렛트가 상위 묶음인가 — ⚠ **D15**.
- **Exception(예외·선행조건 미충족)** 🟠: ① **Location 미지정/공간 부족** → 임시·바닥 적치? ② **잘못된 창고유형** 적치(자재를 제품창고) ③ 한 파렛트 다LOT 혼적. [확인] 위치 못 정할 때 처리·임시적치 기록 여부.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 위치가 시스템에 없어 담당자 경험에 의존, 재고 찾기 시간↑, Location 표준 없음.
- **Boundary(경계)** 🔗: 창고 내부(시스템 경계 없음). 단 재고 키 구조(품목+LOT+Location vs 재고No)는 모델 결정.
- **Open-Issue(연계 미결)**: ⚠ B7(재고 키·LOT:Location 카디널리티) · D15(파렛트-포장단위 관계).
- **[Check(확인)]**: 재고 조회 화면/대장의 *키 단위*(품목+LOT+Location인지 재고No인지). Location 코드가 실제 있나. 한 LOT 여러 위치 사례. 파렛트 단위 적치 실물.

## S6. 재고 보관 · 상태(가용/Hold) 관리

- **Trigger(촉발)**: 적치 완료 / 상태 변경 사유 발생(검사·홀드·해제).
- **Actor(주체)**: 물류담당 (+품질담당: Hold/Release 판정).
- **Action(행위)**: 재고 현황 유지, 가용/Hold 상태 관리, 유효기간 관리(해당 시).
- **Input(입력)**: 재고 스냅샷, 검사결과/Lot Status.
- **Medium(매체)** 🟡: *가설* — **엑셀 재고대장**(일/주 단위 갱신). 실시간성 없음. Hold 표시는 비고란/색칠.
- **Result(결과)**: 재고 현황(수량·위치·상태). **상태변화**: 가용 ↔ Hold.
- **Rule(선행조건·규칙)**: **Hold/Release 상태를 재고가 직접 보유 vs 품질 Lot Status 참조** — ⚠ **D2**. Hold 이력(1:1 현재 vs 1:N 이력) — ⚠ D2. 가용재고 = Release분.
- **Exception(예외·선행조건 미충족)** 🟠: ① **Hold 전환 사유**(재판정·클레임·리콜) → 절차·권한 ② **유효기간 경과** → 자동 Hold/폐기 대상? ③ **장부-실물 불일치**(실사 외 시점) 발견 처리 ④ **부분 Hold**(수량 일부). [확인] Hold 전환 누가/어떻게, 유효기간 관리, 수시 불일치 처리.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 재고대장과 실물 불일치, 가용/Hold 수기 관리로 오출고 위험, 유효기간 임박 자재 추적 불가.
- **Boundary(경계)** 🔗: **물류 ↔ 품질**(상태 소유). 재고 정본(ERP vs MES) 정합 — B7의 L2 측면.
- **Open-Issue(연계 미결)**: ⚠ D2(Lot Status 위치·이력화) · B7(재고상태 컬럼 보유) · 부분 Hold(수량 일부만 Hold) 여부.
- **[Check(확인)]**: 출고 차단을 *어디서* 판정하나(재고 상태컬럼? 품질 Lot Status 조회?). Hold 이력 남기나. 부분 Hold 사례. 재고대장 갱신 주기·실물 대조 빈도.

## S7. 출고 (생산 투입)

- **Trigger(촉발)**: 작업지시(W/O) 발행 / 생산 출고요청.
- **Actor(주체)**: 물류(창고)담당 (+생산/현장담당).
- **Action(행위)**: 요청 자재 LOT 선택(FEFO/FIFO) → 불출 → 재고 차감 → 생산 투입 인계.
- **Input(입력)**: W/O/출고요청, 대상 자재LOT, BOM 소요량.
- **Medium(매체)** 🟡: *가설* — **종이 출고전표/피킹리스트 또는 엑셀**. LOT 선택은 *구두/경험*(FIFO).
- **Result(결과)**: **재고 감소**, 출고 기록, **genealogy 시작**(어느 자재LOT이 어느 생산에 투입). **상태변화**: 자재 → WIP 투입.
- **Rule(선행조건·규칙)**: **가용(Release)분만 출고**(Hold 차단, D2). LOT 선택 규칙(FEFO/FIFO/지정). [창고제안] 부품출고=Lot번호 Manual 출고.
- **Exception(예외·선행조건 미충족)** 🟠: ① **결품/수량 부족**(재고<소요) → 부족분·대체자재 ② **가용 없음(Hold분만)** → 강제출고/특채 출고 허용? ③ LOT 미지정 출고 ④ **미사용 자재 창고 반납**(역흐름) ⑤ W/O 없는 출고(긴급·샘플). [확인] 결품 처리, Hold 강제출고 여부, 반납 흐름 존재 여부.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 어떤 LOT 나갔는지 기록 부실 → **역추적(genealogy) 끊김**, 선입선출 안 지켜짐, 출고-BOM 소요 대조 수기.
- **Boundary(경계)** 🔗: **창고(C6) → 생산(C2)**. 출고 No 발번? — ⚠ B8. genealogy 시작점(자재LOT) — **A1·A5 직결**.
- **Open-Issue(연계 미결)**: ⚠ A1(자재LOT 소유) · A5(역추적 시작) · B8(출고 발번) · D2(Hold 출고 차단).
- **[Check(확인)]**: 출고 시 *어느 LOT을 꺼냈는지* 기록하나(genealogy 핵심). LOT 선택을 누가/무엇 기준으로. 출고전표 실물. Hold 자재 출고 차단이 실제로 걸리나.

## S8. 재고이동 (창고 · Location · 파렛트 간)

- **Trigger(촉발)**: 재배치 필요 / 생산 라인 인근 이동 / 창고 간 이동.
- **Actor(주체)**: 물류(창고)담당.
- **Action(행위)**: From→To 위치 간 재고 이동, 위치 갱신.
- **Input(입력)**: 대상 LOT/파렛트, From/To Location.
- **Medium(매체)** 🟡: *가설* — **종이 이동증 또는 엑셀**. [창고제안]은 '자재이동 Collecting=이동증(ERP 산출물)'.
- **Result(결과)**: **Location 변경**(수량 불변). 이동 No(?).
- **Rule(선행조건·규칙)**: 이동 단위(LOT/파렛트/포장 중 무엇으로 잠그나) — ⚠ D15. 동일 평가영역 내면 회계전표 없음.
- **Exception(예외·선행조건 미충족)** 🟠: ① 이동 중 분실·손상 ② **이동 후 위치 갱신 누락** ③ **Hold 재고 이동** 허용 여부. [확인] 이동 누락 보정, Hold 이동 정책.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 이동 후 위치 갱신 누락 → 재고 위치 부정확.
- **Boundary(경계)** 🔗: 창고 내/간. 이동증이 **ERP 산출물**일 수 있음(B8·§8.1).
- **Open-Issue(연계 미결)**: ⚠ B8(이동 발번 주체) · D15(이동 단위).
- **[Check(확인)]**: 이동 시 무엇을 발행하나(이동증?). 그게 ERP산출인지 MES인지. 이동 단위(낱개 LOT? 파렛트?).

## S9. 재고실사

- **Trigger(촉발)**: 정기(월/분기) 또는 수시 실사.
- **Actor(주체)**: 물류담당 (+회계/관리).
- **Action(행위)**: 품목·LOT별 실물 카운트 → 장부 대비 차이 산출 → 조정.
- **Input(입력)**: 장부 재고, 실물 카운트.
- **Medium(매체)** 🟡: *가설* — [창고제안] **엑셀 업로드 실사**. 카운트는 종이→엑셀.
- **Result(결과)**: 장부 vs 실사 차이, **재고 조정**. **상태변화**: 재고 수량 보정.
- **Rule(선행조건·규칙)**: 차이 발생 시 조정 → **ERP 연계**(조정 전표). 카운트=실행 / 조정 전표=회계.
- **Exception(예외·선행조건 미충족)** 🟠: ① **실사 중 입출고 발생**(동결 안 됨) → 카운트 왜곡 ② 차이 **원인 미상**·조정 권한·승인 ③ 차이 과다 시 재실사. [확인] 실사 동결 여부, 조정 승인 권한·사유 기록.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 실사 주기 길어 차이 누적, 엑셀 업로드 오류, 조정 사유 추적 미흡.
- **Boundary(경계)** 🔗: 실사 카운트(MES 작업) ↔ **조정 전표(ERP)**. — ⚠ B8(실사 발번), 조정=ERP 전표.
- **Open-Issue(연계 미결)**: ⚠ B8(실사 발번) · 조정의 ERP 연계 방식.
- **[Check(확인)]**: 실사를 *어떻게* 하나(엑셀 업로드?). 차이 조정이 *어디서* 회계 반영되나. 조정 사유 기록하나.

## S10. 반품 (공급사)

- **Trigger(촉발)**: IQC 불합격(S3) / 입고 후 하자 발견.
- **Actor(주체)**: 물류담당 (+품질담당).
- **Action(행위)**: 불합격분 공급사 반품 처리, 잔량반품.
- **Input(입력)**: 불합격 LOT/입하분, 반품수량, 사유.
- **Medium(매체)** 🟡: *가설* — **종이 반품전표/엑셀**.
- **Result(결과)**: 반품 기록, **재고 감소**(또는 애초에 입고 안 됨). 반품 No(?).
- **Rule(선행조건·규칙)**: 반품 3유형(공급사반품/고객반품입고/클레임입고) 중 *공급사반품* — ⚠ D14. 재고 증감 방향 유형별 상이.
- **Exception(예외·선행조건 미충족)** 🟠: ① **공급사 반품 거부** → 폐기(S11) 전환? ② 부분·잔량반품 ③ 반품-입하 연결 추적 실패. [확인] 반품 거부 시 처리, 잔량반품 관리.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 반품-입하 연결 추적 부실, 잔량반품 관리 수기.
- **Boundary(경계)** 🔗: **창고 → 공급사**. 반품=credit memo(회계) → ERP 전표(B8). 
- **Open-Issue(연계 미결)**: ⚠ D14(반품 3유형 재고영향) · B8(반품 발번·credit).
- **[Check(확인)]**: 불합격분이 *입고됐다 빠지나, 아예 입고 전에 반품되나*(재고 영향 시점). 반품전표 실물. ERP credit 연계.

## S11. 폐기 (Scrap/Disposal)  ⚠ 설계 갭

- **Trigger(촉발)**: 불량·유효기간 경과·손상·반품 불가 자재 발생.
- **Actor(주체)**: 물류담당 (+품질담당).
- **Action(행위)**: 폐기 대상 선별 → 처분 → 재고 차감.
- **Input(입력)**: 폐기 대상 LOT/품목, 폐기수량, 사유.
- **Medium(매체)** 🟡: *가설* — **불명**. 종이/엑셀 수기 or *아예 미관리*(재고에 남거나 임의 차감)일 가능성.
- **Result(결과)**: (요구 시) 재고 감소, 폐기 기록, genealogy 종결.
- **Rule(선행조건·규칙)**: **현 모델 미설계** — 반품(외부)·실사조정(차이)·불량(수집)과 별개. 요구 시 C6 신규 트랜잭션.
- **Exception(예외·선행조건 미충족)** 🟠: 폐기 전반이 미설계 — ① **승인 권한**·사유 확정 절차 ② **재고손익(전표)** 처리 ③ 잔재/재활용 분기. (D21) [확인] 폐기 승인 흐름, 손익 반영, 재활용 경로.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 폐기가 시스템에 없어 *재고 부정합*, 폐기손익(재고손익) 누락, 수율 산정 왜곡.
- **Boundary(경계)** 🔗: 폐기손익=ERP 전표. 폐기 작업·사유=MES.
- **Open-Issue(연계 미결)**: ⚠ **D21(신규)** — 폐기 요구 유무·처분 방식·재고손익 연계·잔재/재활용. **(고객 확인 대기)**
- **[Check(확인)]**: 불량·만료·손상 자재를 *실제로 어떻게* 처분하나. 재고에서 빼나, 사유 남기나, ERP 손익 반영하나. 잔재/재활용(재투입·부산물) 있나.

## 현장 실행 체크리스트 (자재 창고)

**1건 추적(필수)**: 실제 입하 1건을 골라 S2→S3→S4→S5→(S7)까지 *따라가며* 매체·핸드오프·LOT 흐름 관찰.

**수집물(실물·데이터)**:
- 종이 양식: 거래명세서·입하대장·검사성적서·출고전표·이동증·반품전표
- 엑셀: 입하대장·재고대장·실사 파일
- 라벨 실물: 자재LOT 바코드/라벨
- 화면 캡처: 발번 화면(ERP/MES/레거시)·재고 조회 화면
- **DB 스키마 + 대표 덤프**: 재고·입고·자재LOT 테이블 (B섹션 L3 결론)

**정량 데이터(APS·사이징용)**: 일/월 입하 건수, 품목(SKU) 수, 자재LOT 발생량, 창고·Location 수, 평균 재고 회전, 분할입고 빈도.

**관찰 포인트(말 말고 동작)**: LOT 라벨이 *실제로* 붙는지, 출고 시 *어느 LOT 꺼냈는지 적는지*, Hold 자재가 *정말* 막히는지, 재고대장과 실물이 *맞는지*.

> **핵심 원리**: 예외는 *"선행조건 ↔ 그 조건이 깨질 때"* 의 쌍이다. 정상 흐름의 Rule 하나마다 대응 예외가 최소 1개 있다. 현장에서 *진짜 운영 차이*는 정상 흐름이 아니라 **이 예외 처리에서** 드러난다(가입고·특채·강제출고·수기 우회의 존재 여부).
