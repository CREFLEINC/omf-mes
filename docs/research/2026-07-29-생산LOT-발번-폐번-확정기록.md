## 1 · 배경 — 무엇이 미결이었나

이슈 #42(「생산LOT 러닝체인지 정본 3건」)가 두 가지를 제기했다.

1. **추가 발번·폐번 규칙이 정본에 없다.** 개념모델은 `N = 양품목표 ÷ LOT크기`로 **개수 고정**을 전제하고, 생산LOT 엔티티의 「상태」 필드는 **값 목록 자체가 없다**.
2. **「전/후 분할」 표현이 깨진다.** 추가 발번분은 시간상 뒤인데 BOM은 '전'(구부품)이다.

여기에 **채번 범위**(전역 vs W/O 내 연번)가 정본에 미명시라는 점이 겹쳐 있었다.

## 2 · 확정 결정 사항

### 2-1 · 추가 발번 = 초과 생산 (W/O 일반 규칙)

> **선발행된 LOT을 다 쓰고도 더 생산하면 생산LOT 번호를 추가 발행한다. 이는 러닝체인지와 무관한 모든 W/O의 규칙이다.**

- 러닝체인지가 **없는** W/O도 동일 — 계획보다 많이 생산하면 추가 발번한다.
- 러닝체인지가 **있는** W/O에서 러닝체인지가 하는 일은 **추가분이 어느 BOM에 귀속되는지를 정하는 것뿐**이다. 구부품(기존 BOM)으로 추가 생산하면 추가 LOT의 BOM 스냅샷 = 구BOM.
- **⚠ 추가 발번은 다른 구간의 계획을 줄이지 않는다.** 구부품 추가 발번을 해도 **신부품 선발행분은 전부 그대로 유지**된다. W/O 총량이 **증가**한다(마감결과 = 초과 달성).

```
예) 양품목표 200 · LOT크기 10 → 선발행 20슬롯 (구 1~10 · 신 11~20)
    구부품으로 계획 초과 생산  → 21번 추가 발번 (BOM 스냅샷 = 구BOM)
    신 11~20 은 전부 유지 · 총량 200 → 210 · 마감결과 「초과 달성」
```

> *(기존 서술 폐기 — 이슈 #42 본문 및 2026-07-29 세션 중간 설명: 「러닝체인지 폐번은 W/O 총량은 유지한 채 구BOM↔신BOM **배분만 조정**」. 총량은 유지되지 않는다.)*

### 2-2 · 폐번 = W/O 마감 시점 전용·자동

> **선발행된 LOT 번호 중 W/O 마감 시점에 실적 등록이 없는 것은 자동으로 폐번된다.**

- **시점**: 마감 **전용**. 진행 중 미사용 슬롯을 미리 버리는 절차는 없다.
- **조건**: 실적 등록 여부. 관리자 개별 지정이 아니라 **시스템 자동**.
- **재사용 금지**: 폐번된 번호·순번은 재사용하지 않는다. 추가 발번은 항상 뒤로 이어붙인다.

### 2-3 · 패턴 귀속 — 신규 창작이 아니라 **P3 패턴**의 생산LOT 적용

설계결정서 결정 05가 이미 확정한 **패턴 P3**(사전발행 placeholder → 확정 시 활성 → 미사용·취소분 폐번 기록·**재사용 금지**)와 구조가 동일하다. 자재LOT 라벨·포장라벨에만 명문화돼 있던 것을 생산LOT으로 확장한다.

| P3 단계 | 생산LOT 대응 | 근거 |
| --- | --- | --- |
| 사전발행(placeholder) | **선발행**(W/O 배포 시 · 번호/슬롯 예약 · 완료 전까지 실물 미귀속) | ✓확정 2026-06-24 · ✓확정 2026-07-15 |
| 확정 시 활성 | **실적 등록**(작업실적—생산LOT 1:1) | ✅ A3·B3 |
| 미사용분 폐번·재사용 금지 | **마감 시 실적 없는 슬롯 자동 폐번** | ✓확정 2026-07-29 (본 문서) |

### 2-4 · 생산LOT 「상태」 값 목록 신설

정본에 값 목록이 없던 필드를 P3 3단계로 채운다.

| 값 | 의미 | 전이 |
| --- | --- | --- |
| **대기** | 선발행됨 — 번호/슬롯만 예약, 실물 미귀속 | W/O 배포 시 생성 |
| **활성** | 실적이 등록되어 실물이 귀속됨 | 대기 → 활성 |
| **폐번** | 마감 시 실적 없음 — 재사용 금지 | 대기 → 폐번(마감 자동). **활성 → 폐번 없음** |

### 2-5 · 채번 범위 = 공장 내 유일(전역) + 설정형 규칙 — **하류 정합**

상류 정본에 미명시였으나 **하류 데이터모델이 이미 확정**해 두었다. 상류가 이를 따른다.

| 근거(하류 · 읽기 전용) | 내용 |
| --- | --- |
| `3-2 논리적 모델링.md` | **`UNIQUE(plant_id, lot_no)`** — 공장 내 유일 |
| `mes_erd.md` `lot` 테이블 | `varchar lot_no "UK(공장내 유일)"` |
| `3-2 §22.10 numbering_rule` | 채번규칙 엔티티 — `pattern`·`reset_cycle_code`·`lot_type_code`별 설정 |
| `2-5 LOT 추적성.md` FR-LT-005·006 | LOT 번호 자동 생성(품목군·공장·LOT 유형별 설정형) · 동일 관리범위 내 중복 생성 금지 |

**`lot_no`는 W/O 소속이나 순서를 담지 않는다** — 여러 W/O가 동시 진행되면 한 W/O의 LOT 번호는 띄엄띄엄 잡히고, `reset_cycle_code`로 주기 리셋도 걸린다.

### 2-6 · W/O 내 순번 신설 (A안)

> **생산LOT은 `lot_no`(공장 내 유일)와 별개로 W/O 내 순번을 갖는다.**

- **필요 근거**: 선발행 슬롯의 **구간 지정**. 관리자가 계획 화면에서 「1~10 구부품, 11~20 신부품」을 찍어야 러닝체인지 분할 지정이 성립한다. 리더 지시의 「21번」이라는 표현 자체가 이 순번을 가리킨다.
- 폐번은 마감 시 **실적 없는 것 전부**가 대상이라 개별 지정이 불요하므로, 순번의 근거는 **구간 지정 1개**다.
- 폐번 후에도 순번은 재사용하지 않는다(2-2).
- **⚠ 하류 미보유** — `lot` 테이블에 해당 속성이 없다. **[docs→데이터모델] 이슈로 발행**(§5).

### 2-7 · 「전/후 분할」 표현 정정 → 「BOM 스냅샷별 분할」

**데이터는 무결하다** — BOM 스냅샷이 **LOT 레벨**이라 추가 발번분이 구BOM을 갖는 데 문제가 없고 genealogy도 정상이다. 깨지는 것은 **표현**뿐이다.

| | 폐기 | 채택 |
| --- | --- | --- |
| 표현 | 「생산LOT만 **전/후** 분할」 | 「생산LOT만 **BOM 스냅샷별** 분할」 |
| 이유 | 시간 이분법(교체 전/후)을 전제하는데, 추가 발번분은 **시간상 뒤인데 BOM은 '전'** | 구/신을 정하는 것은 **각 LOT의 BOM 스냅샷**이지 시간·번호 순서가 아니다 |

**부기 원칙**: **LOT 번호 순서 ≠ 시간 순서**. QA #37의 실질(W/O 무분할·LOT만 분할·BOM 스냅샷=LOT 레벨)은 **그대로 유지**되며, 표현만 교체한다.
