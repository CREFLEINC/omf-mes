## 핵심 요약 (TL;DR)

- **MES가 ERP(UNIERP)에서 수신하는 것은 마스터 6종 + 트랜잭션(구매발주·생산오더·수주) + 초기 재고 현황(1회, 가동 시)이다.** 나머지는 대부분 MES 정본(직접 관리)이거나 MES→ERP 역방향 송신이다.
  - **수신 마스터 6종**: 품목 · BOM · 공통코드 · 조직 · 사용자 · 거래처(공급사)  〔🔹2026-07-08: 거래처 추가 · '작업자'→'사용자' 개명〕
  - **수신 지시·트랜잭션**: 구매발주 P/O · **생산오더 P/O** · 수주 정보 · **초기 재고 현황(1회)** · (P/O 변경 이벤트)  〔🔹2026-07-08: '생산계획'은 ERP 대상 아님→생산오더로 한정; 수주·초기재고 요청 추가〕
- **연계 채널**: UNIERP · **DB 중계 테이블(Temp Table)** 방식, 트리거 = Time Schedule(주기) / Event(즉시). (QA #18)
- **취급 규칙**: 수신분은 **원본 필드 읽기 전용**(연계분 수정·삭제 불가), MES 확장 속성만 편집·이력. (QA #34·#35)
- **큰 반전**: 초기 기획(기능분해도)이 "ERP→MES 송신"으로 나열했던 **공정·품질·설비·툴**은 확정 단계에서 전부 ERP 수신에서 빠졌다(대부분 MES 정본). **출하지시도 ERP가 아니라 고객사 엑셀**이다. → §5·§6.

## §2. ERP→MES 수신 — 지시·트랜잭션

기준정보(마스터)가 아닌, 운영 중 ERP가 내려주는 트랜잭션 계열. 모두 ERP 정본·MES 수신·**MES 수정 불가**.  〔🔹2026-07-08: '생산계획 **수립**'은 ERP 대상에서 제외 — ERP 수신은 구매발주·생산오더·수주·재고까지. 생산계획 수립은 MES가 공정(Routing) 기반으로 수행(§5)〕

| 데이터 | 정본 | 수신 트리거 | 포함 필드 | MES가 생성하는 하위 | 무지시(standalone) 예외 | 근거 | 상태 |
|---|---|---|---|---|---|---|---|
| **P/O — 구매발주(자재)** | ERP | ERP P/O 발행 / 납기 임박 | 품목·수량·납기·공급사·발주잔량 | 입하예정 인지 → 입하 등록 | **무발주 도착**(긴급·샘플·무상): MES 입하 단독 생성, 사후 ERP 매칭 [확인] | REQ-PR-0024, QA #23·#29·#36, D10 | ✅확정 |
| **P/O — 생산오더(생산)** 🔹 | ERP | ERP 생산오더 발행 → MES 연계 / 착수 임박 | 오더번호·품목·생산수량·완료예정일·(자재예약) | **W/O 전개(1 오더 → N W/O)** | P/O 없는 긴급생산=긴급 W/O / 시제=개발품 작업계획서(별도) | REQ-PR-0024·0014·0033, QA #35 | ✅확정 · 🔹2026-07-08: '생산계획' 수립은 ERP 대상 아님 → ERP 수신은 **생산오더로 한정**(현행 생산계획은 공정 Routing 이행, §5) |
| **P/O 변경 이벤트** | ERP | 계획 실행 후에도 발생 | 중단 / 수량 변경 | W/O·계획 전파 + 관리자 확인 | **강행 옵션**('변경 반영 vs 기존 유지'), 강행 시 **P/O-W/O 불일치 플래그** | REQ-PR-0024, QA #23·#45(E11) | ✅확정 |
| **수주 정보** 🔹 | ERP | ERP 수주 등록 | 수주번호·고객·품목·수주수량·납기·상태 | 생산·출하를 수주에 연결·추적 | — | 🔹2026-07-08 요청 결정 | 🟡요청(조건부) — 생산오더와 동일 테이블이면 생략 |
| **초기 재고 현황(제품·자재 잔량)** 🔹 | ERP(재고 현황) | **가동 시점 1회** | 품목·창고·현재고수량(잔량)·(LOT/로케이션)·기준일시 | 초기 재고 이관 | — | 🔹2026-07-08 요청 결정 | ✅요청(범위 확정) — **초기 이관 1회·현황(잔량)만**. 정기 대사·상시 수신 제외; 가동 후 변동은 MES 정본→ERP(§7) |

**3계층 발번 골격 (수신의 위치)** — 하나의 물류 사건을 세 계층으로 분리한다:

```
상위 지시 (ERP P/O, nullable)  →  작업지시 (MES W/O, 항상 생성)  →  회계전표 (ERP, 회계발생분만)
      ↑ 수신                          ↑ MES 정본(§5)                  ↑ MES→ERP 송신(§7)
```

- **작업지시(W/O)는 MES 소유**다 — ERP에서 받지 않는다. P/O(생산오더)를 nullable로 참조할 뿐. (§5 참조)
- 회계전표(입고 G/R·출하 PGI·반품 credit·실사 조정전표)는 **ERP 채번** → MES→ERP 송신 방향(§7).

## §3. 연계 아키텍처 — 수신 채널 (✅확정, QA #18)

| 항목 | 내용 |
|---|---|
| ERP 시스템 | **UNIERP** |
| 전달 방식 | **DB 중계 테이블(Temp Table) 방식** — 송신측(ERP) DB 생성 → **MES 수신측 pull** → 중계 테이블 적재 → MES 마스터 반영 |
| 트리거 | **Time Schedule(주기)** / **Event(즉시)** |
| 방향성 | 수신/송신 분리. 송신(MES→ERP)은 **항목별 on/off 선택형**(configurable) — 수신은 목록 고정 |
| 접근 정보 🔹 | Temp Table 접근 권한(IP·Port·ID·PWD·DB명) + 전체 DB 백업본/스키마 제공 여부 = 고객 회신 대기(요청서 시트2, 🔹2026-07-08) |
| 병행 외부 시스템 | **추적관리시스템**(자사(CTO) 개발, OA 사업부 생산·포장·출하 3단계 바코드 이력) **병행 운영+연계** 확정. MES와의 역할·데이터 경계 정의는 CREFLE 설계 과제(⚠️ §8) |

## §4. 수신분 취급 규칙 (✅확정, QA #34·#35)

- **연계 원본 필드 = 읽기 전용**(연계분 MES 수정·삭제 불가). 초기 기획의 "연계분 전체 수정/삭제 불가"에서 **원본 필드 한정**으로 정제됨.
- **MES 확장 속성은 편집 가능 + 변경 이력 필수** — 예: 품목의 개발품 플래그·재생재 하위코드·유효기한 플래그, 공통코드의 다국어(한/베) 명칭.
- **개발품**: ERP에 품목은 존재하나 표식 없음 → MES에서 플래그 지정, ERP 생산실적 전달 제외(QA #35·#57).
- **재생재**: ERP 동기화 제외 + 고객사향 문서·라벨 제외, MES 내부 genealogy는 완전 기록(코드 2단 구조, QA #31·#53).

## §5. ERP에서 '받지 않는' 것 — MES 정본·비연계 (오해 방지, 중요)

초기 기획(기능분해도)과 다르므로 명시한다. **아래는 ERP 수신 대상이 아니다.** 이들 중 현행 자료(엑셀·대장)를 MES 초기 등록용으로 받는 항목은 요청서 시트3에서 별도 요청한다(🔹2026-07-08).

| 항목 | 실제 소유/출처 | 왜 ERP 수신이 아닌가 | 근거 |
|---|---|---|---|
| **공정(Routing)** | **MES 정본** (직접 CRUD·Rev 이력) | ERP에 공정 정보가 없는 경우가 실재 전제로 확인. **생산계획 수립의 기준** 🔹 | QA #74, 결정 07, REQ-PR-0026·0002 |
| **검사기준(검사항목·UCL/LCL/Target)** | **MES 정본** (As-Is 엑셀 → DX) | 정본 미정(B5)이 MES로 종결. ERP QM/별도 QMS 아님 | QA #4, REQ-PR-0027·0025, 결정 12·06 |
| **검사 결과(합·불 수량 포함)** | MES 보유 | **ERP 비연계 확정** — "Lot Status 합·불 수량 ERP 연계" 가정 폐기. ERP엔 생산 실적만 전달 | QA #4·#6 |

| **예비품** | **MES 정본** (별도 마스터, 품목 통합 아님) | — | QA #7 |
| **WorkCalendar · 계측기·계측기이력 · 불량코드/판정유형/손실사유 · 사용자/역할/권한** | **MES 정본** | 전부 MES 관리(계층형·2계층 N:M 등) | 결정 03·06·12, REQ-PR-0015·0027 |

## §7. (참고·대칭) MES→ERP 역방향 송신

수신의 반대 방향 — MES가 ERP로 **보내는** 것. 수신과 혼동을 막기 위해 참고로 둔다. **전부 항목별 on/off 선택형 연계**(QA #6).

| 트랜잭션 | ERP 전표 | 송신 시점·규칙 | 근거 |
|---|---|---|---|
| 생산 실적 | — | 필수, **개발품 제외** | QA #35 |
| 입고 | **G/R** | **IQC 합격 직후 건별** 즉시 연계 | QA #1 |
| 출하 | **PGI** | 출하 후 ERP 반영 | REQ-PR-0030(방향) |
| 반품 | credit memo | 반영 필요·방식 미정(⚠️ §8) | QA #6 |
| 재고실사 | 조정전표 | 차이 조정 → ERP 연계 | — |
| 검사 결과 | — | **비연계** (§5) | QA #4 |

> 🔹2026-07-08: 시트1의 '초기 재고 현황(수신)'과 여기 '입고·출하·실사(송신)'는 방향이 반대다. 재고 정본은 **MES**(가동 후 변동은 MES→ERP 송신)이며, ERP 수신은 **가동 시점 초기 이관 1회·현황(잔량)으로 한정**한다(정기 대사·상시 수신 제외; §2·§8 #10).
