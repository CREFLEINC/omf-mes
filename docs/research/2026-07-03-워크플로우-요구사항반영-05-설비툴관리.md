## 0. 사용법 · 범위 · 발견 방법

**이 문서의 위상**: 2026-07-01 현장 점검(요구사항 명세서 v1.1) 결과를 반영한 재정리본 = *커버리지 체크리스트 + 검증·요구 반영 + 잔존 가설*. 명세서로 확인된 항목은 ✅+REQ 근거로 전환했고, 확인되지 않은 항목은 🟡 가설로 잔존시켜 **여전히 반증할 대상**으로 남긴다. 각 단계의 Medium·Pain 중 미검증분은 전형적 제조 SME(종이 점검표·엑셀 보전대장·계수기 수기) 기준 추정이며, **UNIMES 제안서(벤더 To-Be)에 앵커링하지 않는다** — 단계 목록만 데이터모델/기능분해도에서 빌려오고, *현행이 실제 어떻게 도느냐*는 개방형으로 듣는다.

**핵심 전제 — 점검 ≠ 보전** (✅ 결정문서 §2): **점검 = "괜찮은지 본다(진단)"**, **보전 = "고치거나 미리 정비한다(조치)"**. 점검 NG·누계타발수 초과·고장이 보전을 *트리거*한다. 둘은 다른 트랜잭션이며 데이터 단위·소유가 다르다. 본 문서는 점검(S2·S3)과 보전(S5·S8)을 분리해 다룬다.

**핵심 전제 — MES 경량 보유 결정** (✅ D4 결정, 2026-06-26 — **CTO 문답으로 재확정**, ✓확정 2026-07-04 QA #10): 고객은 **EAM/CMMS 미보유** → 보전 계획·지시를 둘 곳이 MES뿐. 따라서 MES = ① 설비 상태·비가동·점검·고장 **수집** + ② 보전 **트리거** + ③ 생산 **통제** + ④ 경량 보전 **계획/지시/실적**. 단, **비용·원가·자산 감가상각·수명·예비품 발주(구매)·고급 신뢰성 분석(MTBF/MTTR 전용)은 범위 밖**(추후 EAM 도입 시 '지시–작업지시' 패턴으로 이관). "언제·무엇을·누가 정비했나"까지 MES, "얼마·자산·재고 발주"는 범위 밖.

**핵심 전제(신규) — 툴 마스터 정본 = MES** (✅ 충돌③, REQ-PR-0003): 현행은 "ERP 시스템 사용 X : 엑셀로 관리"(REQ-PR-0003 현행 — S1의 엑셀 대장 가설이 툴·지그에 한해 검증됨). 요구는 "금형, 지그를 포함한 **모든 도구**의 정보 관리를 MES에서" + "QR 코드 부착하여 관리(제품 정보 등록 → QR 발급)"(REQ-PR-0003 요구). 따라서 **툴·금형·지그 마스터 = MES 직접 등록·정본, I/F 연계 대상에서 툴 제외, 기존 엑셀 대장은 DX(마이그레이션) 대상**. (기존 가설 폐기: 툴/금형 master는 Legacy/ERP 연계 대상이라는 모델 표기 — 툴에는 성립하지 않음.) 설비(기계) 대장의 매체·연계 여부는 여전히 미검증(🟡 유지).

**요구 공백의 취급 → 해소**: 명세서 47건에 점검(S2·S3)·보전(S5)·예비품(S6)·툴 PM(S8) 요구가 전무했으나, CTO 문답으로 **공백 ≠ 불요 — 경량 보전(점검+고장 수집+보전 계획·지시·실적) 보유 필요 확정**(✓확정 2026-07-04 QA #10). 본 도메인 미결도 일괄 종결: **D3=점검 통제 차단/경고/미적용 설정형(QA #9) · D4=경량 보전 범위 확정(QA #10) · D5=PM 트리거 타발수+주기 겸용 설정형(QA #11) · D6=타발수 작업실적 수동+환산 옵션(QA #12) · C3=별도 예비품 마스터(QA #7)**. B6·D5의 '현행 화면 확인' 소멸→신규 설계 재량 전환(통합분석 §2 충돌③)도 그대로 확정·종결. (기존 서술 폐기: "해당 단계를 가설·미결 그대로 유지… 침묵의 성격 확인은 차기 미팅 안건")

**범위(IN)**: 설비·툴 자산 등록·기준정보(점검·보전 항목·주기·적정타수) → 설비 점검(Daily/Monthly) 계획·수행 → 작업 전 점검 통제(생산 차단) → 고장·비가동 수집 → 설비 보전(경량 계획→지시→실적) → 예비품 사용·출고 → 툴 사용실적 수집(누계타발수) → 툴 PM(MaintenanceOrder→PM실적·자기참조) → 설비/툴 신규입고·폐기(자산 처분).
**범위(OUT, 별도 워크플로우)**: 생산 실적·작업지시(W/O)·4M투입(②생산), 품질 검사·SPC 측정값 *내부 절차*(④품질), 자재/제품 재고·입출고(⑥물류), 보전 **비용·자산 회계·예비품 구매발주·전용 신뢰성 분석**(범위 밖/추후 EAM). 경계로 맞닿는 지점은 🔗로 표시.

**발견 방법(차기 현장·미팅)**: ① 1건 추적 — 실제 설비 1대를 골라 *점검표→작업 전 통제→고장 발생→보전 지시→예비품 출고*까지, 그리고 금형 1세트를 *타발수 수집→누계→PM*까지 따라가기. ② 관찰 — 점검이 *실제로* 작업을 막는지, 타발수가 *실제로* 자동 들어오는지 동작 확인. ③ 실물·데이터 수집 — Daily/Monthly 점검표·보전대장·예비품 출고전표·엑셀 툴 대장(마이그레이션 원천). 각 단계 끝 **[Check(확인)]** 에 관찰·수집·질문 포인트.

## S1. 설비·툴 자산 등록 / 기준정보 설정 (신규 입고 · 점검·보전 항목·주기·적정타수 · QR 발급)

- **Trigger(촉발)**: 신규 설비/금형·지그 도입·입고, 또는 점검·보전 기준 제·개정. (신규) 기존 엑셀 툴 대장의 MES 이관(DX 마이그레이션) — ✅ 충돌③ 파생(REQ-PR-0003).
- **Actor(주체)**: 설비담당 — 툴·금형·지그는 **MES 직접 등록**(✅ REQ-PR-0003 요구). (+전산담당: 설비(기계)의 Legacy 연계 여부는 미확정 — 확인 후 역할 결정.)
- **Action(행위)**: 설비/툴 자산을 마스터에 등록(설비코드/툴코드, 설비그룹, 호기, Set·Cavity), **관리 대상 = 금형·지그를 포함한 모든 도구**(✅ REQ-PR-0003 요구 — 기존 범위 '금형' 중심에서 확대), **점검/보전 항목·주기** 정의, 툴 **사용한도(적정타수)** 설정, **예비품(Spare Part) 지정**, (신규) **툴 등록 시 QR 코드 발급·부착**(✅ REQ-PR-0003 요구 — "제품 정보 등록 → QR 발급").
- **Input(입력)**: 설비/금형·지그 사양서, 제작사 보전 매뉴얼·권장 주기, 적정타수(타발 수명), (신규) 기존 엑셀 툴 대장(마이그레이션 원천 — REQ-PR-0003 현행).
- **Medium(매체)**: 툴(금형·지그) = ✅ **엑셀 관리 · ERP 미사용**(REQ-PR-0003 현행 — 기존 '엑셀 금형대장' 가설이 현장에서 검증됨). ## S4. 설비 고장 · 비가동 발생 수집 (사후보전 트리거)

## S5. 설비 보전 (경량: 계획 → 지시 → 실적)

- **[Check(확인)]**: 예방보전 예정일을 *어디서* 관리하나(시스템? 엑셀 달력?). 보전 '지시'가 별도로 발행되나, 아니면 결과(이력)만 적나(As-Is 참고 — D4는 종결(QA #10 2026-07-04), 계획→지시→이력 구조는 내부 설계). 사후/예방/예지 3유형이 실제 구분되나. 외주 보전 기록 범위. ~~(신규) 보전 기능의 고객 기대 수준(요구 공백 — 차기 미팅 안건)~~ → **소멸: 경량 보전 범위 확정 (QA #10 2026-07-04)**.

- **Medium(매체)** ✅: **현행 엑셀 관리 확정**(✓확정 2026-07-04 QA #7 — 기존 🟡 '엑셀 예비품대장' 가설 검증됨. 엑셀 대장=DX 마이그레이션 대상). 종이 출고전표 병용 여부는 참고 확인. 예비품 재고가 일반 자재 재고와 같은 곳인지 별도인지는 내부 설계(마스터는 별도 확정 — QA #7).

- **Boundary(경계)** 🔗: **예비품 마스터 = 별도 마스터 확정(품목 마스터 통합 아님 — 사용자 결정)**(✓확정 2026-07-04 QA #7 — C3/종합12 종결). 예비품 **재고·출고와 C6 물류의 구조 관계**는 내부 설계. 출고전표 회계 성격(소모) → ERP 전표 가능 — 🔗 **B8**(출고 발번 3계층) 인접, ERP 송신은 항목별 선택(on/off) 원칙 준용(QA #6 2026-07-04 참고). ## S7. 툴 사용실적 수집 (타발수 · 누계타발수 · 사용가능타수)

- **Trigger(촉발)**: 금형(툴) 생산 가동 — **작업실적 발생**(✓확정 2026-07-04 QA #12 — **계수기 설비 없음**, '설비/계수기 신호' 경로 폐기).

## S8. 툴 PM (MaintenanceOrder → PM실적 · 차기 PM 산출)

- **Trigger(촉발)**: 누계타발수/사용가능타수가 적정타수 도달·초과(S7), 또는 BaseDate 기준 PM 주기 도래 — **타발수·날짜 주기 둘 다 지원(겸용 설정형) 확정**(✓확정 2026-07-04 QA #11).

- **Action(행위)**: **MaintenanceOrder Create(BaseDate)** → 보전계획(예정일·항목·담당자) → PM 시행(유형·부위·점검결과·수량 기록) → **마지막PM수량·다음PM수량 산출**(차기 PM 시점).
- **Input(입력)**: 누계타발수(S7), 적정타수, 직전 PM실적(마지막PM수량).
- **Medium(매체)** ✅(부분): **적정타수 실존 — 현행 엑셀 관리 확정**(✓확정 2026-07-04 QA #11 — 적정타수 엑셀=DX 마이그레이션 원천. 기존 '적정타수 존재 추정' 가설 검증됨). 툴 관리 전반이 엑셀·ERP 미사용으로 확인(REQ-PR-0003 현행)되어 **현행 툴 PM '시스템' 체계는 부재**로 판정(통합분석 D5) — PM대장·점검표 실물은 마이그레이션·설계 참고용으로 수집. 차기 PM 수량 산출 로직은 신규 설계 재량.
- **Result(결과)**: 툴보전오더 + 툴PM실적(보전부위·점검결과·수량·마지막PM수량·다음PM수량). **상태변화**: 금형 PM 완료, 누계 리셋/차기 기준 갱신.
- **Rule(선행조건·규칙)**: PM 트리거 = **타발수(적정타수 도달·초과) + 날짜 주기 — 둘 다 지원하는 겸용 설정형**(✓확정 2026-07-04 QA #11). 적정타수 = 실존·현행 엑셀 관리(QA #11). "PM 수량" = **타발수**(S7과 동일 단위).
- **Exception(예외·선행조건 미충족)** 🟠: ① **PM 주기/적정타수 도래했으나 생산 우선 지연** → 초과 가동(금형 파손·불량 위험) 누가 승인? — (신규) 초과 도달 시 **이벤트 알람(REQ-PR-0016 요구)** 발신이 통제 수단 후보(설비·툴 이벤트의 알람 유형 포함 여부는 고객 회신 대기) ② **PM 중 추가 결함**(예상 외 마모·균열) → 보전 범위 확대·폐기 판정(S9) ③ **차기 PM수량 산출 오류**(누계 부정확 S7 전파) ④ 긴급 금형 수리(계획 외) → 오더 사후 생성. [확인] PM 지연 시 통제·승인, 자기참조(이전→차기) 산출 로직, 추가 결함 시 분기.

## S9. 설비 · 툴 폐기 (자산 처분)

- **Trigger(촉발)**: 설비/금형·지그 수명 종료·수리 불가·노후 교체·생산 단종.
- **Actor(주체)**: 설비담당 (+관리/회계: 자산 처분).
- **Action(행위)**: 폐기 대상 선별 → 폐기 승인 → 마스터 상태 '폐기' 전환 — 툴(금형·지그)은 **MES에서 직접 상태 전환**(✅ 충돌③ 파생, REQ-PR-0003 — 기존 가설 폐기: '신규입고/폐기 상태 Legacy 연계'는 툴에 성립하지 않음), 설비(기계)는 전환 주체 미확정 → (해당 시) 잔존 부품·예비품 회수.
- **Input(입력)**: 폐기 대상 설비/툴, 폐기 사유, 잔존가치(회계).
- **Medium(매체)** 🟡: *가설 유지(부분 갱신)* — 설비(기계)는 **불명**(Legacy 연계 폐기 처리 or *아예 미관리* 가능성). 툴은 현행 엑셀 대장(REQ-PR-0003 현행)에서 상태 관리 여부 불명 → To-Be는 MES 마스터 상태 전환.
- **Result(결과)**: 설비/툴 master 상태 '폐기', (요구 시) 자산 처분 기록·잔존 부품 회수. **상태변화**: 자산 '운용→폐기'.
- **Rule(선행조건·규칙)**: 본 '폐기' = **설비·툴 자산 처분**(자재/제품 폐기 D21과 *별개* — D21은 불량품·자재·제품 Scrap). 툴(금형·지그) 상태 관리 = **MES 정본**(✅ REQ-PR-0003 요구). **자산 감가상각·잔존가치·재고손익(전표) = 범위 밖**(✅ D4 — 추후 EAM/ERP).
- **Exception(예외·선행조건 미충족)** 🟠: ① **폐기 승인 권한·절차** 미정 → 임의 폐기·마스터 미갱신 ② **잔존 부품·예비품 회수**(폐기 설비에서 쓸 수 있는 부품) 처리 ③ **폐기 자산의 비가동/사용실적 이력** 보존(폐기 후에도 추적 가능해야) ④ 자산 재평가·손익(ERP) 연계 누락. [확인] 폐기 승인 흐름, 설비(기계) 마스터 상태 갱신 주체(MES? Legacy?), 잔존 부품 회수, 자산/손익 연계.
- **Pain/Wish(문제·요구)** 🟡: *가설 유지* — 폐기 자산이 *마스터에 남아* 점검/보전 대상에 잡힘(유령 설비), 폐기 이력·잔존가치 관리 부재.
- **Boundary(경계)** 🔗: **MES(자산 상태=폐기 기록) ↔ ERP/Legacy(자산 회계·감가상각·손익)**. 툴(금형·지그) 마스터 정본 = **MES**(✅ 충돌③)이므로 상태 전환도 MES 단독 — 연계 없음. 설비(기계)는 정본 소재 미확정 — 정본이 Legacy/ERP면 MES는 상태 동기화만. **D21(자재/제품 폐기)와 구분** — 본 단계는 설비·툴 자산뿐. 참고: D21 자체는 명세서로 **확정**됨(불량창고 우선 입고→재작업/폐기 판단→내부 품의→기타 출고 — REQ-PR-0025·0028, WF01 S11·WF04 S10 소관) — 본 단계와 혼동 금지 원칙은 유지.
- **Open-Issue(연계 미결)**: ⚠ 설비(기계) 신규입고/폐기 상태의 채번·동기화 주체(C1, 전용 질문 없음 — B6 키 스킴·S1 인접. **툴은 MES 확정으로 제외** — REQ-PR-0003) · 자산 처분 회계 연계(범위 밖, D4) · D21(자재/제품 폐기 — 확정, *별개* 유지 — REQ-PR-0025·0028).
- **[Check(확인)]**: 폐기 설비/금형을 *어떻게* 처리하나 — 툴은 현행 엑셀 대장에서 폐기 표기 여부(마이그레이션 시 폐기분 포함 범위), 설비는 마스터 상태 전환? 삭제? 방치?. 폐기 승인 절차. 잔존 부품 회수 실태. 폐기 자산 이력 보존 여부. 자산 회계(ERP) 연계.

**정량 데이터(사이징·CBM용)**: 설비 수·설비그룹 수, 금형·지그 수(전 도구 — REQ-PR-0003 범위)·Cavity, Daily/Monthly 점검 항목 수, 월 고장·비가동 건수·시간, 월 보전 건수(예방:사후 비율), 예비품 SKU·재고, 금형별 적정타수·월 타발수, 타발수 자동수집 비율, (신규) QR 발급 대상 툴 총수·라벨 수요(프린터 사이징 — REQ-PR-0017).

**관찰 포인트(말 말고 동작)**: 점검이 *실측 없이 ○만* 찍히는지, ~~점검 미실시가 *정말* 작업을 막는지(시연)~~ → To-Be 통제=설정형 확정(QA #9 2026-07-04) — As-Is 관행은 참고 관찰만, ~~타발수가 *자동으로* 들어오는지~~ → 확정: 계수기 없음·작업실적 수동 기입(QA #12 2026-07-04) — 수기 기입의 누락·오기 실태만 관찰, ~~적정타수 초과가 *알림으로 뜨는지*~~ → 확정: 현행 알람 없음(REQ-PR-0016 현행) — 대신 *초과 시 현장이 어떻게 인지·대응하는지* 관찰, 폐기 설비가 *마스터(대장)에 남아* 점검 대상에 잡히는지, (신규) ~~캠데코 설비의 네트워크 구간이 불안정 구간(REQ-OA-0005 현행)을 지나는지~~ → 인프라 관리·원인 해결=고객 책임 확정(QA #32 2026-07-04) — 폴백(POP 로컬 버퍼링) 설계 참고로만 확인.

## 예외 흐름 카탈로그 (선행조건 미충족)

각 예외는 **공통 4질문**으로 점검한다 — **(a) 차단하나 / 우회(미점검 가동·강제 진행·수기 입력·임시 조치)하나 · (b) 누가 승인하나 — (신규) 처리 방향 확정: 관리자 개입이 필요한 예외 발생 시 **담당 관리자에게 알람(메시지) 발신**이 에스컬레이션 채널로 요구됨(✅ REQ-OA-0009 요구 — 메시지 전달. 매체=대시보드+카카오톡/Zalo 선택형 확정, Zalo 기업 API 기술 검토=CREFLE 액션 — QA #24 2026-07-04) · (c) 어디에 기록(매체)하나 · (d) 사후 정합(이력·재고·차기 산출·ERP/EAM) 방법.**
