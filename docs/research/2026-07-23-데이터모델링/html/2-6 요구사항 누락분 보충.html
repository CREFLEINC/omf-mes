작업지시공정별 작업지시, 전체 일괄 생성, 상태, 분할, 공용 단말기
자재투입자재 LOT 스캔, 대체자재, 추가투입, 잔량, 재고 차감
생산실적부분실적, 양품·불량, 후속 공정 가용수량, 생산 LOT
품질관리검사계획, 검사실적, 판정, 부적합, 특채, 재검사

2. 5대 기능 간 책임 경계

각 기능이 동일한 데이터를 중복으로 변경하지 않도록 원본 데이터의 책임을 명확히 해야 한다.

데이터원본 책임 기능다른 기능의 역할
작업지시 상태·지시수량작업지시다른 기능은 참조
자재 투입·사용·반납수량자재투입생산실적·추적성에서 연결
양품·불량 생산수량생산실적품질·LOT·작업지시에서 참조
합격·불합격·보류 판정품질관리재고·후속공정 사용통제에 반영
LOT 계보와 연결관계LOT 추적성원본 업무 이벤트를 연결
현재 재고수량재고 또는 물류 기능자재투입·생산실적이 재고 이벤트 생성

다음과 같은 중복 처리를 금지해야 한다.

생산실적 기능이 품질판정을 직접 변경
LOT 추적 기능이 생산수량을 별도 계산하여 저장
품질관리 기능이 자재투입 이력을 직접 수정
작업지시 기능이 재고수량을 직접 조정

권장 원칙은 다음과 같다.

각 업무기능은 자신의 원본 이벤트를 생성하고, 다른 기능은 그 이벤트를 참조하거나 정해진 상태전파 규칙에 따라 후속 이벤트를 생성한다.

3. 공통 기능 요구사항 누락

CR-FR-001 기능 간 상태전파

하나의 기능에서 상태가 변경되면 관련 기능에 미치는 영향을 명확하게 정의해야 한다.

예시:

발생 이벤트필수 후속 처리
작업지시 취소미사용 자재 예약 해제, 미작업 잔량 복원
자재투입 취소재고 복원, 관련 생산 LOT 영향 검증
생산실적 취소생산 LOT, 후속 공정 가용수량, 재고 재계산
품질 불합격LOT 보류·격리, 후속 공정과 출하 차단
LOT 무효화관련 생산·품질·출하이력 존재 여부 검증

상태전파가 실패한 경우 예외목록에 등록하고 재처리할 수 있어야 한다.

CR-FR-002 기준정보 스냅샷 및 버전 고정

작업지시 생성 또는 작업 시작 시 적용한 기준정보를 보존해야 한다.

적용대상은 다음과 같다.

  • 라우팅 및 라우팅 버전
  • BOM 및 BOM 버전
  • 검사계획 및 검사규격 버전
  • 표준 Cycle Time
  • 단위환산 기준
  • 대체자재 기준
  • LOT 생성정책
  • 공정별 필수입력 정책

기준정보가 변경되어도 이미 생성된 작업지시와 실적의 적용기준이 자동으로 바뀌어서는 안 된다.

CR-FR-003 통합 예외업무 목록

다음 미처리·오류 항목을 하나의 예외업무 목록에서 조회할 수 있어야 한다.

  • 작업지시 생성 실패
  • 필수 자재 미투입
  • 자재수량 불일치
  • 미확정 생산실적
  • 품질검사 미완료
  • 보류·불합격 미처리
  • LOT 연결 누락
  • 재고수량 불일치
  • ERP 전송 실패
  • 오프라인 입력 충돌
  • 작업지시 마감 실패
  • 출하 통제 대상

예외에는 담당자, 중요도, 처리기한, 처리상태와 처리결과를 기록해야 한다.

CR-FR-004 공통 승인 워크플로

다음 예외처리에 공통 승인 절차를 적용할 수 있어야 한다.

  • 지시수량 초과생산
  • 사후 실적입력
  • 음수재고 허용
  • 대체자재 사용
  • 보류 자재 사용
  • 특채
  • 마감 취소
  • 생산실적 정정
  • LOT 관계 정정
  • 재고조정

승인단계는 업무유형, 수량, 금액, 품목 또는 공정에 따라 설정할 수 있어야 한다.

CR-FR-005 첨부 및 근거자료 공통관리

정정·승인·특채·폐기·부적합 처리 시 사진, 문서, 작업표준, 승인서 등을 첨부할 수 있어야 한다.

첨부파일은 원본 업무 이벤트와 연결되어야 하며 일반 사용자가 임의 삭제할 수 없어야 한다.

CR-FR-006 대량처리

다음 업무는 한 건씩뿐 아니라 선택한 여러 건을 일괄 처리할 수 있어야 한다.

  • 작업지시 발행·보류·취소
  • 예정 설비·근무조 변경
  • 자재 투입예정 등록
  • 생산실적 일괄입력
  • 검사대상 생성
  • LOT 일괄 보류
  • ERP 재전송

대량처리 결과는 성공·실패 건을 구분하여 제공해야 한다.

CR-FR-007 업무일자와 실제시각 구분

야간조가 자정을 넘어가는 운영을 고려하여 다음을 구분해야 한다.

  • 실제 발생일시
  • MES 입력일시
  • 생산 업무일자
  • 근무조 기준일자

예를 들어 7월 15일 야간조가 7월 16일 오전에 생산한 실적을 어느 생산일자로 집계할지 설정할 수 있어야 한다.

4. 작업지시 관리 보완사항

4.1 생산계획 변경에 따른 재생성

생산계획 확정 후 다음 내용이 변경되면 이미 생성된 전체 공정 작업지시에 대한 처리방식이 필요하다.

  • 계획수량 변경
  • 품목 변경
  • 라우팅 변경
  • 생산일자 변경
  • 공정 관리 여부 변경

다음 정책을 지원해야 한다.

미발행 작업지시: 자동 재생성 가능
발행 후 미작업: 취소 후 재생성
작업중: 기존 생산분 유지 후 잔량 신규 작업지시 생성
작업완료·마감: 변경 불가, 별도 보정 작업지시 생성

4.2 작업지시 간 수량 불균형

공정별 수율이나 폐기 발생으로 각 작업지시 수량이 다를 수 있으므로 다음을 구분해야 한다.

  • 계획수량
  • 지시수량
  • 선행 공정 인계수량
  • 공정 투입수량
  • 완료수량
  • 후속 공정 가용수량

모든 공정 작업지시가 생산오더 수량과 동일해야 한다는 규칙으로 고정해서는 안 된다.

4.3 작업지시 병합

동일 품목·공정·라우팅·설비조건의 작업지시를 작업 시작 전에 병합할 수 있는 기능이 검토되어야 한다.

병합 시 원본 작업지시 번호와 생산계획 연결관계를 유지해야 한다.

필수 기능은 아니지만 작업지시 분할을 지원한다면 대응되는 병합 정책도 필요하다.

4.4 작업 세션 관리

작업지시 상태와 별개로 실제 작업 세션을 관리하는 것이 필요하다.

작업지시 WO-001
├─ 작업 세션 1: 주간조, 작업자 A
├─ 작업 세션 2: 야간조, 작업자 B
└─ 작업 세션 3: 다음날 주간조, 작업자 C

작업 세션에는 시작·중지·재개·종료, 작업자, 근무조, 설비를 기록해야 한다.

하나의 작업지시가 여러 근무조에 걸쳐 수행되는 경우 작업지시 자체의 작업자·근무조 컬럼만으로는 충분하지 않다.

5. 자재투입 관리 보완사항

5.1 예약·불출·투입·소비 구분

현재 요구사항은 투입과 재고차감을 중심으로 되어 있으나 다음 단계를 구분하는 것이 필요하다.

자재 예약
→ 창고 불출
→ 생산현장 인계
→ 작업지시 투입
→ 실제 소비
→ 잔량 반납
단계의미
예약작업지시에 사용할 재고 확보
불출창고에서 생산구역으로 이동
투입특정 작업지시·공정에 연결
소비실제 생산에 사용된 수량
반납미사용 잔량을 재고로 복귀

모든 고객사가 전 단계를 사용할 필요는 없지만 데이터 모델은 구분 가능해야 한다.

5.2 자재 대체 유효조건

대체자재는 단순 승인 여부뿐 아니라 다음 조건을 가져야 한다.

  • 적용 품목
  • 적용 공정
  • 적용 작업지시
  • 유효 시작·종료일
  • 최대 대체수량
  • 고객 제한
  • 품질 승인조건
  • 원자재와 대체자재 간 우선순위

5.3 실제 소비량 배분

하나의 자재 LOT가 여러 생산실적 또는 생산 LOT에 사용된 경우 실제 소비량을 어떻게 배분할지 명확해야 한다.

  • 직접 스캔
  • 실적수량 비례
  • BOM 표준소요량
  • 투입시간 구간
  • 작업자 확정

추정 배분과 정확 배분을 구분해야 한다.

5.4 생산 부산물·스크랩

공정에서 정상 제품 외에 다음이 발생할 경우 처리방식이 필요하다.

  • 스크랩
  • 퍼징 자재
  • 회수 가능 잔재
  • 재생 원료
  • 부산물

현재 고객사가 스프루 재사용을 하지 않더라도 폐기수량과 귀책·폐기사유를 관리할 구조는 유지해야 한다.

6. 생산실적 관리 보완사항

6.1 공정수량 보존 규칙

각 공정에서 다음 관계를 정의해야 한다.

공정 투입수량
= 양품수량
+ 불량수량
+ 보류수량
+ 현재 재공수량
+ 공정손실수량
+ 조정수량

생산완료수량만 관리하면 아직 공정 내에 남아 있는 재공수량을 설명하지 못할 수 있다.

6.2 재공수량 관리

작업지시가 진행 중일 때 다음 재공을 조회할 수 있어야 한다.

  • 공정 투입 후 미완료수량
  • 공정 완료 후 미인계수량
  • 검사대기수량
  • 보류수량
  • 창고 입고 전 수량

이는 공정별 작업지시와 부분실적을 운영할 때 필수적인 정합성 항목이다.

6.3 복수 산출물

하나의 작업지시에서 둘 이상의 품목이 산출될 가능성을 검토해야 한다.

예:

  • 주제품과 부산물
  • 좌·우 제품 동시 생산
  • 다수 Cavity의 다른 품번
  • 세트 구성품 동시 생산

현재 고객사에 해당하지 않으면 1차 범위에서 제외하되 데이터 모델의 확장 가능성은 유지하는 것이 좋다.

6.4 자동실적과 수동실적 구분

향후 설비 연계가 추가될 경우 생산실적의 출처를 구분해야 한다.

  • 수동입력
  • 설비 자동수집
  • 파일 업로드
  • ERP 수신
  • 관리자 보정

자동실적과 수동실적이 중복 반영되지 않도록 우선순위와 병합정책이 필요하다.

6.5 공정 간 수율

선행 공정 양품수량과 후속 공정 투입수량 차이를 다음 유형으로 설명할 수 있어야 한다.

  • 정상 수율 차이
  • 공정 간 이동손실
  • 샘플 사용
  • 품질검사용 사용
  • 파손
  • 수량조정
  • 미인계 재공

7. 품질관리 보완사항

7.1 검사장비 및 교정상태

측정기·검사장비를 사용하는 경우 다음 정보가 필요하다.

  • 검사장비 번호
  • 장비 유형
  • 최근 교정일
  • 교정 유효기간
  • 교정상태
  • 사용 가능 여부

교정 유효기간이 지난 장비로 검사결과를 확정하려는 경우 경고하거나 차단할 수 있어야 한다.

7.2 검사 측정환경

치수검사 등 환경조건이 중요한 검사에는 다음 정보를 기록할 수 있어야 한다.

  • 온도
  • 습도
  • 검사장소
  • 검사장비
  • 검사조건
  • 시편 조건

모든 검사에 필수는 아니며 검사항목별로 설정해야 한다.

7.3 품질원인과 귀책 분석

불량유형뿐 아니라 다음을 구분해야 한다.

  • 불량현상
  • 추정원인
  • 확정원인
  • 발생공정
  • 유출공정
  • 귀책부서
  • 귀책구분
  • 시정조치

예를 들어 흠집은 현상이고 취급 부주의는 원인이다. 둘을 동일한 불량코드로 관리해서는 분석성이 떨어진다.

7.4 시정·예방조치

중대하거나 반복되는 부적합에 대해 시정조치 또는 예방조치 업무를 연결할 수 있어야 한다.

  • 문제 정의
  • 원인분석
  • 임시조치
  • 근본대책
  • 책임자
  • 완료기한
  • 효과확인
  • 재발 여부

정식 CAPA 기능은 2차 범위로 둘 수 있으나 부적합 건에 조치내용과 담당자·기한은 최소한 포함해야 한다.

7.5 검사결과의 생산구간 지정

근무조 중간에 검사한 결과가 어느 생산수량 또는 시간구간에 적용되는지 정의해야 한다.

  • 특정 생산 LOT
  • 특정 생산실적
  • 검사시각 이후 생산분
  • 이전 검사 이후 현재 검사까지
  • 작업자가 지정한 수량구간

이 규칙이 없으면 검사 불합격 발생 시 영향범위를 정확하게 산정하기 어렵다.

8. LOT 추적성 보완사항

LOT 추적성은 직전 검토에서 대부분 보완되었다. 특히 다음 내용은 필수 추가항목으로 유지해야 한다.

  • LOT 관계유형
  • 사용수량 배분방식
  • 정확·추정 추적 구분
  • 추적 완전성 검증
  • 관계 정정 및 역처리
  • 시점 기준 상태조회
  • 취급단위와 LOT 분리
  • 외주공정·외부창고 추적
  • 외부 식별번호 연결
  • 개별 일련번호 연계
  • 리콜·회수 사건 관리
  • 오프라인 이벤트 재동기화

추가로 다음 사항을 명시해야 한다.

8.1 LOT 계보와 재고이력의 분리

LOT 계보는 “어떤 LOT에서 어떤 LOT가 만들어졌는가”를 나타내며, 재고이력은 “어디로 얼마나 이동했는가”를 나타낸다.

LOT 계보:
자재 LOT → 반제품 LOT → 완제품 LOT

재고이력:
자재창고 → 생산현장 → 반제품창고 → 완제품창고

두 관계를 하나의 이동 테이블로 처리해서는 안 된다.

8.2 계보 생성 근거

모든 LOT 관계는 다음과 같은 원본 업무 이벤트를 가져야 한다.

  • 자재투입
  • 생산실적
  • 공정 인계
  • LOT 분할
  • LOT 병합
  • 포장
  • 재작업
  • 출하

사용자가 근거 없이 LOT 관계만 직접 생성하는 것은 제한해야 한다.

9. 공통 비기능 요구사항 누락

9.1 오프라인 운영정책

네트워크 장애 시 어떤 기능까지 허용할지 기능별로 정의해야 한다.

기능오프라인 허용 검토
작업지시 조회최근 동기화 데이터 조회 가능
작업 시작·종료임시 이벤트 저장 가능
자재 LOT 투입제한적으로 허용, 복구 후 재검증
생산실적 입력임시저장 가능
품질 최종판정원칙적으로 온라인 권장
LOT 분할·병합충돌위험으로 온라인 권장
출하처리온라인 필수 권장

오프라인 입력은 단순 재전송이 아니라 수량·상태·작업순서 충돌검증이 필요하다.

9.2 멱등성 식별체계

모든 주요 등록 요청에는 중복처리를 방지할 고유 이벤트 번호가 있어야 한다.

적용 대상:

  • 작업지시 생성
  • 자재투입
  • 생산실적
  • 품질검사 확정
  • LOT 생성·분할·병합
  • 재고이동
  • ERP 전송

9.3 정합성 점검 배치

시스템은 주기적으로 다음 정합성을 점검할 수 있어야 한다.

  • 작업지시 수량과 실적
  • 선행·후속 공정 수량
  • 자재 투입과 재고 차감
  • 생산실적과 생산 LOT 수량
  • 품질상태와 사용 가능상태
  • LOT 이벤트와 현재수량
  • MES 실적과 ERP 실적

오류가 발견되면 자동으로 임의 수정하지 않고 예외목록에 등록해야 한다.

9.4 관측성과 운영 모니터링

다음 운영지표를 확인할 수 있어야 한다.

  • API 오류율
  • 평균 응답시간
  • 작업지시 생성 실패
  • 실적등록 실패
  • 중복요청 차단
  • 오프라인 대기 이벤트
  • ERP 연계 실패
  • LOT 추적 단절
  • 수량 정합성 오류
  • DB 및 저장공간 사용량

9.5 백업·복구 정합성

백업 복구 후 단순히 테이블이 복원되는 것만으로는 부족하다.

다음 관계가 일치하는지 검증해야 한다.

  • 작업지시와 실적
  • 자재투입과 재고
  • 생산실적과 생산 LOT
  • 품질판정과 LOT 상태
  • LOT 계보
  • 출하 관계
  • 감사이력

9.6 개인정보 및 중요정보 최소노출

작업자, 고객, 공급사 정보는 역할에 따라 접근을 제한해야 한다.

현장 단말기에는 작업 수행에 필요한 최소한의 정보만 표시해야 하며, 고객별 출하정보나 원가정보 등을 노출해서는 안 된다.

9.7 대량 데이터 보관 및 아카이브

생산실적, 검사 측정값, LOT 이벤트가 장기간 누적되므로 다음을 정의해야 한다.

  • 온라인 조회 보관기간
  • 아카이브 전환 시점
  • 아카이브 조회방법
  • 법적·고객 요구 보존기간
  • 삭제 승인절차
  • 추적조회 최대 복원시간

9.8 시간 동기화

서버, 단말기, ERP 및 외부연계 시스템 간 시간차가 추적성을 왜곡하지 않도록 해야 한다.

  • 서버 기준시간 사용
  • 단말기 시간차 감지
  • 공장별 시간대 관리
  • 실제 발생일시와 수신일시 분리
  • 지연입력 표시

10. 기능별 완료조건 누락

요구사항 문서에는 기능 목록뿐 아니라 수용 가능한 완료조건이 필요하다.

작업지시 완료조건

  • 생산계획 확정 시 관리 대상 공정 작업지시가 중복 없이 전체 생성된다.
  • 공정 간 선후관계가 라우팅대로 연결된다.
  • 공용 단말기에서 허용 공정의 작업지시만 처리된다.

자재투입 완료조건

  • 잘못된 자재와 사용불가 LOT가 차단된다.
  • 투입·소비·잔량·폐기수량이 일치한다.
  • 자재 LOT와 생산 LOT 관계가 생성된다.

생산실적 완료조건

  • 부분실적과 누적실적이 일치한다.
  • 후속 공정 가용수량이 선행 공정 양품수량을 초과하지 않는다.
  • 실적 취소 시 관련 LOT와 재고가 정합성을 유지한다.

품질관리 완료조건

  • 검사계획에 따른 필수 검사가 자동 생성된다.
  • 불합격·보류 LOT의 투입과 출하가 차단된다.
  • 판정 변경 이력이 보존된다.

LOT 추적성 완료조건

  • 출하 LOT에서 투입 자재 LOT까지 역추적할 수 있다.
  • 자재 LOT에서 고객 출하까지 정방향 추적할 수 있다.
  • 분할·병합·재작업 이후에도 원본 계보가 유지된다.
  • 영향범위의 재고·공정재·출하수량을 조회할 수 있다.

12. 최종 판단

5대 기능의 개별 요구사항은 충분히 폭넓게 작성되어 있다. 현재 가장 큰 누락은 새로운 업무기능 자체보다는 다음과 같은 공통 실행통제 규칙이다.

어떤 기능이 원본 데이터를 책임지는가
한 기능의 변경이 다른 기능에 어떻게 전파되는가
잘못된 데이터를 어떻게 취소·정정하는가
각 단계의 수량 합계가 어떻게 일치해야 하는가
기준정보 변경 이후 기존 작업에는 어떤 버전을 적용하는가
장애와 지연입력 시 충돌을 어떻게 처리하는가

따라서 별도의 여섯 번째 업무기능을 추가하기보다는, 5대 기능 공통 장으로 다음 내용을 정의하는 것이 적절하다.

공통 상태전파, 정합성, 승인, 예외처리, 정정·역처리, 오프라인 처리, 감사이력 및 연계 재처리 요구사항
