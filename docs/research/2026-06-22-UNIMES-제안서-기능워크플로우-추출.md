### 사용 시나리오
> 사용자(액터)가 이 모듈 기능을 사용하는 시나리오. 단계 = (액터) 행동 → (시스템) 반응.

**시나리오 1 — MES 독자 기준정보 등록·수정**
- 액터: 운영자(기준정보 담당)
- 사전조건: ERP 연계분이 아닌 MES 독자 기준정보(공통코드·품목·공정·검사·작업조·라우팅 등)를 신규 등록하거나 변경해야 함
- 단계:
  1. (운영자) 기준정보 관리 화면(공통코드·품목·조직·생산·품질·설비)에서 대상 항목을 선택 → (시스템) 기준정보 마스터 데이터와 사용여부(Y/N)·외주공정 구분 등 입력 폼 표시
  2. (운영자) 공통코드·품목·라우팅 Sequence·공정 Ver 항목을 입력·수정 후 저장 → (시스템) 등록·수정·삭제·조회 처리 및 변경이력 컬럼(생성주체 'MES System') 기록
  3. (운영자) 연계(Legacy 출처) 기준정보 항목을 수정 시도 → (시스템) 연계분은 MES 수정/삭제 불가로 차단
- 분기·예외: 연계(Legacy 출처) 기준정보 = 수정/삭제 불가 / MES 독자 기준정보 = 등록·수정·삭제·조회 가능(변경이력 관리)
- 결과: 표준 기준정보(공통코드·품목정보·BOM·라우팅)가 마스터에 반영되고 변경이력이 남는다

**시나리오 2 — ERP 연계 기준정보 수신 확인**
- 액터: 운영자(연계 담당)
- 사전조건: ERP 송신측 DB에 전송대상 기준정보(코드·조직·작업자·품목·BOM·공정·품질·설비·툴·작업지시)가 생성됨
- 단계:
  1. (운영자) 기준정보 관리(연계) 화면에서 수신 현황을 조회 → (시스템) I/F Data(MS SQL) 경유 pull 수신분을 Temp Table 적재 후 검증·분석 결과 표시
  2. (운영자) 송수신 검증 결과를 확인 → (시스템) 연계 트리거(Time Schedule 또는 Event)별 자동 연계 상태와 MES 기준정보 테이블 반영분 표시
- 분기·예외: 연계 트리거 = Time Schedule 또는 Event 자동 연계 / 수신분(Legacy 출처)은 MES 수정·삭제 불가
- 결과: ERP→MES 기준정보가 일관성 있게 동기화되고, MES→ERP 제조이력 송신 기반이 마련된다

### 사용 시나리오
> 사용자(액터)가 이 모듈 기능을 사용하는 시나리오. 단계 = (액터) 행동 → (시스템) 반응.

**시나리오 1 — ERP P/O를 세부 W/O로 편성·확정·배포**
- 액터: 생산관리자
- 사전조건: ERP에서 P/O(대표공정)와 자재예약정보(품목·공정·설비·수량·완료예정일)가 MES로 연계됨
- 단계:
  1. (생산관리자) 작업지시관리 화면에서 연계된 P/O를 세부공정 W/O로 전개 → (시스템) Routing 기준으로 세부 W/O 편성, WorkOrderID 단위 LotMaster 생성
  2. (생산관리자) W/O에 설비·작업자·자재·툴 자원을 배정 → (시스템) 자원 할당 시 유효성 Check(설비·작업자·자재재고·툴 상태·진행 가능) 수행, W/O 그리드에 OK/NG 표기
  3. (생산관리자) 금형 교체 등 작업 효율을 고려해 W/O 우선순위 조정 → (시스템) 비가동 최소화 기준으로 우선순위 반영
  4. (생산관리자) W/O 확정 → (시스템) 확정 W/O를 현장에 자동 배포
- 분기·예외: 자원 할당 이상(NG=부적합) → 시스템이 작업자에게 알림
- 결과: 확정·현장 배포된 W/O, WorkOrderID 단위 LotMaster

**시나리오 2 — 현장 작업 실적·LOT 수집(LOT 생명주기)**
- 액터: 현장 작업자
- 사전조건: 확정 W/O가 현장 배포되고 생산LOT 라벨이 선 발행·배포됨(본 제안 방식)
- 단계:
  1. (현장 작업자) 단말기에서 설비 선택 시 배정 W/O·전달사항·문서 확인 → (시스템) 설비 배정 W/O 정보·문서 단말 표시
  2. (현장 작업자) 투입 자재 Lot을 바코드/스캐너로 스캔해 자원 투입 → (시스템) 투입 자재·설비·작업자·Tool의 W/O 적합성(오투입) Validation Check, 적합/오투입 판정
  3. (현장 작업자) 작업 진행 후 생산실적을 Lot 스캔으로 등록(불량·비가동·검사·작업조건 포함) → (시스템) W/O별 생산LOT No 생성, 인식표(Lot No+seq) 발행, WIP 재고·공정별 실적 반영
  4. (현장 작업자) 작업 종료/LOT 종료 → (시스템) 실시간 생산현황·작업실적 집계
- 분기·예외: 수집 방식은 수작업(현재) vs 장비·IoT 자동(향후) / 라벨은 선 발행(제안) vs 현장 실시간 발행(변동 시 발행 Infra 필요)
- 결과: 생산 Lot·인식표 Label, 실시간 생산현황, 공정별 실적 List

**시나리오 3 — P/O·W/O 대비 작업 현황 점검**
- 액터: 생산관리자
- 사전조건: 현장에서 작업 실적이 수집·집계됨
- 단계:
  1. (생산관리자) 생산 현황/분석 화면에서 P/O 또는 W/O 대비 작업 현황 조회 → (시스템) 실적·진행 집계해 작업 현황·진행 현황 제시
- 분기·예외: —
- 결과: ERP P/O 대비 작업·진행 현황

**시나리오 4 — 생산LOT 기준 제조이력 역추적 조회**
- 액터: 품질담당 / CS(클레임 대응)
- 사전조건: 생산품에 인식표(QR = 생산LOT No + seq, Unique)가 부착되고, 제조이력이 LOT 기준으로 축적됨 (p.31·57)
- 단계:
  1. (품질담당) 생산품 인식표(QR)를 스캔 → (시스템) 인식표 = Lot No + seq를 읽어 **생산LOT No 식별** (또는 생산LOT No 직접 입력)
  2. (품질담당) 역추적(역전개) 조회 실행 → (시스템) 해당 생산LOT 기준으로 관련 LOT·제조이력 조회: 투입 자재LOT(계보)·자재 출고/투입 이력·공정 검사/작업 이력·투입 설비·작업자·작업조건·설비상태·불량/비가동·출하 작업/검사 이력
  3. (품질담당) 결과에서 '누가·언제·어디서·무엇을·어떻게·왜'를 확인 → (시스템) LOT 단위 제조이력 상세 제공
- 분기·예외: 정전개(자재→제품)/역전개(제품→자재) 방향 선택 / 설비·IoT 자동수집 값 Matching 불가 시 작업시간 기준 Trend로 연계 표시 / **출하 단계 제품LOT·포장라벨에서 시작하는 역추적은 생산LOT 승계 관계 필요(→ §추출 한계 'LOT 키 승계')**
- 결과: 해당 생산LOT의 전체 제조이력·계보 열람 (클레임·부적합 원인 규명)

**시나리오 1 — 설비 단위 공정 작업 진행과 제조이력 등록**
- 액터: 현장 작업자
- 사전조건: 생산관리에서 작업지시(W/O)가 해당 설비에 배포되어 있고, 작업 전 점검 항목이 정의되어 있다.
- 단계:
  1. (작업자) 설비를 선택한다 → (시스템) 해당 설비에 할당된 작업지시 목록을 표시한다.
  2. (작업자) 작업지시를 확인·선택한다 → (시스템) 작업 전 점검 사항을 제시하고, 점검 이력이 없으면 작업을 통제한다.
  3. (작업자) 작업 전 점검을 수행하고 작업을 시작한다 → (시스템) 작업 시작을 기록하고 자원 투입 단계로 진행한다.
  4. (작업자) 투입 자원(작업자·자재·금형·작업조건)을 등록하며 자재LOT·금형ID를 스캔한다 → (시스템) 작업지시 적합성을 Validation Check하고 오투입 여부를 판정한다.
  5. (작업자) 공정 검사(자주·초중종)를 수행하고 불량·비가동을 기록한다 → (시스템) 검사·불량·비가동 실적을 제조이력에 누적한다.
  6. (작업자) 이동단위 적재가 완료되면 작업을 완료 처리한다 → (시스템) 이동단위별 LOT(인식표)를 발행하거나 공정이동표를 부착 대상으로 출력하고, WIP 이동/재공을 Push/Pull 기준으로 관리한다.
- 분기·예외: 작업 전 점검 미실시 → 작업 통제(진행 차단) / 4M 오투입 판정 → 투입 차단 / 툴 사용한도 초과 → 경고.
- 결과: 설비 선택부터 완료까지 공정 제조이력(자원·검사·실적·LOT/공정이동표)이 등록되고, WIP가 다음 공정으로 이동·재공 관리된다.

- 결과: WO 단위 제조이력·투입실적이 등록되어 제조이력관리로 연계

**시나리오 2 — 작업자→관리자 호출**
- 액터: 현장 작업자
- 사전조건: 작업 중 이상 상황 발생, 관리자 지원 필요
- 단계:
  1. (작업자) 단말기에서 관리자 호출(Call 전달) 요청 → (시스템) 호출 상태=미해제로 설정, Call 정보를 관리자에게 전달
  2. (작업자) 상황 종료 후 호출 해제 → (시스템) 호출 상태=해제로 갱신
- 분기·예외: 단말기에서 호출 해제 가능
- 결과: 호출 상태가 해제 전까지 유지되어 관리자 대응 누락 방지

**시나리오 3 — 관리자→작업자 전달사항 공지·확인**
- 액터: 생산관리자
- 사전조건: 작업자에게 전달할 지시·공지 발생
- 단계:
  1. (관리자) 전달사항·대상·Message 입력·저장 → (시스템) 현장PC에 Popup 표시, 작업지시 연계
  2. (작업자) Popup 확인 → (시스템) 확인 이력 저장(DB)
- 분기·예외: (없음)
- 결과: 전달사항이 현장에 즉시 전달되고 확인 여부가 이력으로 남음

  3. (품질담당) 합격 처리 → (시스템) 합격품 자재LOT을 생성하고 바코드를 발행, Lot Status를 Release로 전환하며 합·불 수량을 ERP로 연계

- 결과: 수입검사 결과·성적서·자재LOT 생성, 바코드 발행/부착으로 입고 진행

- 결과: 출하검사 결과·성적서·납품라벨, 합·불 수량 ERP 연계 후 출하

  2. (품질담당) 관리선 대비 측정값 추이를 확인 → (시스템) 관리선 이탈 구간을 모니터링 표시

### 사용 시나리오
> 사용자(액터)가 이 모듈 기능을 사용하는 시나리오. 단계 = (액터) 행동 → (시스템) 반응.

**시나리오 1 — 금형ID 스캔으로 누계타발수 확인 후 교체 판단**
- 액터: 현장 작업자
- 사전조건: 툴 기준정보(사용한도·Cavity·적정타수)가 등록되어 있고, 생산 중 금형이 설비에 장착되어 있음
- 단계:
  1. (작업자) 현장에서 금형ID를 스캔 → (시스템) 해당 툴의 사용이력·누계타발수 조회 표시
  2. (설비/계수기) 타발수를 자동 수집(수동 입력도 가능) → (시스템) 누계타발수 집계, 적정타수 대비 사용가능타수 산출
  3. (작업자) 사용가능타수 확인 → (시스템) 사용한도 대비 누적 사용량을 비교해 한도 초과 여부 표시
- 분기·예외: 사용한도/적정타수 초과 → 툴 교체·보전 트리거 / 자동수집 미연동 구간은 작업자가 사용실적(생산량 기준)을 수정·보완 입력
- 결과: 누계타발수·사용가능타수 갱신, 한도 초과 시 교체·보전 대상으로 식별

**시나리오 2 — 보전 오더 생성과 PM 실적 기록**
- 액터: 설비담당(보전 담당자)
- 사전조건: 금형 기준정보·보전계획(수리주기·적정타수·Cavity)이 등록되어 있고, 사용이력(타발수·누계)이 수집된 상태
- 단계:

  3. (설비담당) 다음 PM 시점 확인 요청 → (시스템) 마지막PM수량·다음PM수량을 산출해 차기 PM 시점 제시
- 분기·예외: 보전유형(점검/예방 등)에 따라 항목 분기 / 적정타수·사용가능타수 초과 시 보전 트리거 발생

**시나리오 1 — 자재 입하·수입검사·입고 처리**
- 액터: 현장 작업자(자재창고)
- 사전조건: ERP 발주에 대한 공급사 입하분이 도착, 수입검사 대상으로 등록됨
- 단계:
  1. (작업자) 입하 자재를 수입검사관리(입하) 화면에서 검사 대상으로 호출 → (시스템) 공급사·상품·외주 입하품 정보와 검사 항목을 표시
  2. (작업자) 수입검사 결과·성적서를 입력 → (시스템) 합격 시 입고 대상으로 전환, 불합격 시 반품(공급사) 분기 처리
  3. (작업자) 합격품 입고를 확정 → (시스템) 자재LOT 생성, 바코드 라벨(인식표)을 발행
  4. (작업자) 바코드 라벨을 부착하고 PDA로 적치 Location을 스캔 → (시스템) 입/출/재고를 LOT·Location 단위로 기록
- 분기·예외: 불합격→공급사 반품(반품관리), 잔량반품 처리, 외주품은 제품입고 시점에 수입검사
- 결과: 합격 자재가 LOT·바코드·Location 기준으로 적치되어 출고 가능 상태가 됨

**시나리오 2 — 제품 출하 Picking·출하검사·Packing**
- 액터: 현장 작업자(제품창고)
- 사전조건: ERP 출하지시가 수신되고 출하 대상 적치품이 제품창고에 존재
- 단계:
  1. (작업자) 출하지시 기준으로 Picking & Packing 화면에서 대상품을 Picking → (시스템) 출하지시·대상 LOT을 매칭해 Picking 목록 제시
  2. (작업자) 출하작업 후 출하검사 결과·성적서를 입력 → (시스템) 합격 시 납품라벨 출력 단계로 진행
  3. (작업자) 납품라벨을 출력하고 생산LOT과 Matching → (시스템) 라벨-생산LOT 일치 여부를 판정, 일치 시 부착 허용
  4. (작업자) Packing 후 Pallet/바코드 사진을 등록하고 출하 확정 → (시스템) 출하품·납품라벨·재고를 갱신
- 분기·예외: 라벨-생산LOT 불일치 시 부착 차단, 고객 클레임/부적합→반품입고→클레임 결과 입고
- 결과: 출하품이 납품라벨·생산LOT 검증을 통과해 고객사로 출하되고 재고가 반영됨

**시나리오 1 — 자재 결품 조기경보 수신·드릴다운 (Early Warning System)**
- 액터: 생산관리자
- 사전조건: EWS 대시보드 가동 중, 자재·생산·작업지시 정보가 수집되고 있음
- 단계:
  1. (생산관리자) EWS 대시보드를 연다 → (시스템) 6대 영역(자재/생산/공정/품질/설비/출하) Warning 현황을 표시한다.
  2. (시스템) 시간대별(1H~7H) 재고 추이를 시뮬레이션해 현재고-누적소요가 음수에 도달하는 품목을 결품으로 판정하고, 결품수량/시점/리드타임/업체와 부족수량을 자재 이상 경보로 띄운다.
  3. (생산관리자) 자재 이상 경보를 더블클릭한다 → (시스템) 해당 품목의 BOM 자품목으로 드릴다운해 상세를 보여준다.
- 분기·예외: 6대 영역별로 결품/진행이상/Bottle Neck/KPI/설비/출하로 경보가 분기된다. 품질·설비 이상은 설비 제어와 연동된다.
- 결과: 관리자가 결품 예상 시점·수량·업체·리드타임을 사전 인지해 대응한다.

**시나리오 2 — 품질 관리도 패턴 이상 경보 확인 (Nelson Rule)**
- 액터: 품질담당
- 사전조건: 측정값 시계열(UCL/X̄/LCL, ±1~3σ)이 관리도로 수집되고 있음
- 단계:
  1. (품질담당) 품질 이상 예시 화면(관리도)을 조회한다 → (시스템) 측정값 시계열을 Nelson 8 Rule로 판정한다.
  2. (시스템) Rule 위반 패턴(예: ±3σ 이탈, 9개 동일면, 6개 연속 증감 등)을 감지하면 Rule 위반 경보와 관리도를 표시한다.
- 분기·예외: Nelson 8 Rule 각 패턴별로 위반 판정이 분기된다.
- 결과: 품질담당이 관리도 패턴 이상을 조기에 인지한다.

### 상태전이 모델

**Action 기반(자재·LOT 흐름) — 단계별 Lot 발행/스캔:**
```
[자재창고 입고(자재LOT 발행)] → [자재출고(Lot분할/합병→재발행, Lot스캔)]
  → [작업창고 입고(Lot스캔)] → [자재 투입(Lot스캔)]
  → [생산실적(Lot스캔 + 금형ID 스캔→타발수, 생산LOT 발행)]
  → [제품입고(포장분할/합병, 포장라벨 발행)] → [제품출하(포장라벨 스캔)]
  → [자품목 출고(외주·일반, Lot스캔)] → [재고 실사(자재/제품창고)]
```
LOT 생명주기(작업실적): `W/O 선택(생산LOT 선발행) → 작업/LOT 시작 → 자원투입·실적·불량·비가동·검사 → 작업/LOT 종료 → W/O 마감`

**Process 기반(제품 출하 흐름):**
```
[ERP 출하지시] → [제품창고 Picking] → [출하작업] → [출하검사(OQC)]
  → 합격 → [납품라벨 출력 + 생산LOT Matching] → 일치 → [라벨 부착]
  → [Packing(Pallet/바코드 사진)] → [출하] → [고객사]
                                        └ 부적합/클레임 → [반품입고] → [클레임 결과 입고]
```
Lot Status 전이(품질): `검사 전 Hold → 양호 Release / 불량 Hold 유지(부적합)`
