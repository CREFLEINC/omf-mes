## §1. 배경 — 무엇이 충돌했나

기존 확정(2026-06-24 결정·QA #13·설계결정 09): **생산LOT은 W/O 배포 시 선발행**되고, 그 레코드 자체가 "양품수·불량수" 두 필드를 함께 보유 — 즉 **불량도 그 생산LOT의 속성으로 집계**되는 구조였다(개념데이터모델 v2.4 §2 line 207).

사용자 의견: "생산LOT에는 PQC를 통과한 양품만 담아야 한다. 불량·의심자재는 완료되지 않은 것으로 보고 생산LOT에 등록하지 않는다." → 검증 결과 기존 결정과 **정면 충돌** 확인(자세한 대조는 대화 로그 참조). **본 문서에서 새 정책으로 확정, 기존 결정을 대체한다.**

## §2. 확정 결정 사항 (11건 — #5 폐기)

| # | 항목 | 결정 |
| --- | --- | --- |
| 1 | 선발행의 의미 | **번호(슬롯) 예약일 뿐, 실물 등록이 아니다.** 생산LOT은 W/O 배포 시 선발행(상태=대기)되지만, 그 시점엔 아무 실물도 귀속되지 않는다. |
| 2 | 생산LOT 필드 | **불량수 필드 삭제.** 생산LOT의 기록된 제품 수량 = 실적 중 양품 수뿐. |
| 3 | 생산불량LOT 신설 트리거 | **PQC 판정 불량 + 현장 발견 불량 + 의심자재(판정 보류) 모두 포함.** 세 원천 전부 생산불량LOT行을 만든다. |
| 4 | 원천 구분 | 생산불량LOT은 **원천별로 개별 채번**(원천 혼재 불가 — LOT당 단일 원천값). PQC 불량 10개=1LOT, 현장 불량 10개=별도 1LOT. |
| 5 | 크기 분할 | ~~생산불량LOT도 생산LOT처럼 단위 크기로 분할되어 여러 건 생성 가능. 예: 총 불량 20개·단위 10개면 2건 생성.~~ **(기존 서술 폐기: 2026-07-16 B-7·B-8로 대체) — 단위 크기(기본값+override) 개념 없음. 수량 = 실제 불량 수량을 발생 시 직접 입력, 채번 = 불량 발생 즉시 1건씩(원천 이벤트 1건당 생산불량LOT 1건·수량 N). ✓확정 2026-07-16 |
| 6 | 생산LOT과의 관계 | **생산LOT을 경유하지 않는다 — W/O 직접 귀속**(생산LOT과 형제 관계, 동일 위치). |
| 7 | 재작업 후 재투입 | 재작업 성공분은 **다시 PQC 투입 → 생산LOT에 등록**되며, 이때의 생산LOT은 **재투입 시점에 진행 중인 W/O의 생산LOT**(원래 소속 LOT과 무관). |
| 8 | 의심자재 Release | 의심자재 판정이 나중에 Release(불량 아님 확정)되면 **생산LOT으로 복귀**(재작업 성공과 동일 패턴 — 그 시점 진행 중인 생산LOT에 재등록). |
| 9 | 재투입 이력 추적 | 생산불량LOT에 **"재투입된 생산LOT No" 참조 필드 보유** — 수리 공정 왕복 추적(REQ-OA-0004)과 연결. |
| 10 | Lot Status 적용 | 생산불량LOT은 **Lot Status(Hold/Release/한도승인/특채/폐기) 비대상.** 자체 "처분구분(재작업/폐기)" + "상태" 필드만으로 관리. |
| 11 | W/O 실적 집계 | **작업실적 = W/O 실적 = 생산LOT 포함 제품 수(양품) + 생산불량LOT 포함 제품 수(PQC 불량·현장 발견·의심자재 전부 합산).** |

**용어 확정(✓확정 2026-07-16)**: 5번 답변의 "확인 불량" = 1번 답변의 "현장 발견 불량"(현장에서 작업자가 확인한 불량). 원천 열거형 표기는 **"현장 발견"으로 통일**한다(다른 문서는 이미 "현장 발견"/"현장" 사용 — 파급 없음).
