## 0. 사용법 · 범위 · 발견 방법

**이 문서의 위상**: 원본(v0.3)의 *커버리지 체크리스트 + 현행 가설* 골격을 유지하되, 2026-07-01 요구사항 명세서 47건으로 **검증·확정된 지점을 반영한 재정리본**이다. 이 도메인은 트랜잭션(입출고·실적)보다 **마스터 데이터 + ERP↔MES 연계**가 핵심이라, 단계를 사건의 시계열이 아니라 **"등록 → 연계 → 변경 → 통제"** 흐름으로 구성한다. 각 단계의 Medium·Pain 중 명세서가 답하지 않은 것은 여전히 전형적 제조 SME(ERP+엑셀+레거시) 기준 추정이며, **UNIMES 제안서(벤더 To-Be)에 앵커링하지 않는다** — 마스터 목록만 데이터모델에서 빌려오고, *정본이 어디에 있고 어떻게 동기화되느냐*는 개방형으로 듣는다.

**이 도메인이 던지는 핵심 질문(반증할 가설의 축)** — 명세서 반영으로 판이 바뀌었다:
1. **정본이 어디인가** — ~~BOM·Routing은 ERP 정본이 거의 확실(L1)~~ → **Routing/공정은 ERP에 정보가 없는 경우가 실재 전제로 확인돼 정본=MES로 확정**(충돌①, REQ-PR-0026 요구 · REQ-PR-0002 요구). **툴(금형·지그)도 ERP 미사용·엑셀 관리 현행이 확인돼 정본=MES**(충돌③, REQ-PR-0003 현행·요구). BOM은 **ERP 정본(L1)·버전(Rev) 관리 확정**(✓확정 2026-07-04 QA #3 — 잔여: 유효기간 관리 여부 스키마 확인, 방침=MES 선택(optional) 속성) (기존 서술 폐기: Routing 전례를 고려한 ERP 보유 재확인 필요). **검사 기준정보 정본(B5)은 MES 정본으로 종결**(✓확정 2026-07-04 QA #4 — As-Is 엑셀 문서 → DX 마이그레이션) (기존 서술 폐기: 명세서 무응답으로 미정 유지) — BOM과 검사기준을 같은 'ERP 정본'으로 묶으면 안 된다는 원칙이 사실로 검증됐다.
2. **연계가 어떻게 도느냐** — **ERP=UNIERP · 연계=DB 중계 테이블 방식 확정**(✓확정 2026-07-04 QA #18 — D18 종결) (기존 서술 폐기: 통신방식 XML/File/DB/Web/FTP 미확정·모듈별 상이 가능). 잔여는 Time Schedule(주기)/Event(즉시) 트리거·중계 테이블 스키마·재처리 등 운영 설계. 연계 실패·지연(타이밍 갭)을 현장이 어떻게 메우나. **추가: 추적관리시스템(자사 개발 — OA 생산·포장·출하 3단계 제품 바코드 이력)과 병행 운영+연계 확정 — 역할·데이터 경계 정의=설계 과제**(✓확정 2026-07-04 QA #18·#19). 현장 네트워크 불안정으로 생산 중단이 빈번하다는 현행은 확인됐다(REQ-OA-0005 현행 — 단 추적관리시스템 계층).
3. **연계분을 못 고치면 무슨 일이 벌어지나** — 연계분(Legacy 출처) 기준정보 MES 수정/삭제 불가 원칙(근거p53·54)은 **잔존 연계분(품목·BOM·코드·조직·작업자·설비·작업지시 등)에 한정**된다. 공정·툴·Location 등 MES 정본 마스터는 수정 가능(+변경 이력 필수)으로 경계가 재정의됐다(REQ-PR-0002·0003·0021 요구). **최종 확정: 연계 수신본(품목·BOM·P/O)의 원본 필드=읽기 전용, MES 정본 마스터 전체+MES 확장 속성(개발품 플래그·재생재 하위 코드 등)=수정 가능+변경 이력 필수**(✓확정 2026-07-04 QA #34).

**범위(IN)**: 신규 품목 등록 → BOM 등록/변경(Rev·유효기간) → Routing/공정 등록(MES 정본·CRUD) → 검사항목(검사기준) 등록 → 설비·툴·작업자·창고/Location·공통코드 마스터 → ERP→MES 연계 동기화(Time Schedule/Event) → 변경관리(잔존 연계분 수정·삭제 불가 / MES 정본분 수정+이력) → 사용자 권한 관리(+POP 사번 경량 인증).
**범위(OUT, 별도 워크플로우)**: 실적·트랜잭션 전체(자재창고·생산실행·품질·설비/툴·출하 등 타 문서). MES→ERP 역방향 송신의 *실행·트랜잭션*(타 문서 — 출하 후 ERP 반영 요구는 확인됨, REQ-PR-0030 요구) — 단 **송신 연계 스펙(대상·방식·항목별 on/off)은 S7에서 확정 반영**(✓확정 2026-07-04 QA #4·#6). 경계로 맞닿는 지점만 🔗로 표시.

**발견 방법(현장)**: ① **1품목 추적**(실제 신규 품목 1건을 품목 등록 → BOM → 공정(MES) → 검사기준 → 연계 → W/O 사용까지 따라가기) ② 관찰(말이 아니라 실제 동작 — 잔존 연계분 수정이 *정말* 막히나, 연계 실패 시 *실제로* 어떻게 메우나, 공정 정보 없이 *실제로* 어떻게 계획을 세우나) ③ 실물·데이터 수집(ERP 마스터 스키마(품목·BOM) · MES 마스터 스키마+덤프 · I/F정의 테이블 · 연계 로그 · 검사기준 정본 화면 · 권한 화면 · **툴 관리 엑셀 대장**(REQ-PR-0003 현행 — 마이그레이션 소스) · **세분화 공정 수기 기록 실물**(REQ-PR-0002 현행)). 각 단계 끝 **[Check(확인)]** 에 관찰·수집·질문 포인트.

**검증 렌즈(2026-06-26 재정리 → 2026-07-03 갱신)**: 마스터별로 ERP 소유 정도가 차등이다.
- **L1 — ERP 정본 기준정보**: BOM(B1) — **ERP 정본·Rev 관리 확정**(✓확정 2026-07-04 QA #3, 잔여: 유효기간 컬럼 스키마 확인) (기존 서술 폐기: ERP 보유 여부 재확인 필요). ~~Routing/공정(B2)~~ → 충돌①로 L2 이동.
- **L2 — 소유·정본 조율(대면 필수)**: ~~검사기준 정본(B5, 미해소)~~ → **MES 정본 종결**(✓확정 2026-07-04 QA #4) · ~~연계 발번/소유(D18·I/F)~~ → **UNIERP·DB 중계 테이블 확정**(✓확정 2026-07-04 QA #18) · **B2(Routing 정본=MES 확정 · 키 설계도 종결 — 품목코드×Routing Rev 헤더+Sequence 라인, ✓설계확정 2026-07-06 결정 07)** · 권한 편입(D1 — 편입 확정, 입도 잔여=고객 액션 E9 회수 대기). **핵심 쟁점이던 B5·D18이 모두 종결돼 잔여는 내부 설계와 고객 회수 대기로 이동했다** — 내부 설계로 이동한 설계 결정 전환분은 2026-07-06 내부 설계 결정서로 전 건 확정됐다.
- **L3 — MES 내부 키·정규화**: 이력성 엔티티 키(B6 — 현행 체계 부재(엑셀) 확인으로 신규 설계 재량 전환, REQ-PR-0003 현행) 등. *MES DB 스키마+덤프* 및 신규 설계 결정으로 해소.

## S1. 공통코드 · 조직 마스터 등록

- **Trigger(촉발)**: 프로젝트 초기 코드체계 정의 / 신규 거래처·조직·코드값 추가.
- **Actor(주체)**: 전산(ERP 연계)담당 · 운영자(표준화 TFT).
- **Action(행위)**: 코드그룹+코드값 정의, 코드명·정렬순서·사용여부(Y/N) 등록. "회계=물류=생산 동일코드" 표준 적용. **코드명·마스터 명칭에 다국어(한국어·베트남어) 속성 등록** — ✅ 시스템 전반 한/베 지원 요구 (REQ-PR-0012 요구). **적용 범위=전범위 확정: UI + 마스터 명칭(한/베) + 출력물(라벨·보고서) 언어 선택, 언어는 사용자별 설정(역할 고정 아님 — 베트남인 관리자급 존재)** (✓확정 2026-07-04 QA #33 — E23 종결). 판정유형 코드(S5 참조) 등 신규 코드그룹 후보 포함.
- **Input(입력)**: ERP 코드 마스터, 표준화 정의(코드정의서).
- **Medium(매체)** 🟡: *가설* — 코드 정본은 **ERP**, MES는 연계 수신. 신규 코드는 ERP 등록 또는 **엑셀 코드정의서** 경유 추정. (열림↔갇힘: ERP·MES·엑셀 3곳에 코드가 흩어지면 끊김) 단, **다국어 명칭은 ERP 정본 코드명과 별개로 MES가 보유** — 마스터 편집 정책(연계 원본 읽기 전용+MES 확장 속성 편집, ✓확정 2026-07-04 QA #34)에 따라 다국어 명칭=MES 확장 속성으로 편집 (기존 서술 폐기: 소유 구분 확인 필요).
- **Result(결과)**: 공통코드 마스터(코드그룹+코드값+다국어 명칭) 생성 — 다른 모든 마스터·트랜잭션의 참조 기반.
- **Rule(선행조건·규칙)**: 코드체계 표준(회계=물류=생산 동일코드 원칙, 근거p18·20·24·27). ERP-MES I/F 연계대상에 '코드·조직' 포함. 시스템은 한국어·베트남어를 **전범위(UI·마스터 명칭·출력물)**로 지원하며 언어는 사용자별 설정이다(REQ-PR-0012 요구 · ✓확정 2026-07-04 QA #33).
- **Exception(예외·선행조건 미충족)** 🟠: ① **ERP↔MES 코드 체계 상이**(자릿수·구분자·그룹 다름) → 매핑 테이블 필요? ② 신규 코드 **MES 선등록**(연계 전 현장이 임시 코드 사용) ③ 사용여부 N 코드를 트랜잭션이 참조 ④ **다국어 명칭 미등록 코드**(한쪽 언어만 존재) 시 화면 표시 규칙. [확인] 코드 매핑 방식, 임시코드 사후 정합.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 코드가 ERP·MES·엑셀에 분산, 매핑표 수기 관리, 동일코드 원칙이 실제론 안 지켜짐.
- **Boundary(경계)** 🔗: **ERP → MES**. 코드 정본 = ERP. "회계=물류=생산 단일코드" 경계(ERP 모듈 간). **ERP 정본 코드명 ↔ MES 다국어 명칭의 소유 분담**(REQ-PR-0012).
- **Open-Issue(연계 미결)**: ~~D18(연계 통신방식)~~ → **종결: UNIERP·DB 중계 테이블**(✓확정 2026-07-04 QA #18) · ERP-MES I/F 연계대상(코드·조직 — 중계 테이블 스키마 상세) · ~~다국어 명칭의 소유·적용 범위~~ → **종결: 전범위(코드·품목명 등 마스터 명칭 전반 포함)·사용자별 언어·다국어 명칭=MES 확장 속성**(✓확정 2026-07-04 QA #33·#34).
- **[Check(확인)]**: 코드 정본이 *어디* 있나(ERP? MES? 엑셀?). ERP↔MES 코드 매핑표 존재 여부. 동일코드 원칙 실태. ~~다국어 명칭을 어디에 실을지~~ → **확정: MES 확장 속성 · 전범위 · 사용자별 언어**(✓확정 2026-07-04 QA #33·#34) — 잔여: ERP 코드명의 언어 실태(한국어/베트남어)만 확인.

## S2. 품목(Item) 신규 등록

- **Trigger(촉발)**: 신규 품목(자재/반제품/제품/상품/**개발품**) 발생 — 신규 수주·신규 자재 소싱·**시제품(개발품) 개발**(REQ-PR-0033 요구).
- **Actor(주체)**: 전산담당 · 생산관리자 (+구매).
- **Action(행위)**: 품목코드 채번, 품명·품목구분·단위(UoM)·규격·사용여부·**생산LOT 기본크기(양품 목표 수량)** 등록.
  - **개발품(시제품) 플래그 = MES 확장 속성 확정** — ERP에 품목은 존재하나 '개발품' 정보가 없어 **ERP 수신 정보만으로는 판별 불가**, MES에서 플래그를 지정(연계 원본 필드 읽기 전용+MES 확장 속성 편집)하고 **ERP 생산 실적 송신 대상에서 제외**한다 (✓확정 2026-07-04 QA #35 — E28 종결) (기존 서술 폐기: '품목구분에 개발품 추가' 안 — 품목구분은 ERP 연계 원본이라 MES 임의 추가 불가). ✅ 시제품 항목 관리·개발품 작업 계획서 요구 (REQ-PR-0033 요구). 개발품 W/O 전개는 생산실행 문서(WF02)와 경계 공유.
  - **생산LOT 기본크기** ✅ — 기본 수량 값을 사용하되 **트랜잭션 시점 수정 가능(LOT 수량 고정 X)** (REQ-PR-0008 요구). 기존 '기본크기 등록' 설계가 실사용과 일치하되 override 허용 요구가 추가됐다. **적용 대상 확정: 자재·생산 양쪽 — 품목(자재)별 자재LOT '보관 단위(수량·무게) 기본값' + 특이 시 개별 수량 설정(override)** (✓확정 2026-07-04 QA #14 — E26 종결, 혼적(입고—자재LOT 1:N) 실재 확인).
  - **재생재 코드 2단 구조 확정 — 품목 코드=ERP 동일 코드 1개(신재·재생 공통) + 하위 코드(예: 생산처 코드)로 MES 내부 구분** (✓확정 2026-07-04 QA #31 — E19 종결) (기존 서술 폐기: 'MES 전용 원산 구분(신재/재생) 속성 신설' — 하위 코드 구조로 구체화). **하위 코드=비노출 축**: ERP 동기화 제외+고객사 향 문서·라벨·보고서 제외+MES 일반 화면 숨김(권한 관리자만 조회), genealogy는 하위 코드 포함 완전 기록. 재사용/분쇄 자재는 이후 절차에서 신재료와 같은 코드로 관리하되 외부(고객사·회계)에서 확인되지 않아야 한다 (REQ-PR-0031 요구). **설계 원칙: '외부 비노출' ≠ '내부 미기록'** — MES 내부 genealogy(재생재→생산LOT 투입 추적)는 유지하고 ERP·고객사 연계 계층에서만 필터링한다. 내부까지 기록을 끊으면 품질 이슈 역추적이 불가능해진다.
  - **품목 유효기한 관리 플래그 + 선출 정책 신설** — 유효기한 관리 품목=FEFO, 나머지=FIFO(품목별 설정). **유효기한 관리 자재 실존 확인**. 자재LOT에 유효기한 속성 병행 (✓확정 2026-07-04 QA #28 — E16 종결).
- **Input(입력)**: ERP 품목 마스터, 신규 품목 정보.
- **Medium(매체)** 🟡: *가설* — **ERP 정본 등록 → MES 연계 수신**. 단 모델상 생성주체 'MES System' 표기가 혼재(근거p55) — 누가 채번하는지 ⚠. (자재LOT 발번은 MES로 확정됐으나 품목 채번 주체는 별개 — 아래 Open-Issue)
- **Result(결과)**: 품목 마스터 생성(키=품목코드). **BOM·Routing·검사·LOT·전 트랜잭션의 참조 백본**.
- **Rule(선행조건·규칙)**: 회계=물류=생산 동일 품목코드. ERP-MES I/F 연계대상에 '품목'. 품목 마스터가 BOM·Routing·검사·LOT의 참조 백본 — 품목 선등록이 후속 마스터의 선행조건. 생산LOT은 기본 수량 값 사용+수정 허용(REQ-PR-0008 요구) — 자재LOT도 품목별 보관 단위(수량/무게) 기본값+override(✓확정 2026-07-04 QA #14). 품목 유효기한 관리 플래그+FEFO/FIFO 선출 정책(✓확정 2026-07-04 QA #28). 개발품 플래그=MES 확장 속성·ERP 생산 실적 송신 제외(✓확정 2026-07-04 QA #35). 재사용/분쇄 자재는 신재료와 동일 품목 코드+MES 하위 코드로 내부 구분·외부 비노출(REQ-PR-0031 요구 · ✓확정 2026-07-04 QA #31).
- **Exception(예외·선행조건 미충족)** 🟠: ① **신규 품목 미등록 상태로 생산/입하 발생**(BOM·Routing·검사기준도 동반 미등록 → S2~S5 연쇄 갭) → 임시 품목/차단? ② **ERP↔MES 품목 불일치**(코드·구분·단위 상이) ③ 품목구분 오등록(자재를 제품으로) ④ 사용여부 N 품목에 트랜잭션 발생 ⑤ **개발품을 양산 품목구분으로 등록**(개발품 전용 흐름·실적 분리 실패, REQ-PR-0033). [확인] 미등록 품목 현장 처리, 사후 ERP 매칭.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 신규 품목 등록 리드타임 길어 현장이 임시코드·수기 처리, ERP-MES 품목 싱크 지연.
- **Boundary(경계)** 🔗: **ERP(UNIERP) → MES**. 품목 정본 = ERP(수신 확정 목록 포함 — QA §3.1·§3.2 2026-07-04). 생성주체 'MES System' 표기 충돌(근거p55)은 **A1 완전 확정으로 해소 — LOT 3종=MES 발번, 품목=ERP 정본 유지**(✓확정 2026-07-04 QA #1). **재생재 = 품목코드(ERP 동일)+하위 코드(MES 내부) 2단 구조**(✓확정 2026-07-04 QA #31) — 동일 품목코드 원칙(회계=물류=생산)과의 정합은 하위 코드 축으로 해소 (기존 서술 폐기: 정합 방식이 경계 쟁점, REQ-PR-0031).
- **Open-Issue(연계 미결)**: ⚠ **A1 완전 확정** — 자재LOT 2단계 모델('LOT 번호 사전 발행'(REQ-PR-0001 요구)+'LOT 생성=IQC 합격 시점'(REQ-PR-0007 요구))에 더해 **제품LOT 발번 주체=MES(LOT 3종 전부 MES 발번) · ERP G/R=IQC 합격 직후 건별 즉시 연계 확정**(✓확정 2026-07-04 QA #1 — §8.A.1 종결) (기존 서술 폐기: 제품LOT 발번 주체·G/R 시점 잔여). ~~D18~~ → 종결(UNIERP·DB 중계 테이블, ✓확정 2026-07-04 QA #18) · ~~재생재 정합 방식~~ → 종결(하위 코드 2단 구조, ✓확정 2026-07-04 QA #31) · ~~REQ-PR-0008 적용 대상~~ → 종결(자재·생산 양쪽 '기본값+수정 가능', ✓확정 2026-07-04 QA #14 — E26 해소). 잔여: ERP-MES I/F(품목) 중계 테이블 상세 · 사전발행 번호와 IQC 생성의 정합(내부 설계).
- **[Check(확인)]**: 품목 등록을 *ERP에서* 하나 *MES에서* 하나. '생성주체 MES System'의 실제 의미. 신규 품목 미등록 시 현장이 어떻게 도나(임시코드/차단/구두). ~~개발품(시제품)을 현행 품목 체계에서 어떻게 구분하나~~ → **확정: ERP에 개발품 정보 없음 — MES 확장 속성 플래그 지정**(✓확정 2026-07-04 QA #35). ~~재사용/분쇄 자재의 현행 코드 실태~~ → **확정: 품목코드+하위 코드(생산처) 2단 구조**(✓확정 2026-07-04 QA #31 — 잔여: 하위 코드 값 체계는 내부 설계). ~~LOT 기본수량 override의 적용 대상~~ → **확정: 자재·생산 양쪽**(✓확정 2026-07-04 QA #14).

## S3. BOM 등록 / 변경 (Rev · 유효기간)  — L1(ERP 정본 ✓확정 — 유효기간만 잔여)

- **Trigger(촉발)**: 신규 품목 BOM 정의 / 설계변경(E/O)·자재 대체 → BOM Rev 변경 / **러닝체인지(생산 도중 부품 교체)**(REQ-PR-0020 요구).
- **Actor(주체)**: 생산관리자 · 전산담당 (+설계/구매).
- **Action(행위)**: 부모-자품목 구성·소요량·단위·**BOM Rev·유효기간** 등록/개정.
- **Input(입력)**: ERP BOM 마스터, 설계 BOM/E/O 통지.
- **Medium(매체)** ✅: **ERP 정본(L1) → MES 연계 수신 확정 — BOM은 ERP에 있고 버전(Rev) 관리가 존재한다** (✓확정 2026-07-04 QA #3) (기존 서술 폐기: Routing 전례를 고려한 ERP 보유 여부 재확인 필요 — 보유 확인으로 해소). 잔여: **유효기간 관리 여부는 ERP 스키마 확인 필요 — 방침: 필수 아니면 MES에서 선택적(optional) 속성으로 사용**(QA #3). 식별자(BOM No vs 부모+자품목+Rev)는 스키마 확인 대상 유지.
- **Result(결과)**: BOM 마스터 생성/개정. **결품 시뮬레이션·자재예약 전개 기준**(근거p79) + ✅ **자재 출고 요청 자동 발행의 소요량 산정 기준**(작업 지시서 생성 완료 → 자재 출고 요청서 자동 발행, REQ-PR-0022 요구) + ✅ **Routing 부재 시 4M 투입 계획의 대체 전개 기준**(REQ-PR-0026 요구).
- **Rule(선행조건·규칙)**: 품목 등록돼야 BOM 등록. BOM은 Rev로 버전관리(Rev 관리 실재 — ✓확정 2026-07-04 QA #3) · 유효기간은 확인 잔여(방침: MES 선택 속성, QA #3). ERP 정본 가설 시 연계분 MES 수정/삭제 불가(잔존 연계분 원칙 — S8). W/O 자재 소요 전개·출고요청 자동 산정은 BOM 기준(REQ-PR-0022 요구).

## S4. Routing / 공정 등록 (MES 정본 · CRUD)  — L2(MES 키 설계)

> **충돌① 반영 — 기존 가설 폐기: "ERP 정본(L1) → MES 연계 수신"은 명세서로 뒤집혔다.** 고객 ERP에 공정(Routing) 정보가 없는 경우가 실재 전제이며, MES 공정 정보 관리 기능이 확정 요구다(REQ-PR-0026 요구). 세부 공정의 추가/삭제/수정도 MES에서 가능해야 한다(REQ-PR-0002 요구).

- **Trigger(촉발)**: 신규 품목 Routing 정의 / 공정 변경 → **신규 Routing Rev 발행**(명칭 '공정Ver'→'Routing Rev' 통일 — ✓설계확정 2026-07-06 결정 07) / 세부(세분화) 공정 추가·삭제·수정(REQ-PR-0002 요구).
- **Actor(주체)**: 생산관리자 · 전산담당 (+생산기술).
- **Action(행위)**: ✅ **MES에서 품목별 공정 순서(라우팅 Sequence)·공정코드·외주공정 구분·Routing Rev(구 공정Ver — 결정 07)·표준 C/T·L/T·UPH·사용여부를 직접 등록·수정·삭제(CRUD)** (REQ-PR-0026 요구 · REQ-PR-0002 요구). 라인 속성에 **PQC 검사 공정 명시 플래그** 보유(QA #4 PQC opt-in의 근거 필드 — ✓설계확정 2026-07-06 결정 07). 단일 제품의 공정에 다수의 세분화 공정이 존재한다(예: 사출→조립→검사→부착→검사)는 현행 확인 (REQ-PR-0002 현행). 세부 공정별 생산 이력(생산량·자재 투입량·불량률 등) 관리의 기준 구조가 된다 — 이력 자체는 생산실행(WF02) 소관.
- **Input(입력)**: 공정 표준, 세분화 공정 정의(현행: 작업자 수기 기록, REQ-PR-0002 현행). (ERP에 공정 정보가 존재하는 품목이 있다면 수신 참조 — 선택 경로)

[확인] 외주공정·표준시간 입력 실태 (~~공정Ver 변경 시 진행 W/O 전환~~ → Rev 스냅샷으로 종결, 결정 07).
- **Pain/Wish(문제·요구)**: ✅ **세분화 공정의 생산 이력을 작업자가 수기 기록 중**(REQ-PR-0002 현행 — '한 화면에 모든 정보' 요구 병행). 🟡 *가설 잔존* — 외주공정 구분 누락, 표준시간 미입력으로 목표관리 공백.
- **Boundary(경계)** 🔗: **MES 정본** *(기존 가설 폐기: ERP → MES L1)*. ERP 공정 정보 존재 시 수신은 선택 경로 — 이 경우 ERP Routing과 MES 세부공정의 계층 관계(정본 분담)가 신규 쟁점. 공정 변경 → 진행 W/O·목표관리(C2·분해도 3.2.3) 경계 — 진행 W/O 측은 Rev 스냅샷으로 차단(결정 07). ## S7. ERP(UNIERP)↔MES 연계 동기화 (Time Schedule / Event · DB 중계 테이블)  — D18 종결 + 추적관리시스템 병행 연계

## S8. 변경관리 (Rev/Ver 전환 · 잔존 연계분 수정·삭제 불가)  — L2

> **적용 범위 재정의 — 충돌①③ 파생.** '연계분 MES 수정/삭제 불가' 원칙은 **잔존 연계분(품목·BOM·코드·조직·작업자·설비·작업지시 등 ERP 정본 유지분)의 원본 필드에 한정**된다. 공정(REQ-PR-0002 요구)·툴(REQ-PR-0003 요구)·Location(REQ-PR-0021 요구) 등 **MES 정본 마스터는 MES에서 수정 가능하되 변경 이력 필수**. **최종 확정 — 마스터 편집 정책(✓확정 2026-07-04 QA #34 — E27 종결): 연계 수신본(품목·BOM·P/O)의 원본 필드=읽기 전용 · MES 정본 마스터 전체+MES 확장 속성(개발품 플래그·재생재 하위 코드·다국어 명칭 등)=수정 가능+변경 이력 필수.** "$모든 정보 수정 가능"(REQ-PR-0021)의 범위='MES 정본 마스터 전체'로 확정 — 잔존 연계분 차단 원칙과 충돌 없음.

- **Trigger(촉발)**: 마스터 변경 필요(BOM Rev·Routing Rev(구 공정Ver — 결정 07)·품목 속성·검사기준 개정) / **현장이 MES에서 직접 수정 시도**.
- **Actor(주체)**: 전산담당 · 생산/품질담당 · 운영자.
- **Action(행위)**: **잔존 연계분**은 정본 시스템(ERP/QMS)에서 개정 → 연계 재동기화(S7), MES 직접 수정·삭제 **차단**. **MES 정본 마스터(공정·툴·Location 등)**는 MES에서 직접 개정 ✅ — 세부 공정 추가/삭제/수정(REQ-PR-0002 요구)·도구 정보 관리(REQ-PR-0003 요구)·Location 사용자 설정/수정(REQ-PR-0021 요구). 변경 이력 기록 병행.
- **Input(입력)**: 변경 요청, 정본 마스터, 진행 중 트랜잭션(W/O) 현황.
- **Medium(매체)** 🟡: *가설* — 잔존 연계분은 정본에서 개정 후 연계, MES는 조회·사용만. 변경 승인·이력 매체 불명(엑셀·구두 가능).
- **Result(결과)**: 마스터 개정(BOM Rev/Routing Rev/유효기간), 이력 보존. **진행 중 트랜잭션 영향**(구/신 버전 적용 시점 — 러닝체인지 시 계획 분할 방향 확정, REQ-PR-0020 요구·E4).
- **Rule(선행조건·규칙)**: **잔존 연계분(Legacy 출처)의 원본 필드는 MES 수정/삭제 불가**(근거p53·54 — 적용 범위를 잔존 연계분으로 한정, 충돌①③ 반영). **MES 정본 마스터는 수정 가능 + 변경 이력 필수**(REQ-PR-0002·0003·0021 요구 · ✓확정 2026-07-04 QA #34 — MES 확장 속성(개발품 플래그·하위 코드 등) 포함). BOM Rev·유효기간(선택 속성 방침 — QA #3)·Routing Rev로 버전 전환 — **Routing 수정=신규 Rev 발행(확정 Rev in-place 수정 금지·작성중 상태에서만 편집), W/O는 전개 시점의 Rev를 스냅샷 고정**(✓설계확정 2026-07-06 결정 07). 변경 시 진행 중 W/O 영향(Routing 축은 스냅샷으로 종결 — BOM 축 잔여).
- **Exception(예외·선행조건 미충족)** 🟠: ① **잔존 연계분을 현장에서 수정 시도 → 차단(의도된 동작)** → 우회로(엑셀·별도 메모)가 존재하나 ② **Rev/Ver 변경 시 진행 중 W/O가 구 버전 참조** → 전환 시점·소급 처리(러닝체인지는 계획 분할로 분리 — REQ-PR-0020 요구, 잔여는 S3·E4) ③ ~~MES 고유 보강 속성의 수정 허용 여부~~ → **확정: 연계 원본 필드=읽기 전용 · MES 확장 속성=편집 가능+변경 이력 필수**(✓확정 2026-07-04 QA #34) (기존 서술 폐기: '허용 필요로 기울었다' — 확정으로 전환). 필드 단위 경계='연계 원본 vs MES 확장' 구분 자체로 확정 — 잔여는 I/F 필드 목록 확정 시 기계적 적용 ④ 긴급 변경 시 ERP 미경유 MES 직접 입력. [확인] 차단의 실제 동작, 필드 단위 경계, 진행 W/O 전환.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 변경이 ERP에만 반영되고 MES 진행건 미반영, 차단된 항목을 엑셀·구두로 우회, 변경 승인·이력 추적 미흡.
- **Boundary(경계)** 🔗: **ERP/QMS(정본) → MES(잔존 연계분 수정 불가)** vs **MES 정본 마스터(수정 가능+이력)** — 마스터별 정본 소유에 따라 차단 경계가 갈린다(충돌①③). 변경 → 진행 중 W/O(C2).
- **Open-Issue(연계 미결)**: ⚠ B1 잔여(유효기간 스키마·Rev 키 — ERP 정본·Rev는 ✓확정 2026-07-04 QA #3) · ~~B2 재정의분(MES Routing 키 설계 — S4, 설계 결정 전환 QA §1 2026-07-04)~~ → **종결: 품목코드×Routing Rev 헤더+Sequence 라인 · 수정=신규 Rev 발행 · W/O Rev 스냅샷 고정**(✓설계확정 2026-07-06 결정 07 — 상세 S4) · 잔존 연계분 수정/삭제 불가 플래그 운용(연계분/MES 원천분 구분 플래그 — S7) · ~~D18~~ → 종결(UNIERP·DB 중계, ✓확정 2026-07-04 QA #18) · ~~"$모든 정보는 수정 가능" 적용 범위~~ → **종결: MES 정본 마스터 전체(연계 수신본은 읽기 전용) — 잔존 연계분 차단 원칙과 충돌 없음, 설계 의견 채택**(✓확정 2026-07-04 QA #34).
- **[Check(확인)]**: 잔존 연계분 수정 시도가 *실제로* 막히나(화면 시연). ~~MES 고유 속성 수정 허용 범위~~ → **완전 확정: 연계 원본 읽기 전용 + MES 정본·확장 속성 편집 + 변경 이력 필수**(✓확정 2026-07-04 QA #34) — 필드 단위 경계는 I/F 필드 목록 확정 시 적용. Rev 변경 시 진행 W/O 전환 규칙(~~Routing 축~~ → **종결: 전개 시점 Rev 스냅샷 고정**(✓설계확정 2026-07-06 결정 07) — BOM Rev 축 잔여). 변경 승인·이력 매체.
