## §2. 사이드 구조도 설계 — 「01.자재창고관리-사이드」

현 메인이 다루지 않는 자재창고 흐름을 **사이드 5열(A~E)** 로 설계한다. S10 반품과 S11 폐기는 열 수 한도(≤5) 준수를 위해 1열로 통합(E). S6 재고 보관·상태는 독립 열 없이 각 열의 차단 판정(Lot Status 참조)으로 반영.

**공통 제작 규칙** (도식 문법 = figjam-workflow-diagram SKILL.md):
- 신규 섹션 `01.자재창고관리-사이드`. 좌표는 오케스트레이터가 「새 섹션 배치」 절차로 산정(01 메인 하단 밴드는 02와 간격 200뿐이라 최하단 배치 예상). 그리드: 축 y=430(섹션 상대), 축 중심 간격 ~260, 체인 세로 스텝 ~190.
- 클론 킷 인스턴스만 사용(신규 드로잉 금지). 아이콘 라벨 ≤10자 · 헥사곤 ≤16자 · 스티키 ≤12줄 · 한국어.
- 색: 시작 상태·시작 커넥터=빨강 / 진행=검정 / 완료=파랑 / 행위 체인·데이터=초록 / 경계·대안=회색. 경계 위임=**회색 헥사곤 「→ NN 도식」**(03 관행: 사이드 진입 표기=회색 헥사곤, 데이터 노트=체인→MES(Server)→스티키 초록 배선).
- 도식에는 근거 마커(REQ/QA) 표기 금지 — 본 §2·§3에만.

## §5. 메인 개선 후보 (선택 — 그리지 않음, 목록만)

전사 중 발견한 현 도식의 보완 여지. 반영 여부는 사용자 판단.

1. **용어 정합(반품 노트)**: 노트 ④(3:3268) 「입고 번호/입고 정보」 — IQC 불합격 시점에는 LOT 미생성·입고 미발생이므로 「입하 번호/입하 정보」가 정합 (REQ-PR-0007·WF01 S3→S10).
2. **입하/입고 상태 용어 혼용**: 축 상태 「입하 완료 - 적치 대기」 vs 노트 ②(3:2111) 「상태 : 입고 완료」 — IQC 합격=입고(LOT 생성) 시점이므로 축·노트 간 용어 통일 여지.
3. **G/R 헥사곤(3:6692) 시점 병기**: 「합격품 한정, G/R 송신」에 '건별 즉시' 뉘앙스 추가 여지 (QA #1 — IQC 합격 직후 건별).
4. **미정의 마커 식별 코드 부재**: 3:6494·3:6587에 (U#) 라벨 병기 여지 (스킬 문법 예: "(U9) …" — 본 스펙 U-M1·U-M2와 대응).
5. **IQC 체인 2벌 중복**: 사전발행 라벨 유/무 경로가 Desktop·File 각 2개로 병렬 — 라벨 스캔 후 OR 합류로 단순화 여지.
6. **OR(3:5858)→자재 입하 목록(3:1781) 커넥터 2개(3:5932·3:6189)**: 정상/초과 병행 경로의 조건 라벨 구분이 없어 오독 여지 — 커넥터 1개 정리 또는 조건 라벨 보강 여지.
7. **S1 미도식 요소**: P/O 변경 이벤트(중단·수량 변경·강행 옵션 — REQ-PR-0024·QA #23)와 무발주 도착 인지 경로가 도식에 없음 — 커버 범위 밖 명시 유지 또는 추후 사이드 후보.
8. **라벨 길이**: 일부 아이콘 라벨이 문법 한도(≤10자) 초과(예: 「초과분만 별도 입하 정보 생성 (P/O 미등록)」·「보관 위치 코드 검증 스캔」) — 가독 문제는 없어 유지 무방, 문법 통일 시 축약 여지.
9. **메인→사이드 연결 표기**: 메인 「자재 반품」(3:2140)·「초과분 별도 입하」(3:6142) 옆에 회색 헥사곤 「→ 사이드 E」 추가 여지 (사이드 제작 후).
