## 0. 공통 문법 (01. 자재창고관리 도식과 동일) + 본 도메인 특칙

| 요소 | 도형/아이콘 | 규칙 |
| --- | --- | --- |
| 상태 박스 | Archive | 메인 축 상태. 시작=빨강 · 진행=검정 · 완료=파랑 |
| 작업자 | User | 메인 축에서 상태 박스와 교대 배치 |
| 행위 | Mobile(스캔·현장입력) / Desktop(화면) / File(기록) / Wallet(목록) | 초록 화살표로 상태·작업자에 연결. 라벨 ≤10자 |
| MES 노트 | Server + 초록 스티키 | 스티키 첫 줄 "KEY - …" 필수, ≤12줄 |
| ERP | Database + 조건 헥사곤 | **본 도메인 사용 금지 — §0 특칙 ① 참조** |
| 분기 | 검정 헥사곤 | 라벨 ≤16자 |
| 검증·합류 | OR(⊕) | 복수 경로 합류 지점 |
| 미정의 | 빨간 Email | 미확정·대기 사항 |
| 화살표 | 검정=주 흐름 · 회색=대안/생략 · 초록=행위 · 빨강=시작 | |

**본 도메인 특칙**

1. **ERP(Database) 아이콘 등장 금지.** 툴·금형·지그 마스터=MES 직접 등록·정본(I/F 연계 대상에서 툴 제외), 보전=EAM/CMMS 미보유로 MES 경량 단독 채번, 예비품=별도 MES 마스터. 설비·툴 도메인에는 ERP 연계 접점이 없다 — 도식에 Database 아이콘이 하나라도 있으면 오류.
2. **직선 흐름이 아니라 주기 루프.** [구성 판단] 이 도메인은 점검(Daily/Monthly)·보전·PM이 주기적으로 반복되는 루프 성격이므로, 고객이 매일 접하는 대표 루프인 **설비 점검 루프를 메인 축**으로 잡고(수행 빈도 최고 + 생산 통제와 직결 — 작업 전 점검 통제가 생산(②) 도메인과 맞닿는 유일한 강결합 지점), 나머지는 사이드 구조 4종(툴 PM · 경량 보전 · 표준 I/F · 비가동)으로 분리한다. 루프 회귀는 회색 점선으로 표현한다.
3. S1(자산 등록·기준정보)·S9(폐기)는 도식 범위 외 — 기준정보는 Wallet(목록) 참조로만 등장시키고, 자산 수명주기는 본 도식에서 다루지 않는다. [구성 판단: 고객 협의의 초점=운영 루프]

**수량 제약 준수 현황**: 메인 축 7개(≤12) · 행위 노드 총 20개(≤30) · MES 노트 9매 · 분기 헥사곤 5개 · 미정의 마커 7개.

## 2. 사이드 구조도 (4종)

[구성 판단] 후보 전부를 채택한다 — 4종 모두 확정 근거(QA #7~#12·#32, 결정 03)가 있고 메인 루프와 접점이 명확하다. 배치: 메인 축 하단 2×2 (좌상=A 툴 PM, 우상=B 경량 보전, 좌하=C 표준 I/F, 우하=D 비가동).

### 2.1 사이드 A — 툴/금형 PM 루프 (타발수 → 누계 → PM 트리거 → PM 실적·차기 산출)

**연결점**: 메인 A5(생산진행)에서 회색 화살표 유입(라벨 "작업실적 발생").

```
[SA1 작업실적발생(빨강)] ─빨강→ (U3 작업자) → MES-3(툴사용실적)
   → <H5 PM 도달?(타발/날짜)> ─미도달(회색 점선)→ SA1 회귀(누계 계속)
                     └─도달(검정)→ (U4 설비담당) → MES-4(툴보전오더) → MES-5(툴PM실적) → [SA2 PM완료(파랑)]
                                                                              └─회색 점선(차기 PM 기준 갱신)→ H5
```

| U3 | User | 작업자 | 작업실적 입력자 |

| B8 | Mobile | 타발수기입 | U3 부착. 작업실적 입력 시 수동 기입 |
| B9 | Desktop | 환산옵션 | U3 부착 — **회색**(대안). 생산 수량 기반 환산=사용 여부 선택형, 수량 대비 타발수 비율(Cavity 배수) 설정 |

**MES-3** — 부착: U3 행위 체인 하단.

```
KEY - 툴사용실적No

타발수=수동 기입(계수기 설비 없음)

적정타수=툴 마스터 참조(엑셀→DX)
```
