**본 도메인 특칙**

1. **06은 ERP(Database) 아이콘이 메인에 등장하는 유일한 기준정보 도메인이다.** 단, **수신 연계로 그릴 수 있는 마스터는 품목·BOM·공통코드·조직·작업자 5종뿐이다**(ERP=UNIERP · 연계=DB 중계 테이블 방식). **금지: 공정(Routing)·툴/금형/지그·검사기준의 ERP 연계 화살표 — 전부 MES 정본이므로 그리면 오류다.** 설비는 수신 확정 목록에 미포함(잔여 확인)이므로 역시 연계 화살표를 그리지 않는다. **P/O(작업지시) 수신=ERP 트랜잭션 연계 — 02(생산실행) 도식 소관이며, 본 도식에는 경계 헥사곤(H2, UNIERP 옆)으로만 표시한다. 출하지시는 ERP 원천이 아니다 — 고객사 문서 import(D+1·시간대별)로서 04(제품출하) 도식 소관이며, ERP 아이콘과 분리한 회색 경계 주석으로만 표시한다(H2에 포함 금지 — ERP 수신 항목 오독 방지, §1.3 경계 주석).**
2. **연계 수신본 표기 규칙: 원본 필드=읽기 전용 + MES 확장 속성(개발품 플래그·재생재 하위 코드·다국어 명칭 등)만 편집 가능.** 수신본을 MES에서 수정하는 표현(수신본 대상 편집 행위 아이콘·수정 화살표)은 금지한다 — 확장 속성 편집 행위(B3)만 허용.
3. **본 도식은 트랜잭션 흐름이 아니라 '마스터 온보딩 + 연계 체계' 도식이다.** 메인 축의 상태 박스는 사건 진행이 아니라 **'신규 품목 1건의 기준정보가 생산 사용 가능해지기까지의 준비 상태'**를 뜻한다. 이 문장을 도식 범례(또는 제목 하단 회색 주석)에 명기한다.
4. **도식 문법 = v2 표기체계 이관 완료(2026-07-22) — 검정 조건 헥사곤 폐기, 실분기=OR(⊕)+인라인 라벨.** 정본: `research/2026-07-13-도식-조건라벨-표기체계-v2.md`.
   - **회색 화살표의 '경계 인계·상세 위임' 라벨 용법**: 공통 규약(회색=대안/생략)에 더해, 타 도식 인계·사이드 위임을 회색 화살표+라벨로 표기한다(A6 진출 3갈래 · A3↔사이드 A "상세 위임" · SB2→SB3 "재동기화 → 06-S-A" 등).
   - **실분기 = OR(⊕) 노드(외곽선 초록) + OR-발 초록 배경 인라인 라벨**: H3(PQC 공정 명시?)·H5(정본=ERP/MES?). 검정 조건 헥사곤은 쓰지 않는다.
   - **단일경로 조건 = 인라인 라벨(노드 없음)**: H1(기준5종수신 — 위반금지 확정규칙이라 노랑 Bold 강조)·H4(트리거 주기/즉시). **H2(P/O 경계·진출 없음)=회색 텍스트 주석**. 단순 합류(H3 양 갈래→A5·H4→SA2)는 별도 ⊕ 없이 커넥터로 직결. **회색 리셉션·경계 hex는 유지**(조건이 아닌 경계 표기이므로 v2에서도 존치).

**수량 제약 준수 현황 (v2 캔버스 실측 2026-07-22 — 메인 675:6942 자식 79 · 사이드 710:7241 자식 70)**: 메인 축 9개(≤12 — Archive 6 + User 3) · 행위 노드 총 14개(≤30) · MES 노트 12매(불량코드 마스터 MES-11·판정유형 코드 목록 MES-12 승격 — **작화 완료**) · **분기·조건 표기(v2 표기체계 — 검정 조건 헥사곤 0)**: OR(⊕) 2(H3 687:7206·H5 712:7343, 외곽 초록) + 인라인 조건 라벨(H1 강조 노랑 Bold·H4 등) + 회색 텍스트 경계(H2) + 회색 리셉션 hex 3(사이드 A/B/D) + A6→02 회색 경계 hex 1 · 미정의 마커 7개(판정유형 E3 빨간 Email 포함) · Database 아이콘 3개(메인 UNIERP 676:7023 · 사이드 A DB-A 710:7254 · 사이드 D DB-D 717:7522 — 수신 5종 연계·I/F 정의 한정). 경계 주석(회색 텍스트 — 출하지시)은 도형 수량에 불포함.

**[구성 판단] — 메인 축 = A안 '신규 품목 온보딩 축' 채택 (사용자 확정 사항)**

- **A안 채택 사유**: ① 고객 직관성 — "신규 품목 1건이 생산에 쓰이기까지 누가 무엇을 어디에 등록하나"는 고객이 실제로 겪는 사건 단위다. ② 정본 소유 2체계 대비 — 축의 앞 구간(ERP 등록→수신)과 뒤 구간(MES 정본 직접 등록)이 한 축 위에서 자연스럽게 대비되어, 이 도메인의 최대 확정 사실(품목·BOM·공통코드·조직·작업자=ERP 정본 / Routing·검사기준·툴·창고/Location·예비품=MES 정본)이 구조로 드러난다. ③ WF06의 현장 발견 방법 '1품목 추적'(S2 품목 → S3 BOM → S4 공정 → S5 검사기준 → S7 연계 → W/O 사용) 시나리오와 정합한다.
- **B안(연계 파이프라인 축) 기각**: 연계 동기화는 주기 반복되는 배치 프로세스라 상태 진행 축으로 그리면 고객 협의의 초점(등록 주체·정본 위치)이 흐려진다 → **사이드 A로 이동**해 상세(트리거·Temp 적재·수신본 반영)를 위임한다.
- **운영 마스터(설비·툴·창고/Location·작업자·WorkCalendar·예비품)는 축 상태로 넣지 않는다** — 품목 단위 온보딩 사건이 아니라 전제 참조(S6 Trigger=신규 설비/툴 입고·신규 입사·창고 신설로, 품목 발생과 별개 사건)이므로 Wallet 참조(B7)+MES-5 노트로만 배치한다.
- 상태 박스의 의미는 특칙 ③(기준정보의 준비 상태)을 따른다.

### 4.2 도식에 표기하지 않은 잔여 미결 (협의 시 구두 보조)

- ERP-MES I/F 중계 테이블 스키마·트리거(Time Schedule 주기 vs Event 즉시) 상세 — S1·S2·S3·S7 공통 잔여(운영 설계).
- BOM 식별자 택일(BOM No vs 부모+자품목+Rev) — 내부 설계.
- 판정유형 코드 목록(MES-12 · 고객 액션 E3): **확정 4(보류/Release/Hold/PQC 검사 필요 — 「PQC 검사 필요」는 03 전이도 7번째 상태 승격 완료·632:6932·2026-07-21·사용자 C-1(a))** + **미확정 3(한도승인/특채/폐기 — E3 대기 [확인], 03 전이도 미확정 3상태 동형)** · **소속(S1 공통코드 vs 품질 마스터)=설계 결정 [확인](WF06 S5)**. 구조·2계층 승격은 확정, 미확정 3상태 값·소속만 대기.
- 알람 상황 유형 목록(고객 액션 E1) — 구조 확정, 값만 고객 회신 대기.
- WF06 예외 E1(신규 품목 미등록 상태 생산/입하)·E2(검사기준 미등록)·E6(ERP-MES 마스터 불일치)·E7(코드 체계 상이·매핑) — 확정 처리 방향 없음(공통 4질문 현장 확인 대상이라 도식에 그리지 않음). ※ 고객 액션 E번호와 별개 체계.
- Routing 부재 시 BOM fallback의 As-Is 실태 미확인 + BOM 미등록 W/O 전개=단일 실패점(WF06 예외 E3 BOM 축 잔존).
- MES 원천분/연계분 구분 플래그 설계(충돌①③ 파생) · 검사항목-측정값 매핑 스키마(D9잔)·검사기준 키 단위(복합키 vs surrogate) · 재생재 하위 코드 값 체계 · 사전발행 LOT 번호와 IQC 생성의 정합 · 다국어 명칭 보관 구조(테이블 분리 vs 컬럼 병기) — 내부 설계.
- 설비의 ERP 수신 대상 여부(수신 확정 목록 미포함 — 잔여 확인) + 설비·작업자 마스터 매체=가설(ERP/Legacy 연계 추정 미검증).
