## 0. 사용법 · 범위 · 발견 방법

**이 문서의 위상**: 원본(v0.4)은 *커버리지 체크리스트 + 현행 가설*이었다. 본 재정리본(v1.0)은 2026-07-01 현장 점검 요구사항 명세서 47건 중 자재창고 접점 27건을 통합해, **검증된 항목은 ✅(REQ 근거)로 전환하고, 검증되지 않은 가설은 🟡로 유지해 계속 반증 대상**으로 남긴다. 각 단계의 Medium·Pain 중 🟡 표기는 여전히 전형적 제조 SME(종이·엑셀·레거시) 기준 추정이며, **UNIMES 제안서(벤더 To-Be)를 기준으로 삼지 않는다** — *현행이 실제 어떻게 도느냐*는 개방형으로 듣는다.

**범위(IN)**: 자재(원자재·부자재·외주품) 창고의 입고~보관~불출 사이클 — 발주 수신 · 입하 · 수입검사 · 입고(자재LOT 생성·적치) · 재고 보관 · 출고(생산창고 인계) · 재고이동 · 재고실사 · 반품(공급사) · 폐기 · **생산창고(라인사이드) 재고 관리(S12 신규 — REQ-PR-0034)**.
**범위(OUT, 별도 워크플로우)**: 제품 출하·Picking&Packing·생산 실적·작업지시(W/O)·품질 검사 *내부 절차*. (단 경계로 맞닿는 지점은 🔗로 표시)

**발견 방법(현장)**: ① 1건 추적(실제 입하 1건을 입고→적치→출고까지 따라가기) ② 관찰(말이 아니라 실제 동작) ③ 실물·데이터 수집(거래명세서·재고대장 엑셀·라벨 실물·화면 캡처·DB 스키마+덤프). 각 단계 끝 **[Check(확인)]** 에 관찰·수집·질문 포인트 — 명세서로 답이 나온 항목은 취소선+확정 처리했다.

**워크플로우 개요 (검증·요구 반영)**
```
[ERP 발주(P/O)] ─수신→ S1 (P/O 변경 이벤트 포함 — REQ-PR-0024)
 (선택) LOT 번호 사전 발행 → 협력사 라벨 부착·납품 (REQ-PR-0001)
 공급사 납품 ─도착→ S2 입하(사전발행 라벨 스캔 · 거래명세서 문서 분석 자동 등록 — QA #29)
                     → S3 수입검사(IQC) ─합격→ S4 입고(자재LOT 생성=IQC 합격 시점·QR·ERP G/R 건별) → S5 적치
                                          └불합격→ S10 반품(공급사)
 S4/S5 ─→ S6 재고 보관(가용/Hold·의심자재 등록)
   ├─ W/O 생성 → 출고요청 자동 발행 → S7 출고(부분출고·출고 QR 항상 발행) → S12 생산창고 재고(버퍼) → [생산 투입]
   ├─ → S8 재고이동(창고·Location 간 + 불량창고 반출)
   ├─ 주기 → S9 재고실사 → 차이 조정 → [ERP]
   └─ 불량·만료·손상 → 불량창고 우선 입고 → S11 판정(재작업/폐기) → 품의 → 기타 출고(폐기)
```

## S1. 발주 정보 수신 / 입하 예정 인지

- **Trigger(촉발)**: ERP에서 P/O(구매발주) 발행 / 공급사 납기 임박.
- **Actor(주체)**: 전산(ERP 연계)담당 · 물류(창고)담당.
- **Action(행위)**: 입하 예정(품목·수량·납기·공급사)을 파악·공유.
- **Input(입력)**: P/O(ERP), 발주잔량.
- **Medium(매체)** 🟡: *가설* — ERP 화면 조회 후 **엑셀/종이로 입하예정표 수기 작성** 또는 구두 공유. (열림↔갇힘: ERP는 시스템이나, 창고로의 전달이 엑셀·구두면 끊김)
- **Result(결과)**: 입하 예정 인지(상태변화 없음, 정보 전달).
- **Rule(선행조건·규칙)**: P/O 존재(ERP 발행 정본). P/O는 ERP 발행·MES 수신(MES에서 수정 없음) — ✅ 확정 (REQ-PR-0024 요구, D10 해소).
- **Exception(예외·선행조건 미충족)** 🟠: ① 예정에 없는 **무발주 도착**(긴급·샘플·무상 대체품)을 어떻게 *인지*하나(예정표에 없어 누락 위험). [확인] 무발주 도착 인지 경로·빈도. ② **P/O 변경(중단·수량 변경) 수신** — 생산 계획 실행 후 P/O 변경 발생 가능이 확정됨: 중단→생산계획 중단, 수량 변경→생산계획 수량 변경 + 관리자 확인 — ✅ (REQ-PR-0024 요구). W/O 연쇄 변경은 생산실행 워크플로우(🔗). ~~P/O 변경 무시·강행 옵션 필요 여부는 고객 확인 대기~~ → 확정: **강행 옵션 필요** — 관리자 확인 화면에서 '변경 반영 vs 기존 유지(강행)' 선택, 강행 시 P/O-W/O 불일치 플래그 명시 (✓확정 2026-07-04 QA #23). ③ **P/O 초과 물량 도착** — 처리는 S2 Exception ②에서(REQ-OA-0011).
- **Pain/Wish(문제·요구)** 🟡: *가설* — 입하예정이 시스템에 안 떠서 공급사 도착을 *그때그때* 안다 / 발주잔량 추적 수기.
- **Boundary(경계)** 🔗: **ERP → 창고**. P/O는 ERP 정본. (지시 계층 = ERP)
- **Open-Issue(연계 미결)**: ⚠ ~~D10(P/O 수신본 여부)~~ → 확정: P/O=ERP 발행·MES 수신 + 변경 이벤트 처리 (REQ-PR-0024 요구). ~~강행 옵션 여부~~ → 확정: 강행 옵션+불일치 플래그 (QA #23 2026-07-04) · ~~D18(ERP 연계 통신방식)~~ → 확정: **ERP=UNIERP, 연계=DB 중계 테이블 방식** (✓확정 2026-07-04 QA #18).
- **[Check(확인)]**: P/O를 창고가 *어디서* 보나(ERP 직접? 엑셀 사본?). 입하예정표 실물 수집. 발주잔량 어떻게 관리하나. (신규) P/O 변경이 현행 창고·입하 예정에 *어떻게 전달되나* · ~~강행 옵션 필요 여부~~ → 확정(QA #23 2026-07-04).

## S2. 입하 (공급사 도착 등록)

- **Trigger(촉발)**: 공급사 차량 도착 · 납품.
- **Actor(주체)**: 물류(창고)담당 (+공급사 기사).
- **Action(행위)**: 도착 등록, 납품수량·품목 1차 확인, 입하유형(자재/외주품/상품) 구분. (신규) **사전발행 LOT 라벨 스캔** — 협력사가 사전 발행된 자재LOT 번호 라벨을 부착해 납품한 경우, 라벨 스캔으로 도착 등록·입고 전 상태 관리 — ✅ (REQ-PR-0001 요구). (정정) **거래명세서 문서 분석 자동 등록** — 자재 도착 시 IQC 전에 P/O 대비 수량·품목을 확인하는 *입하(도착) 등록*을, 수기 대신 거래명세서 문서를 분석해 자동 등록한다(P/O 대조 + P/O 초과 검증(REQ-OA-0011)과 결합, 수기 입력=대안) — ✅ (REQ-PR-0006 요구 재해석 · ✓확정 2026-07-04 QA #29). 원문의 "창고 입고 X"는 '이 시점에 재고 반영 아님'의 뜻이지 입고 절차 생략이 아니다 (기존 서술 폐기: '창고 입고 절차 생략형 간이 입고 경로' — QA #29 해석 정정). 순서 정합 미결은 소멸 — 입하(자동 등록)→IQC→LOT 생성 순서 그대로 정합. 패턴: '외부 문서→구조화 자동 등록'(출하지시서 import와 동계열).
- **Input(입력)**: 공급사 거래명세서·납품서, P/O(대조용), 실물 자재, (신규) 사전발행 LOT 라벨(부착 시).
- **Medium(매체)** 🟡: *가설* — 현행은 **종이 거래명세서 수령 → 엑셀 입하대장 수기 입력** (체인). 바코드 스캔 여부 불명(인프라는 신규 설치 대상 — REQ-PR-0017 요구, S4 참조).
- **Result(결과)**: 입하 No 발생(?), 입하 등록. **상태변화**: '입하 대기' 재고는 아직 아님(수입검사 전 — 자재LOT도 아직 미생성, REQ-PR-0007 요구).
- **Rule(선행조건·규칙)**: P/O 대비 수량 check.
- **Exception(예외·선행조건 미충족)** 🟠: ① **P/O 조회 안 됨/미연계**(ERP엔 있으나 창고 미수신·타이밍 갭) ② **불일치**(품목 상이·미등록 품목·수량 부족·분할납품) — 이 중 **수량 초과는 확정**: P/O 수량 초과 입고분은 초과 물량으로 식별하고 **'입고 처리 vs 초과분 반품'을 선택하는 기능**으로 처리(차단 아님) — ✅ (REQ-OA-0011 요구). 잔여: 승인 주체·사후 ERP 정합 ⚠ ③ 거래명세서 누락. → 나머지 불일치 유형은 **차단 vs 가입고(provisional) 후 사후 정합**? 승인 주체? 🔗 무발주=ERP 상위지시 없이 MES 입하 단독 → **3계층 nullable 상위지시 검증**. [확인] P/O 없을 때 실제 처리(반송/가입고/수기), 무발주 빈도·사유, 사후 ERP 매칭.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 거래명세서 종이 보관, 입하↔P/O 수량차 수기 대조, 외주/상품/자재 처리 경로가 담당자 경험에 의존.
- **Boundary(경계)** 🔗: **공급사 → 창고**. 입하 No 발번 주체? — ⚠ **B8**(입하 발번: 지시=ERP P/O / 작업지시=MES 입하 / 전표=후속 G/R). 사전발행 LOT 번호는 MES 발번(REQ-PR-0001 요구 + A1 완전 확정 — LOT 3종 전부 MES 발번, QA #1 2026-07-04) — 협력사는 라벨 부착만.

- **Rule(선행조건·규칙)**: 가용재고 = Release분 — 판정 기준은 재고 상태컬럼이 아니라 **Lot Status(C4) 참조**로 산정한다(재고 행 상태 비보유) (✓설계확정 2026-07-06 결정 08·10).

## S7. 출고 (자재창고 → 생산창고)

> **구조 변경(충돌 해소)**: 원본은 '출고=생산 즉시 투입(WIP 전환)'을 가정했으나, 명세서가 며칠분 자재의 **생산창고 적치** 사용과 호퍼 잔량의 재고 관리를 명시 — **「출고 → 생산창고 재고(버퍼, S12) → 투입」의 2단 구조로 교체**한다 — ✅ (REQ-PR-0034 요구). (기존 가설 폐기: 출고→WIP 즉시 전환)

- **Trigger(촉발)**: 작업지시(W/O) 발행 → **자재 출고요청서 자동 발행** — 작업계획 기반으로 시스템이 필요 수량을 자동 산정해 담당자 개입 없이 요청 — ✅ (REQ-PR-0022 요구). (원본의 '출고요청 수신' 가정을 자동 발행으로 구체화)
- **Actor(주체)**: 물류(창고)담당 (+생산/현장담당).
- **Action(행위)**: 요청 자재 LOT 선택 → 불출 → 재고 차감 → **생산창고로 인계**. (신규) **LOT 부분 출고·잔량 관리** — 자재LOT 스캔 후 출고 수량 입력, 작업계획서의 출고 수량 기반 자동 계산, 자재LOT별 잔량 정보 관리 — ✅ (REQ-PR-0004 요구). (신규·확정 갱신) **출고 QR** — 자재 반출 시 관리 QR 발급, 출고 시 Scan + 입고 시 Scan의 양방향 확인으로 자재 이동 추적 — ✅ (REQ-OA-0010 요구). 확정: **'보관 단위(자재LOT 라벨) vs 이동 단위(출고 QR)' 분리 — 분할(부분) 출고뿐 아니라 전량 출고에도 일관성 위해 예외 없이 항상 발행**, 사전발행 LOT 라벨과 명칭·디자인 구분 (✓확정 2026-07-04 QA #16; 기존 서술 보완: '분할품 한정 관리 QR' → 전 출고 공통 출고 QR).

## S11. 폐기 (Scrap/Disposal) — D21 확정 반영

> **갱신(미결 해소)**: 원본의 '⚠ 설계 갭' 상태였던 폐기 요구가 명세서로 확정됨 — **불량창고 우선 입고 → 입고 후 재작업/폐기 판정 → 내부 품의 → 기타 출고 처리**의 흐름 (D21 해소 — ✅ REQ-PR-0025·0028 요구).

- **Trigger(촉발)**: 불량·유효기간 경과·손상·반품 불가 자재 발생 → **불량창고 우선 입고** — ✅ (REQ-PR-0025 요구).
- **Actor(주체)**: 물류담당 (+품질담당, 품의 승인권자).
- **Action(행위)**: 불량창고 우선 입고 → **입고 후 재작업(리페어) 가능 불량 / 폐기 불량 판정** — ✅ (REQ-PR-0025 요구) → 폐기 판정분은 **내부 품의 → 기타 출고 처리 → 재고 차감** — ✅ (REQ-PR-0028 요구). 재작업 가능 판정분은 재작업 경로로(재작업으로 양품화된 제품은 생산실적 기록 — REQ-PR-0025 요구; 재작업 절차 자체는 품질·생산 도메인 🔗).
- **Input(입력)**: 폐기 대상 LOT/품목, 폐기수량, 사유, 판정 결과, 품의 문서.
- **Medium(매체)** 🟡: *가설* — 현행 처분 실태는 여전히 **불명**(명세서는 To-Be 요구만 확정, As-Is 미기재). 종이/엑셀 수기 or *아예 미관리* 가능성은 관찰 대상으로 유지.

## S12. 생산창고(라인사이드) 재고 관리 — 신규 단계

> **신규 단계(REQ-PR-0034)**: 문서 말미에 추가하나, **흐름상 위치는 S7(출고)과 S8(재고이동) 사이** — 자재창고 출고분이 생산 투입 전에 머무는 버퍼 재고 지점이다. 원본에 없던 재고 지점으로, S7의 '출고=즉시 투입' 가설을 뒤집으며 신설되었다.

- **Trigger(촉발)**: S7 출고분 생산창고 도착 / 생산 라인 자재 사용(투입) / 사출 후 호퍼 잔량 발생 / 재사용·분쇄 자재 발생.
- **Actor(주체)** 🟡: *가설* — 생산(현장)담당 중심(+물류담당). 생산창고 재고의 소유 부서는 확인 필요.
- **Action(행위)**: ① **라인(생산창고) 입고 검증** — 생산 계획대로 입고되었는지 확인: 수량 체크 → QR 스캔 — ✅ (REQ-OA-0002 요구) + 분할품 관리 QR 입고 스캔(양방향 확인의 입고 측 — ✅ REQ-OA-0010 요구) ② **며칠분 적치 재고 관리** — 생산 자재를 자재창고에서 가져와 생산창고에 적치해 두고 사용 — ✅ (REQ-PR-0034 요구) ③ **호퍼 잔량 관리** — 사출 이후 호퍼에 남아있는 원재료를 생산창고 재고로 관리 — ✅ (REQ-PR-0034 요구). 방식 확정: **호퍼 잔량=사용자가 직접 실측해 시스템 입력(계산·추정 아님), 등록 트리거=생산창고 입고 시점** (✓확정 2026-07-04 QA #5) — 기록 구조 확정: 실측 입력=실사 계열 **조정 트랜잭션**으로 수불 원장에 기록(잔량 직접 덮어쓰기 금지), **호퍼=Location으로 모델링**(설비—Location 매핑) (✓설계확정 2026-07-06 결정 08) ④ **재사용/분쇄 자재 재고 등록** — 생산창고에 재고 등록, 이후 절차에서 신재료와 동일 코드로 관리 — ✅ (REQ-PR-0031 요구; 정밀화: '동일 코드'=품목 코드 레벨, MES 내부는 하위 코드로 구분 — QA #31 2026-07-04) ⑤ 생산 투입(실제 WIP 전환 — 생산실행 워크플로우 🔗).
- **Input(입력)**: S7 출고분(분할 QR 라벨), 생산 계획/W/O, 호퍼 잔량, 재사용·분쇄 자재.
