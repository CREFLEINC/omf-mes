## 0. 사용법 · 범위 · 발견 방법

**이 문서의 위상**: 사전 정의 = *커버리지 체크리스트 + 현행 가설*. 현장에서 채우는 틀이 아니라 **반증할 가설**이다. 이 도메인은 트랜잭션(입출고·실적)보다 **마스터 데이터 + ERP↔MES 연계**가 핵심이라, 단계를 사건의 시계열이 아니라 **"등록 → 연계 → 변경 → 통제"** 흐름으로 구성한다. 각 단계의 Medium·Pain은 전형적 제조 SME(ERP+엑셀+레거시) 기준 추정이며, **UNIMES 제안서(벤더 To-Be)에 앵커링하지 않는다** — 마스터 목록만 데이터모델에서 빌려오고, *정본이 어디에 있고 어떻게 동기화되느냐*는 개방형으로 듣는다.

**이 도메인이 던지는 핵심 질문(반증할 가설의 축)**:
1. **정본이 어디인가** — BOM·Routing은 ERP 정본이 거의 확실(L1)하나, **검사 기준정보(검사항목·UCL/LCL/Target)는 정본이 ERP QM·MES·별도 QMS 중 미정**(B5, 소유경계). BOM/Routing과 검사기준을 같은 'ERP 정본'으로 묶으면 안 된다.
2. **연계가 어떻게 도느냐** — Time Schedule(주기)/Event(즉시) 트리거, Temp Table·MS SQL 중계, 통신방식(XML/File/DB/Web/FTP, D18)이 모듈별로 다른가. 연계 실패·지연(타이밍 갭)을 현장이 어떻게 메우나.
3. **연계분을 못 고치면 무슨 일이 벌어지나** — 연계분(Legacy 출처) 기준정보는 MES 수정/삭제 불가(근거p53·54). 현장이 수정해야 할 때 *실제로* 막히나, 막히면 어디로 우회하나.

**범위(IN)**: 신규 품목 등록 → BOM 등록/변경(Rev·유효기간) → Routing/공정 등록(공정Ver·Sequence) → 검사항목(검사기준) 등록 → 설비·툴·작업자·창고/Location·공통코드 마스터 → ERP→MES 연계 동기화(Time Schedule/Event) → 변경관리(연계분 MES 수정·삭제 불가) → 사용자 권한 관리.
**범위(OUT, 별도 워크플로우)**: 실적·트랜잭션 전체(자재창고·생산실행·품질·설비/툴·출하 등 타 문서). MES→ERP 역방향 제조이력 송신(연계의 반대 방향, 타 문서). 경계로 맞닿는 지점만 🔗로 표시.

**발견 방법(현장)**: ① **1품목 추적**(실제 신규 품목 1건을 ERP 등록 → BOM → Routing → 검사기준 → MES 연계 → W/O 사용까지 따라가기) ② 관찰(말이 아니라 실제 동작 — 연계분 수정이 *정말* 막히나, 연계 실패 시 *실제로* 어떻게 메우나) ③ 실물·데이터 수집(ERP 마스터 스키마 · MES 마스터 스키마+덤프 · I/F정의 테이블 · 연계 로그 · 검사기준 정본 화면 · 권한 화면). 각 단계 끝 **[Check(확인)]** 에 관찰·수집·질문 포인트.

**검증 렌즈(2026-06-26 재정리)**: 마스터별로 ERP 소유 정도가 차등이다.
- **L1 — ERP 정본 기준정보**: BOM(B1)·Routing/공정(B2). *ERP 마스터 스키마 열람*으로 사실상 해소.
- **L2 — 소유·정본 조율(대면 필수)**: 검사기준 정본(B5)·연계 발번/소유(D18·I/F)·권한 편입(D1). **여기가 핵심 쟁점**.
- **L3 — MES 내부 키·정규화**: 이력성 엔티티 키(B6) 등. *MES DB 스키마+덤프*로 해소.

**워크플로우 개요(가설)**
```
[ERP 마스터 = 정본]                         [MES 수신본 = 연계분(수정·삭제 불가)]
  S1 공통코드·조직 ─┐
  S2 품목(Item) ───┤  ── ERP→MES I/F 연계대상 ──
  S3 BOM(Rev·유효) ┤   코드·조직·작업자·품목·BOM·
  S4 Routing/공정 ─┼─→  공정·품질·설비·툴·작업지시  ─→ S7 연계 동기화 ─→ [MES 기준정보]
  S6 설비·툴·작업자·창고┘    (Time Schedule/Event,            (Temp Table·         │ 참조
                            통신방식 D18 ⚠)                  MS SQL 중계)        ▼
  S5 검사항목/검사기준 ⚠ ── 정본 미정(ERP QM/MES/별도 QMS, B5) ──┘            [트랜잭션: 타 문서]
                                                                                  ▲
  S8 변경관리(Rev·유효기간 전환 · 연계분 수정/삭제 차단) ←── 변경 발생 ───────────┘
  S9 사용자 권한 관리(자료·화면·법인 접근 통제) ⟷ 전 단계 횡단 통제
```

## S1. 공통코드 · 조직 마스터 등록

- **Trigger(촉발)**: 프로젝트 초기 코드체계 정의 / 신규 거래처·조직·코드값 추가.
- **Actor(주체)**: 전산(ERP 연계)담당 · 운영자(표준화 TFT).
- **Action(행위)**: 코드그룹+코드값 정의, 코드명·정렬순서·사용여부(Y/N) 등록. "회계=물류=생산 동일코드" 표준 적용.
- **Input(입력)**: ERP 코드 마스터, 표준화 정의(코드정의서).
- **Medium(매체)** 🟡: *가설* — 코드 정본은 **ERP**, MES는 연계 수신. 신규 코드는 ERP 등록 또는 **엑셀 코드정의서** 경유 추정. (열림↔갇힘: ERP·MES·엑셀 3곳에 코드가 흩어지면 끊김)
- **Result(결과)**: 공통코드 마스터(코드그룹+코드값) 생성 — 다른 모든 마스터·트랜잭션의 참조 기반.
- **Rule(선행조건·규칙)**: 코드체계 표준(회계=물류=생산 동일코드 원칙, 근거p18·20·24·27). ERP-MES I/F 연계대상에 '코드·조직' 포함.
- **Exception(예외·선행조건 미충족)** 🟠: ① **ERP↔MES 코드 체계 상이**(자릿수·구분자·그룹 다름) → 매핑 테이블 필요? ② 신규 코드 **MES 선등록**(연계 전 현장이 임시 코드 사용) ③ 사용여부 N 코드를 트랜잭션이 참조. [확인] 코드 매핑 방식, 임시코드 사후 정합.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 코드가 ERP·MES·엑셀에 분산, 매핑표 수기 관리, 동일코드 원칙이 실제론 안 지켜짐.
- **Boundary(경계)** 🔗: **ERP → MES**. 코드 정본 = ERP. "회계=물류=생산 단일코드" 경계(ERP 모듈 간).
- **Open-Issue(연계 미결)**: ⚠ D18(연계 통신방식) · ERP-MES I/F 연계대상(코드·조직).
- **[Check(확인)]**: 코드 정본이 *어디* 있나(ERP? MES? 엑셀?). ERP↔MES 코드 매핑표 존재 여부. 동일코드 원칙 실태.

## S2. 품목(Item) 신규 등록

- **Trigger(촉발)**: 신규 품목(자재/반제품/제품/상품) 발생 — 신규 수주·신규 자재 소싱.
- **Actor(주체)**: 전산담당 · 생산관리자 (+구매).
- **Action(행위)**: 품목코드 채번, 품명·품목구분(자재/반제품/제품/상품)·단위(UoM)·규격·사용여부·**생산LOT 기본크기(양품 목표 수량)** 등록.
- **Input(입력)**: ERP 품목 마스터, 신규 품목 정보.
- **Medium(매체)** 🟡: *가설* — **ERP 정본 등록 → MES 연계 수신**. 단 모델상 생성주체 'MES System' 표기가 혼재(근거p55) — 누가 채번하는지 ⚠.
- **Result(결과)**: 품목 마스터 생성(키=품목코드). **BOM·Routing·검사·LOT·전 트랜잭션의 참조 백본**.
- **Rule(선행조건·규칙)**: 회계=물류=생산 동일 품목코드. ERP-MES I/F 연계대상에 '품목'. 품목 마스터가 BOM·Routing·검사·LOT의 참조 백본 — 품목 선등록이 후속 마스터의 선행조건.
- **Exception(예외·선행조건 미충족)** 🟠: ① **신규 품목 미등록 상태로 생산/입하 발생**(BOM·Routing·검사기준도 동반 미등록 → S2~S5 연쇄 갭) → 임시 품목/차단? ② **ERP↔MES 품목 불일치**(코드·구분·단위 상이) ③ 품목구분 오등록(자재를 제품으로) ④ 사용여부 N 품목에 트랜잭션 발생. [확인] 미등록 품목 현장 처리, 사후 ERP 매칭.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 신규 품목 등록 리드타임 길어 현장이 임시코드·수기 처리, ERP-MES 품목 싱크 지연.
- **Boundary(경계)** 🔗: **ERP → MES**. 품목 정본 = ERP. 단 생성주체 'MES System' 표기 충돌(근거p55) → **A1 LOT 발번 경계와 연결**.
- **Open-Issue(연계 미결)**: ⚠ A1(품목-자재/제품 LOT 발번 주체) · D18 · ERP-MES I/F(품목).
- **[Check(확인)]**: 품목 등록을 *ERP에서* 하나 *MES에서* 하나. '생성주체 MES System'의 실제 의미. 신규 품목 미등록 시 현장이 어떻게 도나(임시코드/차단/구두).

## S3. BOM 등록 / 변경 (Rev · 유효기간)  — L1(ERP 정본)

- **Trigger(촉발)**: 신규 품목 BOM 정의 / 설계변경(E/O)·자재 대체 → BOM Rev 변경.
- **Actor(주체)**: 생산관리자 · 전산담당 (+설계/구매).
- **Action(행위)**: 부모-자품목 구성·소요량·단위·**BOM Rev·유효기간** 등록/개정.
- **Input(입력)**: ERP BOM 마스터, 설계 BOM/E/O 통지.
- **Medium(매체)** 🟡: *가설* — **ERP 정본(L1) → MES 연계 수신**. 식별자(BOM No vs 부모+자품목+Rev)는 미확정 → **ERP 마스터 스키마 확인 대상**.
- **Result(결과)**: BOM 마스터 생성/개정. **결품 시뮬레이션·자재예약 전개 기준**(근거p79).
- **Rule(선행조건·규칙)**: 품목 등록돼야 BOM 등록. BOM은 Rev·유효기간으로 버전관리. ERP 정본(I/F 연계대상=BOM). 연계분 MES 수정/삭제 불가.
- **Exception(예외·선행조건 미충족)** 🟠: ① **BOM 미등록인데 W/O 전개**(소요량 산출 불가) ② **Rev 변경 시 진행 중 W/O가 구 Rev 참조**(전환 시점·소급 여부) ③ 유효기간 경과 BOM 사용 ④ 같은 부모-자품목 **다 Rev 공존** 시 어느 Rev 적용. [확인] 진행 W/O의 Rev 전환 시점, 다 Rev 적용 규칙.
- **Pain/Wish(문제·요구)** 🟡: *가설* — BOM 변경이 ERP에만 반영되고 MES 진행 W/O에 늦게 반영, Rev 이력 추적 미흡.
- **Boundary(경계)** 🔗: **ERP → MES (L1, ERP 정본 거의 확실)**. BOM 변경 → 진행 중 W/O 영향 경계(C2 생산실행).
- **Open-Issue(연계 미결)**: ⚠ B1(BOM Rev/유효기간 키) · D18 · ERP-MES I/F(BOM).
- **[Check(확인)]**: ERP **BOM 마스터 스키마**(Rev·유효기간 컬럼·키=BOM No vs 부모+자품목+Rev). Rev 변경 시 진행 W/O 처리. 다 Rev 공존 실태.

## S4. Routing / 공정 등록 (공정Ver · Sequence)  — L1(ERP 정본)

- **Trigger(촉발)**: 신규 품목 Routing 정의 / 공정 변경 → 공정Ver 증가.
- **Actor(주체)**: 생산관리자 · 전산담당 (+생산기술).
- **Action(행위)**: 품목별 공정 순서(라우팅 Sequence)·공정코드·외주공정 구분·**공정Ver**·표준 C/T·L/T·UPH·사용여부 등록.
- **Input(입력)**: ERP Routing 마스터, 공정 표준.
- **Medium(매체)** 🟡: *가설* — **ERP 정본(L1) → MES 연계 수신**. 키 구성(품목+공정Ver+Sequence)이 키의 일부인지 별도 버전 마스터인지 미확정.
- **Result(결과)**: Routing/공정 마스터 생성. **W/O 세부공정 전개 기준**.
- **Rule(선행조건·규칙)**: 품목 등록돼야 Routing 등록. Routing은 공정Ver·Sequence로 관리. ERP 정본(I/F 연계대상=공정). 외주공정 구분. 표준 C/T·L/T·UPH는 목표관리(3.2.3) 연계.
- **Exception(예외·선행조건 미충족)** 🟠: ① **Routing 미등록인데 W/O 전개** ② **공정Ver 변경 시 진행 W/O 영향** ③ 외주공정 누락(외주 흐름 통제 불가) ④ 표준 C/T·UPH 미입력(목표·가동률 산정 불가). [확인] 공정Ver 변경 시 진행 W/O 전환, 외주공정·표준시간 입력 실태.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 공정 변경이 MES W/O에 늦게 반영, 외주공정 구분 누락, 표준시간 미입력으로 목표관리 공백.
- **Boundary(경계)** 🔗: **ERP → MES (L1)**. 공정 변경 → 진행 W/O·목표관리(C2·분해도 3.2.3) 경계. WorkCalendar 표준작업시간 적용(D8).
- **Open-Issue(연계 미결)**: ⚠ B2(Routing 공정Ver·Sequence 키) · D8(WorkCalendar 적용 단위) · D18 · ERP-MES I/F(공정).
- **[Check(확인)]**: ERP **Routing 마스터 스키마**(공정Ver·Sequence 키 구성). 공정Ver 변경 시 진행 W/O 처리. 외주공정·표준 C/T·UPH 입력 여부.

## S5. 검사항목(검사기준) 등록  ⚠ 소유경계 — L2(정본 미정)

- **Trigger(촉발)**: 신규 품목 검사기준 정의 / 검사기준(UCL/LCL/Target) 개정.
- **Actor(주체)**: 품질담당 · 전산담당.
- **Action(행위)**: 검사유형(IQC/PQC(공정·초중종·자주)/OQC)·품목·항목별 **UCL·LCL·Target·단위** 등록, 불량코드 연결. 검사항목 마스터(C1)와 품질기준값(C4) 구분.
- **Input(입력)**: 검사기준 정본 시스템(⚠ ERP QM / MES / 별도 QMS 중 미정), 도면·시방.
- **Medium(매체)** 🟡: *가설* — **정본 미정**. 품질 PC 엑셀·레거시·별도 QMS일 가능성. **BOM/Routing과 달리 ERP 정본이 자명하지 않음**(검사 *결과*는 ERP, 검사 *기준*은 QMS/MES가 일반).
- **Result(결과)**: 검사항목/품질기준값 마스터 생성. IQC/PQC/OQC 합부 판정의 기준.
- **Rule(선행조건·규칙)**: 품목 등록돼야 검사기준 등록. 검사 *결과*(합/불·Lot release)만 ERP 연계가 일반.
- **Exception(예외·선행조건 미충족)** 🟠: ① **검사기준 미등록 신규 품목** → 무검사 통과/임시기준(자재창고 S3 E2와 연쇄) ② **기준 버전 불일치**(개정분 미반영 검사) ③ **ERP↔MES↔QMS 기준 불일치**(어느 값이 진짜인지) ④ 공정별 불량코드 vs 공정 무관 공통 불량코드(D7). [확인] 기준 없는 품목 처리, 정본 간 불일치 시 우선순위·승인.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 검사기준이 어느 시스템 정본인지 불명, 버전관리 미흡, ERP/QMS/MES 이중·삼중 관리로 불일치.
- **Boundary(경계)** 🔗: **품질 ↔ ERP ↔ (별도 QMS)**. 검사기준 정본 = ⚠ **B5(미정, 소유경계)** — BOM·Routing(L1)과 다른 자리. 계측기 마스터(D17)·SPC 매핑(D9)도 품질 소유. 자재LOT 생성 vs Release(C4)와도 맞닿음.
- **Open-Issue(연계 미결)**: ⚠ **B5**(검사기준 정본·식별자·PQC 하위 분기) · D7(공정별 불량코드) · D9(검사항목-설비측정값 SPC 매핑) · D17(계측기 이력종류) · ERP-MES I/F(품질).
- **[Check(확인)]**: 검사기준이 *어느 시스템*에 정본으로 사나(ERP QM/MES/별도 QMS). ERP 연계 범위가 *결과만*인지 *기준까지*인지. 기준 등록 화면의 키 단위(복합키 vs surrogate). PQC 하위(자주·초중종)가 기준값을 다르게 갖나.

## S6. 설비 · 툴 · 작업자 · 창고/Location 마스터 등록 (운영 마스터)

- **Trigger(촉발)**: 신규 설비/툴 입고, 신규 입사, 창고·Location 신설, 예비품 지정.
- **Actor(주체)**: 설비담당 · 물류담당 · 인사/운영 · 전산담당.
- **Action(행위)**: 설비코드·설비그룹·점검/보전항목·주기 / 툴(금형)코드·사용한도·Cavity·보전항목 / 사원번호·자격증·작업조 / 창고+Location·창고유형(자재/제품/반제품/상품) / 예비품 지정 등록.
- **Input(입력)**: 설비·툴·인사·창고 정보, ERP 마스터(작업자·설비·툴 I/F 대상), Legacy 신규입고/폐기 상태.
- **Medium(매체)** 🟡: *가설* — 일부 **ERP/Legacy 연계**(작업자·설비·툴 I/F 대상), 일부 **MES 직접 등록**(창고/Location). **예비품 마스터 소유 불명**(품목 마스터 뷰 vs 독립 마스터).
- **Result(결과)**: 운영 마스터 생성. 자원배정·보전·적치·검사의 참조 기반.
- **Rule(선행조건·규칙)**: 작업자·설비·툴은 ERP-MES I/F 연계대상. 설비 신규입고/폐기 상태 Legacy 연계. 설비 보전 소유경계 = **MES 경량 보유**(D4 결정, 점검 Daily/Monthly MES 유지).
- **Exception(예외·선행조건 미충족)** 🟠: ① **예비품이 품목(Item) 마스터에 포함된 한 종류인가 별도 예비품 마스터인가**(종합12·질문지 C3) ② 설비/툴 **신규입고 상태인데 마스터 미등록**으로 자원배정 ③ **작업자 자격증 만료/미등록**인데 작업 투입 ④ 창고유형 미지정/오지정(자재를 제품창고). [확인] 예비품 화면이 품목 마스터를 쓰나, 자격 미충족 투입 통제.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 설비/툴/예비품 마스터가 ERP·MES·엑셀 분산, 작업자 자격·작업조 수기, Location 코드 표준 없음.
- **Boundary(경계)** 🔗: **ERP/Legacy → MES**(작업자·설비·툴). 예비품 = ⚠ **품목(C1) 동일실체 vs 독립 마스터**(종합12). 설비 보전 = **MES 경량**(D4, 비용·자산·발주·신뢰성 분석은 범위 밖). 창고/Location = C1 소유(물류 트랜잭션이 참조).
- **Open-Issue(연계 미결)**: ⚠ 종합12(예비품 마스터 소유경계) · D4(설비보전 경량 *범위*·계획-지시-이력 카디널리티) · D8(WorkCalendar 적용 단위) · D18 · ERP-MES I/F(작업자·설비·툴).
- **[Check(확인)]**: 예비품 등록·출고·재고 화면이 *품목 마스터를 쓰나*. 설비/툴 신규입고-폐기 상태 연계. 작업자 자격·작업조 등록 경로. Location 코드 체계 유무.

## S7. ERP→MES 연계 동기화 (Time Schedule / Event)  — L2(소유·발번 조율)

- **Trigger(촉발)**: 마스터 신규/변경 발생(ERP) → 연계 트리거(**Time Schedule** 주기 또는 **Event** 즉시).
- **Actor(주체)**: 전산(ERP 연계)담당 · 시스템(I/F).
- **Action(행위)**: ERP 송신측 DB 생성 → MES 수신측 pull → **Temp Table 적재** → MES 마스터 반영(I/F Data **MS SQL 중계**).
- **Input(입력)**: ERP 마스터 변경분, ERP-MES I/F 연계정의(연계대상·트리거·송수신 방향·Temp Table).
- **Medium(매체)** 🟡: *가설* — **통신방식 미확정**(XML/File/DB/Web/FTP/Protocol 중 — D18). 모듈별로 방식이 다를 수 있음. 계측기·IoT·설비는 Middleware 경유(향후).
- **Result(결과)**: MES 기준정보 동기화. 연계분에 **'Legacy 출처' 플래그(수정/삭제 불가)**.
- **Rule(선행조건·규칙)**: ERP-MES I/F 연계정의(메타엔티티)가 연계대상·트리거를 관리. **연계대상 = 코드·조직·작업자·품목·BOM·공정·품질·설비·툴·작업지시**. 연계분은 MES 수정/삭제 불가(근거p53·54).
- **Exception(예외·선행조건 미충족)** 🟠: ① **연계 실패·지연(타이밍 갭)** → 현장 마스터 부재로 트랜잭션 차단? 임시 사용 후 사후 정합? ② **ERP-MES 마스터 불일치**(부분 동기화·일부만 반영) ③ **Event 누락**(변경이 MES 미반영) ④ Temp Table 적재 오류·중복. [확인] 연계 실패 시 알림·재처리·현장 우회.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 연계 실패 시 알림·재처리 없이 조용히 누락, ERP-MES 마스터 불일치 수기 대조, 통신방식 모듈별 상이로 운영 복잡.
- **Boundary(경계)** 🔗: **ERP/Legacy ↔ Middleware ↔ MES**. I/F정의 = C1 메타엔티티. 'MES→ERP 송신'(제조이력: 투입자재·실적)은 역방향(타 문서).
- **Open-Issue(연계 미결)**: ⚠ D18(연계 통신방식 모듈별) · ERP-MES I/F 연계대상·트리거(Time Schedule/Event) · A1(LOT 발번 시 ERP↔MES 연계 시점).
- **[Check(확인)]**: 모듈별 **연계 통신방식**(XML/File/DB/Web/FTP). 트리거(Time Schedule 주기 vs Event 즉시). Temp Table·MS SQL 중계 실태. 연계 실패 처리·로그. 연계분 플래그가 실제 찍히나.

## S8. 변경관리 (Rev/Ver 전환 · 연계분 MES 수정·삭제 불가)  — L2

- **Trigger(촉발)**: 마스터 변경 필요(BOM Rev·Routing 공정Ver·품목 속성·검사기준 개정) / **현장이 MES에서 직접 수정 시도**.
- **Actor(주체)**: 전산담당 · 생산/품질담당 · 운영자.
- **Action(행위)**: 변경분을 **정본 시스템(ERP/QMS)에서 개정 → 연계 재동기화(S7)**. 연계분은 MES 직접 수정·삭제 **차단**.
- **Input(입력)**: 변경 요청, 정본 마스터, 진행 중 트랜잭션(W/O) 현황.
- **Medium(매체)** 🟡: *가설* — 정본에서 개정 후 연계, MES는 조회·사용만. 변경 승인·이력 매체 불명(엑셀·구두 가능).
- **Result(결과)**: 마스터 개정(Rev/공정Ver/유효기간), 이력 보존. **진행 중 트랜잭션 영향**(구/신 버전 적용 시점).
- **Rule(선행조건·규칙)**: 연계분(Legacy 출처) **MES 수정/삭제 불가**(근거p53·54). BOM Rev·유효기간·Routing 공정Ver로 버전 전환. 변경 시 진행 중 W/O 영향.
- **Exception(예외·선행조건 미충족)** 🟠: ① **연계분을 현장에서 수정 시도 → 차단(의도된 동작)** → 우회로(엑셀·별도 메모)가 존재하나 ② **Rev/Ver 변경 시 진행 중 W/O가 구 버전 참조** → 전환 시점·소급 처리 ③ **MES 고유 보강 속성**(연계 안 되는 속성)의 수정은 허용? ④ 긴급 변경 시 ERP 미경유 MES 직접 입력. [확인] 차단의 실제 동작, MES 고유 속성 수정 범위, 진행 W/O 전환.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 변경이 ERP에만 반영되고 MES 진행건 미반영, 차단된 항목을 엑셀·구두로 우회, 변경 승인·이력 추적 미흡.
- **Boundary(경계)** 🔗: **ERP/QMS(정본) → MES(수정 불가)**. MES 고유 보강 속성의 수정 권한 경계. 변경 → 진행 중 W/O(C2).
- **Open-Issue(연계 미결)**: ⚠ B1·B2(버전 키) · 연계분 수정/삭제 불가 플래그 운용 · D18.
- **[Check(확인)]**: 연계분 수정 시도가 *실제로* 막히나(화면 시연). MES 고유 속성 수정 허용 범위. Rev/공정Ver 변경 시 진행 W/O 전환 규칙. 변경 승인·이력 매체.

## S9. 사용자 권한 관리 (자료 · 화면 · 법인 접근 통제)  — L2(보완)

- **Trigger(촉발)**: 신규 사용자·역할 / 권한 변경 / 보안 요구([창고제안]).
- **Actor(주체)**: 전산담당 · 운영자.
- **Action(행위)**: 사용자별 **메뉴·데이터·법인** 단위 접근 권한 부여/회수.
- **Input(입력)**: 사용자·역할 정의, [창고제안] 권한 요구(근거p488·545).
- **Medium(매체)** 🟡: *가설* — **UNIMES 미명시** — 현 ERP/창고 시스템 권한 방식 추정. MES 권한 마스터 편입 여부 미정.
- **Result(결과)**: (편입 시) 권한 마스터. 자료/화면 접근 통제.
- **Rule(선행조건·규칙)**: [창고제안] 사용자별 자료/화면 권한 요구. 권한 통제가 전 단계(S1~S8) 마스터 접근의 횡단 선행조건.
- **Exception(예외·선행조건 미충족)** 🟠: ① **권한 없는 사용자 접근**(통제 부재로 마스터 임의 변경) ② 권한 입도(메뉴/데이터/법인) 미정 ③ **다법인(비나) 데이터 격리** 안 됨 ④ 마스터 변경 권한과 조회 권한 미분리. [확인] 현 권한 운영 방식, 입도, 법인 격리.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 권한 통제 없어 기준정보 임의 변경 위험, 법인 간 데이터 노출.
- **Boundary(경계)** 🔗: **[창고제안](ERP 측 요구) ↔ MES 반영 여부**. 권한 마스터는 C1 기준정보 편입 *후보*(순수 데이터 엔티티 아님). 전 단계(S1~S8) 접근 통제와 횡단.
- **Open-Issue(연계 미결)**: ⚠ D1(권한 마스터 편입·입도) · 종합15.
- **[Check(확인)]**: 현 ERP/창고 권한 운영 방식. MES 권한 편입 요구 수준(메뉴/데이터/법인). 다법인 격리 요건.

## 요약 매핑 — 단계 ↔ 핵심 미결 ↔ 경계 ↔ 검증 렌즈

| 단계 | 핵심 미결(질문지) | Boundary(경계, 🔗) | 렌즈(L1/L2/L3) |
| --- | --- | --- | --- |
| S1 공통코드·조직 | D18 · I/F(코드) | ERP→MES | L1(코드 정본 ERP) |
| S2 품목(Item) | A1 · D18 · I/F(품목) | ERP→MES | L1 · A1(LOT 발번) |
| S3 BOM | **B1** · I/F(BOM) | ERP→MES | **L1**(ERP 마스터 스키마) |
| S4 Routing/공정 | **B2** · D8 · I/F(공정) | ERP→MES | **L1**(ERP 마스터 스키마) |
| **S5 검사항목** | **B5** · D7 · D9 · D17 | **품질↔ERP↔QMS** | **L2(소유경계)+L3** |
| S6 설비·툴·작업자·창고 | 종합12 · D4 · D8 · I/F | ERP/Legacy→MES | L1/L3 혼재 |

*최우선 검증*: **S5 검사항목(B5 — 검사기준 정본 = 소유경계)** + **S7 연계 동기화(D18 통신방식·연계대상·트리거)**. BOM·Routing(S3·S4, L1)은 *ERP 마스터 스키마 열람*으로 해소되지만, **검사기준 정본과 연계 방식은 대면(L2) 확정**이 필요하다. 반증할 핵심 = "BOM·Routing은 ERP, 검사기준도 ERP일 것"이라는 통념이 깨지는 지점(B5).

## 예외 흐름 카탈로그 (선행조건 미충족)

각 예외는 **공통 4질문**으로 점검한다 — **(a) 차단하나 / 우회(임시 마스터·수기·MES 직접입력)하나 · (b) 누가 승인하나 · (c) 어디에 기록(매체)하나 · (d) 사후 정합(ERP·연계) 방법.**

| # | 예외 유형 | 발생 단계 | 깨지는 선행조건 |
| --- | --- | --- | --- |
| E1 | 신규 품목 미등록 상태로 생산/입하 발생 | S2(연쇄 S3~S5) | 마스터 선등록 |
| E2 | 검사기준 미등록·임시기준(신규 품목) | S5 | 검사기준 존재 |
| E3 | BOM/Routing 미등록인데 W/O 전개 | S3·S4 | 전개 기준 존재 |
| E4 | Rev/공정Ver 변경 시 진행 중 W/O 영향 | S3·S4·S8 | 버전 일관성 |
| E5 | 연계 동기화 실패·지연(타이밍 갭) | S7 | 연계 성공 |
| E6 | ERP-MES 마스터 불일치(부분 동기화) | S7 | 정합 일치 |
| E7 | ERP↔MES 코드 체계 상이(매핑 필요) | S1 | 코드 정합 |
| E8 | 연계분을 현장에서 수정 시도(차단) | S8 | 정본 단일 |
| E9 | 예비품 마스터 소유 불명(품목 vs 독립) | S6 | 마스터 단일화 |
| E10 | 권한 없는 사용자 접근 | S9 | 접근 통제 |

> **핵심 원리**: 예외는 *"선행조건 ↔ 그 조건이 깨질 때"* 의 쌍이다. 기준정보 도메인의 *진짜 운영 차이*는 마스터 등록 정상 흐름이 아니라 **이 예외에서** 드러난다 — ① 마스터가 없을 때 현장이 *임시로* 도는 방식(E1·E2·E3), ② 연계가 깨졌을 때 메우는 방식(E5·E6), ③ 못 고치게 막은 걸 *우회*하는 방식(E8). 여기서 ERP↔MES↔QMS의 진짜 소유 경계가 보인다.

## 현장 실행 체크리스트 (기준정보·연계)

**1품목 추적(필수)**: 실제 신규 품목 1건을 골라 **S2 품목 → S3 BOM → S4 Routing → S5 검사기준 → S7 MES 연계 → (W/O 사용)** 까지 *따라가며* 정본 위치·연계 트리거·연계분 플래그를 관찰.

**수집물(실물·데이터)**:
- **ERP 마스터 스키마**(L1 해소용): 품목·BOM(Rev·유효기간 컬럼)·Routing(공정Ver·Sequence 키) 테이블 구조.
- **MES 마스터 스키마 + 대표 덤프**(L3 해소용): 품목·BOM·Routing·검사항목·설비·툴·작업자·창고/Location, 연계분 플래그 컬럼.
- **ERP-MES I/F정의 테이블 + 연계 로그**: 연계대상·트리거(Time Schedule/Event)·통신방식·Temp Table·실패 이력.
- **검사기준 정본 화면/파일**(B5): 어느 시스템(ERP QM/MES/별도 QMS)에 UCL/LCL/Target이 사나.
- **권한 화면**(D1): 현 ERP/창고 권한 운영.
- 코드 매핑표(ERP↔MES)·코드정의서 엑셀.

**정량 데이터(사이징용)**: 품목(SKU) 수, BOM 행 수·평균 Rev 수, Routing/공정 수, 마스터 변경 빈도(월), 연계 주기(Time Schedule)·연계 실패율, 사용자·역할 수.

**관찰 포인트(말이 아닌 동작)**: 검사기준이 *실제로 어디* 정본인가(B5). 연계분 수정이 *정말* 막히나(S8 차단 시연). 연계 실패 시 현장이 *실제로* 어떻게 메우나(S7). 예비품 화면이 *품목 마스터를 쓰나*(S6). 신규 품목 미등록 시 현장이 *임시로* 어떻게 도나(E1).
