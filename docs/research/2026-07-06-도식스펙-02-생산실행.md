> 용도: FigJam 워크플로우 도식 「02.생산실행」 제작 스펙 — **고객 협의용**. 도식 문법은 「01.자재창고관리」 도식과 동일(가로 메인 축 + 작업자별 수직 행위 체인 + Server/초록 스티키 데이터 노트 + Database(ERP) 연계 + 검정 헥사곤 분기 + 빨간 Email 미정의 마커).
> 표기 원칙: **확정 근거(요구사항 명세서 REQ·QA 확정·설계 결정)가 있는 요소만 도식화한다.** 근거 없는 지점은 그리지 않고 미정의 마커로 표시한다(§4). 도식에는 근거 마커(REQ/QA/결정 번호)를 넣지 않는다 — 근거는 본 스펙 §3에만 기록.

---

## §1 메인 구조도

범위: ERP P/O 수신 → W/O 전개·배정·확정·배포 → 작업 전 점검 → 4M 투입 → 작업실적 수집(3원) → 불량·비가동 → 생산LOT 완료·인식표 → 공정 이동 → W/O 마감·ERP 회신. (WF02 S1~S12)
복잡 예외 4종(작업 홀드·러닝체인지·P/O 변경·긴급 직행)은 §2 사이드 구조도로 분리하고, 메인에는 진입 헥사곤만 둔다.

### ② 작업자별 행위 체인 (총 23 노드 ≤ 30)

**작업자 1. 생산관리자** (WF02 S1~S4) — 7노드

> **① 전개·배정 입력 = 두 마스터(도식 표시)**: `1-2 W/O 전개` 좌측에 입력 소스 2종을 그리고 각각 1-2로 회색 참조 화살표를 문다 — **Server 「공정 Routing · MES 정본」**(세부공정 전개 기준) + **Database(ERP) 「BOM · ERP 정본」**(자재 소요 기준 → 1-3 자재 배정·1-6 출고요청으로 연결). 소유 구분: **공정 = MES 소유(수정 가능)** vs **BOM = ERP 원본의 읽기전용 수신본**. 두 아이콘은 입력 참조용 — ④의 초록 데이터 노트(산출물)와 구분한다.
> **② 분리 항목(본 체인 미표시)**: P/O 변경 수신 = 사이드 C(진입 헥사곤 B1)로 처리, 개발품 계획서 = 별도 도식으로 이관. 본 체인은 **양산 정상 흐름(공정 계획)**만 담는다.

## §2 사이드 구조도

메인에서 분리한 복잡 예외 4종. 각각 메인 진입 헥사곤(③ B11·B12·B1·B13)과 점선 참조로 연결한다.

### 사이드 A — 작업 홀드 (중단 → 재개)

**필요성**: 중단·재개가 W/O당 N회 반복되고 홀드품 실물 관리(라인사이드)가 별도 흐름이라, 메인 축에 넣으면 주 흐름이 끊긴다.

**노드 시퀀스**:
1. 진입: 메인 상태 5(생산 진행)에서 헥사곤 「작업 중단 발생 시」(B11)
2. Wallet 「중단 사유 선택」 — 관리자 설정형 코드(초안 3종: 긴급 오더 끼어들기 / 설비 고장 / 도구 고장)
3. Mobile 「홀드품 등록」 — 대상 생산LOT·수량
4. User 「라인사이드 적치」 — 홀드품 이동은 재고이동 트랜잭션으로 별개 기록(홀드이력에서 참조)
5. 상태(Archive) 「W/O 중단」 (검정)
6. 재개: 헥사곤 「중단→진행 전이(재개)」 → 메인 상태 5로 복귀(검정 화살표). **'재시작'이라는 별도 상태 박스를 그리지 않는다** — 재시작은 상태가 아니라 전이 이벤트
7. 헥사곤 「마감 시 미종료 홀드」 → 「강제 종료(마감 편입)」 라벨 → 메인 5-3(이월/소멸 선택) 흐름에 회색 합류

**조건**: 중단/재개는 반복 가능(헥사곤 「N회 반복 가능」을 5↔6 사이에 배치). 중단 구간 합계 = W/O 비가동(중단 기인분) 집계 원천.

**데이터 노트 전문**:
```
작업홀드이력
KEY - 홀드이력 No
- W/O No 참조
- 중단 사유 코드(관리자 설정형)
- 홀드품(생산LOT·수량)
- 보관 Location = 라인사이드
- 시작/종료 일시(구간·N회 반복)
- 행위자·처리 결과(재개/취소/마감)
- 홀드품 이동 = 재고이동 참조
상태 : 중단(미종료 구간 존재)
```

### 사이드 B — 러닝체인지 (W/O 무분할 · 생산LOT만 전/후 분할)

**필요성**: 설비 무중단 상태에서 구성 부품만 교체하며 **생산LOT이 전/후로 분할**되는 특수 흐름 — 메인 4M 투입에 겹쳐 그리면 정상 투입 규칙과 오독된다. **확정(2026-07-07 QA #37): W/O는 분할하지 않고, W/O에 속한 생산LOT만 전/후 분할한다. BOM 스냅샷(부품 구성)을 LOT 레벨에 보유**(각 LOT이 전/후 부품 구성) — 하나의 연속 작업(job)이므로 W/O 무분할이 정합.

**노드 시퀀스**:
1. 진입: 헥사곤 「부품 교체(러닝체인지)」(B12) — 동일 품목의 구성 부품만 교체하는 유형
2. Desktop 「교체 시점 지정」 (생산관리자) — **W/O 유지**, 부품 교체 시점만 표시(계획 무분할)
3. File 「생산LOT 분할」 — 시스템이 교체 시점에서 생산LOT을 전/후 분할(각 LOT이 BOM 스냅샷 보유·전/후 genealogy 분리)
4. Mobile 「신규 부품 등록」 (작업자) — **작업 중단 없이** 설비 동작 중 투입 부품만 신규 등록(헥사곤 「설비 무중단」 병기). 후 LOT의 4M 투입이 신규 부품 참조
5. ⊕ 합류 → 메인 4M 투입(N6)·실적 수집으로 복귀

**조건**: 러닝체인지는 부품 교체이므로 Routing 무관 — W/O의 Routing Rev 스냅샷은 유지된다(BOM 스냅샷만 LOT 레벨에서 전/후로 갈림).

**~~미정의 마커 U7~~ → 종결(2026-07-07 QA #37)**: 투입 Validation의 BOM 기준 시점 = **해당 생산LOT의 BOM 스냅샷 기준**. U7 마커 제거.

**데이터 노트 전문**:
```
생산LOT 분할(러닝체인지)
KEY - 생산LOT No(분할 신규)
- W/O 무분할 — LOT만 전/후 분할
- BOM 스냅샷 = LOT 레벨 보유
- 전/후 genealogy 분리
- Routing Rev 스냅샷 = W/O 유지
- 투입 Validation = 해당 LOT BOM 기준

```

### 사이드 C — P/O 변경 수신 (반영 vs 강행)

**필요성**: ERP발 변경 이벤트가 관리자 확인·강행 분기라는 별도 제어 흐름을 갖는다 — 메인 S1은 정상 수신만 남긴다.

**노드 시퀀스**:

### 사이드 D — 긴급 W/O 직행 (생산 실행 관점 · 출하는 04 도식 위임)

**필요성**: 긴급 W/O는 P/O 비귀속·점검 우회·배정 생략이 겹치는 생산 예외다. 정상 생산과 **무엇이 다른지 생산 단계로 세분**해 보여주고, 완성 이후 **직행 출하(창고 적치 생략·기록상 입고+출하 자동 생성)는 04 제품출하 도식의 「긴급 직행 출하」 사이드로 위임**한다 — 출하 영역은 02가 관통하지 않는다(정상 출하도 04 소관이므로 일관성 유지). **영역 분리 확정(2026-07-06 CTO 검토, #3=(a) — 긴급 경로를 생산 단계로 세분·출하 꼬리는 04로 이관).**

**노드 시퀀스 (생산 단계 세분)**:
1. 시작 상태(Archive) 「긴급 생산 요청」 (빨강)
2. Desktop 「긴급 W/O 발행」 — W/O 유형=긴급, P/O 비귀속. **미정의 마커(U8)**: 승인 주체
3. 헥사곤 「점검 통제 우회 허용」 (회색) — 정상은 작업 전 점검이 선행조건, 긴급은 우회(QA #9)
4. 헥사곤 「배정 없이 투입」 — 4M 자원배정(계획) 단계 스킵 → 투입 배정 참조 null
5. Mobile 「자재 즉시 투입」 — 배정 계획 없이 현장 자재 스캔. **미정의 마커(U9)**: 자재 조달·출고 경로
6. Mobile 「금형·설비 투입」 — 정상은 배정→투입 2단, 긴급은 투입만(배정 참조 null)
7. Mobile 「실적 입력」 — 양품/불량/손실 3원·genealogy = **정상과 동일 규칙**(배정 참조만 null)
8. Desktop 「LOT 완료·인식표」 — 메인 작업자 4와 동일
9. **경계 헥사곤 「긴급 직행 출하 → 04 도식」** (회색) — 창고 적치 생략·기록상 제품입고+출하 자동 생성·ERP 전표는 04 사이드 소관. 02는 여기서 끊는다.

**조건**: 생산 기록(실적·genealogy·인식표)은 정상과 동일. 긴급이 생산에서 **다르게 하는 것 3가지** = ① 점검 통제 우회 ② 4M 배정 스킵(투입 참조 null) ③ 자재 조달 경로 미정(U9). 출하(직행)는 04로 위임.

**데이터 노트 전문**:
