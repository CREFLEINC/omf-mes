## 0. 사용법 · 범위 · 발견 방법

**이 문서의 위상**: 사전 정의 = *커버리지 체크리스트 + 현행 가설*. 현장에서 채우는 틀이 아니라 **반증할 가설**이다. 각 단계의 Medium·Pain은 전형적 제조 SME(종이 검사성적서·엑셀 검사대장·품질 PC) 기준 추정(🟡)이며, **UNIMES 제안서(벤더 To-Be)에 앵커링하지 않는다** — 단계 목록만 데이터모델 C4에서 빌려오고, *현행 검사가 실제 어떻게 도느냐*는 개방형으로 듣는다.

**범위(IN)**: 품질 검사의 기준 등록~판정~통제~분석 사이클 — 검사 기준정보 준비(B5 소유경계) · 공정검사(PQC: 자주·초중종) 트리거·수행 · 검사실적/검사결과 입력 · 합부 판정(특채·재검 포함) · Lot Status(Hold/Release) 물류통제 · 불량/부적합 처리(불량코드) · SPC 측정·관제(OOC 대응) · 출하검사(OQC) 수행·판정 · 계측기 검교정. **검사 3종 IQC/PQC/OQC는 단일 검사실적 엔티티 + 검사유형 코드**로 표현한다.
**범위(OUT, 별도 워크플로우)**:
- **수입검사(IQC)** — 자재 창고 관리 문서 **S3**에 이미 As-Is 가설로 작성. 본 문서는 *참조만* 하고 중복 작성하지 않는다(검사 3종 중 IQC 흐름·예외는 자재창고 S3 참조). 경계로 맞닿는 지점은 🔗로 표시.
- **제품 출하 절차**(Picking&Packing·고객 출하·납품) — 물류/재고 영역. OQC 합격 *이후*의 출하는 OUT(OQC 검사 자체는 IN).

**발견 방법(현장)**: ① 1건 추적(실제 검사 1건 — PQC 또는 OQC — 을 기준등록→검사실적→판정→Lot Status→불량/출하까지 따라가기) ② 관찰(말이 아니라 실제 동작 — 자주검사가 *정말* 도는지, Hold가 *정말* 출고를 막는지) ③ 실물·데이터 수집(검사시방서·검사성적서·자주검사 체크시트·부적합 보고서·SPC 차트·검교정 대장·계측기 라벨·화면 캡처·DB 스키마+덤프). 각 단계 끝 **[Check(확인)]** 에 관찰·수집·질문 포인트.

**워크플로우 개요(가설)**
```
[검사 기준정보(검사항목·UCL/LCL/Target)] ─선행→ 모든 검사 (정본 ERP QM/MES/별도 QMS 미정 ⚠B5)
 (자재 입하분 IQC = 자재창고 S3, 본 문서 OUT·참조만)
 작업 시작/중/종 · 자주주기 ─트리거→ S2 공정검사(PQC) 의뢰
                                       ▼
                              S3 검사 수행 · 검사실적/검사결과 입력 (계측기 계측값 연계)
                                       ▼
                              S4 합부 판정 (합격/불합격·불량수량 / 특채·재검)
                          ├─합격→ S5 Lot Status: Release ──→ [출고/출하 가용]
                          └─불합격→ S5 Lot Status: Hold ──→ S6 불량/부적합 처리(불량코드)
                                                              └→ 반품(자재창고 S10)·폐기(D21 갭)
 S3 측정값 ──────────────────────────→ S7 SPC 측정·관제 (Xbar-R·Cp-Cpk·OOC/Nelson)
 [출하지시·제품입고] ─트리거→ S8 출하검사(OQC) ─합격→ 납품라벨-생산LOT Matching →[출하 OUT]
 [검교정 주기 도달·고장] ─트리거→ S9 계측기 검교정 ─선행→ S3·S8 검사
```

## S1. 검사 기준정보 준비 (검사항목 · 품질기준값 · 소유경계)

- **Trigger(촉발)**: 신규 품목/공정 도입, 검사기준(검사시방서·도면) 개정, 고객 사양 변경.
- **Actor(주체)**: 품질담당 (+전산담당: ERP QM/QMS 연계분).
- **Action(행위)**: 검사유형(IQC/PQC(공정·초중종·자주)/OQC)·품목·검사항목별 기준값(UCL·LCL·Target·단위) 등록·개정.
- **Input(입력)**: 도면, 검사시방서(분해도 3.2.1), 고객 사양, 공정 표준.
- **Medium(매체)** 🟡: *가설* — 검사기준이 *어느 시스템*에 있는지 불명(ERP QM 모듈? 별도 QMS? MES? 품질 PC 엑셀 기준표?). 종이 검사시방서 + 엑셀 기준표 병존 가능. (열림↔갇힘의 출발: 기준이 시스템에 없으면 검사 전 과정이 수기에 의존하게 됨)
- **Result(결과)**: 검사항목·품질기준값 마스터(합·불 판정 근거). **상태변화 없음**(기준정보).
- **Rule(선행조건·규칙)**: 검사 전 기준이 존재해야 판정 가능. 검사기준 정본 시스템이 **1개로 단일화**되어야 함 — ⚠ **B5**. **우리 보정(2026-06-26)**: 검사 *결과*(합/불·Lot release)는 ERP 연계, 검사 *기준*(검사항목·UCL/LCL/Target·SPC)은 QMS/MES가 일반 — BOM·Routing과 달리 **ERP 정본이 자명하지 않아 L1이 아니다**(정본 = ERP QM·MES·별도 QMS 중 **미정**).
- **Exception(예외·선행조건 미충족)** 🟠: ① **검사기준 미등록 신규 품목** → 무검사 통과? 임시기준? 구두기준? ② **기준 버전 충돌**(도면 개정 전후 동시 사용) ③ PQC 하위(공정/초중종/자주)가 기준값을 다르게 갖는데 한 기준만 등록. [확인] 기준 없는 품목의 검사 처리, 도면 개정 반영 절차.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 검사기준 버전관리 미흡(도면 개정 미반영), 기준이 ERP·QMS·엑셀에 산재(이중관리), 시방서 종이 보관.
- **Boundary(경계)** 🔗: **품질 ↔ 전산(ERP/QMS)**. 검사기준의 정본 시스템·ERP 연계 범위(결과만 vs 기준까지) — ⚠ **B5**(L2 소유경계 + L3 식별자).
- **Open-Issue(연계 미결)**: ⚠ B5(검사기준 정본·품질기준값 식별자·PQC 하위 분기) · B4(검사결과 라인 구조는 S3) · 종합7.
- **[Check(확인)]**: 검사기준이 *어디 저장*되나(실물 확인 — ERP QM 화면? QMS? 엑셀?). 품질기준값 키가 '품목+검사항목+검사유형' 복합키 1건인지, PQC 하위가 기준값을 다르게 갖는지. ERP 연계가 *결과만*인지 *기준까지*인지.

## S2. 공정검사(PQC) 트리거 / 검사 의뢰 (자주 · 초중종)

- **Trigger(촉발)**: 작업 시작(초물) · 공정 중 자주검사 주기 도달(중물·자주) · 작업 종료(종물) — 분해도 3.1.2.2.
- **Actor(주체)**: 작업자/현장반장(자주검사 수행) · 품질담당(초중종 입회·판정).
- **Action(행위)**: 검사 시점 인지 → 샘플 채취 → 검사 의뢰/수행 분기(자주=현장 자체, 초중종=품질 연계).
- **Input(입력)**: W/O · 생산LOT, 검사기준(S1), 자주검사 주기.
- **Medium(매체)** 🟡: *가설* — 자주검사는 **종이 체크시트/현장 게시판**, 초중종은 **품질 엑셀/성적서**. 시스템 트리거 없음 — 작업자 기억·타이머·반장 지시.
- **Result(결과)**: 검사 대상(생산LOT) 지정, 검사 시점 기록. **상태변화**: 검사 대기.
- **Rule(선행조건·규칙)**: 검사기준 존재(S1) + 검사 시점 도달. **PQC = 생산LOT 대상**(검사실적—생산LOT N:1). 검사실적이 W/O 단위인지 생산LOT 단위인지(작업실적 이력 경유 간접연결) — C4 미결.
- **Exception(예외·선행조건 미충족)** 🟠: ① **자주검사 미실시**(주기 놓침·작업자 자가판단 생략) → 작업 통제(차단)되나? ② **검사기준 미등록 품목**(S1 미충족) → 검사 스킵/임시 ③ **초물 검사 전 양산 진행**(검사 결과 나오기 전 다음 공정). [확인] 자주검사 미실시 시 실제 통제 여부, 초물 미검 양산 빈도.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 자주검사 누락 추적 불가(했는지 안 했는지 모름), 검사 시점 수기, 검사 의뢰→수행 핸드오프 구두.
- **Boundary(경계)** 🔗: **생산/현장(C2·3.1.2.2) ↔ 품질(C4)**. 검사실적—W/O 연결(원본 직접 명시 약함, 작업실적 이력 경유).
- **Open-Issue(연계 미결)**: ⚠ B5(검사기준 선행) · (검사실적—W/O 연결은 C4 미결, 질문 번호 미부여 → [확인]으로 검증).
- **[Check(확인)]**: 자주검사가 *실제로* 도는지(체크시트 실물). 검사 시점을 무엇으로 인지(타이머/지시/기억). PQC 검사가 W/O 단위인지 생산LOT 단위인지.

## S3. 검사 수행 · 검사실적 / 검사결과 입력 (IQC/PQC/OQC 공통)

- **Trigger(촉발)**: 검사 대상 지정(S2) / OQC 시점(S8) / IQC 입하(자재창고 S3, 참조만).
- **Actor(주체)**: 품질담당·검사원 (자주검사는 작업자).
- **Action(행위)**: 검사항목별 측정 → **검사실적(헤더) + 검사항목별 검사결과(라인)** 입력, 계측기 계측값 연계, 성적서(Coa/Coc) 첨부.
- **Input(입력)**: 검사 대상 LOT, 검사기준값(S1), 계측기(S9), 공급사/사내 성적서.
- **Medium(매체)** 🟡: *가설* — **종이 성적서/엑셀 검사대장**. 계측값 수기 전사. 검사실적이 시스템에 들어가는지·실시간인지 불명. (현장 검사실적관리 4.3.2 '계측값 자동 연계'는 To-Be, 현행은 수기 추정)
- **Result(결과)**: **검사실적 1건**(검사유형·대상 LOT·검사자·검사일시·성적서) + **검사항목별 검사결과 라인**(측정값·기준값 참조·OK/NG·계측기). **상태변화**: 측정 완료.
- **Rule(선행조건·규칙)**: 검사기준 존재(S1) + **계측기 검교정 유효**(S9). 검사결과를 **항목별 라인으로 입력(2테이블)** vs **평면 1건(항목 컬럼 펼침, 1테이블)** — ⚠ **B4**.
- **Exception(예외·선행조건 미충족)** 🟠: ① **계측기 미검교정/고장**(S9 미충족) → 검사 강행? 대체 계측기? ② **검사 누락·사후 입력**(생산 먼저, 검사 나중 소급) → 정합·시점 ③ **측정값 일부 누락**(전 항목 미측정). [확인] 사후 입력 허용 범위, 미검교정 계측기 검사 처리, 부분 측정 판정.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 종이→엑셀 이중입력, 계측값 수기 전사 오류, 검사실적 실시간성 없음(나중에 일괄 입력).
- **Boundary(경계)** 🔗: 품질 내부. 계측값 자동연계(4.3.2 현장 검사실적관리). 검사실적—검사결과 정규화 — ⚠ **B4**.
- **Open-Issue(연계 미결)**: ⚠ B4(검사결과 헤더/라인 vs 평면·종합7) · D17(계측기 이력·S9 연계) · B5(기준 식별자).
- **[Check(확인)]**: 검사결과 입력 화면이 *항목별 라인*인지 *평면 1건*인지(B4 직결 — MES 검사실적 스키마+화면 같이 본다). 계측값 자동연계 실제 동작 여부. 검사 누락분 사후 입력 경로.

## S4. 합부 판정 (합격 / 불합격 · 특채 · 재검)

- **Trigger(촉발)**: 검사결과 입력 완료(S3).
- **Actor(주체)**: 품질담당 (특채 시 +품질책임자/생산책임자 승인).
- **Action(행위)**: 항목별 OK/NG 종합 → 검사 합/불 판정 → 합격수량/불합격수량 산출.
- **Input(입력)**: 검사결과 라인(측정값 vs 기준값), 판정 규칙.
- **Medium(매체)** 🟡: *가설* — 자동 판정(기준값 대비 시스템 판정) vs 수기 판정(육안·엑셀 수식) 불명. 특채 승인은 종이 결재 추정.
- **Result(결과)**: 합/불 판정, 합격/불합격 수량. **상태변화**: 후속 Lot Status 전이(S5) 트리거.
- **Rule(선행조건·규칙)**: 모든 필수 검사항목 측정 완료(S3). 합격→Release 대상, 불합격→Hold·불량처리(S6). 합·불 수량 ERP 연계(분해도 5.2.3).
- **Exception(예외·선행조건 미충족)** 🟠: ① **특채(조건부 합격)** — 불합격이나 사용 승인: *권한·기록 매체*? ② **재검·보류**(판정 불가·재측정) ③ **부분 합격**(수량 일부만 합격). [확인] 특채 절차·승인 권한·기록 매체, 재검 흐름, 부분 합격 처리.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 경계값 판정 모호, 특채 남용·기록 부실(구두 승인), 판정 이력 추적 미흡.
- **Boundary(경계)** 🔗: **품질 판정 → 물류(Lot Status)**. 합·불 수량 ERP 연계(검사 *결과*는 ERP, B5).
- **Open-Issue(연계 미결)**: ⚠ B4(판정 근거 = 검사결과 라인) · D2(판정→Lot Status 전이) · B5(결과 ERP 연계). (특채는 미결 번호 미부여 → [확인]으로 검증).
- **[Check(확인)]**: 합부 판정이 *자동*인지 *수기*인지. 특채를 *누가 승인*하고 *어디 기록*하나. 경계값·재검 처리.

## S5. Lot Status (Hold / Release) 물류통제

- **Trigger(촉발)**: 합부 판정(S4) / 재판정·클레임·리콜.
- **Actor(주체)**: 품질담당(상태 판정) · 물류담당(통제 적용).
- **Action(행위)**: 검사 결과 기반 LOT을 **Hold/Release** 전이, 합·불 수량 ERP 연계.
- **Input(입력)**: 판정 결과(S4), 대상 LOT(자재/생산/제품).
- **Medium(매체)** 🟡: *가설* — **재고대장 비고/색칠** 또는 시스템 상태컬럼. 실시간성 불명. Hold 표시가 물류에 *실제로 전달*되는지가 관건.
- **Result(결과)**: Lot Status(Hold/Release). **상태변화**: 출고(자재창고 S7)·출하 가용성 결정.
- **Rule(선행조건·규칙)**: 검사 미완 LOT = **Hold(기본)**. **Release분만 출고/출하 가능**. Lot Status를 **재고가 직접 보유 vs 품질 Lot Status 참조** — ⚠ **D2**. 이력 1:1(현재상태) vs 1:N(변경이력) — ⚠ **D2**.
- **Exception(예외·선행조건 미충족)** 🟠: ① **Hold 자재/제품 강제 출고·출하**(특채 연계 S4) → 차단 우회 허용? ② **부분 Hold**(수량 일부만 Hold) ③ **Release 후 재Hold**(리콜·재판정·클레임). [확인] 강제출고 차단이 *실제로 걸리는지*, 부분 Hold 사례, Hold 이력 보존.
- **Pain/Wish(문제·요구)** 🟡: *가설* — Hold 수기관리로 오출고 위험, Hold 이력 미보존(언제·왜 Hold됐는지 모름), 재고-품질 상태 불일치.
- **Boundary(경계)** 🔗: **품질 ↔ 물류/재고**(B7). 출고 차단 판정 위치 — ⚠ **D2**(종합16). 자재창고 **S6 재고보관·S7 출고**와 직결.
- **Open-Issue(연계 미결)**: ⚠ D2(Lot Status 위치·이력화·종합16) · B7(재고 상태컬럼 보유 여부).
- **[Check(확인)]**: 출고/출하 차단을 *어디서* 판정하나(재고 상태컬럼 vs 품질 Lot Status 조회). Hold 이력 남기나(1:1 vs 1:N). 부분 Hold 사례.

## S6. 불량 / 부적합 처리 (불량코드)

- **Trigger(촉발)**: 불합격 판정(S4) / 현장 불량 발생(4.3.3).
- **Actor(주체)**: 품질담당 · 현장반장(현장 불량 수집).
- **Action(행위)**: **불량코드**(불량유형·공정별) 부여 → 불량 실적 등록 → 후속(재작업/반품/폐기) 분기.
- **Input(입력)**: 불합격분, 불량코드 마스터(C1), 불량수량.
- **Medium(매체)** 🟡: *가설* — **종이 부적합 보고서/엑셀**. 불량코드 부여 수기.
- **Result(결과)**: 불량 실적(불량코드·수량). **상태변화**: 불량 LOT 후속 처리 대기.
- **Rule(선행조건·규칙)**: 불량코드 존재. **불량 실적 소유** — 품질 검사실적(C4)의 불량코드 부여 vs 현장 불량관리(4.3.3)·생산실적 단일화 — ⚠ **C2**(종합11). 공정별 불량코드 vs 공정 무관 공통 불량코드 — ⚠ **D7**.
- **Exception(예외·선행조건 미충족)** 🟠: ① **불량코드 미등록**(신규 불량유형) → 임시코드/'기타' ② **같은 불량 중복 집계**(품질+현장+생산 3경로) → 불량률 왜곡 ③ **불합격 LOT 종착 미결**(Hold 방치·반품·폐기) — 폐기는 모델 미설계(⚠ D21 갭). [확인] 불량 입력 경로(품질/현장/생산) 추적, 중복 집계 여부, 불합격 LOT의 최종 행선지.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 불량 이중집계로 불량률 왜곡, 불량코드 체계 미흡(원인 분석 불가), 불합격품 방치(재고 부정합).
- **Boundary(경계)** 🔗: **품질 검사실적(C4) ↔ 현장 불량관리(4.3.3)/생산실적**. 불합격 LOT → 반품(자재창고 **S10**)·폐기(자재창고 **S11** 갭).
- **Open-Issue(연계 미결)**: ⚠ C2(불량 실적 소유·종합11) · D7(공정별/공통 불량코드) · D21(폐기 갭·불합격 LOT 종착).
- **[Check(확인)]**: 불량을 *어디서* 입력하나(품질/현장/생산 — 경로를 따라가 본다). 같은 불량이 *중복 집계*되나. 불합격품이 *최종 어디로* 가나(재작업/반품/폐기/방치).

## S7. SPC 측정 · 관제 (Xbar-R · Cp-Cpk · OOC)

- **Trigger(촉발)**: 검사결과 측정값 축적(S3) / 설비 자동수집값 / 관제 주기.
- **Actor(주체)**: 품질담당 (+설비담당: 설비측정값 소스).
- **Action(행위)**: 측정값을 부분군(subgroup)으로 SPC 차트(Xbar-R·Cp-Cpk·Histogram) 산출, 관리한계(UCL/LCL/CL) 이탈(OOC)·패턴 감지.
- **Input(입력)**: 검사결과 측정값(S3) / 설비 측정값(Cycle_Time·사출속도/압력 등), 관리선.
- **Medium(매체)** 🟡: *가설* — **엑셀 SPC 수기 차트** 또는 **미운영**. 설비 자동수집 미연동(Middleware 향후).
- **Result(결과)**: SPC 통계·관리도, OOC 알람. **상태변화 없음**(분석/관제).
- **Rule(선행조건·규칙)**: 측정값 소스 일관. **SPC측정값 = 검사 측정값(사람 입력) vs 설비 자동수집값(별개 소스)** — ⚠ **C5**(종합14). 설비 측정값 ↔ SPC 검사항목 기준값 매핑 — ⚠ **D9**.
- **Exception(예외·선행조건 미충족)** 🟠: ① **관리한계 이탈(OOC)·Nelson 8 Rule 패턴**(분해도 B.3.3) 발생 → *누가/어떻게* 조치하나 ② **측정 데이터 부족**(부분군 미달로 통계 산출 불가) ③ **설비 자동수집 단절** → 수기 대체. [확인] OOC 발생 시 실제 대응 절차(설비 정지? 재검? 기록만?), SPC 데이터 소스.
- **Pain/Wish(문제·요구)** 🟡: *가설* — SPC 수기로 실시간성 없음(사후 분석), 측정 소스 이원화(검사값/설비값)로 정합 안 됨, OOC 대응 표준 부재.
- **Boundary(경계)** 🔗: **품질(검사 측정값) ↔ 설비(자동수집·Middleware 향후)**. — ⚠ **D9 · C5**(종합14).
- **Open-Issue(연계 미결)**: ⚠ C5(SPC측정값 소스·검사값 vs 설비값·종합14) · D9(설비측정값 SPC 매핑) · B4(SPC 측정값 = 검사결과 라인 동일성).
- **[Check(확인)]**: SPC 차트가 보는 데이터 소스(*사람 입력 검사값* vs *설비 자동수집값*). OOC 시 대응. 설비-검사항목 매핑이 실제 있나.

## S8. 출하검사 (OQC) 수행 · 판정 · 납품라벨 Matching

- **Trigger(촉발)**: 출하지시 수신 / 제품입고·포장 완료(분해도 8.3.1).
- **Actor(주체)**: 품질담당 (+출하/물류담당).
- **Action(행위)**: **제품LOT 대상** 출하검사 수행·판정 → 합격 시 **납품라벨 출력 · 생산LOT Matching · 부착**.
- **Input(입력)**: 제품LOT, 검사기준(OQC, S1), 계측기(S9), 출하지시.
- **Medium(매체)** 🟡: *가설* — **종이 출하성적서/엑셀**. 납품라벨 출력·Matching이 바코드인지 수기인지 불명.
- **Result(결과)**: OQC 합/불, 납품라벨—생산LOT Matching. **상태변화**: 합격→출하 가능(출하 절차 자체는 OUT).
- **Rule(선행조건·규칙)**: 검사기준(OQC) 존재 + 계측기 유효(S9). 합격→Release(S5). **역추적**: 납품라벨—생산LOT Matching이 *제품LOT 경유*인지 *직접*인지 — ⚠ **A5**(역추적 시작점). OQC 검사실적—제품LOT N:1.
- **Exception(예외·선행조건 미충족)** 🟠: ① **OQC 불합격 제품** → 재포장/등급강하/반품(고객반품 아님, 출하 전 차단) ② **납품라벨 Matching 불일치**(라벨↔실물 LOT 상이) → 출하 차단되나? ③ **검사 생략 긴급출하**. [확인] OQC 불합격 처리, Matching 불일치 시 출하 차단, 긴급출하 검사 생략 빈도.
- **Pain/Wish(문제·요구)** 🟡: *가설* — OQC→출하 핸드오프 수기, 라벨 Matching 오류로 오출하, 클레임 시 **역추적(genealogy) 끊김**.
- **Boundary(경계)** 🔗: **품질(OQC) → 물류 출하(C6, 출하 절차 OUT)**. 납품라벨 Matching — ⚠ **A5**. 제품LOT 발행 주체는 IQC 자재LOT과 동일 경계(ERP vs MES) — ⚠ **A1**(참조).
- **Open-Issue(연계 미결)**: ⚠ A5(역추적·납품라벨-생산LOT Matching) · A1(제품LOT 발번 주체 — IQC와 동일 경계, 참조) · B5(OQC 기준).
- **[Check(확인)]**: OQC 화면에서 납품라벨—생산LOT Matching이 *실제로 동작*하는지. 불일치 시 출하가 *정말 막히는지*. 클레임 대응 시 제품LOT→생산LOT→자재 **역추적 절차 시연**(A5).

## S9. 계측기 검교정 관리

- **Trigger(촉발)**: 검교정 주기 도달 / 신규 계측기 도입 / 계측기 고장.
- **Actor(주체)**: 품질담당 (+외부 검교정 기관).
- **Action(행위)**: 검교정 일정 관리 → 검교정 수행/의뢰 → 이력 기록 → 계측기 상태 갱신.
- **Input(입력)**: 계측기 마스터, 검교정 주기, 검교정 성적서.
- **Medium(매체)** 🟡: *가설* — **검교정 대장 엑셀/종이 성적서**. 주기 알림 수기(달력·기억).
- **Result(결과)**: 검교정 이력, 계측기 상태(정상/만료/고장). **상태변화**: 계측기 사용 가부.
- **Rule(선행조건·규칙)**: **검교정 유효 계측기만 검사 사용**(S3·S8의 선행조건). 이력 종류(검교정/점검/고장) 구분 — ⚠ **D17**.
- **Exception(예외·선행조건 미충족)** 🟠: ① **검교정 만료 계측기로 검사 수행**(S3 차단 안 됨) → 검사 결과 소급 무효화? ② **계측기 고장·분실** → 대체/검사 중단 ③ **검교정 주기 미설정 신규 계측기**. [확인] 만료 계측기 검사 통제 여부, 고장 시 대체, 주기 미설정 처리.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 검교정 주기 수기관리로 만료 놓침, **만료 계측기 검사로 결과 신뢰성 저하**, 이력 종류(검교정/점검/고장) 미구분.
- **Boundary(경계)** 🔗: 품질 내부 (+외부 교정기관). 검사실적—계측기 연계(검사결과 N:1 계측기, 계측값 자동연계 4.3.2).
- **Open-Issue(연계 미결)**: ⚠ D17(계측기 이력종류 세분) · (계측값 자동연계는 4.3.2 현장 — 향후).
- **[Check(확인)]**: 검교정 이력에 *종류(검교정/점검/고장)*를 구분해 남기나(D17). 만료 계측기로 검사가 *막히는지*. 검교정 주기 관리 방식(시스템 알림 vs 수기).

| S4 합부 판정 | B4·D2·B5 | 품질→물류 | (판정·특채) |
| S5 Lot Status | **D2**·B7·종합16 | 품질↔물류/재고 | 물류통제(Hold/Release) |
| S6 불량/부적합 | **C2**(종합11)·D7·D21 | 품질↔현장/생산 | 불량코드 |
| S7 SPC 관제 | **C5**(종합14)·D9·B4 | 품질↔설비 | SPC 측정값 |
| S8 출하검사(OQC) | **A5**·A1·B5 | 품질→출하(OUT) | OQC |
| S9 계측기 검교정 | **D17** | 품질(+외부) | 계측기 |

*최우선 검증*: **B5(검사기준 정본·소유경계)** — 모든 검사의 선행조건이자 정본 미정(ERP QM/MES/별도 QMS). 그 다음 **D2(Lot Status 위치)** — 품질 판정이 물류통제로 *실제로 전달되는가*(출고 차단의 기본 구조).

*검사 3종 통합*: IQC(자재창고 S3·OUT)·PQC(S2~S6)·OQC(S8)는 **단일 검사실적 엔티티 + 검사유형 코드**. 본 문서는 PQC·OQC를 다루고 IQC는 자재창고 문서 S3을 참조한다.

## 예외 흐름 카탈로그 (선행조건 미충족)

각 예외는 **공통 4질문**으로 점검한다 — **(a) 차단하나 / 우회(특채·강제출고·임시기준·사후입력)하나 · (b) 누가 승인하나 · (c) 어디에 기록(매체)하나 · (d) 사후 정합(ERP·재고·LOT) 방법.**

| # | 예외 유형 | 발생 단계 | 깨지는 선행조건 |
| --- | --- | --- | --- |
| E1 | 검사기준 미등록 품목·기준 버전 충돌 | S1·S2 | 검사기준 존재·단일정본 |
| E2 | 자주검사 미실시·검사 누락·사후 입력 | S2·S3 | 검사 시점 수행 |
| E3 | 계측기 미검교정·고장 상태로 검사 | S3·S9 | 검교정 유효 |
| E4 | 특채(조건부 합격)·재검·보류·부분합격 | S4 | 합격 판정 |
| E5 | Hold 강제출고·부분 Hold·Release 후 재Hold | S5 | Release분만 출고 |
| E6 | 불량코드 미등록·중복집계·불합격 LOT 종착(반품/폐기) | S6 | 불량코드·종착 경로 |
| E7 | SPC 관리한계 이탈(OOC)·Nelson rule·데이터 부족 | S7 | 관리한계 내·소스 일관 |
| E8 | OQC 불합격·납품라벨 Matching 불일치·긴급출하 검사생략 | S8 | OQC 합격·Matching 일치 |
| E9 | 검교정 만료 계측기 사용·주기 미설정 | S9 | 검교정 주기 유효 |

> **핵심 원리**: 예외는 *"선행조건 ↔ 그 조건이 깨질 때"* 의 쌍이다. 정상 흐름의 Rule 하나마다 대응 예외가 최소 1개 있다. 품질에서 *진짜 운영 차이*는 정상 합격 흐름이 아니라 **이 예외 처리에서** 드러난다 — 특히 **특채·강제출고·미검교정 검사·자주검사 누락·OOC 대응**의 실제 존재 여부와 기록·승인·사후정합 방식.

## 현장 실행 체크리스트 (품질 관리)

**1건 추적(필수)**: 실제 검사 1건(PQC 또는 OQC)을 골라 S1 검사기준→S3 검사실적/검사결과→S4 판정→S5 Lot Status→(S6 불량 또는 S8 출하)까지 *따라가며* 매체·핸드오프·합부 판정·Hold 전이 관찰. 클레임 1건으로 **역추적(제품LOT→생산LOT→자재)** 시연 요청(A5).

**수집물(실물·데이터)**:
- 종이 양식: 검사시방서·검사성적서(IQC/OQC)·자주검사 체크시트·초중종 검사표·부적합(불량) 보고서·검교정 성적서
- 엑셀: 검사대장·SPC 차트·검교정 대장·불량률 집계
- 라벨 실물: 납품라벨, 계측기 검교정 라벨
- 화면 캡처: 검사실적 입력 화면(헤더/라인 vs 평면 — B4)·Lot Status·SPC chart·계측기 관리
- **DB 스키마 + 대표 덤프**: 검사실적·검사결과·Lot Status·품질기준값·SPC측정값 테이블 (B 섹션 L3 결론)

**정량 데이터(사이징용)**: 일/월 검사건수(IQC/PQC/OQC), 검사항목 수, 불량률·불량코드 분포, 특채 빈도, 재검 빈도, 계측기 수·검교정 주기, OOC 발생 빈도.

**관찰 포인트(말이 아니라 동작)**: 자주검사가 *실제로* 도는지, 계측값이 *자동연계*되는지(아니면 수기 전사인지), Hold 자재/제품이 *정말* 출고를 막는지, 특채가 *기록되는지*, SPC가 *실시간*인지 사후 엑셀인지, 만료 계측기로 검사가 *막히는지*.
