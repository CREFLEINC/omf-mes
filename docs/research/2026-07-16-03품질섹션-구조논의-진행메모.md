## §1. 무엇을 정하는가

03 품질관리 도식을 어떻게 배치할지:
- **옵션 1 (현행)**: 03 독립 섹션 유지 — PQC 중심 메인 축 + 사이드 5종. IQC(01)·OQC(04)는 경계만.
- **옵션 2 (사용자 초기 제안)**: 03 해체 — IQC→01 사이드·PQC→02 사이드·OQC→04 사이드로 분산.
- **옵션 3 (합의된 방향)**: 하이브리드 — 트리거·수행은 도메인에 co-locate, **공통 거버넌스는 03에 "품질 공통"으로 재정의해 보존.**

## §2. 합의 (2026-07-16)

**사용자: 옵션 3이 적합.**

근거(층위 분리):
- **검사 트리거·수행** (IQC=입고 때·PQC=생산 중·OQC=출하 때) = 도메인 종속 → 각 도메인에 co-locate. **사용자 직관("PQC는 생산 종속")이 맞는 층위이며, 02에 반영돼 있다**(02 메인의 PQC 분기 → §4 재점검 결과: PQC **수행까지** 02-S-E 사이드로 이전 — 03 위임 없음).
- **품질 거버넌스** (Lot Status 전이·판정 유형 코드·불량코드 마스터·SPC/검사측정치·계측기 검교정·표준 I/F) = 3종 검사 공통 → 한 곳에 모아야 함. 이것이 03의 존재 이유.

결정적 관찰: **03의 메인(PQC)은 도메인 종속이라 분산 가능하지만, 03의 사이드 5종은 전부 공통 인프라**다(A 수리왕복·B Lot Status 전이도·C 표준 I/F·D 계측기 검교정·E 불량코드 2계층). "03 해체"는 트리거는 처리하나 이 5개 공유 조각을 집 없게 만든다.

→ **옵션 3 = 03을 "PQC 도식"에서 "품질 공통 도식(판정·Lot Status·불량코드·SPC·계측기)"으로 이름표·역할 재정의.** PQC 메인 축은 "검사 수행·판정·Lot Status 전이"로 얇게(생산 gating 로직은 02 소유). 사용자가 느낀 "PQC 종속인데 왜 독립 섹션?" 위화감 해소 — 03은 PQC의 집이 아니라 품질 거버넌스의 집.
