### 1.3 지정 정합 점검 5건 (충돌 판정 — 전부 무충돌)

**(a) #2·#3 모바일 vs 결정 17 시나리오 1(생산=POP 선배포) — 무충돌.**
시나리오 1(결정서:151)은 **생산 실행 체인(자재 투입→생산 실적→생산LOT 등록)** 을 POP 선배포로 오프라인 지속. #2(WIP 공정 이동·현장반장)·#3(수리 투입/반출)은 **공정 간 재공 이동**으로 시나리오 1 체인에 없고 주체(작업자 vs 현장반장)·행위가 다르다. WF02 S11(:227) 매체 🟡가설 = 「POP 이동 스캔 또는 구두·종이」로, POP 확정이 아니라 미확정 가설 → 모바일 확정에 충돌 없음. **WIP 이동·수리 왕복은 결정 17 2시나리오 어디에도 미해당 → 온라인 전용**(확정기록·포인터에 명시).

**(b) #5 모바일 vs 도식스펙-05 M3·사번입력 — 무충돌.**
M3(도식스펙-05:128)은 「점검 입력 매체가 POP인지 **미확정**」 → #5가 모바일로 해소(미확정 해소이지 뒤집기 아님). B1「사번입력」의 "POP 로그인 생략"(도식스펙-05:80)도 M3 미확정 우산 아래 — 점검자(U1)의 사번·점검입력 모두 모바일로 귀속(순회 점검 정합). B3「점검입력」은 Mobile 아이콘(:82)이라 배지 모바일과 우연 정합. **도식스펙-05 M3/B1 문구 갱신은 이연**(배지 미정본화 — §3 파급표).

**(c) #4 관리웹 vs 도식스펙-04 사이드 A(B1 Desktop)·OQC — 무충돌.**
04 사이드 A: SA2 물류담당 → **B1 Desktop「직행 처리」원클릭**(도식스펙-04:180) → SA3 → O3 합류(OQC M6·Packing **우회**). 직행 = **정상 절차(OQC·창고 적치) 생략 승인 + 전표 2건 자동생성 = 사무** → 관리웹(폼팩터 원칙 정합). B1 Desktop 아이콘 = 화면 조작 행위 → 관리웹과 자연 정합(아이콘=행위·배지=폼팩터, placement-plan 범례). OQC(M6)는 정상 경로 판정 지점으로 직행과 별개 → 무충돌.

**(d) #6·#7 2단말 vs 도식스펙-05 사이드 B/D — 무충돌(관찰 1건).**
고장기록 = **사이드 B B13**(File, 도식스펙-05:213 「고장 현상·비가동 사유·정지 시각 기록 — 사이드 D와 공유」). 비가동기록 = **사이드 D B19**(File, :298 「실적 비가동·현장 수집·소유 C4」), 캘린더설정 = B20 Desktop(:299, 기존 관리웹). #6(고장=모바일+관리웹)·#7(비가동=POP+관리웹)의 현장 캡처 단말 상이(모바일 vs POP)는 **사용자 폼팩터 원칙(돌발 고장 즉시 보고=모바일 / 비가동 실적 고정 수집=POP)이 disambiguate** → 충돌 아님. **관찰**: B13·B19가 사유·시각 필드를 공유하므로 2단말 캡처의 레코드 조율은 uiux/figjam 작화 시 확정(확정기록 §7 기록).

**(e) #8 명문화 대상 결정 17 시나리오 2 문언 확인 — 확정.**
