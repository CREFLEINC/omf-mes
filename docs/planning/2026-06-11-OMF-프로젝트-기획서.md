## 1. 한 장 요약 (Executive Summary)

**OMF는 LLM 기반 AI Agent가 본체에 내장된 한국형 MES다.**

- **확인된 것 (공급 측)**: 글로벌 선도 벤더(SAP·Siemens·AVEVA·Rockwell)는 2024~2026년에 걸쳐 MES·산업 플랫폼에 명시적 AI Agent를 빠르게 탑재 중이다. 반면 조사한 한국 주요 벤더 5개사 기준, MES 본체에는 LLM 기반 AI Agent가 **거의 부재**하다 — AI/ML을 별도 분석·엔지니어링 제품으로 분리 제공하거나(미라콤·삼성SDS), MES 본체의 AI 기능이 불명확하다(LG CNS). → **"AI Agent 네이티브 한국형 MES"는 엔터프라이즈 벤더군에 한해 확인된 공급 측 공백이다** (단, 국내 4개 벤더 및 SMB향 공급사 미조사, 한국 벤더 LLM 로드맵 미확인 — 공백의 지속 기간은 불확실. §9·§10).
- **확인 안 된 것 (수요 측)**: 고객이 이 공백을 돈 주고 메우려 하는가 — 즉 MES 본체 내장 AI에 대한 지불 의사 — 는 미검증이다. **§10-2 고객 검증을 go/no-go 게이트로 둔다.**
- **왜 CREFLE인가**: CREFLE는 머신비전 검사 솔루션과 이력추적 솔루션(Flowtrack)을 보유하고 있다. 검사는 제조 현장에서 품질 데이터가 *발생하는 지점*이다. 검사(품질 소스) → MES(수집·추적) → 성과분석으로 이어지는 **수직 통합**은 별도 QMS 도입 부담을 낮추면서 품질 분석이 강한 MES를 가능하게 한다(자사 검사 도입 라인에서 최대 효과 — §6). 단, 'AI 네이티브'를 만들 수 있다는 **AI 구현 역량의 근거는 본 문서에 미제시** 상태이며 §9 실행 리스크 및 §10-3 PoC 게이트로 다룬다.
- **무엇을 만드는가**: ISA-95 Part 3 활동 모델을 기준으로 한 **v1 MES 코어**(디스패칭·실행관리·데이터수집·추적 + 경량 RCA·NLQ 코파일럿) → **v2 MOM 확장**(상세 스케줄링·성과분석 심화 + 승인 게이트 기반 제한적 자율).

## 2. 배경 및 문제 정의

### 2.1 시장의 구조적 문제

**검증된 문제 (시장조사 기반):**

1. **MES와 AI의 제품 단위 분리.** 조사된 한국 벤더는 "MES 본체 = 운영 실행 기록(트랜잭션) 시스템 / AI = 별도 분석 제품" 구도다. 사용자는 실행과 분석을 다른 화면·다른 제품에서 오가야 하며, 한 화면·한 대화창에서 작동하는 통합형 AI 경험은 약하다.
   > ※ 단, 이 분리가 **왜** 존재하는지는 검증되지 않았다. 가설 3가지: (a) 고객 수요 부재(내장 AI에 지불 의사 없음) (b) 기술 부재(LLM 통합 역량 미보유) (c) 벤더 조직 구조(분석 사업부 분리). (a)라면 공백은 기회가 아니다 — §10-2 검증 대상.

**가설적 문제 [가설 — §10-2 고객 검증 대상]:**

2. **중소 제조사의 도입·운영 부담.** 기존 MES는 SI 중심 구축(커스터마이징·장기 프로젝트)이 일반적이어서, 전담 IT 인력이 없는 중소·중견 제조사에는 도입 장벽과 운영 부담이 크다는 가설. 시장조사에서 검증되지 않은 통념이므로 인터뷰로 확인한다.
3. **품질 데이터의 단절.** 검사 장비·비전 검사의 판정 데이터는 통상 별도 시스템(또는 수기)으로 관리되고, MES와의 연결은 프로젝트마다 SI로 해결되는 것으로 **추정**된다(경쟁 MES의 검사 연동 제공 방식은 미조사 — §10-1 보강 대상). 제품 계보(genealogy: 자재→제품 추적)·품질 이력·근본원인분석(RCA)으로 이어지는 데이터 파이프라인이 제품 수준에서 보장되지 않는다는 가설.

### 2.2 표준 프레임 (ISA-95 / IEC 62264)

- MES는 ISA-95 자동화 계층(Level 0~4)에서 **Level 3(제조운영관리, MOM)** 에 해당한다.
- Part 3는 MOM을 생산·품질·설비 보전(maintenance)·재고 4개 범주로 나누고, 각 범주에 공통 8개 활동(정의 관리·자원 관리 + ①상세 스케줄링 ②디스패칭 ③실행 관리 ④데이터 수집 ⑤추적 ⑥성과 분석)을 정의한다. (지원/실행 루프 구분과 ①~⑥ 번호는 본 프로젝트의 편의적 그룹핑 — 표준상 8개 활동은 동등)
- Part 4는 Job Order(작업 지시)/Job Response(작업 실적) 등 **MOM 내부(L3 활동 간) 정보 교환 객체 모델**을 정의한다. ERP(L4)와의 연동 데이터 계약은 **Part 1/2의 Operations Schedule·Operations Performance 객체**(구현 표준: B2MML)가 표준 기반이다.
- **OMF는 이 표준 활동 모델을 제품 범위 정의의 기준으로 삼는다** (→ §5). 표준 기반 설계는 ERP 연동 리스크를 낮추고, 표준 준수를 요구하는 고객에도 대응 가능하게 한다. (표준 준수는 내부 설계·연동 리스크 관리의 근거이지, 그 자체가 고객 구매 근거는 아니다 — §4.2)

## 3. 시장 분석 요약

> 상세: 시장조사 리포트(2026-06-05) 참조. 모든 주장(claim)은 3표 적대적 검증을 거침(20건 확정, 5건 반박·폐기).

### 3.1 한국 주요 벤더 — MES 본체에 LLM 기반 AI Agent 거의 부재 (조사 5개사 기준)

| 벤더 | 제품 | MES 본체 AI 현황 |
|------|------|------------------|
| 미라콤아이앤씨 | Nexplant MESplus | MES Core(생산·자재·품질·설비) 4모듈에는 없음. ML 기반 설비 분석(FDC·EPT·sDM)은 **EES 확장**에 분리 |
| 삼성SDS | Nexplant MES | 본 제품에 'AI Agent' 명시 없음(advanced analytics 수준). AI는 별도 제품(Brightics 등)에 귀속 |
| LG CNS | Factova MES | 본 제품 페이지에서 명시적 AI Agent 기능 불명확 |

| BISTel | eDataLyzer | ※ 분석 플랫폼. ML 기반 RCA이며 자율 에이전트 아님(검증에서 반박됨) |

**조사 범위의 한계 (기획 확정 전 보강 필수 — §10-1):**
- 미조사 벤더: 포스코DX, 신성이엔지, 더존비즈온, 영림원소프트랩.
- **위 표는 전부 엔터프라이즈급 벤더다.** 선언된 타깃(중소·중견, §7)에서 실제로 부딪힐 경쟁 집합 — 스마트공장 보급사업 공급기업 생태계, 경량 클라우드 MES, 지역 SI — 은 미조사 상태다. 공백 검증과 타깃의 경쟁 집합이 아직 일치하지 않는다.

### 3.2 글로벌 선도 벤더 — AI Agent 탑재 가속 (단, 다수가 로드맵/베타 단계)

| 벤더 | 제품 | 단계 (2026-06 기준) |
|------|------|------|
| SAP | Joule Agents — Production Planning & Operations Agent(조건 충족 시 주문 자동 검증·릴리스) | 2025-10 발표 시 2026 Q1 GA 계획 → 이후 자료에서 **Q2 2026으로 보고 혼재. 현재 GA 여부 1차 출처 미확인(§10-1 갱신 대상)**. SAP은 2026년 Sapphire·Hannover Messe에서 에이전트 라인업 확장 지속 발표 |
| Siemens | Industrial Copilot — 자연어 대화형 정비 지원 | 2024-07 GA, 2025-03 정비 확장 |
| AVEVA | Industrial AI Assistant — LLM+RAG 자연어 질의(HMI/SCADA/MES) | MES 질의 일부 Open Beta |
| Rockwell | NVIDIA Nemotron Nano(SLM) — 엣지·오프라인 환경 | 초기 발표 단계 |

### 3.3 시사점

1. **공급 측 공백은 실재하나 닫히는 속도가 불확실하다.** SAP의 자율 에이전트는 GA 직전·직후 경계에 있고(상단 표), 한국 벤더의 LLM 탑재 로드맵은 미확인이다. 속도가 중요하다는 판단은 유지하되, 무엇을 선점해야 하는지가 핵심이다(→ §8: 모방이 쉬운 NLQ가 아니라 모방이 어려운 검사-품질 데이터 자산).
2. **'자율'은 아직 시장 전체에서 초기다.** 명백한 자율 수준은 SAP Joule(주문 검증·릴리스)에 한정되며, Siemens Copilot은 생성형 정비 지원(코파일럿) 단계다. → OMF가 v1부터 '자율'을 약속할 필요는 없다. 코파일럿 수준의 차별화는 **수요 검증을 전제로** 후보로 성립한다(§10-2 게이트).
3. **온프레미스·엣지 요구의 존재 가능성.** Rockwell-NVIDIA의 엣지 SLM 방향(초기 발표 단계)은 제조 현장의 데이터 보안·오프라인 요구 가능성을 시사한다 [추정 — 고객 검증 필요]. → OMF의 LLM 아키텍처는 클라우드 단일 전제로 설계하지 않되, 배포 모델은 비용 트레이드오프와 함께 §11-2에서 결정한다.

## 4. 제품 비전 및 포지셔닝

### 4.1 비전

> **"불량이 나면 원인 후보까지 당일, 일일 보고는 자동 생성.**
> **작업자는 스캔·터치 한 번으로 실적을 남기고, 관리자는 한 대화창에서 답을 얻는 MES."**

페르소나 분리 원칙: **현장 작업자**에게는 최소 입력 UX(스캔·터치 — 자연어 입력을 요구하지 않는다), **관리자·품질 담당**에게는 자연어 질의·브리핑. NLQ의 실수요자는 후자다.

### 4.2 포지셔닝 — 3축 차별화

| # | 차별화 축 | 고객에게 주는 결과 | 근거와 한계 |
|---|-----------|------|------|
| 1 | **AI 네이티브** | 실행과 분석이 한 제품·한 화면 — 별도 분석 제품 구매·이중 운영 불요 | 조사 5개사 기준 공급 측 공백(§3.1). **단, 공백 ≠ 수요**: 내장 AI 지불 의사는 §10-2 검증 대상. AI는 8개 활동 전체(지원 2종 + 실행 루프 ①~⑥)에 내장 |
| 2 | **검사·품질 수직 통합** | 검사기-MES 연동 SI 비용·기간 0(자사 검사 기준), 불량 발생 → 원인 후보 제시까지 당일 [절감 규모 추정치는 §10-1 조사 후 확정] | 자사 검사 도입 라인에서 최대 효과(§6에 적용 범위·데이터 부담 명시). 비규제 업종에서 별도 QMS 도입 부담 경감 — 인증·문서형 QMS(IATF 16949 등)는 별개 영역(§6). 표준 근거(ISA-95상 in-line 품질 데이터 수집·분석은 L3 고유 활동)는 각주 수준 |
| 3 | **도입·운영 경량성** | SI 최소화로 빠른 가동, 한국 제조 현장 도메인 대응 — 작업일보·4M·수불·로트 관리 용어와 서식 그대로 질의·출력 | [가설] §2.1-2의 도입 부담 가설에 의존. "합리적 운영 비용"은 LLM 추론 비용 포함 가격 모델 수립(§10-5) 전까지 **미검증 목표**로만 표기 |

### 4.3 AI 성숙도 3단계 모델 (제품 원칙)

| 단계 | 정의 | OMF 적용 |
|------|------|----------|
| **AI 보조** | 이상 감지·알림·자동 집계 등 백그라운드 지원 | v1 |
| **AI 코파일럿** | 자연어 질의·요약·원인 후보 제시 — 판단은 인간 | v1~v2 |
| **AI 자율** | 조건 충족 시 에이전트가 업무를 직접 실행 | v2 이후 단계적 도입 |

**자율 기능 거버넌스 (통일 원칙):** v2 자율 기능은 **승인 게이트 기본 활성(필수)** 이며, 게이트 해제는 고객의 명시적 설정 + 전 실행 감사 로그를 전제로만 허용한다. (§1·§5.2·§8 모두 이 문구를 따른다)

> 원칙: **과장하지 않는다.** 시장조사에서 확인된 교훈 — '자율'을 성급히 표방한 주장들은 검증에서 반박되었다. OMF는 실제 동작 수준으로만 단계를 표기한다.

## 5. 제품 범위 (ISA-95 Part 3 기반)

> 상세 기능 정의: MOM 기능 정의서 참조. 생산(Production) 범주 우선, 품질·설비 보전·재고 범주로 단계 확장.

### 5.1 v1 — MES 코어 + AI 코파일럿

**대상 활동 (생산 범주 중심):**

| 활동 | v1 범위 | v1 AI 적용 |
|------|---------|-----------|
| 제품 정의 관리 | 품목·BOM·라우팅(공정 순서) 기본 관리 | 정의 데이터 자연어 검색 |
| 자원 관리 | 설비·인력·자재의 가용성·능력 정보 관리 | 가용성 이상 알림(보조) |
| ② 디스패칭 | 작업 우선순위 결정·작업 릴리스(디스패치 리스트) | 우선순위 변경 영향 요약(코파일럿) |
| ③ 실행 관리 | Job Order 기반 작업 시작/완료, 작업 표준 준수 확인 | 작업 이상 상황 자연어 설명 |
| ④ 데이터 수집 | 실적·품질 판정 데이터 수집. **자사 비전 검사 판정 직결(핵심 차별화)** | 수집 데이터 실시간 요약·이상 감지(보조) |
| ⑤ 추적 | 로트·시리얼 단위 생산 이력, genealogy(자재→제품 계보) | "이 로트 어디서 문제?" 자연어 추적 질의(코파일럿) |
| ⑥ 성과 분석(기본+경량 RCA) | 기본 실적 리포트(생산량·불량률·가동 개요) + **검사 판정 × 공정조건·자재로트 교차 상관 뷰** | 일일/주간 실적 자연어 브리핑 + **불량 원인 후보 제시 코파일럿(경량 RCA)** |

> **경량 RCA를 v1에 포함하는 이유**: 차별화 축 2(검사·품질 수직 통합)의 고객 체감 가치 — "불량 원인을 빨리 찾는다" — 가 v2(SPC·심화 RCA)에만 있으면 v1은 자기가 내세운 차별화를 입증하지 못한다. 또한 NLQ는 모방 장벽이 낮아(§9) 지속 해자가 아니다 — 해자는 검사-품질 데이터 자산의 조기 축적이며, 경량 RCA가 그 축적을 v1부터 시작하게 한다. (반영 여부는 §11-6 의사결정 항목)

**v1 비범위(Non-goals):** ① 상세 스케줄링 전체, 설비 보전(CMMS) 심화, 재고 범주 전체, ERP 대체 기능, QMS 인증 문서 관리.

> ※ MOM 기능 정의서는 ①을 v1(기본 순서화·재계획)+v2(자율 최적화)로 배치하나, 본 기획서는 v1 범위 최소화를 위해 ① 전체를 v2로 조정했다(의도적 차이 — §11-4에서 합의 필요). ①을 양보할 수 있는 근거: 긴급성의 대표 증거인 SAP 자율 에이전트는 대기업 ERP(SAP Cloud ERP) 연동 환경이 타깃으로, OMF의 1차 타깃 세그먼트와 겹치지 않는다는 가설 [§10-1에서 확인].

**v1 데이터 계약:** Part 4의 Job Order / Job Response 객체 모델을 **L3 내부 표준**으로 채택. ERP 연동(수주 수신·실적 업로드)은 이를 Part 2의 Operations Schedule / Operations Performance(B2MML)로 변환·집계해 처리한다.

### 5.2 v2 — MOM 확장 + 제한적 자율

| 확장 영역 | 내용 |
|-----------|------|
| ① 상세 스케줄링 | 유한 생산능력(finite capacity) 기반 작업 순서 최적화(자체 경량 구현 vs APS 제휴 — §11-7 의사결정) + 스케줄 대안 제시 코파일럿 |
| ⑥ 성과 분석 심화 | OEE, 품질 RCA 심화(다변량·예측 분석), v1 경량 RCA의 고도화 |
| 품질 범주 확장 | SPC, 검사 계획 관리 — 검사 수직 통합의 본격화 |
| 제한적 자율 | 예: 조건 충족 시 디스패치 제안 자동 생성 → 관리자 승인 후 실행. 승인 게이트 기본 활성(§4.3 거버넌스 원칙) |

### 5.3 v3 이후 (방향성만)

설비 보전(예지보전)·재고 범주 확장, 자율 범위 점진 확대, 멀티 사이트.

## 6. 핵심 차별화 상세 — 검사·품질 수직 통합

> 상세: 품질 데이터 흐름도 참조.

### 6.1 데이터 흐름

1. **현장(L1~L2)**: 자사 비전 검사가 인라인에서 판정(합/불·결함 유형·측정값) 생성. (L0은 물리적 제조 공정 자체)
2. **MES(L3)**: ④ 데이터 수집이 판정을 Job Response에 직결 수집(표준상 검사 결과는 품질 범주에 1차 귀속되나, 수직 통합 시 생산 데이터 수집 단계에서 함께 수집하는 구현) → ⑤ 추적이 로트·시리얼 계보에 연결.
3. **분석(L3)**: ⑥ 성과 분석이 공정 조건·자재 로트·설비 이력과 품질 판정을 교차 분석 → 불량 원인 후보 제시(코파일럿).

### 6.2 "그 데이터 누가 입력하는데?" — 데이터 소스별 수집 방식과 부담

교차 분석의 입력 중 자동 확보되는 것은 자사 검사 판정뿐이다. 나머지의 수집 부담을 숨기지 않는다:

| 데이터 | 수집 방식 | 현장 부담 |
|--------|-----------|-----------|
| 검사 판정 | 자동(자사 검사 직결) | 없음 |
| 자재 로트 계보 | 공정당 스캔 1회 | 현장 스캔 규율 필요 — UX로 최소화하되 0은 아님 |
| 공정 조건 | PLC/설비 연동 옵션 | 추가 구축 비용(옵션) |
| 설비 이력 | MES 내 기록 또는 연동 | 운영 규율 필요 |
| 수기 검사(자주·수입·출하) | 모바일/터치 입력 경로 제공 | 입력 부담 있음 — 품질 소스는 비전 검사만이 아님 |

**약속의 계층화:** 최소 입력(검사 판정+로트 스캔)만으로는 "불량 로트 즉시 식별·역추적 + 검사항목 × 로트 상관 후보"까지, 풀 데이터(PLC 연동 포함) 시 "공정 조건 포함 원인 후보 분석"까지. 영업·제품 메시지도 이 두 수준을 구분해 약속한다.

### 6.3 경쟁 우위의 본질과 적용 범위

- 기존 벤더 고객은 검사 장비 연동을 통상 프로젝트별 SI로 구축하는 것으로 **추정**된다 [내부 가설 — 경쟁 MES의 검사 연동 제공 방식(제품 내장 vs SI)·평균 견적·기간은 §10-1 조사 대상]. OMF는 검사 SW와 MES를 같은 회사가 만들므로 데이터 계약이 제품 수준에서 보장된다.
- **적용 범위의 정직한 한정**: 이 보장은 **CREFLE 검사 도입 라인에서 최대**다. 타사 비전·AOI·계측기가 섞인 라인에서는 해당 장비 연동이 여전히 개별 작업이다. → 타사 검사기·계측기용 **개방 표준 인터페이스(공개 데이터 계약)** 를 제공해 락인 우려에 선제 대응한다(제공 범위는 §11-8 의사결정).
- **QMS와의 경계**: 인라인 품질 데이터 수집·추적·분석은 OMF가 제품 수준에서 자동 확보한다. 고객사 감사·인증 대응(IATF 16949, 시험성적서, CAPA, 문서관리)을 위한 인증·문서형 QMS는 **별개 영역**이며 필요 시 데이터 연동을 제공한다. 인증 수요 업종(자동차·전자 부품)에는 "QMS 대체"가 아니라 "QMS에 먹일 품질 데이터를 자동으로 만들어주는 MES"로 포지셔닝한다.

| 1차 타깃 | 비전 검사 수요가 있는 중소·중견 제조(조립·가공 라인) | 기존 CREFLE 검사 고객 인터뷰 |

| MES 본체 내장 AI 지불 의사 | 별도 분석 제품 대비 내장형에 추가 지불 의사가 있다 (공백=기회 전제 자체의 검증) | 인터뷰에 비교 질문 포함 — §2.1-1의 공백 원인 가설(수요 부재/기술 부재/조직 구조) 판별 |

> ※ 본 절은 시장조사로 검증되지 않은 **내부 가설**이다. 고객 검증 전 확정하지 않으며, 합격 기준 미달 시 §10-2가 피벗/중단 분기점이 된다.

## 8. AI Agent 적용 5축 → OMF 로드맵 매핑

시장조사에서 검증된 AI Agent 적용 5개 축과 OMF 버전 매핑:

| # | 기능 축 | 시장 현황 | OMF |
|---|---------|-----------|-----|
| 1 | 품질 예측·RCA | ML 분석 단계(자율 아님) | **v1 경량 RCA**(교차 상관 뷰+원인 후보 코파일럿) → v2 심화. 수직 통합 강점 영역이자 **데이터 자산 해자의 출발점** |
| 2 | 설비 이상탐지·예지보전 | ML+생성형 혼재 | v3 — 설비 보전 범주 확장 시 |
| 3 | 생산계획·스케줄링 | 자율 에이전트 등장(SAP, GA 경계) | v2 — 스케줄 대안 코파일럿 → 승인형 자율 |
| 4 | 자연어 질의·요약(NLQ) | 생성형 코파일럿 단계 | v1 — 가시적 차별화. **단, 모방 장벽이 낮아 단독 해자가 아님**(§9) — 체감 기능으로 위치 부여 |
| 5 | 자율 업무 실행 | SAP Joule 한정(GA 경계) | v2 이후 — 승인 게이트 기본 활성(§4.3) |

**선점의 대상 재정의:** 속도 전략의 목적은 'NLQ 선점'이 아니라 **검사-품질 데이터 자산의 조기 축적**(모방 곤란 영역)이다. 기존 벤더가 챗 인터페이스를 후행 탑재해도, 검사 판정-계보-공정조건이 연결된 데이터 자산과 그 위의 RCA 품질은 단기 모방이 어렵다.

## 11. 의사결정 요청 사항 (Open Questions)

1. **타깃 세그먼트 검증 착수** — §7 가설(중소·중견 + 검사 고객 업셀)로 검증을 진행할지. 단, §10-1(b)(c) SMB 경쟁·채널 조사가 세그먼트 확정의 선행 조건.
2. **배포 모델** — 온프레미스 vs SaaS vs 하이브리드. 트레이드오프 명시 필요: 온프렘 프라이빗 LLM은 '경량 도입·합리적 비용' 포지셔닝과 충돌 → 예: SMB 기본 = SaaS/경량 모델, 온프렘 = 보안 요구 고객용 별도 티어.
3. **보강 조사 착수 여부** — §10-1 (특히 (d) 한국 벤더 LLM 로드맵과 (e) 검사 연동 SI 실태는 각각 공백 지속 기간·차별화 크기 판단에 필수).
4. **v1 범위 동의** — §5.1의 활동 범위·비범위. 특히 ① 상세 스케줄링 전체 제외(MOM 기능 정의서의 v1 배치와 의도적 차이)에 대한 합의.
5. **자사 검사 제품과의 통합 수준** — 제품명·인터페이스 표준화 범위 + AI 구현 역량 자산 목록화 (제품 조직과 협의).
6. **경량 RCA의 v1 인입 여부** — 인입(권고) vs v1 가치제안을 "추적 자동화+NLQ"로 축소하고 RCA는 v2로. 권고 이유는 §5.1 참조.
7. **스케줄링 build vs partner** — v2 ①의 자체 경량 구현 vs APS 제휴(국내 MOZART 등 후보). 판단 기준·결정 시점 합의.
8. **개방 검사 인터페이스 범위** — 타사 검사기·계측기용 공개 데이터 계약 제공 수준(락인 반론 대응 vs 차별화 희석 트레이드오프).
