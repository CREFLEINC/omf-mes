## 개요
2026-06-26 세션에서 현장 검증(STEP 3) 질문지·개념데이터모델을 검토하며 **확정·보정·등재**한 설계 결정 5건을 요약한다. 관통하는 공통 축:
1. **MES ↔ ERP/EAM 소유경계** — "무엇을 MES가 정본으로 갖고, 무엇을 외부 시스템에서 받느냐".
2. **지시–작업지시–전표 분리 패턴** — 상위 지시(ERP) / 실행(MES) / 회계전표(ERP)의 3계층.
3. **출력(파생 집계 뷰) ≠ 소유(단일 진실원)** — 화면은 다차원으로 보여주되, 기준 데이터는 한 곳에서 일관 파생.

## 1. 트랜잭션 발번 = 지시(ERP)–작업지시(MES)–전표(ERP) 3계층
**✔** 입하·입고·출고·출하·반품·재고이동·재고실사 7개 트랜잭션 번호를 "MES가 다 발번"으로 두면 회계전표(입고=G/R·출하=PGI·반품=credit·실사조정)에서 단일원장 충돌·순환의존이 생긴다. → **상위 지시(ERP, 있으면 참조)·작업지시(MES, 항상 생성)·회계전표(ERP, 회계 발생분만)** 로 분해.
- 생산의 `P/O(ERP)→W/O(MES)` 패턴을 물류·보전으로 확장한 것(동형).
- 작업지시 → 상위지시 = nullable 참조(0..1:N) → ERP 지시 없어도 MES 단독 동작.
- 순수 회계 사건(실사 조정·반품 credit)은 작업지시 없이 ERP 전표로만.

## 2. B 섹션 검증 렌즈 (L1/L2/L3)
**✔** B 항목을 세 렌즈로 재분류 → 검증 방법을 재배치:
- **L1 ERP 정본 기준정보**(B1 BOM·B2 Routing) → ERP 마스터 스키마 열람.
- **L2 소유·정본 조율**(B5·B7·B8) → 소유경계 결정(대면).
- **L3 MES 내부 키·정규화**(B4·B6·B7 키) → MES DB 스키마+덤프.
- **대면 검증이 꼭 필요한 건 L2(B5 검사기준 정본·B8 발번)·B6(발번규칙)** 로 축소. L1·L3는 자료 확보로 사실상 닫힘.

## 3. B5 보정 — 검사 기준정보 소유경계
**✔** 처음 B5를 L1(ERP)로 분류했으나 보정: **검사 기준정보는 BOM·Routing과 달리 ERP 정본이 자명하지 않다.**
- 일반 원칙(🔶): **검사 *결과*(합/불·Lot release)는 ERP, 검사 *기준*(검사항목·UCL/LCL/Target·SPC)은 QMS/MES.**
- 귀사 문서도 ERP 연계대상에 '품질'이 있으나 송신원천 목록엔 빠져 **정본 미확정** → B5 = **소유경계(ERP QM/MES/QMS) + L3 구조**.

## 4. D4 설비 보전 — EAM 미보유 → MES 경량 보유
**✔** 보전 계획·지시는 본래 EAM/CMMS 도메인이나, 고객이 **EAM 미보유** → **MES 경량 보유**로 결정.
- **점검(Daily/Monthly) = MES 유지**(작업 전 점검 차단=생산 통제 직결). **점검 ≠ 보전**(점검=진단, 보전=조치).
- **경량 범위**: 예방보전 예정일·지시·실적·고장+비가동·트리거·예비품 *사용기록* 까지 MES / **비용·자산·예비품 발주·신뢰성 분석(MTBF 등)은 범위 밖**.
- 원칙: "언제·무엇을·누가 정비했나까지 MES, 얼마(비용)·자산·발주는 범위 밖."
- 추후 EAM 도입 시 지시–작업지시 패턴으로 이관(EAM 보전오더 → MES 보전작업/실적) → 느슨 결합 권장.

## 5. 폐기(Scrap/Disposal) 갭 — 미설계, 고객 확인 대기 (D21)
**⚠** 제품·자재 폐기 처리가 **현 설계에 없다**("폐기"는 설비·툴 자산 처분 플래그뿐).
- 불량(수집)·반품(외부 방향)·실사조정(우발적 차이)과 **별개**인 내부 폐기 트랜잭션 부재.
- 영향: 재고 정합·회계(재고손익 전표)·수율·추적성.
- 요구 확인 시 → C6 신규 트랜잭션 '폐기'(대상 LOT/품목·폐기수량·사유·재고 차감) + 불량(C4)·Lot Status(C4)·ERP 재고손익 전표 연계.
- **다음 액션**: 고객 폐기 요구 유무 확인(담당: 사용자) → 있으면 설계 반영, 없으면 범위 밖 명시.

## 공통 설계 원칙 (이번 세션에서 도출)
- **소유경계가 먼저, 구조는 그 다음** — B5·D4·폐기 모두 "어디가 정본/범위냐"를 정한 뒤 키·카디널리티를 정한다.
- **지시–작업지시–전표 패턴** — 생산(P/O→W/O)과 동형으로 물류·보전에 일관 적용. ERP 지시는 nullable, 회계전표는 ERP, 실행은 MES.
- **출력 ≠ 소유** — 다차원 가동률·품질현황은 *파생 집계 뷰*로 제공하되, 기준 데이터(WorkCalendar·검사기준 등)는 단일 진실원에서 일관 파생(예: 계획비가동=분모/정지손실=분자, 차원 귀속은 출처별).
- **회계는 ERP, 실행은 MES** — G/R·PGI·credit·재고손익·폐기손익 전표는 ERP; 채번·실행·수집·트리거는 MES.
