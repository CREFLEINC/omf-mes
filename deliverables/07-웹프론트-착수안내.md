## §3. 목 서버

### 소스와 소유

```
deliverables/openapi/mdm-기준정보.json     ← 이 저장소(omf-mes)가 정본
  OpenAPI 3.1 · 경로 73 · 스키마 102 · 오퍼레이션 109
  example 478건 포함
```

**목 서버 구성은 `omf-mes-client` 저장소에서 만든다**(2026-08-04 확정). 도구 선택도 그쪽 판단이다.

⚠ **`openapi.json` 자체는 이 저장소가 정본이다.** client 로 복사해 두면 갱신이 갈린다 — **참조하거나 빌드 시 가져오는 형태**를 권한다. 스펙이 바뀌면 여기가 먼저 바뀐다.

### `example`을 넣어 두었다

목 도구가 스키마만 보고 값을 만들면 `"string"` · `0` 이 나와 **화면이 실제로 어떻게 보이는지 검증이 안 된다.** 화면 스펙의 예시 값을 그대로 넣었다.

```
warehouseName   "1공장 자재창고"       itemCode    "ABC-123"
locationCode    "A-01-03"             lotNo       "LOT-2026-0804-0031"
partnerName     "(주)대한부품"          workerName  "홍길동"
```

**전부 합성값이다.** 실제 운영 데이터가 아니므로 공개 저장소에 그대로 두어도 된다.

**문맥 보정을 6건 했다** — 예를 들어 `IntegrationMessage`는 `statusCode: FAILED` · `retryCount: 3` · `lastErrorMessage` 가 채워져 있다. `W-06-10`(재처리 화면)이 **목만으로도 의미 있는 실패 행**을 보이게 하기 위해서다.

### ⚠ 목의 한계 — 코드값 목록이 없다

`enum`이 **3개뿐**이다(`ErrorItem.scope` · `ConflictResponse.conflictCause` · `Editability.reason`). 나머지 `*Code` 필드는 **자유 문자열**이라 목이 무엇을 반환할지 모른다.

**원인** — 공통코드 그룹·값 목록이 아직 확정되지 않았다(**#64** 회신 대기). 「창고유형에 어떤 값이 있는가」가 정해지지 않았다.

**대응** — `Select`의 선택지를 **목의 응답이 아니라 프런트의 상수**로 두고 시작한다. 확정되면 API 조회로 바꾼다. 상수를 한 곳에 모아 두면 교체가 한 번에 끝난다.

> **DS 회신을 기다리지 않는다.** 6건 전부 대체 구현으로 막히지 않게 설계돼 있다(`ds-gap.md` 판정). 회신이 오면 갈아탄다.

### ⚠ 1번(행 순서)에는 저장 규약이 붙는다

순서 컬럼에 유일 제약이 걸린 곳에서는 **행을 하나씩 바꾸면 중간 상태가 제약을 위반한다**(10↔20을 바꾸는 순간 잠깐 중복이 생긴다).

**화면은 최종 순서 전체를 한 번에 보낸다.** 이동할 때마다 저장을 호출하지 않는다.

- 대상 2곳: `PUT /planning/routings/{routingId}/operations` · `PUT /quality/inspection-plan-versions/{inspectionPlanVersionId}/items`
- ⚠ **전체 치환 `PUT` 은 10곳**이지만 **순서 재배치가 걸린 것은 위 둘뿐**이다. 나머지 8곳은 부여·회수 형(§5-1)이라 순서 개념이 없다
- 근거: 공유계약 **A-5**

### ⚠ 3번(읽기 전용)은 서버가 사유를 준다

프런트가 「이 필드를 잠글까」를 판단하지 않는다. 응답의 `editability`를 읽는다.

```jsonc
"editability": {
  "codeEditable": false,
  "reason": "RECEIVED_FROM_ERP"
}
```

`reason` 은 **4값**이다(실측 `enum`).

| 값 | 뜻 | 화면 문구 예 |
| --- | --- | --- |
| `EDITABLE` | 편집 가능 | — |
| `REFERENCED` | 다른 곳이 참조 중이라 잠김 | 「N건이 참조 중이라 코드를 바꿀 수 없습니다」 |
| `NOT_COUNTABLE` | **참조 건수를 셀 수 없어** 무조건 잠김 | 「참조 범위를 확인할 수 없어 코드는 고정입니다」 |
| `RECEIVED_FROM_ERP` | 외부 시스템 원본 | 「ERP 원본이라 이 필드는 수정할 수 없습니다」 |

**문구를 한 곳에 정의**하고 6화면이 같은 말을 쓰게 한다. 지금 `RECEIVED_FROM_ERP` 는 **서버가 판정하지 못한다**(§7-1) — 값은 오지만 실제 잠금은 미구현이다.

## §5. 반드시 지킬 공통 규약

**공유계약**(`uiux/화면상세스펙-공통/공유계약.md` v0.6)이 정본이고, 여기는 **프런트가 자주 틀리는 것만** 뽑았다.
API 쪽 대응은 `06-API-요구서.md` **§4-1 공통 규약 대조표**에 조항별로 정리돼 있다 — **화면 만들기 전에 그 표를 한 번 읽어라.**

### §5-1. 리소스 패턴이 셋이다 — 109개를 규칙으로 읽는다

| 패턴 | 판별 | 화면이 하는 일 |
| --- | --- | --- |
| **마스터 형** | `:deactivate` 가 있다 | 목록 · 상세 · 생성 · 수정 · **사용 중지**(삭제 아님) |
| **부여·회수 형** | `PUT` 하나뿐 | **전체 치환** — 현재 상태 전부를 보낸다. 추가/삭제 API가 없다 |
| **버전 마스터 형** | `:new-revision` `:confirm` `:obsolete` | 헤더–버전–라인 3계층 · 확정되면 수정 불가 |

### §5-2. ★ 낙관적 잠금 — 헤더로 오간다

**가장 자주 틀리는 곳이다.**

```
GET  /mdm/warehouses/{id}     →  응답 헤더  ETag: "7"
PUT  /mdm/warehouses/{id}     →  요청 헤더  If-Match: "7"     ← 필수
```

- `ETag`를 받아 **상태에 보관**했다가 저장할 때 `If-Match`로 되돌려 보낸다
- **화면에 판 번호를 표시하지 않는다**(공유계약 A-4). 헤더로만 오간다
- 저장 응답의 `ETag`도 받아 갱신한다 — 안 하면 연속 수정 시 매번 재조회해야 한다

### §5-3. ★ 오류가 두 계열이다

| 응답 | 뜻 | 화면 |
| --- | --- | --- |
| **409** | **저장 충돌** — 보는 사이 남이 고쳤다 | 「다시 불러오세요」 · **재로드하면 풀린다** |
| **400** `code: STATE_LOCKED` | **상태 잠김** — 확정·폐기라 못 고친다 | **재로드해도 안 풀린다.** 새 Rev 발행 등 다른 행위를 안내 |

**둘을 같은 배너로 처리하면 안 된다.** 「새로고침」만 제시하면 상태 잠김에서는 눌러도 같은 화면이 돌아온다. — 공유계약 **G-1**

### §5-4. 오류 표시 위치

| 오류 범위 | 위치 | 응답 |
| --- | --- | --- |
| **한 필드** (형식·필수·유일 위반) | **인라인** — 해당 입력란 아래 | `ErrorItem.scope = "field"` + `field` |
| **여러 필드** (짝 제약·합계 불일치) | 관련 필드 전부 인라인 | 동 |
| **화면 수준** (저장 충돌·권한·통신) | **배너** `AlertBanner` | `scope = "screen"` |

서버가 `scope`를 내려주므로 **프런트가 판단하지 않는다.** — 공유계약 **G-1**

### §5-5. 그 밖 자주 걸리는 것

| 상황 | 규약 |
| --- | --- |
| **유일 제약 위반** | 오류 문구에 **어느 범위에서 중복인지** 담는다 — 「같은 공장 안에 이미 있는 코드입니다」 (A-1) |
| **짝 제약** | 둘 중 하나만 채우면 오류. **관련 필드 모두에 인라인** (A-2) |
| **합계 제약** | 실시간 잔여 표시 + 불일치 시 저장 비활성 (A-3) |
| **미확정 코드값** | 목록에 없는 코드가 오면 **원본 코드를 그대로 보이고 배지는 중립색.** 빈칸으로 두지 않는다 (G-2) |
| **비활성 사유** | 버튼을 감추지 않는다. **비활성 + 사유 표시** — 「왜」가 아니라 **「어떻게 풀 것인가」**를 담는다 (F-1 · G-3) |
| **목록** | 페이지네이션 규약은 `PageMeta` 스키마 (B-7) |
| **중복 제출** | 멱등 키 헤더 `Idempotency-Key` (C-2) |

## §7. 알고 시작해야 할 함정 — 2건

### §7-1. ⚠ 수신본 편집 잠금이 **서버에서 강제되지 않는다** (#65)

`code_group` · `code_value` · `department` 는 **ERP에서 받아온 것일 수 있어 읽기 전용이어야 하는데, 그것을 판정할 컬럼이 물리 모델에 없다.**

**그래서 API가 지금 쓰기를 열어 두고 있다.**

| 지금 | 나중 |
| --- | --- |
| 전 필드 편집 가능한 마스터로 보인다 | 수신본은 읽기 전용이 되어야 한다 |

**이대로 「완전 편집 가능」으로 만들면 — 나중에 ERP가 덮어써서 사용자 입력이 사라진다.**

**대응** — `editability`를 읽어 렌더하는 구조로 만들되, **잠금이 아직 안 걸린다는 것을 코드에 주석으로 남긴다.** 서버가 사유를 주기 시작하면 화면은 그대로 동작한다. 구조를 미리 잡아 두는 것이 핵심이다.

### §7-2. ⚠ `W-06-04` 판정유형은 **재작업 위험**이 있다

이 화면은 지금 `/mdm/code-values` 를 쓴다 — **`W-06-06`의 코드값 편집기와 같은 경로다.**

전용 통제 속성 6개(출고차단·출하차단 등)를 담을 컬럼이 **없어서**(#64), 확정이 요구한 「판정유형 전용 마스터」가 성립하지 않는다.

**대응** — **코드값 편집기를 재사용하는 형태로** 만든다. 컬럼이 생기면 필드가 추가되지 화면이 뒤집히지는 않는다. **처음부터 전용 화면으로 만들면 그때 버리게 된다.**

## §9. 막히면

### 우리가 통지하는 것 — 설계가 바뀌면

이 문서는 **전달 시점의 상태**다. 이후 설계가 바뀌어 **이미 만든 코드가 영향을 받으면 `omf-mes-client` 저장소에 이슈로 통지한다** — 접두 `[uiux→client]`.

| 등급 | 뜻 |
| :-: | --- |
| **⛔** | **이미 만든 것이 틀린다** — 조항 변경·철회, 경로 삭제, 필드 의미 변경 |
| **⚠** | 새로 만들 것이 생긴다. 기존은 안 깨진다 |

**여러분의 트래커로 갑니다.** 이 저장소를 주기적으로 들여다볼 필요는 없다.

> ⚠ 실제로 바뀝니다 — 공유계약이 **사흘에 6번**(v0.2 → v0.6) 바뀌었고 그중 「정정」이 15건이다. 예를 들어 **순서 재배치 대상이 4곳 → 3곳 → 2곳으로 두 번 줄었다.**

### 우리에게 물을 것

| 성격 | 어디로 |
| --- | --- |
| **화면 스펙이 모호하다 · API가 부족하다** | `CREFLEINC/omf-mes` 이슈 · 접두 `[client→uiux]` |
| **DS 컴포넌트가 없다 · prop이 부족하다** | `CREFLEINC/design-system-v2-webui` 이슈 — ⚠ **공개 저장소다.** 제품 화면명·내부 용어를 쓰지 않고 **컴포넌트의 언어로** 쓴다 |
| 색·간격·라운드 **값**이 없다 | 파운데이션 `design-system-v2` 이슈 |

**회신 전까지 전부 대체 구현으로 간다**(§4). 진행 상황은 그 저장소에서 본다.
