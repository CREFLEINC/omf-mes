## §5. ⭐ 적합성 — **「이 API 로 이 화면을 그릴 수 있는가」**

⚠ **커버리지 ✅ 가 적합성 ✅ 가 아니다** — 검사기는 구조를 보고, 「그릴 수 있나」는 사람이 본다.

### 5-1. ✅ 그릴 수 있다 — **5장**

`W-01-01` · `W-03-01`(⚠ 반쪽 · §5-3) · `W-03-02` · `W-03-03` · `P-02-13`.

### 5-2. ⚠ 반쪽 — `W-03-05` 검사실적·검사결과 조회

| 보기 | 그려지나 |
| --- | :-: |

### 5-3. ⚠ 반쪽 — `W-03-01` 이력 검색

**요건 ①의 세 축(기간·판정유형·행위자) 중 「판정유형」이 안 선다.** 보류 등록·해제만 남기 때문이다.

⭐ **화면이 이미 A-11 로 물러나 있다** — 「보류 이력만 보입니다」를 결과 표 머리에 적는 설계다. **계약이 그 설계를 그대로 지원한다.**

### 5-4. ⛔ 못 그리는 부분 — `W-03-09` 「부적합 열기」

`concession.nonconformance_id` 가 **NOT NULL** 인데 **부적합 상세가 04 계약**이다. 번호는 보이고 **열 수 없다**.

⚠ **`P-02-02`(05 계약 부재)와 같은 형태다.** → **착수 통지 판단 대상**(§6).

### 5-5. ⭐ 적합성이 계약을 **키웠다** — 경로 하나를 더했다

**요구서를 쓰다가 세 화면이 그려지지 않는 것을 발견했다.**

`W-03-01`·`W-03-02`·`W-03-03` 의 대상 목록은 **LOT + 품질 상태 + 보류 요약 + 창고**를 한 행에 요구하는데, **01 계약의 `GET /trace/lots` 는 물류 축이라** 그것을 못 준다:

| 화면이 요구하는 열 | 01 `/trace/lots` |
| --- | :-: |
| 창고 필터 | ⛔ **파라미터 없음** |
| 보류 수량 합계 · 가용 | ⛔ **`held` boolean 뿐** |
| 「최근 전이」·사유 | ⛔ 없음 |
| **전량 보류 여부**(선택 불가 표시) | ⛔ 없음 |

→ ⭐ **`GET /quality/lot-statuses` 신설**(경로 17 → 18 · 스키마 27 → 28).

⛔ **01 경로에 파라미터를 더하지 않았다** — 축이 다르고, 남의 계약을 이 트랙이 고치지 않는다. **같은 경로를 두지 않는다는 규칙은 지켰다.**

⚠ **02 는 적합성이 계약을 「고치게」 했고**(`ValidationFinding.severity`) **여기서는 「키웠다」.** 둘 다 **커버리지 검사기가 못 잡는 것**이다.
