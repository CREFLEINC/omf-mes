## §1. 이 계약이 무엇을 푸는가

**「발행했다」는 사실을 남기는 계약이다.** 인쇄 자체가 아니다.

라벨·검사성적서·추적보고서를 만드는 화면이 **최소 10장**인데, 도메인이 셋(01·02·04)에 걸치고 규약은 **§K 하나**다. 화면마다 발행을 다시 발명하면 회차·사유·단말 기록이 갈린다.

### 1-1. ⚠ 이 편은 **화면을 소유하지 않는다**

공유 계약이라 **경로만 공유하고 화면은 각 도메인 요구서가 센다.**

| 화면 | 어디가 세나 |
| --- | --- |
| `P-01-01` 자재LOT 등록·라벨 · `P-01-02` 출고 QR 발행 | **01 요구서** §3-6·§3-15 — 「미착지」로 적혀 있던 것을 **이 계약으로 갱신**한다 |
| `W-04-03` CoA · `P-04-01` Packing · `M-02-01` WIP 이동 | **04·02 요구서** — 출력이 액션 하나뿐이라 그쪽이 센다(§7) |
| `W-06-07` 라벨 이미지 미리보기 | **mdm 요구서** — 라벨 **양식 마스터**다 |
| **`P-02-05`·`P-02-07`·`P-02-09`·`P-04-02`·`P-04-04`** | **이 문서** — 출력이 주 기능이고 도메인 요구서가 아직 없다 |

### 1-2. §K 7조항이 계약에 어떻게 들어갔나

| 조항 | 계약이 지키는 방식 |
| :-: | --- |
| **K-1** 회차로 쌓고 지우지 않는다 | `issueSeq` 를 **서버가 매긴다**. 삭제·수정 경로 **없음** |
| **K-2** 재발행에 사유 필수 | 이미 발행된 대상이 섞이면 `reissueReasonCode` 없이는 **422** |
| **K-3** 단말·프린터를 남긴다 | `terminalId`·`printerName` |
| **K-4** 인쇄는 트랜잭션 밖 | 발행(`POST`)과 인쇄 결과 보고(`:report-print`)를 **분리** |
| **K-5** 라벨은 서버가 그린다 | `GET …/rendition` — 클라이언트는 레이아웃을 그리지 않는다 |
| **K-6** 회차를 인쇄면에 | `rendition` 이 회차를 **그려서** 준다 |
| **K-7** 기록은 남고 인쇄만 실패 | `printOutcome` **3값**(`PENDING`/`SUCCEEDED`/`FAILED`) |

⭐ **K-7 이 이 계약의 형태를 정했다.** 발행과 인쇄를 한 호출로 묶으면 「인쇄 실패 = 발행 실패」가 되어 **K-4 와 부딪친다.** 그래서 `printOutcome` 이 기본값 `PENDING` 이고, 보고 전에는 **「기록은 있으나 실제로 나왔는지 모른다」**가 정확한 상태다.

## §2. 읽는 법

`§3` 매핑표는 화면 액션 하나하나에 엔드포인트를 붙인다. **엔드포인트가 없으면 「없음 + 이유」**를 적는다 — 빈칸은 누락이다.

### 2-0. 「없음」의 이유가 셋이다

| 표기 | 뜻 | 대응 |
| --- | --- | --- |
| **없음 — API 불필요** | 화면 안에서 끝난다 | 없음 |
| **없음 — 두지 않는다** | **의도적으로 막았다** | 조항 근거를 함께 적는다 |
| **⛔ 미착지** | 있어야 하는데 없다 | 선행 이슈를 적는다 |

### 2-1. ⚠ 액션 표가 없는 화면 3장

`P-02-05`·`P-02-07`·`P-02-09` 는 **확대 3차 서식**이라 `### §5-N. 액션` 소절이 없다. 생성기가 경고로 표시하고, 요구는 **§5 본문에서 사람이 읽어** 아래 §3 에 옮겼다. **생성 목록에 없다고 요구가 없는 것이 아니다.**

## §5. 미착지가 무엇을 막는가

### 5-1. ⚠ 발행 **전** 미리보기가 없다

`rendition` 이 `documentIssueLogId` 를 받으므로 **발행해야 볼 수 있다.** 그런데 `P-04-02`·`P-04-04` 는 「미리보기 → 발행」 순서로 그려져 있다.

**두 갈래다.**

| 안 | 결과 |
| :-: | --- |
| **가** | 발행 전 미리보기 경로를 신설(`/app/document-renditions:preview` 를 `POST` — 기록 없이 그린다) ⛔ **채택 안 함** |
| **나** | 화면 순서를 「발행 → 미리보기 → 인쇄」로 바꾼다. **회차가 미리보기마다 오른다** ⛔ |

⭐ **가를 권고한다** — 나는 K-1(회차는 실제 발행 횟수)의 뜻을 깨뜨린다. **다만 화면 스펙 재확인이 선행**이라 v0.1 에서는 열어 둔다. → §8

### 5-2. ⚠ 재발행 사유 값 목록이 없다

`reissueReasonCode` 가 공통코드인데 값이 정해지지 않았다. **「인쇄 실패」 값 요청은 #64 코멘트로 올렸다**(K-7 이 만든 상태라 반드시 필요하다).

화면은 **G-2 로 비활성 + 사유**를 보인다. 계약은 값을 강제하지 않으므로 **값이 오면 계약 변경 없이 풀린다.**

### 5-3. ⚠ 프린터 목록의 원천이 정해지지 않았다

`GET /app/printers` 를 두었으나 **서버가 무엇을 보고 목록을 만드는지**는 이 계약이 정하지 않는다. `document_issue_log.printer_name` 이 **자유 텍스트**라 마스터가 없다.

⛔ **`mdm.terminal` 에 프린터 축이 없다**(실측). 단말–프린터 매핑이 어디 사는지가 미결이다 → §8

### 5-4. ✅ **해소 — 목록 화면이 액션을 활성할 수 있다** *(리뷰 반영)*

초안은 이력 조회가 **대상 하나씩**뿐이었다. 그런데 화면 셋이 **행마다** 「이미 발행됐는가」를 알아야 한다.

| 화면 | 액션 | 활성 조건 |
| --- | --- | --- |
| `P-04-02` | 재발행 사유 선택 | **이미 발행된 대상** |
| `P-04-02` · `P-04-04` | 발행 이력 보기 | **대상에 회차 ≥ 1** |
| `P-02-05` | 대량 발행 | 480건 중 **무엇이 재발행인가** |

⛔ **건당 1회 호출이면 480건에 480번**이라 목록을 그릴 수 없다. → **`GET /app/document-issues/summary`** 신설(대상 최대 1000건 한 번에).

⚠ **발행한 적 없는 대상도 `issueCount: 0` 으로 돌려준다** — 빠뜨리면 화면이 **「모른다」와 「없다」를 구분할 수 없다**(G-9).

### 5-5. ✅ **해소 — 개체를 만들 경로가 생겼다** *(2026-08-13 · 같은 날 발견하고 같은 날 메웠다)*

**§3-1 이 「개체 생성은 02 생산실행 계약 소관」이라 적고 넘겼는데, 그쪽에도 없었다.**

착수 통지 발행 직전 실측에서 잡혔다 — 전 계약 6종에 `serial` 이 경로·스키마로 등장하는 파일이 **0건**이었다(`mdm-기준정보.json` 의 6건은 설비 일련번호로 다른 것이다).

```
화면 스펙 §5-3 이 그린 주 기능
  ① serial_number × N      개체 생성    ⛔ 없었다  →  ✅ POST /trace/serial-numbers
  ② document_issue_log × N 발행 기록    ✅ POST /app/document-issues
```

⛔ **①이 없으면 ②의 `targets` 에 담을 것이 없다.** 대상이 존재하지 않으므로 발행 자체가 실행되지 않았다.

⭐ **한 트랜잭션이 아니라 두 요청이다.** 화면 스펙은 둘을 한 묶음으로 그렸지만 계약은 나눴다.

| | 왜 |
| --- | --- |
| **각 요청 안에서는 전량 롤백** | 480개 중 300개만 만들어지면 번호에 구멍이 나고 그것을 메울 화면이 없다 |
| **두 요청 사이는 끊어도 된다** | ①만 성공하면 「개체는 있고 아직 발행 안 됨」이 되고, 화면이 그 상태를 다시 잡아 ②를 부른다. 화면 §6 이 이미 같은 형태를 다룬다 — 「프린터 오프라인 → 개체는 생성되고 인쇄만 실패 → 재인쇄로 해결」 |
| **소관이 갈린다** | 개체는 생산실행, 발행 기록은 여기. 한 요청으로 묶으면 한쪽이 남의 표를 쓴다 |

⚠ **화면 스펙 §8 은 「차단 0건」이라 적었다.** 스펙 작성(2026-08-04)이 이 계약(2026-08-07)보다 앞서 미착지를 알 수 없었다. **`M-02-02` 와 같은 형태 두 번째** — 「차단 0건」 문장을 믿지 않고 §8 을 전수 확인한 것이 잡았다.
