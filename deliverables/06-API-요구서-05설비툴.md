## §1. 범위

### 1-1. 이 계약이 소유하는 것

```
maintenance   inspection · breakdown(+attachment) · order · result
              downtime · tool-usage · collection-channel · calibration      8자원
mdm           equipment-group · equipment(쓰기) · equipment-inspection-item
              (+부여) · mold · spare-part(+설비 매핑) · work-calendar
              (+일자·적용)                                                  6마스터
app           operation-policy                                              1정책
```

### 1-2. 소유하지 않는 것 — 명시

| 제외 | 어디 |
| --- | --- |
| 변경 이력 조회 | **기준정보** — `GET /audit/events`. 네 화면이 같은 것을 부른다 |
| QR 라벨 발행·이미지 | **공통 출력물** — `/app/document-issues` 계열 |
| 예비품 **출고** 전표 | **01 자재창고** — 보전 실적은 출고 건을 **참조만** 한다 |
| 작업 전 점검 통제 | **02 생산실행** — `P-02-02`. 05 는 통제의 **근거만** 만든다 |
| 검사 실행 | **03 품질** — 05 는 검교정 유효 게이트의 **근거만** 만든다 |
| 설비종합효율(OEE) | ⛔ **1차 범위 밖** — 재료 셋은 실재하나 소유가 세 도메인으로 갈린다 |

### 1-3. ⭐ 왜 계약 파일 셋에 걸치나 — **읽는 쪽이 갈린다**

| 무엇 | 어디 | 왜 |
| --- | --- | --- |
| **보전 기록** 8자원 | 전용 파일 | 05 만 쓴다. 보전이 이 도메인의 본체다 |
| **마스터 6종** | 기준정보 | ⭐ **05 밖에서도 읽는다** — 툴은 생산 실행이, 작업 캘린더는 통합 대시보드가, 예비품은 06 이 소유한다 |
| **환산 정책** | 공통 | ⭐ **05 전용이 아니다** — 같은 표를 작업 전 점검 통제와 경미 정지 임계가 함께 쓴다 |

⛔ **「05 것이니 05 파일에」로 가르지 않았다.** 가르는 기준은 **「누가 읽는가」**다. 마스터를 05 파일에 두면 생산 실행이 남의 도메인 파일을 불러야 한다.

### 3-0. 「없음」의 다섯 갈래

| 갈래 | 뜻 |

### 3-1. `W-05-12` 설비·설비그룹 마스터 *(관리웹)*

| 액션 | API | 근거 |
| --- | --- | --- |
| 그룹 추가 · 설비 추가 | `POST /mdm/equipment-groups` · `POST /mdm/equipments` | §5-1 · A-1 |
| 저장 / 취소 | `PUT /mdm/equipment-groups/{equipmentGroupId}` · `PUT /mdm/equipments/{equipmentId}` — 토큰은 같은 경로 상세 조회의 `ETag` | §5-4 · B-1 |
| 사용 중지 | `POST /mdm/equipment-groups/{equipmentGroupId}:deactivate` · `POST /mdm/equipments/{equipmentId}:deactivate` — ⛔ 물리 삭제 없음 | §5-1 · B-4 |
| 점검 항목 부여 편집 | `PUT /mdm/equipment-groups/{equipmentGroupId}/inspection-items` · `PUT /mdm/equipments/{equipmentId}/inspection-items` — **묶음 통째 교체** | §5-1 · B-6 · G-30 |
| 변경 이력 | `GET /audit/events` — 기간 필수 | §5-1 · B-5 |
| 계층 텍스트 확인 | `GET /mdm/equipments/{equipmentId}` 응답의 `hierarchy` — ⭐ **화면이 잇지 않는다.** `groupAssigned` 가 거짓이면 「소속 그룹 없음」을 밝힌다 | §5-3 · G-9 |

- **참조 건수를 화면이 세지 않는다** — 상세 응답의 `editability` 가 가부와 사유를 함께 내린다(B-4).
- ⭐ **설비 그룹의 저장처는 생산 라인 표다.** 상류는 「설비그룹」, 물리 모델은 「생산라인」이라 이름이 둘인데 형태가 같다. 계약은 화면의 말을 쓰고 `Equipment.productionLineId` 가 같은 값임을 설명에 적었다.
- ⛔ **상위 그룹 순환을 물리 제약이 막지 않는다** — 직계 자기참조만 막힌다. 서버가 진다(A-9 등급 2).

### 3-2. `W-05-11` 계측기 마스터 관리 *(관리웹)*

| 액션 | API | 근거 |
| --- | --- | --- |
| 계측기 추가 | `POST /mdm/equipments` — ⭐ **전용 경로를 두지 않는다.** 계측기는 설비의 한 종류이고 `equipmentTypeCode` 가 가른다 | §3-2 |
| 저장 / 취소 | `PUT /mdm/equipments/{equipmentId}` | §5-6 · B-1 |
| 사용 중지 | `POST /mdm/equipments/{equipmentId}:deactivate` | §5-1 · B-4 |
| 폐기 처리 | `POST /mdm/equipments/{equipmentId}:dispose` — ⭐ 사용 중지와 **다른 축**이다 | §5-1 · B-16 |
| 검교정 이력 등록으로 이동 | ⛔ **없음 — 소관 이동.** 등록은 `W-05-10` 의 `POST /maintenance/calibrations` 다. 이 화면은 `GET /maintenance/calibrations` 로 읽기만 한다 | §5-1 · B-4-1 ④ |
| 변경 이력 | `GET /audit/events` | §5-1 · B-5 |

- **목록은 `GET /mdm/equipments` 에 `equipmentTypeCode`·`calibrationRequired` 를 걸어 부른다.**
- ⭐ **네 모양을 그릴 재료가 다 있다** — 대상 아님 · 아직 안 함 · 유효 · 만료. 앞 셋은 `calibrationRequired`·`lastCalibrationDate` 로, 넷째는 `calibrationDueDate` 와 오늘을 견줘 만든다. ⛔ **「만료」를 컬럼에 넣지 않았다** — 아무도 아무것도 하지 않아도 날짜가 지나면 바뀌는 값이다(A-15).
- **검교정 주기와 정밀도는 신설한 두 칸이다** — 주기가 없으면 다음 예정일을 산출할 수 없다. 조건부 필수(검교정 대상이면 주기 필요)는 물리 제약이 막지 않아 서버가 진다.

- ⭐ **라벨이 나간 코드는 참조가 0이어도 잠근다** — `editability.reason=LABEL_ISSUED`. 참조 0은 「시스템 안에서 아무도 안 쓴다」이지 「현장에 아무것도 없다」가 아니다.

### 3-7. `M-05-01` 설비 점검 입력 *(모바일)*

| --- | --- | --- |

| ⑤ | ⛔ **툴의 날짜 주기 축이 통째로** | `W-05-02` | 주기 유형·간격·단위 + 마지막 시행일 + 파생 넷 |
| ⑥ | 보전 지시의 기준일 | `W-05-02` | `baseDate` |

### 5-1. ⭐ ①이 가장 위험했다 — **판정을 바꾸면 그 판정을 인용한 자리를 센다**

4단계에서 「계측기 전용 경로를 두지 않는다」로 판정을 바꿨다. **그때 `gaugeId` 를 함께 고치지 않았다.** 구현팀은 `gaugeId` 를 보고 `/mdm/gauges` 를 찾다 막혔을 것이다.

⛔ **저장 충돌 토큰을 「응답 헤더에서 받는다」고 적고 헤더를 선언하지 않아 19곳이 막힌 것과 같은 형태다** — 둘 다 **가리키는 곳이 없는 이름**이다.

⭐ **05 는 아직 착수 통지 전이라 지금 고치는 것이 공짜였다.** 통지 뒤였으면 ⛔ 변경 통지 대상이다.

### 5-2. ⭐ ⑤는 화면 하나가 통째로 성립하지 않던 자리다

확정이 「예방보전 트리거 = 타발수 + 날짜 주기 **겸용 설정형**」인데 계약에는 **타발수 축만** 있었다. 목록이 절반만 나온다.

⚠ **화면 스펙에도 없었다** — 툴 마스터 스펙(`W-05-13` §4-A)의 필드표에 주기 세 칸이 없다. **11차에 그 화면을 쓸 때는 13차의 판정이 아직 없었기 때문**이고, 13차가 「툴 마스터에 주기 축 셋을 더한다」로 정한 뒤 **11차 필드표로 되돌아가지 않았다.** 이번에 함께 적었다.

⭐ **파생 넷은 저장하지 않는다** — 다음 예정일 · 도래 여부 · 먼저 도달한 축 · 초과율. 판별 질문은 하나다 — **「아무도 아무것도 하지 않아도 이 값이 바뀌는가.」** 넷 다 「예」다.
