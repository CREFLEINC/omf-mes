# UI 적합성 점검표

> 「이 API 로 이 화면을 그릴 수 있는가」를 화면별로 판정한다.
> 근거: `uiux/2026-08-03-API스펙/00-설계.md` §5-2

## 1. 진입 호출 수

- 화면을 처음 그리는 데 필요한 호출을 **전부 나열**했는가
- 선택 목록 조회가 **3회를 넘으면** 그 이유를 적었는가

관리웹은 온라인 전제(결정 17)라 호출 수 자체가 결함은 아니다 — **세지 않은 것이 결함이다.**

## 2. 필요한 정보가 응답에 있는가

화면이 **스스로 계산하거나 추가 호출로 알아내야 하는 것이 없어야** 한다.

| 확인 | 근거 |
| --- | --- |
| 코드 수정 가능 여부와 사유가 응답에 있는가 | 공유계약 B-4 |
| 선택 목록의 유효성 판정을 서버가 했는가 | G-8 |
| 저장 충돌의 원인 구분이 응답에 있는가 | B-1 |
| 오류의 범위(필드/화면) 구분이 응답에 있는가 | G-1 |
| 유일 위반의 범위가 응답에 있는가 | A-1 |
| 일괄 처리의 건별 결과가 응답에 있는가 | C-2 |

## 3. 안 쓰는 것을 담고 있지 않은가

- 응답 필드 중 **화면 스펙 §4 필드표에 없는 것**이 있는가
- 있다면 왜 필요한지 적었는가(정렬 키·다음 호출의 입력 등)
- ⚠ **대외비가 섞이지 않았는가** — `W-06-10` 의 payload 가 대표 사례다

## 4. 예외를 표현할 수 있는가

화면 스펙 **§6 의 각 행**이 어느 오류 코드·상태코드로 오는지 대응이 있어야 한다.

조건부 필수 위반 · 짝 제약 위반 · 범위 위반 · 유일 위반 · 권한 없음 · 상태 불일치

## 5. 상태 전이를 지원하는가

- 화면 스펙 **§5-2 의 각 상태**를 만들 수 있는가
- **§5-4 의 편집 잠금**(수신본 / 상태=확정 / 참조 존재 / 권한)을 **판정할 근거가 응답에 있는가**
- ⚠ 「수신본이라 잠김」은 **현재 판정 근거 컬럼이 없다(#65)** — 그 사실을 적는다

## 판정

화면별로 다섯 항목에 **✅ / ⚠(조건부) / ❌** 를 매긴다. **❌ 는 API 설계 결함**으로 보고 고친다.
