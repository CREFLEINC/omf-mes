# 재작성 판정 기준 — Tier 0 / 1 / 2

> 왜 이게 필요한가: `uiux/2026-08-18-최종산출물-문서구성/00-설계.md`가 기록한 선례 —
> 원본을 검토해 처음부터 다시 쓰는 "전량 신규 작성" 방식으로 만든 편람 8종이 **3주 만에
> 6/8이 낡았다.** 이유는 "복사본에는 갱신 의무가 아무에게도 없다"는 것. 이번 재구성도
> 같은 실수를 반복하지 않기 위해 대상마다 재작성 강도를 다르게 정한다.

## Tier 0 — 복제 금지, 링크만

**대상**: `openapi/*.json`, 물리 모델 SQL, 확정기록 원문, 두 번 이상 인용되는 수치(조항 수·
화면 수·경로 수 등).

**규칙**: Wiki 페이지는 이 자료를 절대 복제하지 않고 **딥링크만** 건다. 정본이 하나여야
하는 것을 둘로 만들면 반드시 어긋난다 — 예전에 낡은 6/8이 전부 "손으로 옮겨 적은 수치·
산문 요약" 유형이었다.

**판정법**: "이 값이 나중에 재실측하면 달라질 수 있는가?" → 그렇다면 Tier 0.

## Tier 1 — 경량 재작성 (덜어내기)

**대상**: 화면 상세 스펙 118장.

**방식**:
1. 9블록 구조·필드표 **원문은 그대로 재사용**(재타이핑 금지 — 복사+붙여넣기만).
2. 배치 폴더·차수("확대3차" 등) 언급을 제거한다.
3. §8 미결은 **생존 항목만 남기고** 해소된 것은 L4(근거·이력)로 옮긴다.
4. 페이지 맨 위에 3줄 요약(개요·데이터·액션)을 블록 0으로 신설한다.
5. 원문 필드 수 = 재작성본 필드 수가 **반드시 1:1 일치**해야 한다 — 어긋나면 재작성이 아니라
   유실이다.

**금지**: 필드 정의·검증 규칙 문장을 새로 쓰지 않는다. 자리만 옮긴다.

## Tier 2 — 재구성형

**대상**: README류, 화면진도표, 08/09 표지, 용어사전처럼 이미 "표지+지도+판단"만 담는
허브 문서.

**방식**: 이미 좋은 패턴이므로 크게 다시 쓰지 않는다. 그 패턴 자체를 `wiki/00-index.md`나
이 schema 문서로 **승격**한다.
