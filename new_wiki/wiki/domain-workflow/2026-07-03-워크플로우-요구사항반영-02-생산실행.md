## 0. 사용법 · 범위 · 발견 방법

**이 문서의 위상**: 사전 정의 = *커버리지 체크리스트 + 현행 가설 + 2026-07-01 요구사항 명세서의 검증·요구 반영*. 명세서로 검증된 항목(✅ REQ 표기)은 확정으로 다루고, 잔존 🟡 가설은 여전히 **반증할 대상**이다. 각 단계의 Medium·Pain 중 미검증분은 전형적 제조 SME(종이·엑셀·구두·반자동) 기준 추정이며, **UNIMES 제안서(벤더 To-Be)에 앵커링하지 않는다** — 단계 목록(분해도 §2·3·4)만 커버리지로 빌려오고, *현행이 실제 어떻게 도느냐*는 개방형으로 듣는다.

**범위(IN)**: P/O 수신 → W/O 전개·확정 → 자원배정(4M 계획) → 작업 시작(작업 전 점검 통제) → 작업실적 수집(생산수량·4M투입·불량·비가동·검사실적 트리거) → 생산LOT·인식표 발행 → 공정 이동(WIP) → W/O 완료·마감. 즉 **지시가 현장에 내려가 실물 생산·실적·LOT으로 완결되는 사이클**.
**범위(OUT, 별도 워크플로우)**: 자재 입출고·재고(자재창고 문서 ①)·품질 검사 *내부 절차·검사실적 소유·판정·Lot Status·검사방식 거버넌스*(품질 문서 — **소유·거버넌스 OUT 유지**. 단 2026-07-16 캔버스 재구성으로 PQC **검사 수행·검사 결과 입력 *지점*은 02-S-E 사이드로 이전**, 03 재정의 확정 2026-07-20(도식스펙-03 v2.1 Lot Status 전이도·검사 수행 도메인 co-locate) · 상호 참조) *(기존 서술 폐기: 2026-07-16 캔버스 재구성 — 수행 지점 02 이전, 소유는 03 유지)*·제품 출하·Picking&Packing. (단 경계로 맞닿는 지점은 🔗로 표시 — 특히 자재 출고(투입), 생산창고 버퍼, 검사 트리거)

**발견 방법(현장)**: ① 1건 추적(실제 W/O 1건을 편성→배포→작업시작→실적→생산LOT→완료까지 따라가기) ② 관찰(말이 아니라 실제 동작 — POP/단말에서 무엇이 *찍히는지*) ③ 실물·데이터 수집(작업지시서·실적 입력 화면·인식표 라벨 실물·비가동 코드표·DB 스키마+덤프). 각 단계 끝 **[Check(확인)]** 에 관찰·수집·질문 포인트.

**워크플로우 개요(검증·요구 반영)**
```
[ERP 발주/생산계획(P/O)] ─연계 수신→ S1   (P/O 변경 → W/O 전파: 중단/수량 변경 + 관리자 확인 ✅ REQ-PR-0024)
  S1 ─→ S2 W/O 전개·편성(세부공정 — Routing 정본=MES, 부재 시 BOM 기반 fallback ✅ REQ-PR-0026)
        ─→ S3 자원배정(4M 계획)·유효성Validation ─→ S4 W/O 확정·현장 배포

  현장 ─→ S5 작업 전 점검 (인증=작업 시작 전 사번 입력, 로그인 없음 ✅ REQ-PR-0023) ──미실시→ [작업 통제: 차단/경고/미적용 설정형·긴급 W/O 우회] (D3 확정 ✓QA#9)
            └합격→ S6 작업 시작·4M 투입(라인 수령 검증 → 자재LOT·금형QR 스캔, 오투입 Validation,
                                        러닝체인지·재생재 투입·생산창고/호퍼 경유)
                      └─→ S7 작업실적 수집(생산수량·양품/불량/손실 3원·작업조건)   ← 작업실적 = 생산LOT 1:1 ✅
```

**W/O 상태 체계 — 상태 전이 그래프 확정 (✓설계확정 2026-07-06 결정 14)**: '재시작' 상태 제거, 아래 그래프의 상태 값으로 확정 —

```
편성 → 확정 → 배포 → 진행 → 완료 → 마감
                │       ↕ (중단/재개 — 반복 가능)
                │      중단
                ├→ 진행불가 (자원 Validation NG — 해소 시 배포로 복귀)
확정·배포·진행 → 취소
```

**'재시작'은 상태가 아니라 중단→진행 전이 이벤트** — 상태로 두면 재시작 후 '진행'과 구분되지 않는 죽은 값이 된다 *(기존 서술 폐기: '중단·홀드 ↔ 재시작' 상태 추가 — 재시작을 상태 값으로 표기)*. **중단=작업홀드이력 구간(P2 패턴: 현재 상태 1행+변경 이력 1:N)** — 홀드이력 1건=사유 코드·시작/종료 일시·행위자·홀드품(생산LOT·수량)·보관 Location, **W/O당 N회 반복** 가능하며 "현재 중단 중"=미종료 홀드이력 존재와 상태 컬럼의 정합을 시스템이 보장한다. **마감 시 미종료 홀드는 강제 종료(처리 결과=마감 편입)** — 미달 마감의 이월/소멸 선택(QA #27) 흐름에 합류. 중단 구간 합계=W/O 단위 비가동(중단 기인분) 집계의 원천. — ✅ (REQ-PR-0009 요구: 홀드된 제품 정보·보관장소·작업중단 사유 기록). 중단 사유=관리자 설정형 코드(추가 가능, 초안 3종: 긴급 오더 끼어들기·설비 고장·도구 고장)·홀드품 보관장소=라인사이드 (✓확정 2026-07-04 QA #25). 현행은 작업 중단 시 따로 이력 관리 없이 바로 다른 작업을 진행 중 — ✅ (REQ-PR-0009 현행).
> ※ **두 Hold의 구분(각주)**: 여기서의 **작업중단 홀드(REQ-PR-0009)**는 W/O·생산 영역(C2)의 상태 체계다. 품질의 **Lot Status Hold**(검사 판정 기반, C4/D2 — 의심 자재·판정 보류, REQ-PR-0027)와는 **별개 상태 체계**이므로 혼동하지 않는다.

## S1. P/O 수신 / 생산계획 인지

- **Trigger(촉발)**: ERP에서 P/O(생산계획·대표공정 단위) 발행 → MES 연계 송신 / 생산 착수 임박.
- **Actor(주체)**: 전산(ERP 연계)담당 · 생산관리자.
- **Action(행위)**: P/O(품목·수량·완료예정일·자재예약정보)를 MES가 연계 수신·인지, W/O 전개 대상 식별. **P/O 변경 이벤트 수신 시 W/O 전파 처리**(아래 Rule) — ✅ (REQ-PR-0024).
- **Input(입력)**: P/O(ERP 발행분), BOM(**ERP 보유·Rev 관리 확정 — B1 종결, 유효기간=선택(optional) 속성** (✓확정 2026-07-04 QA #3) *(기존 서술 폐기: ERP 보유 여부 재확인 필요)*), 공정/Routing(**MES 정본** — 충돌①, S2 참조).
- **Medium(매체)** 🟡: *가설* — ERP가 Time Schedule/Event로 송신 → MES Temp Table 적재(자동) **또는** 현행은 ERP 화면 조회 후 **엑셀/구두로 생산계획 공유**(연계 미구축 시). 어느 쪽인지가 핵심 분기.
- **Result(결과)**: P/O 연계 참조본 보유(MES). **상태변화 없음**(정보 수신). W/O 전개 대기.
- **Rule(선행조건·규칙)**: P/O 존재. **P/O는 ERP 발행·MES 수신본(수정 불가)** — ✅ 모델 정의(C2), 명세서로 유지 검증(P/O 변경은 ERP 측 사건이고 MES는 W/O 전파로 대응). **P/O 변경 시 W/O 전파 규칙**: ① 중단 → 생산 계획 중단 ② 수량 변경 → 생산 계획 수량 변경 — 두 경우 모두 **관리자 확인** 후 처리 — ✅ (REQ-PR-0024 요구). 관리자 확인 화면에서 **'변경 반영 vs 기존 유지(강행)' 선택 가능 — 강행 시 P/O-W/O 불일치 플래그 명시** (✓확정 2026-07-04 QA #23).

- **Actor(주체)**: 생산관리자 (+설비/현장담당).

- **Exception(예외·선행조건 미충족)** 🟠: ① **자원 충돌·중복 배정**(한 설비 다 W/O 동시) → 우선순위·강제 배정? ② **Validation NG 무시하고 확정**(이상 알림 묵살) → 권한·기록? ③ 배정 자재가 결품(가용재고<소요) → 배정 보류/부분 배정? ④ 배정 작업자 미출근·자격 미달. [확인] Validation NG 시 차단되나, 배정-투입이 화면상 분리되나(D11), 충돌 배정 조정 방법.

## S4. W/O 확정 · 현장 배포 (+ 생산LOT 선발행 · 전달사항 · 출고요청 자동 발행)

- **Open-Issue(연계 미결)**: ⚠ C1 — **종결**(Notice 단일 엔티티+scope·표시방식·확인이력, 알림과 자동/수동 경계 분리 — ✓설계확정 2026-07-06 결정 02) · A3·B3(작업실적=생산LOT 1:1, ✅확정 — 현장 실태만) · ~~생산LOT 선발행 vs 실시간(C3 발행방식, 분해도 2.2.2.3)~~ — **종결**(W/O 배포 시 선발행 ✓확정 2026-06-24 · 선발행=번호/슬롯 예약·완료 전까지 실물 미귀속 ✓확정 2026-07-15 — 현행 실태 관찰만 유지) · 신규: BOM 미비 시 출고요청 자동화 정지 리스크(REQ-PR-0022 연계).

## S5. 작업 전 점검 / 작업 통제

- **Trigger(촉발)**: 작업자가 **작업 시작 전 사번 입력(로그인 없음)** → 배포 W/O 선택 → 작업 착수 시도 — ✅ (REQ-PR-0023 요구). *(기존 가설 폐기: '작업자 POP 로그인' 전제 — 현장 단말기 로그인은 작업성을 떨어뜨려 생략, 충돌·명세서 우선.)*
- **Actor(주체)**: 현장반장·작업자 (+설비담당).
- **Action(행위)**: 설비 작업 전 점검(Daily Check 등) 수행·기록 → 점검 이력 없으면 작업 통제 — **차단/경고/미적용 3단계 정책을 설정으로 선택(설정형)** (✓확정 2026-07-04 QA #9) *(기존 서술 폐기: 일률 '차단' 단정)*. 점검·작업 기록의 작업자 귀속은 **사번 입력 기반** — ✅ (REQ-PR-0023 요구).
- **Input(입력)**: 사번, 설비 점검 항목·기준(설비 마스터), 점검 이력.
- **Medium(매체)** 🟡: *가설* — 종이 점검표·체크시트 **또는** POP 점검 입력. 통제(차단)가 *시스템 강제*인지 *반장 구두 확인*인지 불명.
- **Result(결과)**: 점검 이력 생성(사번 귀속), 작업 진행 허용/차단. **상태변화**: W/O '배포'→'진행 가능' 또는 '진행불가'.
- **Rule(선행조건·규칙)**: **작업 전 점검 이력 존재 = 작업 진행 선행조건** — ✅ 분해도 3.1.1 — 단 통제 수준은 **차단/경고/미적용 3단계 설정형이며 긴급 W/O는 우회 허용** (✓확정 2026-07-04 QA #9). **현장 단말 인증 = 작업 시작 전 사번 입력(로그인 생략)** — ✅ (REQ-PR-0023 요구).
- **Exception(예외·선행조건 미충족)** 🟠: ① **점검 미실시인데 작업 강행**(긴급·통제 미작동) → 확정: 통제 자체가 3단계 설정형(차단/경고/미적용)이고 **긴급 W/O는 우회 허용** (✓확정 2026-07-04 QA #9) — 잔여: 우회 시 기록·승인 주체. ② **점검 NG(설비 이상)** → 작업 통제 + 보전(C5) 연계·비가동 처리? ③ 점검 항목 미등록(신규 설비). ④ **사번 오입력·대리 입력**(경량 인증의 귀속 오류) → 검증·보정 방법? [확인] 점검 미실시 시 *실제로* 작업이 막히나(시스템 강제 vs 구두), NG 시 보전/비가동 전환 경로, 통제가 W/O 상태에 반영되나.

## S6. 작업 시작 · 4M 투입 (라인 수령 검증 · 자재LOT·금형QR 스캔 · 러닝체인지 · 재생재)

- **Actor(주체)**: 작업자·현장반장.
- **Action(행위)**:

BOM 고정 적합성 Validation과의 정합 — 부분 확정: **러닝체인지는 부품 교체이므로 Routing 무관(계획·생산LOT 분할로 처리), W/O=Routing Rev 스냅샷 고정, BOM Rev와는 느슨한 연결(강제 동기화 없음)** (✓설계확정 2026-07-06 결정 07) — 투입 Validation의 BOM 기준 시점 상세는 잔여.

## S8. 공정검사(PQC) 트리거 · 품질 연계

- **Exception(예외·선행조건 미충족)** 🟠: ① **검사기준 미등록**(신규 품목/공정) → 무검사 진행/임시기준? ② **검사 NG(공정 불량 발생)** → 작업 중단·재작업·특채 분기 — 판정 유형 확장(한도승인·특채·폐기 등, 목록 고객 회신 대기)과 연계(REQ-PR-0027). ③ 계측기 미검교정·자동연계 두절 → 수기 입력? ④ ~~자주검사 미실시(생략)~~ → 재정의: **생략은 정식 옵션** — ✅ (REQ-OA-0003) — 생략 시 기록·승인 조건은 잔여 확인. [확인] 검사기준 없을 때 진행 방법, NG 시 생산 통제 경로.
- **Pain/Wish(문제·요구)** 🟡: *가설* — 검사 결과 종이→엑셀 이중입력, 검사-생산 실적 연계 끊김, 검사기준 버전 혼선. (OA는 전수검사 결과를 정리·보유 중이 확인됨 — 이중 정리 부담 추정, ✅ REQ-OA-0003 현행)

- **Open-Issue(연계 미결)**: ⚠ B5 — **종결**(검사기준=MES 정본·검사 결과 ERP 비연계·생산 실적 연계 필수 — QA #4 2026-07-04) · B4(검사결과 헤더/라인 — 내부 설계 전환, QA §1) · 검사실적—W/O 연결(C4 미결, PQC가 W/O vs 생산LOT 단위) · ~~PQC 생략 시 기록·승인 조건~~ → 재정의: 생략=Routing 미명시 시 자동(설정 기반 opt-in — QA #4), 별도 생략 승인 절차 논점 소멸 · **부품사업부 PQC 방식**(전수 vs 샘플링 — 사업부별 상이 가능, OA만 확인됨) · ~~캠데코 연동 통신방식~~ → 표준 I/F 스펙=CREFLE 정의(QA #8 — 자료 회수 의존성 소멸).

## S10. 생산LOT 완료 · 인식표 발행

- **Trigger(촉발)**: 생산LOT 양품 목표 수량 달성(또는 마감 결정).
- **Actor(주체)**: 작업자·현장반장 (+Label Printer).
- **Action(행위)**: 생산LOT 완료 처리 → **인식표(QR) 발행·부착**(양품 생산품 **개체별 1:1**, seq=개체 일련번호) + **LOT 라벨 출력·부착(LOT 단위 — 2026-07-16 캔버스 [3.작업자] 2단)**. 불량품 미부착 — **불량 물량은 생산불량LOT으로 분리 관리**(2026-07-15). **별도 포장 작업 공정([4.포장] — 생산 인라인 포장 아니고 별도 포장 마감 필요 시)**: 포장 작업자가 LOT 스캔→제품 포장→LOT 단위/제품 단위 포장별 라벨 재출력·부착 (결정 05 보정 정합 — 생산 포장 원천=포장단위 생성 / 「재발행」=재출력=기존 인식표·생산LOT 라벨 재인쇄·신규 발행 아님, 결정 13. 사용자 확정 2026-07-20). 출하 포장(P&P)=04 소관 경계 유지.
- **Input(입력)**: 완료 생산LOT(양품수), 인식표 양식(생산LOT No+seq).
- **Medium(매체)**: **✅(간접)** — **라벨 프린터 '설치' 요구(REQ-PR-0017)가 현행 프린터·라벨 인프라 부재를 방증** → 수기 라벨/미부착 추정 강화(실물 확인은 잔여 🟡). **To-Be = Label Printer 신규 설치 전제**. 부착 단위(개체/이동/박스)가 핵심.
