# 귀속 사번을 「받을 자리」로 계약에 선언한다 — 이슈 omf-mes#178

> 작성일: 2026-08-21 · 작성 주체: CREFLE OMF 팀 (UI/UX)
> 계약 패치: `deliverables/openapi/patch-178-worker-no.py` · 검사기 신설: `deliverables/openapi/check-worker-no.py`
> 앞선 작업: `uiux/2026-08-21-검사자-서버파생/00-완료보고.md`(#173) — 이 건은 그 보고가 「남은 것 ①」으로 넘긴 것이다

## 무엇

**현장 단말·모바일의 쓰기 요청이 사번을 실을 자리를 계약에 만들었다.**

공유계약 **D-5**(귀속 정보는 세션이 아니다)가 「현장 단말·모바일의 쓰기 요청에 사번 **필수** — 없으면 서버가 거부」라고 정해 두었는데, **그 사번을 받을 자리가 응용 프로그램 인터페이스 계약(OpenAPI) 일곱 벌 어디에도 선언돼 있지 않았다.**

| 대상 | 바뀐 것 |
| --- | --- |
| 계약 **6벌** `components.parameters` | `WorkerNo`(필수) · `WorkerNoOptional`(선택) 신설 — **쓰는 파일에만** |
| 쓰기 **36 오퍼레이션** | 참조(`$ref`)로 헤더를 건다 — **필수 30 · 선택 6** |
| 공유계약 **D-5** | 소절 신설 — 「계약이 이 헤더를 선언한다」 + **필수·선택이 갈리는 이유**. 판 v3.0 → **v3.1** |
| 공유계약 **F-4** 미결 행 | 단말 토큰 세대 번호와 **같은 층이지만 별건**임을 표시 |
| 요구서 **6장** | 변경 이력 · 01자재창고 §4-1 공통 규약 대조표에 **D-5 행** 신설 |
| 검사기 **신설** | `check-worker-no.py` — 실측 계수와 검증을 겸한다 |

⛔ **건드리지 않은 것** — 경로 · 질의 · 쓰기 본문. **헤더만 는다.** 그래서 이미 만든 코드는 깨지지 않는다.

## 어떻게

### ⭐ 뿌리 — 저장 충돌 토큰에서 겪은 것과 **같은 형태**다

| | 저장 충돌 토큰(2026-08-17) | 귀속 사번(이번) |
| --- | --- | --- |
| 조항이 정한 것 | `If-Match` **필수** | 사번 **필수 — 없으면 거부** |
| 계약이 빠뜨린 것 | 그 값을 **받을 곳**(`ETag` 응답 헤더) | 그 값을 **실을 곳**(요청 헤더) |
| 드러난 방식 | 구현팀이 물었다 | 구현팀 질의 #173 을 풀다가 옆에서 드러났다 |
| 규모 | **19건** | **36 오퍼레이션** |

**받을 자리를 계약이 선언해야 한 세트가 된다.** 조항에만 적힌 필수는 구현되지 않는다.

⚠ **이번 것은 실패 방식이 더 나쁘다.** 저장 충돌 토큰은 구현자가 「어디서 받나」를 몰라 **물어봤다.** 귀속 사번은 계약에 없으면 **아무도 안 묻는다** — 프론트는 보낼 생각을 못 하고 서버는 누가 했는지 모르는 채 기록을 남긴다. **조용히 빈 채로 쌓인다.**

### 실측 — 36 오퍼레이션 · 36화면 · 계약 6벌

```
기준: deliverables/06-API-요구서-*.md 는 화면마다 `### 3-N. <화면ID>` 소절을 갖고
      그 안의 액션 표가 「메서드 + 경로」를 적는다. 소절 머리의 화면 ID 가
      P-(현장 단말)·M-(모바일)이면 그 소절의 쓰기 호출을 모은다.
정본: deliverables/openapi/check-worker-no.py
```

⭐ **경로 이름을 계약 실물로 정규화해 오퍼레이션 단위로 접었다.** 요구서가 같은 경로를 `{id}` 와 `{putawayTaskId}` 로 **달리 적은 자리**가 있어, 이름을 그대로 두고 세면 한 오퍼레이션을 둘로 **많게** 센다.

| --- | :-: | :-: | :-: |
| `logistics-01자재창고.json` | 17 | 13 | 4 |
| `production-02생산실행.json` | 10 | 10 | 0 |
| `equipment-05설비툴.json` | 6 | 6 | 0 |
| `app-공통.json` | 1 | 0 | 1 |
| `quality-03품질.json` | 1 | 0 | 1 |
| `shipment-04제품출하.json` | 1 | 1 | 0 |
| `mdm-기준정보.json` | **0** | — | — |
| **합계** | **36** | **30** | **6** |

기준정보가 0인 것은 **관리웹 전용**이기 때문이다 — 계정 토큰이 곧 귀속이라 헤더가 필요 없다.

### ⚠ 이슈 #178 이 적은 「37경로」를 **36 오퍼레이션**으로 정정한다

이슈를 낼 때 쓴 계수기는 경로 이름을 정규화하지 않아 `putaway-tasks:complete` 를 **둘로 셌다**. 또 `/trace/serial-numbers` 를 자재창고 계약으로 적었으나 실제로는 **생산실행 계약**에 있다.

| | 이슈 #178 | **실측(정정)** |
| --- | :-: | :-: |
| 대상 | 37경로 | **36 오퍼레이션 · 36경로** |
| `logistics-01자재창고` | 18 | **17** |
| 화면 | 36 | 36 (변동 없음) |
| 계약 | 6벌 | 6벌 (변동 없음) |

⚠ **더 앞선 판은 「39화면 · 218 쓰기 오퍼레이션(상한)」이었다** — 그것은 상한 추정이었고 실측이 이 표다. 품질 요구서 v0.4 가 적어 둔 「39화면」도 이번에 정정했다.

### ⚠ 이 수치는 **하한**이다 — 무엇을 «안» 보는가

검사기 첫머리에 적어 두었다(uiux-design §2-4 — 「적게 세면 그것을 믿고 놓친다」).

- **소절 밖**(문서 머리말 · 역방향 점검 표)에만 적힌 호출 — 못 본다
- **메서드를 안 적고 경로만** 쓴 줄 — 못 본다
- 한 소절이 **여러 화면을 겹쳐** 다룰 때의 화면별 귀속 — 소절 전체로 뭉갠다
- 요구서에 **아직 안 적힌** 화면의 호출 — 없는 것으로 친다
- 사번이 **맞는 사람인지** — 계약이 답할 물음이 아니다(도용 리스크 수용 · D-1)

⇒ 「전부 덮었다」가 아니라 **「여기까지는 덮었다」**이다.

## 왜

### ⭐ 여섯을 「선택」으로 둔 것이 이 건의 핵심 판단이다

서른여섯 중 **여섯은 관리웹 화면도 같은 경로·같은 메서드를 부른다.**

| 오퍼레이션 | 현장·모바일 | 관리웹도 부른다 |
| --- | --- | --- |
| `POST /app/document-issues` | `P-01-01` 외 5 | `W-05-13` |
| `PUT /inventory/counts/{inventoryCountId}/lines` | `M-01-11` | `W-01-04` |
| `POST /logistics/goods-issues` | `M-01-08` | `W-01-05`·`W-01-06`·`W-04-10` |
| `POST /logistics/goods-receipts` | `M-04-04` | `W-01-10`·`W-04-06` |
| `POST /logistics/stock-transfers` | `M-01-10` | `W-04-11` |
| `POST /quality/inspection-results` | `P-02-13` | `W-01-01`·`W-04-03` |

⛔ **일괄로 필수를 걸면 관리웹이 「없는 사번」을 지어내게 된다** — 관리웹 화면에는 사번 입력 자리가 없다.

**그래서 서버가 인증 토큰의 종류로 가른다.**

| 온 곳 | 헤더 | 서버가 행위자를 푸는 법 |
| --- | :-: | --- |
| 계정 토큰(`app_user`) — 관리웹 | 없어도 된다 | **인증 주체 그 자체** |
| 단말 토큰(`mdm.terminal`) — 현장 단말·모바일 | **없으면 거부** | 헤더가 지목한 사번 |

⭐ **이것은 #173 에서 확정한 규칙의 확장이지 새 규칙이 아니다.** #173 은 「행위자는 서버가 인증 주체에서 푼다」로 닫았는데, **관리웹은 인증 주체가 곧 사람**이고 **현장 단말은 인증 주체가 단말**이라 사람을 헤더가 지목한다.

⚠ **응용 프로그램 인터페이스 규약으로는 「단말 토큰이면 필수」를 표현할 수 없다.** 선택으로 두고 규칙을 설명문에 적었다 — `IfMatchVersionOptional` 이 **이미 같은 방식**이다. ⛔ **「헤더가 선택」이 「사번이 선택」은 아니다.**

### 선례를 그대로 따랐다 — 새 방식을 만들지 않았다

| | 저장 충돌 토큰 | 귀속 사번 |
| --- | --- | --- |
| 필수판 | `IfMatchVersion` | **`WorkerNo`** |
| 선택판 | `IfMatchVersionOptional` | **`WorkerNoOptional`** |
| 두는 곳 | `components.parameters` — **쓰는 파일에만**(7벌 중 4벌) | 같음(7벌 중 **6벌**) |
| 거는 법 | 오퍼레이션의 `parameters` 에 참조 | 같음 |

계약 일곱 벌 전부 헤더를 `components.parameters` 에 두고 참조한다 — **경로에 직접 쓴 선언은 0건**이다.

### ⭐ 택하지 않은 안 넷

| 안 | 왜 아닌가 |
| --- | --- |
| **서른여섯 전부 필수** | 관리웹 6화면이 **없는 사번을 지어내야 한다.** 지어낸 값은 그럴듯한 문자열이라 감사 기록에 박혀도 아무도 못 잡는다 |
| **관리웹 겸용 6경로를 셸마다 쪼갠다** | 경로가 늘고 **화면 ↔ 경로 매핑을 다시 짜야 한다.** 같은 일을 하는 두 경로는 서버 구현도 두 벌이 된다 |
| **본문 필드로 받는다** | ⛔ **#173 에서 방금 뺀 것을 되살리는 것**이다. 「같은 것을 두 경로가 말하면 어긋날 자리만 생긴다」 |
| **단말 토큰에 사번을 넣어 발급한다** | ⛔ **귀속을 인증으로 승격시키는 것**(F-2 단서 금지). 게다가 **교대마다 토큰을 재발급**해야 하고, 그러면 사번이 곧 인증 자격이 되어 REQ-PR-0023 의 「로그인 생략」이 우회로 되살아난다 |

### 검사기를 실측 정본과 **한 몸**으로 만들었다

`check-worker-no.py` 가 요구서에서 대상을 세고, `patch-178-worker-no.py` 가 **그 계수를 그대로 가져다 쓴다.** 목록을 패치 쪽에 베껴 두면 요구서가 바뀔 때 두 벌이 **조용히 갈린다.**

검사기가 보는 것 셋 — ① 대상 오퍼레이션이 헤더를 선언하는가 ② **필수·선택 등급이 맞는가**(관리웹이 겹치면 선택이어야 한다) ③ 쓰는 파일이 그 파라미터를 정의하는가.

## 남은 것

### ① ⚠ 구현팀 변경 통지 — **초안만 썼다. 아직 안 보냈다**

| | |
| --- | --- |

| 대상 | `CREFLEINC/omf-mes-client` (**공개 저장소**) |

**검사기가 잡아 준 것 둘** — ① 예시값으로 쓴 사번이 **실 사번 형식**(`9` + 다섯 자리)이었다 → 합성값으로 바꿨다 ② 요구사항 번호에 뜻을 붙여 적었다 → **번호를 빼고 규칙만** 남겼다(프론트에게 내부 번호는 쓸모가 없다).

⚠ **낼 시점은 판단이 필요하다.** 규칙대로면 ⚠ 등급은 **차수 마감 때 묶어서** 낸다. 그런데 **이미 착수 통지가 나간 현장·모바일 화면이 36건 열려 있어**(`omf-mes-client`), 그 화면들이 쓰기를 구현하는 시점에 이 헤더가 필요하다. ⛔ **늦으면 「조용히 빈 채로 쌓이는」 실패가 먼저 일어난다.**

### ② ⏳ 단말 토큰 세대 번호 — **우리가 못 닫는다**

`mdm.terminal.token_version` 이 물리 모델에 없어 **분실 단말을 영구히 끊을 수 없다**(공유계약 §I-31 · F-4 「현재 구현 불가」). 귀속 헤더와 **같은 인증 층**이지만 그쪽은 **물리 모델 결손**이라 우리 소관이 아니다.

⭐ **기다리지 않고 헤더를 먼저 넣었다**(uiux-design §1-2 — 물리 모델이 못 담아도 계약은 화면대로 쓴다). 기다렸으면 둘 다 안 됐다.

### ③ ⚠ 미결 대장이 스펙과 갈려 있다 — **이번 작업이 만든 것이 아니다**

`collect-open-items.py --check` 가 붉다. ⭐ **main 에서 돌려도 똑같이 붉어** 기존 상태임을 확인했다. 이 작업 범위 밖이라 손대지 않았다 — 고치면 #178 과 무관한 변경이 같은 판에 섞인다.

### ④ ⚠ 요구서에 계약과 안 맞는 호출 표기가 1건 있다

`POST /logistics/{문서}/{id}:request-cancel`(`W-01-13`) — 세 리소스를 **묶어 쓴 표기**라 계약 경로와 문자 그대로는 안 맞는다. 관리웹 화면이라 이 건의 대상은 아니고, 검사기가 「대상 밖」으로 분류해 알린다.
