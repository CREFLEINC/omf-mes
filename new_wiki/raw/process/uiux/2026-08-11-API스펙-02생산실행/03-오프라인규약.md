# 02 생산실행 — 3단계 오프라인 규약

> 작성일: 2026-08-11 · 선행: `02-URL동작규약.md`
> **대상**: POP 13장이 쓰는 큐 경로 · 2단계가 넘긴 미결 2건

## 1. ⛔⛔ 먼저 — **오프라인 헤더는 이미 정의돼 있다**

「3단계에서 확정한다」로 넘겼는데 **01 계약이 이미 갖고 있다.** 실물을 열어 확인했다.

```json
components.parameters (logistics-01자재창고.json)
  IdempotencyKey          required: true    uuid    "전 쓰기 API 필수. 같은 키로 다시 보내면 새 전표를 만들지 않는다"
  IfMatchVersion          required: true            "낙관적 잠금용 version_no … 근거: 공유계약 B-1"
  IfMatchVersionOptional  required: false           "오프라인에서도 쓰는 오퍼레이션에서는 선택이다 —
                                                     없으면 낙관적 잠금 검사를 건너뛴다.
                                                     큐에 쌓인 요청은 토큰을 싣지 않는다. 근거: 공유계약 C-9"
```

⭐ **2단계 §6-3 의 「경로를 나누지 않고 헤더로 구분」은 이미 그렇게 구현돼 있다** — `IfMatchVersionOptional` 이 정확히 그 장치다.

⚠ **이번 세션 다섯 번째 「이미 처리돼 있다」** — 휴일 달력 · 인증 3컬럼 · 알림/공지/좌표 · 액션 표 7장 · **이 건**. ⛔ **관문 ②를 「이슈」에만 쓰고 「계약」에는 안 돌렸다.**

## 2. ⭐ 그래서 02 가 더할 것은 **넷이다**

**01 계약이 공유계약 오프라인 조항을 몇 개나 실었는지 세었다.**

| 조항 | 01 계약 인용 | 02 가 |
| :-: | :-: | --- |
| **C-8** 멱등키·`business_date` | **16건** | ✅ 계승 |
| **C-9** 큐는 잠금 토큰 미탑재 | **11건** | ✅ 계승 |
| **C-7** 저장 피드백 두 등급 | ⚠ **인용 0건** *(그러나 `202` 는 6곳에서 쓴다)* | ⭐ **규약을 명시한다** §3 |
| **C-10** 순서 의존 묶음 거부 | ⛔ **0건** | ⭐ **더한다** §4 |
| **C-12** 발생 시각은 단말 시계 | ⛔ **0건** | ⭐ **더한다** §5 |
| **C-16** 부분 전송 — 급한 것 먼저 | ⛔ **0건** | ⭐ **더한다** §6 |

⚠ **01 이 안 실은 것이 게으름은 아니다** — 01 의 오프라인은 **모바일 입출고 단일 단말**이라 넷이 다 안 걸렸다. **02 는 POP 13장이고 작업이 이어진다.**

## 3. ~~C-7 — 저장 피드백이 두 등급이다~~ ⛔⛔ **2026-08-12 철회**

> **이 절의 판단이 틀렸다. 아래 서술은 이력으로만 남긴다.**
>
> ⛔ **오프라인이면 HTTP 요청 자체가 없다** — C-1 이 클라이언트 outbox 라고 정했으므로 서버는
> 그 요청을 본 적이 없다. 서버가 「큐에 담겼다 — 아직 서버가 모른다」를 응답으로 말할 수 없다.
>
> ⛔ **근거였던 「01 도 202 를 쓴다(`202:6`)」가 틀렸다** — 여섯 건 전부 **결재 상신·ERP 재동기**다.
> **응답 코드 분포만 세고 뜻을 안 봤다.** 이 프로젝트가 반복해 온 「수는 맞는데 뜻이 다르다」이다.
>
> ⭐ **C-7 은 화면 조항이다**(`Toast` ↔ `Chip(warning)`). 미확정 표식은 **셸의 outbox** 가 붙인다.
> → 02 계약에서 오프라인 `202` **11건을 뺐다**(`:resync` 1건은 진짜 비동기라 남는다).


```
201 Created      즉시 성공 — 서버가 받았고 번호가 정해졌다
202 Accepted     큐에 담겼다 — 아직 서버가 모른다
```

⚠ **`202` 자체는 01 이 이미 쓴다** — 응답 코드 분포 실측 `200:67 · 201:12 · **202:6** · 400:42 · 403:39 · 404:22 · 409:32`. ⛔ **없던 것을 더하는 게 아니라 「두 등급」 규약을 명시하는 것**이다. **C-12 와 같은 형태** — 필드·코드는 있고 규약이 안 적혔다.

⭐ **`202` 는 「성공」이 아니라 「접수」다.** 화면이 그렇게 말한다(`M-01-12` §6-1 의 「LOT 번호는 전송 후 정해집니다」와 같은 형태).

| 오퍼레이션 | 정상 | 큐 |
| --- | :-: | :-: |
| 세션 열기 · 투입 · 실적 · 중단 | **201** | **202** |
| 조회 | 200 | ⚠ **캐시**(C-6 — 판정값은 캐시하지 않는다) |

⛔ **`202` 응답에 리소스 ID 를 넣지 않는다** — 아직 없다. **멱등키를 돌려준다.**

## 4. ⭐⭐ C-10 — 순서 의존은 **한 곳만 강하다**

**02 의 큐 항목이 서로 순서에 걸리는지 실측했다.**

| 큐 항목 | 선행이 필요한가 | 근거 |
| --- | :-: | --- |
| **작업 중단·재개**(`work_session_event`) | ⛔⛔ **필요하다** | `work_session_id` **NOT NULL** — `P-02-10` §5-2 「**세션이 없으면 기록할 수 없다**」 |
| **자재 투입**(`material_consumption`) | ⚠ **아니다** | `work_session_id` **nullable** — `P-02-03` §5-5 |
| 실적 등록(`production_result`) | ⚠ 아니다 | W/O 로 선다 |
| 세션 작업자 | ⛔ 필요 | 세션 FK |

⭐ **세션을 만드는 요청이 큐에 있으면, 그 뒤 세션 참조 요청은 묶음으로 간다.**

```
묶음 = [ 세션 열기, 이벤트…, 작업자…, 세션 닫기 ]
  → 앞이 실패하면 뒤를 보내지 않고 묶음 전체를 거부한다 (C-10)
  → 409  { "code": "BATCH_DEPENDENCY_FAILED", "failedAt": <멱등키> }
```

⛔ **투입·실적은 묶지 않는다** — 세션 없이도 서므로 **각자 간다.** ⚠ **묶으면 하나가 막을 때 나머지가 같이 못 간다.**

⚠ **배치 경로를 새로 만들지 않는다** — 클라이언트가 **순서대로 보내고 실패 시 멈춘다.** 서버는 **선행 부재를 409 로 답할 뿐**이다. ⭐ **01 에 배치 경로가 0건인 이유가 이것이다.**

## 5. C-12 — **발생 시각은 단말이 보낸다**

```
production.work_session_event.occurred_at   timestamptz NOT NULL   (SQL 889)
```

⭐ **`occurredAt` 은 01 계약이 이미 30곳에서 쓴다.** ⚠ **그런데 C-12(오차 보정 규약)를 인용한 곳이 0건**이다 — 필드는 있고 **규약이 안 적혔다.**

**02 가 적는다**

| 규칙 | |
| --- | --- |
| **클라이언트가 보낸다** | 서버 수신 시각으로 덮지 않는다 |
| **서버 수신 시각도 남긴다** | `created_at`(**893** · `DEFAULT clock_timestamp()`)이 그 자리다 |
| ⚠ **둘의 차이가 임계를 넘으면** | **거부하지 않고 표시**한다 — 현장 기록을 버리지 않는다(**C-12**) |

> ⛔ **2026-08-18 정정 — 여기서 인용을 잘못했다.** `G-20` 은 「**버려지는** 데이터가 있으면 화면이 그렇게 말한다」이지 「버리지 마라」가 아니다. **뜻이 반대로 읽혔고 그 오독이 계약 `description` 으로 복사돼** 구현팀이 읽었다. 맞는 근거는 **C-12**(발생 시각은 단말 시계가 정한다 — 서버가 덮지 않는다)다.
> ⚠ **왜 안 잡혔나** — 조항 인용 검사기가 `uiux/` 만 훑어 **계약 안의 인용은 0건 검사**다.
| ⛔ **미래 시각** | **거부**한다 — 400 |

⚠ **임계값을 계약이 정하지 않는다** — `operation_policy` 후보(**B-22** 목록에 일곱째). → §8

## 6. C-16 — **부분 전송은 「급한 것 먼저」**

큐가 여럿 쌓였을 때 **전송 순서**다.

| 순위 | 무엇 | 왜 |
| :-: | --- | --- |
| **1** | **세션 닫기**(`:end`) | 열린 채로 남으면 **다음 작업이 409** 로 막힌다 |
| **2** | 실적 · 투입 | 재고·집계에 든다 |
| **3** | 이벤트 · 작업자 | 이력 |

⛔ **계약이 순서를 강제하지 않는다** — **클라이언트 규약**이다. 계약은 **묶음 거부(§4)만 정의**한다. ⭐ **계약이 못 하는 것을 계약에 적지 않는다.**

## 7. ⭐⭐ 2단계 미결 — **`:override` 를 삭제한다**

2단계가 「기록 자리가 없으면 경로를 만들지 않는다」로 넘겼다. **A-13 4단을 돌렸더니 자리가 있다.**

```
production.work_session_event (SQL 884) — 실측
  886  work_session_id   bigint NOT NULL  FK
  888  event_type_code   code_t NOT NULL      ← 「통제 우회」를 값으로
  889  occurred_at       timestamptz NOT NULL
  890  reason_code       code_t               ← 우회 사유
  891  performed_by      bigint               ← 누가 우회했나
  892  terminal_id       FK
  893  created_at        DEFAULT clock_timestamp()
```

⭐ **여섯 컬럼이 우회 기록에 필요한 것을 그대로 갖고 있다** — 신설 0.

⭐ **`P-02-02` 화면이 이미 「기록이 남습니다」라고 말하고 있다**(§4 화면 66행) — **약속은 돼 있었고 자리를 못 찾았을 뿐**이다.

### 그래서 액션이 아니라 **세션 생성의 인자**가 된다

```
POST /production/work-sessions
  { workOrderId, …, "controlOverride": { "reasonCode": "...", "note": "..." } }
    → 세션 + work_session_event(CONTROL_OVERRIDE) 를 한 트랜잭션으로 만든다
```

⛔ **`:override` 액션을 두지 않는다** — 우회는 **세션을 여는 순간에 일어나는 것**이고, 별도 액션이면 **우회만 하고 세션을 안 여는 상태**가 생긴다.

⚠ **`:동사` 가 12 → 11 로 준다.** ⭐ **F-6 을 만족한다** — 우회가 **기록되지 않으면 세션이 열리지 않는다.**

⚠ **`event_type_code` 값 목록에 `CONTROL_OVERRIDE` 가 붙는다**(`P-02-10` §8-1 이 「값 목록 미정」으로 남긴 그 목록) — ~~**A-16 대응표**에 등재~~ → ✅ **`A-25` 대응표에 등재 완료(2026-08-23)**. ⚠ **`A-16` 이 아니었다** — `A-16` 은 등재 «시점»을 정하는 운영 규칙이고, 표 자체의 집은 `A-25`(판별자 코드가 형제 사유 칸의 코드 그룹을 정한다)다.
