### 1-1. 2단계 예측과 **하나 달랐다 — 그리고 그것이 맞았다**

```
2단계 예측   경로 15 · 오퍼 19
파일 실측    경로 16 · 오퍼 19
```

**차이는 `PUT /logistics/shipment-lot-allocations/{id}`** — 2단계를 쓸 때 `P-04-01` §4-C 의 「배분 **읽기·갱신**」에서 **갱신**을 흘렸다. 포장을 확정하면 **배분에 취급 단위를 이어야** 한다.

⭐ **오퍼레이션 수는 맞았다** — 2단계가 `POST /shipment-lot-allocations` 를 세었는데 **그것이 없어지고 `PUT` 이 생겼다.** 우연히 상쇄된 것이라 **계수가 맞은 것을 근거로 삼지 않는다.**

## 3. ⭐ 03 의 Blocker 를 **처음부터 막았다**

생성기 끝에 **공유 스칼라 오염 가드**를 넣었다(`I64`·`QTY`·`TS`·`DT`·`STR`·`INT`·`BOOL` 7종).

**일부러 오염시켜 확인했다.**

```
종료코드 1
⛔ 공유 스칼라 TS 이 오염됐습니다 — 추가된 키 ['description'].
```

⚠ **「가드를 넣었다」와 「가드가 잡는다」는 다르다** — 03 재리뷰에서 얻은 것이다.

⭐ **재현 확인** — `rm` 후 재생성해 sha256 일치.

## 4. ⛔⛔ 계약이 드러낸 것 — **처분 결정을 만드는 화면이 없다**

```
GET  /quality/disposition-decisions          ✅ 낸다 — 세 화면의 진입 목록
GET  /quality/disposition-decisions/{id}     ✅ 낸다 — 판정 이력 보기
POST                                          ⛔ 만들지 않는다
```

`x-internal-note` 에 **왜 없는지와 무엇이 막히는지**를 그대로 적었다 — 「03 요구서는 04 것이라 넘겼고 `W-04-07` 은 03 이 만든다고 적었다 · **서로에게 미뤘다**」, 「이 목록이 비면 세 화면이 진입하지 못한다」.

⚠ **02 가 `material-losses` 를 뺀 것과 같은 규칙**(부르는 버튼 0건)인데 **파급이 다르다** — 저쪽은 아무도 안 불렀고, 이쪽은 **세 화면이 읽으려고 기다린다.**

## 5. ⛔ 01 계약 결손을 하나 더 찾았다

`M-04-01` 제품LOT 피킹의 「피킹 확정」이 **`inventory.inventory_reservation` 에 쓴다**(§4-C 실측). 그런데—

```
01 계약  /inventory/reservations  →  GET 만 있다
```

⭐ **역방향 ②와 같은 형태 두 번째다.** 앞서 `W-02-10`·`P-02-06`·`P-02-08` 셋이 같은 사고였다.

⛔ **04 가 만들지 않는다** — `inventory_reservation` 은 01 소유 테이블이다. `x-internal-note` 에 적고 **5단계 적합성에서 `M-04-01` 착수 통지 가부를 판단**한다.
