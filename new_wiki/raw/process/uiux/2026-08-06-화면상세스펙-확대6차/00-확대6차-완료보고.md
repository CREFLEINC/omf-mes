## 2. ⭐ 이 차수의 최대 발견 — **계약 자신이 상류를 못 따라가고 있었다**

### 2-1. §F가 2026-07-28의 정정을 반영하지 못한 채 굳어 있었다

확대 4차가 미확인을 하나 남겼다:

> **창고 작업에 대응하는 「공정」이 있는가** — 없으면 창고 스테이션 POP과 모바일 7화면의 게이팅이 성립하지 않는다. (`P-01-02` §8-3)

**실측으로 답을 냈다.**

```
mdm.process 를 참조하는 곳     전수 14  →  전부 생산·품질·외주·정책. 창고 0
terminal_id 컬럼을 가진 곳      전수 7   →  logistics 0 · inventory 0
```

**그런데 이 답은 이미 있었다.** 「POP 단말인증 설계검토」(2026-07-28) **§2.3**:

> 모바일에는 이 매트릭스가 거의 적용되지 않는다 — **그리고 그게 정상이다.** … 배지단말 **#8**이 「통신 두절 시 입·출측 스캔을 단일 단말기 하나로」 수행하는 축퇴 규칙을 명문화했다 — 단말의 행위 범위는 **넓어져야** 한다. **플래그를 추가할 일이 아니다.**

같은 문서 v0.5는 「모바일 업무가 표현되지 않는다」를 미결로 올렸다가 **철회**하며 「**조치할 것이 없다**」로 닫았고, 그러면서 **자기 초안도 정정했다** — `terminal_process`를 「**인가의 정본**」에서 「**단말 기능 구성**」으로 격하하고 「**보안 경계는 단말 인증 하나뿐**」이라 못박았다.

**우리 §F는 그 정정 전 상태였다.**

| | 정정 전(우리 §F) | 정정 후 |
| --- | --- | --- |
| 절 이름 | **「권한 게이팅」** | **인증·기능 구성·귀속** |
| F-2 | 축이 **둘** — 단말×공정(**POP·모바일**) / 사용자×기능(관리웹) | 축이 **셋** — 인증 / 기능 구성(**생산·품질 단말**) / 귀속 |

> **⚠ 이 문서 자신도 하류다.** §I가 「확정 ↔ 물리 모델」을 세는데, **계약 ↔ 확정**도 어긋날 수 있다는 것이 이번에 드러났다. 4차가 남긴 미확인은 **데이터가 없어서가 아니라 우리가 확정을 안 읽어서** 생긴 것이다.

**→ §I에 이슈 발행 전 관문 3개를 신설했다**(§3-3).

### 2-2. ⛔ 확정된 컬럼 하나가 미착지라 **분실 단말을 끊을 수 없다**

「POP 단말인증 설계검토」 **§6-②**(2026-07-28 **사용자 결정**):

> 폐기 = 세대 번호 **`mdm.terminal.token_version`**. 발급할 때마다 +1 하고 토큰 클레임 `tv`와 매 요청 대조한다. **재발급이 곧 이전 토큰 전부의 무효화**다.
> `is_active`만으로는 폐기가 되지 않는다 — **스위치일 뿐이라 단말을 다시 켜면 유출 토큰도 되살아난다.** 실측: 유출 토큰 200 → 비활성화 401 → **재활성화 200**.

**`token_version`이 물리 모델에 없다** — 전 파일 검색 **0건**. 같은 문서가 「모델링 정본 SQL에 **역반영이 필요**」라고 예고해 둔 것이 반영되지 않았다.

**파급은 모바일이 더 크다** — PDA는 들고 다니는 물건이다.

**A-11로 물러났다** — `W-CO-06`은 **「재발급으로 이전 토큰을 끊는 기능」을 그리지 않는다.** 있는 척 그리면 **운영자가 끊었다고 믿는다.**

### 2-3. ⭐ §I-11과 §I-5는 **따로 풀 수 없다**

`W-03-01`이 요구받은 것은 「기간·판정유형·행위자로 이력을 직접 검색」(인벤토리 v1.3 통합 조건 ①)이다.

**전이 9건을 `trace.lot_hold`와 전수 대조했다.**

```
온전히 남음   2건   (C5 ⊕→보류 · C10 의심자재등록→보류)
반쪽만 남음   2건   (C7 재판정 합격 · C8 재판정 불합격 — 「왜」가 안 남는다)
사라짐        5건   (C4 합격 · C6 불합격 · C9 재Hold · C14 · C15)
```

**`audit.audit_event`에는 세 축이 이미 컬럼으로 있다** — `occurred_at`(기간) · `after_value`(판정유형) · `performed_by`(행위자).

**⛔ 그런데 §I-5가 정확히 그것을 막는다** — `target_id` 비-FK · **jsonb 키 규약 없음(판정유형으로 검색 불가)** · 아직 아무도 쓰지 않아 시작하면 **이벤트 코드 체계를 먼저 정해야** 한다.

> **두 항목이 #64와 #68에 나뉘어 있는데, 먼저 답할 것은 하나다** — 「**전용 테이블인가 `audit_event`인가**」. 결정 10이 「1:N 신설」이라 못박았으므로 **전용 테이블을 권고**한다. `audit_event`로 가면 **이 화면 하나를 위해 전사 감사 규약을 먼저 세우는 순서**가 된다.

3. **플랫폼 기능은 DS로 올리지 않는다** — `M-CO-01`의 QR 스캔 뷰는 Capacitor 네이티브 카메라다. `d`로 올리면 **DS가 카메라를 갖게 된다** → **`c`**. ⚠ 바코드 스캔(D-2)과 다르다 — 그쪽은 HID 키보드 입력이다.
