## 1. 개요

2026-07-01 현장 점검 미팅에서 확보한 **요구사항 명세서 47건**(부품사업부 36 + OA사업부 11)을 기존 기획 문서 8종(워크플로우 가설 6종 + 현장검증 질문지 + 개념데이터모델)과 전수 대조했다. 대조는 문서별 독립 분석(8건 병렬) 후 교차 종합했으며, 접점은 총 **254건**이다.

| 판정 유형 | 의미 | 규모 |
| --- | --- | --- |
| **충돌** | 기존 기획의 가정·확정과 명세서가 다름 → **명세서 우선으로 교체** | 전역 3건 + 국지 5건 |
| **미결해소** | 질문지·모델의 미결(⚠·[확인필요])에 명세서가 답 | 질문지 코드 기준 약 15개 코드 (부분 해소 다수) |
| **일치검증** | 기존 가설(🟡)·설계가 명세서 현행(As-Is)·요구로 확인됨 | 약 44접점 |
| **신규** | 기존 기획에 없던 요구 → 재정리본에 추가 | 약 20건 (엔티티·상태·규칙) |

## 2. 전역 충돌 3건 — 기존 기획을 뒤집는 결정 (명세서 우선)

### 충돌① Routing(공정) 정본: ERP → **MES** (REQ-PR-0026 · 0002)

- 기존: Routing=ERP 정본(검증 렌즈 **L1**), ERP→MES I/F 동기화, 연계분 MES 수정·삭제 불가. B2는 "ERP Routing 마스터 스키마 열람으로 닫힌다"고 판정.
- 명세서: **"ERP에서 공정(Routing) 정보가 없을 경우"가 실재 전제** → "MES 공정 정보 관리 기능 필요" + "공정 정보가 없을 경우 BOM 기반으로 4M 투입 계획 가능하도록 구성"(0026). 세부 공정(사출→조립→검사→부착→검사)의 추가/삭제/수정이 MES에서 가능해야 함(0002).
- **판정: Routing 정본=MES.** ERP 연계 대상에서 공정 제외(존재 시 수신하는 선택 경로로 격하). W/O 전개는 MES Routing 기준 + Routing 미비 시 **BOM 기반 4M 투입 계획 fallback**. 검증 렌즈에서 B2를 L1→**L2(소유·정본 조율)**로 재분류. `[의견]` BOM(B1)은 L1 유지 — 명세서가 'BOM 기반 계획'을 대안으로 제시하므로 BOM 존재는 간접 확인되나, ERP 보유 여부는 Routing 전례를 고려해 재확인이 필요하다.
- 파급: 질문지 B2·B렌즈 / 데이터모델 C1 공정·I/F 연계정의 / WF02 S2 / WF06 S4·S7·S8.

### 충돌② 출하지시 원천: ERP → **고객사 지시서(엑셀) import** (REQ-PR-0029)

- 기존: 출하지시=ERP 정본·수신본(WF04 S3 "ERP에서 출하지시(납품오더) 발행", 3계층 상위지시=ERP).
- 명세서: 현행 = "고객사에서 전달받은 지시서 엑셀 파일을 직접 참고". To-Be = "지정된 양식으로 전달되는 지시서에서 데이터를 가져와서 시스템에 등록 (단, **D+1일치 분량만**)". 일부 항목은 **시간대별 지시**.
- **판정: 상위지시 계층의 원천 = 고객사 출하지시서 파일 import.** ERP 출하지시 계층은 사실상 부재로 본다. **3계층 골격 자체는 유지** — 상위지시(고객사 지시서, nullable) → MES 출하작업지시(항상 MES 소유) → 출하 후 ERP 반영(전표 계층, PGI 성격 — REQ-PR-0030이 방향 확인). 기존 WF04 S3 Exception ①(무지시 standalone)이 "예외"가 아니라 **상시 구조**였던 셈.
- 잔여: 현행 출하-ERP 프로세스·ERP 기록 정보(0030, 명세서 자체가 '확인 필요'), 지시서 샘플·납품라벨 형식(고객 요청 중).
- 파급: 질문지 B8 출하 행·D20 / 데이터모델 C6 출하 / WF04 S3.

### 충돌③ 툴/금형 기준정보: ERP(Legacy) 연계 → **MES 정본 + QR** (REQ-PR-0003)

- 기존: 툴/금형 master = Legacy 연계 대상(신규입고/폐기 상태 Legacy 연계, I/F 연계대상에 툴 포함).
- 명세서: 현행 = "ERP 시스템 사용 X : 엑셀로 관리". 요구 = "금형, 지그를 포함한 **모든 도구**의 정보 관리를 MES에서" + "QR 코드 부착하여 관리(제품 정보 등록 → QR 발급)".
- **판정: 툴·금형·지그 마스터 = MES 직접 등록·정본.** '지그(Jig)' 범위 명시, QR 발급·부착 속성 추가, I/F 연계대상에서 툴 제외. 기존 엑셀 대장은 DX(마이그레이션) 대상. B6(이력 키)·D5(툴 PM)의 "현행 화면 확인" 과제는 **현행 체계 부재 확인으로 소멸** — 키·발번은 CREFLE 신규 설계 재량.
- 파급: 질문지 B6·D5 / 데이터모델 C1 툴/금형·I/F / WF05 S1·S7 / WF06 S6.

### 확정④ 자재LOT 발번·등록/Release 모델 (REQ-PR-0001 · 0007 — 2026-07-20 재정의로 개정, 구 "생성 2단계" 폐기)

- **자재LOT 등록 시점 = 입하 (Lot Status=Hold) · 재고 가용(Release) = IQC 합격** (0007 개정 — 2026-07-20 CREFLE 재정의: 기존 "IQC 합격 '생성'(Release 아님)·C4"를 뒤집어 정확히 Release 모델로 확정). 발번 주체 = **경로 이원화**(사전부착=공급사 번호 MES 수용·등록 / 직접부착=MES 발번). (✓확정 2026-07-20 자재LOT재정의 #4·#5·#7, 기존 서술 폐기: "IQC 합격이 '생성'이며 'Release' 아님 → C4 해소"·"발번 주체=MES 단일")
- **LOT 번호 사전 발행(Pre-issue)** 별도 존재: 협력사가 라벨 부착·납품(입고 전 상태 관리, 0001).
- **판정: 'LOT 번호 등록(존재)' 과 '재고 가용(Release)'의 분리 모델.** 라이프사이클: (사전부착=공급사 번호 수용 / 직접부착=MES 발번) → **입하 등록(Lot Status=Hold)** → IQC → **합격 시 Release(가용)** / 불합격 시 Hold 유지·반품 → 분할(QR)·부분출고·잔량. A1 잔여 = 제품LOT 발번 주체. (✓확정 2026-07-20 자재LOT재정의 #1·#5, 기존 서술 폐기: "'번호 사전 발행'≠'LOT 생성(활성)' 2단계·합격 시 LOT 생성")
- `[의견]` 파생 보정 (2026-07-20 재정의로 개정): "IQC 미완 LOT=Hold" 규칙(WF03 S5)은 **자재LOT에도 적용된다** — 자재LOT은 입하 시 등록되어 Lot Status=Hold이고 IQC 합격 시 Release된다. 불합격분은 Hold 유지 후 반품(재고 미가용). Hold 통제가 자재·생산·제품LOT 전반에 적용된다. (✓확정 2026-07-20 자재LOT재정의 #5, 기존 서술 폐기: "자재엔 Hold 미성립·합격 전 LOT 없음·'입하 대기(LOT 미생성)'")

## 7. 리스크·설계 의견 `[의견]`

1. **재생재 '외부 비노출'(0031) ≠ '내부 미기록'.** MES 내부 genealogy(재생재→생산LOT 투입)는 반드시 유지하고, ERP·고객사 연계 계층에서만 필터링해야 한다. 내부까지 기록을 끊으면 품질 이슈 역추적이 불가능해지고, B7의 ERP 재고 정합 검증에서 '동기화 제외 구역'으로 명시적으로 다뤄야 한다. 고객사 스펙 준수 여부는 고객 책임 영역이나, 시스템은 내부 추적성을 보존하는 설계가 맞다.
2. **로그인 생략(0023) vs 권한 분리(0015)의 긴장.** POP는 사번 입력 경량 인증(실적 귀속·도용 리스크 수용), 권한 통제는 관리 화면(메뉴·데이터·법인) 중심으로 이원화하는 것이 합리적이다.
3. **"$모든 정보는 수정 가능"(0021)의 범위.** Location 한정인지 전 마스터인지 불명. 전 마스터라면: MES 정본 마스터는 수정 가능+**변경 이력 필수**, 잔존 연계분(품목·P/O)의 수정불가 원칙은 유지해야 정본이 훼손되지 않는다.
4. **거래명세서 입고(0006)와 IQC 시 LOT 생성(0007)의 순서 정합.** 간이 입고가 IQC 생략을 뜻하는지, 그 경우 LOT 생성 시점이 어디인지 미정 — 신규 확인 필요.
5. **우선순위 미분류.** 47건 중 우선순위 기재는 0018('중요') 1건뿐, 요약 시트 필수/중요/선택 집계 0. 범위·일정 산정 전 고객과 우선순위 확정이 선행돼야 한다.
6. **설비·보전 요구의 공백.** 47건 어디에도 점검·보전·예비품·PM 요구가 없다(D3·D4 잔여·D5·D6·B6 키·C3 전부 미해소). 이 침묵이 '불요'인지 '미논의'인지 확인해야 한다 — 기존 'MES 경량 보전' 결정(D4)은 유지하되, 다음 미팅에서 점검·보전 범위를 명시적으로 다룰 것을 권고한다.
7. **PR-0008의 적용 대상 모호.** '잔량 관리' 분류로 보아 자재LOT 문맥일 수 있으나 생산LOT 크기 override와도 정합 — 양쪽 모두 '기본값+수정 가능'으로 반영하되 적용 범위를 확인 항목으로 남긴다.
