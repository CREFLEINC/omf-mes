## 1. 무엇을 결정해야 하는가

**「여러 전표에 흩어진 입고 라인을 한 표로 보는 경로」를 01 자재창고 계약에 만들지**입니다.

```
지금 계약   GET /logistics/goods-receipts                     전표 목록
            GET /logistics/goods-receipts/{id}/lines          한 전표의 라인

없는 것     라인을 전표와 무관하게 조건으로 모으는 경로
            (예: 「불량창고에 있는 입고 라인 전부」)
```

## 2. 왜 지금 나왔는가

### 2-1. 프론트가 구현 중에 부딪혔습니다

`W-01-06`(폐기 품의·기타출고) PR ① 을 만들다 보고가 올라왔습니다(client #34).

**스펙 §3 이 대상 표를 「LOT · 품목 · 보유 · 원천 · 입고일」 **한 표**로 그렸는데, 계약으로는 세울 수 없습니다** — 라인이 전표 하나에 매인 경로뿐입니다.

### 2-2. 프론트가 이미 우회했습니다

> **전표 목록(6열) → 전표를 고르면 라인 표(7열)** 의 2단으로 나눠 실현한다 — 공급사 반품(`W-01-05`)과 같은 구성.

⭐ **막히지 않았습니다.** 그리고 **같은 저장소에 선례가 있습니다**(`W-01-05`).

### 2-3. ⛔ 그런데 화면 설계가 한 표를 전제했습니다

`W-01-06` §3 이 「불량창고 입고분」을 **한 표에서 고르는** 모양입니다. 2단이 되면 **사용자가 전표를 먼저 알아야** 합니다.

⚠ **폐기 대상은 「어느 전표로 들어왔는지」가 아니라 「지금 불량창고에 무엇이 있는지」로 찾는 것이 자연스럽습니다.**

### 2-4. 같은 형태가 다른 화면에도 있습니다

**실측** — 라인을 전역으로 모아 보는 화면이 더 있는지 봤습니다.

| 화면 | 무엇을 한 표로 보나 | 지금 |
| --- | --- | :-: |
| `W-01-06` 폐기 품의 | 불량창고 입고 라인 | ⚠ **2단으로 물러남** |
| `W-01-05` 공급사 반품 | 반품 대상 입고 라인 | ✅ **원래 2단**(선례) |
| `W-04-11` 재고 재등록 | 처분 = 정상인 대상 | ⭐ **처분 결정 축**이라 무관 |

⭐ **지금 걸리는 것은 `W-01-06` 하나**입니다.

## 3. 결정 항목 — **안 셋**

### 3-A · **2단 구성을 정본으로 한다** *(권고)*

계약을 안 늘리고 **화면 스펙을 2단으로 고칩니다.**

| ✅ | ⛔ |
| --- | --- |
| **선례가 있다** — `W-01-05` 가 같은 구성 | ⚠ **폐기 대상을 전표로 찾게 된다** — 업무 흐름과 어긋날 수 있다 |
| **계약을 안 늘린다** — 01 은 손으로 유지되고 생성기가 없다 | ⚠ 스펙 §3 을 고쳐야 한다(프론트는 이미 그렇게 짓고 있다) |
| 프론트가 **이미 그렇게 진행 중**이라 재작업 0 | |

### 3-B · **전역 라인 목록 경로를 신설한다**

`GET /logistics/goods-receipt-lines` 를 만듭니다(창고·품목·기간·상태로 거른다).

| ✅ | ⛔ |
| --- | --- |
| **화면 설계대로 한 표가 선다** | ⛔ **01 계약을 또 고친다** — 이번이 **세 번째**다(앞서 3건 · `/inventory/reservations` 1건) |
| 다른 화면이 같은 요구를 하면 재사용된다 | ⚠ **부르는 화면이 지금 하나뿐**이다 — 「테이블이 있으니 경로를 만든다」의 변형이 될 수 있다 |
| | ⚠ 프론트가 **이미 2단으로 지었다** — 되돌리는 재작업이 생긴다 |

### 3-C · **재고 축으로 바꾼다**

입고 라인이 아니라 **`GET /inventory/balances`**(재고 잔액)로 불량창고 재고를 찾습니다.

| ✅ | ⛔ |
| --- | --- |
| ⭐ **업무 뜻에 가장 가깝다** — 「지금 불량창고에 무엇이 있나」 | ⛔ **입고일·원천 전표를 못 보인다** — 잔액 축에 없다 |
| 경로가 **이미 있다**(01 계약) | ⚠ 스펙 §3 의 열 두 개를 뺀다 |
| 계약 신설 0 | |

## 5. 권고 — **3-A(2단 정본화)**

**두 가지를 먼저 봤습니다.**

| 물음 | 답 |
| --- | --- |
| **용도가 하나인가** | ✅ **그렇다** — 부르는 화면이 `W-01-06` 하나다. 하나를 위해 계약을 늘리는 것은 이 저장소가 두 번 되돌린 형태다 |
| **고객 약속인가** | ⛔ **아니다** — 「한 표로 본다」는 우리 화면 설계이지 요구가 아니다. REQ-PR-0025 는 「불량창고 입고 후 판단」까지다 |

⭐ **프론트가 이미 2단으로 지었고 선례(`W-01-05`)도 있습니다.** 계약을 늘리지 않고 **스펙 §3 을 2단으로 고치는 것**을 권고합니다.

⚠ **3-C 가 업무 뜻에는 더 맞습니다** — 폐기 대상은 「전표」가 아니라 「지금 불량창고 재고」로 찾는 것이 자연스럽습니다. **다만 입고일·원천 전표 열을 잃습니다.** 그 두 열이 판정에 필요한지는 **현업 확인이 필요**합니다.

→ **그 확인이 되면 3-C 가 3-A 보다 나을 수 있습니다.**

## 6. 무엇을 막고 있나 — **막지 않습니다**

프론트가 2단으로 진행 중이라 **작업이 멈춰 있지 않습니다.** 다만—

| 안 | 프론트 재작업 |
| :-: | --- |
| **3-A** | ⭐ **0** — 이미 그렇게 지었다 |
| 3-B | ⚠ PR ① 을 다시 짓는다 |
| 3-C | ⚠ PR ① 의 조회 축을 바꾼다 |

⛔ **늦게 정할수록 3-B·3-C 의 재작업이 커집니다** — PR ②(라인·수량)가 그 위에 쌓입니다.
