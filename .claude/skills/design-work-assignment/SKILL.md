# design-work-assignment — 개발 업무 배정

`multi-agent-team-workflow-v2.md` §1-1을 따른다. **원문 그대로**: "업무 배정을 임의로 하지
않으며 사용자가 직접 지시가 있을 때 지시에 따라 업무를 배정한다." 이 스킬은 사용자 발화 없이
자체 판단으로 절대 실행되지 않는다 — 다른 스킬(`design-review-intake` 등)의 부산물로 배정이
필요해 보여도, 이 스킬을 자동으로 부르지 않고 사용자에게 지시를 요청한다.

## 절차

1. **입력 확인** — 사용자가 지정한 범위(전체/특정 도메인/특정 팀)를 명확히 한다. 모호하면
   진행하지 않고 되묻는다.
2. **자료 수집** — 에이전트를 스폰하지 않고 직접 읽는다:
   - `design/wiki/handover/화면-진도표.md` — 화면↔스펙↔요구서↔계약↔통지 현황.
   - `design/wiki/handover/99-인계대장.md` — 살아있는 미결 + 차단 등급.
   - `design/wiki/handover/미결-대장.md` — 이슈#N↔화면 역인덱스(이미 특정 팀이 붙들고 있는
     화면을 다시 배정하면 충돌한다).
3. **배분안 산출** — 판단 기준은 v2 §1-2)(2)의 원문: "업무 간 의존성, 병합 시 충돌 가능성 등을
   고려하여 최대한 독립적으로 개발할 수 있도록 배정한다." 표로 제시:

   | 화면/도메인 | 제안 팀 | 의존성 | 병합 충돌 위험 | 근거 |
   |---|---|---|---|---|

4. **사람 확인** — 배분안을 사용자에게 제시하고 승인받는다. 승인 없이 라벨을 부착하거나 이슈를
   발행하지 않는다.
5. **실행** — 승인 후:
   - `omf-mes` 이슈에 `Agent : T{n}`·`Agent : {type}` 라벨 부착은 `gh issue edit --add-label`로
     직접 수행(`team-issue-protocol` §2 라벨 표를 따른다).
   - 아직 착수 통지가 안 나간 화면을 새로 배정했다면, 통지 발행은 이 스킬이 하지 않는다 —
     `uiux-client-handoff` 스킬로 넘긴다.

## 하지 않는 것

- ⛔ 사용자 지시 없이 "이 화면들이 비어 보이니 배정하자"고 스스로 시작하지 않는다.
- ⛔ 배분안을 승인 없이 바로 라벨·이슈로 실행하지 않는다.
- ⛔ 착수 통지 발행은 이 스킬의 일이 아니다(`uiux-client-handoff`).
- ⛔ `omf-mes-server`(백엔드)는 이슈 0건·라벨 0개로 협업 미가동 상태다 — 백엔드 배정은 이 스킬로
  실행할 수 없다는 것을 사용자에게 알린다.
