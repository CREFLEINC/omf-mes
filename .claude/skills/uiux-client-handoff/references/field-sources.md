# 폼 6항목을 우리 산출물 어디에서 가져오나

이 파일이 이 스킬의 본체다. **폼을 채우는 일 자체는 어렵지 않고, 어려운 것은 어느 문서의 어느 절을 봐야 하는지다.**

전제 — 화면 상세 스펙은 **9블록 서식**(`uiux/화면상세스펙-공통/00-서식.md` v1.0)으로 쓰여 있다. 폼 6항목이 그 9블록에 거의 그대로 대응한다.

```
스펙 §1 식별      →  폼 1 · 1-2
스펙 §2 근거 4면   →  폼 2
스펙 §4~§7        →  폼 3
스펙 §8 미결      →  폼 4      ← 등급 번역이 필요하다
스펙 §5·§9        →  폼 5
스펙 §5 ⚠ · §I    →  폼 6
```

## 1-2. 리소스 패턴 — **우리 유형과 1:1이 아니다**

폼의 네 값은 **프론트가 재사용할 화면 골격**이고, 우리 스펙 §1 의 「유형」은 **업무 성격**이다. 축이 다르므로 번역한다.

| 스펙 §1 유형 | 폼 값 | 판별 |
| --- | --- | --- |
| **설정·마스터** | `마스터 형` | `is_active` + `version_no` 를 가진 테이블 하나가 주제 |
| **설정·마스터**(버전·이력 있음) | `버전 마스터 형` | 헤더–버전–라인 구조 + `status_code` + 유효기간 |
| **조회·상세** | `조회 형` | 저장하지 않는다. 목록·상세·집계 |
| **입력** | `입력 형` | 실적·전표를 만든다 |
| **판정·승인** | **`입력 형`** | ⚠ 저장을 하므로 입력 형이다. **§J 승인 워크플로우가 붙으면 6번에 적는다** |

⚠ **API 요구서의 「리소스 패턴 3종」과 헷갈리지 않는다.** 그쪽은 **경로 모양**을 정하는 축이고 값이 다르다(마스터 형 / **부여·회수 형** / 버전 마스터 형).

**「부여·회수 형」은 폼에 없다.** 그것만으로 된 화면은 대개 마스터 화면의 하위 구획이므로 **`마스터 형`** 을 고르고, **6번에 성질을 적는다** — 「전체 치환 PUT 이고 낙관적 잠금이 없다(`version_no` 컬럼 자체가 없음)」. 프론트가 이걸 모르면 `If-Match` 를 붙이려다 막힌다.

## 2. 근거 — 포인터만

네 줄이면 된다. **경로와 버전만 적고 내용은 옮기지 않는다.**

| 줄 | 어디서 | 주의 |
| --- | --- | --- |
| 화면 스펙 | 스펙 파일 경로 + **변경 이력 표의 최신 날짜** | 「작성일」이 아니라 **최신 개정일** |
| 계약 정본 | `deliverables/openapi/<도메인>.json` + 판 날짜 | 도메인마다 파일이 다르다 |
| 공유계약 | `공유계약.md` **v번호** | 헤더 첫 줄에 있다 |
| 디자인 시스템 | **고정 커밋 + 실물 확인 결과** | ⛔ 아래 |

```
- 화면 스펙: uiux/2026-08-03-화면상세스펙-확대1차/W-06-03-불량원인코드2계층마스터.md (개정 2026-08-03)
- 계약 정본: deliverables/openapi/mdm-기준정보.json (2026-08-06판)
- 공유계약: 공유계약.md v0.9
- 디자인 시스템: design-system-v2-webui 커밋 <해시> 설치본에서 Table·Chip 실물 확인
```

### ⛔ 디자인 시스템은 **이슈 상태를 적지 않는다**

이 규칙 하나 때문에 규칙 전체가 생겼다.

> **이슈가 닫힌 것과 우리가 쓰는 커밋에 들어 있는 것은 서로 다른 사실이고, 어느 쪽으로도 틀릴 수 있다.**

실제로 양방향으로 다 틀렸다.

| 사례 | 무슨 일 |
| --- | --- |
| DS `#39` 행 순서 재배치 | 우리 문서는 「없다」고 적었는데 **고정 커밋 설치본에 이미 있었다.** 그대로 믿었으면 4화면이 쓸 부품을 중복 제작 |
| DS `#40` 날짜 입력 | 이슈는 CLOSED 인데 **구현이 우리 고정 커밋보다 뒤에** 들어와 대체 부품이 여전히 필요했다 |

**확인 방법** — `ds-gap.md` 의 판정을 그대로 옮기지 말고, **클라이언트 저장소가 고정한 커밋의 `node_modules/@crefle/web-ui`** 에서 해당 컴포넌트·prop 이 실제로 있는지 본다. 확인한 커밋 해시를 적는다.

⚠ **`ds-gap.md` 의 「확인 대상」 항목은 특히 위험하다**(2026-08-06 현재 3건 — `Table` 서버 페이지네이션·정렬 / `StatCard` 비숫자 값 / 차트 컴포넌트). **셋 다 「있다고 가정하고 쓴」 것**이라 실물 확인 없이 옮기면 그대로 사고가 된다.

## 2-2. 확인 시점

**위 근거를 실제로 확인한 날짜.** 오늘 날짜를 기계적으로 넣지 말고, DS 실물 확인을 어제 했다면 어제 날짜를 적는다.

이 칸이 별도로 있는 이유 — 근거 칸 안에 산문으로 섞으면 「스펙 확인함」 한 줄로도 넘어가 정작 시점이 안 남는다.

## 4. 미결 — **가장 중요한 칸**

### 등급 ↔ 처리 방법 대응표

스펙 §8 의 **미결 3등급**(서식 §7)을 폼의 **처리 3방법**으로 번역한다. **기계적 1:1이 아니므로 판단이 필요하다.**

| 스펙 §8 등급 | 뜻 | 폼의 처리 방법 |
| :-: | --- | --- |
| **차단** | 화면 골격이 바뀐다 | ⛔ **번역 대상이 아니다 — 이슈를 발행하지 않는다** |
| **조정** | 동작·문구가 바뀐다 | **비활성 + 사유 표시**(자리는 확정, 동작 규칙 미정)<br>또는 **만들지 않는다**(나중에 붙여도 구조가 안 흔들릴 때) |
| **표시** | 표시만 바뀐다 | **자리표시 상수 + 안내**(모양 확정, 값만 미정) |

**갈림길 판단** — 「조정」이 둘로 갈리는 지점:

```
그 UI 요소의 자리가 확정인가?
   ├─ 예 → 비활성 + 사유 표시     (버튼은 있는데 언제 눌리는지 미정)
   └─ 아니오 → 만들지 않는다       (그 기능을 이번에 빼도 나머지가 성립)
```

### 미결 성격별 자주 나오는 형태

| 스펙 §8 성격 | 대개 이렇게 처리된다 |
| --- | --- |
| **공통코드**(값 목록 미정) | **자리표시 상수 + 안내** — 값만 미정이고 컨트롤 모양은 확정 |
| **회신 대기** | **비활성 + 사유 표시** — 공유계약 **G-2** 가 「화면은 만들되 비활성」으로 이미 정해 두었다 |
| **상류↔하류 불일치** | **만들지 않는다** — 담을 컬럼이 없으면 UI 를 만들 수 없다 |
| **설계 결정** | 사안별 |

### 추적 번호

**설계 저장소 이슈 번호를 `omf-mes#64` 형태로 적는다.** 번호만 적고 그 이슈의 내용은 옮기지 않는다.

우리 §8 표는 대개 처리 열에 이슈 번호를 이미 갖고 있다. 없으면 §I 대장(`공유계약.md`)에서 찾는다.

### 미결이 없으면

`없음` 한 단어. **비워 두지 않는다.**

## 5. 선행·순서

세 가지를 본다.

| 무엇 | 어디서 |
| --- | --- |
| **선행 화면** | 스펙 §5 의 **B-9**(선행 화면이 만드는 객체가 `NOT NULL`이면 의존을 명시) 적용 지점 |
| **공용 부품** | `ds-gap.md` — **제품 내부 공용 1순위**(2026-08-06 현재 `ScanField`·편집 그리드). 먼저 만들 부품이 있으면 적는다 |
| **재작업 위험** | 스펙 §8 의 「조정」 중 **컬럼이 생기면 필드가 추가되는** 것과 **화면이 뒤집히는** 것을 가른다 |

**여러 이슈를 동시에 열 때 여기에 우선순위를 적는다.**

```
- 선행: 없음
- 함께 열린 이슈 중 순서: #12(W-06-03) → 이 이슈 → #14(W-06-10)
- 재작업 위험: 낮음. 목록 열이 1~2개 늘 수 있으나 화면 구조는 안 바뀐다
```

⚠ **재작업 위험이 높으면 그것을 그대로 적는다.** 도메인 06 에서 `W-06-04` 가 실례다 — 전용 컬럼이 없어 코드값 편집기를 재사용하게 했고, 「처음부터 전용 화면으로 만들면 그때 버리게 된다」를 착수 안내에 적었다.

## 6. 특별히 조심할 것

**어긋남은 대개 이미 알려져 있고, 모르는 쪽은 나중에 그 자리에 도착하는 프론트다.**

세 곳을 훑는다.

| 원천 | 무엇을 찾나 |
| --- | --- |
| **스펙 §5 의 ⚠ 표시** | 스펙 서술과 계약이 다른 지점 · 겉보기와 다르게 동작하는 규칙 |
| **공유계약 §I 대장** | 이 화면이 걸리는 불일치. **A-11 로 물러난 것**이 있으면 반드시 적는다 |
| **`deliverables/07-웹프론트-착수안내.md` §7 함정** | 이미 알려진 함정 목록 |

자주 나오는 형태:

```
- 사용 중지 요청에도 If-Match 가 필요하다 — 스펙 서술과 계약이 다르니 계약을 따른다
- 409 응답의 원인 값은 3가지로 확정돼 있다. 「원인 미확정」이 아니다
- 상태 코드 목록은 스펙에 예시가 하나뿐이지만 확정된 전체 목록이다
- 수신본 편집 잠금이 서버에서 강제되지 않는다 — editability 를 읽어 렌더하되 잠금이 아직 안 걸린다
```

⚠ **「값이 하나만 적혀 있다」는 것 자체를 적는다.** 예시인지 확정인지 판별할 근거가 문서에 없으면 프론트가 규칙을 혼자 만든다 — 실제로 그 사고가 있었다.
