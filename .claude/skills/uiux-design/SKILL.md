# omf-mes UI/UX 설계 하네스

**규칙 원문은 `uiux/CLAUDE.md` 「설계 소관과 보고 방식」에 있다.** 여기는 **그것을 실제로 지키게 하는 절차**다.

⚠ **규칙을 아는 것으로는 안 막힌다.** 이 하네스가 담는 실패는 전부 **규칙이 이미 있는 상태에서** 일어났다.

---

## 0. 시작 전 — 세 줄 확인

```
① 이 일이 우리 소관인가          → §1
② 무엇을 실측해야 하는가          → §2
③ 보고를 어떻게 쓸 것인가         → §4
```

---

## 1. 소관 — 우리가 정하고 데이터 모델이 따라온다

### 1-1. 갈래

| 무엇 | 누가 | 우리가 할 일 |
| --- | --- | --- |
| 화면이 무엇을 보이고 저장하나 | **우리** | 정한다 |
| 응용 프로그램 인터페이스 규약 | **우리** | 화면 요구대로 쓴다 |
| 컬럼·제약·무결성 | 데이터 모델링·백엔드 | **통지한다** |

### 1-2. ⛔ 물리 모델이 못 담을 때 — **물러서지 않는다**

```
⛔ 하지 않는다   "모델이 비울 수 없게 돼 있으니 계약은 모델 변경 후에 고친다"
✅ 한다          ① 계약은 화면대로 쓴다
                 ② 내부 주석에 모델 결손 + 요청 번호를 적는다
                 ③ 데이터 모델 담당에게 통지한다 — 기다리지 않는다
```

### 1-3. 표기 — **「회신 대기」를 남발하지 않는다**

| 표기 | 언제 |
| --- | --- |
| ⏳ **회신 대기** | 팀 리더·고객 확정 — **답이 와야 다음이 된다** |
| 📨 **작업 통지** | 데이터 모델·구현팀 — **남의 작업 · 우리 차단 없음** |

**판별** — 「그 답이 없으면 내가 지금 못 하는 일이 있나」. 없으면 통지다.

---

## 2. 실측 — 세 가지를 세기 전에는 쓰지 않는다

### 2-1. ⛔ 「없다」를 검색 없이 적지 않는다

**양쪽으로 틀린다.**

| 형태 | 실제 사례 |
| --- | --- |
| **있는데 없다고 했다** | 거래처 역할 표가 이미 있는데 새 컬럼을 만들려 했다 |
| **없는데 있다고 했다** | 거래처 유형 컬럼을 「값 확인 필요」라 적었는데 그 컬럼이 없었다 |

**어간으로 넓게 찾는다.** 이름이 다를 수 있다.

### 2-2. ⭐ 값·필드·경로를 만들기 전에 **사용처를 센다**

```
① 이 값을 넣는 화면이 있나
② 요구·업무 흐름 문서가 부르나
③ 담을 마스터·등록 화면이 있나
```

**셋 다 0 이면 만들지 않는다.** 폐기 처리 업체 값을 만들려다 셋 다 0 이어서 물렸다 — 「표가 있으니 값을 만든다」의 변형이다.

⚠ **기존 관문 둘로는 안 잡힌다.** 「용도가 하나인가」·「고객 약속인가」를 통과하고도 틀렸다.

### 2-3. ⭐ 수치는 **기준과 함께** 적는다

```
⛔  "값 목록 없는 코드 51종"
✅  "값 목록 없는 업무 코드 44종
     — 기준: 저장 컬럼에 착지한 것 중 인스턴스 식별·표준값·상태값 제외
     — 정본: deliverables/openapi/count-undecided-codes.py"
```

**두 번 이상 인용될 수치는 스크립트를 정본으로 둔다.** 문서 셋이 같은 수를 베끼면 하나 틀릴 때 셋이 함께 틀린다.

⚠ **앞 수정이 분모를 바꾸면 뒤 수치도 다시 센다.** 정정하면서 또 틀린 적이 있다.

### 2-4. ⚠ 세는 도구가 **적게 세면 그것을 믿고 놓친다**

만든 검사기가 응답 구조만 훑어 **요청 파라미터 갈래를 통째로 빠뜨렸다.** 스무 곳이라 했는데 실제 스물넷이었다.

**검사기를 만들면 「무엇을 안 보는가」를 먼저 적는다.**

---

## 3. 조항·확정을 인용할 때

### 3-1. ⛔ **마지막 단계까지 간다**

조항을 인용해 앞 단계만 밟아도 **그럴듯한 결론**이 나와서 안 걸린다.

**사례** — 다형 참조 조항을 인용해 「두 칸이 짝이다」까지 적고, **그 조항이 요구하는 대응표**를 안 적었다.

**물음** — 「이 조항이 **내놓으라는 산출물**이 무엇인가. 그것을 냈나.」

### 3-2. ⛔ 조항의 **뒷부분까지 읽는다**

같은 조항이 앞뒤로 다른 것을 말할 수 있다. 앞부분만 읽고 뒷부분이 뒤집어 놓은 결론을 되살린 적이 있다.

### 3-3. ⚠ 확정문의 **주어**를 본다

「회계 계정은 밖이다」라는 확정을 근거로 **거래처 기록도 밖**이라 단정했다. **확정문의 주어는 회계 계정**이었다.

## 4. 보고 — 무엇 · 어떻게 · 왜

### 4-1. 구성

```
무엇   바꾼 것·만든 것을 한 줄로
어떻게 방법과 근거 — 실측 수치(기준 포함) · 인용 원문
왜     그렇게 한 이유 + ⭐ 택하지 않은 안과 그 이유
```

### 4-2. ⛔ 줄임말·기호를 그대로 쓰지 않는다

**대상** — 화면 번호 · 조항 번호 · 이슈 번호 · 회신 번호 · 차수 · 업무 약어 · 전문 용어

```
⛔  W-01-06 에 A-10 을 적용
✅  자재 폐기 화면(W-01-06)에 다형 참조 대응표 조항(A-10)을 적용
```

**전문 용어는 그 자리에서 푼다.**

| 말 | 이렇게 푼다 |
| --- | --- |
| **다형**(참조) | 한 칸이 상황에 따라 여러 표를 가리킨다 |
| **멱등** | 같은 요청을 여러 번 보내도 결과가 한 번 보낸 것과 같다 |
| **낙관적 잠금** | 저장할 때 버전을 대조해 남이 먼저 고쳤는지 잡는다 |
| **구간 형** | 「진행 중」을 상태 값이 아니라 **끝 시각이 비어 있음**으로 판정한다 |
| **파생** | 저장하지 않고 그때그때 계산해 낸다 |

⭐ **검사기가 있다** — `scripts/check-report-language.py`

### 4-3. ⚠ 자기 정정은 **양쪽으로 흔들리지 않게**

한 건에서 **과하게 넣었다가 과하게 뺐다.** 두 번 다 **실측 전에 판단**했다.

**정정할 때도 §2 를 먼저 돌린다.**

---

## 5. 산출물을 내기 전 — 검사기

| 무엇 | 언제 |
| --- | --- |
| `scripts/check-report-language.py` | 요청서·완료보고·이슈 초안을 쓴 뒤 |
| `deliverables/verify-*.py` | 계약·화면을 고친 뒤 전부 |
| `deliverables/test-verify-*.py` | 검사기를 고친 뒤 |
| `deliverables/openapi/check-enum-narrowing.py` | ⭐ **계약을 고친 뒤 · 통지를 내기 전** — 값 목록이 좁아졌는데 통지가 없으면 잡는다 |
| `.claude/skills/uiux-client-handoff/scripts/check-issue.py` | 구현팀 통지 **발행 전** |

### ⛔ 값 목록이 좁아지면 «이미 만든 것이 틀린다»

자유 문자열이 값 목록으로 좁아지거나 값이 빠지면 **⛔ 변경 통지 대상**이다. 넓어지는 것과 다르다 — 넓어지면 기존이 안 깨지지만(⚠ 등급) 좁아지면 **이미 만든 코드가 틀린다.**

실제로 빠뜨렸다 — 재고 상태를 네 값으로 좁히고 통지를 내지 않아 **구현팀이 타입이 깨져서야 알았다**(2026-08-16). ⚠ **값 목록 44종이 확정될 때마다 반복된다.** 그래서 검사기로 뺐다.

⚠ **검사기는 「좁아진 것이 있다」까지만 말한다** — 통지를 실제로 냈는지는 안 본다.

---

⚠ **화면을 늘리면 정본이 둘이다** — 통합 정보구조 문서와 화면 인벤토리 문서. 생성기의 기대 계수도 함께 고친다. **검사기가 잡아 준 적이 있다.**
