## §3. 결정 11 이 정한 것 · 우리가 정할 것

| 결정 11 | 우리가 정할 것 |
| --- | :-: |
| 키 = **설비 FK + 채널명** | ⛔ 없다 |
| 값 = **대상 검사항목 FK** | ⚠ **어느 검사항목인가** §5-2 |
| **+ 품목·공정 조건** | ⚠ **조건을 어떻게 매기나** §5-3 |
| 「설비 추가 = 매핑 행 추가」 | ⚠ **채널명을 어떻게 아나** §5-4 |
| SPC 측정값 → 검사측정치 흡수 | ⛔ 없다(03 소관) |

⭐ **§5-4 가 이 화면의 실질 설계 지점**이다 — 매핑을 만들려면 **설비가 무엇을 보내는지 알아야** 한다.

### §5-1. ⛔ 이 화면이 **연동을 만들지 않는다**

| 이 화면 | 아닌 것 |
| --- | --- |
| 수신된 **채널명을 검사항목에 잇는다** | ⛔ 통신 설정(IP·포트·프로토콜) |
| 미매핑 채널을 **보인다** | ⛔ 수신 로그 조회·재처리(**`W-06-10`** 연계 동기화 현황) |

⭐ **QA #8 이 「포맷·프로토콜 = CREFLE 정의」**라 했다 — 그것은 **개발 시점에 정하는 것**이고 화면 설정 대상이 아니다. **가변부는 채널↔검사항목 매핑뿐**이라는 것이 결정 11 의 요지다.

### §5-2. 대상 검사항목이 **비어 있을 수 있다** — 「미매핑」

`inspection_item_spec` 은 **검사기준 버전(Rev)에 속한다**(`inspection_plan_version_id` NOT NULL). 그래서 채널을 항목에 이으려면 **그 항목이 이미 등록돼 있어야** 한다.

| 상황 | 처리 |
| --- | --- |
| 항목이 아직 없다 | ⚠ **채널만 등록하고 매핑은 비운다** — 「미매핑」 |
| 미매핑 채널의 수신값 | ⛔ **버려진다** — 그 사실을 화면이 말한다(「수신돼도 버려집니다」) |

⭐ **G-15**(비어 있으면 판정이 안 서는 필드는 저장을 막지 말고 목록에서 보인다) 적용 — 「미매핑만 보기」 필터를 둔다.

⚠ **검사기준 Rev 가 오르면 `inspection_item_spec_id` 가 바뀐다** — 매핑이 옛 Rev 를 가리킨 채 남는다. → §8-2

### §5-3. 품목·공정 조건 — **비면 「전체」다**

결정 11 이 「값 = 대상 검사항목 FK(**+품목·공정 조건**)」이라 했다. **조건의 의미를 정한다.**

```
조건 비었다   →  이 설비의 이 채널은 **언제나** 그 항목으로 간다
품목 지정     →  그 품목을 생산할 때만
공정 지정     →  그 공정에서만
```

⚠ **같은 채널에 조건이 다른 행이 여럿일 수 있다** — 「품목 A 면 외경, 품목 B 면 두께」. **그러면 유일 제약(설비+채널명)과 부딪친다.**

**확정 — 유일 제약을 (설비 + 채널명 + 품목 + 공정)으로 넓힌다.**

⛔ **`NULL` 이 섞이므로 일반 UNIQUE 로는 안 된다** — 공유계약 **A-7**(부분 유일 인덱스 `COALESCE`)의 형태다. `app.operation_policy` 가 이미 같은 방식이다(실측 — `COALESCE(item_id,0)` 등).

⭐ **A-7 이 그대로 쓰인다** — 오류 문구에 **유일 범위를 담는다**: 「이 설비의 `Vision_Dim_A` 채널에 **품목·공정 조건이 같은** 매핑이 이미 있습니다」.

### §5-4. ⭐ 채널명을 **어떻게 아는가** — 이 화면의 실질 설계 지점

결정 11 의 「설비 추가 = 매핑 행 추가로 끝난다」가 성립하려면 **그 설비가 무엇을 보내는지 알아야** 한다. **사람이 문서를 보고 손으로 치면 오타 하나로 조용히 버려진다.**

**확정 — 「수신 로그에서 가져오기」를 둔다.**

| 무엇 | |
| --- | --- |
| 최근 수신 레코드에서 **채널명을 뽑아 목록으로** 보인다 | 손으로 치지 않는다 |
| **미매핑 채널을 그 자리에서** 보인다 | 설비를 붙이면 곧바로 무엇이 오는지 알 수 있다 |
| 최근 수신값을 **함께 보인다** | 「`Temp_Barrel` 218.5」 — 어느 항목에 이을지 판단 근거 |

⚠ **수신 로그 자체는 이 화면이 갖지 않는다** — `integration.integration_message`(SQL 2682)가 실재하고 **`W-06-10`**(연계 동기화 현황)이 소유한다. **여기는 읽기만** 한다.

⭐ **B-19**(「이미 있는 것을 쓴다」는 단계별로 확인한다) 적용 — `integration_message` 가 **설비 수신도 담는가**는 확인이 필요하다. 담지 않으면 축이 하나 는다. → §8-3

### §5-5. 단위가 다르면 **경고한다 · 변환하지 않는다**

수신값의 단위(℃)와 검사항목의 단위(K)가 다를 수 있다.

⛔ **자동 변환하지 않는다** — 변환 규칙을 어디에도 저장하지 않았고, **틀리면 측정값이 조용히 어긋난다.** 경고만 하고 사람이 맞춘다.

⭐ **A-8**(수치 컬럼의 **저장 단위**를 계약이 못박는다)의 취지 — **저장 단위는 하나**여야 하고, 다르면 **보내는 쪽이나 항목 정의를 고친다.**

## §9. 이 장에서 나온 공유 계약 후보

### 9-1. ⭐ **외부에서 오는 이름은 손으로 치게 하지 않는다**

§5-4 가 그 사례다 — 채널명을 손으로 치면 **오타 하나로 수신값이 조용히 버려진다.**

**규칙안**: 외부 시스템·설비가 정하는 식별자(채널명 · 외부 코드 · 파일 컬럼명)를 매핑하는 화면은

1. **수신·수집된 실물에서 목록을 뽑아 고르게** 한다
2. **아직 매핑되지 않은 것을 그 자리에서 보인다** — 무엇이 남았는지가 곧 할 일이다
3. **최근 값을 함께 보인다** — 이름만으로는 무엇인지 모른다
4. ⛔ **손 입력을 막지는 않는다** — 아직 한 번도 안 온 채널을 미리 등록할 수 있어야 한다

**해당 후보**: 수집채널 매핑(이 화면) · ERP 연계 필드 매핑(`W-06-09`) · 엑셀 업로드 컬럼 매핑.

### 9-2. **버려지는 데이터가 있으면 화면이 그렇게 말한다**

미매핑 채널의 수신값은 **버려진다**. 그 사실을 안 적으면 **설정한 사람은 저장되고 있다고 믿는다.**

**규칙안**: 수신·수집 데이터 중 **처리되지 않고 버려지는 것**이 있으면

1. **건수를 보인다** — 「미매핑 채널 2개」
2. **버려진다고 명시한다** — 「수신돼도 버려집니다」. 「매핑 없음」만으로는 결과를 모른다
3. **원본은 남는가를 밝힌다** — 로그에는 남는다면 그 경로를 안내한다

⚠ **G-9**(모르는 값과 없는 값을 다르게)의 확장이다 — 여기는 **「받았지만 안 쓴다」**는 셋째 상태다.
