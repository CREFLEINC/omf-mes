## §5. 집계 규칙

### §5-1. ⛔ OEE 를 **그리지 않는다** — 재료는 있으나 **소유가 셋으로 갈린다**

WF05 S4 Boundary 가 「OEE 산출은 비가동의 **파생 집계**」라 했고 Pain 도 「가동률·**OEE** 산출 부정확」이라 했다.

**⭐ 재료는 세 항 다 실재한다**(실측 — A-13 4단을 돌린 결과).

| 항 | 재료 | 실재 |
| --- | --- | :-: |
| **시간가동률** | 조업시간(`work_session`) − 비가동 | ✅ |
| **성능가동률** | **`planning.routing_operation.standard_cycle_time_sec`**(SQL 648 · `CHECK (> 0)`) × 생산량 ÷ 가동시간 | ✅ **있다** |
| **양품률** | **`production.production_result.good_qty`·`defect_qty`·`hold_qty`·`scrap_qty`·`rework_qty`**(SQL 1625~) | ✅ **있다** |

⭐ **`standard_yield_rate`(SQL 650)까지 있다** — 표준 수율 대비 실적 비교도 재료가 있다.

**그런데 이 화면이 OEE 를 그리지 않는다. 이유가 「없어서」가 아니라 「소유가 갈려서」다.**

| 항 | 소유 | 근거 |
| --- | --- | --- |
| 시간가동률 | **05 설비툴** | WF05 S4 Rule — 비가동은 **이 도메인이 공급자** |
| 성능가동률 | **02 생산실행** | 재료가 `routing_operation`(계획) + `production_result`(생산 실적)다 |
| 양품률 | **03 품질** | `W-03-05`(검사실적·불량률 집계)가 소유한다 |

⛔ **소유가 다른 축을 한 화면이 곱하면, 그 값이 틀렸을 때 누구도 책임지지 못한다.** 세 도메인이 각자 분모를 정의하고 각자 예외를 다룬다(이 화면만 해도 **겹침·열린 구간·경미 정지** 셋을 어떻게 세는지 §5-3~5 에서 정했다).

⭐ **그래서 「시간가동률」로 부른다** — 낼 수 있는 항의 **자기 이름**이다. 「OEE 92.7%」로 보이면 **세 항을 곱한 값으로 읽힌다.**

⚠ **OEE 를 낼 수 없다는 뜻이 아니다** — **통합 대시보드(`W-CO-05`)처럼 세 도메인을 함께 보는 자리**가 그것을 맡는 것이 맞다. 이 화면은 **한 항을 정확하게** 낸다. → §8-2

### §5-2. 조업시간의 재료 — **`work_session` 이 있다**

⭐ **A-13 ④ 로 찾았다** — 「가동시간 테이블이 없다」고 볼 뻔했으나 `production.work_session`(SQL 847)이 그것이다.

```
조업시간   = Σ (work_session.ended_at − started_at)   설비별·기간별
계획비가동 = 캘린더(W-05-09)                            휴무·계획 정지
실적비가동 = 비가동 실적(12차 P-05-02)
시간가동률 = (조업시간 − 실적비가동) ÷ 조업시간
```

⚠ **`work_session.equipment_id` 가 nullable 이다** — 설비가 안 붙은 세션은 **설비별 집계에서 빠진다**. 그 건수를 요약에 보인다(**G-9** — 모르는 값과 없는 값을 다르게).

### §5-3. 겹친 구간 — **합계는 한 번만 센다 · 목록은 그대로 보인다** *(12차 이월)*

12차 `P-05-02` §6-1 이 「겹침을 경고하되 막지 않는다」로 정했다(한 설비에 두 사유가 동시일 수 있다). **집계가 그것을 받는다.**

| 무엇 | 어떻게 |
| --- | --- |
| **합계 시간** | ⭐ **구간을 합집합으로 병합**해 센다 — 겹친 30분을 두 번 세면 가동률이 음수로 갈 수 있다 |
| **사유별 시간** | ⚠ **겹치면 나눌 수 없다** — 사유별 합이 총합보다 크다. **그 사실을 표에 적는다** |
| **목록** | 원본 그대로 — 병합하지 않는다 |
| 경고 | 「겹친 구간 2건 — 합계는 겹침을 한 번만 셉니다」 + **보기** |

⛔ **겹침을 임의로 배분하지 않는다**(예: 30분을 15분씩) — **근거 없는 숫자**가 만들어진다. **L-10**(정책이 미정인 의심스러운 데이터는 섞지도 지우지도 않고 분리 보기)와 같은 취지.

### §5-4. 열린 구간 — **집계에서 빼고 건수를 보인다** *(12차 이월)*

12차 `P-05-02` §5-3·G-16 이 「자동 종료를 두지 않는다 — 임의 종료 시각은 집계를 **조용히** 틀리게 만든다」로 정했다. **그러면 열린 구간은 길이가 없다.**

| | |
| --- | --- |
| 집계 | ⛔ **뺀다** — 길이를 모른다 |
| 표시 | ⚠ **「열린 구간 3건 — 집계에서 빠졌습니다」 + 보기**(**G-16** 규칙 4) |
| ⛔ 하지 않는 것 | 「지금까지」로 잘라 세기 — **조회할 때마다 값이 바뀐다**(A-15) |

### §5-5. 경미 정지 — **임계로 거르지 않고 줄을 나눈다** *(12차 이월)*

WF05 S4 Exception ③ 이 「**경미 정지(Chokotei) 미기록**」을 현행 문제로 적었다. 12차가 「화면은 막지 않는다(1분짜리도 저장) · 집계에서 임계로 거를지는 `W-05-08` 소관」으로 넘겼다.

**확정 — 거르지 않는다. 별도 줄로 나눈다.**

```
경미 정지(<5분)   84건   6h 12m   4.8%   ⓘ 별도
```

| 왜 | |
| --- | --- |
| **거르면 84건이 사라진다** | 경미 정지가 **잦다는 것 자체가 신호**다(WF05 Pain) |
| **섞으면 건수가 왜곡된다** | 「설비 고장 12건」과 「경미 정지 84건」을 같은 줄에 세면 평균이 뜻을 잃는다 |
| **임계값은 설정형** | 기본 5분 · `app.operation_policy` 에 둘 수 있다(13차 §8-7 확인분) → §8-3 |

⭐ **L-10** 과 같은 형태다 — **분리 보기**로 답한다.

### §5-6. 「지시 없이 완료」를 센다 *(13차 이월)*

13차 `W-05-04` §5-4 가 「보전 지시를 강제하지 않는다 · 대신 **「지시 없이 완료」를 세어 보인다** — `W-05-08` 이 받는다」로 넘겼다.

**③ 탭에 넷째를 두지 않고 ② 요약에 한 줄로 둔다.**

```
보전  사후 18건 / 예방 7건   ⚠ 지시 없이 완료 6건 (24%)
```

⚠ **이것은 비가동 집계가 아니다** — 그런데 **같은 사람이 같은 시점에 본다**(사후보전 비율이 높으면 예방 계획이 부실하다). **탭을 늘리지 않고 요약에 붙인다.**

⭐ **G-17** 이 여기서 값을 낸다 — 13차가 **보전유형을 트리거가 정하게** 했으므로 이 비율이 **사람이 고른 값이 아니다.**

### §5-7. 작업실적 : 툴사용실적 카디널리티 — **여기서도 안 걸린다** *(13차 이월)*

13차가 「실제로 걸리는 곳은 **개별 실적 행을 세는 화면** — `W-05-08` 또는 툴 사용 이력 조회」로 이월했다.

**확인 결과 — 이 화면도 아니다.**

| 이 화면이 세는 것 | 툴 사용실적을 세는가 |
| --- | :-: |
| 비가동 시간 · 조업시간 · 보전 건수 | ⛔ **아니다** |

⭐ **툴 사용실적을 행 단위로 세는 화면이 05 에 없다.** `W-05-02` 는 마스터의 누계를 보고, 이 화면은 비가동을 본다.

**확정 — 카디널리티 결정을 계속 이월하지 않는다.**

| | |
| --- | --- |
| **지금 필요한가** | ⛔ **아니다** — 17장 어디도 개별 실적 행을 세지 않는다 |
| **언제 필요해지나** | **툴 사용 이력 조회 화면이 생기면** — 인벤토리에 **없다** |
| **처리** | ⭐ **이월을 종료하고 #67 회신에 「지금은 결정하지 않는다 · 필요해지면 그때」로 적는다** |

⚠ **12차 → 13차 → 14차로 세 번 이월됐다.** **세 번 이월된 항목은 「지금 필요한가」를 물어야 한다** → §9-1

### §5-8. W/O 중단과의 이중 계상 *(12차 이월)*

12차 `P-05-02` §8-4 가 「결정 14(작업 홀드)의 중단 사유에 **설비/도구 고장**이 있어 같은 사건이 두 곳에 기록된다 — **집계에서 이중 계상되지 않게** `W-05-08` 이 확인」으로 넘겼다.

**확인 결과 — 이중 계상되지 않는다. 축이 다르기 때문이다.**

| | 축 | 분모 |
| --- | --- | --- |
| **이 화면** | **설비**가 얼마나 멈췄나 | 설비별 조업시간 |
| 작업 홀드(결정 14) | **W/O** 가 얼마나 멈췄나 | W/O 별 소요시간 |

⭐ **한 사건이 둘 다에 기록되는 것이 정상**이다 — 설비도 멈췄고 W/O 도 멈췄다. **같은 분모에 두 번 더하는 일이 없으므로 이중 계상이 아니다.**

⚠ **다만 두 값이 다를 수 있다** — 설비 비가동 5시간인데 W/O 중단은 3시간일 수 있다(그 사이 다른 W/O 가 없었다). **두 숫자를 나란히 놓는 화면이 생기면 그때 설명이 필요**하다. 이 화면은 **설비 축만** 보인다.

| **L-9** 다계층 조회는 한 화면이지 한 표가 아니다 | 요약 + 3탭 |

⚠ **「미분류」 줄이 L-10 의 넷째다** — 사유 코드가 비었거나 폐지된 코드를 참조하는 건. **섞지도 지우지도 않는다.**

## §9. 이 장에서 나온 공유 계약 후보

### 9-1. ⭐ **세 번 이월된 항목은 「지금 필요한가」를 먼저 묻는다**

작업실적:툴사용실적 카디널리티가 **12차 → 13차 → 14차**로 세 번 옮겨 다녔고, **어느 화면도 실제로 필요로 하지 않았다.**

**규칙안**

1. **이월할 때 「어느 화면이 이것을 필요로 하는가」를 이름으로 적는다** — 못 적으면 이월이 아니라 **보류**다
2. **세 번째 이월에서는 「지금 필요한가」를 판정**한다 — 아니면 **이월을 종료**하고 「필요해지면 그때」로 닫는다
3. ⛔ **이월 목록이 길어지는 것 자체가 신호**다 — 답이 없는 물음을 계속 나른다

⚠ **12차·13차가 잘못한 것이 아니다** — 그때는 걸릴 것처럼 보였다. **세 번째에 멈추는 규칙이 없었을 뿐이다.**

### 9-2. **하류에 이미 반대 구조가 있으면 조항의 적용 범위를 적는다**

**G-16**(「진행 중」을 상태 컬럼으로 두지 않는다)이 「해당: **작업 세션(`production.work_session`)**」이라 적었다. **그런데 그 테이블은 `ended_at` 과 `status_code` 를 둘 다 갖는다**(실측).

**규칙안**: 조항이 「해당」 목록을 가질 때 **이미 존재하는 것과 앞으로 만들 것을 나눈다.**

| | |
| --- | --- |
| **앞으로 만들 것** | 조항을 지킨다 |
| **이미 있는 것** | ⚠ **고치라는 뜻이 아니다** — 「이 조항과 다르다」를 적고, **화면은 실재 구조를 쓴다** |

⛔ **조항이 하류를 소급으로 고치게 하면 안 된다** — 11차가 세운 「원칙 1)은 앞으로 만들 것에 적용된다」와 같은 취지다.

### 9-3. **집계는 「낼 수 있는 것」만 내고 이름을 빌리지 않는다**

§5-1 이 그 사례다 — 세 항 중 하나만 낼 수 있어 **「OEE」라는 이름을 쓰지 않았다.**

**규칙안**: 널리 쓰이는 지표 이름(OEE · MTBF · 수율 · 리드타임)은 **정의된 계산식을 전부 낼 수 있을 때만** 쓴다. 일부만 내면 **그 항의 이름으로 부른다**(「시간가동률」).

⛔ **이름을 빌리면 보는 사람이 없는 항까지 반영된 값으로 읽는다.**
