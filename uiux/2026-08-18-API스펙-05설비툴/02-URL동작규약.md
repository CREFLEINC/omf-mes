## 3. ⭐ 판정 1 — 고장 상태 전이는 **`:동사` 둘이고 되돌리지 않는다**

설비고장 상세처리 화면(`W-05-04`) §5-1 이 「접수 → 처리중 → 완료 **셋뿐이고 되돌리지 않는다**」로 못박았다.

| 경로 | 화면 액션 |
| --- | --- |
| `POST /maintenance/breakdowns/{breakdownId}:start-handling` | 「처리 중으로」 |
| `POST /maintenance/breakdowns/{breakdownId}:complete` | 「완료」 — **원인 코드 + 처리 내역 필수** |

⛔ **되돌리는 `:동사` 를 두지 않는다.** 잘못 완료했으면 **새 고장 건으로 등록**한다(§6 「이미 완료된 건 — 상태 잠김」). 01 트랙이 `:cancel` 계열을 만든 것과 다른데, **거기는 전표라 되돌림이 업무이고 여기는 사건 기록**이다.

⚠ **경미 건은 접수 → 완료로 바로 간다** — `:start-handling` 을 거치지 않아도 `:complete` 가 성립한다.

## 4. ⭐⭐ 판정 2 — 보전 지시를 **세 화면이 만드는데 카디널리티가 반대다**

| 화면 | 무엇을 고르나 | 몇 건이 생기나 |
| --- | --- | :-: |
| `W-05-05` 보전지시 발행 | 트리거 **다중**(같은 설비끼리) | **1건** |
| `W-05-02` 툴 보전오더 생성 | 툴 **다중** | **N건** — 「한 오더 = 한 툴」(§5-4) |
| `W-05-04` 설비고장 상세 | 고장 **1건** | **1건** |

**확정 — `POST /maintenance/orders` 는 «한 건 생성»이다.** 다중 선택 화면은 **N번 부른다.**

⭐ **일괄 생성 경로를 두지 않는 이유 셋**

1. **부분 실패를 다룰 수 있다** — 툴 8건 중 3건만 성공하는 상황이 실재한다(기준 미등록·이미 오더 있음). 일괄이면 전부 실패시키거나 조용히 일부만 만든다.
2. **멱등키가 건별로 선다** — 일괄이면 키가 묶음 단위라 재시도가 거칠어진다.
3. **트리거 묶음은 «본문»이 받는다** — `W-05-05` 의 다중 트리거는 한 건의 속성이지 여러 건이 아니다.

⚠ **화면이 진행 상황을 책임진다** — 「툴 2건에 오더 2건이 발행됩니다」를 미리 보이고(`W-05-02` §4), 실패 건은 목록에 남겨 다시 시도하게 한다.

## 5. ⭐ 판정 3 — 비가동은 **구간 형**이다

공유계약이 정의한 **구간 형**(「진행 중」을 상태 값이 아니라 **끝 시각이 비어 있음**으로 판정한다)을 그대로 쓴다.

| 경로 | 메서드 | 화면 액션 |
| --- | :-: | --- |
| `/maintenance/downtimes` | `GET` `POST` | `P-05-02` 실적 저장 · `W-05-08` 목록 |
| `/maintenance/downtimes/{downtimeId}` | `GET` `PUT` | 상세 · 수정 |
| ⭐ `/maintenance/downtimes/{downtimeId}:close` | `POST` | **「지금 종료」** — 진행 중 건을 끝낸다 |

⛔ **「진행 중」 이라는 상태 값을 두지 않는다.** 끝 시각이 비어 있으면 진행 중이다. `W-05-08` 의 「열린 구간」이 그것을 센다.

## 6. ⭐ 판정 4 — 집계 응답에 **목록을 넣지 않는다**

비가동 집계 조회 화면(`W-05-08`) 이 「열린 구간 보기」·「겹친 구간 보기」를 요구한다. **집계 안에 목록을 실으면 응답이 무거워지고 페이지를 못 준다.**

| 경로 | 무엇 |
| --- | --- |
| `GET /maintenance/downtimes/summary` | 요약 + **열린 구간 «건수»** + 겹친 구간 «건수» |
| `GET /maintenance/downtimes?openOnly=true` | 「열린 구간 보기」 — 목록 경로를 필터로 부른다 |
| `GET /maintenance/downtimes?overlappingOnly=true` | 「겹친 구간 보기」 |

⭐ **집계는 「낼 수 있는 것」만 낸다** — `W-05-08` §9-3 이 세운 것이고, **설비종합효율(OEE)을 그리지 않는** 판정과 같은 줄기다.

## 7. ⭐ 판정 5 — 저장 충돌 보호는 **여섯 곳에만** 붙인다

⛔ **자동으로 붙이지 않는다** — 잠그는 «대상»과 버전 축을 맞춰야 한다(하네스 §5). 기준은 공유계약 `G-30` 의 두 조건 — ①통째로 교체하는 저장이고 ②**대상을 오가며 편집**할 때.

| 붙인다 (`If-Match` + `409`) | 왜 |
| --- | --- |
| `/mdm/equipment-groups/{id}` · `/mdm/molds/{id}` · **`/mdm/equipments/{id}`** | 목록에서 대상을 골라 옆에서 고친다 |
| `/mdm/spare-parts/{id}` · `/mdm/work-calendars/{id}` | 동상 |
| 점검 항목 **부여 편집** · 예비품-설비 **매핑** | 대상을 오가며 **묶음을 통째로 교체**한다 |

| 안 붙인다 | 왜 |
| --- | --- |
| 점검·고장·보전실적·비가동·툴사용실적 기록 | **한 건을 만들고 끝난다** — 오가며 고치는 대상이 아니다 |
| 검교정 이력 | ⛔ **수정 자체가 없다**(§8) |
| 보전 지시 | 발행 후 바뀌는 것은 상태뿐이고 `:동사` 가 받는다 |

⛔ **토큰을 «받을 곳»을 함께 선언한다** — `If-Match` 를 필수로 두고 `ETag` 응답 헤더를 선언하지 않아 구현이 막힌 적이 19건 있었다(2026-08-17). 4단계에서 `check-lock-token-source.py` 로 확인한다.

계측기 검교정 이력 화면(`W-05-10`) 이 「⛔ 수정·삭제 — 없다(B-3 · `updated_at` 부재)」로 적었다. **계약도 그렇게 쓴다.**

### 11-0. ⛔ 왜 17 → 26 이 됐나 — **세 가지가 드러났다**

⭐ **셋 다 같은 형태다** — 2단계가 「자원 하나」로 센 것이 실제로는 **자원 여럿**이었다.

| # | 무엇 | 2단계가 센 것 | 실제 |
| :-: | --- | :-: | :-: |
| ① | **설비 자체에 쓰기 경로가 없었다** | 0 (기존 자원) | **+3** |
| ② | **점검 항목 「부여」 경로가 없었다** | 0 (마스터에 포함) | **+2** |
| ③ | **캘린더 일자·적용 경로가 없었다** | 0 (머리에 포함) | **+3** |

**①이 가장 무겁다.** 2단계 §11-4 는 `/mdm/equipments` 를 「기존 자원을 그대로 부른다 — 신설 0」으로 셌다. **그런데 있던 것은 선택 목록용 조회 하나뿐**이고, `W-05-12` 는 「설비 추가 · 저장 · 사용 중지」를 요구한다.

⭐ **1단계가 0단계에 대해 잡은 것과 정확히 같은 실수다** — 「**있다**」와 「**내가 쓸 수 있는 형태로 있다**」는 다르다. 1단계 §1 이 그 교훈을 적었는데 2단계가 다시 밟았다.

**②·③은 「부여」와 「본체」를 가르는 문제**다. 항목 마스터가 있어도 **어느 설비가 어느 항목을 도는가**는 다른 자원이고(공유계약 B-6), 캘린더 머리가 있어도 **어느 날이 휴무인가**·**어느 그룹이 이것을 따르는가**는 각각 다른 자원이다.

### 11-1. ⛔ 판정 변경 — **계측기 전용 경로를 두지 않는다**

2단계는 `/mdm/gauges` 4경로를 두기로 했다. **4단계에서 되돌린다.**

**근거는 11차 계측기 마스터(`W-05-11`) §3-2 자신이다** — 계측기는 `mdm.equipment` 의 한 종류이고 `equipment_type_code` 가 가른다.

```
⛔ /mdm/gauges + /mdm/equipments     같은 행 · 같은 version_no · 쓰기 두 벌
✅ /mdm/equipments 하나               계측기 화면은 equipmentTypeCode 로 «거른다»
```

⭐ **「같은 테이블을 다른 눈으로 본다」는 «필터» 이지 «자원» 이 아니다.** 두 경로에 각각 쓰기를 두면 **한 행을 두 계약이 쓰고**(공유계약 B-13 정면), 폐기 처리가 두 벌이 된다. 계측기 전용 속성(검교정 주기·정밀도)은 **설비 스키마에 더했다** — 계측기가 아니면 비어 있는 것이 정상이다(A-2 조건부).

⚠ **경로 이름도 하나 갈았다** — `/mdm/inspection-items` → **`/mdm/equipment-inspection-items`**. 이 계약에는 **품질 검사 항목이 이미 있고**(`/quality/inspection-plan-versions/{id}/items`), 11차 §4-C-1 이 「점검(설비) ≠ 검사(품질)」을 **테이블을 나누는 근거**로 세웠는데 경로 이름이 그것을 지우면 안 된다.

⭐ **`:deactivate` 와 `:dispose` 를 가른다** — 사용 중지(`is_active`)와 폐기(`status_code`)는 **다른 축**이다(`B-16`). `W-05-11`·`W-05-13` 이 버튼 둘을 따로 갖는다.

⭐ **`:import` 는 전 계약에서 처음 두는 파일 올리기다** — 2단계 §12 와 3단계 §7 이 「첨부와 같은 자리인지 못 정했다」로 남긴 자리의 답이다. **첨부와 다른 자리로 정했다** — 첨부는 **보관되는 파일**이고 올리기는 **읽고 버리는 입력**이다. 결과는 새 스키마를 만들지 않고 **기존 `BatchResult`** 로 받는다(부분 실패 허용).

⛔ **툴에만 두고 설비에는 두지 않았다** — 툴 엑셀 대장은 「엑셀 관리·ERP 미사용」이 확정이고(REQ-PR-0003), 설비 대장은 **매체가 미검증**이다(WF05 S1 🟡). **근거가 다르므로 판단이 다르다**(11차 §5-5).
