# 05 설비·툴 도메인 API 스펙 — 0단계 설계

> 작성일: 2026-08-18 · 대상 화면 **17장** · 작성 주체: CREFLE OMF 팀 (UI/UX)

---

## §1. 이 트랙이 마지막이다

06 기준정보 · 01 자재창고 · 02 생산실행 · 03 품질 · 04 제품출하 · 공통이 끝났다. **이 트랙을 끝내면 전 도메인 계약이 완주한다.**

### 1-1. ⛔ 「`#67` 회신 대기」는 이미 풀려 있었다

이 도메인은 오랫동안 **「데이터모델 회신을 기다린다」**로 표시돼 있었다. **틀린 표시였다.**

`omf-mes#67` 에 **우리가 직접 적어 두었다.**

> 이 이슈가 「05 착수 전 해소 필요」로 열려 있었는데 **그 전제가 바뀌었습니다.** 동결을 풀고 **17장을 전부 설계했으며** … 「이렇게 고쳐 달라」가 아니라 「화면이 이런 데이터를 필요로 한다」입니다.

**화면 스펙은 17/17 완성**이고, 확정(2026-08-10 작업 방식)이 「데이터 모델은 UI/UX 설계 결정에 맞춰 따라온다」다. **기다릴 것이 없다.**

⚠ 이 표시 오류는 **여러 판 동안 유지됐다.** 규칙(「그 답이 없으면 내가 지금 못 하는 일이 있나」)을 아는 상태에서 어겼다.

### 1-2. 차단 미결 — **17장 전수 0건**

05 스펙은 등급 열 대신 **성격**을 적는 서식이다(설계 결정 / 수집 대기 / 회신 대기). 전수로 훑어 **✅ 처리되지 않은 항목 6건**을 하나씩 열었고, **전부 「화면은 지금 지어도 된다」**였다.

| 화면 | 보류 항목 | 실제 |
| --- | --- | --- |
| `W-05-11` | 만료 계측기로 검사할 때 차단인가 | **이 화면의 결정 대상이 아니다** — 검사 화면 소관 |
| `W-05-12` | 설비 대장 매체 · 항목 표시 순서 | 엑셀 업로드를 **안 넣는 근거**이고, 순서는 화면이 순서대로 그린다 |
| `W-05-13` | QR 라벨 규격 | **이미지 생성 자체는 막지 않는다** — 도안 치수는 서버 파라미터 |
| `M-05-01` | 점검 항목 표시 순서 | 화면은 순서대로 그린다 |
| `P-05-01` | 적정 타수 초과 알람을 목록에 넣을지 | **우리가 정한다** — 확정으로 이벤트 목록은 계약이 갖는다 |

## §2. ⛔⛔ 이 트랙은 계약이 모델보다 **가장 크게** 앞선다

물리 모델이 **머리말에서 스스로 범위를 선언**하는데 **설비 보전이 그 안에 없다**(`#67`). 실측 결과 설비·툴 관련 표가 **셋뿐**이다.

```
✅ 실재  mdm.equipment · mdm.mold · quality.equipment_calibration
        (+ mdm.production_line · app.operation_policy · production.work_session 등 인접)
```

**없는 것**(전 파일 검색 0건):

| 없는 것 | 어느 화면이 필요로 하나 |
| --- | --- |
| 설비 그룹 | `W-05-12` |
| 점검 기록 — 헤더·라인 | `M-05-01` |
| 고장 기록·조치 | `M-05-02` · `W-05-04` |
| 보전 지시 · 보전 실적 | `W-05-05` · `W-05-06` · `W-05-03` |
| 예비품 마스터 · 설비-예비품 매핑 | `W-05-06` |
| 비가동 기록 | `P-05-02` · `W-05-08` |
| 툴 사용실적(타발수) | `P-05-01` · `W-05-02` |
| 수집 채널 매핑 | `W-05-07` |
| 작업 캘린더 · 휴일 | `W-05-09` |

⭐ **그것을 이유로 계약을 물리지 않는다.** 앞선 세 트랙에서 같은 원칙으로 처리했다 — `M-01-12`(컬럼 하나) · `P-02-05`(표 하나) · 공통(일곱). **규모가 다를 뿐 원칙은 같다.**

⚠ **다만 이번엔 스펙이 이미 형태를 정의해 두었다.** 각 화면 §8 이 「✅ 정의했다」로 헤더·라인 구조와 관계까지 적었다. **계약은 그것을 옮기면 된다** — 새로 발명하지 않는다.

## §3. 리소스 도출 — **어느 계약 파일에 두나**

⛔ **새 파일을 만든다** — `equipment-05설비툴.json`.

기존 다섯 계약 어디에도 안 맞는다. 네임스페이스가 물리 스키마를 따르는데 **설비 보전 스키마가 아직 없어** 우리가 정해야 한다. `mdm`(마스터)과 `production`(실행)에 흩어 넣으면 **도메인이 사라진다.**

⭐ **네임스페이스는 `/maintenance` 로 둔다** — 「보전」이 이 도메인의 본체이고, 마스터 셋(`equipment`·`mold`·계측기)은 이미 `mdm` 에 있어 그쪽을 쓴다.

| # | 리소스 | 경로 | 쓰는 화면 |
| :-: | --- | --- | --- |
| 1 | **점검 기록** | `/maintenance/inspections` | `M-05-01` |
| 2 | **고장 기록** | `/maintenance/breakdowns` (+ 조치) | `M-05-02` · `W-05-04` |
| 3 | **보전 지시** | `/maintenance/orders` | `W-05-05` · `W-05-02` |
| 4 | **보전 실적** | `/maintenance/results` | `W-05-06` · `W-05-03` |
| 5 | **예비품** | `/mdm/spare-parts` (+ 설비 매핑) | `W-05-06` |
| 6 | **비가동 기록** | `/maintenance/downtimes` (+ 집계) | `P-05-02` · `W-05-08` |
| 7 | **툴 사용실적** | `/maintenance/tool-usages` | `P-05-01` · `W-05-02` |
| 8 | **수집 채널 매핑** | `/maintenance/collection-channels` | `W-05-07` |
| 9 | **작업 캘린더** | `/mdm/work-calendars` | `W-05-09` |

**기존 자원을 쓰는 것** — 설비·설비그룹(`/mdm/equipment`) · 툴(`/mdm/molds`) · 계측기 검교정(`/quality/equipment-calibrations`) · 타발수 환산 파라미터(`app.operation_policy`).

⚠ **작업 캘린더를 `mdm` 에 두는 이유** — 휴일은 05 만 쓰지 않는다. **통합 대시보드(`W-CO-05`)의 설비종합효율 분모**가 여기 걸려 있다(`#67` 코멘트). 05 안에 가두면 그 화면이 남의 도메인을 부른다.
