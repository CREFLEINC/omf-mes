## §1. ⛔⛔ 0단계가 「기존 자원을 쓴다」고 한 것 **넷이 계약에 없다**

0단계 §3 이 이렇게 적었다 —

> **기존 자원을 쓰는 것** — 설비·설비그룹(`/mdm/equipment`) · 툴(`/mdm/molds`) · 계측기 검교정(`/quality/equipment-calibrations`) · 타발수 환산 파라미터(`app.operation_policy`)

**전 계약 6종의 경로를 전수로 훑어 확인했다.**

| 0단계가 「있다」고 한 것 | 실측 |
| --- | :-: |
| `/mdm/equipment` 설비 | ✅ **있다** — 정확히는 `/mdm/equipments` |
| **설비 그룹** | ⛔ **없다** |
| **툴·금형** `/mdm/molds` | ⛔ **없다** |
| **계측기 검교정** `/quality/equipment-calibrations` | ⛔ **없다** |
| **타발수 환산 파라미터** `app.operation_policy` | ⛔ **없다** — 물리 표는 실재하나 **계약 경로가 없다** |

⭐ **왜 어긋났나** — 0단계는 **물리 모델에 표가 있으면 계약에도 있다고 읽었다.** 둘은 다른 축이다. `mdm.mold` 는 실재하지만 **그것을 부르는 경로를 아무 트랙도 만들지 않았다** — 06 기준정보 트랙이 설비까지만 다뤘기 때문이다.

⚠ **이것이 규모를 바꾼다** — 0단계가 「신설 9」라 했는데 **실제로는 마스터 쪽에서 넷이 더 붙는다.**

### 1-1. 반대로 **덮여 있는 것 셋**을 찾았다

| 액션 | 쓰는 화면 | 기존 경로 |
| --- | --- | --- |
| **변경 이력 조회** | `W-05-11`·`W-05-12`·`W-05-13`·`W-05-07` **4장** | ✅ `GET /audit/events` *(기준정보 계약)* |
| **QR 라벨 이미지 생성 · 발행 이력** | `W-05-13` | ✅ `/app/document-issues` 계열 *(공통 출력물 계약)* |

```
신설 14   설비그룹 · 점검항목 · 툴 · 계측기 · 예비품 · 작업캘린더 · 운영정책
          점검기록 · 고장기록 · 보전지시 · 보전실적 · 비가동 · 툴사용실적
          수집채널 · 검교정이력          ← 열다섯인데 «설비» 가 기존이라 14
기존  3   설비(/mdm/equipments) · 변경이력(/audit/events) · 출력물(/app/document-issues)
```

⚠ **0단계의 「9」에서 늘었다** — 마스터 넷(설비그룹·툴·계측기·작업캘린더)과 점검 항목·운영 정책·검교정 이력이 더해졌고, 0단계가 「기존」이라 본 것들이 실제로는 없었기 때문이다.
