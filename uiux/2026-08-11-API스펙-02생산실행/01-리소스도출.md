### 1-1. ⛔ **계수부터 고친다 — 22이지 23이 아니다**

설계 초안이 「`production` 15 · 계 **23**」이라 적었다. **실측은 `production` 14 · 계 22** 다.

```
grep -cE '^CREATE TABLE planning\.'    →  8
grep -cE '^CREATE TABLE production\.'  → 14
```

⚠ **프로젝트에서 계수 오류가 반복된다** — 화면 진도 2회 · 조항 1회 · **이번**. **⛔ 표를 눈으로 세지 말고 `grep -c` 로 센다.**

## 2. ⭐⭐ 패턴 7 「구간 형」 — **신설한다**

### 2-1. 왜 기존 6종으로 안 되는가

**`production.work_session`(SQL 847)을 「라. 업무 문서 형」에 넣어 보면 어긋난다.**

| 업무 문서 형 | **`work_session`** |
| --- | --- |
| 만들고 → 확정하고 → 끝난다 | ⭐ **만들면 「열린 채로」 있다** |
| 상태가 컬럼에 있다 | ⛔ **끝 시각의 부재가 상태다**(**G-16**) |
| 조회 = 기간 필터(**L-3**) | ⚠ **「지금 열린 것」이 기본 조회**다 — 기간이 아니다 |
| 한 건이 한 번 확정된다 | **한 W/O 에 세션이 여럿**(`session_no` · `uq_work_session` 865) |

### 2-2. 「구간 형」의 정의

```
사. 구간 형 —  시작 시각이 필수이고 끝 시각이 없을 수 있다.
              「진행 중」은 상태 컬럼이 아니라 끝 시각의 부재로 판정한다.
```

**계약이 갖는 것 넷**

| # | 무엇 | 형태 |
| :-: | --- | --- |
| 1 | **열린 것 조회** | ⛔ `?status=RUNNING` 아님 → **`?open=true`**(끝 시각 없음). 기본값 |
| 2 | **여는 것** | `POST` — 리소스 생성 |
| 3 | **닫는 것** | ⭐ **`:end` 액션** — 상태 전이(URL 규약) · ⛔ `PATCH ended_at` 아님 |
| 4 | **겹침 거부** | 같은 대상에 **열린 구간이 둘이면 안 된다** → 409 |

⚠ **`ck_work_session_dates`(866 — 종료 ≥ 시작)는 계약이 400 으로 먼저 막는다.**

⛔ **02 가 쓰기 경로를 만들지 않는다** — **읽기만** 둔다. ⚠ **소유 화면이 없다** → §5-2

## 4. 판정하며 걸린 것 셋

### 4-1. ⭐ `work_order` 가 **두 패턴에 걸친다**

`production.work_order`(773)는 **업무 문서**(만들고 확정하고 마감)인데 **`work_session` 을 여럿 낳는다.** ⛔ **W/O 자체를 구간 형으로 보지 않는다** — **확정·마감이 상태 전이**이고 시각의 부재가 아니다.

⭐ **판정 기준 — 「둘째 시각이 없으면 진행 중인가」를 묻는다.** W/O 는 아니다(상태 코드가 있다). 세션은 그렇다.

### 4-2. ⚠ `production_result` 의 수량 5컬럼 — **#60 이 열려 있다**

`good_qty`·`defect_qty`·`hold_qty`·`scrap_qty`·`rework_qty`(1634~1638) · `CHECK (합 > 0)`(1660).

**정본은 3원**(양품/불량/손실)인데 **물리는 5컬럼**이다. ⛔ **계약이 임의로 3으로 접지 않는다** — **5를 그대로 노출하고 `#60` 을 계약에 링크**한다.

### 4-3. ⚠ `operation_handover` 가 **업무 문서인지 구간인지**

공정 간 인계다. **인계 시각과 인수 시각이 따로**면 구간 형이고, **한 번에 확정**되면 업무 문서다.

⛔ **지금 판정하지 않는다** — **2단계에서 화면(`M-02-01` WIP 공정 이동)의 버튼을 세어** 정한다. ⭐ **01 정정 #2 그대로 — 테이블이 아니라 버튼을 센다.**
