## 3. ⭐⭐ 02 는 앞의 셋과 **성격이 다르다** — 「진행 중인 것」이 있다

| 도메인 | 무엇을 다루나 | 시간축 |
| --- | --- | --- |
| **06 기준정보** | 마스터 | 유효기간 |
| **01 자재창고** | 전표 · 원장 · 잔액 | **끝난 사건** |
| ⭐ **02 생산실행** | **작업 세션 · 실적 · 상태 전이** | ⭐ **열린 구간이 있다** |

### 3-1. 「열린 구간」이 계약에 미치는 것

```
production.work_session   started_at  timestamptz NOT NULL   (SQL 855)
                          ended_at    timestamptz            (856 · nullable)
                          CHECK (ended_at IS NULL OR ended_at >= started_at)  (866)
```

⭐ **공유계약 G-16**(「진행 중」을 상태 컬럼으로 두지 않는다 — **끝 시각의 부재로 표현**)이 **계약 층에서 처음 검증된다.**

| 물음 | 계약이 답해야 하는 것 |
| --- | --- |
| 「진행 중 세션」을 어떻게 조회하나 | ⛔ `?status=RUNNING` 이 아니다 → **`?ended=false`** 같은 형태 |
| 끝내는 것은 PATCH 인가 액션인가 | **상태 전이** → **`:end`** (URL 규약) |
| 두 단말이 같은 세션을 끝내면 | **C-2**(오프라인 유일성) · `uq_work_session (work_order_id, session_no)`(865) |

→ **패턴 7번째 「구간 형」이 필요한지 1단계에서 판정**한다.

### 3-2. ⛔⛔ **오프라인이 여기서 본론이 된다**

01 은 모바일 일부만 오프라인이었다. **02 는 POP 13장이 전부 「제한적 오프라인」**(결정 17 — W/O 선배포 생산)이다.

**계약이 실어야 하는 것**

| 조항 | 계약에 무엇이 |
| :-: | --- |
| **C-8** | **멱등키를 클라이언트가 만든다** — `business_date` 까지. 헤더인가 본문인가를 **못박는다** |
| **C-9** | 오프라인 큐 전송에는 **낙관적 잠금 토큰을 싣지 않는다** — `If-Match` 를 **요구하지 않는 경로**가 생긴다 |
| **C-10** | **순서 의존이 있으면 묶음으로 거부** — 배치 전송 응답 형태 |
| **C-12** | 발생 시각은 **단말 시계** — `occurred_at` 을 클라이언트가 보낸다(`work_session_event.occurred_at` SQL 889 실재) |
| **C-16** | 한 건이 **부분 전송**되는 경우 — 급한 것을 먼저 |

⚠ **01 트랙은 이것을 화면별로 적었고, 02 는 계약 자체가 두 벌**이 된다 — 온라인 경로와 큐 경로. **같은 리소스에 규약이 둘이면 그 사실을 계약이 말해야 한다.**

### 3-3. ⭐ 단말 게이팅이 계약에 올라온다 — **F-1**

`mdm.terminal_process` **8플래그**(SQL 569~)가 액션 활성 조건이다. **02 화면 다수가 이 플래그로 버튼을 켠다.**

| 물음 | |
| --- | --- |
| 게이팅을 **서버가 강제하나 화면만 하나** | ⛔ **서버가 강제해야 한다** — 화면만 하면 우회된다 |
| 계약은 무엇을 보이나 | **403 의 사유 코드** · 그리고 **어떤 플래그가 막았는지** |

⚠ **F-6**(판정할 수 없음을 통과로 처리하지 않는다)이 걸린다 — 매핑 행이 없으면 **막는다.**

| **3** | **오프라인 규약** — 멱등키·큐 경로·배치 거부. ⭐ **02 에서 신설되는 단계** | `03-오프라인규약.md` |

## 6. ⭐ 계약이 모델보다 앞서도 된다 — 유지

2026-08-06 사용자 확정을 그대로 따른다. **02 에서 특히 그렇다** — `#76`(긴급 W/O 가 P/O NOT NULL 체인에 막힘 · **차단**)·`#86`(계획 자원배정 엔티티 부재)·`#60`(수량 구분 3원 ↔ 5컬럼)이 **전부 02 범위에서 열려 있다.**

⛔ **막힌 것을 계약이 우회하지 않는다** — **계약이 「이렇게 있어야 한다」를 적고, 모델이 따라온다.** 다만 **차단(`#76`)은 계약에 그대로 적어 드러낸다.**

## 7. 착수 전 확인 대상

### 7-1. ✅ **확인 완료 — 출력물 계약이 3장을 덮는다**

`app-공통.json` `/app/document-issues` 계열 **7 오퍼레이션**(발행·재발행 · 이력 · 렌디션 · 인쇄 결과 보고 · 프린터 목록 · 대상별 요약)이 받는다. **요구서 §3-1·3-2·3-3 이 세 화면을 각각 다뤘다.**

⛔ **「출력물이니까 덮겠지」로 넘기지 않고 실물을 열었다**(B-19).

### 7-2. ⛔⛔ **내 진단이 틀렸다 — 7장은 이미 처리돼 있다**

**설계 초안에서 이렇게 적었다.**

> **검사기는 고쳤고 스펙은 안 고쳤다.** … 1단계에서 **02 의 3장을 보정**하고, 01 의 4장은 **별건으로 넘긴다**.

⭐ **둘 다 이미 처리돼 있다 — 「액션 표를 만드는」 방식이 아니라 「사람이 본문에서 읽어 옮기는」 방식으로.**

| 어디 | 무엇 |
| --- | --- |
| **출력물 요구서 §2-1** | 「`P-02-05`·`P-02-07`·`P-02-09` 는 **확대 3차 서식**이라 액션 소절이 없다. 요구는 **§5 본문에서 사람이 읽어** §3 에 옮겼다. **생성 목록에 없다고 요구가 없는 것이 아니다**」 |
| 동 **§3-6** | 「**본문 도출 16건** ✅ · ⚠ **자동 검산 대상이 아니다** — 사람이 §3-1~3-3 을 읽어 확인한다」 |
| **01 요구서 115행** | 「액션 표가 없는 화면 4장은 목록에 안 잡힌다. **§5 본문에서 사람이 읽어** §3-20~23 에 따로 옮겼다」 |

⛔ **커버리지가 부풀려진 것이 아니다.** 검사기가 **경고를 내고**, 요구서가 **경고를 받아 사람이 메우고**, 그 사실을 **문서에 적었다.** 설계된 대로 작동했다.

### ⚠ 그래서 남는 진짜 항목은 **다르다**

| 하지 않는 것 | 하는 것 |
| --- | --- |
| ⛔ 3차 스펙에 액션 표를 소급 추가 | ⭐ **02 요구서도 같은 방식을 쓴다** — 본문 도출분은 **§2-1 같은 절을 두어 명시**한다 |

⚠ **소급 추가는 이득이 없다** — 요구서가 이미 다뤘고, 스펙을 고치면 **그때의 서식 기록이 지워진다.**

### ⭐ 이번 세션에서 **네 번째다** — 「이미 처리돼 있다」

휴일 달력(#67 회신) · 인증 3컬럼(#69·#90) · 알림·공지·좌표(#90·#87) · **이 건**. **관문 ②(이미 판정이 있는가)가 네 번 다 걸렸다.**

⛔ **공통점 — 「내가 방금 발견한 것」처럼 쓰기 전에 앞의 산출물을 연다.**

### 7-3. 열려 있는 데이터 모델 이슈 3건이 02 범위다

| 이슈 | 무엇 | 계약에서 |
| :-: | --- | --- |
| **#76** | 긴급 W/O 가 P/O `NOT NULL` 체인에 막힘 | ⛔ **차단** — `W-02-07` 이 성립하지 않는다. 계약에 드러낸다 |
| **#86** | 계획 자원배정 엔티티 부재(결정 04 계획 쪽) | `W-02-03` 4M 자원배정 |
