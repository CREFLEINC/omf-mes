### 1-1. ⭐ `operation_handover` — **버튼이 하나라 구간이 아니다**

`M-02-01`(WIP 공정 이동 스캔)의 액션을 세었다.

```
① LOT 스캔  →  ② 다음 공정 선택  →  수량 입력  →  [ 인계 확정 ]
```

⛔ **「인수」 버튼이 없다.** 인계와 인수가 **한 번에 확정**된다.

| 구간 형 판정 기준(1단계 §4-1) | `operation_handover` |
| --- | :-: |
| 「둘째 시각이 없으면 진행 중인가」 | ⛔ **아니다** — 한 번에 끝난다 |

⭐ **테이블 이름(`handover` = 인계)만 보면 구간처럼 보였다.** 화면을 열어 **버튼을 세니 하나**였다. → **구간 형은 `work_session` 하나뿐**이다.

### 1-2. ⭐⭐ BOM·Routing 은 **06 계약이 이미 갖고 있다**

`mdm-기준정보.json` **실물 대조**(B-19).

```
/planning/boms · {bomId} · :set-default · /components · /components/{id}          5
/planning/routings · {routingId} · :new-revision · :confirm · :obsolete
                   · /operations · /operation-dependencies                        7
                                                                          계 12경로
```

⛔ **02 가 다시 정의하지 않는다 — 읽기만 한다.** `W-02-02`(BOM·Routing Rev 선택)는 **06 경로를 호출**한다.

⚠ **1단계 배정이 바뀐다** — 「다. 버전 마스터 3」은 **02 소유 0** 이다.

### 5-1. ⚠ **중단·재개는 두 층에 있다 — 갈라 적는다** *(리뷰 반영)*

✓설계확정 **결정 14** — 「W/O 상태 8종 … **중단↕재개 반복** · **재시작은 상태가 아니라 중단→진행 전이 이벤트**」.

| 층 | 무엇 |
| --- | --- |
| **W/O** | ⭐ **`:hold` · `:resume`** — 결정 14 의 상태 전이. `P-02-01` 의 「**재개**」(「설비 고장 · 09:40부터 → [재개]」)가 이것이다 |
| **세션** | ⛔ **`:hold` 를 두지 않는다** — **`:end` 뒤 새 `session_no`** 로 잇는다. `P-02-01` §5-4 가 「`uq_work_session` … **중단·재개마다 는다**」로 적었다 |

⚠ **초안이 `:hold`·`:resume` 를 세션에만 걸었다** — `P-02-10` 이 POP 화면이라 세션으로 보였으나 **상태는 W/O 가 갖는다.**

### 5-2. ⛔⛔ **`:cancel` 을 「없다」로 적었던 것이 틀렸다** *(리뷰 반영)*

**초안이 이렇게 단정했다.**

> ⛔ **`:cancel` 은 두지 않는다** — 02 화면 20장 어디에도 취소 버튼이 상태 전이로 쓰이지 않는다

⛔ **세 화면이 반대로 적고 있다.**

| 화면 | 원문 |
| --- | --- |
| **`W-02-06`** §5-5 | 「**W/O를 취소해야 한다** — 예외 **E-4 ④** 가 「**취소 상태 신설 확정**·선발행 LOT 회수 규칙 잔여」로 남겼다」 |
| **`W-02-04`** §8-6 | 「배포 후 W/O 수정·취소 — **취소 상태 신설은 확정**」 |
| **`W-02-08`** §8-3 | 「`work_order.status_code` 값 목록 — **「취소」가 오면 카드가 는다**」 |

⚠ **추출된 액션 표만 보고 판정했다.** 표의 「취소」(`P-02-04`·`W-02-04` §5)는 **입력 화면을 닫는 것**이 맞지만, **W/O 수준 취소는 §5-5·§8 에 있다.**

⭐ **같은 문서가 3차 6장은 본문을 읽었는데**(§3 본문 도출 16건) **5차 화면의 본문은 안 읽었다.**

**계약이 적는 것**

```
POST /production/work-orders/{workOrderId}:cancel
  ✅ 취소 상태 신설은 확정 (예외 E-4 ④)
  ⛔ 선발행 LOT 회수 규칙이 잔여 — 이 액션의 부수 효과를 계약이 못 적는다
     R82「마감 시 자동 폐번」은 마감 경로이고 취소 경로가 아니다
```

⚠ **`#76`·`:override` 와 같은 취급** — **경로는 적고 미결을 드러낸다.** ⛔ 임의로 「폐번한다」로 정하지 않는다.

## 6. 판정하며 걸린 것 셋

### 6-1. ⛔ `W-02-07` 긴급 W/O — **#76 이 차단이다**

`P/O NOT NULL` 체인에 막혀 **P/O 없는 W/O 를 만들 수 없다.** ⛔ **계약이 우회하지 않는다** — 경로는 적되 **`x-internal-note` 에 「#76 미해소 시 501」**을 명시한다.

### 6-2. ⚠ `:override` — **데이터에 근거가 없다**

`P-02-02` 가 「우회하고 시작」을 갖고 `P-02-12` §5-3 이 「**통제 우회 — 데이터에 근거가 없다**」로 적었다.

⭐ **F-6**(판정할 수 없음을 통과로 처리하지 않는다) — **우회는 기록돼야 한다.** ⛔ 기록할 자리가 없으면 **경로를 만들지 않고 미결로 올린다.** → §7

### 6-3. ⚠ 오프라인 경로가 **따로 필요한가**

POP 13장이 큐를 쓴다. **같은 리소스에 규약이 둘**이 된다.

| 안 | |
| :-: | --- |
| 가 · **경로를 나눈다**(`/queue/...`) | ⛔ 리소스가 두 벌이 된다 |
| ⭐ **나 · 같은 경로 + 헤더로 구분** | **멱등키 헤더**가 있으면 큐 전송 — `If-Match` 미요구(**C-9**) |

⭐ **「나」로 간다** — **3단계에서 확정**한다.
