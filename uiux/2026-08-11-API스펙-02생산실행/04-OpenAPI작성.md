# 02 생산실행 — 4단계 OpenAPI 작성

> 작성일: 2026-08-11 · 선행: `03-오프라인규약.md`
> **산출물**: `deliverables/openapi/production-02생산실행.json` · **생성기** `build-02-openapi.py`

## 1. 규모

```
경로 32 · 오퍼레이션 45 · 스키마 42 · :동사 경로 11 · 122KB
검사기 3종 전건 통과 — check-structure · check-public-safe · 단위 테스트 23
```

| | 06 기준정보 | 01 자재창고 | 공통 | **02 생산실행** |
| --- | :-: | :-: | :-: | :-: |
| 경로 | 78 | 63 | 15 | **32** |
| 오퍼레이션 | 116 | 85 | 19 | **45** |
| 스키마 | 107 | 105 | 27 | **42** |

⭐ **02 가 화면은 가장 많은데(24) 경로는 적다** — 남의 계약을 많이 쓴다(BOM·Routing 06 · LOT·출고요청 01 · 검사 03 · 출력물 공통).

## 2. ⛔⛔ **검사기에 구멍이 있었다 — `patch` 가 빠져 있었다**

```python
# 고치기 전
WRITE_METHODS = ('post', 'put', 'delete')      # ⛔ patch 없음
ALL_METHODS   = ('get',) + WRITE_METHODS
```

**PATCH 오퍼레이션은 멱등키·example·409 검사를 통째로 빠져나간다.** 계수에도 안 잡힌다.

### 2-1. 어떻게 드러났나

**내 생성기가 센 오퍼레이션 45 와 검사기가 센 43 이 달랐다.** 차이 2가 정확히 PATCH 2건이었다.

⚠ **숫자가 안 맞아서 찾았다** — 검사기가 「✅ 계약으로 성립합니다」를 답하고 있었으므로 **결과만 봤으면 못 봤다.**

### 2-2. 왜 지금까지 안 드러났나

| 계약 | PATCH |
| --- | :-: |
| 06 기준정보 · 01 자재창고 · 공통 | **0건** |
| **02** | **2건** |

⭐ **앞의 셋이 PATCH 를 한 번도 안 써서 구멍이 안 보였다.** ⚠ **다음 계약이 PATCH 를 쓰면 조용히 검사를 빠져나갔을 것**이다.

### 2-3. 고쳤다 — 그리고 **즉시 두 건을 잡았다**

```python
WRITE_METHODS = ('post', 'put', 'patch', 'delete')
```

고친 검사기가 바로 답했다.

```
⛔ 쓰기인데 Idempotency-Key 없음 — PUT /planning/production-plans/{productionPlanId}
⛔ 쓰기인데 Idempotency-Key 없음 — PUT /production/work-orders/{workOrderId}
```

⭐ **구멍이 실재했다는 증거다.** 두 건 다 붙였다.

⚠ **01 트랙 정정 #5 와 같은 형태**다 — 「**검사기가 산문에 걸려도 통과하고 있었다** — 커버리지를 보증하려는 도구가 커버리지를 부풀렸다」.

## 3. ⛔ 규약 이탈을 스스로 잡았다 — **02 만 PATCH 를 쓸 뻔했다**

**앞의 세 계약은 수정에 `PUT` 만 쓴다.**

```
mdm-기준정보     get 56 · post 35 · put 25 · patch 0
logistics-01     get 46 · post 28 · put 11 · patch 0
                                    ─────────────────
                                     PUT 36 · PATCH 0
```

⛔ **02 의 PATCH 2건을 PUT 으로 바꿨다.** ⚠ **「부분 수정이니 PATCH 가 맞다」는 일반론보다 「이 저장소가 무엇으로 통일돼 있는가」가 먼저**다.

## 4. ⭐ `:validate` 를 액션에서 뺐다 — **상태 전이가 아니다**

2단계가 `:동사` 목록에 `:validate` 를 넣었는데, **2단계 자신의 규약(`:동사` 는 상태 전이에만)에 걸린다.**

| | |
| --- | --- |
| ⛔ 구 | `POST /production/work-orders/{id}:validate` |
| ⭐ 신 | **`GET /production/work-orders/{id}/validation`** |

⭐ **저장하지 않는다.** 4M 배정이 부딪히는지 보고 결과만 돌려준다. **`:동사` 가 11 → 10 이 된다**(02 소유 기준).

## 5. ⭐⭐ 계약을 쓰다가 찾은 것 둘

### 5-1. `idempotency_key` 가 **테이블 컬럼으로도 있다**

```
production.material_consumption.idempotency_key  varchar(150) NOT NULL UNIQUE
production.production_result.idempotency_key     varchar(150) NOT NULL UNIQUE
```

⭐ **헤더로 받아 그 자리에 저장한다** — C-8 의 저장 측이 이미 준비돼 있었다. `x-internal-note` 에 적었다.

### 5-2. ⛔ `operation_handover` 에 **시각이 둘인데 받는 화면이 없다**

```
handed_over_at  timestamptz NOT NULL   (1706)
received_at     timestamptz            (1707 · nullable)
```

⚠ **데이터는 구간 형 모양이다.** 그런데 2단계가 **버튼을 세어 업무 문서 형으로 판정**했다(`M-02-01` 의 버튼은 「인계 확정」 하나 · 「인수」 0건).

**둘이 어긋난다.** ⭐ **원칙 1)에 따라 화면을 따른다** — **인계 확정 시 두 시각을 함께 찍는다.**

⚠ **`x-internal-note` 에 그대로 적었다** — 「받는 쪽 화면이 없어 `received_at` 을 채울 경로가 생기지 않는다. **인수 확인 화면이 나중에 생기면 `:receive` 를 더한다**」.

## 6. 계약이 **드러낸** 미해소 셋

⛔ **우회하지 않았다.**

| 무엇 | 계약에 |
| --- | --- |
| **#76** 긴급 W/O 가 P/O `NOT NULL` 체인에 막힘 | `POST /production/work-orders` 에 **`501`** 응답 + `x-internal-note` |
| **#60** 수량 3원 ↔ 물리 5컬럼 | **다섯 컬럼을 그대로 노출** · 「계약이 임의로 접지 않는다」를 스키마 설명에 |
| **DR-007** 취소 시 선발행 LOT 회수 | `:cancel` 경로는 두고 **부수 효과를 적지 않는다** · `x-internal-note` 에 사유 |

## 7. 구간 형이 계약에서 어떻게 섰나

| 무엇 | 형태 |
| --- | --- |
| 열린 세션 조회(기본) | `GET /production/work-sessions?open=true` — ⛔ `?status=` 아님 |
| 닫기 | `POST …/{id}:end` — ⛔ `PUT ended_at` 아님 |
| 중복 | **409 `OPEN_SESSION_EXISTS`** |
| 작업자 이탈 | ⭐ **`POST …/workers/{id}:leave`** — ⛔ `DELETE` 아님. **떠난 시각을 찍는다** |
| 통제 우회 | ⭐ **세션 생성의 인자** `controlOverride` — 별도 액션 없음 |

⭐ **`leftAt` 도 구간이다** — 작업자 참여도 「둘째 시각의 부재」로 판정된다. **패턴 7 이 세션 밖에서도 선다.**
