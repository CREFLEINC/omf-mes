## 2. ⭐⭐ 14차가 넘긴 OEE — **받아서 실측했고, 그리지 않는다**

14차 `W-05-08` 이 「**통합 대시보드처럼 세 도메인을 함께 보는 자리가 맡는 것이 맞다**」로 넘겼다. **그 자리에 와서 확인했다.**

### 14차의 이유는 **해소된다**

14차가 못 그린 이유는 「**소유가 셋으로 갈린다**」였다. ⭐ **이 화면은 셋을 다 보이므로 그 문제가 생기지 않는다.**

### ⛔⛔ 그런데 **다른 것이 걸린다 — 분모가 없다**

```
시간가동률 = 실제 가동시간 ÷ 계획 조업시간
                              ↑ 성립하지 않는다
```

**A-13 4단 실측** — `calendar`·`work_calendar`·`non_working`·`closure`·`planned_stop`·`maintenance` **전부 0건**. `mdm.shift.start_time`·`end_time`(542·543)은 있으나 **「그날 조업했는가」를 모른다.**

### ⭐⭐ 유일한 `holiday` 한 건이 문제를 정확히 보여 준다

```sql
-- SQL 3359 · OPERATION_POLICY 시드
('ALLOW_PRODUCTION_ON_HOLIDAYS',  '휴일 생산 허용',  100),
```

⭐ **정책은 「휴일에 생산을 허용할 것인가」를 묻는데, 어느 날이 휴일인지를 담을 곳이 없다.** **F-3**(게이트는 판정 근거 컬럼의 실재를 확인해야 성립) 이 말한 그대로이고, **✓설계확정 결정 03**(「계획 비가동 = WorkCalendar 계층형」)이 **물리 모델에 없다.**

### 결론

| | 그리나 |
| --- | :-: |
| 양품률 · 성능가동률 | ✅ |
| **시간가동률** | ⚠ **그리되 분모를 본문으로 밝힌다**(⛔ 툴팁 아님) |
| **OEE(곱)** | ⛔ **그리지 않는다** |

⭐ **곱은 결손을 평균 내 감춘다.** 「OEE 61%」는 **세 가지 서로 다른 행동** 중 무엇을 해야 할지 알려 주지 못한다. → **L-16 신설**

⚠ **14차의 이유가 해소돼도 결론이 유지된다 — 이유가 다르기 때문이다.** 이것을 조항에 적었다.

## 3. ⭐⭐ 「같은 모양」을 컬럼 단위로 검증했다

DR-005 가 「**알림과 같은 모양**」·「따로 만들면 같은 것을 두 번 만든다」고 적었다. **16차가 알림을 이미 정의했으므로 실제로 대조할 수 있었다.**

| | 알림 | 공지 |
| --- | --- | --- |
| 누가 만드나 | ⚙ 이벤트 | 👤 **사람** |
| 게시 기간 · 확인 강제 | ⛔ 없다 | ✅ **있다** |
| 대상 | 다형 참조 | 범위 2종 |
| **1 : N 확인 이력** | ✅ | ✅ **같다** |

⭐ **본체는 나누고, 수신 이력만 형태를 맞춘다.** 합치면 **절반이 늘 NULL** 이다.

⚠ **확정의 의도는 「두 번 만들지 말라」이지 「한 테이블에 넣으라」가 아니다.** → **A-22 신설**

### ⭐ B-24 가 두 화면에서 **반대 결론**을 냈다

| 물음(B-24) — **자동 포함이 의도인가** | |
| --- | :-: |
| 16차 알람 수신자 — **명단**이다 | ⛔ 「전사」 안 둔다 |
| 17차 공지 — 신규 입사자도 **당연히 봐야** 한다 | ✅ **「전사」 둔다** |

⭐ **조항이 제 일을 한 것이다.** 낱말이 같다고 판단이 같지 않다.

## 4. ⭐ 「무엇을 안 쓰는가」가 설계였다 — 재생재

DR-006 이 **둘을 동시에** 확정했다 — 「구분한다」와 「**추적하지 않는다**」.

| 계보를 적을 자리 | 실재 | 이 화면 |
| --- | :-: | :-: |
| `trace.lot.parent_lot_id`(1054) | ✅ | ⛔ **비운다** |
| `trace.lot_relation`(2078) — 「계보의 원천」 | ✅ | ⛔ **행을 만들지 않는다** |

⚠ **일부만 채워진 계보가 빈 계보보다 위험하다** — 「추적 가능」으로 오해된다. → **A-21 신설**

### ⭐ 통계를 만드는 것은 구분 코드가 아니라 **`item_id` 분리**다

```
inventory_balance.item_id   NOT NULL (1094)
goods_issue_line.item_id    NOT NULL (1474)
```

**신재와 재생재가 다른 `item_id` 를 가지면 재고·출고가 자동으로 갈린다** — 전용 집계 화면을 만들 필요가 없다(→ **L-15**). ⭐ **이것이 「자재 묶음이 아니라 품목에 둔다」가 옳은 이유**다.

### ⭐ 「추적하지 않는다」와 「기록하지 않는다」를 갈랐다

`source_id` 가 **`NOT NULL`**(1052)이다. **누가 언제 얼마를 등록했나는 남고**, **어느 LOT 에서 나왔나는 안 남는다**. → **B-25 신설**

## 7. ⛔ 스스로 잡은 것 — **B-22 를 세운 우리가 B-19 를 안 돌렸다**

**B-22**(범용 정책 테이블은 「코드 목록」이 계약이다)를 14차에 세울 때 **`OPERATION_POLICY` 시드가 이미 있는지 확인하지 않았다.**

```
mdm.code_group('OPERATION_POLICY')  시드 14건   SQL 3341~3366
```

⚠ **B-19**(「이미 있는 것을 쓴다」를 단계별로 확인)를 **세운 것이 우리이고, 그것을 안 돌린 것도 우리다.** 조항이 무효가 되지는 않는다 — **규칙 1 의 뜻이 「목록을 만든다」에서 「이어붙인다」로 좁아진다.** B-22 에 보완으로 적었다.

⚠ **우리가 더할 코드 중 하나는 이미 있다** — 사후입력 허용시간은 `LATE_ENTRY_ALLOWED_HOURS` 로 시드에 있다.
