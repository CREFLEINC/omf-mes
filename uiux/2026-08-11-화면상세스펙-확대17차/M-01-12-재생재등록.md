## §3. ⭐⭐ 이 화면의 설계 지점은 **「무엇을 안 쓰는가」**다

DR-006 은 **두 가지를 동시에 확정**했다 — 「구분한다」와 「추적하지 않는다」.

### §3-1. 계보 자리가 **실재하는데 채우지 않는다**

**A-13 4단을 돌린 결과, 계보를 적을 곳이 두 군데 있다.**

| 자리 | 실재 | 이 화면 |
| --- | :-: | :-: |
| `trace.lot.parent_lot_id`(SQL 1054) | ✅ 있다 | ⛔ **비운다** |
| `trace.lot_relation`(SQL 2078) | ✅ 있다 — 「**계보의 원천**」(1055 주석) | ⛔ **행을 만들지 않는다** |

⛔ **「자리가 있으니 채운다」로 가지 않는다.** DR-006 이 「**어디서 어떻게 만들어진 건지 추적하는 건 불필요**」로 확정했고, 그 확정은 **문답 31번의 「내부 이력 완전 기록」을 명시적으로 뒤집은 것**이다.

⚠ **채우면 손해가 있다** — 계보가 **일부만 채워진 상태**가 된다. 재생재 LOT 에만 부모가 있고 다른 경로에는 없으면, **계보 조회 화면이 「추적 가능」으로 오해**한다. **비워 두는 것이 「추적하지 않는다」를 정직하게 표현**한다. → §9-1

### §3-2. ⭐ 통계를 만드는 것은 **구분 코드가 아니라 `item_id` 분리**다

DR-006 은 목적을 「**재생재 사용량 통계 분석**」으로 못박았다. **그 통계가 실제로 성립하는 이유가 무엇인지 실측했다.**

```
inventory.inventory_balance.item_id   NOT NULL  (SQL 1094)   ← 재고가 품목으로 선다
logistics.goods_issue_line.item_id    NOT NULL  (SQL 1474)   ← 출고도 품목으로 선다
```

⭐ **신재와 재생재가 서로 다른 `item_id` 를 가지면 재고·투입·출고가 자동으로 갈린다.** 집계 화면을 새로 만들 필요가 없다 — **기존 조회에 축이 하나 느는 것**이다.

⚠ **이것이 「구분 코드를 품목에 둔다」가 옳은 이유**다. 자재 묶음(LOT)에 붙였다면 재고는 여전히 한 `item_id` 로 서고 **집계할 때마다 LOT 를 훑어야** 한다.

### §3-3. ⛔ 유일 제약이 부딪친다 — **DR-006 이 이미 적었다**

```
현재:  mdm.item.item_code  app.code_t NOT NULL UNIQUE   (SQL 365)
필요:  같은 ERP 코드에 「신재」·「재생재」 두 행
```

⚠ **이것은 이 장의 발견이 아니다** — **DR-006 §「이 확정이 데이터에 남기는 것」이 이미 같은 내용을 적었다.** 이 장이 더하는 것은 하나다: **A-19**(유형 코드를 더하면 유일 제약을 함께 본다)의 **두 번째 사례**이고, 첫 사례(`W-05-07` 채널 매핑)와 **해법이 다르다**.

| | `W-05-07` | **이 화면** |
| --- | --- | --- |
| 부딪친 것 | 품목·공정 조건이 유일 제약과 | ERP 코드가 유일 제약과 |
| 해법 | **A-7 부분 유일 인덱스** | ⭐ **복합 유일** `(item_code, mes_category_code)` |
| 왜 다른가 | 조건이 **NULL 일 수 있다** | 구분 코드는 **모든 행에 있다**(기본 `NEW`) |

### §5-B. 품목 마스터에 더할 것 — **`[신설]` 1**

| 컬럼 | 무엇 | 값 |
| --- | --- | --- |
| `mes_category_code` | **MES 구분 코드**(DR-006 6-A) | `NEW`(신재) / `RECYCLED`(재생재) · **기본 `NEW`** |

⛔ **ERP 로 보내지 않는다** — DR-006 「ERP 에는 신재와 동일하게 처리」. **웹-기간계연계-송신이 이 컬럼을 제외**한다. → §8-3

⚠ **`item_code` 는 그대로 둔다** — ERP 와 공유하는 코드는 하나다. **바뀌는 것은 유일 제약**이다(§3-3).

### §5-1. LOT 번호는 **서버가 발번한다** — 화면이 미리 보이지 않는다

`trace.lot.lot_no` 는 `uq_lot UNIQUE (plant_id, lot_no)`(SQL 1063)다. **번호를 클라이언트가 정하면 오프라인 두 단말이 같은 번호를 만든다**(**C-2**).

⭐ **그래서 화면이 「번호는 저장 후 정해집니다」라고 먼저 말한다**(**C-7** 두 등급 피드백 · **G-19** 저장 전에 파급을 말한다).

### §5-2. `source_type_code` — **다형 참조에 값이 하나 는다**

`trace.lot.source_type_code`·`source_id`(SQL 1051·1052)는 **FK 가 없는 다형 참조**다. 재생재 LOT 은 **입고 전표도 작업지시도 아니다.**

⭐ **A-16** 이 정한 대로 **계약이 먼저 값을 갖는다** — `RECYCLE_ENTRY`(이 화면의 등록 건). → §9-2

⚠ **`source_id` 가 `NOT NULL`**(1052)이다. **가리킬 행이 있어야 한다** — 등록 건 자체를 남길 자리가 필요하다. ⛔ **그런데 「추적 불필요」다.** 모순처럼 보이나 아니다:

| 무엇 | 필요한가 |
| --- | :-: |
| **누가 언제 얼마를 등록했나** | ✅ **필요** — 감사 추적이고, `NOT NULL` 이 요구한다 |
| **이 재생재가 어느 LOT 에서 나왔나** | ⛔ **불필요** — DR-006 이 뺀 것 |

⭐ **DR-006 이 뺀 것은 「원료 계보」이지 「등록 기록」이 아니다.** → §9-3

### §5-3. 액션·상태

| 액션 | 활성 조건 |
| --- | --- |
| 스캔 | 항상 |
| 등록 | 자재·구분·수량(>0)·창고·위치 **전부** |

**상태**: `초기` → `자재 선택됨` → `입력 중` → `저장 중` → **`성공(LOT 번호 표시)`** / `대기(오프라인 큐)` / `실패`

⛔ **연속 등록으로 만들지 않는다** — 분쇄는 **독립 사건**(DR-006 6-C)이고 한 번에 한 건이다. 저장 후 **입력을 비우고 같은 화면에 머문다**.

### §6-1. ⭐ 오프라인 — **담기지만 번호는 나중에 온다**

**C-14**(판정값을 쓰는가)로 판정한다.

| 물음 | 답 |
| --- | :-: |
| 이 화면이 **판정값**을 쓰는가 | ⛔ 아니다 — 재고를 **늘리기만** 한다 |
| 내가 만든 것이 **남의 판정 근거**인가(**C-15**) | ⚠ **그렇다** — 재고가 는다 |

```
⏳ 등록 대기 1건 — 연결되면 전송됩니다
   LOT 번호는 전송 후 정해집니다
```

⛔ **오프라인 상태에서 라벨을 인쇄할 수 없다** — **K-5**(라벨은 서버가 그린다) + 번호가 아직 없다. **화면이 그렇게 말한다**(**G-20** — 버려지는 것이 아니라 **미뤄지는 것**임을 구분해 적는다).

⚠ **멱등키는 `business_date` 까지 클라이언트가 정한다**(**C-8**) — 같은 등록이 두 번 전송돼도 LOT 이 둘 생기지 않는다.

## §9. 이 장에서 나온 공유 계약 후보

### 9-1. ⭐⭐ **「기록하지 않기로 한 것」은 컬럼을 비우고, 비운 이유를 스펙이 적는다**

**G-24**(만들지 않기로 한 것을 목록으로 적는다)의 **데이터 판**이다.

| 상황 | 하는 것 | ⛔ 안 하는 것 |
| --- | --- | --- |
| 자리가 있고 채우기로 함 | 채운다 | |
| **자리가 있는데 안 채우기로 함** | ⭐ **비우고, 스펙에 「왜 비우는가」를 적는다** | 「있으니까」 채우기 |
| 자리가 없고 필요함 | 신설 요구 | |

⚠ **일부만 채워진 계보가 빈 계보보다 위험하다** — **「추적 가능」으로 오해**되기 때문이다. 「없음」은 정직하고 「일부 있음」은 거짓말에 가깝다.

— `M-01-12` §3-1 · G-24 · A-13

### 9-2. **다형 참조 값 목록에 `RECYCLE_ENTRY` 를 더한다**(A-16 운영)

`trace.lot.source_type_code` 의 값 목록에 **여섯째**가 붙는다. **A-16** 이 정한 대로 계약이 먼저 갖는다.

### 9-3. ⭐ **「추적하지 않는다」와 「기록하지 않는다」는 다르다**

DR-006 이 뺀 것은 **원료 계보**이고, **누가 언제 얼마를 등록했나는 남는다**(`source_id NOT NULL` 이 요구하기도 한다).

| 구분 | 무엇 | 이 확정에서 |
| --- | --- | :-: |
| **감사 추적** | 누가 언제 무엇을 했나 | ✅ **남는다** |
| **계보 추적** | 이것이 무엇에서 나왔나 | ⛔ **빼기로 함** |

⚠ **확정을 넓게 읽어 둘 다 빼면 감사가 불가능해지고, 좁게 읽어 둘 다 남기면 확정을 어긴다.**

— `M-01-12` §5-2 · **16차 `W-CO-10` §3-1 과 같은 형태**(뺀 이유를 보면 경계가 나온다)

### 9-4. **집계 축이 느는 것은 「전용 화면」이 아니라 「기존 필터」다**

⭐ **`item_id` 가 갈리면 집계는 이미 갈려 있다.** 새 화면을 만드는 대신 **기존 조회에 필터 축을 더한다.**

⚠ **다만 「더해야 한다」는 사실이 조용히 묻히면 안 된다** — 어느 화면에 무슨 축이 느는지를 **차수 마감 시 목록으로 넘긴다**.

⭐ **같은 목록이 「빼야 하는 것」도 받는다** — 복합 유일로 바뀌면 **품목코드 단독 조회가 성립하지 않는 경로**가 생긴다(§8-4a). **축이 느는 것과 유일성이 깨지는 것은 같은 변경의 앞뒤**다.
