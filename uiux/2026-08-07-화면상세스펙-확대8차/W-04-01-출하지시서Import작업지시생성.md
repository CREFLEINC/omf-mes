## §5. 액션·상태

### §5-1. ⭐ 3계층이 **수량 3개로 연결된다** — DB가 강제한다

```
ck_shipment_request_qty   CHECK (shipped_qty <= allocated_qty AND allocated_qty <= requested_qty)
ck_sales_shipped_qty      CHECK (shipped_qty <= ordered_qty)
```

01·02 도메인의 문서는 헤더–라인 2계층이었는데 **04는 세 층이 수량으로 물려 있다.**

| 층 | 무엇을 정하나 | 어느 화면 |
| --- | --- | --- |
| 고객사 출하지시서 | **요청** — 얼마를 언제까지 | 수신(이 화면 읽기) |
| **출하작업지시** | **배정** — 그중 얼마를 이번에 | **이 화면** |
| 출하지시 | **출하** — 실제 나간 수량 | `W-04-04` |

**규칙**: 배정 수량이 요청을 넘으면 **DB가 거부**하므로 화면이 먼저 막는다. 오류 문구에 **어느 제약인지가 아니라 무엇을 고쳐야 하는지**를 담는다 — 「배정은 요청 수량 500을 넘을 수 없습니다」.

⚠ **부분 배정이 정상이다** — 가용이 모자라면 배정을 줄이고 나머지는 다음 작업지시로 간다. 화면이 그것을 막지 않는다.

### §5-2. ⭐ 「지시서 없이 단독 생성」은 **데이터가 이미 허용한다**

인벤토리 근거가 「⚠ 지시서 없이 단독 생성 모드(§8-5)」를 미결로 달아 두었다. **실측 결과 모델이 이미 받는다.**

```
shipment_request_line.sales_order_line_id   bigint REFERENCES ...   ← nullable
```

**두 모드가 같은 테이블에 들어간다.**

| 모드 | `sales_order_line_id` | 언제 |
| --- | :-: | --- |
| 지시서 경유 | 채워진다 | 정상 흐름 |
| **단독 생성** | **비어 있다** | 긴급 출하 · 샘플 · 지시서가 늦게 오는 경우 |

**화면 규칙** — 단독 생성은 **별도 진입**(`[+ 단독 생성]`)으로 두고, 편성 화면은 같은 것을 쓴다. 고객·납품처를 사람이 고르는 것만 다르다.

⚠ **단독 생성분은 ERP 지시서 번호가 비어 있다** — `W-04-04`의 ERP 송신에서 매칭 문제가 될 수 있다. `W-01-11`(신규 P/O 등록)이 같은 형태였다 → §8-3.

### §5-3. ⛔ 시간대 슬롯을 담을 컬럼이 **없다**

WF04 S3 M2와 인벤토리 근거가 「**시간대 슬롯**」을 요구한다. `W-04-02`(출하 예정 목록)의 필터 축이기도 하다.

```
slot · time_slot · ship_time · window   전 파일 검색 0건 (실측)

sales_order_line.requested_delivery_date    date
shipment_request.requested_ship_date        date     ← 둘 다 날짜뿐
```

**A-11로 물러난다.**

| 확정·기대 | 물러난 수준 |
| --- | --- |
| 출하 희망 **시간대** 지정 | **날짜만** 받는다 |
| 시간대별 슬롯 편성·충돌 확인 | ⛔ **불가** |
| `W-04-02` 시간대 필터 | ⛔ **불가** — 날짜 필터로 |

**화면이 그 사실을 말한다** — 「⚠ 시간대는 아직 저장할 자리가 없습니다」를 날짜 입력 옆에 둔다. → §8-1 · **`[docs→데이터모델]` 이슈**.

### §5-4. 「고객 LOT 요구」는 **남이 읽고 판단할 자유 텍스트**다 — A-12

```
customer_lot_requirement   varchar(200)   ← nullable · 형식 없음
```

**여기 적힌 문장을 피킹하는 사람이 읽고 판단한다**(`M-04-01`). 「A사는 제조 3개월 이내만」 같은 조건이 비어 있으면 **현장이 아무 LOT이나 집는다.**

**A-12를 적용한다** — DB가 nullable이어도 **고객·품목 조합에 요구가 있으면 화면이 필수로 만들고**, 예시로 형식을 유도한다.

```
ⓘ 고객이 LOT 에 요구하는 조건을 적어 주세요
   예) 제조 90일 이내 / 동일 LOT 단일 구성 / 앞자리 A 계열 제외
```

⚠ **형식을 강제할 수는 없다** — `varchar(200)`이고 마스터가 없다. **고객별 상용구 마스터**가 있으면 좋겠으나 지금은 없다 → §8-4.

### §5-5. 「가용」은 이 화면이 계산하지 않는다

배정하려면 **지금 출하할 수 있는 재고**를 알아야 한다. 그 값은 `W-04-08`(완제품 재고·Lot Status 조회)이 쓰는 것과 **같은 원천**이다.

| | |
| --- | --- |
| 가용 수량 | 완제품 창고의 그 품목 **가용 잔액** — 예약·피킹·차단분 제외 |
| ⚠ **Release 안 된 것은 가용이 아니다** | 결정 10이 Lot Status를 차단의 단일 지점으로 만들었다 |

**규칙**: 화면이 여러 조회를 조합해 스스로 빼지 않는다 — **계약이 가용 수량을 내려 준다.** 화면마다 다르게 빼면 `W-04-08`과 `M-04-01`이 다른 숫자를 보인다 → §9-2.

### §5-6. 지시서 Import — **파일인가 연계인가**

「Import」가 두 가지로 읽힌다.

| 갈래 | 근거 |
| --- | --- |
| **ERP 연계 수신** | `erp_sales_order_no` 컬럼이 있다 — ERP가 원천인 경로가 설계돼 있다 |
| **엑셀·파일 업로드** | 「Import」라는 낱말 · 고객사가 파일로 보내는 관행 |

**둘 다 성립하고 배타적이지 않다.** 화면은 **연계 수신을 기본**으로 두고(목록에 그냥 나타난다), **파일 업로드를 보조 진입**으로 둔다.

⚠ **파일 업로드의 형식이 정해지지 않았다** — 고객사마다 다르다. **G-9 적용**(파일 업로드는 조합이고 단일 파일만 된다) · → §8-5.

### §5-7. 액션

| 액션 | 활성 조건 |
| --- | --- |
| 조회·필터 | 항상 — 고객·기간·편성 여부 |
| 페이지 이동 | 목록 2쪽 이상 — **G-12** |
| 지시서 선택 | 목록 행 클릭 |
| **지시서 가져오기** | ⚠ **파일 형식 미정**(§5-6) — 비활성 + 사유 |
| **단독 생성** | 항상 — 고객·납품처를 사람이 고른다(§5-2) |
| 라인 추가·삭제 | 단독 생성 시 · 지시서 경유는 라인이 고정 |
| 배정 수량 입력 | **≤ 요청 수량**(§5-1) |
| 출하검사 대상 토글 | 라인마다 |
| **편성** | 라인 ≥ 1 AND 배정 수량 ≥ 1 AND 출하 희망일 입력 |
| 취소 | 항상 — 화면 이탈 |
| 편성 취소 | ⛔ **두지 않는다** — 출하작업지시 취소는 **범위 밖**(FR-IM-079는 출하 취소이고 이것은 그 앞이다) |

## §9. 이 장에서 나온 공유 계약 후보

1. ⭐ **여러 층이 수량으로 물린 문서는 「무엇을 고쳐야 하는지」로 오류를 낸다** — `ck_shipment_request_qty`가 `shipped ≤ allocated ≤ requested`를 강제하는데, 위반 문구가 「제약 위반」이면 사용자가 어느 값을 고칠지 모른다. **넘긴 값과 상한을 함께 적는다.** A-1(유일키 범위를 문구에 담는다)의 **수량 판**이다 (§5-1)
2. **여러 화면이 같은 파생 수량을 보이면 계약이 계산해 내려 준다** — 「가용 수량」을 `W-04-01`·`W-04-08`·`M-04-01`이 다 쓰는데 각자 빼면 **세 화면이 다른 숫자를 보인다.** L-2(파생 값은 서버가 계산한다)의 **횡단 적용**이고, 특히 **무엇을 빼는가**(예약·피킹·차단)를 계약이 정의해야 한다 (§5-5)
3. **선택 FK가 nullable이면 그것이 두 번째 모드의 근거다** — `shipment_request_line.sales_order_line_id`가 nullable이라 「지시서 없이 단독 생성」이 데이터로 이미 성립한다. **미결로 남기기 전에 컬럼의 nullable 여부를 먼저 본다** — `W-01-11`의 `erp_purchase_order_no`가 같은 형태였다 (§5-2)
4. **확정된 업무 축을 담을 컬럼이 없으면 그 축을 화면에 그리지 않는다** — 시간대 슬롯이 프로세스·인벤토리 양쪽에 있는데 저장 자리가 0건이다. **입력란을 두고 안 보내는 것이 가장 나쁘다** — 사용자는 저장됐다고 믿는다. A-11의 **입력 쪽 판** (§5-3)
