## §5. 액션·상태

### §5-1. ⭐ 여기가 genealogy 의 **시작점**이다

제품 LOT 이 만들어지는 것은 생산이지만, **완제품 재고로 서는 것은 여기**다. 그 뒤가 전부 이 LOT 을 가리킨다.

```
M-04-04 제품입고·적치
   ↓ 제품 LOT 이 완제품 창고 재고가 된다
M-04-01 피킹 스캔  →  W-04-03 OQC 판정  →  P-04-01 Packing  →  W-04-04 출하 확정
```

**규칙**: 이 화면이 **인수를 거부하면 그 LOT 은 출하 흐름에 들어오지 않는다.** 그래서 수량 차이·손상을 여기서 기록해야 하는데 — §5-4.

### §5-2. 권장 위치 규칙은 `M-01-05`와 **같다**

`M-01-05` §5-2-1(2026-08-06 사용자 확정)이 세 갈래를 정했고, **제품 입고도 같은 `putaway_task`를 쓰므로 그대로 적용된다.**

| 창고 상태 | 품목 규칙 | 동작 |
| --- | --- | --- |
| 위치 관리 함 | **권장 있음** | ⛔ **그 위치만 허용** |
| 위치 관리 함 | **권장 없음** | ⚠ 확인 후 통과 — 「관리 위치가 없는 품목입니다」 |
| 위치 관리 안 함 | — | 위치 스캔 없음 |

⚠ **완제품 창고에 적치 규칙이 등록돼 있어야 한다** — `W-06-14`가 그 자리다. 비면 둘째 갈래로 떨어져 **검증 없이 통과**한다(G-12).

### §5-3. ⚠ Release 되지 않은 LOT 을 입고할 수 있는가

결정 10이 Lot Status 를 **차단의 단일 지점**으로 만들었다. 그런데 **입고는 차단 대상이 아니다** — 들어오는 것을 막으면 물건이 갈 곳이 없다.

**규칙**: **입고는 허용하고 표시만 한다.**

```
⚠ 이 LOT 은 아직 Release 되지 않았습니다 — 출하·피킹은 막힙니다
```

**막히는 것은 하류다**(`M-04-01` 피킹). 여기서 막으면 **현장이 선다.** `M-01-05`의 「규칙이 없다고 막으면 미등록 품목이 적치를 못 해 현장이 선다」와 같은 판단이다.

### §5-4. ⛔ 인수 수량 차이를 담을 자리가 없다

생산이 500 을 넘겼는데 실물이 498 이면? **`goods_receipt_line`에 차이 컬럼이 없다**(실측 — `shopfloor_receipt_line`에는 `variance_qty`·`variance_reason_code`가 있는데 그것은 **창고 → 현장** 방향이다).

| 방향 | 차이 기록 |
| --- | :-: |
| 창고 → 현장 (`shopfloor_receipt`) | ✅ `variance_qty` GENERATED · `variance_reason_code` |
| **생산 → 창고 (제품 입고)** | ⛔ **없다** |

**A-11로 물러난다** — **입고 수량을 실물대로 받고**(그것이 재고가 된다), 차이는 **`remarks`에 적는다.** 차이 사유 코드는 없다.

⚠ **비대칭이다** — 같은 「인수하며 세어 보니 다르더라」인데 한 방향만 자리가 있다. → §8-1 · **`[docs→데이터모델]` 이슈**.

### §5-5. 오프라인 — **§C 13조항이 걸린다**

결정 17 시나리오 2(입출고 단일 단말 스캔)가 이 화면을 덮는다.

| 조항 | 이 화면 |
| :-: | --- |
| **C-5** 오프라인 허용 여부는 화면 속성 | ✅ **허용** — 창고 안에서 통신이 끊긴다 |
| **C-6** 판정에 쓰이는 값은 캐시 금지 | ⛔ **권장 위치는 캐시해도 되나 Lot Status 는 안 된다** — 결정 10 |
| **C-7** 저장 피드백 2등급 | 오프라인이면 **미확정 표식** |
| **C-8** 멱등키에 영업일까지 | 원장이 `UNIQUE(key, business_date)` |
| **C-9** 큐에 낙관적 잠금 토큰 안 싣는다 | ✅ |
| **C-11** 선행 데이터 명시 | **적치 규칙 · 인수 대기 LOT 목록**을 미리 받는다 |
| **C-12** 단말 시계 오차 | ⬜ **미결** — `receipt_datetime`이 단말 시계다 |
| **C-13** 받는 시점도 적는다 | 교대 시작 시 동기화 |

⚠ **Lot Status 를 캐시하지 않으므로 오프라인에서는 「Release 여부」를 못 보인다.** 그 사실을 화면이 적는다 — 「오프라인: Release 상태를 확인할 수 없습니다」.

## §9. 이 장에서 나온 공유 계약 후보

1. ⭐ **들어오는 것은 막지 않는다 — 막는 것은 하류다** — Release 되지 않은 LOT 도 입고는 허용한다. 여기서 막으면 **물건이 갈 곳이 없어 현장이 선다.** `M-01-05`의 「규칙이 없다고 막으면 미등록 품목이 적치를 못 한다」와 같은 판단이고, **차단 지점을 하류에 두는 것이 결정 10의 취지**다 (§5-3)
2. **같은 행위의 반대 방향에 자리가 있으면 없는 쪽이 결손이다** — 「인수하며 세어 보니 다르더라」가 창고→현장에는 `variance_qty`·`variance_reason_code`로 있는데 **생산→창고에는 없다.** 비대칭 자체가 판정 근거다 — `W-03-02`의 「같은 테이블 안의 비대칭」(§I-33)과 같은 형태 (§5-4)
3. **오프라인에서 캐시하지 않는 값은 「없다」가 아니라 「확인할 수 없다」로 보인다** — C-6이 판정값 캐시를 금지하는데, 화면이 그 자리를 그냥 비우면 **사용자는 Release 안 된 것으로 읽는다.** 「오프라인이라 확인할 수 없습니다」가 정확하다. G-9(모르는 값과 없는 값을 같은 모양으로 그리지 않는다)의 **오프라인 판** (§5-5)
