# 검사자·단말을 「서버가 채우는 값」으로 되돌린다 — 구현팀 질의 omf-mes#173

> 작성일: 2026-08-21 · 작성 주체: CREFLE OMF 팀 (UI/UX)
> 회신: omf-mes#173 코멘트 · 계약 패치: `deliverables/openapi/patch-173-inspector-server-derived.py`

## 무엇

**검사 결과 저장 계약에서 검사자(`inspectorId`)와 단말(`terminalId`)을 뺐다.** 서버가 인증 주체에서 채우는 값이라 화면이 만들 수 없다.

| 대상 | 바뀐 것 |
| --- | --- |
| `InspectionResultCreate` | `inspectorId`(**필수였다**) 제거 · `terminalId` 제거 |
| `InspectionResultUpdate` | `inspectorId` 제거 |
| 응답 `InspectionResult` | ⛔ **건드리지 않았다** — 받는 자리와 보이는 자리는 다른 축이다 |
| 화면 상세 스펙 3장 §4-B | 수입검사 판정(`W-01-01`) · 출하검사 판정(`W-04-03`) · 제품 검사(`P-02-13`) 검사자 행을 **「서버 파생」**으로 |

## 어떻게

### 구현팀이 짚은 것 — 다섯 가지 전부 맞았다

| 주장 | 실측 |
| --- | --- |
| 작업자 번호와 앱 사용자 번호가 다른 공간이다 | ✅ `mdm.worker.worker_id` 는 독립 채번(`GENERATED ALWAYS AS IDENTITY`), `app_user_id` 는 참조 열 — 물리 모델 496·502행 |
| `app_user_id` 가 비어 있을 수 있다 | ✅ `NOT NULL` 없음 |
| `inspectorId` 가 필수다 | ✅ `InspectionResultCreate.required` |
| 세션이 작업자 번호를 안 준다 | ✅ `Session` 은 `userId`·`loginId`·`userName`·`departmentId`·`lastLoginAt`·`scopes`·`roles` 뿐 |
| 작업자 목록을 앱 사용자 번호로 못 좁힌다 | ✅ 질의에 `appUserId` 없음. 응답 `Worker` 는 `appUserId` 를 **싣고 있는데** 그것으로 찾을 수는 없었다 |

⛔ **세션의 `userId` 를 그대로 실었다면 품질 감사 기록에 엉뚱한 사람이 검사자로 박히고, 값이 그럴듯한 정수라 아무도 못 잡는다.** 구현팀이 막아 둔 판단이 옳았다.

### ⭐ 뿌리 — 답이 이미 공유계약에 있었다

**인증 축 조항(F-2)** 은 「누가 한 일로 기록하는가」의 수단이 셸마다 다르다고 이미 못박아 두었다.

| 셸 | 인증 수단 | 「누가 했나」 | 번호 공간 |
| --- | --- | --- | --- |
| 관리웹(`W-` 화면) | 계정 토큰 — 계정 로그인(관리웹 인증 수단 결정 DR-002) | 인증 주체 그 자체 | `app.app_user` |
| 현장 단말·모바일(`P-`·`M-` 화면) | 단말 토큰 — ⭐ **로그인이 없다** | 사번 귀속(`X-Worker-No` 헤더) | `mdm.worker` |

**귀속 조항(D-5)** 은 그 사번을 「쓰기 요청에 **필수**」로 정했다.

⭐ **즉 검사한 사람은 두 셸 모두 서버가 이미 알고 있었다.** 계약이 그 위에 본문으로 한 번 더 받고 있었고, **같은 것을 두 경로가 말하면 어긋날 자리만 생긴다.**

### 실측 둘 — 서버가 채우는 것이 이미 관행이었고 검사 결과만 예외였다

**① 쓰기 본문 148개 전수 — 감사 필드 0건**

```
기준: deliverables/openapi/*.json 7벌의 paths 안 requestBody 가 가리키는
      components.schemas = 148개. 그 안의 «속성 이름»을 센다.
⚠ 안 보는 것: 질의 파라미터 · 응답 스키마 · 경로 파라미터 · 설명문 안의 언급
```

`createdBy`·`updatedBy` 를 본문으로 받는 곳 **0 / 148**. 물리 모델은 **표 129개 중 117개**가 `created_by` 를 갖는데(기준: `^CREATE TABLE` 129 · 열 선언 `created_by` 117) 계약은 한 번도 받지 않는다.

**② 스펙에서 「로그인 사용자」로 표기된 저장 칸 7건 중 본문으로 받는 것은 검사자 2건뿐**

| 화면 | 칸 | 본문으로 받나 |
| --- | --- | :-: |
| `W-01-01` 수입검사 판정 · `W-04-03` 출하검사 판정 | 검사자 | ⛔ **받았다** |
| `P-01-01` 자재 로트 등록 · `P-04-02` 납품 포장 라벨 · `M-01-01` 입하 등록 · `W-05-04` 설비 고장 처리 | 발행자·인수자·처리자 | ✅ 안 받는다 |

⭐ **아래 5건은 저장 경로가 실재하는데도 본문에 그 칸이 없다** — `POST /trace/lots` · `POST /logistics/inbound-receipts` · `POST /maintenance/breakdowns` · `POST /maintenance/breakdowns/{breakdownId}:complete` 를 열어 확인했다.

## 왜

### 「선택으로 낮춘다」가 아니라 「뺐다」

선택으로 남기면 **서버가 무시하는 칸**이 된다. 그러면 누군가 값을 넣어 보내고 서버가 조용히 버린다 — 「내가 보낸 검사자가 안 들어갔다」가 나중에 버그로 온다. **값을 안 쓸 거면 받는 자리를 두지 않는 편이 정직하다.** 「사용처가 0이면 두지 않는다」와 같은 잣대다.

⚠ 검사자와 확정자를 분리하지 않기로 한 확정(#62 · 1차 범위)이 이미 있어 **대리 입력 요구가 0**이다. 필드를 남길 근거가 없다.

### 단말도 같은 성질이다

관리웹에는 단말 개념이 **없고**(인증 축 조항 F-2 에서 단말 토큰의 대상은 현장 단말·모바일뿐), 현장 단말에서는 **요청을 인증한 것이 단말 토큰이므로 서버가 이미 안다.** 물리 모델도 `terminal_id` 를 비울 수 있게 두었다.

### 택하지 않은 안

| 안 | 왜 아닌가 |
| --- | --- |
| **세션에 `workerId` 를 싣는다** | 화면이 그 값을 **다시 본문에 담아 보내야** 하고, 담는 순간 「같은 것을 두 경로가 말한다」로 되돌아간다. 작업자가 연결되지 않은 계정의 사정도 화면이 설명하게 된다 |
| **`GET /mdm/workers` 에 `appUserId` 질의를 더한다** | 로그인마다 조회가 하나 늘고 **그 조회가 실패하면 저장이 통째로 막힌다.** ⛔ 게다가 현장 단말(`P-02-13`)에는 앱 사용자가 없어 **아예 통하지 않는다** — 검사 3형 중 하나를 못 덮는다 |

⭐ **택한 안만 세 화면을 한 번에 덮는다** — 관리웹 둘은 계정 토큰에서, 현장 단말 하나는 사번 귀속에서. 서버가 셸을 알고 있으니 갈라 풀 수 있고, 화면은 셋 다 아무것도 안 보낸다.

## ⚠ 남은 것

### ① `X-Worker-No` 가 계약에 선언돼 있지 않다 — **별건**

귀속 조항(D-5)이 「쓰기 요청에 필수」로 정한 헤더가 **계약 7벌 어디에도 없다**(전수 검색 **0건** · 계약이 선언한 헤더 **18건은 전부 `If-Match` 11 · `Idempotency-Key` 7**). 공유계약·소프트웨어 설계사양서·사번 경량 인증 화면(`P-CO-01`)에만 있다.

⛔ **저장 충돌 보호에서 겪은 것과 같은 형태다** — 토큰을 필수로 받아 놓고 **받을 자리를 선언하지 않아** 구현이 막혔던 19건.

**범위가 검사 밖이라 떼어 놓는다** — 현장 단말·모바일 **39화면**이 부르는 쓰기 경로 전체가 대상이고(요구서 매핑을 훑어야 갈린다), 계약의 쓰기 오퍼레이션은 **218개**(상한)다. ⚠ **우리 소관이고 「회신 대기」가 아니다** — 남을 기다리는 것이 아니라 우리가 할 일이다.

⭐ **관리웹인 `W-01-01` 은 이번 수정만으로 착수 가능하다.**

### ② 작업자가 연결되지 않은 계정의 오류 형태

서버가 못 풀면 저장을 거부한다. **정확한 오류 코드·응답 형태를 아직 못박지 않았다** — 통지문에 「따로 알리겠다」로 적었다. 화면 쪽 안내 문구와 「재시도 버튼을 두지 않는다」는 이미 전달했다.

### ③ 검사자 자격 — 서버가 같은 자리에서 본다

`mdm.worker_qualification` 이 검사자 자격을 관리하고 **자격 만료 시 확정을 제한**하라는 요구(NFR-QM-008)가 있다. **인증 주체에서 작업자를 푸는 자리가 곧 자격을 보는 자리**다. 화면이 번호를 보내는 구조였다면 「보낸 번호의 자격」을 검증하게 돼 축이 어긋났다.

### ④ 이번 건과 무관한 기존 수치 불일치 2건 — 손대지 않았다

`verify-counts.py` 가 잡는다. **둘 다 이 작업 이전부터 갈려 있었다**(실측: `quality-03품질.json` 스키마 수 `origin/main` 29 ↔ 작업분 29 — 이번 수정은 속성만 뺐다).
