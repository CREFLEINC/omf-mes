# 04 제품출하 — 3단계 오프라인 규약

> 작성일: 2026-08-13 · 선행: `02-URL동작규약.md`
> **결론: 04 계약의 오프라인 대상 오퍼레이션 = 0건**

## 1. ⛔⛔ 0단계 가정이 틀렸다

**0단계 §3-1 이 이렇게 적었다.**

> ⚠ **04 는 POP 2 · 모바일 3 이라 오프라인 대상이 있다** — 03(1장)보다 넓다.

**화면 수는 맞는데 결론이 틀렸다.** 다섯 화면의 §5·§6 오프라인 절을 전수로 읽었다.

| 화면 | 오프라인 | 쓰는 테이블 |
| --- | :-: | --- |
| `M-04-01` 제품LOT 피킹 | ⛔ **진입 차단** — 「Release 상태를 확인할 수 없어 피킹할 수 없습니다」(C-6) | **04** `shipment_lot_allocation` |
| `P-04-01` Packing 실적 | ⛔ **온라인 전용** — 매칭 판정이 서버에 있다(C-6) | 01 `handling_unit` |
| `P-04-03` 재작업 실적 | ✅ 허용 — 판정값을 쓰지 않는다(C-14) | **02** `production_result` |
| `M-04-03` 포장 재구성 | ✅ 허용 | **01** `handling_unit`·`lot_relation` |
| `M-04-04` 제품입고·적치 | ✅ 허용 — 창고 안에서 통신이 끊긴다(C-5) | **01** `goods_receipt`·`putaway_task` |

### 1-1. ⭐ 두 줄이 정확히 엇갈린다

```
04 테이블을 쓰는 현장 화면    M-04-01  하나뿐   →  ⛔ 오프라인 진입 차단
오프라인을 허용하는 화면      셋        →  전부 남의 테이블(01·02)
```

⛔ **그래서 04 계약에 `IfMatchVersionOptional` 이 0건이다.**

⚠ **「POP·모바일이 몇 장인가」로 오프라인 표면을 세면 틀린다** — **어느 테이블에 쓰는가**를 봐야 한다.

## 2. 왜 04 의 쓰기가 오프라인이 아닌가 — **판정값에 기대기 때문**

**C-6** 이 「판정값은 캐시하지 않는다」이고, 04 의 두 현장 쓰기가 **정확히 판정값을 읽어야 한다.**

| 화면 | 무엇을 판정하나 | 근거 |
| --- | --- | --- |
| `M-04-01` 피킹 확정 | **LOT 이 Release 인가** — 보류·불량이면 피킹하면 안 된다 | 결정 10 「차단 판정 단일 지점」 |
| `P-04-01` 포장 확정 | **납품라벨 ↔ 생산LOT 매칭이 맞나** | 서버가 배분을 안다 |

⭐ **결정 10 이 여기서 값을 한다** — 「출고·출하·Picking **차단 판정은 Lot Status 단일 지점**」이라 캐시로 대신할 수 없다.

⚠ **`P-04-03`·`M-04-03`·`M-04-04` 가 허용되는 이유가 대칭이다** — 셋 다 **판정을 읽지 않고 기록만** 한다(실적·재구성·입고).

## 3. 그래서 이 단계가 하는 일 — **셋**

### 3-1. 04 계약 — 오프라인 파라미터를 **붙이지 않는다**

```
쓰기 오퍼레이션 7건 전부
    Idempotency-Key   ✅ 필수 (C-1 — 재전송 중복 방지는 온라인에도 필요하다)
    If-Match          ✅ required  (⛔ Optional 아님)
    202               ⛔ 없다      (2026-08-12 철회)
```

⚠ **멱등키는 그대로 필수다** — 오프라인이 아니어도 **재전송·중복 클릭**이 있다. C-1 의 근거는 큐가 아니라 중복이다.

### 3-2. ⛔ `M-04-01` 의 진입 차단을 계약이 **거들지 않는다**

화면이 「진입 차단」으로 물러났으므로 **계약은 온라인 경로만 낸다.** 오프라인용 대체 경로를 만들지 않는다.

⚠ **캐시된 Release 로 통과시키는 우회를 두지 않는다** — 그러면 **실물이 이미 라인에 가 있는데 거부가 오는** C-7 ⓑ 상황이 된다.

### 3-3. ⭐ 남의 오프라인 경로가 성립하는지 확인했다

**04 의 오프라인 화면 셋이 부르는 경로가 실제로 오프라인 대상인지** 상대 계약에서 실측했다.

| 화면 | 부르는 경로 | 상대 계약 |
| --- | --- | :-: |
| `P-04-03` 실적 저장 | **02** `POST /production/production-results` | ✅ `IfMatchVersionOptional` |
| `M-04-04` 입고·적치 | **01** `POST /logistics/goods-receipts` · `putaway-tasks/{id}:complete` | ✅ 둘 다 |
| `M-04-03` 재구성 확정 | **01** `POST /inventory/handling-units` · `…:pack` | ✅ 둘 다 |

⭐ **셋 다 이미 있다.** ⚠ **`:pack` 은 2026-08-12 에 우리가 더한 것**이다(01 계약 결손 보완).

## 4. ⚠ 남는 것 — **#117 이 `M-04-03` 을 반쪽으로 만든다**

`M-04-03` 은 오프라인이 허용되는데 **재구성 이벤트 기록 테이블이 없다**(#117).

```
확정 후 되돌리기 | ⛔ 두지 않는다 — 이벤트 이력이 없어 되돌릴 근거가 없다(§5-2)
```

⭐ **화면이 이미 물러나 있다.** 계약도 **되돌리기 경로를 만들지 않는다.**

⚠ **오프라인에서 확정하면 POP 대기 목록에 안 올라간다** — 화면이 그것을 적는다(C-7 미확정 표식). **계약이 할 일은 없다.**

## 5. 남긴 것 — 4단계로

| # | 무엇 |
| :-: | --- |
| 1 | 쓰기 7건 전부 `IfMatchVersion`(**required**) · 멱등키 필수 · **202 없음** |
| 2 | `ConflictResponse.code` 를 04 에 맞게 — 출하 확정·취소의 상태 충돌 |
| 3 | ⭐ **공유 스칼라 오염 가드**(03 Blocker) — 처음부터 넣는다 |
