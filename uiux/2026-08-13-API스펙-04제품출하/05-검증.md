## 1. 세 축 — 전건 통과

```
verify-ui-coverage.py     --domain 04   화면 16 · 액션 147   ⚠ 표 없는 화면 없다

```

⭐ **전 요구서 인용 283/283** — 04 를 더해도 허공이 0건이다.

### 1-1. ⭐ 계수를 **한 번 고쳤다**

| 트랙 | 계수 정정 |
| :-: | :-: |
| 01 | 2회 · 02 | 4회 |
| 03 | **0회** |
| **04** | **1회** — 경로 15 → 16 |

**2단계가 `P-04-01` §4-C 의 「배분 읽기·갱신」에서 갱신을 흘렸다.** 4단계에서 `PUT /logistics/shipment-lot-allocations/{id}` 를 더했다.

⚠ **오퍼레이션 수는 우연히 맞았다**(`POST` 가 빠지고 `PUT` 이 들어와 상쇄) — **계수가 맞은 것을 근거로 삼지 않는다.**

## 2. ⭐ 검사기가 「없다」를 인용으로 셌다 — 표기를 고쳤다

역방향 ②가 처음에 **6건**을 잡았다. 전부 **「이 경로가 없다」를 말하려고 쓴 인용**이었다.

```
⛔ 없다 — POST /inventory/reservations 가 01 계약에 없다
                ↑ 검사기는 살아 있는 인용으로 읽는다
```

⭐ **검사기가 맞다** — 문서가 존재하지 않는 경로를 `METHOD /path` 형태로 적고 있었다. **부재를 말할 때는 그 형태를 쓰지 않는다.**

```
✅ 01 계약의 `/inventory/reservations` 에 쓰기 메서드가 없다 — `GET` 뿐이다
```

⚠ **공통 출력물 요구서의 「채택 안 한 후보안」과 같은 처리**다(2026-08-12).

## 3. ⭐ 적합성 — 그릴 수 있다 12 · 반쪽 1 · 못 그린다 1 · 판단 대기 3

### 3-1. ⛔ 못 그린다 — `M-04-01` 제품LOT 피킹

「피킹 확정」이 `inventory.inventory_reservation` 에 써야 하는데 **01 계약에 쓰기 메서드가 없다**(`GET` 뿐).

⛔ **화면의 유일한 저장 액션**이다. **`W-01-01` 이 03 을 기다렸던 것과 같은 형태.**

⭐ **역방향 ②가 잡은 01 결손 두 번째다** — 앞서 `W-02-10`·`P-02-06`·`P-02-08` 셋이 있었다.

### 3-2. ⏳ 판단 대기 셋 — **진입 목록이 빈다**

`W-04-10`(폐기) · `W-04-11`(재등록) · `P-04-03`(재작업)의 **진입 조건이 처분 결정**인데 **만드는 화면이 116 전체에 0건**이다.

⭐ **화면 골격은 선다** — `EmptyState`. **03 의 `W-03-05` 불량코드 분포와 같은 형태**다.

⚠ **다만 저쪽은 세 보기 중 하나가 비었고 이쪽은 「주 기능」이 빈다** — 그래서 판단 대기로 둔다.

### 3-3. ⚠ 반쪽 — `W-04-08` 완제품 재고 조회

01 `/inventory/balances` 에 **`expiryDate` 축이 없다**(잔액 축이라 LOT 속성이 아니다).

⭐ **03 이 낸 `GET /quality/lot-statuses` 가 LOT 축**이라 **두 경로를 나란히 쓰면 화면이 선다.** 「유효기간 임박」 한 필터만 클라이언트 정렬로 물러난다.

⚠ **03 의 적합성이 04 를 구했다** — 그때 신설한 경로가 여기서 값을 했다.

### 3-4. ⭐ 04 가 낼 것이 0건인 화면 — **셋**

| 화면 | 쓰는 계약 |
| --- | --- |
| `W-04-03` OQC | **03 전부** |
| `W-04-08` 완제품 재고 | **01 + 03** |
| `M-04-04` 제품입고·적치 | **01 + 06** |

⭐ **계약 트랙이 「화면을 덮는다」가 아니라 「빈 곳을 메운다」임이 여기서 가장 뚜렷하다.**

## 4. 역방향 ① — 부르는 화면 0건인 경로 **없다**

16경로 전수. ⚠ **`/quality/disposition-decisions` 둘은 「부르는 화면은 있는데 데이터가 없다」**라 §3-2 로 넘긴다.
