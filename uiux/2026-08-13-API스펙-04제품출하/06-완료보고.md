## 2. ⭐⭐ 이 트랙이 보여 준 것 — **계약은 화면을 덮는 것이 아니라 빈 곳을 메운다**

**16화면 중 셋은 04 경로를 하나도 안 쓴다.**

| 화면 | 쓰는 계약 |
| --- | --- |
| `W-04-03` OQC 출하검사 판정 | **03 품질 전부** |

| `M-04-04` 제품입고·적치 | **01 + 06** |

⭐ **03 이 만든 것이 04 에서 값을 했다** — 검사 3계층 계약이 `W-04-03` 을 통째로 덮었고, `GET /quality/lot-statuses`(03 이 적합성으로 신설한 것)가 `W-04-08` 을 구했다.

## 3. ⛔⛔ 가장 큰 발견 — **처분 판정을 저장하는 화면이 116 전체에 없다**

| 어디 | 무엇이라 적혀 있나 |
| --- | --- |
| **03 요구서** §1-2 | `disposition_decision` → 「**04 제품출하** — `W-04-07`·`P-04-03`」 |
| **`W-04-07`** §5-1 | 「이 화면은 **판정하지 않는다** — 04 는 **의뢰만**」·「만드는 것은 **03**」 |

**「소유는 쓰기를 가진 쪽」으로 풀려니 쓰는 쪽이 없다.** 116화면 액션을 전수로 뽑아 확인했다.

`F04` 정합 확정이 「재작업/폐기 판정은 **03 소관**」이라 했는데 **03 의 다섯 화면에 그 화면이 없다.**

⚠ **`W-04-07` §5-1 이 이미 알고 넘겼다** — 「누가 정하고 누가 반영하는가를 **계약이 갈라야 한다**」. **계약 단계가 왔고 답은 「아무도 안 만든다」였다.**

**막히는 것은 세 화면의 진입 조건**(`W-04-10` 폐기 · `W-04-11` 재등록 · `P-04-03` 재작업).

⛔ **경로를 만들지 않고 읽기만 냈다**(부르는 버튼 0건) + **화면 인벤토리 건으로 올린다.**

## 4. ⛔ 01 계약 결손을 하나 더 찾았다

`M-04-01` 제품LOT 피킹의 「피킹 확정」이 `inventory.inventory_reservation` 에 써야 하는데 **01 계약의 `/inventory/reservations` 에 쓰기 메서드가 없다**(`GET` 뿐).

⭐ **역방향 ②가 잡은 01 결손 두 번째다** — 앞서 `W-02-10`·`P-02-06`·`P-02-08` 셋이 있었다.

⛔ **04 가 만들지 않았다** — 남의 테이블이다. **`M-04-01` 착수 통지 불가.**

## 5. 정정을 **세 번** 했다 — 전부 0~2단계 가정이었다

| # | 어디 | 무엇 |
| :-: | --- | --- |
| **1** | 0단계 → 1단계 | 「출력물이 04 로 미룬 경로 **3건**」 → **1건**. **둘은 01 계약에 이미 있었다** |
| **2** | 0단계 → 3단계 | 「POP 2·모바일 3 이라 오프라인이 03 보다 넓다」 → **04 계약의 오프라인 대상 0건** |
| **3** | 2단계 → 4단계 | 경로 **15 → 16**. `P-04-01` 의 「배분 읽기·**갱신**」에서 갱신을 흘렸다 |

### 5-1. ⭐ 공통점 — **남의 것을 열어 보지 않고 옮겨 적었다**

| | |
| --- | --- |
| 정정 1 | 출력물 요구서의 「04 소관」을 **01 계약을 열지 않고** 옮겼다 |
| 정정 2 | 화면 수로 셌다 — **어느 테이블에 쓰는가**를 안 봤다 |
| 정정 3 | 「읽기·갱신」에서 **읽기만** 봤다 |

⚠ **03 은 계수를 0회 고쳤는데 04 는 3회다.** 04 가 **남의 계약을 다섯 개 쓰기** 때문이고, **그래서 역방향 ②가 이 트랙에서 가장 중요하다**고 0단계에 적었던 것이 맞았다.

## 6. ⭐ 검사기가 「없다」를 인용으로 셌다

역방향 ②가 처음에 6건을 잡았는데 **전부 「이 경로가 없다」를 말하려고 쓴 인용**이었다.

⭐ **검사기가 맞다** — 부재를 말할 때 `METHOD /path` 형태를 쓰면 살아 있는 인용으로 읽힌다. **6곳 표기를 고쳤다.**

```
전 요구서 인용  283 / 283  ✅
```

## 7. ⭐ 03 의 Blocker 를 처음부터 막았다

생성기에 **공유 스칼라 오염 가드**를 넣고 **일부러 오염시켜 종료코드 1 을 확인**했다. 재현도 sha256 으로 확인.

**감사 전건 깨끗** — PATCH 0 · **202 0** · `IfMatchVersionOptional` 참조 0 · example 누락 0 · **설명 누수 0**.
