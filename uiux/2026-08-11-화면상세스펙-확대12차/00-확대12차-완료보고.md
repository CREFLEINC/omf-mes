## 0. 착수 전에 직전 완료보고를 먼저 읽었다 — **11차에서 배운 것**

11차가 「확대 6차 완료보고에 이미 있던 두 건을 다시 발견」해 Major 를 받았다. **그 대책을 이번에 실행했다.**

| 읽은 것 | 12차에 걸린 것 |
| --- | --- |
| **6차** 「모델이 앞선 것」 4건 | ⭐ **3번**(`worker_qualification` 데이터 0건 → 자격 검증 **보류**)이 걸렸다 — `M-05-01` 이 **점검자 자격 게이트를 걸지 않는 근거**로 인용(§8-6) |
| **9차** §7 남긴 것 7건 | ⭐ **6번**(「G-5 터치 타겟 — **POP 착수 전 필수**」)이 걸렸다 — 12차가 **05 첫 POP** 이다. 확인해 보니 **DS #67 이 이미 발행돼 있었다** |
| **11차** §7-1 넘긴 확인 4건 | **2건 해소 · 2건 이월**(§4) |

⭐ **9차가 남긴 것을 11차가 아니라 12차가 받았다** — 「POP 착수 전」이라는 조건이 이번에 성립했기 때문이다. **조건부 이월 항목은 조건이 성립한 차수가 받는다.**

## 2. ⭐⭐ 이 차수의 결론 — **C-14 에 반대쪽이 없었다**

C-14 는 v1.1 에서 「오프라인 가부는 **판정값을 쓰는가**로 정한다」로 확정됐다. **읽는 쪽만 본다.**

```
C-14        이 화면이 판정값을 쓰는가              → 쓰면 오프라인 금지
없던 것     이 화면이 만든 것이 남의 판정 근거인가  → ?
```

**설비 점검 입력이 정확히 후자다.**

```
M-05-01 점검 입력  ──(점검 이력)──▶  P-02-02 작업 전 점검 통제
                                     「주기 내 점검 이력이 있는가」로
                                     작업을 차단·경고·통과 (QA #9)
```

⛔ **오프라인으로 점검하면 서버에 이력이 없다.** 통제 화면은 「점검을 **안 했다**」와 「했는데 **아직 안 올라왔다**」를 구분할 수 없고, **통제 수준이 「차단」이면 점검을 했는데 작업이 막힌다.**

### 2-1. C-15 신설 — 허용하되 셋을 한다

1. **오프라인 입력을 허용**한다 — 막으면 현장이 종이로 돌아간다(현행 그대로다)
2. **미전송 건이 있으면 상시 경고** — ⭐ **무엇에 반영되지 않는지를 이름으로** 적는다(「작업 통제에 반영되지 않습니다」)
3. **C-7 ⓑ 미확정 표식** — ⭐ **ⓑ 의 조건을 넓혔다**: 「실물이 움직인다」 → **「되돌리기 어려운 결과가 남 쪽에서 일어난다」**

⚠ **F-5 의 집행 화면도 알아야 한다** — 「이력 없음」을 「안 함」으로 단정하지 않는다. **5단계(`P-02-02`)가 이것을 받는다.**

## 3. ⭐⭐ C-12 가 v0.7 이래 ⬜ 였는데 12차가 그것을 깨뜨렸다

C-12(발생 시각은 단말 시계에 의존한다)는 **여섯 판 동안 미결**이었다. 미뤄도 됐던 이유가 있다.

| 화면 | 시각이 무엇인가 | 오차의 결과 |
| --- | --- | --- |
| 재고 실사(`M-01-11`) | 언제 셌나 | 몇 분 틀려도 **수량은 맞다** |
| 설비 점검(`M-05-01`) | 주기 내인가 | 몇 분 틀려도 **「오늘 했나」는 맞다** |
| **비가동 실적(`P-05-02`)** | ⛔ **구간의 길이 자체** | **몇 분이 곧 OEE 오차** |

⭐ **가르는 것은 「시각을 기록하는가」와 「시각의 차를 쓰는가」다.**

### 3-1. 규약 넷 — 핵심은 3번

1. ⛔ **화면은 보정하지 않는다** — 작업자가 본 값과 저장된 값이 다르면 **나중에 아무도 설명하지 못한다**
2. **온라인일 때 오차를 재어 보인다** — 1분 이상 차이 나면 헤더 경고
3. ⭐ **저장 시 오차를 함께 보낸다** — `occurred_at`(단말) + **`clock_offset_ms`**
4. **오프라인 구간은 「마지막으로 잰 값」**을 쓰고 그 사실도 보낸다

**3번이 없으면 서버가 영영 보정 못 한다.** 지금까지 화면은 `occurred_at` 만 보냈다.

| **2** | 점검 항목 표시 순서 | ⚠ **이월** — 현행 일상점검표 실물이 있어야 확정된다(WF05 S2 [Check]). 화면은 순서대로 그린다 |
| **3** | 누계타발수 리셋 시점·권한 | ⚠ **이월(3단계 `W-05-03`)** — ⭐ **다만 제약이 하나 늘었다**: **증분 가산 구조(B-18)에서 리셋을 음수 증분으로 처리하면 이력이 「-412,300 회 사용」으로 남는다.** 별도 행위여야 한다 |

## 5. 신규 조항 6건

| 조항 | 무엇 | 계기 |
| :-: | --- | --- |
| **C-15** ⭐⭐ | **내가 만든 것이 남의 판정 근거인가** | 오프라인 점검이 작업 통제를 오판시킨다 |
| **B-18** ⭐⭐ | **누적 컬럼은 증분으로 보낸다** | 오프라인 큐 덮어쓰기가 앞의 입력을 지운다 |
| **A-17** | 파생값을 저장할지는 **질문 둘**로 정한다 | 점검 종합 판정을 저장할까 |
| **C-16** | 한 건의 **부분 전송** — 급한 것 먼저 | 고장 보고 본문 vs 사진 3장 |
| **C-17** | 오프라인 집계는 **「내가 아는 만큼」** | POP 두 화면에서 같은 형태 |
| **G-16** | **「진행 중」을 상태 컬럼으로 두지 않는다** | 비가동 구간 |

### 5-1. ⭐ B-18 이 막은 것

```
POP-A 오프라인   누계 412,300 을 보고 +1,250 → 413,550 으로 덮음
POP-B 온라인     누계 412,300 에 +800  → 413,100 저장
POP-A 복구 후 전송 → 413,550 으로 덮음   ⛔ POP-B 의 800 이 사라진다
```

⭐ **증분으로 보내면 C-2(오프라인 유일성 거부 규약)가 불필요해진다** — 중복이 들어와도 **합쳐지면 맞다**. **조항 하나가 다른 조항의 부담을 줄인 첫 사례**다.

### 5-2. A-17 은 A-15 를 **뒤집지 않고 경계를 그었다**

A-15(11차 신설)가 「달력이 만드는 변화를 컬럼에 넣지 않는다」로 **한쪽을 막았다.** 점검 종합 판정은 그 질문에 「아니다」로 답한다(라인이 이력 불변).

**②를 더했다 — 「재료가 바뀌면 과거 값이 소급으로 달라지는가」.** 그러면 **저장해서 얼린다.** ⭐ **J-9(결재선)가 이미 같은 결론을 낸 적이 있다** — 그 일반형이다.

## 6. 상류 미결에 답한 것 — **도식 마커 M6**

도식스펙-05 §2.4 의 **M6**(「비가동 N:M」)이 「점검/보전이력 ↔ 비가동 **N:M 연계 구조 미결**(내부 설계)」로 남아 있었다.

**고장과 비가동을 두 기록으로 나누고 N:M 으로 잇는다.**

| 근거 | |
| --- | --- |
| ⭐ **결정적** | **WF05 S4 Rule 이 소유 클러스터를 다르게 지정** — 고장·점검 = **C5** / 비가동 = **C4 품질/현장** |
| 보강 | 단말이 갈렸다 — 고장 **모바일**(#6) / 비가동 **POP**(#7). 한 기록이면 갈릴 이유가 없다 |
| 보강 | 비가동의 다수는 고장이 아니다 — 자재 대기·금형 교체·계획 정지 |

⭐ **「소유 클러스터가 다르면 한 테이블에 담지 않는다」가 11차의 반대 사례와 짝이다** — `W-05-13` 은 **하류 4곳이 두 컬럼으로 갖는다**를 근거로 나눴다. **한쪽은 하류 구조, 한쪽은 소유 클러스터.** 둘 다 **화면의 편의가 아니다.**

## 7. DS — 신규 갭 0건 (12차 연속)

**판정 절차 ①을 명령으로 수행**했고 4장 전부 §7 에 적었다.

### 7-1. ⭐ **G-8 이 POP 에서 처음 실질 제약이 됐다** — `b` 승격 근거 둘째

지금까지 G-8 은 **관리웹 기간 필터에서만** 쓰였다(17화면). `P-05-02` 가 **POP 에서 시각을 입력하는 첫 화면**이다.

| 문제 | |
| --- | --- |
| `type="time"` 네이티브 피커가 **Electron Chromium 버전 종속** | 터치 조작 가능 여부가 버전마다 다르다 |
| **네이티브 피커는 `--control-height-xl` 을 안 따른다** | ⛔ **E-3 터치 규격을 지킬 수 없다** |

**대응** — `[지금]` 버튼을 **기본 경로**로 두고 손 입력을 **보정 경로**로 밀었다.

### 7-2. ⚠ **G-5 72px 급이 POP 2화면의 실질 제약**

9차 §7 이 「G-5 — **POP 착수 전 필수**」로 남긴 것이 여기서 걸렸다. **DS `xl` 60px 로 12px 부족**하고 임시 규약(제품 지정)으로 그렸다. ⭐ **DS #67 이 이미 발행돼 있었다** — 11차 교훈대로 **확인부터 했다.**

### 7-3. 갭으로 올리지 않은 후보 1건

| 후보 | 판정 | 근거 |
| --- | :-: | --- |
| 항목별 카드 목록(`M-05-01`) | ⛔ **갭 아님** | **모바일 360dp 에 기준·측정·판정 3열이 안 들어간다** → `Card` 세로 반복 |

**G-6 6곳**(⭐ 수량형 안에 **큰 정수·천단위** 하위 변형 추가) · G-8 · G-5.

## 8. POP 2화면 — **E-1 세로 예산 둘 다 통과**

```
P-05-01   64 + (96+200+200+88=584 +패딩32=616) + 88 = 768   슬랙 0  ✅
P-05-02   64 + (96+160+200+128=584 +패딩32=616) + 88 = 768  슬랙 0  ✅
```

⭐ **`P-05-02` 는 ① 진행 중 구획이 조건부**다(E-4 규칙 2) — 진행 중 비가동이 없으면 접히고 **96px 이 ④로 간다**(④ 224px). **두 배치 다 584 를 맞춘다.**

⚠ **스크롤 구획** — `P-05-01` 은 **없다**(툴 1건에 실적 1건이라 행이 안 는다) · `P-05-02` 는 **④ 하나**.
