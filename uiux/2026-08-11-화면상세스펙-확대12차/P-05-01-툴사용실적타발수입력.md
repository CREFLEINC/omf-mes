### §3-1. 세로 예산 검산 — **E-1 슬랙 0**


⚠ **E-4 적용** — **스크롤 구획은 두지 않는다.** 이 화면은 **툴 1건에 타발수 1건**이라 행이 늘지 않는다. ④ 안내는 **오프라인·경고 시 문구가 길어지므로** 88px 을 고정 확보한다(접지 않는다 — 경고가 접히면 안 보인다).

⚠ **G-5 터치 규격** — ② 숫자 키패드 버튼은 **핵심 등급 64~72px**, 액션바는 **72px 급**(E-3). **DS `xl` 이 60px 이라 12px 부족** — 임시 규약대로 **제품 측 지정**(DS #67 요청 중).

### §3-2. ⭐ 왜 누계를 **③에서 미리 보이는가**

WF05 S7 이 「누계타발수 집계 → **사용가능타수 산출**」을 이 단계의 결과로 적었고, Pain 이 「적정타수 초과를 **모르고 가동**(불량·금형 파손 위험)」이다. **저장 후 얼마나 남는지를 저장 전에 보여야** 작업자가 판단한다.

⛔ **그런데 이 화면이 누계를 계산해 저장하지 않는다** — 서버가 더한다(§5-2). ④가 그 사실을 명시하는 이유다.

### §5-2. ⛔ 누계는 **서버가 더한다** — 화면이 치환하지 않는다

11차 `W-05-13` §5-2 가 `current_shot_count` 를 **마스터 화면에서 읽기 전용**으로 잠갔다. **이 화면이 그 값을 바꾸는 주체**인데, **방식이 중요하다.**

| ⛔ 하지 않는 것 | ✅ 하는 것 |
| --- | --- |
| 화면이 `413,550` 을 계산해 **그 값으로 덮는다** | 화면은 **`+1,250` 만 보낸다** · 서버가 현재 값에 더한다 |

**왜** — POP 이 여럿이고 오프라인 큐가 있다. **덮어쓰기면 나중에 도착한 것이 앞의 것을 지운다.**

```
POP-A 오프라인   누계 412,300 을 보고 +1,250 → 413,550 으로 덮음
POP-B 온라인     누계 412,300 에 +800  → 413,100 저장
POP-A 복구 후 전송 → 413,550 으로 덮음   ⛔ POP-B 의 800 이 사라진다
```

⭐ **이것이 B-13(한 컬럼을 여러 경로가 바꾸면 「누가 정하고 누가 반영하는가」를 가른다)의 구체형**이다 — **정하는 것은 화면(증분), 반영하는 것은 서버(누적).**

⚠ **낙관적 잠금(B-1)을 쓰지 않는다** — 증분 가산은 순서가 상관없고, `version_no` 를 걸면 **동시 입력이 서로를 거부**한다. **C-9**(오프라인 큐 전송에는 낙관적 잠금 토큰을 싣지 않는다)와 같은 취지가 온라인에도 적용되는 자리다. → §9-1

### §5-3. ⭐ 적정타수가 비면 — **G-15 첫 소비처**

11차가 신설한 **G-15**(비어 있으면 판정이 안 서는 필드는 저장을 막지 말고 목록에서 보인다)가 그대로 걸린다.

| 적정타수 | ③ 구획 표시 |
| --- | --- |
| 있다 | 사용 가능 `86,450 회` + `Progress` 82.7% |
| **비었다** | **「적정타수 미등록 — 사용 가능 타수를 산출할 수 없습니다」** · `Progress` **그리지 않는다** |

⛔ **저장을 막지 않는다**(G-15 규칙 1) — 타발수 기록 자체는 남아야 하고, 적정타수는 `W-05-13` 에서 나중에 채우면 **누계가 이미 쌓여 있으므로 바로 산출된다.**

⛔ **`Progress` 를 0% 로 그리지 않는다**(G-15 규칙 2 · G-9) — 「다 썼다」로 읽힌다.

### §5-4. 환산은 **이 화면이 정하지 않는다**

QA #12 가 「생산 수량 기반 환산은 **사용 여부 선택형** + 수량 대비 타발수 비율 설정」을 확정했고, **비율을 설정하는 화면은 `W-05-01`**(웹-타발수환산-파라미터설정)이다.

| 이 화면 | `W-05-01` |
| --- | --- |
| 환산을 **쓸지 말지 고른다** · 수량을 넣는다 | **비율을 정한다** |

⚠ **11차 `W-05-13` §8-8 이 남긴 것** — 「캐비티 수는 `W-05-13` 에 있고 비율은 `W-05-01` 에 있어 **두 화면이 한 계산의 입력을 나눠 갖는다**」. **이 화면이 그 계산을 실행하는 자리**다.

**비율이 설정돼 있지 않으면 환산 옵션을 비활성**하고 사유를 보인다(G-2·G-3) — 「환산 비율이 설정돼 있지 않습니다(타발수 환산 파라미터 설정)」.

### §5-5. ⚠ 「작업실적 : 툴사용실적 = N:1」 이 모호하다

WF05 S7 Open-Issue 가 「작업실적:툴사용실적 **N:1** 확정(QA #12)」이라 적었고 MES-3 은 「**작업실적 1건당 기록(N:1)**」이라 적었다. **두 문장이 방향을 반대로 읽히게 한다.**

**화면은 안전한 쪽으로 그린다** — **작업지시 1건 + 툴 1건 = 실적 1건**, 한 작업에 툴이 여럿이면 **툴마다 한 건씩** 입력한다.

⚠ **어느 방향이어도 이 화면은 성립한다.** 카디널리티는 **집계 화면(`W-05-02` 툴보전오더 생성)이 확정**한다 — 거기서 「한 작업의 타발수를 어떻게 세는가」가 실제로 걸린다. → §8-3

### §6-2. 오프라인 — **허용 · 다만 누계를 보이지 않는다**

**QA #32 확정**: POP **로컬 버퍼링 + 복구 시 자동 동기화**. **C-14 기준으로도 허용**이다 — 초과 판정은 **경고이지 차단이 아니다**(§6-1).

⛔ **그런데 ③ 누계 구획이 오프라인에서 위험하다.**

**C-6**(오프라인에서 조회는 캐시를 보이되 **판정에 쓰이는 값은 캐시하지 않는다**)의 응용이다. 누계는 **다른 POP 도 동시에 더하고 있다.**

```
오프라인 POP    캐시 누계 412,300 + 내 입력 1,250 = 413,550 으로 표시
실제 서버       그 사이 다른 단말이 +3,000 → 415,300
                → 화면이 보인 「사용 가능 86,450」이 실제로는 83,450
```

**확정 — 오프라인에서 ③ 구획을 이렇게 바꾼다.**

| | 온라인 | **오프라인** |
| --- | --- | --- |
| 누계 | `412,300 회` (기준 시각 표시) | **`412,300 회` + 「08-11 09:40 기준 · 이후 다른 단말 입력분 미반영」** |
| 저장 후 누계 | `413,550 회` | ⛔ **보이지 않는다** |
| 사용 가능 | `86,450 회` + `Progress` | ⛔ **「연결 후 확인」** · `Progress` **그리지 않는다** |

⭐ **G-15·G-9 와 같은 원리다** — **모르는 값을 그럴듯한 숫자로 그리지 않는다.**

⚠ **입력 자체는 막지 않는다** — 타발수는 **작업자가 아는 값**(생산 수량)이고 누계와 무관하게 기록돼야 한다.

**C-11 선행 데이터**

**C-2 오프라인 유일성** — 같은 툴·같은 W/O 에 두 건이 들어올 수 있다. **거부하지 않는다** — 한 작업에서 여러 번 나눠 기입하는 것이 정상이고, **증분 가산이라 합쳐지면 맞다**(§5-2).

## §9. 이 장에서 나온 공유 계약 후보

### 9-1. ⭐⭐ **누적 컬럼은 「덮어쓰기」가 아니라 「증분」으로 보낸다**

B-13 은 「한 컬럼을 여러 경로가 바꾸면 **누가 정하고 누가 반영하는가**를 가른다」인데, **반영 방식**을 정하지 않았다.

**규칙안 — 누적되는 값(`current_shot_count`·재고 수량·집계 카운터)에 대해**

1. **화면은 증분만 보낸다** — `+1,250`. 계산된 최종값을 보내지 않는다
2. **서버가 현재 값에 더한다** — 순서가 상관없어진다
3. ⛔ **낙관적 잠금을 걸지 않는다** — 증분 가산에 `version_no` 를 걸면 **동시 입력이 서로를 거부**한다(C-9 가 오프라인에 대해 이미 같은 결론)
4. **화면이 보이는 「저장 후 값」은 예상치**임을 명시한다

**왜 계약인가** — 이 규칙이 없으면 **오프라인 큐가 앞의 입력을 지운다**(§5-2 의 3줄 예시). 그리고 **C-2 오프라인 유일성 거부 규약이 불필요**해진다 — 중복이 들어와도 합쳐지면 맞다.

⚠ **리셋은 증분이 아니다**(§8-2) — 음수 증분으로 처리하면 이력이 「-412,300 회 사용」으로 남는다. **별도 행위로 둔다.**

### 9-2. **`terminal_process` 8플래그가 05 도메인을 덮지 않는다**

F-1 이 「8플래그를 액션 활성 조건으로 쓴다」이고 「생산·품질 단말 한정」으로 범위가 정정돼 있다. **05 의 POP 화면 둘이 그 8종에 해당 플래그를 못 찾는다.**

| 화면 | 잠정 포섭 |
| --- | --- |
| `P-05-01` 툴 사용실적 | `can_input_result` |
| `P-05-02` 비가동 실적 | `can_input_result` |

**규칙안**: 새 도메인의 단말 액션이 8플래그에 없으면 **① 기존 플래그에 포섭되는지 먼저 보고 ② 포섭 근거를 스펙에 적고 ③ 포섭이 억지면 플래그 추가를 요청**한다.

⚠ **지금은 ①로 갔다** — 「실적 입력」이 생산 실적만 뜻하는지 확인이 필요하다. **플래그를 늘리는 것은 단말 설정 화면(`W-CO-06`)에 체크박스가 느는 일**이라 가볍지 않다.

### 9-3. **오프라인에서 「합계」를 보이지 않는다 — 내 몫만 보인다**

C-6 은 「판정에 쓰이는 값은 캐시하지 않는다」이고, **누계는 판정값이 아니라 표시값**이라 캐시해도 될 것처럼 보인다. **그런데 위험하다** — 다른 단말이 동시에 더한다.

**규칙안**: 오프라인에서 **여러 단말이 동시에 기여하는 합계**는

1. **마지막 동기 값 + 기준 시각**을 보인다
2. **「이후 다른 단말 입력분 미반영」**을 함께 적는다
3. ⛔ **합계를 재계산해 보이지 않는다** — 「저장 후 누계」·비율·잔량
4. **내 입력분은 보인다** — 그것은 확실하다

**해당 후보**: 툴 누계타발수(이 화면) · 재고 수량 · W/O 진척률 · 비가동 누계 시간.
