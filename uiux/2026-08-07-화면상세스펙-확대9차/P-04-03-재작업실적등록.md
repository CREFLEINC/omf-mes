## §5. 액션·상태

### §5-1. ⭐ 재작업이 **어디서 왔는지**를 세 갈래로 가리킨다

```
work_order.rework_source_work_order_id      원본 작업지시
work_order.rework_source_lot_id             원본 생산 LOT
work_order.rework_source_nonconformance_id  ⭐ 원본 부적합
```

**셋 다 late FK 이고 nullable 이다.** 어느 것이 채워지는지가 **재작업의 성격**을 가른다.

| 재작업 원천 | 채워지는 것 |
| --- | --- |
| 생산 중 불량 | 원본 W/O · 원본 LOT |
| **반품 재작업** | ⭐ **부적합** — W/O 는 **없다**(반품은 W/O 없이 온다) |

**이 화면은 반품 재작업을 다루므로** 화면 상단에 **부적합 내용을 보인다** — 작업자가 「무엇을 고쳐야 하는지」를 그 문장에서 읽는다(`W-04-07` §5-3 이 형식을 유도한 이유다).

### §5-2. ⚠ 「재작업 수량」이 여기서 **0 이다** — 헷갈리는 자리

```
production_result.rework_qty   app.qty_t NOT NULL DEFAULT 0
```

**`rework_qty` 는 「이 실적에서 재작업으로 돌린 수량」**이다. **이 화면은 재작업을 하는 화면**이므로 **여기서 다시 재작업으로 돌리지 않는다.**

```
⛔ 잘못된 이해   재작업 실적이니까 rework_qty 에 160 을 넣는다
✅ 옳은 이해     재작업 결과를 양품·불량·보류·폐기로 가른다. rework_qty = 0
```

**화면이 그것을 말한다** — 「재작업 후 다시 불량이면 **「불량」**입니다 — 재작업 수량이 아닙니다」.

⚠ **재재작업이 필요하면** 그때 `rework_qty` 를 쓴다. 다만 **반복 재작업 정책이 정해지지 않았다** → §8-3.

### §5-3. 수량 다섯의 합을 **DB 가 강제한다**

```sql
CHECK (good_qty + defect_qty + hold_qty + scrap_qty + rework_qty > 0)
```

⚠ **「합계 = 대상 수량」이 아니라 「합계 > 0」이다** — 검사 결과(`ck_inspection_result_qty`)와 **다르다.**

| | 검사(`inspection_result`) | **생산 실적(`production_result`)** |
| --- | --- | --- |
| 제약 | 합계 **= 검사 수량** | 합계 **> 0** |
| 뜻 | 전량이 분류돼야 한다 | **부분 실적이 정상**이다 |

**화면은 「합계 = 처분 수량」을 권고하되 강제하지 않는다** — 재작업이 여러 번에 나눠 끝나는 것이 정상이다. ④ 진행 구획이 누계를 보인다.

⚠ **불량 > 0 이면 불량 코드가 필수다**(결정 09) — DB 가 강제하지 않으므로 **화면 책임**이다(A-9 ⓐ).

### §5-4. 결과 LOT — **새로 만들지 않는다**

`W-04-06`·`W-04-11` 과 같은 판단이다. **재작업은 같은 물건을 고치는 것**이므로 LOT 이 갈리지 않는다.

```
양품 150  →  원 LOT 유지 · Lot Status 가 풀린다(03 소관)
불량 8    →  원 LOT 에 남고 Hold 유지
```

⚠ **선별과 다르다** — 선별(`sorting_result`)은 `good_lot_id`·`defect_lot_id` 로 **LOT 을 가른다.** 재작업은 안 가른다. **컬럼이 그 차이를 말한다.**

## §9. 이 장에서 나온 공유 계약 후보

1. ⭐ **같은 이름의 수량 컬럼이 화면마다 다른 것을 뜻하면 화면이 그것을 적는다** — `rework_qty` 는 「재작업으로 **돌린** 수량」인데 **재작업 실적 화면**에서는 0 이다(여기서 다시 돌리지 않으므로). **이름만 보고 채우면 틀린다** — 「재작업 후 다시 불량이면 불량입니다」를 입력란 옆에 적는다. A-8(수치 컬럼 저장 단위)의 **의미 판** (§5-2)
2. **합계 제약이 「= 대상」인가 「> 0」인가가 부분 처리 허용 여부를 말한다** — 검사(`= 검사 수량`)는 전량 분류를 요구하고 생산 실적(`> 0`)은 **부분 실적을 허용한다.** 화면이 그것을 뒤집으면(합계를 강제하면) **여러 번에 나눠 끝내는 정상 운용이 막힌다.** 제약의 형태가 업무 규칙을 말한다 (§5-3)
3. **LOT 이 갈리는가 아닌가를 컬럼이 말한다** — 선별(`sorting_result`)은 `good_lot_id`·`defect_lot_id` 를 갖고 **재작업은 안 갖는다.** 「새 LOT 을 만들 것인가」를 화면이 판단하지 않고 **모델이 이미 답을 갖고 있다** — A-13(한 층 아래를 본다)의 적용례 (§5-4)
