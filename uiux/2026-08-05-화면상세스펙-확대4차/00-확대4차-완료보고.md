## 3. 가장 큰 발견 셋

### 3-1. ⛔ 「캐시 없이 판정」과 「오프라인 허용」이 한 화면에서 동시에 성립하지 않는다

```
결정 10   출고·출하·Picking 차단 판정은 Lot Status 단일 지점 참조 · 캐시 없음
C-1       로컬 저장 후 즉시 성공 피드백 — 통신을 기다리지 않는다
```

**둘 다 확정이다.** 오프라인은 서버를 볼 수 없다는 뜻이고, 「캐시 없음」은 서버를 봐야만 한다는 뜻이다.

게다가 **볼 대상이 없다** — §I-11이 이미 기록한 대로 **Lot Status 현재 상태 테이블이 물리 모델에 없다**(실재하는 것은 `trace.lot_hold` 보류 이력뿐). 3차까지 대장에만 있던 항목이 **4차에서 처음 화면을 막았다.**

**해법** — C-2가 유일성 판정에 쓴 구조(로컬 선검사 → 서버 확정 → **건별 되돌리기**)를 보류 판정에 그대로 쓰고, 대가로 **C-7의 「미확정 표식」**을 도입했다. 근거는 **결정 17 시나리오 2**가 오프라인 출고를 전제한다는 것이다 — 출고를 오프라인 금지로 하면 그 확정이 무너진다.

⚠ **남는 대가**: 거부가 오면 **실물이 이미 라인에 가 있다.** 회수 지시 화면이 인벤토리에 없다(§4-1).

**20번은 요청 형태가 명확하다** — `quality.sorting_result`가 이 화면이 필요로 하는 모양을 **정확히** 갖고 있다(`started_at` NOT NULL / `ended_at` nullable / `worker_id` / `status_code` / `good_lot_id`·`defect_lot_id`). **「선별과 같은 모양으로 재작업용을 하나」**라고 요청할 수 있다.

### 3-3. A-10 다형 참조가 5곳이 아니라 **전수 16쌍**이었다

v0.5의 「실측 5곳」은 **확대 2차가 만진 범위만** 센 것이었다. 4차에서 전수 조사한 결과 **16쌍 / 15테이블이고 전부 `bigint NOT NULL`에 FK가 없다.**

⚠ **그중 `inventory.inventory_transaction`이 있다.** 재고를 움직이는 **모든 화면**이 이 테이블을 지나므로, 대응표가 없으면 **수불 원장의 원천을 되짚을 수 없다.** #68(`audit_event` 사용 규약)과 같은 문제라 함께 정해야 한다.

## 5. 반대로 — **모델이 화면 설계보다 앞선 곳 5건**

확대 2차에서 8건 나왔던 성격이 4차에도 있다. **예외 카탈로그를 볼 때 물리 모델을 먼저 대조해야 한다**는 2차 교훈이 다시 확인됐다.

| 확정·예외가 미정으로 둔 것 | 모델의 실측 | 화면 |
| --- | --- | --- |
| REQ-OA-0001 「적치 Location **안내**」 | `recommended_location_id` + **`applied_putaway_rule_id`**(권장 근거 역참조) + `putaway_rule` 마스터 | `M-01-05` |
| QA #28 「선출=**품목별**」 | **`item.fifo_policy_code`** DEFAULT `'FIFO'` + `shelf_life_days` + `lot.expiry_date` | `M-01-08` |
| 예외 E-6 ③ 「**LOT 미지정 출고** 🟠」 | `picking_line.lot_id`·`goods_issue_line.lot_id` **NOT NULL** — 이미 막혀 있다 | `M-01-08` |
| 예외 E-11 ① 「수량 상이 — **차단? 반송?**」 | **`ck_shopfloor_receipt_qty CHECK (received ≤ issued)`** — 초과는 차단으로 정해져 있다 | `M-01-09` |
| QA #16 「**파렛트=이동 그룹핑**(재고 잠금 단위 아님)」 | `handling_unit` + `handling_unit_content` — **잔액을 갖지 않는다.** 확정 그대로 | `M-01-10` |

> **차수 성격에 대한 정정** — 「1·3차는 확정이 못 착지 / 2차는 모델이 앞섬」으로 정리했는데, **4차는 둘이 같이 나왔다**(불일치 5 · 앞섬 5). **도메인이 아니라 화면 유형에 따라 갈린다** — 기준정보·마스터는 확정이 못 따라가고, **트랜잭션은 모델이 앞선다.** 4차는 재고 트랜잭션(앞섬)과 신개념(호퍼·수리)이 섞였다.
