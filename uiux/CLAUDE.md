# omf-mes UI/UX 작업 폴더

omf-mes 사용자 프로그램(관리웹·POP·모바일)의 UI/UX 작업 산출물을 정리하는 폴더다. 작성 주체: CREFLE OMF 팀.
**모든 산출물은 내부 대외비다** — 외부 서비스에 업로드·공유·게시하지 않는다(docs/와 동일).

## ⭐ 절대 규칙 — 설계 소관과 보고 방식 (사용자 확정 2026-08-13)

> **네 가지다. 넷 다 이번 트랙에서 실제로 어겨서 못박는다.**
> ⚠ **규칙을 아는 것으로는 안 막힌다** — 아래 1·2번은 이미 메모리에 있었는데도 어겼다.
> 그래서 **기계로 볼 수 있는 것은 검사기**로 둔다 → `.claude/skills/uiux-design/`

### 규칙 1 — 데이터 모델링과 설계는 **역할이 다르다**

| 무엇 | 누가 |
| --- | --- |
| 화면이 무엇을 보여 주고 무엇을 저장하는가 | ⭐ **우리(설계)** |
| 그것을 담을 컬럼·제약·무결성 | **데이터 모델링·백엔드** |
| 응용 프로그램 인터페이스 규약(계약) | ⭐ **우리** — 백엔드 공식 범위가 데이터 모델링까지라서다 |

**어긴 사례** — 데이터 모델 담당에게 낸 요청을 **「회신 대기」**라 적었다. 그것은 **남의 작업**이고 우리를 막지 않는다.

⭐ **표기를 가른다** — 「회신 대기」는 **팀 리더·고객 확정**처럼 **답이 와야 다음이 되는 것**에만 쓴다. 데이터 모델 요청은 **「작업 통지 · 우리 차단 없음」**이다.

### 규칙 2 — 데이터 모델은 **「타입·길이」만 준다** *(2026-08-18 강화)*

**설계가 먼저 정하고 데이터 모델이 따라온다.** 물리 모델의 현재 상태를 이유로 **설계나 계약을 물러서지 않는다.**

> ⛔⛔ **사용자 확정 2026-08-18** — 「**데이터 모델링은 설계 결정을 앞설 수 없다.**」
> **무엇을 받나 · 필수인가 선택인가 · 어떤 값이 오나**는 **설계가 정한다.** 모델에서 가져오는 것은 **타입·길이뿐**이다(§설계 문서 지도).

**어긴 사례 셋** *(전부 실측)*

| 어디 | 무슨 일이 있었나 |
| --- | --- |
| 폐기 출고 계약 | 도착지가 없는 경우가 성립하는데 **모델이 「비울 수 없음」이니 모델이 바뀐 뒤에 고치자**고 적었다 |
| 작업 실적 등록(`P-02-04`) | 정본이 「회차·교대 **무관**」인데 `NOT NULL` 을 보고 **교대를 필수로** 받아 적어 계약까지 내려갔다 |
| 공정 등록(`W-06-01`) | 결정 07 의 「유효 시작일(**선택**)」을 필수로 뒤집고 **「제약은 하류가 정본」을 원칙으로 적었다** — ⛔ 원칙이 되면 조용히 퍼진다 |

⭐ **셋 다 순서가 거꾸로다.**

**모델이 화면 요구를 못 담으면**

1. **계약은 화면대로 쓴다**
2. 내부 주석에 **모델 결손과 요청 번호**를 적는다
3. 데이터 모델 담당에게 **통지**한다 — 기다리지 않는다

⭐ **선례** — 「담을 코드 컬럼이 아직 없어 비고란으로 저장된다」로 **필드를 유지한 채** 결손만 적어 둔 곳이 이미 있다.

### 규칙 3 — 보고는 **무엇 · 어떻게 · 왜**를 다 적는다

| | |
| --- | --- |
| **무엇** | 바뀐 것·만든 것을 한 줄로 |
| **어떻게** | 방법과 근거(실측 수치·인용 원문) |
| **왜** | 그렇게 한 이유. **택하지 않은 안과 그 이유**를 함께 |

⛔ **수치를 적을 때는 「무엇을 셌는가」를 함께 적는다.** 기준 없는 수치는 재현이 안 되고 결정 근거가 못 된다.

**어긴 사례** — 세 문서가 인용한 「79종 → 51종」이 **기준을 안 남겨 재현되지 않았다.** 다시 세니 다른 값이었다. → **두 번 이상 인용될 수치는 스크립트를 정본으로 둔다.**

### 규칙 4 — **줄임말·기호를 그대로 쓰지 않는다**

**화면 번호 · 조항 번호 · 이슈 번호 · 회신 번호 · 차수 · 업무 약어**를 보고에 쓸 때는 **반드시 뜻을 함께 적는다.**

```
⛔  W-01-06 에 A-10 을 적용하면 E-4 가 풀린다
✅  자재 폐기 화면(W-01-06)에 다형 참조 대응표 조항(A-10)을 적용하면
    폐기 계정 회신 대기(E-4)가 풀린다
```

⭐ **처음 쓰는 낱말은 그 자리에서 푼다.** **뜻을 아는 사람만 아는 말**이 그 대상이다.

| 말 | 그 자리에서 이렇게 푼다 |
| --- | --- |
| **다형**(참조) | 한 칸이 상황에 따라 여러 표를 가리킨다 |
| **멱등** | 같은 요청을 여러 번 보내도 결과가 한 번 보낸 것과 같다 |
| **낙관적 잠금** | 저장할 때 버전을 대조해 남이 먼저 고쳤는지 잡는다 |
| **구간 형** | 「진행 중」을 상태 값이 아니라 **끝 시각이 비어 있음**으로 판정한다 |
| **파생** | 저장하지 않고 그때그때 계산해 낸다 |

**어긴 사례** — 「다형」을 여러 차례 쓰고도 정의한 적이 없어 사용자가 물었다. **설명이 필요한 말을 설명 없이 쓰면 보고가 아니다.**

## 절대 규칙 — docs/ 불가침 (사용자 지시 2026-07-24)

- **uiux 작업은 docs/(기획·설계 문서)의 내용을 직접 변경하지 않는다.** research/·planning/·raw/는 물론 docs/CLAUDE.md·docs/.claude/(하네스) 파일도 포함이다. docs/는 **읽기 전용 참조**다.
- uiux 결과가 **어떤 이유로든** 기획·설계 문서의 수정을 요구하는 경우, 직접 수정하지 않고 **GitHub 이슈를 발행**해 적절한 조치가 취해지도록 한다 (repo: `CREFLEINC/omf-mes`, 제목 접두 `[uiux→docs]` 권장 — 무엇이/왜/어느 문서에 반영돼야 하는지와 근거 경로를 남긴다).
- FigJam 캔버스 작화는 사용자 지시가 있을 때 figjam 하네스 규칙(`docs/.claude/skills/figjam-workflow-diagram` — 클론 킷·v2 페이지 219:4509·매 콜 setCurrentPageAsync)을 따르되, 그로 인해 생기는 **문서 동기화 필요분 역시 이슈로 넘긴다.** 작업 지시서·보고·검토 산출물은 이 폴더에 둔다.

### FigJam 도식 변경의 소관 (사용자 지시 2026-07-29)

도식 작업은 **역할이 파일 위치로 갈리지 않는다.** 위 「docs/ 불가침」은 **문서**에 대한 규칙이고, **캔버스**는 아래처럼 **변경의 성격**으로 가른다.

| 변경 성격 | 소관 | 예 |
| --- | --- | --- |
| **화면 구성** — 어떤 프로그램을 쓰는가 | **uiux 결정이 정본** (docs는 그 결정대로 작화만) | 프로그램 배지 종류·단말 배정·배지 표기 정책 |
| **워크플로우 내용** — 업무 흐름 자체 | **docs가 직접 수정** (이슈 왕복 불요) | 노드·커넥터·라벨·MES 노트·분기·경계 위임 |

- 판정 예: **#40**(배지 3칩) = 화면 구성 → uiux가 `placement-plan.md`에 결정하고 docs가 작화 · **#43**(02-S-B 시제 주석)·**#44**(SC4 행위 노드 신설) = 워크플로우 → **docs 직접 처리**.
- 갈림이 애매하면 **uiux 결정 쪽으로** 본다 — 화면 구성을 docs가 임의로 정하면 화면 목록·IA가 소급으로 흔들린다.
- ⚠ **작성 주체 ≠ 소유**: `2026-07-24-프로그램배지/placement-plan.md`는 **docs 하네스(`figjam-workflow-team`)가 만들어 uiux/로 이관된 뒤 uiux가 유지**하는 혼종 문서다. **위치만 보고 소관을 판단하지 말고 성격으로 가른다.**
- 역방향 이슈가 필요하면 접두 **`[docs→uiux]`** 를 쓴다(`[docs→데이터모델]`과 같은 형태 — 예: 이슈 #49).
- **구현팀에 통지할 것은 접두 `[uiux→client]`** 를 쓰고 **`omf-mes-client` 저장소에 낸다**(2026-08-04 신설). 설계 변경이 이미 만든 코드에 영향을 줄 때가 대상이다 — **개발팀의 작업 트래커가 거기여야 놓치지 않는다.** ⚠ 그 저장소는 **공개**이므로 아래 §반출 경계를 따른다.

### 공개 저장소 반출 경계 (2026-07-31)

**이 저장소(`omf-mes`)는 비공개이지만, 우리 산출물이 흘러가는 저장소 두 곳은 공개다.** 반출 기준이 셋 다 다르므로 **어디로 쓰는지 먼저 확인하고 쓴다.**

| 대상 | 공개 | 제품 용어·화면명·화면 ID | 고객 식별·계약·실 운영값·인프라·이미지 |
| --- | --- | --- | --- |
| **`omf-mes`** (여기 — 설계·기획) | 비공개 | ✅ | ✅ (현행 그대로) |
| **`omf-mes-client`** (클라이언트 구현 모노레포) | **공개** | ✅ 허용 — 제품 자신이라 제품 용어가 있는 게 정상 | ❌ **금지** |
| **`design-system-v2-webui`** (조직 공용 DS) | **공개** | ❌ **금지** — 제품 중립이어야 한다. **컴포넌트의 언어로만** 쓴다 | ❌ 금지 |

- **`omf-mes-client`** = React 코드 1벌 → 셸 3종(브라우저·Electron·Capacitor) 모노레포. `main` 직접 push는 룰셋으로 차단(PR 필수). **상세 규칙은 그 저장소의 `CLAUDE.md`가 정본**이며, 여기서는 「무엇을 반출하면 안 되는가」만 규정한다.
- **금지 항목**: 고객사명·사업장 위치·담당자 실명 · 계약/견적 금액·수량 · **실 운영 값**(실제 사번·품목코드·LOT 번호 — 합성값을 쓴다) · 인프라 정보(IP·호스트·계정·접속 문자열) · 고객사 ERP 스키마 · **비공개 문서 본문의 복사·발췌** · **와이어프레임·화면 캡처·도식 이미지**.
- **커밋 메시지·PR·이슈·주석·테스트 픽스처에도 동일 적용.** 이 저장소를 참조할 때는 내용을 옮기지 말고 **번호만** 적는다 — `설계 근거: omf-mes#42`.

- ⚠ **DS 저장소는 기준이 한 단계 더 엄하다** — 제품 화면명조차 쓰지 않는다. 갭은 「설비 상세의 가동률 추이」가 아니라 「시계열 차트 위 기간 선택기」로 쓴다. 한 제품에 묶이지 않아야 재사용 가능한 컴포넌트가 되기 때문이다(DS `docs/component-requests.md`).
- **되돌릴 수 없다** — 공개 저장소에 push된 것은 비공개 전환·history 재작성 후에도 인덱싱분·포크가 남는다. 의심스러우면 올리지 말고 먼저 묻는다. 실수했다면 조용히 덮지 말고 **즉시 보고**한다.

#### `[uiux→client]` 통지 — **세 종류다** *(2026-08-04 신설 · 2026-08-06 「착수 가능」 추가)*

**⚙ 하네스가 있다 — `.claude/skills/uiux-client-handoff/`.** 폼 6항목을 우리 산출물 어디서 가져오는지(`references/field-sources.md`)와 **발행 전 금지어 검사기**(`scripts/check-issue.py`)를 담고 있다. 이슈를 손으로 짜지 말고 이것을 쓴다.

| 종류 | 뜻 | 발행 |
| :-: | --- | --- |
| **착수 가능** | **화면 하나를 지금 시작해도 된다** | **화면 하나가 준비될 때마다 1건.** 폼 = `.github/ISSUE_TEMPLATE/uiux-ready.yml` · 라벨 `uiux→client`+`ready` |
| **⛔** | **이미 만든 것이 틀린다** — 조항 변경·철회, 경로 삭제, 필드 의미 변경 | **즉시 1건** |
| **⚠** | **새로 만들 것이 생긴다** — 조항·경로·필드 추가. 기존은 안 깨진다 | **차수 마감 때 묶어서 1건** |
| ℹ | 문서만 바뀜 | 내지 않는다 |

**착수 가능의 세 가지 제약** — 규칙 정본은 클라이언트 저장소의 `docs/uiux-handoff.md`다.

1. **한 이슈 = 한 화면.** §8에 **차단 미결이 있으면 발행하지 않는다**(차단은 화면 골격이 바뀐다는 뜻이다)
2. **발행 후 본문을 고치지 않는다** — 시점 기록이다. 바뀌면 ⛔/⚠를 **새 이슈**로 올리고 링크한다
3. **닫는 것은 프론트다.** 우리는 열기만 하고 상태 라벨도 붙이지 않는다
4. ⛔ **창고·위치 마스터 화면(`W-06-07`)과 공정 등록 화면(`W-06-01`)에는 보내지 않는다** — 이미 병합된 화면이라 「착수 가능」으로 오면 닫힌다. ⛔/⚠로 간다

⚠ **CREFLE 표준 `issue-management` 스킬과 규칙이 넷 다르다**(제목·라벨·추적·종료). 이 채널에서는 **하네스가 이긴다** — 근거는 `issue-management` 자신의 「저장소 라벨 컨벤션 우선」·「남의 저장소 이슈를 닫지 않는다」 조항이다.

**본문 구성** — 세 토막이면 된다.

```
## 무엇이 바뀌었나     ← 한두 줄. 화면 ID·제품 용어는 써도 된다
## 코드에 무엇을 해야 하나  ← 구체적으로
## 근거               ← omf-mes 경로만. ※ 비공개 저장소 — 접근 권한 필요
```

⚠ **「근거」에 내용을 옮기지 않는다.** 확정 기록 인용·물리 모델 컬럼 정의·공유계약 조항 원문은 **비공개 문서 발췌**다. **경로만** 적고 개발팀이 열게 한다(그들은 접근 권한이 있다).

#### ⚠ 공개 저장소 이슈는 **쓰고 나서, 발행 전에** 검사한다

2026-08-04 DS 이슈 발행 때 **발행 후에 검사**하다 제품 용어 2건을 흘렸다(`design-system-v2-webui` #43·#45 — 즉시 수정했으나 **수정 이력에는 원문이 남는다**).

**순서를 바꾼다** — 본문 작성 → **금지어 검사** → 발행. 저장소마다 기준이 다르므로 어느 쪽에 내는지 먼저 확인한다.

| 저장소 | 검사할 것 |
| --- | --- |
| `omf-mes-client` | 고객사명 · 실 운영값 · 인프라 · **비공개 문서 발췌** *(화면 ID·제품 용어는 허용)* |
| `design-system-v2-webui` | 위 전부 **+ 제품 용어·화면명·화면 ID** — 컴포넌트의 언어로만 |
