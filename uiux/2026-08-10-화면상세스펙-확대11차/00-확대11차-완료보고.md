## 2. ⭐⭐ 이 차수의 결론 하나 — **A-13 ④ 가 세 장 중 두 장에서 걸렸다**

동결 사유는 「**설비보전이 물리 모델 Scope 밖**」이었고, 그 판정은 **`W-06-08` 예비품 마스터**(2026-08-03)가 내렸다. 사실 자체는 맞았다 — 점검·고장·보전 테이블은 **정말 0건**이다.

**그런데 마스터 3장 중 둘은 이미 있었다.** 이름이 달라서 못 찾았을 뿐이다.

| 화면 | 「없다」고 볼 뻔한 것 | ④ 다른 이름에서 찾은 것 |
| --- | --- | --- |
| **웹-설비설비그룹-마스터**(`W-05-12`) | 설비그룹 테이블 | **`mdm.production_line`** — `parent_line_id`(상위그룹) · `equipment.production_line_id`(1:N) · `line_type_code`(유형). **개념모델 §1 설비그룹과 형태가 같다** |
| **웹-계측기-마스터관리**(`W-05-11`) | 계측기 마스터 | **`mdm.equipment` 가 계측기를 겸한다** — `calibration_required` 주석이 「**[M] 검사장비 교정관리**」이고, 검사 기준(`default_inspection_equipment_id`)·측정치(`inspection_equipment_id`)가 이 테이블을 가리킨다 |

### 2-1. 상류와 하류가 **같은 결론에 이름만 다르게** 도달했다

```
상류 (결정 03)   「라인 개념 필요 시 별도 라인 마스터 대신
                  설비그룹 유형에 '라인' 추가로 흡수」

하류 (H-4)       라인 마스터를 만들고
                  작업구역을 line_type_code 로 흡수
```

**둘 다 「계층형 테이블 하나 + 유형 코드」다.** 담는 그릇이 같고 부르는 이름이 다르다.

### 2-2. 그래서 **원칙 1)로 정의한 것은 셋뿐**이다

| 무엇 | 어느 화면 | 크기 |
| --- | --- | --- |
| 점검·보전 항목 마스터 + 부여 | `W-05-12` | **테이블 2종** |
| 툴 유형 코드(`tool_type_code`) | `W-05-13` | **컬럼 1개** |
| 검교정 주기 · 정밀도 | `W-05-11` | **컬럼 2개** |

**「17장이 테이블 6개군을 요구한다」던 DR-001 §4-A 의 예상보다 훨씬 작다.** 마스터 3장에 한정된 결과지만, **A-13 을 돌리지 않았으면 테이블 3종을 더 요구했을 것이다.**

### 2-3. ⛔ **「없음」 판정도 A-13 4단을 거쳐야 한다**

차수 배치표 v2.0 이 05 를 「없음」으로 세었고, `W-06-08` 이 「설비·툴 관련 테이블은 3개뿐」이라 적었다. **셋 다 맞았다.** 틀린 것은 **그 셋이 무엇을 담을 수 있는지 보지 않은 것**이다.

### 3-1. ⭐ A-15 가 **다른 화면의 묵은 미결을 닫았다**

`W-06-06`(공통코드·조직·작업자 마스터) §8-5 가 2026-08-03 에 이렇게 남겼다.

> 「오늘 유효기간 밖인 코드」와 「사용=끔인 코드」가 둘 다 선택 목록에서 빠져야 하는데, **판정 주체가 화면인지 서버인지 하류에 규칙이 없다**

**A-15 가 그 답이다** — 「아무도 아무것도 하지 않아도 이 값이 바뀌는가?」에 그렇다면 **컬럼에 넣지 않고 서버가 판정한다.** 유효기간·검교정 만료·PM 도래·특채 만료가 전부 같은 형태다.

### 3-2. ⭐ B-16 이 막은 것 — **네 화면이 한 컬럼을 두고 경합**

`mdm.equipment.status_code` 는 `NOT NULL` 인데 값 목록이 없다. 늘리기 쉬운 자리다.

| 넣고 싶어지는 값 | 실제 주인 |
| --- | --- |
| 고장 | 모바일-설비고장-현장보고 → 웹-설비고장-상세처리 |
| 보전중 | 웹-보전지시-발행 → 웹-보전실적-예비품출고등록 |
| 비가동 | POP-비가동실적-입력 → 웹-비가동집계-조회 |
| 검교정 만료 | **달력이 만든다**(A-15) |

**2값(운용/폐기)으로 묶으면 경합 자체가 생기지 않는다.** 「지금 쓸 수 있는가」는 판정식이 답한다.

⚠ **이 판단은 2단계~4단계 화면 13장의 설계 전제**가 된다 — 그 화면들이 마스터를 갱신하지 않고 **자기 트랜잭션에 기록**한다.

### 3-3. ⭐ **F-3 을 충족하는 첫 사례가 나왔다**

F-3(게이트는 판정 근거 컬럼의 실재를 확인해야 성립한다)은 **⚠ 미충족** 표시를 달고 있었다 — 수신본 판정 플래그가 없어서다. **검교정 게이트는 근거 4개가 전부 실재한다.**

```
calibration_required             ✅  이 장비가 대상인가
equipment_calibration.valid_until ✅  언제까지 유효한가
default_inspection_equipment_id  ✅  검사 항목이 어느 장비를 쓰나
inspection_equipment_id          ✅  실제로 어느 장비로 쟀나
```

→ **F-5 신설** — 근거 화면과 집행 화면의 책임을 나눈다.

| :-: | --- |

## 8. 정정 1건 — 「작업 통제 3단계의 설정처 불명」이 틀렸다

**인벤토리 §5 미결 4** 와 **`deliverables/04-통합-IA.md` §미결 4** 가 이렇게 적었다.

⭐ **`app.operation_policy`(SQL 2541)가 실재한다** — `policy_code` + 범위(사업부·공장·품목·공정) + 값(text/numeric/boolean) + 유효기간 + **부분 유일 인덱스**(`COALESCE` — A-7). v3 의 **[E-4] 「운영정책 코드 시드」**로 들어왔다.

⚠ **다만 범위 축에 설비·설비그룹이 없다** — 「설비그룹별 통제 수준」이 필요하면 축이 하나 는다.

**세 판정 중 둘은 그대로 유효하다** — 통제 수준은 설비 속성이 아니고(`W-05-12` 에 두지 않는다), 점검 ≠ 검사다. **틀린 것은 「신설은 항목 1개라 과하다」의 전제**다 — 신설할 필요가 없다.

→ **정정은 이 보고서와 `W-05-12` §8-7 에 남긴다.** 인벤토리 본문 수정은 **#67 회신 때 한 번에**(관문 ③ — 지금 고치면 회신에서 또 만진다).
