# 공통 도메인 API 스펙 — 0단계 설계

> 작성일: 2026-08-13 · 대상 화면 **10장** · 작성 주체: CREFLE OMF 팀 (UI/UX)

---

## §1. 왜 지금 이 트랙인가

**이미 내보낸 착수 통지 79장이 돌아갈 최소 조건이 빠져 있다.**

```
착수 통지 나간 화면          79장   (관리웹 48 · POP 17 · 모바일 14)
클라이언트에 로그인·인증      ⛔ 0건   (auth·login·session 파일 전무 — 실측)
POP·모바일 셸                ⛔ 없음  (apps/web 하나)
그 셸의 진입점               M-CO-01 · P-CO-01 — 계약 없음
```

⭐ **이 트랙은 「하면 좋은 것」이 아니라 「이미 막고 있는 것」이다.** 남은 두 후보(05 설비툴 · 2차 값 목록)는 미뤄도 아무도 막히지 않는다.

### 1-1. 대상 — **10장** *(⚠ 그동안 「8장」이라 세었다)*

공통 12장 중 계약이 있는 것은 둘뿐이다 — `W-CO-02`(기준정보 트랙) · `W-CO-09`(공통 승인 편).

| 화면 | 이름 | 갈래 |
| --- | --- | --- |
| `W-CO-01` | 계정 로그인 | **인증** |
| `W-CO-10` | 비밀번호 변경 | **인증** |
| `P-CO-01` | 사번 경량 인증 *(POP)* | **인증** |
| `M-CO-01` | 기기 등록·사번 인증 *(모바일)* | **인증** |
| `W-CO-03` | 알림센터 | **알림** |
| `W-CO-11` | 알람 수신자 설정 | **알림** |
| `W-CO-04` | 공지·전달 게시/조회 | **공지** |
| `W-CO-06` | 단말기-공정 매핑 설정 | **단말** |
| `W-CO-08` | 창고 적재 위치 배치도 | **배치도** |
| `W-CO-05` | 통합 대시보드(경영·생산) | **집계** |

### 1-2. 차단 미결 — **전 화면 0건**(§8 전수 확인)

10장 모두 스펙 §8 이 「차단 0건」이다. 막는 것은 계약 부재 하나였다.

---

## §2. ⛔ 이 트랙은 계약이 모델보다 크게 앞선다

**7가지가 물리 모델에 없다**(각 스펙이 A-13 4단으로 실측한 결과).

| 없는 것 | 어느 화면이 필요로 하나 |
| --- | --- |
| 비밀번호 해시 · 실패 누적 · 마지막 로그인 시각 | `W-CO-01` · `W-CO-10` |
| 알림 테이블 | `W-CO-03` · `W-CO-05` |
| 알림 수신자 설정 테이블 | `W-CO-11` |
| 공지 테이블 | `W-CO-04` |
| 단말 토큰 세대 · 기기 식별자 | `M-CO-01` · `W-CO-06` |
| 알림 수신처(전화번호) | `W-CO-11` |
| 휴일·계획 정지 자리 | `W-CO-05` |

⭐ **그것을 이유로 계약을 물리지 않는다** — 「데이터 모델은 UI/UX 설계 결정에 맞춰 따라온다」(2026-08-10 확정). 이번 트랙에서 앞서 `M-01-12`(컬럼 하나)와 `P-02-05`(표 하나)를 같은 원칙으로 처리했다. **다르게 다룰 이유가 없다.**

⚠ **다만 규모가 다르다** — 앞의 둘은 하나씩이었고 여기는 일곱이다. 모델 요청을 **한 번에 묶어** 낸다(기준정보 트랙의 §I 방식 — 건건이 물으면 트랙이 멈춘다).

## §3. 리소스 도출 — **어느 계약 파일에 두나**

「소유는 쓰기를 가진 쪽」과 「네임스페이스는 물리 스키마를 따른다」를 함께 적용한다.

### 3-1. `app-공통.json` 에 둘 것 — **인증 · 알림 · 공지 · 집계**

| # | 리소스 | 경로 | 쓰는 화면 |
| :-: | --- | --- | --- |
| 1 | **세션** | `/app/sessions` · `/app/sessions/current` | `W-CO-01` |
| 2 | **내 계정** | `/app/users/me:change-password` | `W-CO-10` |
| 3 | **알림** | `/app/notifications` · `…/{id}:read` · `…:read-all` | `W-CO-03` · `W-CO-05` |
| 4 | **알림 수신자 설정** | `/app/notification-subscriptions` | `W-CO-11` |
| 5 | **공지** | `/app/notices` + `:publish` · `:close` · `:acknowledge` | `W-CO-04` |
| 6 | **대시보드 집계** | `/app/dashboard-summary` | `W-CO-05` |

### 3-2. `mdm-기준정보.json` 에 둘 것 — **단말 · 배치도**

| # | 리소스 | 경로 | 쓰는 화면 |
| :-: | --- | --- | --- |
| 7 | **단말** | `/mdm/terminals` (+ `:issue-token` · `:deactivate`) | `W-CO-06` · `M-CO-01` |
| 8 | **단말-공정 기능 구성** | `/mdm/terminals/{id}/processes` | `W-CO-06` · `P-CO-01` |
| 9 | **창고 배치도** | `/mdm/warehouses/{id}/layout` | `W-CO-08` |

⭐ **실측 — 단말 경로가 0건이다.** `mdm-기준정보.json` 79경로에 `terminal` 이 하나도 없다. `W-CO-06` 이 통째로 신설이다.

✅ **이미 있어서 안 만드는 것** — 작업자 조회(`/mdm/workers`)는 `P-CO-01` 이 그대로 쓴다. 창고·위치(`/mdm/warehouses`·`/mdm/locations`)도 실재하므로 `W-CO-08` 은 **배치도(도면 + 좌표)만** 더한다.

### 3-3. ⛔ 만들지 않는 것

| 무엇 | 왜 |
| --- | --- |
| 사번 확인 전용 경로 | `P-CO-01` 은 **인증이 아니다**(스펙 §5-1). 작업자 조회로 족하다 — 세션을 만들지 않는다 |
| 언어 설정 저장 | `M-CO-01` §5-3 — **저장할 곳이 없는 것이 맞다.** 내 화면 언어는 단말 로컬이다 |
| 스캐너 페어링 | `M-CO-01` §5-4 — **앱이 관여하지 않는 것이 맞다** |
| 공지 본문 수정(게시 후) | `W-CO-04` — 확인 이력이 무엇에 대한 확인인지 알 수 없어진다(G-19) |

## §4. ⏳ 확정이 필요한 것 **하나**

### `M-CO-01` 기기 등록 — **토큰을 어떻게 기기에 넣나**

스펙 §5-2 가 세 안을 놓고 **B를 권고**했으나 확정은 아니다. **계약 모양이 갈린다.**

| 안 | 어떻게 | 계약에 무엇이 생기나 |
| :-: | --- | --- |
| A | 관리자가 토큰 문자열을 직접 입력 | ⛔ 비현실적(PDA 키보드로 JWT 입력) — 스펙이 이미 뺐다 |
| ⭐ **B** | **관리웹이 등록 QR 을 보이고 기기가 스캔** | **`POST /mdm/terminals/{id}:issue-token` 하나.** 관리웹이 인증된 상태로 부른다 — **무인증 경로가 생기지 않는다** |
| C | 1회용 등록 코드 입력 → 서버가 토큰 교환 | **무인증 경로 하나**(`:redeem-code`) + 만료·재사용 통제 |

⭐ **B로 쓰고 진행한다** — 스캐너·카메라가 이미 있고(D-2), **무인증 엔드포인트를 만들지 않는 것**이 보안 경계를 단순하게 유지한다. 스펙의 권고와 같다.

⚠ **뒤집히면 경로 하나가 는다**(`:redeem-code`). 나머지 9화면과 다른 경로는 영향받지 않는다 — **트랙을 멈출 이유가 아니다.**
