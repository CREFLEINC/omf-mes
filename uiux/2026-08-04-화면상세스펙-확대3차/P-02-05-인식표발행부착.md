## §5. 액션·상태

### §5-1. ★ 단말 게이팅 — `can_print_label`

`P-01-01`(자재LOT 라벨)과 **같은 플래그**를 쓴다. 인식표도 라벨 발행이다.

> 8플래그 중 `can_print_label`은 이제 **2화면**(`P-01-01`·`P-02-05`)이 쓴다. F-1 매핑표가 채워진다.

### §5-2. ⚠ `serial_no`는 전역 유일이다 — `lot_no`와 다르다

```
trace.lot.lot_no              UNIQUE (plant_id, lot_no)   ← 공장 안에서 유일
trace.serial_number.serial_no UNIQUE                      ← 전역 유일
```

**개체 일련번호는 공장이 달라도 겹치면 안 된다.** 채번 규칙에 공장·LOT 정보가 들어가야 충돌하지 않는다.

> ⚠ **채번 규칙이 미정이다.** `app.numbering_rule`이 실재하나 인식표 규칙이 정의됐는지는 확인되지 않았다. §8-2.

### §5-3. 발행 단위가 개체다 — 대량 발행이 기본

**R69** — 「인식표 = 양품 생산품 **개체별 1:1**」

양품 480개면 **인식표 480장**이고 `serial_number` **480행**이다. 화면은 「몇 개를 발행할까」를 받아 **한 번에 만든다.**

```
┌─ 한 트랜잭션 ────────────────────────────────┐
│ ① serial_number × N        개체 생성          │
│ ② document_issue_log × N   발행 기록 (seq=1)  │
└──────────────────────────────────────────────┘
                    ↓ 별도 (K-4)
              프린터로 N장 전송
```

⚠ **`document_issue_log`도 개체당 1행인가** — `uq_document_issue_log(유형, 대상유형, 대상ID, 회차)`가 대상 단위이므로 **개체마다 기록이 생긴다.** 480장 발행 = 960행(개체 480 + 기록 480). §8-3.

### §5-4. 불량품에는 붙이지 않는다

**R69** — 「**불량품 미부착**」 · **R70** — 「인식표 + LOT 라벨 2단 출력·부착(**양품만**)」

화면은 **양품 수량만** 발행 대상으로 잡는다. `production_result.good_qty` 누적이 근거다(`P-02-06` §5-2와 같은 계산).

### §5-5. 재발행 — §K-1·K-2 그대로

```
issue_seq = 1     최초 발행
issue_seq ≥ 2     재인쇄 — reissue_reason_code 필수 (DB가 강제)
```

**개체 단위로 회차가 오른다.** 480장 중 3장이 훼손되면 그 3개체만 회차 2가 된다.

## §9. 이 장에서 나온 공유 계약 후보

1. **식별자의 유일 범위가 다르면 화면이 그것을 안다** — `lot_no`는 공장 내, `serial_no`는 전역이다. 채번 규칙과 중복 오류 문구가 달라진다 (§5-2 · A-1 확장)
2. **대량 생성은 전량 롤백한다** — 개체 번호는 연속이어야 하므로 부분 성공이 구멍을 만든다. B-8(원자성)의 대량 판 (§6)
