## §4. 필드

### §4-A. 발행 기록 `app.document_issue_log`

§K가 정한 그대로다(`P-01-01` §4-A). 이 화면의 값만 적는다.

| 컬럼 | 값 |
| --- | --- |
| `document_type_code` | `LABEL`(주석 예시) |
| `target_type_code` + `target_id` | **LOT**(`trace.lot`) — 다형 참조(A-10) |
| **`lot_id`** | ⚠ **여기서는 다형 참조와 FK가 같은 대상을 가리킨다** §5-2 |
| `issue_seq` · `reissue_reason_code` | K-1 · K-2 |
| `terminal_id` · `printer_name` | K-3 |

### §4-B. 대상 `trace.lot` (읽기 전용)

완료된 LOT만 대상이다. 필드는 `P-02-06` §4-A 참조.

## §5. 액션·상태

### §5-1. 단말 게이팅 — `can_print_label`

`P-01-01`·`P-02-05`와 **같은 플래그**. 이제 **3화면**이 쓴다.

### §5-2. 다형 참조와 FK가 같은 것을 가리킨다

`document_issue_log`는 `target_type_code`+`target_id`(다형)와 `lot_id`(FK)를 **함께** 갖는다.

| 화면 | 대상 | `target_id` | `lot_id` |
| --- | --- | --- | --- |
| `P-01-01` 자재LOT 라벨 | LOT | LOT id | 같은 값 |
| **`P-02-07` 생산LOT 라벨** | LOT | LOT id | **같은 값** |
| `P-02-05` 인식표 | **개체** | serial id | **소속 LOT** (다른 값) |

**A-10 규칙 3**(다형 참조와 FK가 병존하면 FK 쪽을 우선)이 여기서 갈린다 — 인식표는 둘이 **다른 것**을 가리키므로 FK만 보면 안 된다. 화면은 **`target_type_code`로 먼저 판정**하고 `lot_id`는 소속 확인용으로 쓴다.

### §5-3. 2단 출력 — 두 화면이 나눠 가진다

**R70** 「인식표 + LOT 라벨 2단」인데 **화면이 둘**이다.

```
P-02-05  인식표    개체 단위  (S7에서 발행 — 실적 등록 중)
P-02-07  LOT 라벨  LOT 단위   (S10에서 발행 — 완료 후)
```

**발행 시점이 다르다.** 인식표는 생산 중 개체가 나올 때마다, LOT 라벨은 LOT이 완료된 뒤다. 화면은 서로를 안내만 하고 합치지 않는다(레이아웃의 ⓘ).

### §5-4. 미달 마감 LOT도 라벨을 찍는가

`P-02-06`이 「완료」와 「미달 마감」을 나눴다. **미달 마감 LOT도 실물이 있으므로 라벨이 필요하다.**

화면은 **둘 다 대상으로 잡고 상태를 표시**한다(레이아웃의 `…0033 미달`). 다만 라벨에 상태를 찍는지는 서식 소관이다 — §8-2.

## §9. 이 장에서 나온 공유 계약 후보

1. **다형 참조와 FK가 병존할 때 둘이 같은 것을 가리키는지 확인한다** — A-10 규칙 3(FK 우선)은 둘이 같을 때만 안전하다. `document_issue_log`는 인식표에서 둘이 갈린다 (§5-2 · **A-10 보완**)
2. **한 확정 규칙(2단 출력)이 두 화면에 나뉘면 서로를 안내한다** — 사용자는 「2단」을 한 화면에서 기대한다. 시점이 다르다는 것을 화면이 말해 준다 (§5-3)
