
## §4. 미결 — **대장을 신설했다**

### 4-1. 무엇이 문제였나

미결이 태어나는 자리는 **화면 스펙 §8** 하나인데, 그것을 모은 대장이 없었다. 일부만 세 곳으로 흩어져 올라간다(공유계약 §I 46건 · 이슈 · 착수 통지 4번 칸) — **축이 서로 달라 어느 하나도 전체를 안 담는다.**

⛔ **그 결과가 §3-1-② 사고다** — 답이 와도 **어느 화면이 걸리는지 기계로 못 찾는다.**

### 4-2. 신설 — `deliverables/collect-open-items.py` → `미결-대장.md`

⭐ **문서로 쓰지 않고 생성기로 만들었다.** 손으로 쓴 대장은 이 저장소에서 예외 없이 낡았기 때문이다(§3-2).

```
python3 deliverables/collect-open-items.py            # 대장을 다시 만든다
python3 deliverables/collect-open-items.py --check    # 스펙과 갈렸는지만 본다
python3 deliverables/collect-open-items.py --warn     # 추적 표지 없는 행을 나열
python3 deliverables/collect-open-items.py --issue 64 # ⭐ 그 표지가 걸린 화면만
```

**실측 결과**

| 무엇 | 값 |
| --- | :-: |
| 화면 스펙 | 118 (미결 절을 못 찾은 것 **0**) |
| 미결 행 | **709** |
| ├ 해소 표시가 붙은 행 | 101 |
| └ 살아 있는 행 | **608** |
| 그중 **추적 표지가 없는 것** | **383 (63%)** |
| 등급 열에 **차단** | **0** — ⭐ 전 화면이 「지금 지어도 된다」 |

⭐ **이 대장의 존재 이유는 「표지 → 화면」 역인덱스다.** `#64` 가 15화면, `C-12` 가 5화면에 걸린다는 것이 한 줄로 나온다 — **§3-1-② 사고를 다시 안 내는 유일한 수단이다.**

⚠ **못 보는 것**(생성기 주석에 적었다) — 미결의 내용이 맞는지 · 표지가 가리키는 곳이 살아 있는지(닫힌 `#54` 도 표지로 센다) · 표 밖에 적힌 미결(확대 1차는 상세를 공유계약 §I 묶음 표에 두었다).

### 6-2. ⭐ 05 설비툴이 미결 대장보다 먼저인 이유

1. **막는 상대가 있고 없고가 갈린다.** 05 는 17화면의 유일한 병목이고 대체 경로가 없다.
2. **05 는 미결 대장에 의존하지 않는다.** 0단계가 「차단 미결 0건」을 확정했고, 이번 대장이 **118파일 전수 차단 0**으로 재확인했다.
3. **05 를 먼저 해도 대장이 나빠지지 않는다.** 대장의 모집단은 스펙 §8 이고 05 스펙 17장은 **이미 쓰여 있다.**
4. **05 는 반쯤 착수돼 있다.** 여기서 멈추면 트랙 하나가 미완으로 남고, **공통 트랙이 0단계에서 계약으로 건너뛰어 생긴 계수 오차**를 되풀이한다.

⚠ **단 하나 05 앞으로 당겨야 하는 것이 C-12 정정이다** — 5화면 중 4장이 05 이고, 통지 17장이 나가면 낡은 표기가 그대로 전달된다.

## §8. 이번 정리에서 **실제로 한 것**

「찾았다」와 「고쳤다」를 가른다. 아래는 **고친 것**이고, 나머지는 §6 계획이다.

### ⚠ 닫으면서 지킨 것

⛔ **「해결됐다」로 닫은 것은 하나도 없다.** 물리 모델 SQL 은 2026-07-24 이후 무변경이고 요청한 컬럼·표는 지금도 0건이다. 셋 다 **중복 정리 또는 전제 소멸**이며, **요구는 `#155`·`#145` 에서 살아 있다.**

⭐ **닫기 전에 「이 번호를 누가 가리키나」를 셌다.** `#69` 는 계약이 여섯 곳에서 가리키고 있었고, 그중 둘은 공개 문서였다. **세지 않고 닫았으면 공개 계약에 없는 이슈를 가리키는 주석이 남았을 것이다.** 이 계수를 **닫기 절차의 필수 단계**로 둔다.
