# 03 품질 API 스펙 — 설계

> 작성일: 2026-08-12 · 작성 주체: CREFLE OMF 팀 (UI/UX)
> 선행 트랙: 06 기준정보 ✅ · 01 자재창고 ✅ · 공통(승인·출력물) ✅ · 02 생산실행 ✅
> **다섯 번째 계약 트랙.** 방법론은 6단계 그대로.

## 1. 왜 03 이 다음인가

**가장 작아서가 아니라 가장 많이 막고 있어서다.**

| | |
| --- | :-: |
| 03 도메인 화면 | **5** |
| ⭐ **앞 트랙이 03 을 기다리며 미룬 화면** | **2** |
| ⭐⭐ **04 트랙이 쓸 계약을 여기서 만든다** | `W-04-03` OQC |

앞의 네 트랙은 **자기 화면을 자기가 덮었다.** 03 은 다르다 — **남이 못 낸 것을 푸는 트랙**이다.

## 2. ⭐⭐ 화면이 **5가 아니라 7이다**

**설계 착수 전에 계수를 고친다.** 인벤토리 계수(`dom`=`03`)는 5이지만 **계약 대상은 7**이다.

```
생성기 m.BY 에서 dom == '03'      →  5   (W-03-01·02·03·05·09)
01 트랙이 「03 소관」으로 미룬 것  →  1   (W-01-01 IQC 수입검사·판정)
02 트랙이 「03 소관」으로 뺀 것    →  1   (P-02-13 PQC 제품 검사)
                                     ───
                          계약 대상   7
```

### 2-1. 앞 트랙이 남긴 문장 — 실측 인용

**01 요구서 §6-1**(`deliverables/06-API-요구서-01자재창고.md:632`):

```
### 6-1. W-01-01 IQC 수입검사·판정
계약을 만들 수 없어서가 아니라 우리 도메인이 아니다.
소관   03 품질 도메인 — trace.lot_hold 쓰기를 03으로 보낸 것과 같은 규칙
```

**01 요구서 §8-1 #6**: 「03 품질 실행 계약 — 별도 트랙 · **`W-01-01` 이 여기서 풀린다**」

**02 요구서 머리**: 「화면 **20** *(24 중 출력물 3 · **03 소관 1** 제외)*」

⭐ **`W-01-01` 은 01 트랙의 「착수 통지 불가」 목록에 있고, `P-02-13` 은 02 트랙의 통지 16 에 없다.** 이 트랙이 성공하면 **두 화면이 동시에 풀린다.**

### 2-2. ⚠ 계수 함정을 하나 지난다

⛔ **「03 은 5장」은 인벤토리 축이고, 계약 대상 축이 아니다.** 도메인 배지로 세면 이월 2장이 사라진다.
**02 트랙에서 계수를 네 번 고쳤다**(테이블 23→22 · 분류표 겹침 · 액션 99→103 · 통지 16→15). **이번엔 착수 전에 센다.**

## 3. 계승하는 것 — 앞 네 트랙에서 그대로

| 무엇 | 정본 |
| --- | --- |
| **6단계 방법론** | 리소스 → URL·동작 → 오프라인 → OpenAPI → 검증 → 착수 통지 |
| **리소스 패턴 7종** | 가 마스터 / 나 부여·회수 / 다 버전 마스터 / 라 업무 문서 / 마 원장 / 바 파생 잔액 / **사 구간**(02 신설) |
| **URL 규약** | 복수 명사 · kebab-case · **`:동사` 는 상태 전이에만** · **수정은 `PUT`**(01·06 이 PUT 36 · PATCH 0) |
| **오프라인 규약** | `IdempotencyKey`(required) · `IfMatchVersion` · **`IfMatchVersionOptional`**(오프라인 경로 · C-9) · ~~201 즉시 / 202 큐 접수~~ ⛔ **2026-08-12 철회** — 오프라인은 HTTP 가 안 일어난다 |
| **생성기** | `build-02-openapi.py` 복제 — ⛔ **계약을 손으로 고치지 않는다** |
| **검사기 4종** | `check-structure.py` · `check-public-safe.py` · `verify-ui-coverage.py` · `verify-mapping-coverage.py` |
| **검증 두 축** | 커버리지(검사기) + **적합성**(사람) + ⭐ **역방향**(02 신설) |

⭐ **02 가 남긴 「지우고 다시 만든다」를 그대로 쓴다** — `rm quality-03품질.json && python3 build-03-openapi.py`. 「돌리고 검사기가 통과했다」로는 재현이 확인되지 않는다.

### 4-1. ⭐ 그래서 「도메인 이름이 같다」가 「계약이 같다」가 아니다

`mdm-기준정보.json` 이 이미 **`/quality/*` 16경로**를 갖고 있다(마스터 계열 전부). **네임스페이스가 두 파일에 걸친다.**

```
mdm-기준정보.json     /quality/inspection-plans · inspection-plan-versions
                      /quality/defect-codes · cause-codes          ← 마스터
quality-03품질.json   /quality/inspection-requests · …results      ← 실행  (이 트랙)
```

⚠ **2단계가 판정할 것** — 실행 계약을 `/quality/*` 아래 두면 **한 네임스페이스가 두 문서에 갈린다.** 갈라도 되는지, 접두를 달리해야 하는지는 **URL 규약 단계에서 정한다**(§7 확인 3).

### 4-2. ⭐ `trace.lot_hold` 쓰기를 **01 이 명시적으로 넘겼다**

`logistics-01자재창고.json` 의 실측 문장:

```
GET /trace/lots/{lotId}/holds
  "읽기만 제공한다 — 보류를 걸고 푸는 것은 품질 도메인의 화면이다."
```

**`W-03-03`(보류 등록)·`W-03-02`(해제·재판정)가 그 쓰기 측이다.** 같은 경로에 **메서드를 더하는 형태**가 되므로 **§4-1 과 한 문제**다.

### 4-3. ⭐ `W-03-09` 는 승인 실행 계약을 **이미 갖고 있다**

`app-공통.json` 실측 — `POST /app/approval-requests/{id}:approve` · `:reject` · 목록 · 상세가 전부 있다.

**`W-03-09` 가 03 계약에서 새로 필요한 것은 「특채 조건 조회」뿐이다.** 승인 행위 자체는 횡단 계약이 덮는다.

⚠ **다만 `concession.nonconformance_id` 가 NOT NULL 이다**(실측) — **부적합은 04 가 만든다.** `W-03-09` 의 「부적합 열기」가 **04 계약 없이는 갈 곳이 없다**(§8 참조).

## 6. ⭐ 오프라인이 한 화면에만 걸린다 — `P-02-13`

02 는 20장 중 POP·모바일이 다수라 오프라인이 본론이었다. **03 은 7장 중 6장이 관리웹**이라 **C-5**(관리웹은 오프라인 해당 없음)로 닫힌다.

**`P-02-13` 만 예외이고, 그 자리에 저장 측이 이미 준비돼 있다** — 실측:

```
quality.inspection_result.idempotency_key   varchar(150) NOT NULL UNIQUE   ← C-8 저장 측
quality.inspection_result.version_no        integer NOT NULL DEFAULT 1     ← B-1
```

⭐ **02 가 찾은 것과 같은 형태다**(`material_consumption`·`production_result` 의 `idempotency_key`). **헤더로 받아 그 자리에 저장한다.**

⚠ **`inspection_measurement` 에는 `version_no` 가 없다**(실측) — 3계층 중 가장 깊은 층이 **기록 전용**이다. 잠금 토큰은 `inspection_result` 로 대표한다.

## 7. 착수 전 확인 대상 — **관문 3개를 먼저 통과시킨다**

> 계약 트랙에서 이슈·요청을 내기 전 세 가지를 묻는다 — ① **없어야 정상인가** ② **이미 판정이 있는가** ③ **선후가 있는가**.

### 7-1. 관문 ② — **이미 판정이 있는 것 4건** *(새 이슈를 내지 않는다)*

| 무엇 | 판정 | 계약이 따를 것 |
| --- | --- | --- |
| **검사자 ≠ 확정자** | ✅ **#62 종결** — **분리하지 않는다**(1차) | `inspector_id`·`inspected_at` 만 쓰고 **별도 확정자 축을 만들지 않는다.** `confirmed_at` 은 **저장 시각** |
| **판정 유형 값 목록** | ✅ **회신 E-3 종결(2026-08-07)** — 검사 판정 **3값**(`합격`·`불합격`·`보류`) · LOT 상태 **4값**(`정상`·`불량`·`검사 대기`·`폐기`) | 스키마 enum 이 아니라 **공통코드 조회**로 둔다(값이 늘 수 있다 · G-6) |
| **선별 실행** | ✅ **#118 확정 — 1차 범위 밖** | `sorting_result` 경로를 **만들지 않는다** |
| **승인자 유형** | ✅ **J-3 확정 — `USER` 만** | `app-공통.json` 이 이미 담았다. 03 은 그대로 쓴다 |

⭐ **02 트랙에서 관문 ②가 6회 발동해 「신설 요구 새 이슈 0건」이 나왔다.** 03 도 먼저 센다.

### 7-2. 관문 ③ — **선후가 있는 것 1건**

⛔ **`W-03-01` §5-2 가 이미 판정을 냈다** — **§I-11**(Lot Status 변경이력 1:N 신설)과 **§I-5**(`audit_event` 사용 규약)는 **따로 풀 수 없고**, 먼저 답할 것은 「**전용 테이블인가 `audit_event` 인가**」 하나다. **A안(전용 테이블)을 권고**했고 **#64·#68 양쪽에 코멘트**가 나가 있다.

**이 트랙은 회신을 기다리지 않는다** — **A-11 로 물러난 화면 설계가 이미 있다**(보류 이력만 보이고 그 사실을 결과 표 안에 적는다). **계약도 같게 간다: 있는 것만 낸다.**

### 7-3. ⏳ **2단계가 판정할 것 — 3건**

| # | 무엇 | 왜 지금 못 정하나 |
| :-: | --- | --- |
| **1** | **`/quality/*` 네임스페이스를 06 계약과 나눠 쓰는가**(§4-1) | URL 규약 단계의 문제다 |
| **2** | **`trace.lot_hold` 쓰기를 어느 경로에 두는가**(§4-2) | 01 경로에 메서드를 더할지, 03 경로를 새로 낼지 |
| **3** | **`defect_record` 등록을 `P-02-13` 이 하는가** | `P-02-13` §5-8 이 **처분 선택은 잠정**이라 했다. **버튼을 세어 정한다** — ⛔ 테이블이 아니라 화면 버튼 |
