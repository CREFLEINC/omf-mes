## §3. 레이아웃 — **1024×768 실측 그리드**

### §3-1. 세로 예산

```
768  전체
 -64  헤더 (W/O·품목·사번·연결 상태)
 -88  액션바 (핵심 버튼 72 + 상하 여백 8+8)
────
 616  본문 가용
```

### §3-2. 배치 — 좌우 2단 (입력 / 키패드)

```
1024 × 768
┌ 헤더 64 ───────────────────────────────────────────────────────┐
│ W/O-2026-0731-004 · 품목 ABC-123 · 900xxx · ● 온라인          │
├──────────────────────────────────┬─────────────────────────────┤
│ 좌 616 × 616                     │ 우 392 × 616                │
│                                  │                             │
│  대상 LOT   LOT-...-0007  [변경] │   ┌ 숫자 키패드 ─────────┐  │
│                             64px │   │  7    8    9         │  │
│  제품       ABC-123       [변경] │   │  4    5    6         │  │
│                             64px │   │  1    2    3         │  │
│  ──────────────────────────────  │   │  C    0    ←         │  │
│                                  │   └──────────────────────┘  │
│  ▣ 양품수량  [       120 ] EA    │     키 64×64 · 간격 12       │
│                             72px │     블록 216 × 292          │
│                                  │                             │
│    타발수    [        - ]        │   [ ＋10 ]  [ ＋100 ]  64px │
│                             64px │                             │
│    비고      [          ]   64px │                             │
│                                  │                             │
│  잔여수량  380 / 500       64px  │                             │
├──────────────────────────────────┴─────────────────────────────┤
│ 액션바 88    [ 취소 72 ]                      [ 저장 72 ]      │
└────────────────────────────────────────────────────────────────┘
```

**세로 검산(좌단)**: 64+64+72+64+64+64 = 392 + 간격 12×5 = 60 → **452 / 616** — 여유 164px. 통과.

### §3-3. 이 배치가 강제하는 것

- **입력 필드는 3개가 상한**이다(양품수량·타발수·비고). 필드를 하나 더 늘리면 키패드 없이도 빠듯해진다 → **「한 화면 = 한 태스크」가 산술로 증명된다.**
- **숫자 키패드를 화면 안에 고정**한다. Windows 터치 키보드에 의존하지 않는다 — 키오스크 전용 창(결정 16)에서 OS 키보드가 화면을 덮으면 입력 필드가 가려지고 제어가 어렵다.
- 양품수량이 **핵심 입력이라 72px**, 나머지는 64px.
- ⚠ **정본이 「양품만 입력」(R50)이라 이 배치가 성립한다.** 수량 5종을 다 입력받으면 좌단이 넘친다 — §8-1 참조.

## §5. 액션·상태

### §5-1. 액션

| 액션 | 크기 | 활성 조건 |
| --- | --- | --- |
| 변경(LOT / 제품) | 64px | 항상 |

⚠ **`mdm.terminal_process.can_input_result`가 이 화면의 저장 활성 조건이다.** 단말×공정 조합에 플래그가 없으면 저장 불가 — 사유를 표시한다(「이 단말은 이 공정의 실적 입력 권한이 없습니다」). 관리 화면은 `W-CO-06` 단말기-공정 매핑 설정.

### §5-2. 저장 후 분기 (S7 태스크 ⑥)

```
저장 → 잔여수량 재계산
        ├─ > 0 → 제품 선택으로 회귀 (연속 입력)
        └─ = 0 → LOT 완료 처리 안내 → P-02-06 (S10)
```

### §5-3. ⚠ 오프라인 — `idempotency_key`가 핵심

`production_result`에 **`idempotency_key varchar(150) NOT NULL UNIQUE`** 가 있다. 이는 **클라이언트가 생성해 outbox에 담고, 재전송 시 서버가 중복을 흡수**하는 설계다(결정 16 공유물 `outbox 모듈`·결정 17 시나리오 1 W/O 선배포).

화면 요구:
1. 저장 시 **로컬 SQLite에 먼저 기록**하고 즉시 성공 피드백 — 통신을 기다리지 않는다
2. 헤더에 **연결 상태와 미동기 건수 상시 표시**(결정 16 POP 「오프라인/미동기 상시 표시」)
3. `occurred_at`은 **입력 시점**, `recorded_at`은 서버 수신 시점 — 오프라인 지연이 실적 시각을 왜곡하지 않는다
4. 재전송은 같은 `idempotency_key`로 — **사용자에게 중복 저장으로 보이지 않아야 한다**

> 이 규약은 POP·모바일의 모든 입력 화면에 동일하다 → **공유 계약 후보**.

## §7. DS 매핑

### §7-1. ⚠⚠ 갭 — **터치 타겟이 DS 최대치를 초과한다 (b 유형 · 확정)**

| 요구(POP) | DS 실측 | 판정 |
| --- | --- | --- |
| 일반 버튼·입력 **56px↑** | `--control-height-lg: 48px` (최대) | ❌ **미달** |
| 주요 버튼 **64px↑** | 48px | ❌ |
| 핵심 버튼 **64~72px** | 48px | ❌ |
| 위험 버튼 **72px↑** | 48px | ❌ |

`--control-height-sm/md/lg = 32/40/48px` 세 단계뿐이고, **최대인 lg조차 POP 최소 요구(56px)에 미달**한다. `Button`·`TextField`·`Select`·`IconButton`의 `size` prop이 `sm|md|lg`로 이 토큰에 묶여 있다.

- **유형 `b`** — 컴포넌트는 있고 **크기 변형만 없다**
- **소관 = webui 이슈** (파운데이션 아님) — `--control-height-*`는 `styles/web-tokens.css`(webui 소유)에 있고, 파운데이션은 Stage 1이라 색상 토큰만 갖는다
- **요청 형태**: `--control-height-xl(56)`·`--control-height-2xl(64)` 신설 + `size` 스케일 확장. 또는 **터치 밀도 프리셋**(`data-density="touch"`)으로 전체를 한 번에 올리는 방식 — 후자가 화면마다 size를 지정하지 않아도 되어 낫다
- ⚠ **이슈 본문은 제품 용어를 쓰지 않는다** — 「POP 작업실적 등록」이 아니라 **「터치 전용 단말을 위한 컨트롤 높이 스케일·밀도 프리셋」**

**이것이 앞서 예측했던 갭의 실측 확정이다.** POP·모바일 전 화면(41건)에 파급된다.

### §7-2. 갭 — 숫자 키패드 (d 유형 후보)

화면 내장 숫자 키패드가 DS에 없다. `Button` 12개 조합으로 만들 수 있으므로 **`c`(조합)로 볼 수도 있으나**, 포커스 연동·입력 버퍼·`C`/`←` 동작이 함께 와야 쓸모가 있어 **상태를 가진 단일 요소**에 가깝다.

- **잠정 판정 `d`** — `ds-candidates/`에 제품 로컬 구현
- **세 곳 규칙**: POP 입력 화면 대부분이 수량을 받으므로 사용처는 쉽게 3곳을 넘는다(`P-02-04`·`P-02-06`·`P-01-02` 등). 전 화면 매핑 후 확정
