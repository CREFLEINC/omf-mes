## 0. 도메인 적용 노트 (04에만 적용한 판단 규약)

1. **단말 바뀜가 잘 듣는 도메인이다.** 메인 축 User 5개(M2·M4·M6·M8·M10)의 배지가 **웹→모바일→웹→POP→웹**으로 번갈아 바뀌어 축이 5개 스팬으로 기계적으로 잘린다. 사이드도 SA2 웹 / SB3 POP / SC2 웹 / SC4 웹 / SD2 **모바일+POP 스택**으로 배지가 확정돼 있다.
2. **적용 순서**: 배지(단말 바뀜)로 노드 시퀀스를 자르고 → 같은 배지가 인접해도 액터(사용자 바뀜)가 다르면 다시 잘랐다(사이드C: SC2 완제품창고담당 / SC4 품질담당 — 둘 다 웹이지만 액터로 갈림). **스팬 = 그룹**이고, 스팬 내부를 더 쪼개려면 작업 끊김·따로 진입·연속 조작·결과가 입력으로가 필요하므로 그때만 보류다.
3. **Archive 축 노드 12개는 상태 마일스톤이다**(비고에 「빨강(시작)/검정(상태)/파랑(완료)」 명시). 화면을 만들지도 없애지도 않으므로 **커넥터 방향이 지시하는 생산 그룹에 흡수하고 확정** 처리했다. 예외 2건 — `846:8726` 재작업 적치 · `847:8827` 불량창고 **물리** 입고는 라벨·비고가 물리 적치/입고를 지시하고 대응 기록 노드(B3·B4)가 따로 있어 `화면없음:실물작업`(사유 코드 예시 「라인사이드 적치」와 동형)으로 처분했다.
4. **File 노드는 기록 산출물이다**(출하작업지시·피킹 실적·포장 실적·출하 기록·재작업 실적·반품 기록·재구성 이벤트). 조작 화면이 아니라 그 그룹의 기록이므로 그룹에 흡수하고 확정 처리했다. 단 `849:8921`(재구성 이벤트)만 2단말 스택 경계에 걸려 보류다.
5. **경계 표기 5건**(SA3·SB1·SB4·SC5·SC6)은 대장 분류가 `표기`(스펙 원문 「TEXT(근사)」)지만 **캔버스 실측이 전부 HEXAGON**이라고 각 행 비고가 명시한다. 사유 코드는 실체에 맞춰 `섹션인계`를 썼다(`주석`과 마찬가지로 화면없음이라 화면 집합에 영향 없음).
6. **`H7`은 캔버스 미작화**로 확인된 유일한 행 → `화면없음:미작화`(이슈 #26 계류).
