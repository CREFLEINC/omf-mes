# 노드 → 화면 매핑 규칙 (v1.1)

> 작성일: 2026-07-28 (v1.1 — 확정도 체계 도입·사람 확정 단계 명문화 / v1.0 초안) · 작성 주체: CREFLE OMF 팀 (UI/UX)
> 위치: 1계층(`node-registry/`) → **이 규칙** → 2계층(`screen-inventory-ia.md`)

## ⚠ 이 규칙의 위상 — 답을 내는 도구가 아니다

**규칙 적용 결과는 초안이고, 최종 확정은 사람이 한다** (사용자 결정 2026-07-28).

v1.0 초안을 검토한 결과, 나누는 조건뿐 아니라 **묶는 조건에도 주관이 개입하는 여지가 크다**는 판단이 나왔다. 「끊김 없는 연속 조작」이나 「앞 단계 결과가 곧 다음 입력」은 문장으로는 깔끔해도 실제 적용에서 사람마다 다르게 읽힌다. 규칙 문구를 아무리 다듬어도 이 여지는 없어지지 않는다.

그래서 규칙의 목적을 바꾼다.

- **하지 않는 것**: 753행의 화면 귀속을 규칙이 최종 결정한다
- **하는 것**: 규칙으로 **객관적으로 결정되는 것과 사람이 봐야 하는 것을 갈라낸다**

기계 처리의 가치는 정답을 맞히는 데 있지 않고, **사람이 검토할 대상을 753행에서 수십 행으로 줄이는 데** 있다. 그러려면 규칙이 **자기가 확신하지 못하는 지점을 스스로 표시**해야 한다. 조용히 결정해버리면 사람은 전부 다시 봐야 하고, 그러면 기계 처리를 한 의미가 없다.

## 0. 왜 필요한가

화면 목록 v1.0의 적대 검증에서 나온 방법론 결함(M8)이 출발점이다. 같은 문법 요소(Wallet=목록)를 04에서는 독립 화면으로 뽑고 05·06에서는 흡수해, **분해 기준이 도메인마다 달랐다.** 그 결과 「화면 112건이 WBS 추정보다 많으니 누락 없음」이라는 커버리지 근거가 성립하지 않게 됐다.

규칙 없이 화면을 하나씩 더하고 빼는 건 같은 문제를 반복하는 것이다. 먼저 기준을 정하고 전 도메인에 똑같이 적용한다.

## 1. 산출물 규약 — 모든 행은 처분을 받는다

노드 대장의 **모든 행**에 **처분**과 **확정도** 두 값을 부여한다. 빈칸을 허용하지 않는다.

**처분** — 다음 중 하나
- **화면 ID** (`W-01-01` 형식) — 이 노드가 그 화면에 속한다
- **`화면없음:<사유코드>`** — 화면이 아니다. 사유를 반드시 명시한다

**확정도** — 다음 중 하나 (§3-4에서 판정)
- **`확정`** — 객관 근거만으로 결정됐다. 사람 검토 불요
- **`보류`** — 주관 판단이 개입했다. **사람 확정 대상**
- **`근거`** — 왜 그렇게 판정했는지 한 줄. 보류는 **무엇이 갈리는지**를 반드시 적는다

빈칸을 금지하는 이유는 단순하다. **처분이 없는 행은 「검토했으나 화면이 아니다」와 「빠뜨렸다」를 구분할 수 없다.** 대장을 만든 목적 자체가 그 구분이다.

확정도를 함께 요구하는 이유도 같다. **확정과 보류를 구분하지 않으면 사람이 753행을 전부 다시 봐야 한다.** 기계 처리의 가치는 검토 대상을 줄이는 데 있다.

## 2. 분류별 기본 처분

대장의 `분류` 열에서 기계적으로 파생된다. **판단이 필요한 것은 `행위`뿐**이고 나머지는 자동이다.

| 분류 | 기본 처분 | 예외 |
| --- | --- | --- |
| **행위** | **화면 후보** → §3 병합 규칙 적용 | 실물작업·ERP소관은 `화면없음` |
| 시스템 | `화면없음:시스템자동` | — |
| 사람 | `화면없음:액터표기` | 인접 행위 노드의 사용자 열에 반영 확인 필수 |
| 게이트 | `화면없음:게이트` | 분기 조건이 화면의 상태로 정의됐는지 확인 필수 |
| 참조 | `화면없음:섹션인계` | — |
| 표기 | `화면없음:주석` | MES 노트는 대응 화면의 엔티티 열 근거로 인용 |
| 상태 (03) | `화면없음:상태값` | 상태 조회 화면은 별도 도출 |
| 전이 (03) | `화면없음:전이` | 판정 지점 4곳은 행위로 취급 |

「확인 필수」가 붙은 둘은 흡수 대상이 실제로 어딘가에 반영됐는지 대조해야 한다. 흡수한다고 적어놓고 반영하지 않으면 그냥 누락이다.

## 3. 행위 노드 → 화면 병합 규칙

### 3-1 · 나누는 조건 — 하나라도 해당하면 별도 화면

| # | 조건 | 판정 근거 |
| --- | --- | --- |
| **S1** | **액터가 바뀐다** | 대장의 인접 User 노드. 물류담당→품질담당이면 별개 |
| **S2** | **단말이 바뀐다** | **`placement-plan.md` 배지가 기계적 정답을 준다** |
| **S3** | **세션이 끊긴다** | 축 상태가 바뀌거나 시간이 벌어진다. 입하 등록과 며칠 뒤 IQC는 별개 |
| **S4** | **독립 진입 경로가 있다** | 관리웹 메뉴·모바일 홈 타일·POP 태스크 목록에서 직접 들어갈 수 있다 |

S2는 이미 정답이 있다. 배지 정본의 63배치는 적대 검증에서 인벤토리와 **충돌 0**으로 확인됐고, 2단말 스택 3건(04-S-D·05-S-B·05-S-D)이 정확히 화면 2개로 분해된 것도 이 기준이 작동한 결과다.

### 3-2 · 묶는 조건 — 전부 충족해야 한 화면

1. 같은 액터
2. 같은 단말
3. 끊김 없는 연속 조작 (중간에 다른 액터나 시간 경과 없음)
4. 앞 단계 결과가 곧 다음 입력

예: `M-01-01 입하 등록`은 도식에서 「부착 여부 분기 → LOT 스캔 → P/O 후보 선별 → P/O 선택 → 거래명세서 촬영 → 품목·수량 확인 → 등록」 여러 노드지만, 창고 담당자가 PDA를 들고 한 자리에서 연속으로 하는 **한 작업**이라 한 화면이다. 여기서 노드마다 화면을 쪼개면 스캔할 때마다 화면을 넘나들어야 해서 「스캔 퍼스트」라는 모바일 IA 원칙과 정면으로 어긋난다.

### 3-3 · 프로그램별 보정

세 프로그램의 IA 모델이 다르므로 S4(독립 진입)의 해석이 갈린다.

- **관리웹** — 메뉴 트리. 메뉴 항목이 되면 독립 화면이다. 판정·전표·마스터는 원래 독립성이 높다.
- **POP** — 사번 인증 → W/O 태스크 모드. **메뉴가 아니다.** 태스크 흐름 안의 단계는 묶는 쪽이 기본이고, 별도 스테이션(창고 라벨 출력·설비 수집)만 독립 진입을 갖는다.
- **모바일** — 스캔 퍼스트 홈 타일. 타일 하나가 하나의 작업 단위다. 타일 안의 스캔 연쇄는 묶는다.

### 3-4 · 확정도 판정 — 무엇이 객관이고 무엇이 주관인가

§3-1·§3-2의 조건은 **객관성이 서로 다르다.** 이걸 구분하지 않고 뭉뚱그린 것이 v1.0 초안의 결함이었다.

| 조건 | 판정 근거 | 객관성 |
| --- | --- | --- |
| **S1 액터 변경** | 대장의 인접 User 노드 — 있거나 없거나다 | **객관** |
| **S2 단말 변경** | `placement-plan.md` 배지 63배치 — 정본이 정답을 준다 | **객관** |
| S3 세션 단절 | 「시간이 벌어진다」의 해석 | **주관** |
| S4 독립 진입 | 기존 메뉴·타일에 있으면 객관, 신설 판단은 주관 | **혼합** |
| 묶기 ①② (같은 액터·단말) | S1·S2의 이면 | **객관** |
| 묶기 ③ 끊김 없는 연속 조작 | 「끊김」의 해석 | **주관** |
| 묶기 ④ 앞 결과가 다음 입력 | 데이터 흐름 해석 | **주관** |

### 판정 원칙

- **S1·S2만으로 갈린 경계 → `확정`.** 배지가 웹↔POP으로 바뀌는 지점, 물류담당↔품질담당이 바뀌는 지점은 사람이 다시 볼 필요가 없다.
- **S3·S4나 묶기 ③④가 개입한 경계 → 무조건 `보류`.** 결과가 그럴듯해도 보류다. 판단이 들어갔으면 표시한다.
- **§2 분류별 기본 처분(행위 외 7분류) → `확정`.** 유형에서 기계 파생이라 판단이 없다. 단 「확인 필수」가 붙은 `사람`·`게이트`는 흡수 대상이 실제로 반영됐는지 대조한 뒤 확정한다.
- **애매하면 보류.** 확정으로 잘못 넣으면 사람 눈을 영영 못 거치지만, 보류로 잘못 넣으면 검토 한 번 더 하고 끝난다. **비용이 비대칭이므로 보류 쪽으로 기운다.**

### 보류 행에 반드시 적을 것

「보류」만 적고 끝내면 사람이 처음부터 다시 판단해야 한다. **무엇이 갈리는지**를 적어야 검토가 빨라진다.

> 나쁜 예: `보류 — 판단 필요`
> 좋은 예: `보류 — S3. 입하 등록(219:4521)과 LOT 등록(219:4571) 사이에 「수입 검사 대기」 축 상태(219:4512)가 끼어 세션이 끊기는지 애매. 끊긴다고 보면 2화면, 아니면 1화면`

## 4. 적용 순서

**1~3은 기계, 4가 사람이다.**

1. **기계 처분** — `행위` 외 7분류에 §2 기본 처분을 일괄 적용한다. 판단 없음 → 전부 `확정`.
2. **객관 경계 확정** — 행위 노드에 **S2(단말)를 먼저 적용**해 배지 경계로 자르고, 이어 S1(액터)로 자른다. 여기까지로 갈린 그룹은 `확정`.
3. **주관 경계 표시** — 남은 그룹 안에서 S3·S4·묶기 ③④를 적용하되, **결정하지 말고 후보와 갈리는 지점을 적어 `보류`로 남긴다.**
4. **사람 확정** — 보류 행만 검토해 최종 귀속을 정한다. **이 단계 산출이 정본이다.**
5. **대조·재검증** — 확정된 화면 집합을 현행 112건과 맞춘다. 차이가 누락·과잉이고, 적대 검증의 누락 15·과잉 7이 살아남는지 본다. 규칙으로 설명되는 건 지적이 아니라 규칙 적용 결과다.

### 성공 기준

3단계가 끝났을 때 **보류 비율이 얼마나 낮은가**가 이 규칙의 품질이다. 보류가 지나치게 많으면 규칙이 일을 안 한 것이고, 지나치게 적으면 주관을 확정으로 위장한 것이다. 초회 적용 후 실제 비율을 보고 §3-4 판정 기준을 조정한다.

## 5. 이 규칙이 답하지 못하는 것

정직하게 남긴다.

**주관성 자체는 더 이상 「해결할 문제」가 아니다.** v1.0은 규칙 문구를 다듬으면 주관이 사라질 것처럼 썼지만, S3·묶기 ③④는 업무 실태를 아는 사람만 판정할 수 있는 종류다. v1.1은 이를 없애려 하지 않고 **보류로 표시해 사람에게 넘기는 것**으로 처리한다. 규칙의 실패가 아니라 역할 분담이다.

남는 진짜 한계는 셋이다.

- **대시보드·조회 화면은 이 규칙 밖이다.** 이 규칙은 도식 노드에서 화면을 도출하므로, 도식 앵커가 없는 화면은 아예 대상이 아니다. 적대 검증이 지적한 대시보드 5건 난립(W-02-09·W-03-08·W-CO-05·W-05-14·W-04-09)이 여기 해당한다. **REQ·WF 단계를 근거로 하는 별도 도출 체계가 필요하다** — 이 규칙으로는 판정도 반박도 못 한다.
- **1화면의 노드 수 상한이 없다.** 하한(1노드 1화면 아님)은 §3-2에 있지만 상한은 없다. 실무상 한 화면이 10노드를 넘으면 재검토 신호로 보되, 이건 경험칙이지 규칙이 아니다.
- **보류 비율의 적정선을 모른다.** §4 성공 기준에 「너무 많아도 적어도 안 된다」고 썼지만 구체적 수치는 초회 적용 결과를 봐야 정할 수 있다. 첫 적용은 이 값을 재는 실험을 겸한다.
