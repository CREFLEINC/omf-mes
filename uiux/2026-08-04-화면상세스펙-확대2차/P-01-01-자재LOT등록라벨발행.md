## §3. 레이아웃 (POP — 1024×768 실측 제약)

**세로 여유가 119px뿐이다**(E-1). 구획을 쌓지 않고 좌우로 편다. 터치 타겟은 크게(G-5).

## §4. 필드

### §4-A. 발행 기록 `app.document_issue_log`

| 라벨 | 출처 컬럼 | 타입 | 필수 | 검증·비고 | 입력 |
| --- | --- | --- | :-: | --- | --- |
| 문서 유형 | `document_type_code` | `code_t` | ✅ | `LABEL`(주석 「LABEL \| COA \| TRACE_REPORT 등」) | 자동 |
| **대상 유형** | `target_type_code` | `code_t` | ✅ | ⚠ **다형 참조 — 네 번째** §5-4 | 자동 |
| **대상 ID** | `target_id` | bigint | ✅ | FK 아님 | 자동 |
| 자재LOT | `lot_id` | FK → `trace.lot` | — | **여기만 진짜 FK다** §5-4 | 자동 |
| **발행 회차** | `issue_seq` | integer > 0 기본 1 | ✅ | **1=최초 · 2+=재발행**(주석) | 자동 |
| **재발행 사유** | `reissue_reason_code` | `code_t` | 조건부 | ⬇ CHECK가 강제한다 | 선택 |
| 발행자 | `issued_by` | FK → `app_user` | ✅ | 로그인 사용자 | 자동 |
| 발행 시각 | `issued_at` | timestamptz | ✅ | | 자동 |
| **단말** | `terminal_id` | FK → `mdm.terminal` | — | 어느 POP에서 찍었는가 | 자동 |
| **프린터** | `printer_name` | varchar(100) | — | 어느 프린터로 찍었는가 | 자동 |
| 비고 | `remarks` | text | — | | 입력 |

**두 제약이 재발행 규칙을 강제한다**

```
uq_document_issue_log      UNIQUE (document_type_code, target_type_code, target_id, issue_seq)
ck_document_reissue_reason CHECK  (issue_seq = 1 OR reissue_reason_code IS NOT NULL)
```

- **같은 대상의 같은 회차는 하나뿐이다** — 재발행하면 회차가 오른다
- **2회차 이상은 사유가 필수다** — 사유 없이 재인쇄할 수 없다

**기록 전용이다** — 감사 컬럼이 `created_*`도 아니고 `issued_*`뿐이다. 발행 기록은 수정하지 않는다.

## §5. 액션·상태

### §5-1. 액션

| 액션 | 활성 조건 | 비고 |
| --- | --- | --- |
| 입하 건 선택 | 항상 | 미부착 건만 목록에 온다 |
| **등록·인쇄** | 대상 선택 + **`can_print_label`** | LOT 생성 + 발행 기록 + 인쇄 §5-2 |
| **재인쇄** | 발행 이력 있음 + 사유 입력 | 회차 증가 §5-3 |
| 프린터 선택 | 프린터 2대 이상 | ⚠ 설치 구성 미정 §8-4 |

### §5-2. 등록·인쇄가 하는 일 — 트랜잭션 경계

```
┌─ 한 트랜잭션 ──────────────────────────────┐
│ ① trace.lot            생성 (Hold)         │
│ ② document_issue_log   발행 기록 (seq=1)   │
└────────────────────────────────────────────┘
                     ↓ 별도
              프린터로 이미지 전송
```

**`W-01-10` §9-2의 조항이 그대로 적용된다** — 프린터는 외부 장치이므로 트랜잭션 밖이다.

프린터가 죽어 있어도 **LOT은 생성되고 기록은 남는다.** 사용자는 프린터를 고친 뒤 **재인쇄**한다(§5-3). 인쇄 실패로 LOT 생성을 롤백하면 같은 자재에 대해 발번을 다시 해야 하고, 그사이 다른 단말이 번호를 가져갈 수 있다.

> **라벨은 서버가 그린다**(결정 18) — POP은 이미지를 받아 프린터로 보낼 뿐이다. 클라이언트가 레이아웃을 그리지 않으므로 **단말마다 라벨이 달라지지 않는다.**

### §5-3. ★ 재발행 — 회차와 사유

```
1회차   등록·인쇄        reissue_reason_code = NULL
2회차   재인쇄 (라벨 훼손)  reissue_reason_code = 필수 ← CHECK가 강제
3회차   재인쇄 (분실)      reissue_reason_code = 필수
```

화면은 재인쇄 시 **사유를 반드시 받는다.** 데이터가 강제하므로 화면이 빠뜨리면 저장이 실패한다.

**왜 사유가 필수인가** — 라벨이 여러 장 돌아다니면 같은 LOT이 두 곳에서 스캔될 수 있다. 재발행 이력이 있어야 「이 라벨이 몇 번째인가」를 추적한다.

> ⚠ **이전 라벨의 무효화**는 데이터에 없다. 3회차를 찍어도 1·2회차 라벨은 물리적으로 남아 있고 스캔된다. **무효 처리 규칙이 미정** — §8-2.

### §5-4. ⚠ 다형 참조가 **네 번째·다섯 번째**다

```
approval_request.target_type_code + target_id       W-01-02
audit_event.target_type_code + target_id            #68
goods_receipt.source_document_type_code + _id       W-01-10
document_issue_log.target_type_code + target_id     ← 네 번째
trace.lot.source_type_code + source_id              ← 다섯 번째
```

**한 도메인에서 다섯 곳이다.** `W-01-10` §9-2가 세 곳 규칙으로 승격시킨 조항이 여기서 다섯 곳이 됐다 — 계약에 반드시 들어가야 한다.

> `document_issue_log`는 특이하게 **`lot_id`를 별도 FK로 따로 갖는다.** 대상이 LOT일 때는 진짜 FK로도 연결된다는 뜻이다. 다형 참조와 FK가 공존하는 유일한 사례이고, **대상이 LOT인 발행이 압도적으로 많을 것**을 데이터가 예상한 것으로 읽힌다.

### §5-5. ★ 단말 게이팅 — `can_print_label`

```
mdm.terminal_process.can_print_label   boolean NOT NULL DEFAULT false
                     UNIQUE (terminal_id, process_id)
```

**이 단말이 이 공정에서 라벨을 찍을 수 있는가**가 데이터로 정해져 있다. 기본값이 **false**이므로 **명시적으로 허용해야** 찍을 수 있다.

화면은 진입 시 이 플래그를 확인하고, 없으면 **「등록·인쇄」를 비활성**하고 사유를 보인다(공유계약 F-1 — 비활성 사유 표시).

> ⚠ **플래그가 8종인데 화면이 쓰는 것은 1종이다.** 나머지 7종(`can_input_material`·`can_input_result`·`can_start_work` 등)은 도메인 02 POP 화면들이 쓴다. **3차에서 게이팅 규약을 본격적으로 세운다** — 지금은 이 화면이 첫 사용처다.

## §9. 이 장에서 나온 공유 계약 후보 — ★ 발행·재발행 신설

1. **발행은 회차로 쌓고 이전 것을 지우지 않는다** — `issue_seq`가 오르고 `UNIQUE(유형, 대상, 회차)`가 중복을 막는다. 재발행은 새 기록이다 (§5-3)
2. **★ 재발행에는 사유가 필수다** — `ck_document_reissue_reason`이 강제한다. 화면이 사유를 받지 않으면 저장이 실패한다 (§5-3)
3. **발행 기록에 단말과 프린터를 남긴다** — `terminal_id`·`printer_name`. 「어디서 몇 번째로 찍었는가」가 추적의 단위다 (§4-A)
4. **인쇄는 트랜잭션 밖이다 — 실패해도 업무 기록은 유효하다** — `W-01-10` §9-2의 두 번째 적용. 프린터 때문에 발번을 롤백하지 않는다 (§5-2)
5. **★ 단말 게이팅은 `terminal_process` 플래그를 따른다** — 화면이 권한을 자체 판단하지 않는다. 기본값이 `false`이므로 **명시적 허용이 없으면 막는다**. 비활성 사유는 F-1을 따른다 (§5-5)
6. **물리적으로 유통되는 출력물은 회차를 인쇄면에도 넣는다** — 데이터에만 회차가 있으면 현장에서 구분할 수 없다 (§8-2)
