## §3. 이 화면이 정하는 것 — 확정 스펙의 표로 옮김

### §3-1. 송신 항목 5종 (WF06 S7 Rule 원문 그대로)

| 송신 항목 | on/off | 확정 조건 | 근거 |
| --- | :-: | --- | --- |
| **생산 실적** | ⛔ **끌 수 없다(필수)** | **개발품은 제외** | QA #35 · QA #4 |
| **G/R**(입고) | ✅ 선택 | **IQC 합격 직후 건별** — 배치 아님 | QA #1 |
| **출하(PGI)** | ✅ 선택 | | REQ-PR-0030 |
| **반품** | ✅ 선택 | | QA #6 |
| **실사조정** | ✅ 선택 | | QA #6 |
| ~~검사 결과~~ | ⛔ **비연계** | **항목 자체가 없다** — 목록에 두지 않는다 | QA #4 |

**⚠ 「필수」와 「비연계」는 토글이 아니다.** 생산 실적은 **끄는 조작 자체를 제공하지 않고**(비활성 + 사유), 검사 결과는 **목록에 나타나지 않는다**. 둘을 「기본값이 켜짐/꺼짐」으로 구현하면 확정이 무너진다 → §9-1.

### §3-2. `app.operation_policy`로 대신할 수 있나

`app.operation_policy`(SQL 2541~)는 「**소스 수정 없이 설정**」 파라미터를 `policy_code` + 범위(사업부·공장·품목·공정) + `value_boolean`으로 담는 범용 테이블이다. 형태상 on/off를 넣을 수는 있다.

**그러나 두 가지가 걸린다.**

1. **관리 화면이 없다** — `W-06-05` §8-6에서 이미 확인했다(인벤토리 109건에 `operation_policy` 화면 없음).
2. **범위 축이 맞지 않는다** — `operation_policy`의 범위는 **사업부·공장·품목·공정**인데, 송신 on/off의 범위는 **I/F 정의 단위**다. `policy_code`에 문자열로 욱여넣으면 **유일 인덱스(`COALESCE(...,0)` 4축 + `effective_from`)가 의미를 잃는다.**

**→ 전용 테이블이 필요하다**(§8-1).

### §3-3. 「부속 항목」이 무엇인지 불명

인벤토리 근거란의 「**부속 항목**」이 무엇을 가리키는지 WF06·도식스펙 원문에서 확인되지 않았다. 송신 건에 딸리는 상세 필드(예: 실적 송신 시 불량 내역 포함 여부)로 **추정**되나 근거가 없다 `[추정]` — **검증: 도식스펙06 §2.4 B13·B14 원문 확인 또는 리더 확인** → §8-4.

## §9. 이 장에서 나온 공유 계약 후보

1. **「필수」·「비연계」는 기본값이 아니라 구조로 표현한다.**
   확정이 「끌 수 없다」(생산 실적)·「연계하지 않는다」(검사 결과)일 때, 화면이 이를 **기본값 on/off로 구현하면 확정이 무너진다** — 누군가 끄거나 켤 수 있기 때문이다. 규약: **「필수」는 비활성 컨트롤 + 확정 번호를 담은 사유** · **「비연계」는 목록에서 제외**(끈 상태로 보이지 않게). F-1·G-2가 세운 「감추지 않는다」의 **예외**이며, 예외인 이유는 **선택지가 아니라 결정 사항**이기 때문이다.
2. **운영에 즉시 영향하는 설정은 부여·회수(즉시 반영)로 두지 않는다.**
   `W-CO-02`·`W-06-03`의 매핑 토글은 즉시 반영이 자연스러웠지만, 송신 on/off는 **끄는 순간 ERP 전표가 끊긴다.** 규약: **영향 범위가 화면 밖(외부 시스템·현장 작업)으로 나가는 설정은 명시적 저장 + 결과를 문장으로 보이는 확인**을 거친다. 판정 기준은 「되돌리면 원상 복구되는가」 — 매핑은 되고, 미송신 기간은 안 된다.
3. **확정 번호를 사용자 문구에 넣는다.**
   「생산 실적 송신은 필수입니다」보다 「**생산 실적 송신은 필수입니다(2026-07-04 확정 QA #35)**」가 낫다. 현장·고객이 「왜 못 바꾸나」를 물을 때 **추적 가능한 근거**가 화면에 있어야 재확인 요청이 정상 경로로 간다. 대상: 필수·비연계·차단처럼 **사용자가 바꿀 수 없는 것 전부**.
