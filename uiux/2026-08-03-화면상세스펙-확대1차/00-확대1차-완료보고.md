## 4. 파급이 화면 하나를 넘는 것 — 2건

### 4-1. 수신본 편집 게이트가 **구현 불가**다 (§I-2)

WF06 S7 Result가 「연계분에 **'Legacy 출처' 플래그** + MES 원천 등록분과 연계분의 **구분 플래그**」를 **신규 설계로 요구**했는데, 대상 마스터 **5개 전수 확인 결과 어디에도 없다**(`item`·`code_value`·`department`·`worker`·`bom`).

→ `W-06-06` §5-4와 `W-06-05`가 세운 게이트(「수신본은 읽기 전용, MES 확장만 편집」)를 **화면이 판정할 수 없다.** 어느 행이 ERP에서 왔는지 알 방법이 없기 때문이다. **✓확정 QA #34가 구현 불가 상태**다.

여기서 공유계약 조항 하나가 나왔다 — **F-3: 게이트를 계약에 적을 때 「무엇을 보고 판정하는가」를 함께 적고 그 컬럼의 실재를 확인한다.** 현재 게이트 넷 중 **하나가 근거를 갖지 못한다.**

### 4-2. 설비보전이 물리 모델 **선언 범위 밖**이다 (§I-12)

물리 모델 v3 머리말이 스스로 범위를 선언한다 — `Scope: MDM, Production, Inventory, Quality, Traceability, Logistics, Integration, Audit`. **보전이 없고 스키마 10개에도 없다.** 설비·툴 테이블은 **셋뿐**(`mdm.equipment`·`mdm.mold`·`quality.equipment_calibration`)이고 점검·고장·보전지시·보전실적·**예비품은 0건**이다.

**✓확정 QA #10**이 「설비 보전 = MES 경량 보유 · 범위 = 점검+고장 수집+보전 계획·지시·실적」이고 **「공백 ≠ 불요」**까지 명시했는데 하류가 범위에서 제외했다.

→ **파급은 `W-06-08` 1건이 아니라 도메인 05 화면 17건 전체**다. **05 상세 스펙 착수 전에 해소돼야 한다** — 확대 1차에서 드러난 것이 다행이다.

| G-8 날짜 입력 | **c** *(b 승격 후보)* | 유효기간 8곳 + 기간 조회 | `DatePicker` **없음** — `TextField type="date"`로 성립하나 **세 셸 렌더 불일치** |
| G-9 파일 업로드 | **c** | 엑셀 DX 2곳(+3곳 예상) | `FileInput` **없음** — 단일 선택은 조합으로 성립 |
| G-10 읽기 전용 구획 | **c** | 6곳 | 잠금 근거 4갈래 · 컴포넌트는 같음 |

**⚠ 판정 절차를 바꿨다.** 확대 1차에서 **인벤토리를 열지 않고 기억으로 적어 오류 2건**을 냈고(`DatePicker`·`FileInput`을 실재하는 것처럼 사용), 반대로 **갭으로 예상한 것이 전용 컴포넌트로 이미 있었다**(`MatrixGrid` — `W-06-03` 공정×불량코드 N:M에 그대로 맞음). 절차를 **① DS 인벤토리 전수 조회 → ② 조합 시도 → ③ 갭 판정**으로 못박았다(`00-서식.md` §6-1은 ②부터 시작한다).

> DS 문서의 경고에 하나를 더한다 — 「없다」의 절반 이상은 **조합**이고, 「없다」의 일부는 **이미 있다.**

### 7-1. ~~남은 질문 1건 — 외주품 입고처~~ → **철회 (2026-08-03)**

「외주품이 한 종류라면 **입고처가 자재창고인가 완제품창고인가**」를 잔여 질문으로 뒀으나, **질문 자체가 잘못 세워졌습니다.** 리더 지적 — 「어떤 자재·제품·반제품이든 어떤 장소로든 이동 가능하지 않나? 공간별 자재 입·출을 제한하는 설계는 없을 텐데」 — 을 받고 실측으로 재확인했습니다.

**창고는 제약이 아니라 입력값입니다.**

| 확인 | 결과 |
| --- | --- |
| 품목유형 × 창고유형을 묶는 제약 | **0건** — `warehouse_type_code`·`item_type_code`가 각각 있을 뿐 CHECK·FK로 연결되지 않음 |
| 재고 조합 제한 | 없음 — `inventory.inventory_balance`가 창고·위치·품목 자유 조합 |
| 적치 규칙 | `logistics.putaway_rule`은 **권장**(수용량·우선순위) · `is_active`로 끌 수 있음 |
| 입고 전표 | **`goods_receipt.warehouse_id`는 건별 입력값** — 마스터가 미리 정하는 값이 아님 |

**화면 경계를 가르는 것도 창고가 아니었습니다.** 실제 축은 **원천 문서**입니다 — `goods_receipt.receipt_type_code` · `source_document_type_code`+`source_document_id`. 그리고 `goods_receipt_line.inbound_receipt_line_id`가 **nullable**이라 **입하를 거치지 않는 입고가 정상 경로**로 설계돼 있습니다. 외주 회수 경로도 하류가 이미 정했습니다 — `subcontract_receipt.goods_receipt_id` → `goods_receipt`(SQL 2249). 구매 입하와 **원천 문서가 다르므로 화면은 자연히 갈립니다.**

→ **#53은 종결 가능**합니다. 「자재창고 ↔ 완제품창고」는 애초에 대립이 아니었고, 두 문서가 같은 단어를 쓰는 것은 표현 중복입니다. 이슈에 정정 코멘트를 달았습니다.

### 7-1-1. 대신 실제로 남는 것 — **외주 화면이 0건입니다**

대조하다 다른 것이 보였습니다. **외주 트랜잭션 테이블 4종이 실재하는데 대응 화면이 없습니다.**

| 테이블 | 무엇 |
| --- | --- |
| `logistics.subcontract_order` | 외주 발주(작업지시·거래처·공정·품목·수량·회수예정일·상태) |
| `logistics.subcontract_issue` | 외주 반출(`goods_issue` 연결) |
| `logistics.subcontract_receipt` | 외주 회수(`goods_receipt` 연결·공급사 LOT) |
| `logistics.subcontract_reconciliation` | **외주 수량 정산** — 「출고 = 입고 + 잔량 + 불량 + 폐기 + 분실 + 조정」의 유형별 차이수량과 **정산확정 기록** |

화면 108건 중 「외주」가 나오는 곳은 `W-06-01`(Routing 외주 공정 구분)과 `M-04-04`(제품입고 근거 문구) **둘뿐**이고, **발주·반출·회수·정산 화면이 없습니다.** 특히 정산은 사람이 확정하는 업무입니다.

**다만 지금 물을 것은 아닙니다.** 「외주품 관리 설계가 완성되어 있지 않으니 최소 구조만 두고 **추후 구체화**」라는 확정이 이미 있으므로, **그 설계가 서는 시점에 화면 도출을 함께** 하면 됩니다. 기록만 남깁니다.
