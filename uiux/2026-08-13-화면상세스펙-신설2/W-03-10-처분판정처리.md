# `W-03-10` 처분 판정 처리(재작업/폐기/정상)

> ⭐ **DR-008 확정 3-A 로 신설된 화면**(2026-08-13). 인벤토리 **116 → 117**.
>
> **왜 없었나** — `F04` 정합 확정(2026-07-07)이 「재작업/폐기 **판정**은 전 도메인에서 **03 소관** 통일」이라 했는데 **03 의 다섯 화면에 그 화면이 만들어지지 않았다.** 03 요구서는 `disposition_decision` 을 「04 것」이라 넘겼고, `W-04-07` 은 「03 이 만든다 · 04 는 의뢰만」이라 적었다 — **서로에게 미뤘다.**
>
> 04 계약 트랙 1단계에서 **116화면 액션을 전수로 뽑아** 처분을 저장하는 화면이 **0건**임을 확인했다.

### §2-1. ⭐ 데이터가 「사람이 화면에서 정한다」를 말하고 있었다

```sql
quality.disposition_decision
    nonconformance_id      NOT NULL   ← 부적합이 선행한다
    disposition_type_code  NOT NULL   ← 재작업 · 폐기 · 정상
    decision_qty           NOT NULL CHECK (> 0)   ⭐ 부분 처분이 된다
    uom_id                 NOT NULL
    reason                 text NOT NULL          ⭐ 사람이 쓴다
    decided_by             NOT NULL → app.app_user  ⭐ 사람이 정한다
    decided_at             NOT NULL
    approval_request_id                            ← 승인이 붙을 수 있다
```

⭐ **`decided_by`·`reason` 이 NOT NULL 이라 자동 판정이 아니다.** ⚠ `M-01-13` 때와 같은 형태다 — 「이 `NOT NULL` 을 누가 채우나」를 사람으로 답해 보니 **앞단계 화면이 빠져 있었다**(공유계약 **A-24**).

### §5-2. ⭐ 판정 저장과 Lot Status 전이는 **한 트랜잭션**이다

```
disposition_decision INSERT
        +
trace.lot.status_code UPDATE      ← 재작업 → 검사 대기 / 폐기 → 폐기 / 정상 → 정상
```

**공유계약 B-8**(§5-2)**.** 처분만 남고 LOT 이 안 바뀌면 **다음 화면이 잘못된 대상을 집는다** — `W-04-11`(재등록)이 아직 불량인 LOT 을 정상으로 본다.

⚠ **Lot Status 변경이력 테이블이 없다**(`#64`·`#68`) — 전이는 되지만 **누가 왜 바꿨는지가 남지 않는다.** 공유계약 **A-11** 대로 화면이 그 사실을 결과 표 머리에 적는다.

### §5-3. ⭐ 이 화면이 푸는 것 — 세 화면의 진입

| 화면 | 진입 조건 | 지금까지 |
| --- | --- | :-: |
| `W-04-10` 제품 폐기 | 처분 = **폐기** | ⏳ 목록이 비었다 |
| `W-04-11` 재고 재등록 | 처분 = **정상** | ⏳ |
| `P-04-03` 재작업 실적 | 처분 = **재작업** | ⏳ |

### §5-4. ⛔ 이 화면은 **부적합을 만들지 않는다**

부적합 등록·판정 의뢰는 **`W-04-07`**(04)이 한다. **소유가 갈린다** — 공유계약 **B-13**.

| 테이블 | 쓰는 화면 | 계약 |
| --- | --- | --- |
| `nonconformance` · `_lot` | `W-04-07` (04) | **제품출하** |
| ⭐ `disposition_decision` | **`W-03-10`** (03) | **품질** |

⚠ **02 수리·01 자재 불량도 여기로 온다** — 「판정 기준이 하나여야 한다」가 `F04` 확정의 취지다. 그래서 ① 에 **원천 필터**를 둔다.

## §9. 공유 계약 후보

1. ⭐ **부분 처분의 잔량은 서버가 낸다** — 「남은 수량 = 대상 수량 합 − 결정 수량 합」을 **클라이언트가 계산하지 않는다**. L-2 의 사례 추가이지 신설이 아니다
2. ⚠ **판정 화면과 의뢰 화면이 갈릴 때 의뢰 화면은 「여기서 판정하지 않는다」를 상시 표시한다** — `W-04-07` 이 이미 그렇게 하고 있다. **B-13 의 화면 판** 후보
