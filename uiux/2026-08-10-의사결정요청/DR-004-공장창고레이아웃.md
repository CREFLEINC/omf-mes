## 1. 무엇을 결정해야 하는가

**「알람이 난 설비가 공장 어디에 있는지」를 화면에 어떻게 보여 줄 것인가.**

결정할 항목은 **셋**입니다.

| # | 결정 항목 | 선택지 |
| :-: | --- | --- |
| **4-A** | **평면 배치도를 그릴 것인가** | 도면 위에 표시한다 / 목록·계층으로 대신한다 |
| **4-B** | **배치도를 그린다면 무엇으로 만드는가** | 우리가 도면 편집기를 만든다 / 이미지 위에 점을 찍는다 |
| **4-C** | **1차 범위에 넣는가** | 넣는다 / 뒤로 미룬다 |

## 2. 왜 결정해야 하는가

### 2-1. ⚠ 요구사항 원문에 **「고객 확인 필요」가 이미 적혀 있습니다**

요구사항 **REQ-PR-0036** 원문입니다.

> 대시보드 — 일일생산실적 및 알람발생 설비 위치 표시 **(현장 공장·창고 레이아웃 배치 요청해야 함)**
> To-Be: **원하시는 구성 정보 확인 필요**

⭐ **「배치를 요청해야 한다」와 「구성 정보 확인 필요」가 요구사항 단계부터 표시돼 있습니다.** 이 요구는 **처음부터 미완성 상태로 들어왔습니다.**

⛔ **그리고 그 확인이 지금까지 이뤄지지 않았습니다.** 개념 데이터 모델도 「구성 정보·배치도는 **고객 확인 대기**」라고 같은 말을 적어 두었습니다.

### 2-2. 개념에는 있고 물리에는 없습니다

| 층 | 상태 |
| --- | --- |
| **개념 모델 v2.0** | 「공장/창고 레이아웃(master)」 **엔티티 실재** — 「대상(공장/창고) · 구역 · **좌표** · 설비/Location 위치 매핑」 |
| **설비 마스터** | 속성에 「**레이아웃 위치**(→ 공장/창고 레이아웃 master)」 명시 |
| **관계** | 「레이아웃–설비/Location 1:N」 명시 |
| **물리 모델** | ⛔ **좌표 관련 전 파일 검색 0건** |

⭐ **§I-12(설비 보전)와 같은 형태입니다** — 상류가 앞서고 하류가 못 따라간 것이지 **개념이 없는 것이 아닙니다.**

### 2-3. ⛔ 설비가 어디 있는지도 모릅니다 — **더 앞선 문제**

배치도 이전에 **더 기본적인 것이 없습니다.**

| 무엇 | 실측 |
| --- | --- |
| 설비 마스터에 **위치** | ⛔ 없다 (`production_line_id` 만 있다) |
| 위치 마스터에 **설비** | ⛔ 없다 |
| 위치 마스터에 **평면 좌표** | ⛔ 없다 (창고·상위위치·유형·수용량만) |

**이슈 #81 이 이미 발행돼 있습니다** — 「호퍼를 지정할 수 없다 — 설비↔위치 매핑이 어느 방향으로도 없다」.

⚠ **배치도는 「설비가 어느 구역에 있는가」를 아는 상태에서만 그릴 수 있습니다.** 그것이 먼저입니다.

### 2-4. 걸려 있는 것

| 화면 | 무엇이 안 되나 |
| --- | --- |
| **웹-공장창고-레이아웃마스터** | **화면 전체** — 배치를 등록할 곳이 없다 |
| **웹-통합대시보드** | **「알람 발생 설비 위치 표시」** — 요구사항의 핵심 문구 |

⚠ **통합 대시보드는 DR-003(알림)에도 걸려 있었습니다.** 그쪽은 확정됐고 **이것 하나가 남습니다.**

## 3. 결정 항목별 상세

### 3-A. 평면 배치도를 그릴 것인가

#### 안 가 · 도면 위에 표시한다

```
┌─ 1공장 평면도 ──────────────────────┐
│   ┌───┐  ┌───┐  ┌───┐              │
│   │설1│  │설2│  │설3│ ← 🔴 알람     │
│   └───┘  └───┘  └───┘              │
│   ┌─────────────┐                   │
│   │  자재창고    │                   │
│   └─────────────┘                   │
└─────────────────────────────────────┘
```

| | |
| --- | --- |
| **보이는 것** | 한눈에 **어디인지** 안다. 현장을 아는 사람에게 직관적이다 |
| **필요한 것** | 평면 좌표 · **도면 배경** · 설비마다 좌표 지정 · 화면에 그리는 부품 |
| **선행 조건** | ⛔ **설비↔위치 매핑**(#81)이 먼저 |

#### 안 나 · 목록·계층으로 대신한다

```
🔴 알람  1공장 > A라인 > 사출기 3호     10:23  과열
🔴 알람  1공장 > B라인 > 성형기 1호     10:19  정지
⚠ 경고  자재창고 > A구역               09:55  재고 부족
```

| | |
| --- | --- |
| **보이는 것** | **어느 공장·어느 라인·어느 설비**인지 글로 안다 |
| **필요한 것** | 설비에 **소속 계층**만 있으면 된다 (공장 > 라인 > 설비) |
| **선행 조건** | 설비 마스터에 라인 참조가 **이미 있다** |

### 3-B. 배치도를 그린다면 무엇으로 만드는가

안 가를 택할 때만 해당합니다.

| 안 | 방식 | 만드는 부담 |
| :-: | --- | --- |
| **가** | **도면 편집기를 만든다** — 구역을 그리고 크기를 조절하고 설비를 배치 | ⛔ **크다.** 그리기 도구 하나가 화면 여러 장 분량이다 |
| **나** | **이미지 위에 점을 찍는다** — 고객사가 준 도면 이미지를 올리고, 설비마다 그 위 좌표를 클릭해 지정 | 작다. 이미지 업로드 + 클릭 좌표 저장 |

⚠ **디자인 시스템에 도면 편집 부품이 없습니다** — 그리기 도구는 **새로 만드는 원시 요소**라 가장 비쌉니다.

### 3-C. 1차 범위에 넣는가

| | |
| --- | --- |
| **요구사항 분류** | REQ-PR-0036 은 원문에 **「비기능」**으로 기재돼 있습니다 |
| **완성도** | 「배치 요청해야 함」·「구성 정보 확인 필요」 — **고객사가 아직 무엇을 원하는지 말하지 않았습니다** |
| **선행 미결** | 설비↔위치 매핑(#81)이 안 풀렸습니다 |

## 4. 결정되면 어디에 영향을 주는가

| 결정 | 영향 |
| --- | --- |
| **4-A 안 가**(도면) | 웹-공장창고-레이아웃마스터 화면이 **선다.** 통합 대시보드에 도면 구획이 생긴다. 디자인 시스템에 **새 부품 요청**이 필요하다 |
| **4-A 안 나**(목록) | ⛔ **웹-공장창고-레이아웃마스터 화면이 없어진다**(인벤토리 115 → 114). 통합 대시보드는 **알람 목록**만 보인다 |
| **4-B 안 나**(이미지) | 화면 부담이 크게 준다. 다만 **도면 이미지를 고객사가 줘야 한다** |
| **4-C 미룸** | 두 화면이 **1차 범위에서 빠진다.** 통합 대시보드는 알람 목록으로 서고 나중에 도면 구획을 얹는다 |

### 4-1. 다른 확정과의 관계

| 확정 | 무엇이 걸리나 |
| --- | --- |
| **DR-003 알림** | 통합 대시보드가 **알림센터와 같은 원천**을 본다. 위치 표시가 없어도 **알람 목록은 선다** |
| **#81 설비↔위치** | 도면을 그리든 목록을 쓰든 **설비가 어디 소속인지**는 필요하다 |

## 5. 권고안

### 5-A. **안 나 — 목록·계층으로 대신한다**

**이유 넷입니다.**

1. **요구사항이 미완성입니다.** 원문에 「배치 요청해야 함」·「구성 정보 확인 필요」가 적혀 있고, **고객사가 무엇을 원하는지 아직 말하지 않았습니다.** 추측해서 만들면 다시 만듭니다.
2. **요구의 목적은 「위치를 안다」이지 「도면을 본다」가 아닙니다.** 원문은 「알람발생 설비 **위치 표시**」입니다. 「1공장 > A라인 > 사출기 3호」도 위치 표시입니다.
3. **선행이 안 풀렸습니다.** 설비↔위치 매핑(#81)이 없으면 도면에 점을 찍을 대상 자체가 없습니다.
4. **가장 비싼 부품입니다.** 도면 편집은 디자인 시스템에 없는 새 원시 요소이고, 화면 여러 장 분량입니다.

### 5-B. **(안 가를 택하실 경우) 안 나 — 이미지 위에 점을 찍는다**

도면을 그리기로 하시면 **편집기를 만들지 않습니다.** 고객사 도면 이미지를 올리고 그 위에 설비 좌표만 지정합니다. **공장 배치는 자주 바뀌지 않으므로** 편집기를 만들 만한 빈도가 아닙니다.

### 5-C. **뒤로 미룬다 — 다만 화면을 지우지는 않는다**

| 무엇 | 어떻게 |
| --- | --- |
| **웹-공장창고-레이아웃마스터** | 인벤토리에 **남기되 「보류」로 표시** — 고객사 구성 정보 확인 후 착수 |
| **웹-통합대시보드** | **지금 쓴다.** 알람 목록·일일 생산실적으로 서고 **위치는 계층 텍스트**로 보인다 |

⭐ **화면을 지우지 않는 이유** — 요구사항 REQ-PR-0036 이 명시적으로 요구한 것이라 **없애면 요구 누락**이 됩니다. **보류는 「안 한다」가 아니라 「고객 확인 후」입니다.**

---

## 6. ⚠ 고객사에 물어야 할 것

**5-C 로 가면 물어볼 것이 생깁니다.** 정직하게 적습니다.

> **공장·창고 배치도를 화면에 띄우고 알람 위치를 그 위에 표시하기를 원하십니까?**
> **원하신다면 배치도(도면 이미지 또는 구역 목록)를 주실 수 있습니까?**

⚠ **이것은 회신을 기다리는 미결이 아닙니다** — 통합 대시보드는 그 답 없이도 섭니다. **레이아웃 마스터 화면 하나만** 그 답을 기다립니다.
