# 의사결정 요청서 **DR-006** — 재생재를 품목 체계에 어떻게 등록하는가

| 항목 | 내용 |
| --- | --- |
| 번호 | **DR-006** |
| 작성일 | 2026-08-10 |
| 요청 대상 | 팀 리더 |
| 막고 있는 화면 | **1장** — 모바일-재생재-등록(`M-01-12`) · **마지막 동결 화면** |
| 관련 이슈 | **#64**(품목 확장속성 미착지 — 재생재 하위 코드) |

## 1. 무엇을 결정해야 하는가

**분쇄해서 다시 쓰는 재료(재생재)를 시스템에서 어떻게 구분하는가.**

⚠ **「어떻게 구분할지」의 큰 틀은 이미 확정돼 있습니다.** 남은 것은 **그 구분을 어디에 붙이는가**입니다.

| # | 결정 항목 | 선택지 |
| :-: | --- | --- |
| **6-A** | **하위 코드를 어디에 붙이는가** | 품목에 붙인다 / 자재 묶음(LOT)에 붙인다 |
| **6-B** | **누구에게 감추는가** | 권한으로 감춘다 / 화면마다 정한다 |
| **6-C** | **현장에서 어떻게 등록하는가** | 발생 즉시 등록 / 출고와 묶어서 |

---

## 2. 왜 결정해야 하는가

### 2-1. 확정은 있는데 **붙일 자리가 없습니다**

2026-07-04 현장검증 문답 31번이 이렇게 확정했습니다.

> ① 비노출 범위 — **ERP 동기화 제외** + **고객사 향 문서·라벨·보고서 제외** + **일반 화면 숨김**(권한 관리자만)
> ② **내부 이력은 완전히 기록**한다
> ③ **구조: 품목 코드 = 기간계 시스템과 같은 코드 1개**(새 재료·재생 재료 공통) **+ 하위 코드**(예: 생산처 코드)**로 시스템 내부에서만 구분**

**품목 마스터를 실측하니 하위 코드를 담을 칸이 없습니다.**

```
mdm.item — 품목코드 · 품목명 · 유형 · 기본단위 · LOT 관리 · 유효기한 ·
           검사 필요 · 선출 정책 · 마이너스 재고 허용 · 보관 조건 · 개봉 후 시간
           (재생재 하위 코드 없음)
```

**전 파일 검색에서 재생 관련 컬럼 0건**입니다.

### 2-2. ⚠ 확정 문구가 **두 가지로 읽힙니다**

> 품목 코드 = 같은 코드 1개 **+ 하위 코드로 내부 구분**

**「하위 코드」가 무엇에 붙는지가 문장으로 갈리지 않습니다.**

| 읽기 | 뜻 | 결과 |
| --- | --- | --- |
| **품목에 붙는다** | 같은 품목코드 아래 「새 재료 / 재생 재료」 두 개의 하위 품목이 있다 | 품목이 2배로 는다 |
| **자재 묶음에 붙는다** | 품목은 하나이고, **들어온 묶음마다** 「이건 재생재」를 표시한다 | 품목은 그대로 |

⭐ **재생재는 「사건」으로 발생합니다** — 분쇄가 일어날 때마다 생깁니다. **품목이 아니라 그때 생긴 물량에 붙는 성격**으로 보이는데, 확정 문구는 「품목 코드 + 하위 코드」라 품목 쪽으로 읽히기도 합니다.

### 2-3. 걸려 있는 것 — **마지막 동결 화면**

| 화면 | 무엇을 하나 |
| --- | --- |
| **모바일-재생재-등록**(`M-01-12`) | 분쇄재가 생기면 현장에서 **품목코드 + 하위 코드 2단으로 등록**하고 생산창고 재고에 반영한다 |

⭐ **동결 20장 중 19장이 DR-001 로 풀렸고 이것 하나가 남았습니다.**

## 3. 결정 항목별 상세

### 3-A. 하위 코드를 어디에 붙이는가

#### 안 가 · 품목에 붙인다

```
품목코드 ABC-100  (기간계 시스템과 같은 코드)
   ├─ 하위 「신재」
   └─ 하위 「재생」   ← 재고·이력이 여기로 갈린다
```

| | |
| --- | --- |
| **장점** | 재고를 볼 때 새 재료와 재생 재료가 **처음부터 갈려 있다** |
| **단점** | ⛔ **품목 마스터가 2배가 된다.** 기간계 시스템에서 받은 품목마다 재생 하위를 만들어야 하는데, **재생재가 안 생기는 품목에도 만들지 판단이 필요**하다 |
| | ⛔ **기간계 시스템 동기화가 꼬인다** — 받은 코드 1개에 우리가 하위 2개를 붙이면 되돌려 보낼 때 합쳐야 한다 |

#### 안 나 · 자재 묶음(LOT)에 붙인다

```
품목코드 ABC-100  (하나)
   └─ 자재 묶음 LOT-2026-0001  구분 = 신재
   └─ 자재 묶음 LOT-2026-0002  구분 = 재생   ← 분쇄로 생긴 것
```

| | |
| --- | --- |
| **장점** | 품목은 기간계 시스템과 **1:1 그대로**다. 재생재는 **생긴 묶음에만** 표시된다 |
| | 이력이 자연스럽다 — **어느 묶음에서 나와 어느 묶음이 됐는지**가 이미 묶음 단위로 기록된다 |
| **단점** | 재고를 볼 때 **구분 축으로 걸러야** 새 재료·재생 재료가 갈린다 |

⭐ **재고는 이미 구분 축을 여럿 갖고 있습니다** — 품질 상태·재고 상태·소유 형태가 각각 재고를 가르는 차원입니다. **하나 더 늘리는 것이 구조상 자연스럽습니다.**

### 3-B. 누구에게 감추는가

**확정된 비노출 범위 셋**입니다.

| 어디 | 감추는가 |
| --- | :-: |
| 기간계 시스템으로 보내는 데이터 | ✅ 제외 |
| 고객사에 나가는 문서·라벨·보고서 | ✅ 제외 |
| 시스템 일반 화면 | ✅ 숨김 — **권한 관리자만** |

| 안 | 방식 |
| :-: | --- |
| **가 · 권한으로** | 「재생재 조회」 권한을 가진 사람에게만 구분 축이 보인다. **한 곳에서 정한다** |
| **나 · 화면마다** | 화면 설계에서 각각 「여기서는 보인다 / 안 보인다」를 정한다 |

### 3-C. 현장에서 어떻게 등록하는가

| 안 | 방식 |
| :-: | --- |
| **가 · 발생 즉시** | 분쇄가 일어나면 **바로 등록**한다. 출고와 무관한 독립 사건 |
| **나 · 출고와 묶어서** | 재생재를 쓸 때 함께 등록한다 |

⚠ **인벤토리가 이미 「가」로 적어 두었습니다** — 「출고분 입고와 무관하게 발생하는 **독립 사건**이라 별도 화면」.

## 4. 결정되면 어디에 영향을 주는가

| 결정 | 영향 |
| --- | --- |
| **6-A 안 가**(품목) | 웹-품목-마스터에 **하위 코드 관리 구획**이 생긴다. 기간계 연계 화면에 **합치는 규칙**이 필요하다 |
| **6-A 안 나**(묶음) | 모바일-재생재-등록에서 **구분을 지정**한다. 재고 조회 화면들에 **구분 축 필터**가 는다 |
| **6-B 안 가**(권한) | 권한 값 목록에 「재생재 조회」가 는다 — **회신 E-9**(권한 매트릭스)와 연결 |
| **6-C 안 가**(즉시) | 화면 그대로. 인벤토리가 이미 그렇게 잡았다 |

### 4-1. 이미 쓴 화면

| 화면 | 무엇이 걸리나 |
| --- | --- |
| **웹-품목-마스터**(`W-06-05`) | 6-A 안 가면 구획이 하나 는다 |
| **모바일-생산창고입고-호퍼잔량**(`M-01-09`) | 재생재 등록이 **여기서 분리돼 나간 화면**이다 |
| **웹-기간계연계-송신**(`W-06-12`) | 재생재를 **송신에서 빼는 규칙**이 필요하다 |
| **재고 조회 계열** | 6-A 안 나면 구분 축 필터가 는다 |
| **출력물 화면들**(라벨·성적서) | 고객사 향 문서에 재생 구분이 **나가면 안 된다** |

## 5. 권고안

### 5-A. **안 나 — 자재 묶음(LOT)에 붙인다**

**이유 넷입니다.**

1. **재생재는 사건으로 생깁니다.** 분쇄할 때마다 생기고, 같은 품목이라도 어떤 묶음은 새 재료이고 어떤 묶음은 재생입니다. **묶음의 성질이지 품목의 성질이 아닙니다.**
2. **기간계 시스템과 1:1 이 깨지지 않습니다.** 확정 문구가 「**기간계와 같은 코드 1개**」를 강조한 이유가 이것이라고 봅니다. 품목을 쪼개면 그 1:1 이 무너집니다.
3. **재고가 이미 여러 축으로 갈립니다.** 품질 상태·재고 상태·소유 형태가 각각 재고를 가르는 차원이고, **구분 축 하나를 더하는 것이 구조상 같은 형태**입니다.
4. **이력이 자연스럽습니다.** 확정이 요구한 「내부 이력 완전 기록」은 **묶음 사이의 관계**로 기록됩니다 — 어느 묶음을 분쇄해 어느 묶음이 됐는지. **품목 단위로는 그 관계를 적을 수 없습니다.**

⚠ **확정 문구와 어긋나지 않습니다** — 「품목 코드 1개 + 하위 코드로 내부 구분」에서 **「품목 코드 1개」가 핵심**이고, 하위 코드가 품목에 붙어야 한다고는 적혀 있지 않습니다.

### 5-B. **안 가 — 권한으로 감춘다**

**이유 둘입니다.**

1. **확정이 「권한 관리자만」이라고 명시**했습니다. 화면마다 정하면 **한 곳을 빠뜨렸을 때 새어 나갑니다.**
2. **감출 곳이 셋이고 성격이 다릅니다** — 기간계 송신·고객사 문서·일반 화면. **화면마다 정하면 앞의 둘을 놓칩니다.**

### 5-C. **안 가 — 발생 즉시 등록**

인벤토리가 이미 그렇게 판정했고 **되돌릴 근거가 없습니다.** 분쇄는 출고와 별개로 일어납니다.

## 6. ⚠ 이 결정이 남기는 것

| 무엇 | 왜 |
| --- | --- |
| **하위 코드의 값 목록** | 확정이 「예: 생산처 코드」라고만 적었습니다. **무엇을 하위 코드로 쓸지**는 정해지지 않았습니다 |
| **권한 값 목록** | 「재생재 조회」 권한이 필요한데 권한 값 목록 자체가 **회신 E-9 대기**입니다 |

⚠ **둘 다 화면을 막지는 않습니다** — 구분 축이 있고 권한으로 가린다는 것만 정해지면 화면은 섭니다. **값은 나중에 채웁니다.**
