# 의사결정 요청서 **DR-007** — W/O 를 취소하면 **선발행된 생산LOT 을 어떻게 하는가**

| 항목 | 값 |
| --- | --- |
| 요청일 | 2026-08-11 |
| 요청 주체 | CREFLE OMF 팀 (UI/UX) |
| 결정 주체 | 팀 리더 |
| 상태 | ⏳ **요청** — ⭐ **R26·R27 실측으로 권고가 좁혀졌습니다**(§4) |
| 막고 있는 것 | ⚠ **막지 않습니다** — 계약은 미결을 드러내고 갑니다 · §6 |

---

## 1. 무엇을 결정해야 하는가

**작업지시(W/O)를 취소할 때, 이미 발행해 둔 생산LOT 번호를 어떻게 처리할지**입니다.

```
W/O 확정·배포  →  생산LOT 번호를 미리 발행 (선발행)
                  ↓
              W/O 취소
                  ↓
              그 LOT 번호는?   ← 이것이 미정입니다
```

## 2. 왜 지금 결정해야 하는가

### 2-1. 「취소」는 확정됐고 **회수만 남았습니다**

**워크플로우 예외 E-4 ④** 가 이렇게 남겼습니다.

> **취소 상태 신설은 확정** · **선발행 LOT 회수 규칙은 잔여**

**세 화면이 같은 내용을 적고 있습니다.**

| 화면 | 원문 |
| --- | --- |
| `W-02-06` P/O 변경 관리자 확인 §5-5 | 「**W/O를 취소해야 한다** — 예외 E-4 ④가 「취소 상태 신설 **확정**·선발행 LOT 회수 규칙 **잔여**」로 남겼다」 |
| `W-02-04` W/O 확정·배포 §8-6 | 「배포 후 W/O 수정·취소 — **취소 상태 신설은 확정** · 선발행 LOT 회수 규칙은 잔여」 |
| `W-02-08` W/O 진행현황 §8-3 | 「`work_order.status_code` 값 목록 — **「취소」가 오면 카드가 는다**」 |

### 2-2. ⛔ **기존 규칙이 취소를 덮지 못합니다**

**R82** 가 「**마감 시점** 자동 폐번」을 정했습니다. ⚠ **마감 경로**이고 **취소 경로가 아닙니다.**

| 경로 | 규칙 |
| --- | :-: |
| **마감** | ✅ R82 — 자동 폐번 |
| **취소** | ⛔ **없습니다** |

### 2-3. 계약이 지금 이 상태입니다

02 생산실행 API 2단계가 `:cancel` 을 이렇게 적었습니다.

```
POST /production/work-orders/{workOrderId}:cancel
  ✅ 취소 상태 신설은 확정
  ⛔ 선발행 LOT 회수 규칙이 잔여 — 이 액션의 부수 효과를 계약이 못 적는다
```

⚠ **저희가 임의로 정하지 않았습니다** — 「폐번한다」로 적으면 **운영에서 다른 결과**가 나올 수 있습니다.

### 2-4. 데이터는 준비돼 있습니다

```
trace.lot.status_code   app.code_t NOT NULL DEFAULT 'ACTIVE'   (SQL 1053)
```

⭐ **v1.5 에서 「폐번」 값이 이미 정의**됐습니다(공유계약 §I · LOT 상태 4값 확정). **자리는 있고 「언제 그 값이 되는가」가 미정**입니다.

## 3. 결정 항목 — **안 셋**

### 3-A · **취소 즉시 폐번한다**

W/O 취소와 함께 선발행 LOT 을 전부 `폐번` 으로 바꿉니다.

| ✅ | ⛔ |
| --- | --- |
| **R82(마감 폐번)와 같은 모양** — 규칙이 하나로 읽힌다 | **번호가 버려진다** — 채번 규칙이 일련번호면 구멍이 생긴다 |
| 계약이 단순하다 — `:cancel` 의 부수 효과 한 줄 | ⚠ **이미 라벨을 붙였으면** 현장에 폐번된 번호가 돌아다닌다 |
| 되돌릴 필요가 없다 | |

### 3-B · **다른 W/O 로 이관한다**

같은 품목의 다른 W/O 에 그 LOT 번호를 넘깁니다.

| ✅ | ⛔ |
| --- | --- |
| 번호를 버리지 않는다 | ⛔⛔ **받을 W/O 를 누가 고르는가** — 화면이 하나 는다 |
| 라벨을 다시 안 붙여도 된다 | ⛔ **`trace.lot.source_id` 가 가리키는 W/O 가 바뀐다** — 계보가 흔들린다 |
| | ⚠ **자동으로 못 한다** — 사람이 고르는 절차가 필요하다 |

### 3-C · **보류하고 수동 처리한다**

취소 시 LOT 을 `보류` 상태로 두고, 나중에 사람이 폐번하거나 되살립니다.

| ✅ | ⛔ |
| --- | --- |
| **되돌릴 수 있다** — 취소를 번복할 때 유용 | ⛔ **보류 목록을 보는 화면이 없다** — 방치된다 |
| 현장 라벨과 충돌하지 않는다 | ⚠ **「보류」 값이 LOT 상태 4값에 있는가** 확인 필요 |
| | ⚠ **누가 언제 정리하는가**가 다시 미정이 된다 |

## 4. ⭐⭐ 저희 권고 — **3-A(취소 즉시 폐번)** · **근거를 실측했습니다**

**처음에는 「선발행 시점에 라벨을 붙이는지 저희가 모릅니다」로 적었습니다. 재 보니 답이 있었습니다.**

### 4-1. **R26 · R27 이 이미 답을 갖고 있습니다**

`W-02-04` §2 근거에 확정 원문이 그대로 있습니다.

> **R26** 생산LOT = MES 발행 정본 · **W/O 배포 시 선발행**(**번호 슬롯 예약** · ⭐ **완료 전 실물 미귀속**) — ✓확정 2026-06-24 · 2026-07-15
> **R27** N = 계획값 — 초과 시 추가 발번 · ⭐ **미달 슬롯 = S12 마감 자동 폐번**

| 제가 걱정했던 것 | 실측 |
| --- | --- |
| 「라벨을 이미 붙였으면 폐번된 번호가 현장에 남는다」 | ⛔ **안 붙습니다** — **완료 전 실물 미귀속**(R26). `W-02-04` 에 인쇄 액션 **0건** |
| 「번호를 버리는 것이 맞는가」 | ⭐ **이미 버리고 있습니다** — **미달 슬롯은 마감 시 자동 폐번**(R27) |

⭐ **취소 시 폐번은 새 규칙이 아니라 R27 의 자연스러운 확장입니다.**

```
마감  →  미달 슬롯 자동 폐번   (R27 · R82)   ← 이미 확정
취소  →  선발행 슬롯 자동 폐번  (이 결정)     ← 같은 모양
```

### 4-2. 그래서 3-B·3-C 는 **근거가 약합니다**

| 안 | 왜 약한가 |
| :-: | --- |
| **3-B** 이관 | 번호를 아끼자는 것인데 **R27 이 이미 미달 슬롯을 버리고 있습니다.** 아낄 이유가 없습니다 |
| **3-C** 보류 | 되돌릴 필요를 전제하는데 **취소 번복 시나리오가 워크플로우에 없습니다.** 게다가 **보류 목록 화면이 늡니다** |

### 4-3. ⚠ 그래도 **결정을 요청드리는 이유**

**예외 E-4 ④ 가 「회수 규칙 잔여」로 명시적으로 남겼기 때문**입니다. R26·R27 로 읽으면 3-A 가 맞아 보이지만, **그때 잔여로 둔 이유가 따로 있을 수 있습니다.**

⛔ **저희가 「R26 으로 보면 자명하니 그냥 3-A 로 간다」고 넘기지 않습니다** — 확정 기록이 명시적으로 남긴 것을 우리가 닫지 않습니다.

⚠ **이전에 제 권고가 세 번 뒤집혔고 세 번 다 리더님이 옳으셨습니다**(Zalo · 평면 배치 · 재생재). 실측을 붙였지만 **제가 못 본 축이 또 있을 수 있습니다.**

### 4-4. ⭐ 여쭙는 것은 사실상 하나입니다

> **「마감 시 미달 슬롯 자동 폐번(R27)과 같은 규칙을 취소에도 적용합니까?」**

**예** 라면 계약 한 줄이면 끝납니다.

## 5. 이 결정이 낳는 것

| 안 | 무엇이 생기나 |
| :-: | --- |
| **3-A** | 계약 한 줄 — `:cancel` 의 부수 효과. **신설 0** |
| **3-B** | **화면 1 신설** + `source_id` 재지정 규칙 + 계보 영향 검토 |
| **3-C** | **화면 1 신설**(보류 목록) + LOT 상태 값 확인 + 정리 주체 결정 |

## 6. ⚠ **막고 있지 않습니다**

02 계약 4단계(OpenAPI 작성)는 **`:cancel` 경로를 적고 부수 효과를 미결로 드러내는 것**으로 진행합니다. **결정이 오면 `x-internal-note` 한 줄이 본문으로 올라갑니다.**

⛔ **다만 결정 전에는 구현팀에 착수 통지를 낼 수 없습니다** — 「취소하면 무엇이 일어나는가」를 못 적기 때문입니다.
