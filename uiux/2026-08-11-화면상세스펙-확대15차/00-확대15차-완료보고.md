## 2. ⭐⭐ DR-001 이 2026-08-10 에 푼 동결 19장이 **하루 만에 끝났다**

| 차수 | 무엇 | 몇 |
| :-: | --- | :-: |
| 11차 | 05 마스터 | 3 |
| 12차 | 05 현장 입력 | 4 |
| 13차 | 05 사무 처리 | 5 |
| 14차 | 05 집계·설정 | 5 |
| **15차** | **POP 2**(생산실행 소속이나 설비 점검에 의존) | **2** |

⭐ **DR-001 §7 이 5단계를 마지막에 둔 이유가 정확했다** — 「POP-작업전점검 화면은 **점검 기록의 형태가 정해진 뒤**에야 「무엇을 보고 막을지」를 쓸 수 있다」. **12차가 헤더-라인 2계층과 종합 판정 저장을 확정**해 이 화면이 **헤더 한 줄만 보면 되게** 됐다.

## 3. ⭐⭐ 이월 4건이 `P-02-02` 에서 닫혔다

| 출처 | 무엇 | 결론 |
| --- | --- | --- |
| **11차** `W-05-12` §8-7 | **작업 통제 3단계의 소유 화면** — 저장처는 있으나 소유 화면 0건 | ⭐ **이 화면이 소비자다.** ⛔ **설정 화면은 신설하지 않는다** — 인벤토리 §5 미결 4 를 그대로 둔다 |
| **12차** `M-05-01` §9-2 | **오프라인 점검을 게이트가 어떻게 다루나** | ⭐ **구분할 수 없음을 화면이 말한다.** ⛔ **자동 통과시키지 않는다** |
| **13차** `W-05-04` §5-6 | 고장 ↔ 통제 | **보이되 막지 않는다** — QA #9 는 **점검만** 말했다 |
| **14차** `W-05-08` §8-3 | 정책 축에 **설비·설비그룹 없음** | ⛔ **늘리지 않는다** — 통제는 **정책이지 설비 속성이 아니다** |

### 3-1. ⭐ 11차 이월 — 설정 화면을 **신설하지 않는 근거가 강해졌다**

인벤토리 §5 미결 4 가 「**「MES 운영 정책 설정」류 화면이 나중에 여러 항목을 모아 생길 가능성**이 높다」고 예측했다.

| 시점 | `operation_policy` 정책 코드 |
| --- | :-: |
| 예측 시점(v1.3) | 1 (작업 통제) |
| **지금** | ⭐ **4** — 환산 2 + 통제 1 + 경미 정지 1 |

**예측이 맞아 가고 있다.** ⚠ **이 화면은 값을 읽기만 하므로 설정 화면 없이도 동작**한다(시드로 넣으면 된다 — #67 회신 §4-4).

### 3-2. ⭐⭐ 12차 이월 — **서버가 두 경우를 구분할 수 없다**

```
「점검 이력 없음」  =  안 했다   OR   오프라인으로 해서 아직 안 올라왔다
                                      ↑ 서버에 아예 없다
```

**확정 — 구분할 수 없음을 화면이 말한다.**

| 하는 것 | |
| --- | --- |
| 차단하되 **「미전송 점검이 있을 수 있습니다 — 점검 단말을 확인하세요」**를 함께 | ✅ |
| ⛔ **자동 통과** | **하지 않는다** — WF05 S3 Exception ③ 이 「시스템 차단이 없어 **통제가 무력**」을 현행 문제로 적었다 |

⭐ **두 문구가 짝이다** — 점검자는 「미전송 N건 — **작업 통제에 반영되지 않습니다**」(12차), 작업자는 「**미전송이 있을 수 있습니다**」(이 화면). **같은 원인의 두 얼굴**이다. → **C-18 신설**

## 4. 신규 조항 4 · 보완 1

| 조항 | 무엇 |
| :-: | --- |
| **C-18** ⭐⭐ | **한 데이터의 생산자와 소비자는 오프라인 정책이 반대다** |
| **F-6** ⭐⭐ | **「판정할 수 없음」을 「통과」로 처리하지 않는다** |
| **G-22** | **게이트는 막을 때만 보인다** |
| **G-23** | 연결이 끊겼을 때 **회색 버튼만 두지 않는다** |
| *보완* **A-14** | ⭐ **정책 값과 안전 규칙을 분리한다** |

### 4-1. ⭐ C-18 — 반대가 되는 것이 **정상**이다

```
M-05-01 점검 입력   만든다  →  오프라인 ✅ 허용 (C-15)
P-02-01 작업 시작   읽는다  →  오프라인 ⛔ 금지 (C-14)
```

⚠ **한쪽으로 통일하려 하면 현장이 멈추거나 통제가 무력해진다.**

### 4-2. ⭐ A-14 보완 — 통제 수준 「미적용」이 **두 가지를 뜻하면 안 된다**

| 뜻 | 판정 |
| --- | :-: |
| 「점검을 **안 해도** 된다」 | ✅ 정책이 정할 일 |
| 「점검 **NG 인데 돌려도** 된다」 | ⛔ **아니다 — 안전 규칙이다** |

**확정 — 점검 NG 는 통제 수준과 무관하게 차단**하고, **풀 수 있는 길은 긴급 W/O 우회뿐**이다.

⛔ **안전 규칙을 설정 가능하게 두지 않는다.**

## 5. ⭐ F-1 이 정확히 걸리는 **첫 자리**

12·13차가 05 액션을 `can_input_result` 에 **「잠정 포섭」**했다(전용 플래그가 없어서). **여기는 다르다.**

```
[ 작업 시작 ]  활성 조건
   terminal_process (이 단말 × 이 W/O 의 공정) . can_start_work = true
```

⭐ **`can_start_work` 전용 플래그가 실재한다**(SQL 574). **F-1 이 「생산·품질 단말 한정」으로 범위 정정된 그 한정의 정중앙**이다.

## 6. ⭐ 테이블 신설 요구 **0건** — 02 는 Scope 안이다

05 의 17장 중 신설을 요구하지 않은 것이 3장이었다. **15차 `P-02-01` 이 넷째**이고 **이유가 다르다.**

| | 05 | **02**(이 화면) |
| --- | --- | --- |
| 왜 | **A-13 ④ 로 찾았다** · 범용 테이블 재사용 | ⭐ **애초에 Scope 안이라 갖춰져 있다** |

`work_order`(긴급 구분 `work_order_type_code` · 우선순위 · 계획 설비·금형) · `work_session`(세션 번호 · 시작·종료 · 단말) · `terminal_process.can_start_work` — **전부 실재**.

⭐ **`operation_settings_snapshot jsonb` 를 발견**했다 — 주석이 「**기준정보 in-place 변경이 기존 지시에 소급되지 않도록 고정**」이다. **14차 A-18**(판정 근거가 움직이면 스냅샷)의 **하류 선례**다.

⚠ **`P-02-02` 는 하나 요구한다** — **통제 판정 이력**(§5-8). 15차 `P-02-01` §8-3 이 남긴 「우회·경고 진행 기록」도 여기서 닫혔다.

## 7. DS — 신규 갭 0건 (15차 연속)

### 7-1. ⚠ **G-5 「위험 72px」가 처음으로 걸린다**

E-3 이 등급을 넷으로 나눴는데 **지금까지 「위험」 등급 버튼이 없었다.** `P-02-02` 의 **`[ 우회하고 시작 ]`** 이 그것이다 — **점검 통제를 건너뛰는 되돌릴 수 없는 행위**.

⭐ **DS #67 의 근거가 하나 더 생겼다** — 「핵심 64~72」만이 아니라 **「위험 72↑」에 실제 사용처**가 나왔다.

### 7-2. 갭으로 올리지 않은 후보 1건

「무엇을 하면 되나」 구획에 `Stepper` 를 쓰고 싶어지지만 **진행 상태가 없다** — 할 일 안내이지 단계 추적이 아니다 → `Card` + 번호(`c`).

⚠ **네 차수 연속** 「겉모습이 같다고 같은 갭이 아니다」(12차 G-1 · 13차 G-11 · 14차 G-8 · 15차 `Stepper`).

**G-6 7곳**(사번형 셋째) · **G-10 21곳** · **E-1 세로 예산 둘 다 통과**(슬랙 0).

**전부 공통(CO) + 재생재다.**

| 화면 | 막고 있던 것 | 지금 |

| 웹-계정-로그인 · 웹-비밀번호-변경 | 인증 수단 | ✅ **DR-002 확정** |

| 모바일-재생재-등록 | 품목 확장속성 | ✅ **DR-006 확정** |
| **웹-통합대시보드**(`W-CO-05`) | 알림 + 레이아웃 | ✅ **DR-003·DR-004 로 둘 다 해소** |

⭐ **실측으로 확인했다** — `W-CO-05` 는 **미작성 목록에 있다**. 14차 `W-05-08` 이 「OEE 는 통합 대시보드가 후보」로 넘긴 것을 **그 화면이 받는다.**

⚠ **정확한 7건 목록은 차수 배치 시 확정한다** — 생성기 ID 대조에서 **결번 12건**이 섞여 나오므로, 착수 전에 결번을 걸러 목록을 못박는다. **위 여섯 갈래가 성격**이고 나머지는 **DR-002·DR-003 이 신설한 2장**(비밀번호 변경 · 알람 수신자 설정) 중 미작성분이다.

⛔ **착수 통지는 여전히 내지 않는다** — 05·02 API 계약이 없다.
