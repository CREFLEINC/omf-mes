## 1. #62 — 검사자와 확정자를 분리하지 않는다

**확정**: 검사 판정을 기록한 사람이 곧 확정자다. 판정 저장 = 확정.

| 근거 | 실측 |
| --- | --- |
| `quality.inspection_result` | `inspector_id` ✅ · `inspected_at` ✅ · `confirmed_at` ✅ nullable · **`confirmed_by` ⛔ 없다** |
| ⭐ **비대칭** | `confirmed_by` 는 `planning.production_plan` · `logistics.subcontract_reconciliation` 에 **실재한다** |

**「확정한 사람을 남긴다」가 이 모델의 관행이고 검사 결과에만 빠졌다** → 결손이 아니라 **의도**로 읽었다.

**파급**: 검사 3형(`W-01-01` IQC · `P-02-13` PQC · `W-04-03` OQC)이 이미 A-11 로 물러나 있던 설계가 **그대로 확정안이 됐다.** 화면 변경 없음.

⚠ **확장 시 세 화면이 함께 바뀐다** — `confirmed_by` 신설 + 확정 액션 추가.

## 2. #54 — 작업조(Shift) 마스터는 MES 정본이다

**확정**: ERP 수신이 아니라 MES 가 소유한다.

| # | 실측 | 읽는 방향 |
| :-: | --- | --- |
| 1 | `mdm.shift` 에 `start_time`·`end_time`·`crosses_midnight` | **생산 운영 정의**다. 인사·급여 마스터가 아니다 |
| 2 | 유니크 키 `(plant_id, shift_code)` | **공장별** — ERP 전사 마스터의 형태가 아니다 |
| 3 | 참조 3곳이 **전부 `production` 스키마** — `work_order.planned_shift_id` · `work_session.shift_id`(NOT NULL) · `production_result.shift_id`(NOT NULL) | 쓰는 쪽이 생산 실행뿐 |
| 4 | ⭐ **`mdm.worker` 에 `shift_id` 가 없다** | **조 배정이 마스터가 아니라 실적 시점 기록**이다 |

⚠ **쓰지 않은 논거** — 「`erp_*_code` 표식이 없으니 MES 정본」. `mdm` 스키마에서 그 표식을 가진 테이블이 `partner` 하나뿐이라 표식 유무로는 소유를 가릴 수 없다.

**파급**: `W-06-06` 공통코드 마스터 범위에 포함. ⚠ **다만 전용 편집 폼이 필요하다** — `code_value`(코드·명·정렬·유효기간)로는 `start_time`·`crosses_midnight` 를 담을 수 없다. **`W-06-06` 스펙 작성 시 전용 화면 신설 여부를 재확인**한다(인벤토리 영향 가능).

## 3. #46 — `lot.status_code` 에 「폐번」 값을 둔다

**확정**: 「폐번」 값 신설 + W/O 내 순번 속성 신설. 둘 다 `[docs→데이터모델]` 로 넘긴다(assignee `wooju-shin`).

**왜 필요한가**: LOT 번호는 발번되면 **실물 라벨로 나간다**(`P-01-01` · `P-04-04`). 삭제는 답이 아니다 — 라벨이 물리적으로 존재해 재스캔되면 「없는 LOT」 오류가 난다.

⭐ **축이 정합한다** — E-3 제안안의 실측 결과가 이 확정을 뒷받침한다.

| 축(결정 10) | 착지처 | 값 |
| --- | --- | --- |
| ① **수명주기** | **`trace.lot.status_code`** (DEFAULT `'ACTIVE'`) | 활성 / 소진 / **폐번** |
| ② 품질 판정 | `inventory.inventory_balance.quality_status_code` | Release / 보류 / Hold / PQC 검사 필요 |
| ③ 작업 홀드 | `trace.lot_hold` | — |

「폐번」이 ① 에 정확히 들어맞고 ② 와 섞이지 않는다 → 결정 10 의 「한 필드에 섞지 않는다」가 지켜진다.

## 4. #72 — ERP 매칭 시점은 차단이 아니다

**확정**: 이슈는 열어 두되 `W-01-11` 의 선행 조건에서 제외한다.

| 확인 요청 | 상태 |
| --- | --- |
| 1. 가/나 중 어느 쪽인가 | ✅ **「나」**(MES 선등록·ERP 사후 매칭) — 2026-08-04 회신 |
| 2. 승인 주체 | ✅ 「담당부서 관리자」 → **`USER` 만 연다**로 재확정(2026-08-07) · `app-공통.json` 이 정본 |
| 3. **ERP 매칭 주체·시점** | ⬜ **미결 — 그러나 차단 아님** |

**근거**: 화면이 이미 물러나 있다 — `ERP P/O 번호` 는 **입력 가능·필수 아님**, 비면 「ERP 미매칭」 배지. **누가 언제 채우든 필드와 배지는 그대로 선다.** 골격을 바꿀 수 있었던 것은 **승인 단계 유무**였고 그건 2번으로 확정됐다.

**파급**: `W-01-11` **차단 0건** → 착수 가능. ⚠ `priority:high` 라벨은 내려도 된다.
