## 시드 — 개발용

⛔ **반영은 데이터모델 소관이다 — 작업 통지이고 기다리지 않는다**(`design/schema/data-model-boundary.md`).

### 역할 `app.role` — 4

고객이 운영 중 늘리고 고치고 지운다(사용자 결정 2026-09-01). ⭐ 화면 동작은 역할 «이름»이 아니라 **권한**에 걸리므로 이 넷은 출발점일 뿐이다.

| roleCode | roleName |
| --- | --- |
| `ROLE_WORKER` | 실무자 |
| `ROLE_SITE_MGR` | 현장 관리자 |
| `ROLE_EXEC_MGR` | 경영 관리자 |
| `ROLE_SYS_ADMIN` | 시스템 운영자 |

### 최초 관리자 `app.app_user` — 1

⛔ **없으면 아무도 아무 권한을 줄 수 없다.** 마지막 관리자 차단(`code=LAST_ADMIN`)이 걸려 있어 관리자 교체는 «다른 관리자»가 하고, 그래서 **최초 1명은 시드로 서야 한다**. `ROLE_SYS_ADMIN` 을 부여한 상태로 넣는다.

⚠ 운영은 관리자를 **둘 이상** 두어야 한다 — 하나뿐이면 그 사람을 내릴 방법이 없다.

### 사용자 상태 `APP_USER_STATUS` — 3

⭐ **인사 상태다**(표시용). 계정을 쓸 수 있는가는 `is_active` 가 정한다(`W-CO-02` §8-4). `G-31` 마스터안전형이라 개발 이후 고객이 `W-06-06` 에서 편집·대체한다.

| code | name |
| --- | --- |
| `ACTIVE` | 재직 |
| `ON_LEAVE` | 휴직 |
| `RETIRED` | 퇴사 |
