## 1. 원칙 3가지

1. **스펙과 와이어프레임은 한 장이다.** 분리하면 필드를 두 번 정의하고 두 번 어긋난다.
2. **필드는 지어내지 않는다.** 근거는 **프로세스·화면·요구 세 면**이다 — 「있으면 좋을 것 같은 필드」는 쓰지 않는다.
   ⛔ **[v1.1 개정 · 사용자 확정 2026-08-18]** 옛 문장은 「**물리 모델 컬럼에서 오거나**, 없으면 `[미결]`」이었다. **뒤집는다** — 모델에 컬럼이 없어도 **설계가 필요하다고 판단하면 둔다.** 담을 자리가 없는 것은 📨 **작업 통지**이지 우리를 막는 것이 아니다.
3. **모양은 정하지 않는다.** 색·타이포·간격은 `@crefle/web-ui` 토큰이 이미 정했다. 우리가 정하는 것은 **무엇을 어떤 컴포넌트로 어떻게 배치하는가**까지다.

### ⛔⛔ 네 번째 면은 **「타입·길이」만 준다** **[v1.1 · 사용자 확정 2026-08-18]**

> **물리 데이터 모델은 설계 결정을 앞설 수 없다.**

| 무엇 | 누가 정하나 |
| --- | :-: |
| **무엇을 받나**(어떤 필드를 두나) | ⭐ **설계** |
| **필수인가 선택인가** | ⭐ **설계** |
| 어떤 값이 오나(값 목록) | ⭐ **설계** 또는 **고객 설정 마스터**(공유계약 `G-31`) |
| **타입·길이** | 물리 모델 도메인을 그대로 쓴다 |

⛔ **모델의 `NOT NULL`·`CHECK`·`UNIQUE` 를 근거로 화면의 필수·구성을 정하지 않는다.** 확정과 모델이 어긋나면 **확정이 이긴다**(§8 「원본이 이긴다」에 **예외가 없다**).

**왜 못박나 — 실제로 거꾸로 흘렀다.**

| 어디 | 무슨 일이 있었나 |
| --- | --- |
| `P-02-04` 작업 실적 | 정본이 「회차·교대 **무관**」인데 모델 `NOT NULL` 을 보고 **교대를 필수로** 받아 적어 계약까지 내려갔다 |
| `W-06-01` 공정 등록 | 결정 07 의 「유효 시작일(**선택**)」을 필수로 뒤집고, **「제약은 하류가 정본」을 원칙으로 적었다** |

⚠ **모델이 못 담을 때** — ①계약은 화면대로 쓴다 ②내부 주석에 결손과 통지 번호를 적는다 ③📨 **작업 통지**를 낸다. **기다리지 않는다.**

⚠ 프로세스·화면·요구 세 면이 서로 어긋나면 **고치지 말고 §8 미결에 기록**한다. 정본 수정은 각 소관에서 한다(데이터모델은 읽기 전용 — `[docs→데이터모델]` 이슈).

### 2-1. 근거 강도를 구분해 적는다 **[v1.0 신설]**

| 강도 | 뜻 | 표기 |

| **실측** | 저장소 파일을 직접 읽어 확인 | 경로·행 번호 병기 |

## 4. 레이아웃 — 폼팩터마다 방법이 다르다 **[v1.0 개정]**

| 폼팩터 | 규격 | 방법 |
| --- | --- | --- |
| 관리웹 | 데스크톱 브라우저 | **구조 기술** — 영역 분할·배치 순서·컬럼 구성을 글과 표로 |
| 모바일 | **360×720dp = 하한(최소 보장선)** (Android **13+** · 물리 1080×2160) | 구조 기술 + **스크롤 단위** 표시. ⚠ **@xxhdpi(화소 배율 3.0)로 적지 않는다** — 실기 배율은 2.5 라 뷰포트가 432×792 다(omf-mes#275 ①). 실측치를 새 기준으로 삼지 않는다 — 표시·글꼴 크기 설정이 바뀌면 환산이 다시 변한다. 남는 폭·세로는 여유로만 쓴다 |
| **POP** | **1024×768** · 터치 타겟 일반 56px↑ · 주요 64px↑ · 핵심 64~72px · 위험 72px↑ · 간격 8px↑(권장 12~16) | **세로 예산 검산 + 렌더 실측**(아래) |

### 4-1. POP은 검산만으로 부족하다 — 렌더 실측을 병행한다 **[v1.0 신설]**

파일럿에서 **산술 검산이 두 군데 틀렸다**(`P-02-04` §3-3):

- 패딩을 예산에 넣지 않아 세로를 **과소평가**했다(실제 119px 여유)
- **제약이 세로가 아니라 가로**였다 — 34자리 LOT 행이 597/599px

**방법**: `@crefle/web-ui`의 `styles/index.css`(실제 토큰·폰트)를 불러와 해당 치수의 프레임을 브라우저에 렌더하고 측정한다. 재현용 HTML과 캡처를 스펙 옆에 둔다.

⚠ DS 컴포넌트는 CSS Modules(해시 클래스)라 직접 쓸 수 없다 — **토큰으로 치수만 재현**하는 것이며 **실물 컴포넌트 렌더가 아님을 명기**한다. 장갑 조작감·조명·판독 거리는 **실기 확인**(트랙 H) 몫이다.

⚠ **POP 세로 예산은 슬랙이 0이다**(64+616+88=768). 크롬이 1px만 껴도 깨진다.

### 4-2. 와이어 이미지는 비공개 저장소에만

`omf-mes`에만 둔다. **공개 저장소 반출 금지 항목**이다(`uiux/CLAUDE.md` §공개 저장소 반출 경계).

## 5. §4 필드표 규칙

| 열 | 규칙 |
| --- | --- |
| 라벨(한/베) | 베트남어 미정이면 `(미정)`. i18n 키 네이밍은 공유 계약에서 확정 |
| 출처 컬럼 | `스키마.테이블.컬럼`. ⛔ **모델에 없어도 설계가 필요하다고 보면 필드를 둔다** — **`[미착지]`** 로 적고 📨 **작업 통지**를 낸다. **기다리지 않는다** *(v1.1 개정 — 옛 규칙은 「없으면 `[미결]` · 지어내지 않는다」였다)* |
| 타입 | 물리 모델 도메인 그대로. `app.code_t`=varchar(50) · `app.name_t`=varchar(200) · `app.qty_t`=numeric(20,6)≥0 · `app.business_no_t`=varchar(100) — ✅ **이 열만 모델을 따른다** |
| **필수** | ⭐ **설계가 정한다** — 업무가 반드시 받아야 하는가로 판단한다. ⛔ **모델의 `NOT NULL` 을 근거로 삼지 않는다** *(v1.1 개정 — 옛 규칙은 「`NOT NULL` 여부」였다)*. **조건부 필수는 그 조건을 업무 언어로 적는다** |
| 유일 | UNIQUE 제약. **유일키의 범위를 오류 문구에 담는다**(공유 계약 A-1) |
| 검증 | CHECK·FK·도메인 제약을 **사용자에게 보일 문구로** 옮긴다 |
| 편집 | 신규/수정 시 편집 가능 여부. ERP 수신본은 읽기 전용+확장 속성만(REQ-PR-0021) |

**감사 컬럼과 `version_no`는 필드표에 넣지 않는다**(공유 계약 A-4). 다만 `version_no`가 있으면 §5에 **낙관적 잠금 충돌 처리**를 반드시 쓴다(B-1).

⚠ **애플리케이션 검증을 빠뜨리지 않는다.** DB 제약이 없다고 규칙이 없는 게 아니다 — 자재 LOT No의 34자리 고정폭은 `varchar(100)`에 아무 제약이 없고 **전부 화면 책임**이다(`M-01-02` §4-1).

## 6. §7 DS 매핑 규칙 — **조합을 먼저 확인한다** **[v1.0 개정]**

갭은 네 갈래(DS `docs/component-requests.md`):

| 유형 | 뜻 | 처리 |
| --- | --- | --- |
| **a** | 그대로 있다 | 컴포넌트명·주요 prop만 적는다 |
| **b** | 컴포넌트는 있으나 변형·prop이 없다 | DS 이슈 후보 — `ds-gap.md`에 등재 |
| **c** | 기존 컴포넌트의 **조합** | **제품이 소유. 이슈 없음** |
| **d** | 진짜 새 원시 요소 | `ds-candidates/` 후보. **세 번째 사용처**에서 DS 승격 |

### 6-1. 「없다」고 적기 전에 조합 시도를 기록한다

**파일럿에서 갭으로 본 것 셋이 전부 조합이었다** — 검색 바 · 스캔 · 편집 그리드. 특히:

- **스캔** → `TextField` + 포커스 관리 (d로 예상했으나 c)
- **편집 그리드** → `Table`의 `TableColumn.render?: (row, rowIndex) => ReactNode` (갭으로 보였으나 c)

**절차**: `b`·`d`로 적으려면 **「어떤 조합을 시도했고 왜 안 되는지」를 한 줄 이상 근거로 남긴다.** 근거가 없으면 `c`로 본다.

> DS 문서의 경고: *「c가 가장 많고, c를 DS로 올리는 것이 디자인 시스템이 망가지는 가장 흔한 경로다.」*

### 6-2. 이슈는 결손이 확인되는 즉시 낸다 — 「몰아서 낸다」를 폐기한다 **[v1.2 개정]**

⛔ 옛 규칙("전 화면 매핑을 마친 뒤 한 번에 낸다")은 폐기한다. **개발팀이든 설계팀이든, 결손이
확인되면 그 자리에서 바로** `design-system-v2-webui`에 이슈를 낸다 — 다른 화면에서 같은
결손이 몇 건 더 나올지 기다리지 않는다.

⛔⛔ **몇 곳에서 쓰이는지, omf-mes가 그 사이 어떻게 할지는 DS 저장소에 적지 않는다.** 이슈에는
**컴포넌트 자체의 언어**로만 적는다 — 어떤 역할을 하는 컴포넌트인지, 어떤 속성(prop)으로 무엇을
제어할 수 있어야 하는지.

```
⛔ 금지 — omf-mes 사정이 들어감
   "A 컴포넌트 개발 요청. 2곳에서만 결손이 확인됐으니 신규 컴포넌트를 추가하든
    합성 컴포넌트로 처리하든 결정해 주면 된다."

✅ 올바름 — 컴포넌트 언어로만
   "A 컴포넌트 개발 요청.
    · A 역할을 하는 컴포넌트가 필요하다.
    · 가로·세로 길이를 설정할 수 있어야 한다."
```

DS가 그 요청을 신규 컴포넌트로 만들지 기존 조합으로 안내할지는 **DS의 판단이다.** omf-mes는
그 판단과 무관하게 §6-3대로 자체적으로 사용을 결정한다.

⚠ **DS 저장소는 공개다** — 이 원칙은 그대로다.

### 6-3. 사용은 DS 처리와 무관하게 omf-mes가 정한다 **[v1.2 신설]**

발행(6-2)과 사용(이 절)은 **서로 독립이다** — DS가 요청을 받아들이든 반려하든, 접수만 됐다면
아래대로 진행한다.

| 갈래 | 처리 |
| --- | --- |
| **2곳 이상**에서 같은 결손을 겪는다 | 담당 개발자 한 명이 임시 구현 하나를 만들고 나머지 화면이 그것을 공유해 쓴다. DS가 정식 컴포넌트를 내놓으면 **그때 한 번에 교체**한다 |
| **1곳**에서만 쓴다 | 그 화면 안에서 임시로 만든 것을 **그대로 정본으로 쓴다** — DS가 나중에 같은 것을 내놔도 **교체 의무 없음** |

- 임시 구현은 기존 관례대로 `packages/ui/src/ds-candidates/`에 둔다(`d` 처리와 같은 자리).
- "2곳 이상"인지 "1곳"인지는 **설계팀이 착수·변경 통지에 적어 알린다** — 개발팀이 각자 판단하면
  같은 결손을 화면마다 따로 구현할 위험이 있다.

## 7. §8 미결 — 성격을 분류한다 **[v1.0 신설]**

파일럿 4장에서 같은 네 종류가 반복해 나왔다. 성격에 따라 **처리 경로가 다르므로** 분류해 적는다.

| 성격 | 뜻 | 처리 경로 |
| --- | --- | --- |
| **상류↔하류 불일치** ⚠ **뜻이 좁아졌다** | 정본과 물리 모델이 어긋남 — ⛔ **이것은 「모델에 자리가 없다」는 뜻이지 「설계가 막힌다」가 아니다** | 📨 **작업 통지**(`[docs→데이터모델]` · assignee 필수). **설계는 확정대로 쓰고 기다리지 않는다** *(v1.1)* |
| **회신 대기** ⚠ **범위가 줄었다** | 고객 회신이 **있어야 다음이 되는** 것 | 대기 목록에 등재. **화면은 만들되 비활성**(공유계약 `G-2`). ⛔ **「고객이 정할 값 목록」은 여기가 아니다** — `G-31`(마스터) |
| **설계 결정** | 우리가 정하면 되는데 아직 안 정함 | 결정권자 확인 |
| **공통코드** | 코드 값 목록 미정 | ⭐ **먼저 `G-31` 로 가른다** — 동작이 걸리면 **설계가 정하고**, 안 걸리면 **고객 설정 마스터**(`W-06-06`)라 기다리지 않는다 |
