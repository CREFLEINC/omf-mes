> 이 문서는 `design/` 전체(raw·wiki 모두)를 채우고 고칠 때 지키는 메타 규칙이다.
> 원본 규칙 정본은 구 `uiux/CLAUDE.md`(2026-08-13 사용자 확정)였으며, 이 문서는 그 4대
> 규칙을 Raw/Wiki/Schema 구조에 맞게 재정리한 것이다. 재구성 검증 완료 후 원본이 삭제돼
> (2026-08-25) **이 문서가 유일한 정본**이다 — 원문은 `git log`로만 남아 있다.

## 규칙 1 — 데이터 모델링과 설계는 역할이 다르다

| 무엇 | 누가 |
| --- | --- |
| 화면이 무엇을 보여 주고 무엇을 저장하는가 | ⭐ 우리(설계) |
| 그것을 담을 컬럼·제약·무결성 | 데이터 모델링·백엔드 |
| API 계약 | ⭐ 우리 |

상세는 [`data-model-boundary.md`](data-model-boundary.md) 참조.

## 규칙 2 — 데이터 모델은 「타입·길이」만 준다

물리 모델의 현재 상태를 이유로 설계나 계약을 물러서지 않는다. 모델이 화면 요구를 못 담으면
① 계약은 화면대로 쓴다 ② 내부 주석에 모델 결손과 요청 번호를 적는다 ③ 데이터 모델 담당에게
통지한다 — 기다리지 않는다. 상세는 [`data-model-boundary.md`](data-model-boundary.md).

## 규칙 3 — 보고·문서는 무엇·어떻게·왜를 다 적는다

| | |
| --- | --- |
| **무엇** | 바뀐 것·만든 것을 한 줄로 |
| **어떻게** | 방법과 근거(실측 수치·인용 원문) |
| **왜** | 그렇게 한 이유. 택하지 않은 안과 그 이유를 함께 |

⛔ 수치를 적을 때는 「무엇을 셌는가」를 함께 적는다. 두 번 이상 인용될 수치는 스크립트를
정본으로 둔다(→ [`generators/`](generators/)).

## 규칙 4 — 줄임말·기호를 그대로 쓰지 않는다

화면 번호·조항 번호·이슈 번호·회신 번호·차수·업무 약어는 처음 쓸 때 반드시 뜻을 함께 적는다.
번호 체계 정의는 [`numbering-conventions.md`](numbering-conventions.md) 참조.

```
⛔  W-01-06 에 A-10 을 적용
✅  자재 폐기 화면(W-01-06)에 다형 참조 대응표 조항(A-10)을 적용
```

## 규칙 5 — 표기를 폐기했으면 옛 이름을 「지우거나 · 표시를 달거나」 둘 중 하나다

스펙이 이름을 바꾸면 옛 이름이 문서 여기저기에 남는다. 그 자리를 **그냥 두는 선택지는 없다.**
고칠 것이면 고치고, 남겨야 할 이유가 있으면 **왜 남기는지를 기계가 읽을 수 있는 표시로 단다.**

표시는 셋뿐이고 뜻이 서로 다르다.

| 표기 | 언제 쓰나 | 무엇을 뜻하나 |
| --- | --- | --- |
| `«(정합주: …)»` | 그 자리의 **현재 상태를 밝힐 때** | 옛 서술을 남겨 두되, 지금은 무엇이 맞는지를 괄호 안에 적었다 |
| `«(구표기 보존)»` | **회고·반박 서술**이라 옛 이름을 인용해야 뜻이 통할 때 | 「v0.1이 무엇을 틀렸나」처럼, 옛 이름을 지우면 문장이 성립하지 않는다 |
| `~~취소선~~` | **이력 보존**이 목적일 때 | 폐기됐다는 사실 자체를 눈으로 보이게 남긴다 |

```
⛔  단말은 부착형 BLE 스캐너를 쓴다                    ← 폐기된 표기가 맨몸으로 남았다
✅  단말은 스캐너 일체형 PDA를 쓴다
✅  단말은 부착형 스캐너를 쓴다 «(정합주: 2026-08-26 스캐너 일체형으로 확정 — omf-mes-client#442)»
✅  v0.1은 「부착형 BLE 스캐너」를 전제했다 «(구표기 보존)»
✅  ~~부착형 BLE 스캐너~~ → 스캐너 일체형 PDA
```

**고르는 기준은 하나다 — 그 줄을 읽는 사람에게 옛 이름이 «필요한가».** 필요 없으면 지운다.
설명을 위해 필요하면 `«(구표기 보존)»`, 지금 무엇이 맞는지까지 말해야 하면 `«(정합주: …)»`,
폐기 사실을 눈에 보이게 남기는 것이 목적이면 취소선이다.

### 이 절은 검사기가 가리키는 자리다

`generators/verify-stale-terms.py`(폐기된 옛 표기가 남았는지 훑는 검사기)가 발견을 낼 때마다
말미에 **이 문서를 규약으로 안내한다.** 그리고 위 세 표기가 붙은 줄은 **보고하지 않는다** —
「이미 판단했다」는 표식으로 읽기 때문이다. 그러니 표시를 다는 것은 검사기를 속이는 일이 아니라
**검사기에게 판단 결과를 알려 주는 일**이다.

⚠ **회고·이력을 담은 절에는 표시를 달지 않아도 된다.** 최근접 상위 제목에 「이력」·「변경 이력」·
「상세 이력」·「회고」가 들어간 절과 `design/raw/`(시점 고착 자료)는 검사기가 처음부터 건너뛴다.

⭐ **실측(2026-08-31)** — `design/` 아래에서 세 표기 중 하나라도 쓰는 파일은 **129개**이고,
그중 시점 고착 자료(`design/raw/`)를 뺀 것이 **88개**다. 가장 많이 쓰이는 것은 정합주로
`design/wiki`·`design/schema`에서 **21파일 252자리**다. 「무엇을 셌는가」 — 표기 문자열이
파일 안에 한 번이라도 나오는 파일 수, 그리고 정합주는 문자열 출현 횟수다.

## 규칙 6 — 코드 값은 「화면 스펙은 병기 · 계약과 요구서는 단독」

공통코드 값(`MACHINING`·`DAY`·`EMPLOYED` 같은 영문 대문자 SNAKE)을 문서에 적을 때,
**한국어 뜻을 함께 적는가**를 문서 종류가 정한다. 사용자 확정(2026-09-03).

| 층 | 규칙 | 왜 |
| --- | --- | --- |
| **값 자체** — 계약 `enum`·`example` · 코드 사전 「값」 열 | ⛔ **영문만** | 코드는 영문이고 **화면에 보이는 것은 `code_name`** 이다(`§G`). 여기 한국어가 들어가면 화면이 표시명을 갖게 된다 |

⚠ **`example` 은 이 규칙의 대상이지만 검사는 [`check-example-placeholder.py`](generators/openapi/check-example-placeholder.py) 가 한다.** 한 결손에 게이트를 둘 두면 어느 쪽을 고쳐야 하는지 흐려진다 — 자리채움(`"값"`·`"코드"`)이 남은 자리는 그 검사기가 이미 세고 있고, 그중 다수는 **사전 값이 ⬜ 라 지금 채울 수도 없다.**
| **화면 스펙** §4 필드표·본문 | ✅ **병기** — `MACHINING`(가공) | 화면 스펙은 「**사용자에게 무엇이 보이나**」를 다룬다. 읽는 사람이 코드만 보고 화면을 그릴 수 없다 |
| **계약·요구서** 산문 | **단독** — `MACHINING` | 계약과 요구서는 「**기계가 무엇을 주고받나**」를 다룬다. 코드가 곧 계약이고 뜻풀이는 사전이 갖는다 |

⭐ **값 목록의 정본은 `schema/code-dictionary.md` 하나다.** 다른 문서가 값을 적는 것은
전부 **인용**이고, 그래서 인용하는 자리마다 뜻을 다시 적을 필요가 없다.

### ⚠ 이미 쓴 글은 걷어내지 않는다 — 래칫이다

실측(2026-09-03) — 계약 7벌 산문에 병기 **91자리**(고유 36짝) · 요구서 **40자리**.
⛔ **그중 상당수는 병기가 없으면 «오독»한다.**

```
NORMAL (양산)           ← 병기를 빼면 「정상」으로 읽힌다. 실제로는 작업지시 유형이다
PQC (공정·초중종·자주)     ← 병기 없이는 무슨 검사인지 알 수 없다
INJECTION_MOLDING (사출기) · WATER_HEATER (온수기)
```

그래서 이 규칙은 **앞으로 쓰는 글**에 적용하고, 기존 자리는 그대로 둔다. 검사기는
**늘지 않게만** 막는다(래칫). 걷어낼 값이 있다고 판단되면 그때 별건으로 정리한다.

⭐ **값 자체(위 표 첫 줄)는 래칫이 아니다** — 실측 결과 계약 `enum` 한국어 **0** ·
코드 사전 값 열 **165행 전부 영문**으로 이미 100% 지켜지고 있다. 여기가 무너지면 ⛔ 다.

### 이 절도 검사기가 가리키는 자리다

`generators/openapi/check-code-notation.py` 가 세 층을 함께 본다 — 값 자체는 **막고**,
화면 스펙과 계약·요구서의 산문 표기는 **래칫**으로 센다.

## Wiki 재작성 시 추가로 지키는 것

- 재작성 방식은 [`rewrite-tiers.md`](rewrite-tiers.md)의 Tier 0/1/2를 따른다.
- 페이지 구조는 [`page-template.md`](page-template.md)의 L0~L4 계층을 따른다.
- `docs/` 관련 원칙(원본 라 raw 는 읽기 전용, 외부 반출 경계 등)은 이번 재구성으로 `docs/`가
  `design/raw/`에 흡수되면서 이 저장소(`omf-mes`) 전체에 그대로 적용된다 — **모든 산출물은
  내부 대외비**이며 외부 서비스에 업로드·공유·게시하지 않는다.
