# W-CO-06 · 단말기-공정 매핑 설정

## §0. 요약

- **개요**: 관리웹 설정·마스터 화면. 시스템 관리자가 단말기(POP·모바일)를 등록·수정하고, 단말 인증 토큰을 발급하며, 단말×공정 기능 구성 8플래그를 구성한다. 물리 설치·배선은 범위 밖(REQ-PR-0017 · 회신 E-2).
- **주요 데이터**: `mdm.terminal`(7열 + 감사), `mdm.terminal_process`(8 boolean 플래그 · 전부 `DEFAULT false` · `UNIQUE(terminal_id, process_id)`), `mdm.process`, `mdm.location`.
- **핵심 액션**: 단말 등록·수정 → 단말 선택 → 토큰 발급·재발급 → 공정 추가 → 8플래그 토글 → 저장(단말 단위 한 트랜잭션).

> 작성일: 2026-08-06 · 서식: `00-서식.md` v1.0 · 작성 주체: CREFLE OMF 팀 (UI/UX)
> ⭐ **F-1의 적용 범위를 닫는 화면이다.** 4차가 「창고 작업에 대응하는 공정이 있는가」를 미확인으로 남겼는데(`P-01-02` §8-3), **그 답은 이미 2026-07-28에 확정돼 있었다.** 이 장은 실측으로 그것을 확인하고 **공유계약 §F의 과장을 정정**한다.

## §5. 액션·상태

### §5-1. ⭐ F-1의 적용 범위 — **실측이 이미 있던 확정을 뒷받침한다**

4차가 남긴 질문은 이것이었다:

> **창고 작업에 대응하는 「공정」이 있는가** — 없으면 창고 스테이션 POP(`P-01-02`)과 모바일 7화면의 게이팅이 성립하지 않는다. (`P-01-02` §8-3)

**두 갈래로 실측했다.**

**① `mdm.process`를 참조하는 곳** — 전수 **14곳**:

| 참조처 | 성격 |
| --- | --- |
| `planning.routing_operation` · `bom_component` · `production.material_consumption`(`actual_use_process_id`) | 생산 |
| `mdm.equipment` · `worker_qualification` · `terminal_process` | 생산 자원 |
| `quality.inspection_plan` · `defect_code` · `cause_code` · `defect_record`(발생·검출 2컬럼) · `concession` | 품질 |
| `logistics.subcontract_order` · `app.operation_policy` | 외주·정책 |

**창고 작업(입하·적치·피킹·이동·재고조사)을 참조하는 곳이 하나도 없다.** `mdm.process`는 **생산 라우팅의 공정**이다.

**② 창고 작업이 단말을 기록하는가** — `terminal_id` 컬럼 전수 **7곳**:

```
production.work_session          NOT NULL
production.material_consumption  NOT NULL
production.work_session_event
production.production_result
quality.inspection_result
app.document_issue_log
audit.audit_event
```

**`logistics` 0곳 · `inventory` 0곳이다.**

**⚠ 그런데 이것은 새 발견이 아니다 — 이미 판정이 끝난 사항이다.**

「POP 단말인증 설계검토」(2026-07-28) **§2.3**이 같은 것을 보고 **「정상」이라 판정했다**:

> 모바일에는 이 매트릭스가 거의 적용되지 않는다 — **그리고 그게 정상이다.** … 배지단말 확정 **#8**이 「통신 두절 시 입·출측 스캔을 **단일 단말기 하나로** 수행」하는 **오프라인 축퇴 규칙**을 명문화했다 — 단말의 행위 범위는 상황에 따라 **넓어져야** 한다. 순회 장비에 `(단말 × 공정)` 행위를 고정하면 이 규칙이 깨진다. **플래그를 추가할 일이 아니다.**

같은 문서 v0.5는 「모바일 업무가 `terminal_process`로 표현되지 않는다」를 미결로 올렸다가 **철회**하며 「**조치할 것이 없다**」로 닫았다.

> **답**: F-1은 **생산·품질 단말에만 성립하고, 그것이 설계 의도다.** 창고 전용 단말이 이 화면에서 **공정 행 0건**으로 남는 것은 오류가 아니다.

**⛔ 그렇다면 남는 것은 우리 쪽 서술의 과장이다.**

같은 문서 v0.5가 **자기 초안을 정정**했다 — 「`terminal_process`를 **「인가(authorization)의 정본」**으로 격상했던 서술을 **「단말 기능 구성(하드웨어·배치 반영·오조작 방지)」**으로 되돌린다. **보안 경계는 단말 인증 하나뿐이다.**」

**공유계약 §F가 그 정정을 반영하지 않았다.**

| | 현재 §F | 2026-07-28 정정 후 |
| --- | --- | --- |
| 절 이름 | **「권한 게이팅」** | **기능 구성**(보안 경계 아님) |
| F-1 | 「8플래그를 **액션 활성 조건**으로」 | ✅ 그대로 맞다 — 버튼을 여닫는 것은 사실이다 |
| **F-2** | 「축이 **둘**」 — 단말×공정 = **POP·모바일** / 사용자×기능 = 관리웹 | ⛔ **축이 셋**이다 — **인증**(단말 토큰) · **기능 구성**(매트릭스) · **귀속**(사번). 그리고 매트릭스는 **모바일에 걸리지 않는다** |

→ **§F 개정 후보** §9-1. **이슈가 아니라 우리 문서의 정정**이다.

### §5-2. 공정을 추가하면 **아무것도 못 하는 행**이 생긴다 — 화면이 밝힌다

8플래그가 전부 `DEFAULT false`다. 「공정 추가」만 하고 저장하면 **그 단말은 그 공정에서 아무 버튼도 못 누른다.**

**규칙**: 공정을 추가하면 **체크 0개인 상태로 경고를 띄운다.**

```
⚠ 「조립」에 허용된 작업이 없습니다 — 이 단말은 조립 공정에서 아무것도 할 수 없습니다
```

G-3(비활성 사유는 「어떻게 풀 것인가」)의 역방향이다 — 여기서는 **「지금 이대로 저장하면 저쪽 화면이 막힌다」**를 미리 알린다. 저장은 막지 않는다. 「등록만 해 두고 구성은 나중에」가 정상 운용이다.

### §5-3. 부여 테이블의 저장 — **행 단위가 아니라 단말 단위 한 트랜잭션**

`terminal_process`에는 `version_no`가 없다(B-6 — 부여 테이블). **행마다 저장하면 중간 실패 시 절반만 반영된다.**

| | |
| --- | --- |
| 클라이언트 | 단말 하나의 **공정 행 전체**를 모아 보낸다 |
| 서버 | 한 트랜잭션에서 차분 적용 |
| 충돌 판정 | **`mdm.terminal.version_no`로 한다** — 부여 테이블에 토큰이 없으므로 **마스터의 토큰을 대표로 쓴다** |

A-5(순서 컬럼 재배치)·A-6(부분 유일 전환)과 같은 형태다 — **여러 행에 걸친 변경은 서버가 한 트랜잭션으로 한다.**

→ **§B 신규 조항 후보** §9-2.

### §5-4. ⛔ 단말 토큰 — **확정된 컬럼이 물리 모델에 없다**

「POP 단말인증 설계검토」 **§6-②**가 사용자 결정으로 확정했다:

> **폐기 = 세대 번호**(`mdm.terminal.token_version`). 발급할 때마다 +1 하고 그 값을 토큰 클레임 `tv`에 담아 매 요청 대조한다. **재발급이 곧 이전 토큰 전부의 무효화**다.
> `is_active`만으로는 폐기가 되지 않는다 — **스위치일 뿐이라 단말을 다시 켜면 유출 토큰도 되살아난다.** 실측: 유출 토큰 200 → 비활성화 401 → **재활성화 200**.

**그런데 `mdm.terminal`에 `token_version`이 없다** — 물리 모델 전 파일 검색 **0건**(실측). 설계검토 §6-② 자신이 이를 예고했다: 「정본 테이블을 수정하므로 **모델링 정본 SQL에 역반영이 필요**하다」.

**이 화면이 직접 걸린다.**

| 화면 요소 | `token_version` 없으면 |
| --- | --- |
| 「세대 3」 표시 | ⛔ **보일 값이 없다** |
| 「재발급」 | ⛔ 발급은 되지만 **이전 토큰이 안 끊긴다** |
| 분실 단말 차단 | ⛔ `is_active` 해제로 물러남 — **재활성화하면 되살아난다**(실측 확인) |

**A-11(물러난 수준 명시)을 적용한다** — 화면은 「사용 중지」만 두고 **「재발급으로 이전 토큰을 끊는 기능은 아직 없습니다」**를 명시한다. 없는 기능을 있는 것처럼 그리지 않는다.

→ **§I 신규 후보** §9-3. **이슈 대상**(`[docs→데이터모델]`).

⚠ **발급된 토큰 값은 한 번만 보인다.** 저장하지 않으므로(설계검토 §6-② — 토큰 해시 저장 안 함) 다시 볼 수 없다. 화면이 그렇게 말한다.

### §5-5. 단말 코드는 **전역 유일**이다 — 오류 문구에 범위를 담는다

```
terminal_code  app.code_t NOT NULL UNIQUE      ← plant_id 가 들어 있지 않다
```

`mdm.terminal`은 `plant_id` NOT NULL인데 **코드는 공장을 안 묶는다.** 1공장과 2공장이 각각 `POP-01`을 쓸 수 없다.

**A-1 적용** — 「이미 사용 중인 단말 코드입니다 (**전 공장 공통**)」. 「1공장에」라고 쓰면 **다른 공장에서 다시 시도하게 만든다.**

### §5-6. 설치 위치 — **회신 E-2 대기이지만 화면은 막히지 않는다**

REQ-PR-0017은 **비기능**이고 「설치 공정·위치 = 고객 정리 예정」이 잔여다. `terminal.location_id`는 **nullable**이다.

**G-2(미확정 코드 목록의 표시)를 위치에 적용한다**:

```
설치 위치  [ (미지정)        ▾ ]
           ⓘ 설치 위치는 고객사 정리 후 채웁니다 — 지금은 비워 둘 수 있습니다
```

**위치 없이도 단말은 동작한다** — 토큰 클레임은 `terminal_id`·`plantId`만 쓴다. 위치는 **관리 편의**다.

### §5-7. 액션

| 액션 | 활성 조건 |
| --- | --- |
| 단말 등록 | 항상 — `terminal_code`·`plant_id`·`terminal_type_code`·`status_code` 입력 시 |
| 단말 수정 | 선택 시. **단말 코드는 잠김**(B-4 — 키는 바꾸지 않는다) |
| **토큰 발급·재발급** | 선택 시 — ⚠ **경고 필요** §6 · ⛔ **세대 없이는 폐기 효과 없음**(§5-4) |
| 공정 추가 | 단말 선택 시. **이미 있는 공정은 목록에서 제외** |
| 공정 삭제 | 행 선택 시 — ⚠ **경고 필요** §6 |
| 플래그 토글 | 공정 행이 있을 때 |
| 저장 | 변경이 있을 때만. **단말 단위 한 트랜잭션**(§5-3) |
| 사용 중지 | ⚠ **경고 필요** §6 |
| 변경 이력 | ⛔ **없다** — §I-5(`audit_event` 키 규약 부재) |

### §7-1. 8플래그 격자는 `MatrixGrid`가 아니다

**`MatrixGrid`를 갭으로 잘못 봤던** 것과 같은 형태다. 「행=공정 × 열=기능 × 셀=체크박스」는 **표에 체크박스를 렌더하는 것**이고, `Table`의 `TableColumn.render?: (row, rowIndex) => ReactNode`가 그대로 받는다.

**`c`(조합 — 제품 소유)로 판정한다.** 서식 §6-1이 요구하는 「어떤 조합을 시도했는가」의 기록이다.

⚠ 가로 폭이 좁아 터지면 **컴포넌트가 아니라 레이아웃 문제**이므로 DS 이슈가 아니다.

## §9. 이 장에서 나온 공유 계약 후보

1. ⭐ **§F를 「권한 게이팅」에서 「인증·기능 구성·귀속 3층」으로 고쳐 쓴다** — 2026-07-28 설계검토 v0.5가 `terminal_process`를 「인가의 정본」에서 **「단말 기능 구성」**으로 스스로 격하했고 「**보안 경계는 단말 인증 하나뿐**」이라 못박았다. 우리 §F는 그 정정 전 상태다. **F-2의 「축이 둘」은 「축이 셋」**이고, **매트릭스는 모바일에 걸리지 않는다**(§2.3 — 「그게 정상이다」·「조치할 것이 없다」). 4차 `P-01-02` §8-3의 미확인은 **이미 답이 있던 것**이다 (§5-1)
2. **부여 테이블은 `version_no`가 없으므로 마스터의 토큰으로 충돌을 판정한다** — `terminal_process`처럼 B-6의 「부여 테이블」에는 낙관적 잠금 토큰이 없다. **행 단위로 저장하지 않고 마스터 단위 한 트랜잭션**으로 보내며 충돌 판정은 **마스터(`terminal.version_no`)를 대표로** 쓴다. A-5·A-6과 같은 형태다 (§5-3)
3. ⛔ **확정된 컬럼이 물리 모델에 없으면 화면은 그 기능을 그리지 않는다** — `token_version`이 ✓확정 2026-07-28인데 미착지라 **분실 단말을 영구히 끊을 수 없다**(`is_active`는 스위치라 재활성화 시 유출 토큰이 되살아난다 — 실측). **A-11을 적용해 「재발급으로 이전 토큰을 끊는 기능은 아직 없습니다」를 화면이 말한다.** 있는 척 그리면 운영자가 끊었다고 믿는다 (§5-4)
4. **기본값이 「전부 거부」인 부여 행은 만들어질 때 경고한다** — 8플래그가 전부 `DEFAULT false`라 공정만 추가하면 아무것도 못 하는 행이 된다. 저장은 막지 않되 **「저쪽 화면이 막힌다」를 이 화면이 미리 알린다.** G-3의 역방향이다 (§5-2)
