# W-CO-10 · 비밀번호 변경

> 작성일: 2026-08-11 · 서식: `00-화면스펙서식.md` v1.0 · 작성 주체: CREFLE OMF 팀 (UI/UX)
> ⭐ **DR-002 가 신설한 화면**이다 — 「2-A 직접 인증」 확정이 **화면 하나를 만들었다**(인벤토리 113 → 114).
> ⚠ **이 장은 짧다.** DR-002 가 **뺀 것이 많아** 화면이 작다 — 그것이 확정의 결과다.

## §0. 요약

- **개요**: 관리웹 전 사용자(본인)가 자신의 비밀번호를 바꾸는 화면. DR-002(2-A 직접 인증)가 신설했고, 같은 확정이 만료 주기·조합 규칙·직전 비밀번호 재사용 금지를 빼서 **필드가 셋(현재 비밀번호·새 비밀번호·새 비밀번호 확인)뿐**이다.
- **주요 데이터**: `password_hash`(`W-CO-01`이 정의한 컬럼을 그대로 씀) 대조·갱신. 최소 길이 8자는 `[추정]` — `app.operation_policy`에 둘 설계 결정.
- **핵심 액션**: 세 필드 입력 → 검증(8자 이상·두 값 일치·현재 비밀번호와 다름) → **변경**(성공 시 Toast, 강제 로그아웃 없음) / **취소**. 현재 비밀번호를 틀려도 계정을 잠그지 않는다.

## §3. ⭐ DR-002 가 **뺀 것**이 이 화면을 정한다

| DR-002 가 뺀 것 | 이 화면에 없는 것 |
| --- | --- |
| 비밀번호 **만료 주기** | ⛔ 「비밀번호가 만료되었습니다」 강제 변경 화면 |
| **조합 규칙** | ⛔ 「대문자·숫자·특수문자 포함」 검증·강도 표시 |
| **직전 비밀번호 재사용 금지** | ⛔ 「최근 3개와 다르게」 검증 · **비밀번호 이력 테이블** |

⭐ **남는 것은 셋뿐이다** — 현재 비밀번호 확인 · 새 비밀번호 · 확인 재입력.

⚠ **「그럼 왜 화면이 필요한가」** — **2-A 가 「사용자가 자기 비밀번호를 보유한다」**로 확정했기 때문이다. 보유하면 **바꿀 수단이 있어야** 한다. 관리자 초기화만 두면 **초기 비밀번호를 계속 쓰게 된다.**

⭐ **안내 문구가 「없다」를 말한다** — 「**문자 조합 규칙은 없습니다**」. **G-5**(사용자가 바꿀 수 없는 것에는 확정 번호를 문구에 넣는다)의 취지 — ⚠ **여기는 확정 번호 대신 「없음」을 명시**한다. 없으면 사용자가 **규칙을 추측하며 여러 번 시도**한다.

## §5. 필드·규칙

| 라벨(한 / 베) | 출처 | 필수 | 검증 |
| --- | --- | :-: | --- |
| 현재 비밀번호 | `password_hash` 대조 | ✅ | 틀리면 인라인 · ⚠ **실패 카운트에 넣지 않는다** §5-2 |
| 새 비밀번호 | **`[신설]`** | ✅ | **8자 이상**만 §5-1 |
| 새 비밀번호 확인 | — | ✅ | **A-2 짝 제약** — 두 필드에 함께 인라인 |

### §5-1. 최소 길이 8자 — **우리가 정한다**

DR-002 는 **조합 규칙**만 뺐고 **길이를 말하지 않았다.**

| | |
| --- | --- |
| ⛔ **길이 제한이 없으면** | 한 글자 비밀번호가 저장된다 |
| ✅ **8자** | 조합 규칙 없이 길이만 두는 것이 **최소 정책의 통상 형태**다`[추정]` |

⚠ **`[추정]`이다** — 검증 방법: **고객사 보안 요구가 있으면 확인.** ⭐ **`app.operation_policy` 에 두면 나중에 바꿀 수 있다**(B-22 · 정책 코드 여섯째).

### §5-2. ⛔ 현재 비밀번호를 틀려도 **계정을 잠그지 않는다**

`W-CO-01` 의 실패 카운트는 **로그인 실패**용이다. **이미 로그인한 사람이 현재 비밀번호를 틀리는 것**은 다르다.

| | 로그인 실패 | **여기** |
| --- | :-: | :-: |
| 누구인가 | **모른다** — 남일 수 있다 | ⭐ **이미 인증된 본인** |
| 잠그나 | ✅ 5회 | ⛔ **아니다** |

⛔ **잠그면 본인이 자기 계정을 잠근다** — 그리고 **자가 복구 경로가 없어**(DR-002 2-B ③) 관리자를 불러야 한다.

⚠ **그렇다고 무제한은 아니다** — **속도 제한**은 서버 몫이다. **화면 요건이 아니므로 넘기지 않는다.**

### §5-3. 변경 후 — **다시 로그인시키지 않는다**

⛔ **강제 로그아웃을 두지 않는다.**

| 왜 | |
| --- | --- |
| **본인이 바꾼 것**이다 | 남이 바꿨으면 현재 비밀번호를 몰랐을 것 |
| **작업 중일 수 있다** | 편집 중 화면이 날아간다 |

⭐ **B-15**(되돌릴 수 없는 행위를 자동화할 때는 명시적 반대 의사를 타이머보다 우선)의 취지 — **사용자가 요청하지 않은 중단을 만들지 않는다.**

### §5-4. 액션·상태

| 액션 | 활성 조건 |
| --- | --- |
| 변경 | 세 필드 입력 + 새 비밀번호 8자 이상 + 두 값 일치 |
| 취소 | 항상 — 직전 화면으로 |

**상태**: `초기` → `입력 중` → `변경 중` → `성공(Toast)` / `실패` / `통신 실패`

## §6. 예외

| 상황 | 처리 |
| --- | --- |
| 현재 비밀번호 불일치 | 인라인 — ⛔ **잠그지 않는다**(§5-2) |
| 새 비밀번호 8자 미만 | 인라인 — 「8자 이상이어야 합니다」 |
| 두 값 불일치 | **두 필드에 함께 인라인**(A-2) |
| **새 비밀번호가 현재와 같다** | ⚠ **막는다** — 「현재 비밀번호와 같습니다」. ⛔ **재사용 금지가 아니다**(DR-002 가 뺀 것) — **직전 1개**만, **바꾸지 않은 것을 바꿨다고 하지 않기 위해서**다. **화면이 제출 전에 먼저 막고**(§5-4) **계약도 같은 조건을 둔다**(400 · `code=SAME_AS_CURRENT`). ⛔ **「두 값 불일치」와 같은 부류가 아니다** «(정합주: 2026-09-05 정정 — 구표기 「같은 부류다」)» — 확인 칸은 계약에 프로퍼티가 없어 서버에 값이 **도달하지 않지만** 현재 비밀번호는 본문으로 **온다**. 서버도 판정할 수 있는 것을 화면에만 두면 **화면을 우회할 때 규칙이 사라진다** — 선검사만으로 확정하지 않는다(**A-1** ✓확정 2026-08-02). ⚠ **조건이 없다 — 전건이다**(우리 설계에 강제 변경 흐름이 없다 · §3). |
| 통신 실패 | 배너 + 재시도(**G-23**) |
| 오프라인 | **해당 없음** — 관리웹 온라인 전제 |

⚠ **「현재와 같음」을 막는 것이 DR-002 를 어기나** — **아니다.** DR-002 가 뺀 것은 「**직전 비밀번호 재사용 금지**」(이력 저장이 필요한 것)이고, **지금 값과 같은지는 이력 없이 그 자리에서 안다.** ⭐ **B-19**(단계별로 확인) 취지 — **「같은 규칙처럼 보이는 것」이 실제로 같은지 본다.**

## §9. 이 장에서 나온 공유 계약 후보

### 9-1. ⭐ **「없는 규칙」을 화면이 말한다**

「문자 조합 규칙은 **없습니다**」를 안내에 적었다.

**규칙안**: 사용자가 **있을 것으로 기대하는 제약이 없을 때** 화면이 **없다고 말한다.**

| 없으면 | 있으면 |
| --- | --- |
| 사용자가 **규칙을 추측하며 여러 번 시도**한다 | 한 번에 끝난다 |

⭐ **G-2**(미확정 코드는 감추지 않고 비활성 + 사유)·**G-9**(모르는 값과 없는 값을 다르게)와 같은 계열 — **「없음」도 정보다.**

**해당 후보**: 비밀번호 조합 규칙(이 화면) · 「승인 없이 바로 반영됩니다」 · 「이 값은 검증하지 않습니다」.

### 9-2. **같은 이름의 규칙이 실제로 같은지 본다** — B-19 의 작은 판

DR-002 가 「**직전 비밀번호 재사용 금지**」를 뺐다. 「현재와 같은 값 막기」는 **이름이 비슷하나 다르다.**

| | 뺀 것 | 남긴 것 |
| --- | --- | --- |
| 무엇 | **직전 N개**와 비교 | **지금 값**과 비교 |
| 필요한 것 | ⛔ **비밀번호 이력 테이블** | ✅ **없다** — 그 자리에서 안다 |

⭐ **뺀 이유가 「이력 저장이 필요해진다」였으므로**, 이력이 필요 없는 쪽은 **뺀 범위에 들지 않는다.**

⚠ **확정을 좁게도 넓게도 읽지 않는다** — **뺀 이유**를 보면 경계가 나온다.
