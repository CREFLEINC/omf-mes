# W-CO-01 · 계정 로그인

> 작성일: 2026-08-11 · 서식: `00-서식.md` v1.0 · 작성 주체: CREFLE OMF 팀 (UI/UX)
> **DR-002 확정**(2026-08-10)으로 동결이 풀린 화면이다.
> ⭐ **관리웹의 첫 화면**이고, **다른 모든 관리웹 화면의 전제**다 — 74화면이 「로그인 사용자」를 전제로 쓰였다.

## §0. 요약

- **개요**: 관리웹 전 사용자가 아이디·비밀번호로 인증하는 로그인 화면. 관리웹의 첫 화면이자 다른 모든 관리웹 화면의 전제이며, 로그인 전에는 탐색이 없어 `AppShell`을 쓰지 않는 유일한 관리웹 화면(단독 중앙 정렬)이다.
- **주요 데이터**: `app.app_user`(`login_id` 등 기존 항목) + `[신설]` 3컬럼(`password_hash`·`failed_login_count`·`last_login_at`). 로그인 후 `app.user_data_scope`(사업부·공장 두 축, 법인 축 없음)를 읽기만 한다.
- **핵심 액션**: 아이디·비밀번호 입력 → 로그인 → 성공 시 대시보드 진입 / 실패 시 뭉뚱그린 안내 + 남은 시도 횟수 표시(존재하는 계정만) / 5회 누적 시 잠금(관리자 초기화만 가능, 자가 복구 없음) / 언어 전환(한국어·Tiếng Việt)은 항상 가능.

## §3. ⛔ 인증 컬럼이 없다 — 6차가 이미 §I-3 으로 적었다

확대 6차 `P-CO-01`(사번 경량 인증) §I-3 이 「`app_user` 에 담을 컬럼이 없다 — `password_hash`·`failed_login_count`」를 남겼다. **그때는 POP 사번 인증이라 「그래서 비밀번호를 안 쓴다」로 끝났는데, 이 화면은 비밀번호가 본론**이다.

**A-13 4단을 돌렸다** — ① 한 층 아래 ② 다른 파일 ③ 다른 스키마 ④ 다른 이름. **네 단 다 없다.**

| 찾은 것 | |
| --- | :-: |
| `password`·`hash`·`credential`·`secret` 검색 | **0건** |
| `app.role`·`user_role`·`user_data_scope` | 권한만 — 인증 없음 |

→ **⑤ 원칙 1)** — **화면이 정의하고 모델이 따라온다.**

### §3-1. DR-002 2-B 가 요구하는 것은 **셋뿐**이다

```
① 복원 불가 저장      password_hash        [신설]
② 실패 누적 시 잠금    failed_login_count   [신설]  + locked_at [신설]
③ 관리자 초기화       ⭐ 화면이 이미 있다 — W-CO-02 「비밀번호 초기화」 액션
```

⭐ **DR-002 가 「안 나였다면 뺐을 액션이 살아남았다」**고 적은 그 액션이다.

⛔ **더 넣지 않는다** — 만료일·직전 비밀번호 이력·조합 규칙 설정은 **DR-002 가 명시적으로 뺐다.** ⚠ **「있으면 좋을 것 같은 필드는 쓰지 않는다」**(서식 원칙 2).

⚠ **`last_login_at` 은 DR-002 가 「필요」로 적었다**(「사용자 계정에 **비밀번호·실패 횟수·마지막 로그인 시각** 필요」) — 셋째로 더한다.

## §5. 필드·규칙

### §5-A. 입력

| 라벨(한 / 베) | 출처 | 타입 | 필수 | 검증·비고 |
| --- | --- | --- | :-: | --- |
| 아이디 | `app_user.login_id` | varchar(100) | ✅ | ✅ **UNIQUE(전역)** — 실재 |
| 비밀번호 | **`[신설]`** `password_hash` | — | ✅ | ⛔ **평문을 저장·로그하지 않는다** · ⛔ **조합 규칙 없음**(DR-002 2-B) |

### §5-B. 계정에 더할 것 — **`[신설]` 3**

| 컬럼 | 왜 |
| --- | --- |
| `password_hash` | DR-002 2-B ① **복원 불가 저장** |
| `failed_login_count` | 2-B ② **실패 누적 잠금** |
| `last_login_at` | DR-002 「마지막 로그인 시각 필요」 |

⚠ **잠금 상태를 별도 컬럼으로 둘까** — ⛔ **두지 않는다.** **A-14**(상태와 조건을 분리) — 「잠김」은 **`failed_login_count >= 임계`에서 파생**된다. ⭐ **A-15**(달력이 만드는 변화)와는 다르다 — 시간이 아니라 **카운트**가 만든다.

⚠ **`status_code` 가 이미 있다**(기본 `'ACTIVE'`) — **재직/퇴사 축**이고 **잠금과 다르다.** 섞지 않는다.

### §5-1. ⭐ 실패 안내 — **「누가 틀렸는지」를 말하지 않는다**

```
⚠ 아이디 또는 비밀번호가 맞지 않습니다.
   5회 틀리면 계정이 잠깁니다 (2/5)
```

| 하는 것 | 안 하는 것 |
| --- | --- |
| **아이디 또는 비밀번호**로 뭉뚱그린다 | ⛔ 「없는 아이디입니다」 — **계정 존재 여부가 새어 나간다** |
| **남은 횟수를 보인다** | ⛔ 잠긴 뒤에야 알리기 |

⚠ **남은 횟수를 보이는 것이 계정 존재를 알리지 않나** — **알린다.** 그런데 **DR-002 2-B 가 잠금을 요구**했고, **잠길 줄 모르고 잠기면 업무가 멈춘다.** ⭐ **G-3**(사유는 「어떻게 풀 것인가」를 담는다)이 그 판단의 근거다.

⛔ **근거를 바로 적는다** — **존재 노출은 감수한 트레이드오프**다. 없는 계정에 카운트를 보이지 않는 것은 **보일 카운트가 없기 때문**이지 노출을 막기 위해서가 아니다.

| 동작 | 존재 여부가 |
| --- | :-: |
| **존재하는 계정에만 카운트**(이 화면) | ⛔ **드러난다 — 감수한다** |
| 모든 시도에 카운트 | ✅ 안 드러남 · ⛔ **무의미한 숫자** |
| 아무 데도 안 보임 | ✅ 안 드러남 · ⛔ **잠길 줄 모른다** |

### §5-2. 잠긴 계정 — **스스로 풀 수 없다**

DR-002 2-B ③ 이 「**관리자가 초기화해 준다**」이고, **만료·재사용 금지를 뺀 것과 짝**이다(자가 복구 경로를 안 만든다).

```
⛔ 계정이 잠겼습니다.
   관리자에게 비밀번호 초기화를 요청하세요.
```

⛔ **이메일 인증·본인 확인 절차를 만들지 않는다** — DR-002 가 **최소 정책**을 확정했고, `email` 컬럼은 있으나 **발송 경로가 없다**(DR-003 이 알림센터를 정본으로 정했고 **사내망 전제**다).

⚠ **일정 시간 뒤 자동 해제도 두지 않는다** — **A-15**(달력이 만드는 변화)를 쓰면 컬럼이 아니라 파생으로 둘 수 있으나, **DR-002 는 「관리자가 초기화」만 정했다.** 근거 없이 늘리지 않는다.

### §5-3. 로그인 후 — **권한 범위는 사업부·공장 두 축**

DR-002 **2-C** 가 「**법인 축을 두지 않는다**」로 확정했다.

⭐ **`app.user_data_scope`(SQL 277)가 실재**한다 — 확대 1차 `W-CO-02` 가 다룬 그 테이블이다. **이 화면은 읽기만** 하고 **셸 헤더에 현재 귀속을 상시 표시**한다(**D-5** — 귀속 정보는 세션이 아니다).

⚠ **`W-03-01` §8 이 「법인 범위 — `legal_entity_id` 없음(§I-4)」을 미결로 적었다** — ⭐ **DR-002 2-C 가 그것을 닫았다.** 「없는 것이 맞다」로 확정됐다.

### §5-4. 액션·상태

| 액션 | 활성 조건 |
| --- | --- |
| 로그인 | 아이디·비밀번호 둘 다 입력 |
| 언어 전환 | 항상 |

**상태**: `초기` → `입력 중` → `인증 중` → `성공(대시보드로)` / `실패(카운트 표시)` / `잠김` / `통신 실패`

⛔ **「로그인 상태 유지」를 두지 않는다** — 근거가 없고, **공용 사무 PC**에서 위험하다. 필요하면 별도 결정으로.

## §9. 이 장에서 나온 공유 계약 후보

### 9-1. ⭐ **인증 실패 문구는 「무엇이 틀렸는지」가 아니라 「무엇을 하면 되는지」만 말한다**

| 상황 | 문구 | ⛔ 하지 않는 것 |
| --- | --- | --- |

**규칙안**: 인증·알림·공지 같은 **횡단 기능** 화면은

1. **「워크플로우 근거가 없다」를 §2 에 명시**한다 — 빈칸으로 두면 「빠뜨렸다」로 읽힌다
2. **대신 무엇이 근거인지 적는다** — 이 화면은 **DR-002 가 근거의 전부**다
3. ⚠ **그래서 「업무가 실제로 어떻게 도는가」를 확인할 데가 없다** — 결정이 곧 설계다

**해당**: `W-CO-01`(이 화면) · `W-CO-10` · `W-CO-03` · `W-CO-11` · `W-CO-04`.
