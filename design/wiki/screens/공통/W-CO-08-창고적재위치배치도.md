# W-CO-08 · 창고 적재 위치 배치도

> 작성일: 2026-08-11 · 서식: `00-서식.md` v1.0 · 작성 주체: CREFLE OMF 팀 (UI/UX)
> ⭐ **DR-004 가 화면의 목적을 바꿔 놓은 화면**이다 — 「공장 평면 + 설비 위치」에서 **「창고 평면 + 적재 위치」**로.

## §0. 요약

- **개요**: 관리웹에서 물류담당·전산담당이 창고 도면 위에 적재 위치를 점으로 찍어 보는 화면. DR-004로 목적이 「공장 평면 + 설비 위치」에서 「창고 평면 + 적재 위치」로 바뀌었고, **위치 관리가 활성인 창고**(위치가 둘 이상인 창고)에서만 쓰인다.
- **주요 데이터**: 창고(`mdm.warehouse`) · 위치 계층(`mdm.location.parent_location_id`) · 창고 도면(`app.attachment` 다형) · **신설** 좌표 2컬럼(`location.plan_x`·`plan_y`, 0.0~1.0 비율) · 재고(`inventory.inventory_balance`).
- **핵심 액션**: 창고 선택 → 좌 위치 목록 / 우 도면 조회, 편집 모드에서 도면 올리기·점 찍기·옮기기·지우기, 위치 선택 시 재고 조회, 창고 단위 저장(낙관적 잠금).

## §3. ⭐ 신설은 **좌표 둘뿐**이다 — 도면은 붙일 자리가 이미 있다

**A-13 4단을 돌린 결과, 필요한 것 셋 중 둘이 이미 있다.**

| 필요한 것 | 실재 | 어떻게 |
| --- | :-: | --- |
| **창고 도면 이미지** | ✅ **있다** | `app.attachment` 다형 — `target_type_code = 'WAREHOUSE'` |
| **위치 계층** | ✅ **있다** | `location.parent_location_id`(337) |
| **위치의 평면 좌표** | ⛔ **없다** | **`[신설]` 2컬럼** — 도면 위 상대 좌표 |

⭐ **`app.attachment` 가 다형이라 테이블을 안 만들어도 된다** — **다형 참조가 신설을 막았다**(A-16 가 값 목록을 계약에 두게 한 이유이기도 하다).

### §3-1. 좌표는 **픽셀이 아니라 비율**로 둔다

```
[신설]  location.plan_x   numeric   0.0 ~ 1.0
[신설]  location.plan_y   numeric   0.0 ~ 1.0
```

⚠ **도면 이미지가 교체되면 픽셀 좌표는 전부 어긋난다.** 비율로 두면 **같은 구도의 다른 해상도 이미지**로 바꿔도 유지된다. ⛔ **구도가 바뀌면 어차피 다시 찍어야 한다** — 화면이 그렇게 말한다(§6).

## §4. ⭐⭐ 「위치 관리 활성」을 **코드로 판정하지 않는다** — A-14

DR-004 파생 확인 1 이 **「`management_level_code` 값 목록이 미정이라 무엇이 활성인지 판정할 수 없다」**를 남겼다. **그대로 두면 이 화면이 시작되지 않는다.**

### §4-1. 조건으로 파생한다

| 판정 방법 | |
| --- | :-: |
| `management_level_code` 값으로 | ⛔ **값 목록이 미정**이라 지금 못 쓴다 |
| ⛔ **`mdm.location` 행이 있는가로** | ⛔ **늘 참이다** — 아래 |
| ⭐ **위치가 둘 이상인가로** | ✅ **지금 판정된다** |

⛔⛔ **「행이 있는가」는 안 된다 — 스키마가 모든 창고에 위치 행을 강제한다.**

```
inventory.inventory_balance.location_id               NOT NULL   (SQL 1093)
logistics.goods_receipt_line.destination_location_id  NOT NULL   (SQL 1304)
```

**재고를 한 번이라도 받은 창고는 위치 행이 반드시 있다.** 위치 관리를 안 하는 창고도 **「기본 위치」 한 행**을 두어야 재고가 선다.

⭐ **위치 관리를 한다는 것은 「창고 안을 나눈다」는 뜻**이고, 안 나누는 창고는 **기본 위치 하나뿐**이다. **둘 이상이면 나눈 것**이다.

⚠ **A-23 순서 2(「그 말이 참일 때 반드시 있는 것」)를 한 번 더 돌려서 고쳤다** — 처음 고른 조건은 **참일 때뿐 아니라 거짓일 때도 있었다.**

⚠ **A-14**(상태와 조건을 분리한다)를 그대로 따른 것이고, **`W-05-07` 이 「매핑 행이 있으면 대상」으로 판정한 것과 같은 형태**다. → §9-1

### §4-2. ⛔ 값 목록이 정해지면 **바꿔 끼운다** — 골격은 안 바뀐다

**차단이 아닌 이유**다. 판정식 한 줄이 바뀌고 **화면 구성은 그대로**다. → §8-1

## §6. 필드·규칙

### §6-A. 조회

| 요소 | 출처 | 비고 |
| --- | --- | --- |
| 창고 | `mdm.warehouse`(295) | ⚠ **위치가 둘 이상인 창고만**(§4-1) |
| 도면 | `app.attachment`(2626) | 없으면 §6-2 |
| 위치 | `mdm.location`(333) | 계층은 `parent_location_id`(337) |
| 점 | **`[신설]`** `plan_x`·`plan_y` | 없으면 **⚠ 「도면에 없음」** |
| 재고 | `inventory.inventory_balance`(1087) | `location_id`(1093)로 |

### §6-1. ⭐ 세 모양으로 그린다 — **「도면에 없음」을 잃지 않는다**

```
● 재고 있음      정상    좌표 있음 · on_hand_qty > 0
○ 비어 있음      회색    좌표 있음 · 재고 없음
⚠ 도면에 없음    경고    좌표 없음               ← 이것이 사라지기 쉽다
```

⛔ **좌표 없는 위치를 목록에서 빼면 안 된다.** **G-15**(비어 있으면 판정이 서지 않는 필드는 저장을 막지 말고 **목록에서 보인다**)와 **G-13**(세 모양)이 함께 걸린다.

⚠ **찾으러 간 사람이 도면에서 못 찾으면 「그 위치는 없다」로 읽는다** — 실제로는 **찍지 않았을 뿐**이고 물건은 거기 있다.

### §6-2. 도면이 없는 창고 — **화면이 없어지지 않는다**

```
📄 이 창고의 도면이 아직 없습니다.
   [ 도면 올리기 ]     위치 24개는 목록으로 볼 수 있습니다.
```

⭐ **왼쪽 목록은 그대로 쓴다** — 도면은 **보조**이고 위치 마스터가 본체다. ⛔ **빈 화면을 보이지 않는다**(**G-23** 취지 — 회색만 두지 않는다).

### §6-3. 편집 — **점을 찍는 것뿐이다**

DR-004 파생 확인 2 가 **「이미지 위 점 찍기 권고를 유지한다」**로 정했다.

| 하는 것 | ⛔ 안 하는 것 |
| --- | --- |
| 도면 이미지 올리기·교체 | ⛔ **도면 그리기 편집기** |
| 목록의 위치를 도면 위로 끌어다 놓기 | ⛔ 도형·선·구획 작도 |
| 점 옮기기 · 점 지우기 | ⛔ 축척·치수·회전 |
| — | ⛔ **설비 위치 배치**(DR-004 4-A — 필요 없어졌다) |

⭐ **위치는 여기서 만들지 않는다** — 위치 마스터(`W-01-*` 창고Location 마스터)가 만든다. **이 화면은 「어디에 있는지」만 정한다.** ⚠ 만들게 하면 **같은 마스터를 두 화면이 만든다.**

### §6-4. 액션·상태

| 액션 | 활성 조건 |
| --- | --- |
| 편집 | 전산담당·물류담당 |
| 도면 올리기 | 편집 모드 |
| 점 찍기·옮기기 | 편집 모드 · 위치 선택 |
| 재고 조회 | 위치 선택 |
| 저장 | 편집 모드 · 변경 있음 |

**상태**: `조회` ⇄ `편집` · `저장 중` · `충돌`

⚠ **낙관적 잠금이 걸린다** — `mdm.location.version_no`(SQL 354)가 있다. 두 사람이 같은 창고를 편집하면 **B-1** 대로 처리한다. ⛔ **점 하나마다 잠그지 않는다** — **창고 단위로 한 번 저장**한다.

| **4** | **도면 이미지 크기·형식 제한** | **설계 결정** | `[추정]` — `app.attachment.mime_type`·`file_size`(2632·2633) 실재. **이미지만·10MB** 권고 |
| **5** | **구 정의 흔적** — 「공장 평면」·「설비 위치」를 참조하는 문서 | **정합** | ⚠ **DR-004 가 폐기**했다. 인벤토리 v1.6 은 반영됨(실측). **다른 문서는 확인** |

⛔ **차단 미결 0건.**

## §10. 이 장에서 나온 공유 계약 후보

### 10-1. ⭐⭐ **값 목록이 미정인 코드로 화면을 막지 말고, 같은 뜻의 조건으로 파생한다**

**A-14**(상태와 조건을 분리한다)의 **미정 대응 판**이다.

| 순서 | |
| :-: | --- |
| 1 | 코드로 판정하려던 것을 **말로 바꿔 본다** — 「위치 관리를 하는 창고」 |
| 2 | **그 말이 참일 때 반드시 있는 것**을 찾는다 |
| 3 | ⛔⛔ **거짓일 때도 있는지 되짚는다** — 없어야 조건이 성립한다 |
| 4 | 그것으로 판정하고, **코드가 정해지면 바꿔 끼운다** |

⛔ **처음 고른 「위치 행이 있는가」는 순서 3 에서 걸렸다** — `inventory_balance.location_id NOT NULL`(1093)이라 **모든 창고가 참**이었다.

⚠ **미정을 기다리면 화면이 안 나오고, 임의로 값을 정하면 나중에 어긋난다.** **셋째 길이 있다.**

— `W-CO-08` §4 · A-14 · `W-05-07`(매핑 행이 있으면 대상)

### 10-2. ⭐ **그림으로 보이는 화면은 「그림에 없는 것」을 목록으로 함께 보인다**

**G-15·G-13 의 도해 판**이다.

⛔ **그림은 「찍은 것」만 보인다** — 안 찍은 것은 **화면에서 아예 사라진다**. 목록이 없으면 **사라진 것을 아무도 모른다.**

| 그림 | 목록 |
| --- | --- |
| 찾으러 갈 때 | **빠짐없이 볼 때** |
| 찍은 것만 | ⭐ **안 찍은 것도** |

— `W-CO-08` §5·§6-1 · G-13 · G-15

### 10-3. **배경 이미지에 붙는 좌표는 비율로 둔다**

⚠ 픽셀로 두면 **이미지 해상도가 바뀔 때 전부 어긋나고, 어긋난 것이 조용하다**(점이 사라지지 않고 **엉뚱한 곳에 찍힌다**).

⭐ **구도가 바뀌는 교체는 어차피 다시 찍어야 하므로, 저장 전에 파급을 말한다**(**G-19**).

— `W-CO-08` §3-1·§7
