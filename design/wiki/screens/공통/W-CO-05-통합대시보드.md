> 작성일: 2026-08-11 · 서식: `00-서식.md` v1.0 · 작성 주체: CREFLE OMF 팀 (UI/UX)
> **DR-003·DR-004 로 막고 있던 것 둘이 동시에 풀렸다.**

## §0. 요약

- **개요**: 관리웹에서 경영진·생산관리자가 로그인 직후 첫 화면으로 보는 통합 대시보드. 기준 축은 날짜·공장 둘뿐이며(§5-1) KPI 카드 5장(생산량·양품률·성능가동률·시간가동률·미처리 알람)과 일일 생산실적 추이, 미처리 알람, 진행 중 작업지시를 한 화면에서 넓게 보여 준다. 좁혀 보려면 각 카드에서 소유 화면으로 드릴다운한다.
- **주요 데이터**: `production.production_result`(생산량 5종) · `planning.routing_operation.standard_cycle_time_sec`·`standard_yield_rate` · `production.work_session`(실제 가동시간) · `mdm.shift.start_time`·`end_time`(교대 시간대)를 다룬다. 시간가동률의 분모(계획 조업시간)를 담을 휴일·계획 정지 테이블이 없어(§3-2), OEE(곱)는 그리지 않고 양품률·성능가동률·시간가동률 세 항을 나란히 보인다(§3-4).
- **핵심 액션**: 카드 클릭 시 소유 화면으로 드릴다운(기준 날짜·공장 전달) · 알람 항목 클릭 시 알림센터(`W-CO-03`) 이동 · 「자세히」로 일일 생산실적 조회 · 수동 갱신. 위젯 편집·배치 저장은 만들지 않는다(§5-5).

## §3. ⭐⭐ 14차가 넘긴 OEE — **받아서 실측했고, 그리지 않는다**

14차 `W-05-08` §5-1 이 이렇게 넘겼다.

> ⚠ **OEE 를 낼 수 없다는 뜻이 아니다** — **통합 대시보드(`W-CO-05`)처럼 세 도메인을 함께 보는 자리**가 그것을 맡는 것이 맞다.

### §3-1. ⭐ 14차의 이유는 **이 화면에서 해소된다**

14차가 못 그린 이유는 「**소유가 셋으로 갈린다**」였다(시간가동률=05 · 성능가동률=02 · 양품률=03).

⭐ **이 화면은 셋을 다 보인다.** 곱만 보이고 항이 안 보이는 문제가 **여기서는 생기지 않는다.** **14차의 이유만 놓고 보면 그릴 수 있다.**

### §3-2. ⛔⛔ 그런데 **다른 것이 걸린다 — 시간가동률의 분모가 없다**

```
시간가동률 = 실제 가동시간 ÷ 계획 조업시간
                              ↑ 이것이 성립하지 않는다
```

**A-13 4단을 돌렸다** — ① 한 층 아래 ② 다른 파일 ③ 다른 스키마 ④ 다른 이름.

| 찾은 것 | 결과 |
| --- | :-: |
| `calendar` · `work_calendar` · `workcalendar` | **0건** |
| `holiday` | **1건** — ⭐ **테이블이 아니다**(아래) |
| `non_working` · `closure` · `planned_stop` · `break_time` | **0건** |
| `maintenance` · `preventive` | **0건** |
| ✅ `mdm.shift.start_time`·`end_time`(542·543) | **있다** — 교대 시간대는 안다 |

⛔ **교대 시간은 알지만 「그날 조업했는가」를 모른다.** 휴일·계획 정지를 뺄 수 없으면 **쉰 날이 통째로 비가동으로 잡히고 시간가동률이 실제보다 낮게 나온다.**

### §3-3. ⭐⭐ 유일한 `holiday` 한 건이 문제를 정확히 보여 준다

```sql
-- SQL 3359, mdm.code_group('OPERATION_POLICY') 시드
('ALLOW_PRODUCTION_ON_HOLIDAYS',  '휴일 생산 허용',  100),
```

⭐ **정책은 「휴일에 생산을 허용할 것인가」를 묻는데, 어느 날이 휴일인지를 담을 곳이 없다.**

⚠ **이것은 F-3 이 말한 그대로다** — 「**게이트는 판정 근거 컬럼의 실재를 확인해야 성립한다**」. 판정 근거가 없는 정책 코드가 **시드에 이미 들어 있다.** **F-6**(판정할 수 없음을 통과로 처리하지 않는다)이 함께 걸린다. → §8-2

⚠ **✓설계확정 결정 03 이 「계획 비가동 = WorkCalendar 계층형」을 확정했다.** 확정은 있고 **물리 모델에 없다.** → §9-2

### §3-4. 결론 — **세 항을 나란히 보이고, 곱하지 않는다**

| | 그리나 | 이름 |
| --- | :-: | --- |
| **양품률** | ✅ | 재료 완비(1634~1638) |
| **성능가동률** | ✅ | `standard_cycle_time_sec`(648) |
| **시간가동률** | ⚠ **그리되 분모를 밝힌다** | 「**교대 시간 기준**(휴일·계획 정지 미반영)」 |
| **OEE(곱)** | ⛔ **그리지 않는다** | — |

⭐ **곱은 가장 약한 항의 오차를 그대로 물려받고, 그 오차가 어디서 왔는지를 감춘다.** 「OEE 61%」는 읽는 사람에게 **세 가지 서로 다른 행동** 중 무엇을 해야 할지 알려 주지 못한다. **셋을 나란히 보이면 어느 항이 낮은지가 바로 보이고, 그것이 경영진이 실제로 묻는 것**이다.

⚠ **L-14**(집계는 낼 수 있는 것만 내고 **이름을 빌리지 않는다**)를 그대로 따른 것이다. → §9-1

## §5. 필드·규칙

### §5-1. 기준 축은 **둘뿐**이다 — 날짜 · 공장

⛔ **필터를 늘리지 않는다.** 대시보드는 **좁히는 화면이 아니라 넓게 보는 화면**이다. 좁히려면 **드릴다운**으로 각 도메인 화면에 간다.

⚠ **공장 선택지는 사용자의 귀속 범위로 제한**된다(**D-5** — 현재 귀속을 셸 헤더가 상시 보인다).

### §5-2. 지표 5장 — **출처와 분모를 각각 적는다**

| 지표 | 분자 | 분모 | 소유 화면 |
| --- | --- | --- | --- |
| 생산량 | `good_qty` 합(1634) | — | `W-02-*` |
| **양품률** | `good_qty` | 수량 5종 합(1634~1638) | **03** `W-03-05` |

⭐ **각 카드가 자기 소유 화면으로 드릴다운한다** — 값이 이상하면 **누구에게 물어야 하는지가 화면에 있다.**

### §5-3. ⚠ 시간가동률에 **주석을 붙여서 보인다** — 숨기지도 빼지도 않는다

세 갈래 중 하나를 골라야 했다.

| 안 | 결과 |
| --- | :-: |
| 빼 버린다 | ⛔ REQ-PR-0036 이 요구한 것을 안 보이게 한다 |
| 그냥 보인다 | ⛔ **틀린 값을 맞는 값처럼** 보인다 |
| ⭐ **보이되 분모를 밝힌다** | ✅ **G-20 취지** |

⚠ **G-20 의 본칙은 「버려지는 데이터가 있으면 화면이 그렇게 말한다」이고, 여기는 「버려진 것」이 아니라 「분모에서 빠진 것」이다** — 낱말이 다르므로 **취지로 쓴다고 적는다**(⛔ 조항을 늘려 쓰지 않는다).

⛔ **주석을 툴팁에만 두지 않는다** — 카드 아래 **본문으로** 적는다. 툴팁은 **찾아야 보이고**, 이 사실은 **안 찾아도 보여야** 한다.

### §5-4. 집계 기준 시각 — **「언제 것인가」를 항상 적는다**

```

```

⚠ **C-17**(오프라인 집계는 「내가 아는 만큼」으로 줄이고 그 범위를 말한다)의 **온라인 판**이다. 대시보드는 오프라인이 아니지만 **집계 시점이 화면과 어긋난다** — 같은 이유로 범위를 말한다.

⭐ **목표선이 있어서 「목표 대비」를 조합으로 만들지 않아도 된다** → **`a`**(그대로 있음). **이월 종료.**

### §7-2. ⭐⭐ **`Gauge` 를 못 찾을 뻔했다 — 한 층 아래에 있다**

```
git ls-tree a554d11 src/components/         → Gauge 없음  (29종)
git ls-tree -r a554d11 src/components/Progress/
   → src/components/Progress/Gauge.tsx      ⭐ 있다
```

**`GaugeProps`: `value`·`min`·`max`·`size`(sm|md|lg)·`thickness`·`tone`·`thresholds`·`showValue`** — **임계값 색 전환까지 실재**한다.

⚠ **DS 판정 절차 ①(`ls-tree src/components/`)만으로는 「없다」가 나온다.** **A-13 의 DS 판**이다 — **한 층 아래를 본다.** → §9-3

⛔ **다만 이 화면은 `Gauge` 를 쓰지 않는다** — 지표가 다섯이라 **`StatCard` 가 나란히 읽힌다**. 게이지 다섯 개는 **비교가 안 된다**(각자 다른 원을 눈으로 견줘야 한다).

**신규 갭 0건.**

## §9. 이 장에서 나온 공유 계약 후보

### 9-1. ⭐⭐ **곱으로 만든 지표는 가장 약한 항의 신뢰도를 물려받는다 — 항을 나란히 보인다**

**L-14**(이름을 빌리지 않는다)의 **합성 지표 판**이다.

| 물음 | |
| :-: | --- |
| 1 | **항 중 하나라도 분모·분자에 결손이 있는가** |
| 2 | 있으면 ⛔ **곱을 만들지 않는다** — 항을 나란히 보인다 |
| 3 | 없으면 ✅ 곱을 만들되 **항을 함께 보인다** |

⭐ **「셋을 다 보이니 곱해도 된다」가 아니다** — **곱은 결손을 평균 내 감춘다.** 61% 를 보고 무엇을 할지는 **어느 항이 낮은가**로만 정해진다.

⚠ **14차는 「소유가 셋」이라 못 그렸고, 이 화면은 「분모가 없어서」 안 그린다.** **이유가 다르므로 14차의 이유가 해소돼도 결론이 유지된다.**

— `W-CO-05` §3 · L-14 · 14차 `W-05-08` §5-1

### 9-2. ⭐ **확정이 있는데 물리 모델에 없으면, 화면이 그것을 발견하는 자리다**

```
✓설계확정 결정 03    계획 비가동 = WorkCalendar 계층형
물리 모델            calendar·holiday 테이블  0건
정책 시드            ALLOW_PRODUCTION_ON_HOLIDAYS  있다   ← 판정 근거 없이
```

⚠ **셋이 서로 어긋나 있고, 그것이 드러난 곳은 집계를 그리는 화면**이다. **B-19**(「이미 있는 것을 쓴다」를 단계별로 확인)의 **상류 판** — **확정이 있다고 자리가 있는 것이 아니다.**

— `W-CO-05` §3-2·§3-3 · F-3 · B-19

### 9-3. ⭐ **DS 판정 절차 ① 을 보완한다 — 한 층 아래를 본다**

```
① git ls-tree --name-only <SHA> src/components/          ← 지금까지
② git ls-tree -r --name-only <SHA> src/components/<유사>/  ← 더한다
```

⭐ **`Gauge` 가 `Progress/` 안에 있었다.** 절차 ① 만 돌리면 「**없다**」가 나오고, **`d` 유형(새 원시 요소)으로 잘못 올라간다.**

⚠ **A-13 이 코드·컬럼에 대해 말한 것을 DS 에도 같게 적용한다.**

— `W-CO-05` §7-2 · A-13 · DS 판정 절차

### 9-4. **범용 정책 테이블의 코드 목록은 「새로 만드는 것」이 아니라 「이어붙이는 것」이다**(B-22 보완)

⭐ **`OPERATION_POLICY` 코드 그룹 시드가 물리 모델에 이미 있다** — **14건**(SQL 3341~3366). **B-22 규칙 1**(정책 코드 목록을 계약이 갖는다)은 **목록이 없다는 뜻이 아니었고**, 우리가 더할 코드는 **그 14건 뒤에 붙는다.**

| 확인할 것 | |
| :-: | --- |
| 1 | **이미 있는 코드로 되는가** — 예: 사후입력 허용시간은 `LATE_ENTRY_ALLOWED_HOURS` 가 이미 있다 |
| 2 | 없으면 **이름을 시드 관례에 맞춘다**(대문자·스네이크·단위를 이름에) |
| 3 | ⚠ **값 형·범위 축**은 계약이 계속 갖는다(B-22 규칙 1·4는 유효) |

⚠ **B-22 를 세울 때 시드의 실재를 확인하지 않았다** — **B-19 를 세운 우리가 B-19 를 안 돌린 자리**다.

— `W-CO-05` §3-3 · B-22 · B-19
