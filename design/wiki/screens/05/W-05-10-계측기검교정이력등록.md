## §0. 요약

- **개요**: 관리웹에서 품질담당이 계측기 하나를 골라 검교정·점검·수리·폐기 이력을 등록하는 화면. `quality.equipment_calibration`을 이력유형·교정 기관·기관명(모두 신설)으로 넓혀 **결정 06 을 유지**하고, 11차 `W-05-11`이 넘긴 미착지 2건을 여기서 결론짓는다(§3). 저장한 이력은 수정·삭제가 없다(B-3 이력 불변).
- **주요 데이터**: `quality.equipment_calibration`(넓힘) — 계측기 FK·이력유형[신설]·수행일·수행자·결과·비고 + 《검교정 전용》 유효기한·성적서 번호·교정 기관[신설]·기관명[신설]. 유일키는 (계측기+수행일+이력유형)으로 넓어진다(§5-5).
- **핵심 액션**: 계측기 선택(만료·임박 필터) → 이력유형·수행일·수행자·결과 입력(검교정이면 전용 4필드 추가 입력) → 이력 저장. 저장하면 결과=합격 계열일 때 `equipment.last_calibration_date`·`calibration_due_date`를 치환 갱신한다(낙관적 잠금, §5-3). 수정·삭제 버튼은 없음 — 잘못 입력하면 정정 이력을 새로 등록한다(§5-1).

## §3. ⭐ 결정 06 의 미착지 2건 — **결정 06 을 유지한다**

11차 `W-05-11` §4-C 가 「하류가 결정 06 이 **명시적으로 기각한 안**((b) 유형별 테이블)에 서 있다」를 짚고 **최종 형태를 이 화면으로 넘겼다.**

| 결정 06 | 하류 | 이 장의 결론 |
| --- | :-: | :-: |
| 단일 이력 + **이력유형 코드**(4종) | ⛔ 검교정 전용 | ✅ **결정 06 을 유지** |
| 성적서 번호 | ✅ `certificate_no` | — |
| **교정 기관(내부/외부)** | ⛔ 없음 | ✅ **더한다** |
| 차기 예정일 | ✅ `valid_until` | — |

### §3-1. 왜 결정 06 을 유지하는가 — 근거 셋

1. ⭐ **11차 B-16 판정식이 「열린 수리 이력」을 요구한다** — 계측기의 사용 가부는 「운용 + 검교정 유효 + **열린 수리 이력 없음**」이다. **검교정 전용 테이블에는 수리를 담을 수 없다.**
2. **결정 06 이 (b)를 기각한 이유가 그대로 유효하다** — 「유형 추가마다 스키마 변경」. 하류는 **검교정 하나만 만들어** 이미 그 상태다.
3. **데이터량이 작다** — 결정 06 이 「유형별 테이블 분리는 계측기 데이터량(소규모) 대비 **과설계**」라 했다. 반대도 같다 — **테이블 하나면 충분**하다.

### §3-2. 확정 — `equipment_calibration` 을 **넓힌다**

```
quality.equipment_calibration   ← 이름은 그대로 (11차 W-05-13 의 mold 와 같은 판단)
  + history_type_code           이력유형 (검교정 / 점검 / 수리 / 폐기)  [신설]
  + calibration_agency_type     교정 기관 (내부 / 외부)                 [신설]
  + agency_name                 기관명 — 외부일 때                      [신설]
    calibration_date  → performed_at 의 뜻으로 쓴다                     (이름 유지)
    result_code · valid_until · certificate_no                          (검교정 전용)
```

⭐ **11차 `W-05-13` 이 `mdm.mold` 에 대해 내린 판단과 같다** — 「테이블 이름을 바꿔 달라고 하지 않는다. 이름 변경은 참조를 함께 고치는 일이고 그 값이 유형 코드 하나를 더하는 것보다 크지 않다.」

⚠ **유형별 필드가 비게 된다** — 수리 이력에 `valid_until`·`certificate_no` 는 없다. **A-2**(조건부 필수·짝 제약)로 화면이 다룬다(§5-2).

⚠ **유일 제약이 걸린다** — `uq_equipment_calibration (equipment_id, calibration_date)`. 유형이 늘면 **같은 날 검교정과 점검을 둘 다** 할 수 있다. → §5-5

**⛔ 이 표에 `updated_at`·`version_no` 가 없다** — 실측이다. **B-3**(이력 불변)이 스키마에 드러나 있고, 11차 `W-05-11` §4-B 가 이미 짚었다. **이 화면도 수정·삭제를 주지 않는다**(§5-6).

### §5-1. ⛔ 이력을 **고칠 수 없다** — 그래서 입력을 신중하게 만든다

`updated_at` 이 없으므로 **저장하면 끝**이다. **화면이 그 무게를 보여야** 한다.

| 하는 것 | |
| --- | --- |
| 저장 전 **요약 확인** | 「검교정 · 2026-08-11 · 유효 ~2027-08-10 · 외부」 |
| ⚠ **파급을 명시** | 「저장하면 계측기의 **차기 예정일이 갱신**됩니다」 |
| 잘못 넣었으면 | **정정 이력을 새로 넣는다** — ③ 목록에 둘 다 남는다 |

⚠ **「정정」이 이력유형에 없다** — 결정 06 초안 4종(검교정/점검/수리/폐기)에 없다. **관리자 설정형**이므로 필요하면 값을 더하면 된다. ⛔ **우리가 지금 더하지 않는다** — 근거가 없다. → §8-3

### §5-2. 유형마다 필드와 결과 값이 다르다 — A-2

| 유형 | 검교정 전용 4필드 | 결과 값 예 |
| --- | :-: | --- |
| **검교정** | ✅ 필수 | 합격 / 조정 후 합격 / 불합격 |
| 점검 | ⛔ 비활성 | 정상 / 이상 |
| 수리 | ⛔ 비활성 | 완료 / 불가 |
| 폐기 | ⛔ 비활성 | — |

⭐ **G-10**(읽기 전용 구획 + 사유)으로 그린다 — 감추지 않고 **비활성 + 사유**(「검교정 이력에만 적습니다」).

⚠ **결과 값 목록이 유형마다 다르다** — 한 코드 그룹에 다 넣고 유형으로 거른다. **`W-06-06`** 소관이며 **G-2**(비활성 + 사유)로 만든다.

### §5-3. ⭐ 저장이 **마스터를 갱신한다** — B-13

11차 `W-05-11` §4-A 가 `last_calibration_date`·`calibration_due_date` 를 **읽기 전용**으로 잠그고 「**`W-05-10` 이 정한다**」로 넘겼다. **여기가 그 자리다.**

```
유형 = 검교정 AND 결과 = 합격 계열
  → equipment.last_calibration_date = 수행일
  → equipment.calibration_due_date  = 유효기한
```

| 규칙 | |
| --- | --- |
| **치환이다 — 증분이 아니다** | **B-18 단서**(13차) 적용: **낙관적 잠금을 건다**(B-1) |
| **불합격이면 갱신하지 않는다** | 유효기한이 늘어나면 안 된다 |
| 점검·수리·폐기 | ⛔ **갱신하지 않는다** |

⭐ **13차 `W-05-03`(툴 PM 리셋)과 같은 형태**다 — 한 사람이 한 번 하는 치환이라 잠금을 건다.

⚠ **유효기한을 사람이 고칠 수 있게 둔다** — 성적서에 적힌 날이 「수행일 + 주기」와 다를 수 있다. **계산값을 제안하고 사람이 확정**한다(ⓘ 「수행일 + 주기 12개월 = 2027-08-11」).

### §5-4. 교정 기관 — **외부면 기관명을 자유 텍스트로**

결정 06 이 「교정 기관(**내부/외부**)」만 정했다. **기관명을 어디에 적나.**

⭐ **13차 `W-05-06` §5-5(외주처)와 같은 판단**을 그대로 쓴다.

| | |
| --- | --- |
| `mdm.partner` FK | ⛔ **쓰지 않는다** — 교정 기관은 구매 협력사로 등록돼 있지 않을 가능성이 높다 |
| 자유 텍스트 | ✅ 등록을 강제하면 **이력을 못 적는다** |

### §5-5. 유일 제약이 유형 추가로 걸린다

`uq_equipment_calibration (equipment_id, calibration_date)` — **같은 날 검교정과 점검을 둘 다 하면 막힌다.**

**확정 — 유일 제약을 (계측기 + 수행일 + **이력유형**)으로 넓힌다.**

⚠ **11차 `W-05-11` §8-3 이 「정정 재검교정이 같은 날 일어나면 막힌다 — `W-05-10` 설계 시 확인」으로 남겼다.** 유형을 더해도 **같은 날 같은 유형 두 번**은 여전히 막힌다.

| 안 | 판정 |
| :-: | :-: |
| 유형까지 넓힌다 | ✅ **한다** — 유형이 늘었으니 필연이다 |
| **회차까지 넓힌다** | ⛔ **하지 않는다** — 같은 날 같은 검교정을 두 번 하는 것은 **드물고**, 막히면 **다음 날로 적거나 비고에 쓴다** |

⭐ **A-14** 취지 — **값을 늘리기 전에 정말 필요한지 본다.** 실무 빈도 근거가 없다.

| 이력 저장 | 유형 + 수행일 + 결과 (+ 검교정이면 전용 4필드) |
| ⛔ **수정·삭제** | **없다**(B-3 · `updated_at` 부재) |

**상태**: `초기(EmptyState)` → `계측기 선택됨` → `입력 중` → `저장 중` → `성공` / `실패` / `충돌(B-1)`

## §9. 이 장에서 나온 공유 계약 후보

### 9-1. ⭐ **고칠 수 없는 기록은 저장 전에 파급을 말한다**

`equipment_calibration` 은 `updated_at` 이 없어 **수정이 불가능**하고, 저장이 **마스터의 차기 예정일을 갱신**한다.

**규칙안**: 이력 불변(B-3) 테이블에 쓰는 화면은

1. **저장 전 요약**을 보인다 — 무엇이 남는지
2. ⭐ **파급을 명시**한다 — 「저장하면 **차기 예정일이 갱신**됩니다」
3. **정정 경로를 안내**한다 — 「잘못 넣었으면 **정정 이력을 새로** 넣습니다」
4. ⛔ **수정·삭제 버튼을 두지 않는다** — 회색으로도 두지 않는다(있으면 찾는다)

⚠ **B-3 는 「이력은 불변이다」만 말하고 화면이 무엇을 해야 하는지는 안 말한다.**

### 9-2. **유형 코드를 더하면 유일 제약을 함께 본다**

§5-5 가 그 사례다 — 단일 이력에 유형을 더하자 **기존 유일 제약이 곧바로 막았다**(같은 날 검교정 + 점검).

**규칙안**: 테이블에 **유형 코드를 더할 때**(결정 06 의 P1 패턴) **기존 유일 제약·인덱스를 함께 검토**한다.

| 확인할 것 | |
| --- | --- |
| 유일 제약에 유형을 더해야 하나 | 대개 **그렇다** — 유형이 다르면 다른 사건이다 |
| **더해도 남는 충돌이 있나** | 같은 날 같은 유형 두 번 — **빈도 근거 없이 회차를 더하지 않는다**(A-14) |
| 조건부 필드가 생기나 | **A-2** 로 화면이 다룬다 · **G-10** 으로 그린다 |

⭐ **11차 `W-05-13`(툴 유형 코드)에서도 같은 일이 있었다** — 거기는 `cavity_count NOT NULL DEFAULT 1` 이 지그에도 값을 넣는 문제였다(그 장 §8-2). **유형 추가는 제약을 흔든다.**
