# M-05-01 · 설비 점검 입력

> 작성일: 2026-08-11 · 서식: `00-화면스펙서식.md` v1.0 · 작성 주체: CREFLE OMF 팀 (UI/UX)
> ⭐ **마스터가 정의한 점검 항목이 처음으로 쓰이는 화면**이고, **넘긴 확인 항목 2건**(점검 기록의 형태 · 표시 순서)이 여기서 결정된다.
> ⚠ **이 화면이 만드는 기록이 POP-작업전점검의 통제 근거**다 — 그래서 오프라인 판단이 다른 화면들과 다르다(§6-2).

## §0. 요약

- **개요**: 현장 오퍼레이터(일상 점검)나 설비담당(정기 점검)이 모바일(PDA)에서 설비를 스캔·선택해 점검 유형을 고르고, 항목별로 측정값 또는 육안 판정을 입력해 종합 판정과 함께 점검 이력을 남기는 현장 입력형 화면이다. 이 화면이 만드는 점검 이력은 작업 전 점검 통제 화면이 참조하는 통제 근거라서, 오프라인 입력을 허용하되 미전송 상태를 상시 경고하는 별도 처리를 둔다.
- **주요 데이터**: 점검 헤더(설비 · 점검 유형 · 점검일시 · 점검자 사번 · 종합 판정 · 비고 — 전부 신설), 점검 결과 라인(점검 항목 부여 · 순번 · 측정값 · 판정 · 항목 비고 — 전부 신설), 설비별 점검 항목 부여와 판정 기준(하한·상한·단위).
- **핵심 액션**: 설비 QR 스캔 또는 목록 선택 → 점검 유형(일상/정기) 선택 → 항목별 측정값 입력 또는 합격/NG 선택(기준이 있으면 자동 판정, 사람이 덮어쓸 수 없음) → 종합 판정 확인(NG 있으면 비고 필수) → 점검 완료. NG는 보전을 부르되 발행하지 않는다.

## §5. ⭐ 넘긴 확인 항목 2건을 여기서 정한다

### §5-1. 확인 1 — **점검 기록은 헤더-라인 2계층이다**

§7-1 이 「항목별 행인가 점검 1건에 결과 묶음인가」를 남겼다. **둘 다다 — 헤더 1건 + 라인 N건.**

**근거 셋**

| # | 근거 |
| :-: | --- |
| **1** | **도식 MES-1 이 그렇게 적었다**(실측) — 「KEY - **점검이력No** / 설비코드+점검유형 / **항목별 결과**·합/NG 판정 / 점검자=사번 귀속·점검일시」. **키가 하나이고 항목별 결과가 여럿**이다 |
| **2** | **WF05 S2 Result 도 그렇다** — 「설비점검이력 **1건**(점검이력 No, 점검유형, **항목·결과**, 점검일시, 점검자)」 |
| **3** | ⭐ **하류에 같은 형태가 이미 있다**(실측) — `quality.inspection_result`(헤더) + `quality.inspection_measurement`(라인). **✓설계확정 결정 01** 이 「헤더/라인 분리」를 확정한 그 구조다 |

⭐ **3번이 결정적이다.** 품질 검사가 이미 「검사 1건 = 헤더 + 항목별 라인」으로 서 있다. **점검도 같은 모양으로 두면 구현이 같은 골격을 재사용**한다.

⚠ **§4-C 가 「점검 항목 ≠ 검사 항목」으로 테이블을 나눈 것과 모순되지 않는다** — **모양을 빌리되 테이블은 나눈다**(§4-C-1). 소유·대상·게이트가 다르기 때문이며, **구조가 같은 것과 같은 테이블을 쓰는 것은 다른 얘기**다.

### §5-2. 판정은 **항목마다 방식이 다르다**

§4-C-1 이 판정 방식을 「육안(합/NG) / 측정값」 둘로 정의했다. **화면이 그것을 그대로 따른다.**

| 방식 | 입력 | 판정 |
| --- | --- | --- |
| **육안** | `[합격]` `[NG]` 두 버튼 | **사람이 고른다** |
| **측정값** | 숫자 입력 + 단위 | **하한 ~ 상한으로 자동 판정** — 즉시 옆에 결과 표시 |

⚠ **자동 판정을 사람이 덮어쓸 수 없게 한다.** 측정값이 범위 밖인데 「합격」으로 바꿀 수 있으면 기준이 의미를 잃는다. **범위 밖인데 합격시켜야 한다면 그것은 점검이 아니라 특채·한도승인 영역**이고, 그 경로는 품질(`W-03-09`)이 갖는다.

⚠ **하한·상한이 비어 있으면 자동 판정이 안 선다** — **G-15**(비어 있으면 판정이 안 서는 필드) 적용. 저장은 막지 않고 **「기준 미등록 — 육안으로 판정하세요」**로 그린다.

### §5-3. 종합 판정을 **저장한다** — 파생으로 두지 않는다

`종합 판정 = 라인에 NG 가 하나라도 있으면 NG` 는 파생식으로 보인다. **그런데 저장한다.**

**A-15**(달력이 만드는 변화를 컬럼에 넣지 않는다)의 **판별 질문을 돌려 보면 답이 나온다.**

> 「아무도 아무것도 하지 않아도 이 값이 바뀌는가?」 → **아니다.**

라인은 점검 시점에 확정되고 **이후 바뀌지 않는다**(B-3 이력 불변). **A-15 는 시간이 바꾸는 값을 막는 조항이지 파생값 전부를 막지 않는다.**

**저장하는 이유 둘**

1. **작업 전 점검 통제가 이것 하나만 본다** — 라인 N건을 매번 훑어 판정하면 통제 화면이 느려지고, **판정 규칙이 두 화면에 복제**된다
2. **항목 부여가 나중에 바뀌어도 과거 판정이 흔들리지 않는다** — 라인에서 매번 재계산하면 항목이 추가·삭제될 때 **과거 점검의 종합 판정이 소급으로 달라진다**

⭐ **A-15 와 이 판단의 경계가 조항 후보다** → §9-1

### §5-4. NG 는 **보전을 부르지만 만들지는 않는다**

WF05 S2 의 핵심 전제 — **「점검 = 진단, 보전 = 조치」**. 도식 H1 이 NG 를 사이드 B(경량 보전)로 보낸다.

| 이 화면이 하는 것 | 이 화면이 하지 않는 것 |
| --- | --- |
| NG 를 기록한다 · **보전이 요청됨을 알린다** | ⛔ **보전 지시를 발행하지 않는다**(`W-05-05` 소관) |

⚠ **자동 발행하지 않는 이유** — WF05 S2 [Check] 가 「NG→보전 전환이 **자동/수기** 어느 쪽인지(내부 설계)」를 남겼고, **점검자(오퍼레이터)에게 보전 지시 권한이 없다.** 화면은 「요청됨」까지만 하고 **설비담당이 `W-05-05` 에서 발행**한다.

### §5-5. 액션·상태

| 액션 | 활성 조건 |
| --- | --- |
| 설비 스캔 / 목록 선택 | 항상 (D-3 — 스캔 실패 시 직접 선택) |
| 점검 완료 | **필수 항목 전건 판정** + 설비·유형 선택 |
| 다시 입력 | 미저장 상태 |

**상태**: `초기` → `설비 선택됨` → `입력 중(N/M)` → `저장 중` → `성공` / `실패` / **`미전송 큐`**(§6-2)

⚠ **부분 저장을 두지 않는다.** 점검은 **한 번에 한 설비**이고 항목 수가 10 내외다. 부분 저장을 두면 「어디까지 했나」를 관리해야 하고, **미완 점검이 통제 판정에 걸리는지**가 또 갈린다.

⛔ **그런데 이 화면이 만드는 것이 남의 판정 근거다.**

```
M-05-01 점검 입력  ──(점검 이력)──▶  P-02-02 작업 전 점검 통제
                                      「주기 내 점검 이력이 있는가」로
                                      작업을 차단·경고·통과시킨다 (QA #9)
```

**오프라인으로 점검하면 서버에 이력이 없다. 통제 화면은 「점검을 안 했다」와 「했는데 아직 안 올라왔다」를 구분할 수 없다.**

| 통제 수준 | 오프라인 점검의 결과 |
| --- | --- |
| 미적용 | 문제 없음 |
| 경고 | 잘못된 경고가 뜬다 |
| **차단** | ⛔ **점검을 했는데 작업이 막힌다** |

**확정 — 허용하되 셋을 한다.**

1. **오프라인 입력을 허용한다** — 점검자는 순회 중이고 공장 구석은 통신이 약하다. 막으면 종이로 적고 나중에 옮긴다(현행 그대로다)
2. ⭐ **미전송 건이 있으면 화면 상단에 상시 경고**한다 — 「**미전송 점검 2건 — 작업 통제에 반영되지 않습니다**」. `Chip`(warning) 상시(C-1)
3. **전송 성공까지 「완료」로 그리지 않는다** — **C-7 ⓑ 미확정 표식**을 쓴다

⚠ **C-7 ⓑ 는 원래 「실물이 움직이는 작업」용**이다(출고·적치·이동). **여기는 실물이 안 움직이는데 ⓑ 를 쓴다** — 판단 기준이 하나 더 있다는 뜻이다. → §9-2

**C-11 선행 데이터** — 오프라인에서 화면이 서려면 미리 받아야 하는 것:

| 무엇 | 언제 받나(C-13) |
| --- | --- |
| 설비 목록(코드·명·계층 텍스트) | **앱 시작 시** |
| 설비별 점검 항목 부여 + 기준(하한·상한·단위) | **앱 시작 시** — ⚠ 부여가 바뀌면 다음 시작까지 옛 항목으로 점검한다 §8-3 |
| 작업자 사번 목록 | 앱 시작 시(C-13 · `M-CO-01` 과 같은 규약) |

⛔ **캐시하면 안 되는 것 — 없다.** 점검 항목·기준은 **표시값이지 판정값이 아니다**(C-6 · C-13 보강 기준: 「틀렸을 때 무엇이 일어나는가」 → 옛 기준으로 점검하면 **다음 점검에서 바로잡힌다**).

**C-2 오프라인 유일성** — 같은 설비·같은 날·같은 유형의 점검이 두 단말에서 들어올 수 있다. **거부하지 않는다** — 점검은 여러 번 해도 되는 행위이고, 중복이면 **최근 것이 통제 판정에 쓰인다**(가장 가까운 것이 이긴다 — B-17 과 같은 형태).

## §9. 이 장에서 나온 공유 계약 후보

### 9-1. **A-15 의 경계 — 「시간이 바꾸는 값」과 「한 번 정해지면 안 바뀌는 파생값」**

A-15 는 「달력이 만드는 변화를 컬럼에 넣지 않는다」이고 판별 질문은 **「아무도 아무것도 하지 않아도 이 값이 바뀌는가?」**다.

**종합 판정은 그 질문에 「아니다」로 답한다** — 라인이 이력 불변(B-3)이므로 시간이 흘러도 안 바뀐다. **그래서 저장해도 된다.**

**규칙안 — 파생값을 저장할지 정하는 질문 둘**

| 질문 | 「예」면 |
| --- | --- |
| ① 시간이 지나면 값이 바뀌는가 | ⛔ **저장 금지**(A-15) |
| ② 재료가 나중에 바뀌면 **과거 값이 소급으로 달라지는가** | ✅ **저장한다** — 그 시점의 판단을 얼려야 한다 |

**②의 해당**: 점검 종합 판정(항목 부여가 바뀐다) · 검사 종합 판정 · 원가 스냅샷 · 승인 시점의 결재선(J-9 가 같은 취지를 결재선에 대해 이미 정했다).

⭐ **J-9(「결재선을 바꿔도 진행 중인 요청은 옛 결재선으로 끝난다」)의 일반형**이다.

### 9-2. ⭐⭐ **C-14 에 반대쪽이 없다 — 「내가 만든 것이 남의 판정 근거인가」**

C-14 는 **읽는 쪽**만 본다.

```
C-14        이 화면이 판정값을 쓰는가        → 쓰면 오프라인 금지
없는 것     이 화면이 만든 것이 남의 판정 근거인가 → ?
```

**후자가 이 화면이다.** 점검 이력이 없으면 작업이 막힌다(QA #9 차단 설정 시).

**규칙안 — 세 가지를 함께 한다**

1. **오프라인 입력은 허용한다** — 막으면 현장이 종이로 돌아간다
2. **미전송 건이 있으면 상시 경고**한다 — 「미전송 N건 — **작업 통제에 반영되지 않습니다**」. 무엇에 반영되지 않는지를 **이름으로** 적는다
3. **C-7 ⓑ 미확정 표식**을 쓴다 — ⓑ 의 조건을 **「실물이 움직인다」에서 「되돌리기 어려운 결과가 남 쪽에서 일어난다」로 넓힌다**

⚠ **그리고 게이트 쪽이 이 사실을 알아야 한다** — 「이력 없음」을 「점검 안 함」으로 단정하지 않는다. **F-5**(게이트를 만드는 화면과 집행하는 화면을 나눈다)에 **미동기 경우**를 더한다.

### 9-3. **C-12(단말 시계)** — ✅ **v1.8 해소 · v2.7 범위 축소**

이 절이 제기한 요구는 `P-05-02` §9-1 의 규약안으로 **v1.8 에 해소**됐다.
⛔ 다만 **2026-08-18 에 그 규약안의 근거가 뒤집혀** 오차 보정은 범위 밖이 됐다(**C-12** v2.7).
**남은 것은 「단말 시각을 그대로 쓰고 서버가 덮지 않는다」 하나**이고, 아래 표는 **그때의 판단 기록**이다.

**셋이 시각을 데이터로 쓴다.**

| 화면 | 시각이 무엇을 정하나 |
| --- | --- |
| `M-05-01`(이 화면) | **주기 내 점검인가** — 통제 판정 |
| `M-05-02` 고장 보고 | 고장 발생 시각 |

⚠ **「미결이니 나중에」로 넘길 수 없는 지점에 왔다.** 특히 비가동은 **시각 오차가 곧 OEE 오차**다. → `P-05-02` §9 에서 규약안을 낸다.
