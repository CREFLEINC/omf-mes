## §5. 액션·상태

### §5-1. 처리 상태 전이 — **셋뿐이고 되돌리지 않는다**

```
접수 ──▶ 처리중 ──▶ 완료
  └──────────────────▲   (경미 건은 바로 완료)
```

| 전이 | 조건 | 무엇이 필요한가 |
| --- | --- | --- |
| 접수 → 처리중 | 설비담당이 확인 | — |
| 처리중 → 완료 | | **원인 코드 + 처리 내역 필수** |
| 접수 → 완료 | 경미 건 | 동상 |
| ⛔ **되돌리기** | | **없다** — 잘못 완료했으면 **새 고장 건**을 만든다 |

**왜 되돌리기를 두지 않는가** — 완료가 **보전 지시·비가동 종료의 근거**가 된다. 되돌리면 그것들이 붕 뜬다. **B-3**(이력 불변)과 같은 취지이며, 12차가 「처리 상태 값을 늘리지 않는다」(A-14)로 이미 좁혀 뒀다.

### §5-2. ⛔ 현장이 적은 것을 사무가 고치지 않는다

증상·정지 시각·사진은 **읽기 전용**이다. 틀렸으면 **처리 내역에 적는다**.

**왜** — 현장 보고는 **그 시점의 관찰 기록**이고, 사무가 고치면 **누가 무엇을 봤는지가 사라진다.** 공유계약 **G-10**(읽기 전용 구획 + 사유)으로 그리고 사유를 보인다 — 「현장 보고 원문입니다. 정정은 처리 내역에 적으세요」.

⚠ **12차 `M-05-02` §5-2 가 「증상은 설비담당이 이 한 줄만 보고 출동한다」로 A-12 를 걸었다** — 그 한 줄을 사무가 덮으면 A-12 의 의미가 없어진다.

### §5-3. ⭐ 원인 코드는 **`quality.cause_code` 를 쓰지 않는다**

`quality.cause_code`(SQL 1907)가 실재하고 「원인코드」라는 이름이 같다. **A-13 ④ 를 돌린 결과 — 쓰면 안 된다.**

| | `quality.cause_code` | **설비 고장 원인** |
| --- | --- | --- |
| 무엇의 원인 | **불량(defect)의 원인** — `defect_record` 가 추정/확정 2컬럼으로 참조 | **설비 고장의 원인** |
| 소유 | 품질담당(`W-06-03` 불량·원인코드 2계층 마스터) | **설비담당** |
| 값 | 작업자 부주의·자재 불량 … | 부품 마모·윤활 부족 … |

⛔ **이름이 같다고 같은 것이 아니다.** 섞으면 **불량 원인 통계에 설비 고장이 들어간다.**

⭐ **11차 §4-C-1 과 같은 판단**이다 — 「모양을 빌리되 테이블은 나눈다」. **다만 여기는 모양도 안 빌린다** — 값 목록만 새로 만들면 되므로 `mdm.code_value`(공통코드)로 충분하다. → §8-2

### §5-4. 보전 지시로 넘기는 것은 **선택**이다

WF05 S5 Exception ① 이 「**긴급 고장 — 지시 없이 선조치 → 지시-이력 역순/지시 생략?**」을 남겼다.

| 경로 | 언제 |
| --- | --- |
| 고장 → **보전 지시 발행**(`W-05-05`) → 보전 실적(`W-05-06`) | 계획을 세워 처리할 때 |
| 고장 → **바로 완료** | 현장에서 이미 조치했을 때(선조치 후기록) |

⛔ **지시를 강제하지 않는다.** 강제하면 **이미 고친 건에 형식적 지시를 만들게** 되고, 그 지시는 발행 즉시 완료 처리된다 — 데이터가 늘고 뜻은 없다.

⚠ **대신 「지시 없이 완료」를 세어 보인다** — 사후보전 비율이 높으면 예방보전 계획이 부실하다는 신호다. `W-05-08`(비가동 집계, 4단계)이 받는다.

### §5-5. ⭐ 관리웹은 **C-12(단말 시계) 대상이 아니다**

12차가 C-12 를 해소하며 「오프라인 허용 전 화면」을 적용 범위로 뒀다. **관리웹은 온라인 전제**(결정 17 · C-5)라 **서버 시각을 쓴다.**

| | 시각의 출처 |
| --- | --- |
| 모바일·POP(12차) | **단말 시각**(오차는 함께 보내지 않는다 · C-12 v2.7) |
| **관리웹(이 화면)** | ⭐ **서버 시각** — 보정 문제가 없다 |

⚠ **그래서 한 고장 건 안에 두 종류의 시각이 섞인다** — 보고 시각(단말) · 처리 시각(서버). **표시할 때 출처를 구분하지 않는다**(사용자에게 의미 없다) 그러나 **집계에서 섞어 빼면 안 된다**. → §9-2

### §5-6. W/O 중단은 **보이되 만지지 않는다**

도식이 회색 주석으로 「**W/O 중단(사유=설비/도구 고장) — 생산(②) 소유**」를 못박았고, **결정 14** 가 작업 홀드를 **구간 이력(P2 패턴)** 으로 확정했다.

| 이 화면 | 생산(②) 도메인 |
| --- | --- |
| 「이 설비의 W/O 중단 N건」을 **보인다** | **중단·재개를 만든다**(`P-02-10` 작업중단 홀드 등록) |

⛔ **고장 완료가 W/O 를 자동 재개시키지 않는다** — 재개는 작업자가 현장에서 판단한다. **자동 재개는 되돌릴 수 없는 행위를 자동화하는 것**이고 **B-15**(되돌릴 수 없는 행위를 자동화할 때는 명시적 반대 의사를 타이머보다 우선한다)의 취지에 걸린다.

### §5-7. 목록은 **적체 화면**이다 — L-12

**기본값이 「오늘」이 아니라 「미처리 전건」**이고 **정렬은 경과일 긴 순**이다(L-12).

- 요약: 「**24h 경과 2건 · 3일 경과 1건**」 — 경과 구간별 건수
- ⚠ **기간 필터는 보조**다 — ⭐ **L-12 가 L-3 의 예외를 이미 만들어 뒀다**(「적체 관리 화면은 기본 조회 = **미처리 전건**」).

⛔ **L-3 의 본칙은 「기간 필터를 필수로 한다 · 기본 최근 1개월 · 비울 수 없게」이고 전 목록 화면에 걸린다.** 파티션 언급은 **본칙의 강화**(성능 → 가능/불가능)이지 적용 범위가 아니다. **이 화면이 예외인 것은 L-12 때문이지 「파티션이 아니라서」가 아니다.**

### §5-8. 액션·상태 **[2026-08-18 신설]**

> ⚠ **§5 가 「액션·상태」인데 액션 «표»가 없었다** — 소절 일곱이 전부 판정이었다. 새로 설계한 것이 아니라 **§3 레이아웃의 컨트롤과 §5-1~§5-7·§6 의 조건을 모은 것**이다.

| 액션 | 활성 조건 |
| --- | --- |
| 필터·조회 *(미처리 전건 · 설비 · 기간)* | 항상 — 기본은 **미처리 전건**이고 **경과일 긴 순**(L-12 적체) |
| 목록에서 고장 선택 | 항상 |
| 사진 보기 | 첨부가 있을 때 · ⛔ **읽기 전용** — 현장이 적은 것을 사무가 고치지 않는다(§5-2) |
| 원인 코드 선택 | 선택된 건이 **완료가 아님** · ⛔ **값 목록이 비면 비활성 + 사유**(G-2 · §6) |
| 처리 내역 입력 | 선택된 건이 **완료가 아님** · **A-12** 형식 유도 |
| **처리 중으로** | 상태 = **접수** — ⛔ **되돌리지 않는다**(§5-1) |
| **보전 지시 발행** | 상태 = 접수 또는 처리중 · ⭐ **선택이다 — 강제하지 않는다**(§5-4). 발행하면 지시가 자동 연결된다(§4-B) |
| **완료** | 상태 = 접수 또는 처리중 **AND 원인 코드 입력 AND 처리 내역 입력**(§5-1 · §6) |

**고장 건 상태**: `접수` → `처리중` → `완료` *(경미 건은 접수 → 완료로 바로 간다 · §5-1)*
**화면 상태**: `목록` → `선택됨` → `입력 중` → `저장 중` → `성공` / `실패` / **`잠김`**(이미 완료된 건 — §6)

⛔ **W/O 중단을 만지지 않는다** — 「이 설비의 W/O 중단 N건」을 **보이기만** 하고, 중단·재개는 생산 도메인(`P-02-10`)이 소유한다. **고장 완료가 W/O 를 자동 재개시키지 않는다**(§5-6 · B-15).
⛔ **비가동을 종료시키지 않는다** — 열린 비가동이 있으면 **경고하되 막지 않는다.** 종료는 POP(`P-05-02`) 몫이다(§6).
⚠ **처리 시각은 서버 시각이다** — 관리웹은 단말 시계 조항(C-12) 대상이 아니다(§5-5).

## §9. 이 장에서 나온 공유 계약 후보

### 9-1. ⭐ **현장이 적은 것을 사무가 고치지 않는다 — 정정은 덧붙인다**

**규칙안**: 현장 단말(POP·모바일)이 만든 **관찰 기록**은 사무 화면에서 **읽기 전용**으로 두고, 정정은 **별도 필드에 덧붙인다**.

| 무엇 | 왜 |
| --- | --- |
| 증상·측정값·사진·발생 시각 | **그 시점에 그 사람이 본 것**이다. 덮으면 누가 무엇을 봤는지 사라진다 |
| 사무가 아는 것 | **처리 내역·원인 코드**에 적는다 |

⚠ **B-3(이력 불변)은 「이력 테이블」에 대한 조항**이고, 이것은 **트랜잭션 본문 중 관찰 부분**에 대한 것이다. **G-10 으로 그리고 사유를 보인다.**

**해당 후보**: 고장 보고(이 화면) · 점검 결과(`M-05-01` → 사무 조회) · 검사 측정값 · 실사 계수.

### 9-2. **한 건에 단말 시각과 서버 시각이 섞이면 집계에서 빼지 않는다**

12차가 C-12 를 해소하며 **단말 시각에 `clock_offset_ms` 를 붙였다.** 관리웹은 **서버 시각**이라 오차가 없다.

```
고장 보고 시각   단말(오차 있음)
고장 처리 시각   서버(오차 없음)
   → 「처리 소요 시간 = 처리 − 보고」  ⚠ 오차가 그대로 들어간다
```

**규칙안**

1. **두 시각의 출처가 다르면 차를 지표로 쓸 때 오차를 명시**한다
2. **오차가 임계를 넘은 건은 집계에서 표시**한다(제외하지 않는다 — L-10 「섞지도 지우지도 않는다」)
3. **화면 표시에서는 출처를 구분하지 않는다** — 사용자에게 의미가 없다

### 9-3. **겉모습이 같아도 「입력이 있는가」로 컴포넌트가 갈린다**

§7-1 이 그 사례다 — G-11(측면 패널)의 5곳은 **조회**이고 이 화면은 **처리 입력**이다.

**규칙안**: 「목록 + 상세」 패턴에서 상세 구획에 **입력·상태 전이가 있으면 측면 패널을 쓰지 않는다.**

| 근거 |
| --- |
| **닫으면 입력을 잃는다** — 패널은 바깥 클릭으로 닫히는 관례가 있다 |
| **폭이 필요하다** — 입력 컨트롤·검증 문구·버튼 |
| **초점 관리가 다르다** — 조회 패널은 목록으로 돌아가고, 입력은 저장까지 잡아 둔다 |
