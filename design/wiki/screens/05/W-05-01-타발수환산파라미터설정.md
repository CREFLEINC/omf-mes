> 작성일: 2026-08-11 · 서식: `00-서식.md` v1.0 · 작성 주체: CREFLE OMF 팀 (UI/UX)
> **도메인 05 의 마지막 화면**이다.

## §0. 요약

- **개요**: 관리웹에서 설비담당·생산관리가 생산 수량 기반 타발수 환산의 사용 여부와, 품목·공정·공장별 「수량 대비 타발수 비율」 정책을 설정하는 화면. 작업실적 입력 시 손 입력(수동 기입)은 항상 유지되고, 환산은 선택형 보조 경로다.
- **주요 데이터**: 환산 정책 `app.operation_policy`(정책 코드 `SHOT_CONVERSION_ENABLED`·`SHOT_CONVERSION_RATIO` · 사업부/공장/품목/공정 4축 · 유효기간)와, 미리보기에서 참조만 하는 툴 마스터의 캐비티 수(`mdm.mold.cavity_count`).
- **핵심 액션**: 환산 사용 켜기·끄기, 비율 정책 추가·수정·종료(물리 삭제 금지 — 과거 실적은 그 비율로 계산됨), 툴·품목·공정 조합 미리보기, 저장·취소.

## §3. ⭐ 저장처 — **`app.operation_policy` 를 쓴다**

`app.operation_policy` 는 **`W-05-12` §8-7 이 실재를 확인**했고 **완료보고가 먼저 짚은** 범용 정책 테이블이다.

```
policy_code            app.code_t NOT NULL
business_unit_id / plant_id / item_id / process_id   ← 범위 4축 (nullable)
value_text / value_numeric / value_boolean           ← 값 3형 (≥1 필수)
effective_from / effective_to                        ← 유효기간
UNIQUE (policy_code, COALESCE(4축), effective_from)  ← A-7 부분 유일
```

### §3-1. 왜 맞는가 — **B-19 대로 단계별로 확인했다**

| 필요한 것 | `operation_policy` | 판정 |
| --- | :-: | :-: |
| **사용 여부**(선택형) | `value_boolean` | ✅ |
| **비율**(수량 대비 타발수) | `value_numeric` — `numeric(20,6)` | ✅ |
| **품목별로 다르다** | `item_id` 축 | ✅ |
| **공정별로 다르다** | `process_id` 축 | ✅ |
| 유효기간 | `effective_from`·`effective_to` | ✅ |
| ⚠ **툴별로 다른가** | ⛔ **툴 축이 없다** | §3-2 |

⭐ **B-19 가 「있다고 단정하는 것」을 막았고, 이번에는 단계별로 확인한 결과 **거의 다 맞았다**.** `W-05-06`(출고 경로)과 반대 결과다 — **확인하면 되는 경우도 있다.**

### §3-2. 툴 축이 없다 — **필요 없다**

「금형마다 비율이 다른가」가 물음이다. **아니다.**

```
타발수 = 생산 수량 × 비율
비율   = 1 / (한 번 타발에 나오는 개수)  ←  그것이 캐비티 수다
```

⭐ **캐비티 수는 이미 툴 마스터에 있다**(`mdm.mold.cavity_count` — §4-A). **툴별 차이는 캐비티 수가 이미 담는다.**

| 무엇 | 어디 |
| --- | --- |
| **툴별로 다른 것** | `cavity_count` — **툴 마스터**(`W-05-13`) |
| **품목·공정별로 다른 것** | 비율·사용 여부 — **정책**(이 화면) |

⛔ **정책에 툴 축을 더하지 않는다** — 더하면 **캐비티 수와 두 곳에서 같은 것을 정하게** 된다.

⭐ **`W-05-13` §8-8 이 「두 화면이 한 계산의 입력을 나눠 갖는다」로 남긴 것의 답이다** — **나눠 갖는 것이 맞고, 나누는 선이 「툴 고유 ↔ 품목·공정 정책」**이다.

## §5. 필드·규칙

### §5-A. 환산 정책 — `app.operation_policy`

| 라벨(한 / 베) | 출처 컬럼 | 타입 | 필수 | 검증·비고 |
| --- | --- | --- | :-: | --- |
| 정책 코드 | `policy_code` | `code_t` | ✅ | ⭐ **고정 2종** — `SHOT_CONVERSION_ENABLED` · `SHOT_CONVERSION_RATIO` §5-1 |
| 사업부 / 공장 / 품목 / 공정 | 4축 | FK (nullable) | — | **비면 전체** · 유일키 구성(**A-7**) |
| 사용 여부 | `value_boolean` | boolean | 조건부 | 정책 코드 = ENABLED |
| 비율 | `value_numeric` | `numeric(20,6)` | 조건부 | 정책 코드 = RATIO · **`> 0`** §5-3 |
| 유효 시작·종료 | `effective_from` · `effective_to` | date | ✅ / — | `ck_operation_policy_dates`(종료 ≥ 시작) · **A-2 짝 제약** |

**⛔ `value_text` 는 쓰지 않는다** — `ck_operation_policy_value` 가 「셋 중 하나 이상」이라 셋 다 넣어도 통과하지만, **쓰지 않는 칸을 채우면 읽는 쪽이 헷갈린다.**

### §5-1. 정책 코드는 **고정 2종** — 사용자가 만들지 않는다

`operation_policy` 는 범용이라 `policy_code` 를 자유롭게 넣을 수 있다. **이 화면은 둘만 쓴다.**

| 코드 | 값 |
| --- | --- |
| `SHOT_CONVERSION_ENABLED` | `value_boolean` |
| `SHOT_CONVERSION_RATIO` | `value_numeric` |

⛔ **화면에 「정책 코드」 입력란을 두지 않는다** — 사용자는 **「환산 사용」 체크와 「비율」**만 본다. **코드는 화면이 붙인다.**

⭐ **G-17**(분류 값을 사람이 고르게 하면 지표가 의미를 잃는다)의 취지와 같다 — **기계가 정할 수 있는 것을 사람에게 묻지 않는다.**

⚠ **다른 화면도 같은 테이블을 쓴다** — 「작업 통제 3단계」를, `W-05-08` 이 「경미 정지 임계」를 여기 두기로 했다. **정책 코드 목록이 계약 자산이 된다.** → §8-2

### §5-2. ⭐ 범위 해석 — **더 좁은 것이 이긴다** · B-17

`operation_policy` 는 4축이 전부 nullable 이라 **겹칠 수 있다**(공장 기본 + 품목 예외).

**B-17**(계층 해석 규칙은 도메인 안에서 하나만 쓴다 — **가장 가까운 것이 이긴다**)를 그대로 쓴다.

```
품목 지정  >  공정 지정  >  공장 지정  >  사업부 지정  >  전체
                                    ← 지정된 축이 많을수록 좁다
```

⚠ **품목과 공정이 각각 지정된 두 행이 동시에 맞을 수 있다** — 우선순위가 필요하다.

**확정 — 축 우선순위를 `품목 > 공정 > 공장 > 사업부` 로 못박는다.**

| 왜 이 순서인가 | |
| --- | --- |
| **품목이 가장 구체적**이다 | 「이 제품은 한 번에 4개 나온다」 |
| 공정은 그다음 | 「프레스 공정은 대체로 1:1」 |
| 공장·사업부는 기본값 | |

⭐ **`W-05-09`(작업 캘린더) §5-3 의 「해석 미리보기」와 같은 것이 필요**하다 — ③이 그것이다.

### §5-3. 비율은 **`> 0`** 이어야 한다 — DB 가 안 막는다

`value_numeric` 은 `numeric(20,6)` 이고 **CHECK 가 없다**(실측). 0 이나 음수가 들어갈 수 있다.

| 값 | 결과 |
| --- | --- |
| `0` | ⛔ **타발수가 항상 0** — 누계가 안 늘어 **PM 이 영영 안 온다** |
| 음수 | ⛔ 누계가 줄어든다 |

⭐ **A-9**(DB 가 막지 않는 검증은 등급을 나눠 화면이 진다) **등급 2** — 화면·서버 둘 다 막는다.

⚠ **상한도 둔다** — 캐비티 수를 생각하면 비율은 대개 `0 < r ≤ 1` 이다. **1 을 넘으면 경고**한다(막지는 않는다 — 한 번에 여러 번 타발하는 공정이 있을 수 있다).

### §5-4. ⛔ 환산을 켜도 **손 입력이 사라지지 않는다**

QA #12 가 「타발수 = 작업실적 입력 시 **수동 기입 확정**」이고 환산은 「**사용 여부 선택형**」이다. 도식도 **B9 를 회색(대안)**으로 그렸다.

| | |
| --- | --- |
| **손 입력** | ✅ **언제나 된다** — 기본 경로 |
| **환산** | ⚠ **보조 경로** — 켜면 POP 에 「생산 수량으로 환산」 선택지가 생긴다 |

⚠ **①에 그 사실을 적는다** — 「켜도 손 입력은 그대로 됩니다」. 없으면 **환산을 켜면 손 입력이 막히는 줄 안다.**

⭐ **`P-05-01` §5-4 가 「환산 옵션 비활성 + 사유」로 이미 그렸다** — 이 화면이 그 스위치다.

### §5-5. 액션·상태

| 액션 | 활성 조건 |
| --- | --- |
| 환산 사용 켜기·끄기 | 편집 권한 |
| 정책 추가·수정 | 동상 |
| 정책 종료(유효 종료일 지정) | ⛔ **삭제하지 않는다** — 과거 실적이 그 비율로 계산됐다 |
| 미리보기 | 툴·품목·공정 선택 |

**상태**: `초기` → `편집` → `저장 중` → `성공` / `실패` / `충돌(B-1)`

⚠ **정책을 바꿔도 과거 실적은 안 바뀐다** — `P-05-01` §4-A 가 **환산 기준 수량·비율을 실적에 함께 저장**하기로 했다. ⭐ **A-18**(판정 근거가 움직이면 판정 시점 값을 스냅샷)이 이미 적용돼 있다.

## §6. 예외

| 상황 | 처리 |
| --- | --- |
| 비율 ≤ 0 | 저장 거부 + 인라인(**A-9 등급 2**) — 「비율은 0보다 커야 합니다」 |
| 비율 > 1 | ⚠ **경고 + 저장 허용** |

| 저장 충돌 | 배너 + 다시 불러오기(B-1) |
| 오프라인 | **해당 없음** — 관리웹 온라인 전제 |

## §9. 이 장에서 나온 공유 계약 후보

### 9-1. ⭐⭐ **범용 정책 테이블은 「코드 목록」이 계약이다**

`app.operation_policy` 하나를 **세 화면이 쓴다**(환산 · 작업 통제 3단계 · 경미 정지 임계). **테이블은 하나인데 뜻은 코드가 정한다.**

**규칙안**

1. **정책 코드 목록을 계약이 갖는다** — 코드 · 무엇을 정하는가 · **값 형**(boolean/numeric/text) · **범위 축 중 무엇을 쓰는가**
2. ⛔ **화면이 코드를 자유 입력하게 두지 않는다** — 화면이 붙인다(§5-1)
3. **범위 해석 우선순위를 하나로** 한다 — **B-17**. 화면마다 다르면 같은 테이블이 다르게 읽힌다
4. **값 형을 못박는다** — `ck_operation_policy_value` 가 「셋 중 하나 이상」이라 **셋 다 채워도 통과**한다. **어느 칸을 쓰는지 계약이 정한다**

⚠ **A-10**(다형 참조는 대응표를 계약이 정한다)과 **같은 형태의 문제**다 — **FK 가 없는 자리를 문자열이 채우면 계약이 대응표를 가져야** 한다.

### 9-2. **B-19 는 「쓸 수 없다」만 찾는 규칙이 아니다**

B-19 를 세울 때는 **DR-001 의 근거가 틀린 사례**였다. **이 장은 반대 결과다** — 단계별로 확인했더니 **6항목 중 5개가 맞았고 나머지 하나는 필요 없었다.**

**규칙안 — B-19 에 붙인다**: 단계별 확인의 결과는 셋이다.

| 결과 | 처리 |
| --- | --- |
| **전부 맞다** | 그대로 쓴다 — **테이블 신설 0건** |
| **일부만 맞다** | 맞는 부분만 쓰고 **나머지를 신설**한다(`W-05-06`) |
| **안 맞는 것이 필요 없다** | ⭐ **왜 필요 없는지를 적는다** — 이 장의 「툴 축」 |

⚠ **셋째를 안 적으면 나중에 「빠뜨렸다」로 읽힌다.**
