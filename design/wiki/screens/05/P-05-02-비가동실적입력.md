# P-05-02 · 비가동 실적 입력

## §0. 요약

- **개요**: POP(Electron 키오스크 · 1024×768 터치)에서 현장 오퍼레이터·반장이 설비별 비가동을 시작~종료 **구간**으로 기록하는 화면. 진행 중 비가동이 있으면 상단에 보이고 「지금 종료」로 닫으며, 없으면 새 구간(시작·종료 시각·사유·연결 고장)을 입력해 저장한다.
- **주요 데이터**: 신설 비가동 실적(설비 FK · 시작/종료 시각 · 비가동 사유 대/소분류 FK · 연결 고장 FK — `M-05-02` 고장 기록과 N:M · 메모 · 입력자 · 기록 시각). 길이(종료−시작)는 저장하지 않고 서버가 파생 계산한다.
- **핵심 액션**: 시작·종료 `[지금]`(단말 시각을 그대로 기록, 보정 없음) · 「아직 진행 중」 체크 · 사유 선택(대·소분류) · 고장 연결/해제 · 실적 저장(오프라인 로컬 버퍼링 + 복구 시 자동 동기화).

> 작성일: 2026-08-11 · 서식: `00-화면스펙서식.md` v1.0 · 작성 주체: CREFLE OMF 팀 (UI/UX)
> DR-001 §7 2단계의 마지막.
> ⭐ **유일하게 「시각 자체가 데이터」인 화면**이다 — 비가동은 **구간**이다. 이 화면이 C-12(단말 시계)에 규약안을 냈고 그것이 v1.8 로 채택됐다.
> ⛔⛔ **그 규약안의 근거가 2026-08-18 에 뒤집혔다** — 「시각 오차가 곧 설비종합효율 오차」라고 적었는데, **시작과 종료를 이 화면에서 «같은 단말»이 찍으므로 «차»는 정확하다.** 오차 보정은 범위 밖이 됐다(**C-12** v2.7). **남은 것은 「단말 시각을 그대로 쓰고 서버가 덮지 않는다」 하나다.**

| --- | --- | --- |
| 재고 실사(`M-01-11`) | **언제 셌나** | 몇 분 틀려도 재고 수량은 맞다 |
| 점검(`M-05-01`) | **주기 내인가** | 몇 분 틀려도 「오늘 했나」는 맞다 |
| **비가동(이 화면)** | **구간의 길이 자체** | ⭐ **같은 단말이 시작·끝을 찍으므로 «차»는 정확하다**(2026-08-18 실측) |

⭐ **차이는 「시각을 기록하는가」와 「시각의 차를 쓰는가」다.**

**확정 — 하나만 한다** *(2026-08-18 · C-12 v2.7 로 축소)*

1. **`[지금]` 버튼을 기본 경로로 둔다** — 손으로 시각을 적는 것보다 단말 시각이 정확하다

#### ⛔⛔ 뺀 것 둘 — **v1.8 에서 이 화면이 제안했던 것이다**

| 뺀 것 | 왜 |
| --- | --- |
| 단말 시각 오차를 화면이 보인다(1분 이상 경고) | **작업자가 할 수 있는 것이 없다** — 시계를 고칠 권한도 방법도 없다 |

⚠ **다시 볼 조건** — 설비 자동 수집(`W-05-07`)으로 비가동이 들어오면 **설비 시각 ↔ 단말 시각**이 갈린다. 그때가 「한 구간을 두 시계가 나눠 찍는」 첫 사례다 → **C-12** v2.7

### §5-3. 「진행 중」은 **상태가 아니라 종료 시각의 부재**다

**A-14 적용.** 「진행 중 / 종료됨」을 상태 컬럼으로 두고 싶어지지만, **종료 시각이 비었는지로 이미 답이 난다.**

```
종료 시각 IS NULL   →  진행 중
종료 시각 있음      →  종료됨
```

**상태 컬럼을 두면** ① 두 값이 어긋날 수 있고(상태=종료인데 종료 시각 없음) ② **A-15 의 판별 질문에 걸린다** — 「아무도 아무것도 하지 않아도 바뀌는가?」에 **진행 중은 시간이 지나도 진행 중**이라 「아니다」이지만, **「진행 시간」은 계속 바뀐다.** ①에 보이는 `0시간 47분`은 **화면이 매 순간 다시 그리는 값**이지 저장값이 아니다.

⚠ **끝나지 않은 비가동이 쌓이면 OEE 가 틀린다** — 퇴근하며 종료를 안 찍으면 밤새 비가동이다. **`W-05-08`(비가동 집계·조회, 4단계)이 「열린 구간」을 보여야 한다.** → §8-5

### §5-4. 고장 연결은 **선택**이다 — N:M 의 한쪽 — 이 화면이 만드는 것은 「비가동 → 고장」 방향의 0..1 참조다

`M-05-02` §3-2 가 **고장 ↔ 비가동 N:M** 을 확정했다. **이 화면이 그 연결을 만드는 자리**다.

| | |
| --- | --- |
| **선택인 이유** | 비가동의 다수는 고장이 아니다 — 자재 대기·금형 교체·계획 정지 |
| **목록에 나오는 것** | 이 설비의 **열린 고장**(처리 상태 = 접수·처리중) |
| **여러 건 연결** | ⛔ **한 건만** — 비가동 하나가 가리키는 고장은 0 또는 1 이다(`M-05-02` §3-2). N:M 은 **고장 쪽에서** 성립한다 — 고장 하나가 비가동 여럿을 부른다(수리하다 다시 서고, 부품 대기로 또 선다) |

⚠ **`M-05-02` §8-6 이 남긴 것에 답한다** — 「정지 시각을 안 적으면 비가동이 언제부터인가」. **고장을 연결하면 그 고장의 정지 시각을 시작 시각 기본값으로 제안**한다(비어 있으면 제안 없음). **자동으로 넣지 않고 제안만** 한다 — 작업자가 확인해야 한다.

MES-9 가 「비가동 = **계획 / 실적 2원**」으로 적었다.

## §9. 이 장에서 나온 공유 계약 후보

### 9-1. ⭐⭐ **C-12 규약안 — 채택됐다가 근거가 뒤집혔다** *(v1.8 채택 → v2.7 축소)*

이 화면이 규약안 넷을 냈고 **v1.8 에 그대로 채택**됐다. **그런데 2026-08-18 에 그 근거가 무너졌다.**

| 규약안 | 지금 |
| --- | :-: |
| 1. 화면은 시각을 보정하지 않는다 | ✅ **살아 있다** — C-12 의 본체가 됐다 |
| 2. 오차를 재어 화면이 보인다(1분 이상) | ⛔ **뺐다** |
| 3. 저장 시 오차를 함께 보낸다(`clock_offset_ms`) | ⛔ **뺐다** |
| 4. 오프라인은 마지막으로 잰 오차를 쓴다 | ⛔ **뺐다** |

#### ⛔⛔ 내가 세운 전제가 틀렸다 — **「비가동은 시각의 차가 곧 데이터」**

맞는 말이지만 **결론이 틀렸다.** 시각의 차가 데이터인 것과 **시계 오차가 그 차를 틀리게 하는 것**은 다르다.

```
   시작  [ 지금 ]   ← 이 화면 · 이 단말의 시계
   종료  [ 지금 ]   ← «같은» 화면 · «같은» 단말의 시계
   차    = 정확하다.  시계가 5분 빨라도 47분은 47분이다
```

⭐ **시계 오차가 «차»를 틀리게 하려면 시작과 끝을 «다른 시계»가 찍어야 한다.** 이 화면에는 그런 자리가 없다.

⚠ **그리고 보정을 넣으면 오히려 위험이 는다** — 보정값을 잃으면 시각이 튀어 종료가 시작보다 앞서고, 물리 모델 CHECK 에 걸려 **저장이 통째로 실패**한다.

**다시 볼 조건** — 설비 자동 수집(`W-05-07`)으로 비가동이 들어오면 **설비 시각 ↔ 단말 시각**이 갈린다. 그때가 「한 구간을 두 시계가 나눠 찍는」 첫 사례다 → **C-12** v2.7

### 9-2. **「진행 중」을 상태 컬럼으로 두지 않는다 — 끝 시각의 부재로 표현한다**

A-14 의 **구간 판**이다.

**규칙안**: 시작·종료를 갖는 구간 데이터에서

1. **「진행 중」을 별도 상태 컬럼으로 두지 않는다** — `종료 IS NULL` 이 그 뜻이다
2. **경과 시간은 저장하지 않는다** — 화면이 매 순간 다시 그린다(A-15)
3. ⛔ **자동 종료를 두지 않는다** — 임의 종료 시각은 집계를 **조용히** 틀리게 만든다
4. **열린 구간을 집계 화면이 보인다** — 「종료 안 된 N건」

**해당 후보**: 비가동(이 화면) · 작업 세션(`work_session`) · 작업 홀드(결정 14) · 고장 처리 중(`M-05-02`).

⚠ **1번은 「상태를 늘리지 말라」가 아니라 「이미 있는 것을 다시 적지 말라」**다 — A-14 와 결이 다르다.

### 9-3. **오프라인 집계는 「내가 아는 만큼」으로 줄이고 그 범위를 말한다**

`P-05-01` §9-3 과 **같은 규칙의 두 번째 사례**다. 두 화면에서 같은 형태가 나왔으므로 **일반 규칙으로 올린다.**

| 화면 | 오프라인에서 줄인 것 |
| --- | --- |
| `P-05-01` | 저장 후 누계 · 사용 가능 타수 · `Progress` |
| **`P-05-02`**(이 화면) | 오늘 비가동 합계 → **「내 단말 입력분만」** |

**규칙안**: 오프라인에서 **여러 주체가 기여하는 집계**를 보일 때

1. **범위를 이름으로 말한다** — 「내 단말 입력분만」·「08-11 09:40 기준」
2. **파생 지표를 그리지 않는다** — 비율·잔량·`Progress`
3. **그 자리를 비우지 않는다** — 「연결 후 확인」으로 채운다(G-9 — 모르는 값과 없는 값을 다르게)
