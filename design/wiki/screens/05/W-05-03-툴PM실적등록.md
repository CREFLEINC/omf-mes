# W-05-03 · 툴 PM 실적 등록

## §0. 요약

- **개요**: 관리웹에서 설비담당이 미완료 툴 보전오더를 선택해 PM(예방보전) 시행 결과를 등록하는 실적 등록 화면. 보전부위별 점검결과를 기록하고, 오버홀 등으로 누계타발수를 리셋할지 정한다.
- **주요 데이터**: 툴 PM 실적(**신설** — 보전오더 FK·시행일·시행자·결과 내용·리셋 여부/리셋 직전 누계/리셋 후 시작값)과 보전부위 결과 라인(**신설** — 부위 자유 입력·결과 값목록·비고). 리셋 시 「마지막 PM 일자」·누계는 툴 마스터가 갱신하고 자기참조 FK는 두지 않는다.
- **핵심 액션**: 미완료 오더 선택 → 시행일·시행자·보전부위별 결과 입력 → (오버홀이면) 누계 리셋 체크 + 리셋 직전 누계 스냅샷 → 오더 완료 마감 여부 선택 → 실적 저장(낙관적 잠금 적용).

## §3. ⭐⭐ 두 번 이월된 「누계 리셋」을 정한다

| 언제 | 무엇을 남겼나 |
| --- | --- |
| **11차** `W-05-13` §8-3 | 「누계타발수 리셋의 시점·권한 — ⛔ **이 화면이 아니다** · `W-05-03` 설계 시(3단계)」 |
| **12차** `P-05-01` §8-2 | 「⭐ **증분 가산 구조(B-18)에서 리셋을 음수 증분으로 처리하면 이력이 「−412,300 회 사용」으로 남는다.** 별도 행위여야 한다」 |

### §3-1. 확정 — **리셋은 「사건」이고 증분이 아니다**

```
타발수 입력(P-05-01)   증분  +1,250        누적된다
PM 리셋(이 화면)        사건  누계 → 0      기록으로 남는다
```

| 안 | 방식 | 판정 |
| :-: | --- | :-: |
| 가 | 음수 증분 `−412,300` | ⛔ **12차가 이미 기각** — 이력이 「412,300 회 사용」으로 읽힌다 |
| 나 | `current_shot_count = 0` 직접 치환 | ⚠ **B-18 과 부딪치는 것처럼 보인다** — 그러나 §3-2 |
| **다** | **PM 실적이 「리셋 지점」을 기록**하고 누계는 **그 뒤부터 다시 센다** | ✅ **확정** |

### §3-2. 「다」안이 B-18 과 부딪치지 않는 이유

B-18(누적 컬럼은 증분으로 보낸다)은 **여러 단말이 동시에 기여하는 경우**를 다룬다.

| | 타발수 입력 | **PM 리셋** |
| --- | --- | --- |
| 누가 | **여러 POP 이 동시에** | **한 사람이 한 번** |
| 언제 | 작업마다 | **오더당 한 번** |
| 경합 | ⛔ 있다 → 증분 필수 | ✅ **없다** |

⭐ **B-18 규칙 3(「낙관적 잠금을 걸지 않는다」)의 반대**다 — **리셋에는 낙관적 잠금(B-1)을 건다.** 경합이 없으므로 잠금이 서로를 거부하지 않고, **누계를 치환하는 행위라 충돌 감지가 필요**하다.

⚠ **B-18 에 단서를 붙인다** → §8-1

### §3-3. 리셋을 **기록으로 남긴다**

```
PM 실적
  ├ 리셋 여부              ☑
  ├ 리셋 직전 누계타발수    412,300     ← 스냅샷 (W-05-02 §5-2 와 같은 이유)
  └ 리셋 후 시작값          0           ← 보통 0, 오버홀이면 다를 수 있다
```

⭐ **`W-05-02` §5-2 의 「발행 근거를 얼린다」와 같은 형태**다 — **누계가 0 이 되면 「이번 PM 까지 얼마나 썼는지」를 알 수 없다.** 그것이 **수명 분석의 유일한 재료**다.

⚠ **리셋을 안 하는 PM 도 있다** — WF05 S8 Exception ② 가 「금형 교체/오버홀 후 누계 리셋」이라 했다. **부분 정비는 리셋하지 않는다.** 그래서 **체크박스**이고 기본 꺼짐이다.

### §3-4. 권한 — **오더가 대신 답한다**

「리셋 **권한**」이 11차 이월 항목이었다. **별도 권한 축을 두지 않는다.**

| 근거 | |
| --- | --- |
| **리셋은 PM 실적 등록의 일부**다 | 오더 없이 단독으로 리셋하는 경로를 만들지 않는다 |
| **오더가 이미 통제한다** | 오더는 설비담당이 발행하고(`W-05-02`) 실적은 그 오더에 붙는다 |
| ⚠ **단독 리셋이 필요하면** | 그때 권한을 만든다 — 지금 근거가 없다 |

⭐ **11차가 「시점·권한」을 물었고, 답은 「시점 = PM 실적 등록 시 · 권한 = 별도로 두지 않는다」**이다.

### §5-1. ⭐ 「마지막PM수량 → 다음PM수량」 산출 — **자기참조를 두지 않는다**

MES-5 가 「**마지막PM수량→다음PM수량 산출** / 차기 PM 기준 갱신(**자기참조**)」이라 적었고, 마커 **M7**(오더실적구조)이 「자기참조 산출 로직 = 신규 설계 미결」로 남겼다.

**확정 — 자기참조 FK 를 두지 않는다.**

| 안 | 방식 | 판정 |
| :-: | --- | :-: |
| 가 | PM 실적이 **직전 PM 실적을 FK 로** 가리킨다 | ⛔ **체인이 끊기면 복구 불가** — 중간 한 건이 취소되면 뒤가 다 어긋난다 |
| **나** | **툴 마스터의 「마지막 PM 일자」·누계를 갱신**하고 실적은 **각자 독립** | ✅ **확정** |

```
다음 PM 도래 = f(툴 마스터의 마지막 PM 일자 · 주기 · 현재 누계 · 적정타수)
             ← W-05-02 §3-1 의 판정식 그대로. 실적 체인을 타지 않는다
```

⭐ **`W-05-02` §3-2 가 이미 답을 준비했다** — 「마지막 PM 일자」를 **툴 마스터에 저장**하기로 했고, **다음 PM 예정일은 파생**(저장 안 함)이다. **자기참조가 필요 없다.**

⚠ **「마지막PM수량」도 마찬가지다** — 리셋하면 누계가 0 이므로 **다음 도래는 적정타수 그대로**다. 별도 컬럼이 필요 없다.

### §5-2. 오더 없는 PM 실적을 두지 않는다 — **설비와 다르다**

`W-05-06` §5-2 는 「지시 없는 보전 실적을 허용」했다. **여기는 반대다.**

| | 설비 보전 | **툴 PM** |
| --- | --- | --- |
| 지시 없는 실적 | ✅ **허용** — 긴급 고장은 선조치 후기록 | ⛔ **불허** |
| 왜 | 고장은 **예고 없이 온다** | PM 은 **예방**이다 — 도래를 보고 계획해서 한다 |

⚠ **긴급 금형 수리(계획 외)는?** WF05 S8 Exception ④ 가 「긴급 금형 수리(계획 외) → **오더 사후 생성**」이라 이미 답했다. **오더를 먼저 만들고 실적을 붙인다** — `W-05-02` 가 예정일 과거를 경고만 하고 막지 않는 이유다.

### §5-3. 액션·상태

| 액션 | 활성 조건 |
| --- | --- |
| 오더 선택 | 미완료 오더 |
| 부위 추가·삭제 | 저장 전 |

### §8-2. 이 장에서 나온 공유 계약 후보

#### ⭐⭐ **한 누적 컬럼에 「증분」과 「치환」이 함께 붙으면 잠금 정책이 갈린다** — B-18 단서

12차 B-18 이 「누적 컬럼은 증분으로 보낸다 · **낙관적 잠금을 걸지 않는다**」로 확정됐다. **리셋은 치환이고 잠금이 필요하다.**

| 행위 | 방식 | 낙관적 잠금 | 왜 |
| --- | --- | :-: | --- |
| 타발수 입력(`P-05-01`) | **증분** `+1,250` | ⛔ **안 건다** | 여러 POP 이 동시에 기여 — 걸면 서로를 거부한다 |
| **PM 리셋**(이 화면) | **치환** `→ 0` | ✅ **건다** | 한 사람이 한 번 · **덮어쓰는 행위라 충돌 감지가 필요** |

**규칙안 — B-18 에 붙인다**

1. **증분 행위와 치환 행위를 구분해 정의**한다 — 같은 컬럼이라도 다른 API 다
2. **증분은 잠금 없이 · 치환은 잠금과 함께** 보낸다
3. **치환은 반드시 직전 값을 스냅샷으로 남긴다** — 치환하면 이전 값이 사라진다
4. ⛔ **치환을 음수 증분으로 흉내 내지 않는다** — 이력이 「사용」으로 읽힌다(12차 판정)

#### **자기참조 체인 대신 마스터의 현재 값을 갱신한다**

§5-1 이 그 사례다. MES-5 가 「자기참조」를 적었으나 **체인이 끊기면 복구할 수 없다.**

**규칙안**: 「직전 것을 참조해 다음을 산출」하는 구조는 **자기참조 FK 대신 마스터에 현재 값을 두고 갱신**한다.

| | 자기참조 체인 | **마스터 현재 값** |
| --- | --- | --- |
| 중간 한 건 취소 | ⛔ 뒤가 전부 어긋난다 | ✅ 영향 없다 |
| 「지금 상태」 조회 | 체인을 끝까지 타야 한다 | ✅ 한 행 |
| 이력 | 체인이 곧 이력 | 실적이 각자 남는다 |

⚠ **`trace.lot_relation`(계보)처럼 체인 자체가 목적인 것은 예외**다 — **산출의 편의로 체인을 만들지 말라**는 규칙이다.
