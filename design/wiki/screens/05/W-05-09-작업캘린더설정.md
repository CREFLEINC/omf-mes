# W-05-09 · 작업 캘린더(WorkCalendar) 설정

## §0. 요약

- **개요**: 관리웹 설비/툴관리 설정 화면. 생산관리·설비담당이 결정 03(공장 기본 캘린더 필수 + 설비그룹 단위 override 선택 + 설비 개별 캘린더 1차 제외, 해석 = 설비→설비그룹→공장)을 화면으로 옮겨 캘린더별 날짜 상태를 지정하고 공장·설비그룹에 캘린더를 적용한다.
- **주요 데이터**: 캘린더(코드·명·사용, 신설) · 캘린더 일자(키=캘린더+일자, 구분·시각·사유·메모, 신설) · 캘린더 적용(캘린더 FK + 적용 대상 유형(공장/설비그룹) + 대상 ID 다형 참조, 신설).
- **핵심 액션**: 날짜 선택 후 이 날 적용 · 요일 일괄/기간 일괄 적용(미리보기 후 확인) · 공장 기본 캘린더 지정(A-6 한 트랜잭션 전환) · 설비그룹 override 지정·해제 · 설비 선택 시 해석 미리보기(설비→그룹→공장) 확인.

### §5-1. 다형 참조 — **A-16 네 번째**

```
적용 대상 유형   PLANT | EQUIPMENT_GROUP
대상 ID          mdm.plant | mdm.production_line
```

⭐ **11차가 「설비그룹의 저장처 = `mdm.production_line`」**으로 정했으므로(A-13 ④) 대상 테이블이 확정돼 있다.

**A-16 적용** — `document_issue_log`(11차) · `attachment`(12차) · 보전 지시 트리거(13차)에 이어 **네 번째**. **계약 대응표에 먼저 등재**한다.

⚠ **유형이 둘뿐이라 다형을 안 쓸 수도 있다**(`plant_id` nullable + `production_line_id` nullable + CHECK). **다형으로 두는 이유** — 결정 03 이 「**설비그룹 유형에 '라인' 추가로 흡수**」를 열어 뒀고, 나중에 **사업부·공정 축**이 붙을 수 있다. **A-10 이 이미 16쌍을 다루므로 형태가 일관**한다.

### §5-2. ⭐ 「공장 기본 1건 필수」를 어떻게 강제하나 — **A-6**

결정 03 이 「공장 기본 캘린더 **필수**」라 했다. **하나만 참인 부분 유일 인덱스**가 그 형태다.

공유계약 **A-6**(「하나만 참」 부분 유일 인덱스는 전환도 서버가 한다)이 정확히 이것이다.

```
UNIQUE (대상 ID) WHERE 적용 대상 유형 = 'PLANT'      ← 공장당 하나
```

| 규칙 | 화면 |
| --- | --- |
| **전환은 서버가 한 트랜잭션으로**(A-6) | 공장 기본을 바꾸면 **옛것 해제 + 새것 지정**을 함께 보낸다 |
| **A-7** 부분 유일 인덱스의 오류 문구 | 「호치민공장의 기본 캘린더는 하나만 지정할 수 있습니다」 |

⚠ **「필수」는 유일 인덱스로 강제되지 않는다** — **없을 수도 있다**. **G-12**(통제 근거 마스터의 「비어 있음」)로 보인다 — 「기본 캘린더 미지정 공장 1곳」.

⛔ **기본 캘린더 없이 저장을 막지 않는다** — 공장을 새로 만들면 잠시 없는 것이 정상이다. **G-15**(비어 있으면 판정이 안 서는 필드는 저장을 막지 않는다).

### §5-3. ⭐ 해석 미리보기 — **B-17 이 눈에 보이는 자리**

B-17 이 「계층 해석 규칙은 도메인 안에서 하나만 쓴다 — **가장 가까운 것이 이긴다**」이다. **규칙은 짧은데 결과는 안 보인다.**

```
설비 PRS-01 을 고르면
  → 소속 그룹 프레스라인A          (11차 W-05-12 가 만든 소속)
  → 그룹에 override 가 있나?  없다
  → 공장 기본 CAL-HCM-2026 을 따른다
```

| 왜 필요한가 | |
| --- | --- |
| **override 가 늘면 아무도 못 따라간다** | 그룹이 20개면 어느 설비가 무엇을 따르는지 표로는 안 보인다 |
| **설정 화면이 결과를 안 보이면 틀린 줄 모른다** | **G-11**(설정 전환은 「무엇이 바뀌는지」 범위를 화면이 밝힌다)과 같은 취지 |

⭐ **11차가 점검 항목 부여에 같은 규칙을 썼다** — 그 화면에도 같은 미리보기가 필요하다. → §8-3

### §5-4. 「부분 가동」을 두는 이유

결정 03 은 가동/휴무만 말한다. **셋째를 더한다.**

| 근거 | |
| --- | --- |
| **조업시간 계산이 이것을 요구한다** | `W-05-08` §5-2 가 「조업시간 − 계획비가동」으로 가동률을 낸다. **반일 근무**를 휴무로 처리하면 조업시간이 통째로 빠진다 |
| **`mdm.shift` 가 있다**(SQL 537) | 교대 마스터가 실재하므로 **정상 조업시간은 교대가 정한다**. 부분 가동은 **그날만의 예외** |

⚠ **부분 가동의 시작·종료가 교대와 어긋날 수 있다** — 교대가 2교대인데 부분 가동이 08:00~17:00 이면 어느 교대에 얼마를 배분하나. **`W-05-08` 이 설비별로 집계하므로 교대 배분은 필요 없다** — 필요해지면 그때. → §8-2

⚠ **이것이 「필요한가부터 본다」가 값을 내는 자리**다. 「없어서 조합한다」였으면 지금 다시 뒤집혔을 텐데, **「날짜를 고르는 것이 아니라 달력 위에 상태를 칠하는 것」이라 판단**했으므로 그대로 선다.

| | `DatePicker` | **이 화면의 달력** |
| --- | --- | --- |
| 무엇 | 날짜 **하나를 고른다** | **한 달을 펼쳐 상태를 칠한다** |
| 셀 | 날짜 | 날짜 + **가동/휴무/부분** 표시 + 클릭 |

**조합 시도 기록**(서식 §6-1) — `TextField type="date"`(하나만 고른다 · 불가) → **`Table` 7열 + 셀에 `Button`**(`TableColumn.render` 로 셀 내용을 그린다 — 파일럿에서 확인된 경로). **성립 · `c`.**

⛔ **ds-gap G-8 사용처에 넣지 않는다** — G-8 은 「날짜 **입력**」이고 이것은 「월 단위 **편집 그리드**」다. **다른 것이다.**

**신규 갭 0건.**

## §9. 이 장에서 나온 공유 계약 후보

### 9-1. ⭐ **계층 해석 규칙을 쓰는 화면은 「이 대상이 무엇을 따르는가」를 보인다** — B-17 보완

B-17 이 「가장 가까운 것이 이긴다」를 정했다. **규칙은 짧은데 결과가 안 보인다.**

**규칙안**: B-17 을 적용하는 설정 화면은 **해석 결과 미리보기**를 둔다.

```
대상을 고르면  →  탐색 경로를 층별로 보이고  →  최종적으로 무엇을 따르는지 말한다
설비 PRS-01   →  그룹 프레스라인A (override 없음)  →  공장 기본 CAL-HCM-2026
```

| 왜 | |
| --- | --- |
| **override 가 늘면 표로 안 보인다** | 그룹 20개 × 설비 100대 |
| **설정 화면이 결과를 안 보이면 틀린 줄 모른다** | **G-11** 과 같은 취지 |
| **탐색 경로를 보이면 「왜 그런지」가 함께 답된다** | 「override 가 없어서」 |

**해당**: 작업 캘린더(이 화면) · **설비 점검 항목 부여**(`W-05-12` — 같은 규칙인데 미리보기가 없다).

### 9-2. **결정이 이미 구조를 정한 화면은 「우리가 정할 것」을 먼저 세어 본다**

이 장은 §3 에서 **결정 03 의 다섯 항목 중 넷을 「우리가 정할 것 없음」**으로 표시하고 시작했다.

**규칙안**: 상류 결정이 구조를 정해 둔 화면은 **그 결정의 항목을 표로 옮기고 「우리가 정할 것」 칸을 만든다.**

| 얻는 것 | |
| --- | --- |
| **재발명을 막는다** | 정해진 것을 다시 고민하지 않는다 |
| **실제 설계 지점이 드러난다** | 이 장은 **넷 중 하나**(「필수」의 강제 방법)였다 |
| **결정과 어긋나면 바로 보인다** | 「부분 가동」이 결정에 없다는 것도 이 표에서 드러났다(§5-4) |
