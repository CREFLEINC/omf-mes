# W-02-03 · 4M 자원배정·유효성 점검

## §0. 요약

- **개요**: 관리웹에서 생산관리자(+설비담당)가 W/O에 4M 자원(설비·작업자·금형)을 배정하고 배정 적합성을 Validation(OK/NG)한 뒤 우선순위를 조정하는 화면. 상태 「편성」→「확정 대기」로 전환. **데이터 신뢰도는 부분** — 결정 04가 요구한 배정 엔티티가 전 스키마에 없어, `work_order`의 계획 컬럼으로 자원 유형당 1개씩만 배정 가능하다.
- **주요 데이터**: `production.work_order`의 계획 컬럼 5개(라인·책임 작업자·계획 설비·계획 금형·계획 교대)+계획 시각+우선순위. Validation 근거는 `mdm.equipment`·`mdm.worker_qualification`·`mdm.mold`(전부 실재).
- **핵심 액션**: W/O 선택 → 4M 각 구획에서 자원 1개씩 선택 + 계획 시각 입력(중복 판정에 필요) → Validation 자동 재실행(차단ⓐ/경고ⓑ 3등급) → 우선순위 조정 → 저장 → **차단 0건 AND (경고 0건 또는 확인 체크됨)** → 확정 대기로 전환(`W-02-04`).

> 작성일: 2026-08-05 · 서식: `00-서식.md` v1.0 · 작성 주체: CREFLE OMF 팀 (UI/UX)
> **결정 04의 배정 엔티티가 없다.** 배치표가 `work_session`을 근거로 「충분」 판정했는데 **그것은 결정 04가 분리하라고 한 반대쪽(실적)**이다. 배치표 판정을 정정한다.

## §5. 액션·상태

### §5-1. ⛔ 결정 04의 「배정 엔티티」가 없다 — **배치표 판정을 정정한다**

**확정**(✓설계확정 2026-07-06 **결정 04**)

> **R23** 배정 키 = **배정 No(surrogate)** + 논리 유니크(**W/O · 자원유형 · 자원ID**)
> **R24** **계획(배정)·실적(4M투입) 2엔티티 분리** + 투입 → 배정 **nullable 참조**(긴급 = null)

**실측 — 전 스키마에서 배정 테이블 0건.** 있는 것은 `work_order`의 **계획 컬럼 5개**뿐이다.

**⚠ 배치표가 이 화면의 근거로 `work_session`을 들었는데, 그것은 결정 04가 분리하라고 한 반대쪽이다.**

| 결정 04 | 실재 |
| --- | --- |
| **계획(배정)** 엔티티 | ⛔ **없음** — `work_order` 컬럼으로 눌려 있다 |
| **실적(4M투입)** 엔티티 | ✅ `production.work_session` + `work_session_worker` |
| 투입 → 배정 nullable 참조 | ⛔ **참조할 대상이 없다** — `work_session`에 배정 FK 없음 |

**무엇을 잃는가**

| | 결정 04 | 현재 가능한 것 |
| --- | --- | --- |
| 한 W/O에 설비 **N개** | ✅ 자원유형별 N행 | ⛔ **1개** |
| 한 W/O에 작업자 **N명** | ✅ | ⛔ **1명**(`responsible_worker_id`) |
| 배정 이력·변경 추적 | 배정 행 단위 | ⛔ `work_order` UPDATE로 덮어씀 |
| 긴급 W/O의 「배정 없음」 구분 | 투입의 배정 참조 = null | ⚠ **계획 컬럼이 전부 nullable이라 구분은 된다** |

> ⚠ **실적 쪽은 N을 받는다** — `work_session_worker`가 `work_session` 1:N이라 **여러 명이 실제로 일한 것은 기록된다.** 계획만 1명이다. **계획과 실적의 표현력이 비대칭**이다.

**A-11 적용 — 물러난 수준**: 화면은 **자원 유형마다 1개씩만 배정**하고, 「1개만 배정할 수 있습니다(모델 제약)」를 명시한다. 여러 대를 쓰는 공정이 있으면 **W/O를 나누는 수밖에 없다.**

→ **§I 신규 후보** §9-1 · **`[docs→데이터모델]` 이슈**.

### §5-2. 자재(Material)는 배정하지 않는다

프로세스는 4M을 「**설비·작업자·자재·툴/금형**」으로 든다. 그런데 **자재 배정 자리가 어디에도 없다.**

**그럴 만하다** — **R29가 「W/O 생성 완료 → 출고요청 자동 발행(담당자 개입 없음)」**을 확정했다(REQ-PR-0022). 자재는 **배정하는 것이 아니라 BOM 소요량으로 자동 산정**된다.

**화면 규칙**: 자재 구획을 두되 **배정 컨트롤이 아니라 안내**로 채운다.

```
⚠ 자재는 배정하지 않습니다 — 출고요청이 BOM 소요량으로 자동 발행됩니다 (✅REQ-PR-0022 · R29)
```

**G-4 적용** — 「자동이다」를 체크박스 기본값으로 표현하면 누군가 끌 수 있다. **컨트롤을 두지 않는다.**

### §5-3. R25 「NG면 진행 불가」 — 그런데 등급이 갈린다

**R25**: 「자원 가용·유효성 OK라야 확정 진행 · **NG = 진행불가 상태**」(결정 14)

**Validation 항목이 6종인데 전부 같은 무게가 아니다**(§4-C). **A-9 3등급**으로 나눈다.

| | 확정 진행 |
| --- | :-: |
| **ⓐ 차단** — 설비 비가동 · 금형 사용 불가 | ⛔ **막는다** |
| **ⓑ 경고** — 교정 만료 · 자격 만료 · 금형 수명 · 중복 배정 | ⚠ **확인 후 진행 가능** |

⚠ **예외 E-3 ②가 「Validation NG 무시 확정(권한·기록?)」을 🟠로 남겼다.** 무시를 허용할지, 허용하면 권한과 기록을 어떻게 할지가 미정이다.

**화면은 ⓑ를 「확인했음」 체크로 넘기게** 하고 **`work_order.remarks`에 남긴다** — 전용 컬럼이 없다. → §8-2.

### §5-4. 설비 중복 배정 — 화면이 조회해 판정한다

```
설비 EQ-001 이 08-10 08:00~17:00 에 WO-…013 과 WO-…021 양쪽에 배정
```

**DB가 막지 않는다** — `planned_equipment_id`에 유일 제약이 없다(있을 수도 없다 — 시간대를 봐야 한다).

**화면 책임**(A-9 ⓑ):

```
동일 자원 + 시간대 겹침  →  다른 W/O 조회  →  겹치면 경고
```

⚠ **`planned_start_at`·`planned_end_at`이 nullable이다.** 시각이 없으면 **겹침을 판정할 수 없다.** 시각을 필수로 할지가 미정 → §8-3.

⚠ **예외 E-3 ① 「자원 충돌·중복 배정(우선순위·강제 배정?)」**도 🟠다. `priority_no`가 실재하나 **충돌 시 우선순위로 자동 정리하는 규칙이 없다.**

### §5-5. 우선순위 조정 — A-5 대상이 아니다

```
work_order.priority_no  integer NOT NULL DEFAULT 100
```

**유일 제약이 없다**(중복 허용). A-5(순서 재배치 서버 트랜잭션)의 대상이 **아니다** — `code_value.display_order`와 같은 형태다(v0.4.2 정정).

**행마다 개별 갱신**하면 된다. 다만 **G-7(행 순서 재배치 UI)의 사용처는 된다** — `[↑][↓]`로 바꾸고 싶어질 표다.

| | |
| --- | --- |
| **G-7** 행 순서 UI | ✅ 사용처 — **6번째** |
| **A-5** 서버 일괄 치환 | ⛔ 대상 아님(유일 제약 없음) |

**두 목록이 겹치지만 같지 않다**는 v0.4.2 정정이 여기서 다시 확인된다.

| 자원 선택 | `Select` | a |
| **Validation 결과 목록** | `List` + `Chip`(✅/⚠/⛔) | a |

**신규 DS 갭 0건.** ⚠ **G-8에 「날짜+시각」 형태가 처음 나왔다** — 지금까지는 날짜·기간뿐이었다. `TextField type="datetime-local"`로 성립하나 **세 셸 렌더 차이가 더 커진다** → ds-gap에 기록.

## §9. 이 장에서 나온 공유 계약 후보

1. **⛔ 결정 04의 「계획·실적 2엔티티 분리」에서 계획 쪽이 없다** — 실적(`work_session` + `work_session_worker`)은 N을 받는데 계획은 `work_order` 컬럼 5개로 눌려 **자원 유형당 1개**다. **계획과 실적의 표현력이 비대칭이면 「계획 대비 실적」 비교가 성립하지 않는다** (§5-1)
2. **차수 배치표의 「충실도」 판정은 근거 테이블의 성격까지 보아야 한다** — 이 화면의 근거로 `work_session`을 들어 「충분」이 됐는데 **그것은 결정 04가 분리하라고 한 반대쪽**이었다. **성긴 훑기에서 테이블 이름만 맞추면 판정이 뒤집힌다** (§5-1)
3. **확정 규칙이 「NG면 진행 불가」처럼 이분법일 때 화면이 A-9 3등급으로 나눈다** — Validation 6종을 한 무게로 다루면 교정 만료 하나로 생산이 멈춘다. **나누는 판단과 근거를 스펙이 적는다** (§5-3)
