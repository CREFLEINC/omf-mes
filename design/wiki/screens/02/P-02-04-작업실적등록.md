# P-02-04 · 생산 실적 등록

> **POP 공통 개정(2026-09-08)**: 글꼴·버튼·입력·선택·키패드·목록 행과 터치 영역은 관리웹 기본 밀도(E-3)를 사용한다. 본문의 구 56~72px 수치와 확대 터치 판정은 변경 이력이며 구현 기준이 아니다. 모든 선택형 목록은 선택값 + [선택] 버튼과 로컬 검색·목록 스크롤·[페이지 위]·[페이지 아래] 팝업(G-34)을 사용한다.

> 개정일: 2026-09-08 · 현장 테스트 확정 반영
> 기존 `P-02-05` 인식표 발행, `P-02-06` 생산LOT 완료, `P-02-07` LOT 라벨 출력을 이 화면에 통합한다.

## §0. 요약

- **개요**: 진행 중 W/O의 생산 LOT을 순서대로 보여 주고, 최종 생산수량을 확인·수정한 뒤 생산 LOT 라벨을 출력한다. **라벨 출력 시점에 생산 실적을 저장**하고, 부착한 라벨을 스캔하면 해당 LOT을 자동 마감한 뒤 다음 LOT으로 전환한다.
- **중간 실적**: LOT 진행 중 별도 실적 등록 단계는 두지 않는다. 중간 실적 등록은 인식표 발행·등록이 전부이며, 인식표 대상이 아닌 제품에는 관련 영역을 숨긴다.
- **구분**: 이 화면의 LOT 마감은 **LOT 생산 등록 확정**이다. W/O 마감이 아니며, 미달 사유·잔량 이월/소멸과 미사용 선발행 번호 폐번은 관리웹 `W-02-05`의 W/O 마감에서 처리한다.
- **오프라인**: 생산 실적 저장은 기존 오프라인 큐 규약을 유지한다. 라벨 발행·물리 인쇄·스캔 완료의 단계별 상태를 화면에 분리해 보여 준다.

### §2-1. POP 밀도

글꼴, 버튼, 입력, 선택 트리거, 숫자 키패드와 터치 영역은 모두 **관리웹 기본 크기**를 사용한다(공유계약 E-3). 통합 전 화면에 적힌 56~72픽셀 POP 전용 확대 규격은 적용하지 않는다.

### §2-2. 마감된 LOT 목록 팝업

[마감된 LOT 목록 보기]를 누르면 현재 W/O에서 마감된 생산 LOT 번호를 순서대로 표시한다. 이 팝업은 **단순 확인용**이며 선택·재개·정정 기능을 제공하지 않는다. 목록 내부 스크롤과 [페이지 위]·[페이지 아래]를 제공한다.

## §3. 핵심 흐름

```text
현재 LOT 표시
  → 실제 생산수량 확인/수정
  → [생산 LOT 출력]
      1) 생산 실적 저장
      2) 생산 LOT 라벨 발행·렌더링·인쇄
  → 작업자가 라벨 부착
  → 부착한 LOT 번호 스캔
  → 현재 LOT 일치 확인
  → LOT 자동 마감
  → 다음 LOT 번호로 화면 전환
```

### §3-1. 출력 시 생산 실적 저장

[생산 LOT 출력] 클릭은 별도 [실적 저장] 버튼을 대체한다.

1. 실제 생산수량과 `can_input_result`를 검증한다.
2. `POST /production/production-results`로 생산 실적을 저장한다. `goodQty`는 실제 생산수량이고 `lotAllocations=[{lotId: 현재 LOT, allocatedQty: 실제 생산수량}]`를 함께 보내 **해당 LOT의 최종 실적**으로 귀속한다. 작업자·단말은 각각 `X-Worker-No`와 단말 토큰에서 서버가 파생한다.
3. 같은 사용자 동작 안에서 `POST /app/document-issues`(`documentTypeCode=PRODUCTION_LOT_LABEL`)로 발행 기록을 만든다.
4. 렌디션을 받아 물리 인쇄하고 결과를 `POST /app/document-issues/{documentIssueLogId}:report-print`로 보고한다.

생산 실적 저장과 출력물 발행은 서로 다른 트랜잭션이다. 실적 저장 후 출력이 실패하면 현재 LOT을 유지하고 **출력 재시도** 상태를 보여 준다. 재시도는 같은 생산 실적을 다시 만들지 않으며, 이미 발행 기록이 있으면 재출력 사유를 받아 새 회차로 남긴다.

### §3-2. 인식표 중간 실적

- 인식표 대상 여부는 품목/작업 조건에서 서버가 내려 준 값을 사용한다 — `GET /trace/lots` 응답의 `identificationTagRequired`다(2026-09-09 신설).
- 대상이면 [인식표 라벨 출력]과 출력한 인식표 목록을 표시한다.
- 인식표는 `trace.serial_number` 개체 생성 후 `POST /app/document-issues`(`IDENTIFICATION_TAG`)로 발행한다.
- 이 단계에서는 `production_result`를 만들지 않는다. 생성된 개체 수가 LOT 중간 실적이며, `POST /trace/serial-numbers`는 아직 저장되지 않은 양품 누계를 선행조건으로 요구하지 않는다.
- 인식표는 **단위 정보를 갖지 않는다 — 개체 하나가 무조건 1개**다. 그래서 발번 수량을 LOT 실적 배분 수량에서 환산해 구하지 않으며, 단위 환산도 소수도 발생하지 않는다.
- 실적 수량의 단위는 **품목 기준단위 하나**이고 LOT 마다 다르게 설정하지 않는다. 생산 실적은 단위를 헤더에 하나만 싣고 배분 행은 단위를 갖지 않는다.
- 인식표 대상 품목은 생산 LOT 출력 전에 실제 생산수량과 이 LOT의 개체 수가 같아야 한다. 적으면 부족분 인식표를 추가 발행하고, 많으면 실제 생산수량을 이미 생성된 개체 수보다 작게 낮출 수 없다. 이 검증으로 최종 `goodQty`와 중간 개체를 중복 합산하지 않는다.
- 기존 발행분은 `GET /app/document-issues/summary`와 상세 목록으로 구분하고, 재출력은 대상과 사유를 선택해 수동 실행한다.
- 대상이 아니면 인식표 관련 영역과 여백을 모두 숨긴다.

### §3-3. LOT 스캔 마감

생산 LOT 라벨의 물리 인쇄 성공 후 `can_complete_work=true`일 때 스캔 대기 상태로 전환한다. 스캔 값이 현재 LOT과 일치하면 `POST /trace/lots/{lotId}:complete`를 호출하고, 성공 시 다음 미마감 LOT으로 전환한다. 다른 LOT을 스캔하면 마감하지 않고 현재 LOT 번호를 다시 안내한다.

LOT 마감 후에는 생산 실적 수량을 이 화면에서 직접 수정하지 않는다. 정정은 관리웹 `W-02-05`의 정정 흐름을 사용한다.

## §4. 액션·활성 조건

| 액션 | 활성 조건 | 결과 |
| --- | --- | --- |
| 마감된 LOT 목록 보기 | W/O 선택됨 | 단순 목록 팝업 |

| 생산 LOT 출력 | 수량 유효 · `can_input_result` · `can_print_label` · 인식표 대상이면 실제 생산수량=개체 수 | 현재 LOT에 실적 배분 저장 후 라벨 발행·인쇄 |
| 인식표 라벨 출력 | 인식표 대상 · `can_print_label` | 개체/발행 기록 생성·인쇄 |
| 인식표 재출력 | 발행 이력 있음 · 사유 선택 | 선택 대상을 새 회차로 인쇄 |
| LOT 번호 스캔 | 생산 LOT 인쇄 성공 · `can_complete_work` | 일치하면 자동 마감·다음 LOT 전환 |

## §5. 상태·예외

| 상황 | 처리 |
| --- | --- |
| 생산할 LOT 없음 | 완료 안내. W/O 마감 버튼은 제공하지 않음 |
| 실제 생산수량 변경 | 출력 전 허용. 해당 LOT의 최종 수량으로 저장 |
| 인식표 수와 실제 생산수량 불일치 | 인식표 대상 품목은 LOT 출력 차단. 부족분은 추가 발행하고 이미 발행한 개체 수보다 실제 생산수량을 작게 낮추지 않음 |
| W/O 지시수량 미달 | POP에서 사유·잔량 처리를 요구하지 않음. 관리웹 W/O 마감 소관 |
| 실적 저장 성공·발행 실패 | 같은 LOT 유지, 출력 재시도 제공, 실적 중복 저장 금지 |
| 발행 성공·인쇄 실패 | 기존 발행 건 렌디션 재인쇄. 새 실적·새 LOT 생성 금지 |
| 다른 LOT 스캔 | 차단하고 현재 LOT 번호 표시 |
| 중복 스캔 | 이미 마감된 LOT임을 알리고 다음 LOT 상태 유지 |
| 오프라인 | 실적은 동일 멱등 키로 큐 적재. 서버 판정이 필요한 마감은 연결 복구 후 수행하며 출력/마감 상태를 혼합하지 않음 |
| 사용자 전환 | 현재 사번만 삭제. 저장·큐 기록의 작업자 사번 유지 |

## §6. API 매핑

| 목적 | 계약 |
| --- | --- |
| W/O/LOT 진행 정보 | `GET /trace/lots?workOrderId=&currentOnly=true&withProgress=true` 및 `GET /trace/lots?workOrderId=&completed=true` — 인식표 대상 여부(`identificationTagRequired`)도 이 응답이 내린다 |
| 생산 실적 저장 | `POST /production/production-results` + 현재 LOT의 `lotAllocations` + `Idempotency-Key` + `X-Worker-No` |
| 인식표 개체 수·목록 | `GET /trace/serial-numbers?lotId=` |
| 생산 LOT/인식표 발행 | `POST /app/document-issues` |
| 렌더링·인쇄 결과 | `GET /app/document-issues/{documentIssueLogId}/rendition` · `POST …:report-print` |
| 발행 이력·재출력 판정 | `GET /app/document-issues/summary` · `GET /app/document-issues` |
| LOT 마감 | `POST /trace/lots/{lotId}:complete` |

## §7. 명시적 비범위

- 별도 [실적 저장] 버튼과 LOT 중간 실적 반복 등록은 만들지 않는다.
- 인식표 외 중간 실적 종류를 추가하지 않는다.
- LOT 마감을 W/O 마감으로 부르지 않는다.
- W/O 미달 사유, 잔량 이월·소멸, 미사용 선발행 LOT 번호 폐번은 `W-02-05`에 유지한다.
- 인식표 비대상 품목에 비활성 버튼이나 빈 목록을 보여 주지 않는다.

## §8. 확정 정책

- 생산 수량 3원은 공유계약 L-10에 따라 **양품=`goodQty`, 불량=`defectQty + holdQty + reworkQty`, 손실=`scrapQty`**로 표시한다.
- 이 화면은 R50에 따라 양품만 입력하므로 `goodQty`에 실제 생산수량을 저장하고, 불량·보류·재작업·폐기 수량은 이 화면에서 새로 입력하거나 합산하지 않는다.
- 인식표 대상 품목의 수량은 개체 수와 같아 **정수**다(2026-09-09 확정). **버림·반올림 규칙은 두지 않는다** — 소수가 발생하는 경우 자체가 없다.
