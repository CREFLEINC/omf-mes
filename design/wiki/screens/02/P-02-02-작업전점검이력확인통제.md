# P-02-02 · 작업 전 점검 이력 확인·통제

## §0. 요약

- **개요**: POP(Electron 키오스크 · 1024×768 터치)에서 현장 오퍼레이터·반장이 작업을 시작할 때 점검 이력 존재 여부로 생산 진행을 통제하는 게이트 화면이다. `P-02-01`(작업 시작) 위에 뜨는 조건부 오버레이로, 통과하면 화면 자체가 나타나지 않고 차단·경고일 때만 보인다.
- **주요 데이터**: 통제 수준 정책(`app.operation_policy` · `PRECHECK_CONTROL_LEVEL` · BLOCK/WARN/OFF, 공장·공정 축) · 점검 헤더(일상/정기, 헤더-라인 2계층·종합 판정) · 신설 통제 판정 이력(작업지시·설비·판정 시각·사번·통제 수준·판정 결과·근거 점검 헤더 FK·우회 사유).
- **핵심 액션**: 주기 내 점검 이력·종합 판정 조회 → 이력 없음(통제 수준대로)·NG(수준 무관 차단) 판정 → [ 다시 확인 ]으로 재판정 → 긴급 W/O + 이력 없음일 때만 [ 우회하고 시작 ] 활성(NG면 비활성) → [ 돌아가기 ]로 `P-02-01` 복귀.

> 작성일: 2026-08-11 · 서식: `00-서식.md` v1.0 · 작성 주체: CREFLE OMF 팀 (UI/UX)
> **DR-001 이 마지막으로 미룬 화면**이다.
> ⭐ **DR-001 §7 이 「5단계를 마지막에 둔 이유」로 지목한 그 화면**이다 — 「POP-작업전점검 화면은 **점검 기록의 형태가 정해진 뒤**에야 「무엇을 보고 막을지」를 쓸 수 있다」. **그 형태를 확정**했다.

## §5. 판정 규칙

### §5-1. ⭐⭐ 이월 — **통제 3단계의 소유 화면이 여기다**

`W-05-12` §8-7 이 「저장처는 `app.operation_policy` 로 있으나 **소유 화면이 0건**」으로 남겼다. **이 화면이 소비자이고, 설정 화면은 따로 두지 않는다.**

| | |
| --- | --- |
| **값을 읽는 곳** | ⭐ **이 화면**(판정) |
| **값을 정하는 곳** | ⚠ **전용 설정 화면을 신설하지 않는다** — §5-3 |

**정책 코드**(B-22 목록에 넣는다)

```
policy_code   PRECHECK_CONTROL_LEVEL
value_text    BLOCK | WARN | OFF
범위 축       공장 · 공정        ← 설비·설비그룹 축은 없다 (§5-2)
```

### §5-2. ⭐ 이월 — **설비 축이 없어도 성립한다**

`W-05-08` §8-3 이 「`operation_policy` 범위 축에 **설비·설비그룹이 없다** — 「설비그룹별 통제 수준」이 필요하면 축이 하나 는다」로 남겼다.

**확정 — 축을 늘리지 않는다.**

| 왜 | |
| --- | --- |
| **통제 수준은 설비 속성이 아니라 정책**이다 | 인벤토리 §5 미결 4 가 이미 그렇게 판정했다(「`W-05-12` 는 정책이 설비 속성 아님」) |
| **공정 축이면 충분하다** | 「프레스 공정은 차단 · 조립 공정은 경고」가 실무 단위다 |
| ⛔ **설비별로 다르게 두면** | 100대에 100개 정책이 생기고 **누가 어느 수준인지 아무도 모른다** |

⚠ **필요해지면 그때 늘린다** — **A-20**(세 번 이월된 항목은 「지금 필요한가」)과 같은 판단이다. **요구 근거가 없다.**

### §5-3. ⛔ 통제 수준 **설정 화면을 신설하지 않는다**

**인벤토리 §5 미결 4 가 세 후보를 놓고 「신설은 항목 1개짜리라 과하다」**고 했다. **그 전제를 재확인**했고 B-22 가 **정책 코드가 늘어남**을 보였다.

| 시점 | 정책 코드 |
| --- | :-: |
| 지금 | **4종** — 환산 2 + 통제 1 + 경미 정지 1 |

⭐ **「MES 운영 정책 설정」류 화면이 나중에 여러 항목을 모아 생길 가능성이 높다**는 인벤토리 예측이 **맞아 가고 있다.** 4종이 됐고 더 늘 것이다.

**확정 — 지금은 신설하지 않고 인벤토리 미결 4 를 그대로 둔다.** ⚠ **이 화면은 값을 읽기만 하므로 설정 화면이 없어도 동작한다**(시드로 넣으면 된다 — #67 회신 §4-4).

### §5-4. ⭐⭐ 이월 — **「이력 없음」과 「못 올렸음」을 구분하지 못한다**

`M-05-01` §9-2 가 **C-15** 를 세우며 남긴 것이다.

> ⚠ **게이트 쪽(5단계)이 이 사실을 알아야 한다** — 「이력 없음」을 「점검 안 함」으로 **단정하지 않는다.**

**⛔ 서버는 두 경우를 구분할 수 없다.** 오프라인 점검은 **서버에 아예 없다.**

**확정 — 구분할 수 없음을 화면이 말한다.**

| 통제 수준 | 처리 |
| --- | --- |
| **차단** | ⛔ 막되 ⭐ **「미전송 점검이 있을 수 있습니다 — 점검 단말을 확인하세요」**를 ②에 함께 보인다 |
| 경고 | 같은 문구 + 진행 가능 |
| 미적용 | 통과 |

⭐ **이것이 F-5 의 집행 쪽 책임**이다 — 근거 화면(`M-05-01`)은 「미전송 N건 — 작업 통제에 반영되지 않습니다」를 보이고, **집행 화면은 「없음이 아니라 못 봤을 수 있음」을 보인다.** **두 문구가 짝**이다(`P-02-01` §9-1).

⛔ **자동으로 통과시키지 않는다** — 「미전송일 수도 있으니 봐 준다」로 가면 **통제가 무력해진다**(WF05 S3 Exception ③ 이 정확히 그 현행 문제를 적었다).

### §5-5. 판정식 — **주기 내 점검 이력이 있는가**

```
대상 점검 유형   설비에 부여된 항목의 주기가 오늘 도래한 것   (W-05-12 §4-C-2)
판정            그 유형의 점검 헤더가 주기 내에 있고 종합 판정이 합격인가
                                                     ↑ M-05-01 §5-3 이 저장하기로 한 값
```

⭐ **종합 판정을 저장한 이유가 여기서 값을 낸다** — 「라인 N건을 매번 훑어 판정하면 통제 화면이 느려지고 **판정 규칙이 두 화면에 복제**된다」(§5-3). **이 화면은 헤더 한 줄만 본다.**

| 경우 | 판정 |
| --- | :-: |
| 주기 내 이력 있음 · 종합 **합격** | ✅ 통과 |
| 주기 내 이력 있음 · 종합 **NG** | ⛔ **차단**(수준과 무관) — §5-7 |
| 주기 내 이력 **없음** | 통제 수준대로 |
| 여러 건 있음 | ⭐ **가장 최근 것**(§6-2 「최근 것이 통제 판정에 쓰인다」) |

### §5-6. 이월 — 고장은 **보이되 막지 않는다**

`W-05-04` §5-6 이 「**고장 완료가 W/O 를 자동 재개시키지 않는다**」로 정했다. **역방향도 같다.**

| | |
| --- | --- |
| **열린 고장이 있으면** | ⚠ **보인다** — 「이 설비에 처리 중인 고장 1건」 |
| **막는가** | ⛔ **아니다** — 통제 대상은 **점검 이력**이지 고장이 아니다(QA #9) |

⚠ **B-16 판정식의 「열린 고장·보전 건이 없다」와 다르다** — 그것은 **설비 사용 가부**이고, 여기는 **점검 통제**다. **축이 다르므로 섞지 않는다.**

⛔ **고장으로도 막고 싶다면 그것은 새 요구**다 — QA #9 는 점검만 말했다. → §8-3

### §5-7. 점검 NG 는 **수준과 무관하게 차단한다**

WF05 S2 Exception ② 가 「**점검 NG인데 생산 우선** → 임시 가동/조건부 사용은 **통제 정책(QA #9) + 긴급 W/O 우회**로 처리」라 했다.

| | |
| --- | --- |
| 이력 **없음** | 통제 수준(차단/경고/미적용)이 정한다 |
| 이력 있고 **NG** | ⛔ **차단** — 「점검에서 NG 가 나왔습니다」 |
| 풀 수 있는 길 | ⭐ **긴급 W/O 우회뿐** |

**왜 수준과 무관한가** — 「미적용」은 **「점검을 안 해도 된다」**는 뜻이지 **「NG 인데 돌려도 된다」**가 아니다. **두 가지를 한 값이 정하게 하면 위험한 쪽으로 기운다**(**A-14** — 조건을 값에 밀어 넣지 않는다).

### §5-8. 긴급 W/O 우회 — **기록이 남는다**

QA #9 가 「긴급 W/O 우회 허용」을 확정했고 도식 MES-2 가 「**우회·경고 진행도 기록**」이라 적었다.

```
통제 판정 이력  [신설]
  작업지시 · 설비 · 판정 시각 · 사번
  통제 수준(BLOCK/WARN/OFF) · 판정 결과(통과/차단/경고진행/우회)
  근거 점검 헤더 FK  ⚠ nullable (이력 없음이면 비운다)
  우회 사유       ⚠ 긴급 W/O 우회일 때
```

⚠ **`work_session` 에 담을 자리가 없다** — `P-02-01` §8-3 이 남긴 것이고 **여기서 정의한다.**

⛔ **우회를 「긴급 W/O 일 때만」으로 좁힌다** — 아무 지시나 우회하면 통제가 무의미하다. `work_order_type_code` 로 판정한다.

⚠ **우회 사유를 자유 텍스트로 받지 않는다** — 긴급 W/O 자체가 사유다. **더 물으면 형식적으로 채운다**(`M-05-02` §5-2 가 「무거우면 안 적는다」로 같은 판단).

### §5-9. 액션·상태

| 액션 | 활성 조건 |
| --- | --- |
| 돌아가기 | 항상 — `P-02-01` 로 |
| **다시 확인** | 항상 — 판정을 다시 돌린다(점검을 방금 올렸을 수 있다) |
| **우회하고 시작** | ⭐ **긴급 W/O + 판정이 「이력 없음」일 때만** · ⛔ **NG 이면 비활성**(§5-7) |
| 진행(경고 시) | 통제 수준 = WARN · **확인 다이얼로그** |

**상태**: `판정 중` → `통과(즉시 `P-02-01` 로 복귀)` / `차단` / `경고` / `우회 확인`

⭐ **통과하면 이 화면이 뜨지 않는다** — 게이트는 **막을 때만 보인다.**

## §9. 이 장에서 나온 공유 계약 후보

### 9-1. ⭐⭐ **「판정할 수 없음」을 「통과」로 처리하지 않는다**

⛔ **게이트에서 가장 흔한 실수**다 — 조회가 실패하면 통과시키는 것.

**규칙안**: 게이트 화면(F-5 의 집행 쪽)은

1. **통과는 판정 결과여야 한다** — 「판정하지 못함」은 통과가 아니다
2. **판정 실패 시 막고 사유를 말한다** — 「확인할 수 없습니다」(≠「없습니다」)
3. **다시 시도할 경로를 준다**(G-3) — 「복구되면 [ 다시 확인 ]」
4. ⚠ **「없음」과 「확인 못 함」을 다른 문구로** — **G-9**(모르는 값과 없는 값)의 게이트 판

⭐ **C-15 와 짝이다** — 생산자는 「미전송 N건」, 소비자는 「확인할 수 없음」. **같은 원인의 두 얼굴**이다.

### 9-2. **한 값이 두 가지를 정하게 하지 않는다** — A-14 의 게이트 판

통제 수준 「미적용」이 **「점검을 안 해도 된다」**와 **「NG 인데 돌려도 된다」**를 함께 뜻하면 **위험한 쪽으로 기운다.**

**규칙안**: 정책 값 하나가 **성격이 다른 두 판정**을 덮으려 하면 **나눈다.**

| | 무엇을 정하나 | 이 화면 |
| --- | --- | --- |
| 통제 수준 | **이력이 없을 때** 어떻게 하나 | 차단/경고/미적용 |
| NG 처리 | **판정이 실패했을 때** 어떻게 하나 | ⛔ **항상 차단** — 값으로 두지 않는다 |

⚠ **A-14 는 「상태와 조건을 분리한다」였고, 이것은 「정책 값과 안전 규칙을 분리한다」**다. **안전 규칙은 설정 가능하게 두지 않는다.**

### 9-3. **게이트는 막을 때만 보인다**

통과하면 이 화면이 뜨지 않는다(§5-9).

**규칙안**: 게이트 화면은 **통과 시 화면을 띄우지 않는다.**

| 왜 | |
| --- | --- |
| **작업 흐름을 끊지 않는다** | 하루 수십 번 지나는 지점이다 |
| **뜨면 문제가 있다는 뜻**이 된다 | 화면 자체가 신호가 된다 |
| ⚠ **통과 기록은 남긴다** | 안 보이는 것과 안 남기는 것은 다르다(§5-8) |
