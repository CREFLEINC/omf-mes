# P-02-13 · PQC 제품 검사·검사 결과 입력

## §0. 요약

- **개요**: POP(1024×768 터치) 화면. 작업자(자주검사)·품질담당(초중종 입회·판정)이 검사 항목별 결과를 입력하고 종합 판정을 내린다. 단말×공정 플래그 `can_input_inspection`이 이 화면에서 **처음 실증**된다. 02(생산실행)와 03(품질관리)의 경계에 서며, Lot Status 전이·판정유형 목록 자체는 03 거버넌스다.
- **주요 데이터**: `quality.inspection_request`(검사 의뢰, 대개 읽기 전용), `quality.inspection_result`(검사 결과 — 합격·불합격·보류 수량에 `ck_inspection_result_qty` CHECK 제약), `inspection_measurement`, `defect_record`, `mdm.terminal_process`(`can_input_inspection`).
- **핵심 액션**: 항목별 판정·측정값 입력 → 수량(검사·합격·불합격·보류) 입력 → 종합 판정 선택(합격/불합격/보류, 목록 조회) → 불합격 시 처분(재작업 가능/폐기, **잠정** — 확정은 불량창고 입고 후) → 임시 저장 또는 검사 확정(합계 일치·전 항목 판정·종합 판정·권한 플래그 충족 시).

#### 설계 — 두 갈래를 화면이 갖는다

| 기준 | 화면 |
| --- | --- |
| **있다**(정상) | 검사 항목별 규격·판정 — §4·§5-3 그대로 |
| **없다**(확정이 허용한 갈래) | ⭐ **정상/불량 단순 선택 + 자유 입력.** 항목표 대신 판정 두 값과 자유 입력란만 보인다 |

⭐ **왜 물러서면 안 되나** — 기준 미등록은 **현장에서 실제로 일어나는 상태**이고, 그때 검사를 못 하면 **제품이 멈춘다.** 확정이 「단순 선택이라도 하라」고 한 이유가 그것이다. 물러선 판단은 **「기준을 먼저 등록하라」는 안내로 현장을 막는 것**이었다.

📨 **모델 결손은 작업 통지다** — 기준 없는 의뢰를 담으려면 `inspection_plan_version_id` 가 **널을 받아야** 한다(물리 모델은 아직 `NOT NULL`). **우리를 막지 않는다** — 계약은 화면대로 쓰고 기다리지 않는다(§8).

✅ **계약이 착지했다(2026-08-28)** — `InspectionRequest.inspectionPlanVersionId` 를 `required` 에서 빼고 널을 받게 했다. 갈래에 필요한 나머지 셋도 함께 확인했다: 측정치 배열은 **원래 필수가 아니라** 빈 채로 보내면 되고, 자유 입력은 `remarks` 가 받으며, 종합 판정은 **같은 3값 목록을 그대로** 쓴다(값을 새로 만들지 않는다).

⚠ **등급이 올라간다** — 「조정」이 아니라 **화면이 갈래 하나를 더 갖는다.** 구현팀에 ⚠ 변경으로 알렸다(2026-08-18 · `omf-mes-client#86` 코멘트). 계약 착지는 **⛔ 등급**으로 따로 알린다 — 같은 스키마를 `W-01-01`·`W-04-03` 도 읽는다.

### §5-3. A-3 합계 제약이 **DB로 강제**된다

```
ck_inspection_result_qty  CHECK (accepted_qty + rejected_qty + held_qty = inspected_qty)
```

**A-3**(합계 제약의 UI 표현) 그대로: **실시간 합계·잔여를 표시하고 불일치 상태에서 확정 버튼을 비활성.**

```
합계  30 / 30  ✅        ← 일치
합계  28 / 30  ⚠ 2 남음   ← 확정 비활성
```

⚠ **A-3의 단서도 적용된다** — 「**자동 계산은 규칙이 확정된 뒤에만** 얹는다. 어느 칸을 자동으로 할지가 정해져야 한다」(`W-01-01` §8-4 미결). **여기서도 자동 계산을 넣지 않는다** — 합격만 넣으면 불합격이 자동으로 채워지는 것이 자연스러워 보이나, **보류가 있어 2칸이 남는다.**

### §5-4. 종합 판정 — ✅ **회신 E-3 종결(2026-08-07)**

**판정 3값 = `합격`·`불합격`·`보류`.** 검사 판정 **3값**(`합격`·`불합격`·`보류`) — `ck_inspection_result_qty`(`accepted+rejected+held = inspected`)가 **수량 3칸으로 이미 강제**하고 있었다. 각각 LOT 상태 `정상`·`불량`·`검사 대기` 로 전이한다. → `design/raw/process/uiux/2026-08-07-E3-판정유형-제안안/LOT상태-확정기록.md`

#### (구) 회신 E-3 대기 시 G-6 표준 형태

```
inspection_result.overall_judgment_code   app.code_t NOT NULL
```

**회신 E-3**(판정 유형 **전체 목록**)이 대기 중이다. 확정된 것은 **한도승인·특채·폐기** 등 일부뿐이다.

**G-6**(회신 대기 화면의 표준 형태 · v0.4 신설)을 적용한다:

1. **확정분과 대기분을 한 목록에 함께 보이고 표식으로 구분** — 대기분을 감추면 「없는 것」으로 오해한다
2. 회신 전 **임시 등록을 막지 않되 「재검토 대상」으로 표시**
3. **화면 머리에 대기 사유와 회신 번호 명시**(E-3)

⚠ **G-6의 경고가 그대로 걸린다** — 「**대기 범위를 좁게 적지 않는다.** 회신 E-3의 문구는 「판정 유형 **전체 목록**」이라 확정 4종 외에 더 나올 수 있다. **화면은 목록 길이를 가정하지 않는다.**」

**→ 그래서 이 화면은 차단이 아니다.** 버튼을 고정 개수로 그리면 차단이지만, **목록에서 고르는 형태**면 값이 몇 개든 골격이 같다.

### §5-5. `coverage_from_at`/`coverage_to_at` — 모델이 앞섬

```
inspection_request.coverage_from_at  timestamptz   -- [L] 검사결과 적용 생산구간: 시간 (2-6 §7.5)
inspection_request.coverage_to_at    timestamptz
```

**「이 검사 결과가 어느 시간대의 생산분에 적용되는가」**를 담는다. 프로세스·확정 어디에도 없는 개념인데 **데이터가 갖고 있다.**

**왜 필요한가** — 초중종 검사는 **표본**이다. 「09:00~11:00 생산분을 대표한다」가 성립해야 불합격 시 **회수 범위**가 정해진다.

**화면이 쓸 것인가** — **쓴다.** 검사 시작·종료 시각으로 자동 채우되 **작업자가 조정 가능**하게 둔다.

⚠ **불합격 시 이 구간의 생산분을 어떻게 하나**가 미정이다 — 03 소관(Lot Status 전이) → §8-3.

### §5-6. #62(검사자 ≠ 확정자 분리)가 여기서도 걸린다

```
inspection_result.inspector_id   NOT NULL   ← 검사한 사람
inspection_result.confirmed_at   nullable    ← 확정 시각 (누가?)
```

**`confirmed_by`가 없다.** 확정한 사람을 담을 컬럼이 없다.

**#62**(검사자와 확정자를 분리할 것인가)는 `W-01-01`(IQC)에서 **차단** 등급으로 열린 미결이다 — 「분리하면 화면이 둘로 갈리고 권한 축이 생긴다」.

**이 화면에서도 같다.** 다만 **02-S-E의 분업(Q1)이 「검사 수행·결과 입력 지점 = 02-S-E」**라고 하여 **이 화면은 입력까지**로 읽힌다.

| 해석 | 이 화면 |
| --- | --- |
| **분리 안 함** | 작업자가 판정까지 |
| **분리함** | 작업자 입력 → **품질담당 확정은 다른 화면**(`W-03-01` 계열) |

⚠ **02-S-E는 「작업자(자주검사)·품질담당(초중종 **입회·판정**)」**이라 **행위자가 이미 둘**이다. **같은 화면에서 역할만 다를 수 있다.**

**권고**: 이 화면에 **입력과 확정을 함께 두되 `can_input_inspection` 권한으로 가른다.** #62 회신이 오면 재검토 → §8-2.

⚠ **`W-01-01`(IQC)의 #62는 차단이지만 여기서는 조정**이다 — IQC는 화면이 둘로 갈릴 수 있으나, PQC는 **POP 한 화면에서 권한으로 가르는 것이 자연스럽다.**

### §5-7. 오프라인 — `idempotency_key`가 있다

```
inspection_result.idempotency_key  varchar(150) NOT NULL UNIQUE
```

**C-1 대상 4곳 중 하나**(`M-01-05` §5-4에서 전수 확인). **전역 UNIQUE라 `business_date` 문제(C-8)가 없다.**

**POP 오프라인 규약**은 `P-01-02` §8-5가 미결로 남겼다 — 결정 17 시나리오 2는 **모바일** 축퇴다.

**이 화면은 오프라인을 지원한다**고 보는 것이 자연스럽다(현장 검사가 통신에 묶이면 안 된다). C-1·C-7(미확정 표식)·C-9(토큰 미동봉) 적용.

⚠ **다만 판정 결과가 Lot Status에 영향을 준다** — 결정 10의 「캐시 없음」과 `M-01-08` §5-2의 충돌이 여기서도 잠재한다. **판정은 기록이지 차단이 아니므로** 가볍다 → §8-4.

### §5-8. 재작업/폐기 2분류 — 처분구분이 없다

**REQ-PR-0025**: 「재작업 가능 불량 vs 폐기 불량 구분 — **판정은 불량창고 입고 후**」

**§I-10**이 이미 기록했다 — **결정 12가 정한 상세 코드 속성 「처분구분(재작업가능/폐기)」이 `defect_code`에 없다**(#64 묶음 A).

**화면 설계**: 불합격분에 대해 **처분을 사람이 고른다**(자동 판정 불가). 고른 값은 `quality.disposition_decision`에 담긴다(실재).

⚠ **REQ-PR-0025는 「판정은 불량창고 입고 후」**라고 순서를 못박았다. **이 화면에서 처분을 고르면 순서가 뒤집힌다.**

**해석**: 이 화면의 처분 선택은 **잠정**이고, **확정 판정은 불량창고 입고 후 `W-03-10`(처분 판정 처리)**이 한다 — `W-04-07`(04)은 부적합 등록·판정 «의뢰»까지이고 스스로 판정하지 않는다(`W-04-07` §5-1 · 04 요구서 §3-7 「판정 ⛔ 없음 — 두지 않는다」 · `F04` 정합 확정). *(v0.1의 「`W-03-*`」는 당시 03 에 처분 저장 화면이 0건이라 가리킬 곳이 없었고, `W-03-10` 이 2026-08-13 **DR-008 3-A** 로 신설되며 채워졌다 — 03 요구서 §3-8.)* 화면 문구로 밝힌다:

```
⚠ 처분은 불량창고 입고 후 확정됩니다 (✅REQ-PR-0025)
```

### §5-10. 진입 — **대상을 받아서 연다. 목록을 두지 않는다** ⭐ **[2026-08-28 명문화 · `omf-mes#257` ①]**

```
진입 인자   inspectionRequestId   (검사 의뢰 식별자 하나)
```

**이 화면은 대상을 고르지 않는다.** 작업 화면에서 검사 의뢰가 정해진 채로 열린다.
계약이 이미 그렇게 적어 두었다 — 검사 의뢰 **한 건** 조회 경로의 설명이 「이 화면 진입 시
기준 버전·대상 수량을 읽는다」이고, 검사 의뢰 **목록** 경로의 설명은 소비자를 `W-01-01`로 못박았다.

| 상황 | 화면 |
| --- | --- |
| 진입 인자가 있다 | 그 의뢰를 읽어 §3 머리줄을 채우고 검사를 시작한다 |
| 진입 인자가 **없다** | ⛔ **목록을 그리지 않는다.** 「작업 화면에서 진입하세요」 안내 한 장만 그린다 |
| 진입 인자가 있으나 의뢰가 없다(404) | 같은 안내 + 「그 검사 의뢰를 찾을 수 없습니다」 |

⛔ **검사 대기 목록을 이 화면에 얹지 않는다.** 「아직 안 끝난 의뢰만」을 받는 질의(`pendingOnly`)가
계약에 있으나 그것은 **`W-01-01`(수입검사 판정, 관리웹)의 좌단 큐**다. 이 화면이 부르면 같은 큐가
두 곳에 생기고, 그중 하나는 §5-9 액션표에 없는 행위가 된다.

⚠ **진입 경로 화면(`P-02-01`·`P-CO-01`)이 아직 서지 않은 것은 이 규약을 바꾸지 않는다.**
그 화면들이 서기 전에는 진입 인자가 안 오므로 위 두 번째 행(안내 한 장)이 평소 모습이다.

⭐ **이 규약을 다른 POP 화면에 그대로 복사하지 않는다.** §3 도면의 **머리줄이 받는 것**과
**좌단 구획이 고르는 것**은 화면마다 다르다 — `P-02-05`는 좌단이 《대상 LOT》 목록이고
`P-02-09`는 좌단이 《포장 단위》 내용물이다. 이 화면만 좌단이 《검사 항목》이라 고를 것이 없다. §9-4

### §5-11. 자동 판정 — **채우되 잠그지 않는다** ⭐ **[2026-08-28 확정 · `omf-mes#257` ②]**

```
mdm.inspection_item_spec.automatic_judgment   boolean   기본 true
```

`W-06-02`(검사기준 등록) §4-C가 이 플래그의 뜻을 「**상·하한으로 합·불을 자동 판정할지**」로
정해 두었다. 이 화면이 그것을 **읽는 유일한 화면**이다.

**자동 판정이 서는 조건 — 셋이 모두 참일 때만**

| 조건 | 값 |
| --- | --- |
| 자동 판정 플래그 | `automatic_judgment = true` |
| 데이터 유형 | `data_type_code = NUMERIC` — 상·하한이 의미를 갖는 유일한 유형이다 |
| 기준 | 하한·상한 중 **하나 이상**이 채워져 있다 |

**서면**: 화면이 측정값을 상·하한과 대조해 항목 판정을 **채운 채로** 보인다(§3 도면의 ✅·⛔ 그대로).
⭐ **사람이 바꿀 수 있다.** 채운 값은 시작점이지 확정이 아니다.

**서지 않으면**: 판정을 비워 두고 사람이 고른다. 저장을 막지 않는다 — 조항 G-15(비어 있으면 판정이
서지 않는 필드는 저장을 막지 말고 보인다) 그대로다. 화면에 사유를 함께 보인다.

```
기준 없음 — 직접 판정하세요
```

⛔ **종합 판정은 어떤 경우에도 자동으로 내리지 않는다.** 항목이 전부 불합격이어도 종합 판정은
사람이 고른다 — §6의 「자동 불합격 아님」이 가장 강하게 걸리는 자리가 여기다.

⚠ **`M-05-01`(설비 점검 입력)은 같은 형태를 반대로 정했다** — 그쪽은 「자동 판정을 사람이 덮어쓸 수
없게 한다」이다. 설비 점검에는 자동 판정 여부를 가르는 마스터 스위치가 없고(판정 방식 코드 한 축),
제품 검사에는 있다. **스위치가 있는데 결과를 잠그면 스위치를 두 번 쓰는 것**이 된다. §9-5

## §9. 이 장에서 나온 공유 계약 후보

1. **G-6(회신 대기 화면 표준)이 차단 등급을 낮춘다** — 「목록에서 고른다」로 설계하면 값이 3개든 10개든 골격이 같다. **값 목록 미정을 차단으로 볼지 조정으로 볼지는 UI 형태가 가른다** — 고정 버튼이면 차단, 목록이면 조정. **미결 등급 판정 기준에 이 구분을 넣는다** (§5-4)
2. **같은 미결이 화면에 따라 등급이 다르다** — #62(검사자≠확정자)는 `W-01-01`(IQC · 관리웹)에서 **차단**인데 여기서는 **조정**이다. IQC는 화면이 둘로 갈릴 수 있고 PQC는 POP 한 화면에서 권한으로 가른다. **미결 등급은 미결 자체가 아니라 그 화면에서의 파급으로 정한다** (§5-6)
3. **A-3의 「자동 계산 보류」 단서가 두 번째로 확인된다** — `W-01-01`에서 「어느 칸을 자동으로 할지 미정」이었는데, 여기도 **보류가 있어 2칸이 남아** 자동 계산이 성립하지 않는다. **합계 제약이 3항 이상이면 자동 계산은 규칙 확정 전까지 넣지 않는다** (§5-3)
4. **POP 화면의 「받는 것」과 「고르는 것」은 §3 도면이 이미 가른다** — 머리줄이 받는 것이 진입 인자이고, 좌단 구획이 화면 안에서 고를 것이다. `P-02-05`는 좌단이 대상 LOT 목록, `P-02-09`는 포장 내용물, 이 화면은 검사 항목이라 고를 것이 없다. **「POP은 목록을 두지 않는다」로 일반화하면 앞 둘의 선택 구획을 잘못 걷어낸다.** 3화면 실증이 모이면 조항으로 올린다 (§5-10)
5. **마스터가 「자동으로 할지」를 스위치로 갖고 있으면 그 결과를 화면이 잠그지 않는다** — 제품 검사는 항목마다 자동 판정 스위치가 있어 채우되 바꿀 수 있고, 설비 점검(`M-05-01`)은 스위치가 없어 잠근다. **스위치의 유무가 잠금 여부를 가른다** — 같은 「자동 판정」이라는 말로 두 화면을 같게 만들면 안 된다 (§5-11)
