# P-02-12 · 긴급 W/O 현장 투입·실적

## §0. 요약

- **개요**: 긴급 W/O(P/O 비귀속·발행자 직접 전개)의 현장 실행 전 구간을 다루는 POP 진입 화면이다. **정상 경로 화면을 그대로 재사용**하고 긴급 플래그만 유지한다(4단계 확정) — 투입·실적용 화면을 별도로 만들지 않는다. ✅ **되살렸다(2026-08-30)** — `POST /production/work-orders`가 `productionPlanId`를 비우고 부르는 경로를 이미 지원한다. 서버가 내부 P/O(`erpOrderNo` 없음)와 계획을 한 트랜잭션으로 만들어 붙인다(공유계약 B-8) — R07(ERP 정본)과 충돌하지 않는다, ERP가 보내지 않은 합성 P/O는 반제품 전개에서 이미 쓰던 개념이다.
- **주요 데이터**: `production.work_order`(`WorkOrderCreate.productionPlanId` nullable·`workOrderTypeCode=EMERGENCY`), `planning.production_plan`(서버가 내부 P/O와 함께 자동 생성) · 투입·실적은 `P-02-03`·`P-02-04`와 **같은 테이블**(`material_consumption`·`production_result`)을 공유하며 별도 테이블이 없다.
- **핵심 액션**: 긴급 W/O 목록에서 항목 선택 → **정상 화면(자재 투입 `P-02-03`, 실적 입력 `P-02-04`)으로 이동**하며 긴급 플래그를 유지한다. 긴급 W/O 발행 자체는 관리웹(`W-02-07`) 소관이라 이 화면이 만들지 않는다.

> 작성일: 2026-08-04 · 서식: `00-서식.md` v1.0 · 작성 주체: CREFLE OMF 팀 (UI/UX)
> ✅ **되살렸다(2026-08-30)** — 「P/O 비귀속 긴급 W/O」는 서버의 내부 P/O 자동 생성으로 이미 만들어진다.

## §3. 레이아웃 (POP — 1024×768)

**정상 경로 화면 재사용**이 확정이므로 이 화면은 **긴급 표식과 진입점**을 제공하고 나머지는 기존 화면으로 보낸다.

```
┌ 1024 ────────────────────────────────────────────────────────────────────┐
│ 🚨 긴급 W/O                                          단말 POP-L1 ●       │
├──────────────────────────────┬───────────────────────────────────────────┤
│ 《긴급 W/O 목록》            │ 《WO-…E-002》  🚨 긴급                    │
│ ┌──────────────────────────┐ │   품목    XYZ-999                         │
│ │ 🚨 WO-…E-002  XYZ-999   │ │   수량    50 EA                           │
│ │    50 EA   발행 14:20    │ │   발행    14:20 · 김OO                    │
│ └──────────────────────────┘ │   ──────────────────────                  │
│                              │   ⚠ 배정 없음 · 점검 통제 우회            │
│  ⓘ 긴급 W/O 는 관리웹        │                                           │
│    W-02-07 에서 발행합니다    │   ┌──────────────┐  ┌──────────────┐     │
│                              │   │  자재 투입   │  │   실적 입력  │     │
│                              │   └──────────────┘  └──────────────┘     │
│                              │      → P-02-03          → P-02-04         │
│                              │      (긴급 플래그 유지)                    │
└──────────────────────────────┴───────────────────────────────────────────┘
```

### §4-B. 투입·실적

`P-02-03`(투입)·`P-02-04`(실적, 앵커)와 **같은 테이블**을 쓴다. 긴급이라고 별도 테이블이 없다.

**R24** — 「투입 → 배정 **nullable 참조**(긴급 = null)」. `material_consumption`에 배정 참조가 없고 `work_session_id`가 nullable이므로 **배정 없이 투입이 기록된다** ✅.

## §5. 액션·상태

### §5-1. 이 화면은 진입점이다

**4단계 확정** — 「현장 실행 전 구간 = **정상 경로 화면 재사용 + 긴급 플래그**」

긴급이라고 투입·실적 화면을 따로 만들지 않는다. 이 화면은

1. **긴급 W/O 목록**을 보이고
2. 선택 시 **정상 화면으로 보내되 긴급 플래그를 유지**한다

**긴급 W/O 발행 자체는 관리웹**(`W-02-07`)이다 — 프로세스가 「발행자 직접 전개」라 하고, 인벤토리에 `W-02-07`(긴급 W/O 발행)이 실재한다.

### §5-2. ✅ 확정대로 되살렸다 — 「가」안으로 구현됨(2026-08-30)

**확정** — 02-S-D 태스크 ① 「긴급 W/O 발행(**P/O 비귀속** · 발행자 직접 전개 · 별도 승인 없음)」

계약이 이미 **해석 「가」(더미 P/O·계획을 자동 생성)** 로 이 확정을 구현하고 있었다:

```
POST /production/work-orders
    productionPlanId: null   ← 비우고 부른다
```

서버가 내부 P/O·생산계획·W/O 생성을 **한 트랜잭션**으로 처리한다(공유계약 B-8, 중간에 끊기면 전체를 되돌린다). 그 P/O는 `erpOrderNo`가 비어 있다 — **ERP가 보내지 않은 합성 P/O**는 반제품 전개에서 이미 쓰던 개념이라 새로 지어낸 것이 아니다.

| 확정이 요구하는 것 | 실재 |
| --- | --- |
| 긴급 W/O는 **P/O 비귀속** | ✅ 서버가 내부 합성 P/O를 만들어 붙인다 — 사용자 입장에선 「비귀속」 |
| 발행자가 **직접 전개** | ✅ `POST /production/work-orders`(W-02-07)를 발행자가 직접 부른다 |

⚠ **「나. 컬럼을 nullable로」·「다. 긴급 전용 계획」은 채택되지 않았다** — 「가」안이 R07(ERP 정본)과 충돌하지 않는 이유는 **ERP가 보낸 P/O를 MES가 고치는 것이 아니라, ERP가 안 보낸 자리에 MES가 자기 것을 새로 만드는 것**이기 때문이다.

⚠ **이전 버전이 「데이터가 만들어질 수 없다」로 적은 것은 계약을 확인하지 않은 오류였다** — A-13이 경고한 실패 형태의 실례다.

### §5-3. 통제 우회 — 데이터에 근거가 없다

**✓확정 QA #9** — 「작업 통제 = 차단/경고/미적용 **3단계 정책 설정형** + **긴급 W/O 우회 허용**」

`workOrderTypeCode = EMERGENCY`(이미 계약에 확정된 값 — 공유계약 §I-6 계열)로 **서버가 판단**한다 — 유형이 긴급이면 점검 게이트를 건너뛴다. 별도 「통제 우회」 플래그는 두지 않는다 — 유형 축 하나로 충분하다(A-21, 값을 지어내지 않는다).

> ⚠ 다만 **점검 게이트 자체가 `P-02-01`·`P-02-02`이고 #67로 보류**됐다. **우회할 대상이 지금 없다** — 이 화면의 「통제 우회」는 실질적으로 무의미하다. §8-3.

### §5-4. 자재 부족 시 — 수동 출고 요청

02-S-D 태스크 ② — 「부족 시 **「추가 자재 출고 요청」 수동 + 사유**(대응 화면 = `W-02-10` **[추정]** · 도식 미작화)」

**정상 경로는 자동**(R29 「W/O 생성 완료 → 출고요청 자동 발행」)인데 **긴급은 수동**이다. `W-02-04` §5-5의 ④가 「긴급 W/O 제외」인 이유다.

화면은 **부족을 감지하면 `W-02-10`을 안내**한다. 다만 `W-02-10`은 신뢰도 **추정**이고 5차 대상이다.

## §9. 이 장에서 나온 공유 계약 후보

1. **「예외 경로」가 정규 체인의 `NOT NULL`에 걸리면 화면이 아니라 데이터가 답해야 한다** — 긴급·무발주 같은 우회 경로는 정규 참조를 채울 수 없다. 화면이 더미 데이터로 우회하면 정본이 오염된다 (§5-2)
2. **우회 규칙은 우회 대상이 있을 때만 의미가 있다** — 「긴급은 점검을 우회한다」가 점검 화면 부재 시 공허하다. 규칙의 전제를 스펙이 확인한다 (§5-3)
