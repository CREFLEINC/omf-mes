# P-02-08 · 포장 작업 (LOT 스캔·제품 포장)

> 작성일: 2026-08-04 · 서식: `00-화면스펙서식.md` v1.0 · 작성 주체: CREFLE OMF 팀 (UI/UX)
> 이 장에서 **포장 단위(Handling Unit)**와 **중첩 포장**을 다룬다. 제품입고의 단위가 여기서 정해진다.

## §0. 요약

- **개요**: POP(1024×768 터치+스캔)에서 포장 작업자가 LOT·인식표를 스캔해 포장 단위(Handling Unit)를 만들고 내용물을 담는 화면. 좌측 스캔+포장 대상 목록, 우측 포장 단위 정보+내용물 목록의 좌우 2단 레이아웃이다.
- **데이터**: 포장 단위(`inventory.handling_unit`)와 내용물(`inventory.handling_unit_content`)을 다루며, 포장 단위는 상위 포장(`parent_handling_unit_id`)으로 중첩 구조(팔레트→박스)를 가진다. 내용물은 품목·LOT+수량으로만 기록되며(개체 참조 컬럼 없음) 기록 전용이다.
- **핵심 액션**: LOT/인식표 스캔 → 포장 단위 유형·상위 포장 선택 → 내용물 담기(LOT+수량, 재스캔 시 수량 합산) → 혼적(여러 LOT) 시 경고 표시(차단 아님) → 포장 확정(한 트랜잭션으로 포장 단위+내용물 N행 생성, 이 포장 단위가 R73에 따라 제품입고 단위가 된다).

## §4. 필드

### §4-A. 포장 단위 `inventory.handling_unit`

| 라벨 | 출처 컬럼 | 타입 | 필수 | 검증·비고 | 입력 |
| --- | --- | --- | :-: | --- | --- |
| 포장번호 | `handling_unit_no` | `business_no_t` | ✅ UNIQUE | MES 채번 | 자동 |
| **유형** | `handling_unit_type_code` | `code_t` | ✅ | 박스·팔레트 등 ⚠ 값 목록 §8-1 | 선택 |
| **상위 포장** | `parent_handling_unit_id` | FK 자기참조 | — | ⚠ **중첩 포장** §5-3 | 선택 |
| 창고 · 위치 | `warehouse_id` · `location_id` | FK | — | 완료 후 이동 시 채워짐 | — |
| 상태 | `status_code` | `code_t` | ✅ | | 자동 |

```
ck_handling_unit_parent:  parent_handling_unit_id IS NULL
                          OR parent_handling_unit_id <> handling_unit_id
```

자기참조는 막히나 **A→B→A 순환은 막지 않는다** — 서버 책임(A-9 ⓐ).

### §4-B. 내용물 `inventory.handling_unit_content`

| 라벨 | 출처 컬럼 | 타입 | 필수 | 비고 |
| --- | --- | --- | :-: | --- |
| 품목 · LOT | `item_id` · `lot_id` | FK | ✅ **둘 다 NOT NULL** | **LOT 없는 내용물은 없다** §5-2 |
| 수량 | `qty` | `qty_t` > 0 | ✅ | |
| 단위 | `uom_id` | FK | ✅ | |

**기록 전용**(`created_*`만) — 담은 것을 수정하지 않는다. 다시 담으려면 포장을 해체한다(§6).

`uq_handling_unit_content` — 같은 포장에 같은 품목·LOT은 **한 행뿐**이다(수량 합산).

## §5. 액션·상태

### §5-1. 단말 게이팅

⚠ **포장에 해당하는 플래그가 8종에 없다.**

```
can_input_material · can_input_result · can_input_inspection · can_print_label
can_start_work · can_complete_work · can_cancel_input · can_return_material
```

포장은 자재 투입도 실적 입력도 아니다. **가장 가까운 것이 `can_input_result`**(포장이 마지막 공정의 실적이라는 R73 해석)이나 확실하지 않다 — §8-2.

화면은 **게이팅 없이 시작**하되 이 사실을 기록한다. F-1 매핑표에 「포장 = 미매핑」으로 남긴다.

### §5-2. 포장 단위는 LOT을 담는다 — 개체가 아니다

`handling_unit_content.lot_id`가 **`NOT NULL`**이고 개체(`serial_number`)를 가리키는 컬럼은 **없다.**

즉 **「제품 단위 포장」이라 해도 데이터는 LOT + 수량으로 담긴다.** 인식표(개체)는 포장 내용물로 기록되지 않는다.

> ⚠ 프로세스의 「제품 단위 포장 → **인식표 재출력**」(`P-02-09`)은 **포장 겉면에 붙일 것**을 말하는 것이지 내용물 기록이 아니다. §5-4.

### §5-3. 중첩 포장 — `parent_handling_unit_id`

박스를 팔레트에 얹는 구조가 데이터에 있다.

```
팔레트 HU-…0001
  └ 박스 HU-…0007   (parent = 0001)
       └ 내용물: LOT-…0031 × 100
```

**화면은 상위 포장을 선택할 수 있게 한다.** 다만 이 화면의 주 관심은 박스 만들기이고, 팔레트 적재는 물류 쪽(도메인 04)일 가능성이 높다 — §8-3.

### §5-4. 「LOT 수」 반복과 포장 단위 분기

프로세스는 **「포장작업 명시」(「LOT 수」 반복)**이라 한다 — 포장 대상 LOT을 반복해 처리한다는 뜻이다.

포장 후 **분기가 둘**이다.

| 분기 | 다음 | 재출력 대상 |
| --- | --- | --- |
| **LOT 단위 포장** | `P-02-09` | **LOT 라벨** 재출력 |
| **제품 단위 포장** | `P-02-09` | **인식표** 재출력 |

**이 화면은 분기를 만들지 않는다** — 포장 유형(`handling_unit_type_code`)과 내용물 구성이 그것을 함축한다. `P-02-09`가 무엇을 재출력할지 판단한다.

### §5-5. 혼적 — 한 포장에 여러 LOT

`handling_unit_content`가 여러 행일 수 있으므로 **한 포장에 여러 LOT이 들어간다.**

화면은 **혼적을 경고로 표시**한다(레이아웃의 ⚠). 막지는 않는다 — 추적은 `content` 행으로 남는다. 다만 나중에 「이 박스에 어느 LOT이 있나」를 물으면 답이 여럿이 된다.

### §5-6. 포장 확정의 결과

```
┌─ 한 트랜잭션 ────────────────────────────┐
│ ① handling_unit          포장 단위 생성   │
│ ② handling_unit_content  내용물 N행       │
└──────────────────────────────────────────┘
              ↓ 이 화면 밖
        P-02-09 라벨·인식표 재출력
```

**R73** — 「**제품입고 = 포장단위 단위**」. 이 포장 단위가 도메인 04(제품출하)의 입고 단위가 된다.

## §6. 예외

| 상황 | 처리 |
| --- | --- |
| 포장 유형 미선택 | 확정 **비활성** — `NOT NULL` |
| 내용물 0 | 확정 비활성 — 빈 포장은 만들지 않는다 |
| 스캔 수량 > LOT 잔여 | **인라인 오류** |
| 같은 LOT 재스캔 | **수량 합산** — `uq_handling_unit_content`가 한 행만 허용 |
| **혼적** | ⚠ 경고(차단 아님) — §5-5 |
| 미달 마감 LOT 포장 | ✅ 허용 — 실물이 있다(`P-02-07` §5-4와 같은 논리) |
| **포장 해체** | ⚠ **화면이 없다** — 내용물이 기록 전용이라 되돌리려면 별도 경로가 필요하다 §8-4 ⚠ 가장 가까운 것은 `M-04-03` 포장 재구성(`PUT …/contents`)이나 **수량 합 = 원 수량 합** 제약이 걸려 포장 밖으로 빼지 못한다 — 해체가 아니다 |
| 순환 중첩(A→B→A) | 서버가 막는다 — `ck_handling_unit_parent`는 자기참조만 막는다(A-9 ⓐ) |
| 오프라인 | 큐잉 — C-1~C-4 |

## §9. 이 장에서 나온 공유 계약 후보

1. **게이팅 플래그가 없는 액션은 「없음」을 기록한다** — 8플래그에 맞는 것이 없으면 임의로 가까운 것을 쓰지 않고 미매핑으로 남긴다. 잘못 매핑하면 엉뚱한 권한이 걸린다 (§5-1)
2. **담는 관계(`content`)가 기록 전용이면 「해체」 경로를 함께 설계한다** — 되돌릴 수 없는 담기는 현장에서 반드시 문제가 된다 (§6 · §8-4)
