# W-02-01 · P/O 수신·조회

> 작성일: 2026-08-05 · 서식: `00-화면스펙서식.md` v1.0 · 작성 주체: CREFLE OMF 팀 (UI/UX)
> 도메인 02의 입구. **테이블 전체가 ERP 수신본**이라 §I-2(Legacy 출처 플래그 부재 · #65)가 **여기서는 걸리지 않는다.**

## §0. 요약

- **개요**: 관리웹에서 생산관리자·전산(ERP 연계)담당이 ERP로부터 자동 수신된 P/O(생산오더)를 조회하는 화면. 목록(계층형 들여쓰기)+상세 3구획(기본·계획·전개) 레이아웃이며, **테이블 전체가 ERP 수신본**이라 화면 전체가 읽기 전용이다.
- **데이터**: `planning.production_order`(16열 — `erp_order_no`·`parent_production_order_id`·`bom_level` 포함)·`planning.production_plan`·`planning.bom`을 다루며, 상위-하위 P/O(반제품 오더) 계층이 목록에 들여쓰기로 표시된다.
- **핵심 액션**: 필터 조회 → P/O 선택 → 계층 펼침 → (미전개 P/O는) `W-02-02`로 이동해 W/O 전개. 편집·저장 액션은 없다.

## §5. 액션·상태

### §5-1. ★ §I-2가 여기서는 걸리지 않는다 — **테이블 전체가 수신본**이기 때문

**F-3(게이트는 판정 근거 컬럼의 실재를 확인해야 성립)** 이 「수신본이라 잠김」을 **⛔ 구현 불가**로 표시하고 있다(§I-2 · #65 — Legacy 출처 플래그가 마스터 5개에 없다).

**그런데 이 화면은 판정할 필요가 없다.**

| | 마스터(`W-06-05` 등) | **이 화면** |
| --- | --- | --- |
| 한 테이블에 | MES 원천 + ERP 수신분이 **섞인다** | **전부 ERP 수신본** |
| 잠금 판정 | ⛔ 행마다 판정해야 하는데 근거가 없다 | ✅ **테이블 단위로 잠근다** |

**R07이 「P/O = ERP 발행·MES 수신본(수정 불가)」로 예외 없이 못박았으므로 화면 전체를 읽기 전용으로 둔다.**

**G-3 적용** — 잠긴 이유가 「ERP 수신본」이므로 문구가 경로를 담는다:

```
ⓘ ERP 수신본입니다. 수정은 ERP에서 하고 재동기화하세요.  [연계 현황 → W-06-10]
```

> **⚠ 이것은 §I-2의 해소가 아니다.** 마스터 5개(`item`·`code_value`·`department`·`worker`·`bom`)는 여전히 섞이고 여전히 판정할 수 없다. **「테이블 전체가 수신본이면 F-3이 필요 없다」**는 것이 이 화면의 발견이다 — §9-1.

### §5-2. `erp_order_no`가 nullable이다 — MES가 만든 P/O가 있다는 뜻인가

```
erp_order_no  varchar(100)     ← nullable
```

R07은 **P/O를 ERP 발행으로만** 규정한다. 그런데 컬럼이 nullable이라 **ERP 번호 없는 P/O가 데이터상 가능**하다.

**후보 셋**:

| 후보 | 판단 |
| --- | --- |
| **① 긴급 W/O용 더미 P/O** | ⚠ **가능성 높다** — `W-02-07`이 P/O 없이 W/O를 못 만든다(§I-15 · #76). 더미 P/O를 만드는 우회가 있다면 여기가 그 자리다 |
| ② ERP 연계 전 임시 등록 | R07과 충돌 |
| ③ 단순 nullable 관성 | |

**화면은 `erp_order_no`가 비면 `(MES 생성)`으로 표기**하고 구분한다. ①이 사실이면 **`W-02-07`의 해법이 여기 있다** — §8-1에 남기고 `W-02-07` §5-2에서 이어받는다.

### §5-3. 반제품 오더 계층 — G-1 5번째 사용처, 이번엔 **조회**

```
parent_production_order_id  bigint REFERENCES planning.production_order   -- 자기참조
bom_level                   smallint NOT NULL DEFAULT 0 CHECK (>= 0)
ck_production_order_parent  CHECK (parent <> self)
```

주석이 용도를 명시한다(실측): 「**완제품 취소·수량 변경 시 연동 대상 식별**」.

**`bom_level`이 함께 있어 깊이를 안다** — G-1(계층 트리)의 「⚠ 선행 확인: 실제 계층이 2단 이내면 갭 불성립」에 대한 답이 여기 있다.

| | |
| --- | --- |
| 깊이 | **`bom_level`로 알 수 있다** — 데이터가 없어 실측은 못 하나 **BOM 전개 단계라 2단을 넘을 수 있다** |
| 이 화면의 조작 | **조회·전개만** — 편집 아님 |

→ **`Table`의 들여쓰기 표현으로 족하다**(`c`). G-1의 4곳이 전부 「선택」이었는데 **5번째도 편집이 아니다.**

### §5-4. 「자재예약정보」가 P/O에 없다

프로세스 태스크 1이 수신 항목으로 **「품목·수량·완료예정일·자재예약정보」**를 든다.

**앞의 셋은 실재**한다(`item_id`·`order_qty`·`due_date`). **자재예약정보는 `production_order`에 없다.**

`inventory.inventory_reservation`이 실재하고 `source_document_type_code`+`source_document_id`(A-10 다형)를 갖는다 — **P/O를 가리킬 수 있다.**

| 해석 | |
| --- | --- |
| **① 예약은 별도 테이블에 적재** *(권고)* | `inventory_reservation`이 P/O를 가리킨다. 화면은 **조인해서 보인다** |
| ② 수신 시점엔 안 받고 W/O 전개 후 생성 | 출고요청 자동 발행이 예약을 만든다는 해석 |

⚠ **어느 쪽인지 정해지지 않았다** — ①이면 이 화면에 예약 패널이 필요하고, ②면 없다. **패널을 두되 비어 있으면 감춘다**로 설계 → §8-2.

## §9. 이 장에서 나온 공유 계약 후보

1. **테이블 전체가 수신본이면 F-3(수신본 게이트)이 필요 없다** — §I-2의 「Legacy 출처 플래그 부재」는 **한 테이블에 MES 원천과 ERP 수신분이 섞이는 곳**에서만 문제다. `production_order`처럼 전량 수신본이면 **테이블 단위로 잠그면 된다.** F-3에 이 구분을 넣는다 (§5-1)
2. **읽기 전용 화면은 `version_no`가 있어도 B-1을 지지 않는다** — 편집하는 화면이 진다. A-4의 「`version_no`가 있으면 B-1을 반드시 구현한다」는 **엔티티 단위가 아니라 화면 단위**로 읽어야 한다 (§4-A)
3. **G-1 계층은 5곳이 됐는데 여전히 전부 「선택·조회」다** — 편집은 `W-06-07` 하나뿐. **승격 판단 시 조회용 들여쓰기와 편집용 트리를 나눈다** (§5-3)
