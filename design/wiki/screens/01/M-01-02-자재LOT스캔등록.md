# M-01-02 · 자재LOT 번호 스캔·등록 (발번)

## 요약

- **개요**: 모바일(스캐너 일체형 PDA) 전용 화면. 물류(창고)담당이 입하 시 자재LOT 번호를 스캔해 등록(발번)한다 — 공급사가 이미 부착한 번호를 수용하는 「사전부착」 경로와 MES가 직접 채번하는 「미부착」 경로 두 가지로 갈린다.
- **주요 데이터**: 자재 LOT(`trace.lot` — 34자리 LOT No·수량·품목·원천 P/O), 공급사 자체 번호(`lot_external_identifier`), Hold 사유(`lot_hold`) — 등록 즉시 Lot Status=Hold로 생성된다.
- **핵심 액션**: 스캔(포커스 고정 암묵 입력) · 직접 입력(대체 경로) · 건별 등록 · 등록 완료(일괄) · 목록 행 삭제(미동기 건 한정).

> 작성일: 2026-07-31 · 서식: `00-서식.md` v0.1 · 작성 주체: CREFLE OMF 팀 (UI/UX)

### §3-1. 이 화면이 다른 두 폼팩터와 다른 점

- **스캔이 주 입력**이다. 키보드·키패드가 아니라 **일체형 스캐너가 입력을 밀어 넣는다** → 포커스가 스캔 필드에서 벗어나면 입력이 유실된다. **포커스 고정이 기능 요구**다.
- **연속 작업**이다. 한 P/O에 LOT이 수십 건 → 스캔 1건마다 화면 전환 없이 목록에 쌓이고, 마지막에 한 번 완료한다.

### §4-1. ⚠ 34자리 규칙은 화면이 지킨다

`trace.lot.lot_no`는 `varchar(100)`이고 **자릿수·숫자 전용 제약이 DB에 없다.** 따라서 **입력 검증이 화면 책임**이다:

| 검사 | 문구 |
| --- | --- |
| 길이 ≠ 34 | 「자재 LOT 번호는 34자리입니다 (현재 N자리)」 |
| 숫자 외 문자 포함 | 「숫자만 입력할 수 있습니다」 |
| 5분절 파싱 | 제품코드9[1-9] / 수량9[10-18] / 날짜6 YYMMDD[19-24] / 공급사6[25-30] / 번호4[31-34] |
| 제품코드 ↔ P/O 품목 불일치 | 「이 P/O의 품목과 다른 LOT입니다」 |
| 날짜 유효성 | YYMMDD 파싱 실패 시 거부 |
| `UNIQUE(plant_id, lot_no)` | 「이미 등록된 LOT 번호입니다」 |

> **상세 채번 설계(도출·검증·유일성)는 별도 후속 과제**로 남아 있다(MLOT #16). 자릿수만 확정 입력값이다 → §8-2.

## §7. DS 매핑

### §7-1. ⚠ 예측 정정 — **스캔은 `d`가 아니라 `c`였다**

착수 전 「스캔 16건이 d 유형(새 원시 요소) 최대 후보」로 보았으나, **실측하니 아니다.**

**일체형 단말의 바코드 스캐너는 스캔값을 키보드 입력처럼 흘려보낸다**(omf-mes-client#442 확정 — 어댑터의 키보드 입력 구현체). 즉 스캔은 「특수 입력 장치」가 아니라 **포커스가 고정된 텍스트 입력**이다. `TextField` + 포커스 관리 + 자동 제출로 구현된다.

| 구성 요소 | 판정 |
| --- | --- |
| 스캔 입력 = `TextField`(포커스 고정·자동 제출·입력 후 클리어) | **c** |
| 진행·자릿수 표시 = `Progress` 또는 텍스트 | a |
| 등록 목록 = `Table`(compact) 또는 `Card` 목록 | a |
| 오류 피드백 = `AlertBanner` + 오류음 | a |
| 스캐너 연결 상태 = `Chip` | a |

→ **`c`(조합) — 제품이 소유하고 DS 이슈를 내지 않는다.** 다만 스캔 화면이 16건이라 **제품 내부 공용 컴포넌트**(`ScanField`)로 묶을 가치는 크다. 이건 DS 승격 대상이 아니라 `omf-mes-client` 내부 정리다.

### §7-2. 모바일 터치 타겟 — G-5 파급 범위 정정

POP은 터치 규격이 명시돼 DS 최대치(48px)에 미달했으나, **모바일은 터치 규격이 별도로 주어지지 않았다.** Android 표준 권장(48dp)을 따른다면 **DS `lg`=48px로 충족**된다.

→ **G-5(터치 타겟 갭)의 사용처를 「POP·모바일 41건」에서 「POP 22건」으로 정정**한다. 모바일은 규격 확정 후 재판정 — §8-4.

## §9. 이 장에서 나온 공유 계약 후보

1. **스캔 입력 규약** — 포커스 고정·자동 제출·입력 후 클리어·오류 시 필드 유지·오류음. **스캔 16건 공통** (§5-2·§6)
2. **직접 입력 대체 경로 의무** — 스캐너 실패는 현장에서 흔하다. 모든 스캔 화면에 수동 입력을 둔다 (§5-2)
3. **오프라인 유일성 판정 규약** — 로컬은 큐 내 중복만 선검사, 서버 거부 건만 되돌린다. **전체 롤백 금지** (§5-3)
4. **연속 스캔 작업의 완료 모델** — 건별 저장 + 마지막 일괄 완료 (§3-1)
