# M-01-07 · 임시 위치 적재

> 작성일: 2026-08-05 · 서식: `00-서식.md` v1.0 · 작성 주체: CREFLE OMF 팀 (UI/UX)
> 01-S-D 예외 사이드. **확정 태스크에 「적치 사유 입력」이 있는데 사유를 담을 코드 컬럼이 없다.**

## §0. 요약

- **개요**: 모바일(360×720dp · 스캐너 일체형 PDA) 스캔형 화면. 정위치가 포화(01-S-D 예외 사이드)일 때 물류(창고)담당이 임시 위치에 적치를 기록한다(확정). 모바일 스캔 퍼스트 홈 > 적치 타일 3번째에서 「(포화)」 조건부로 진입하며, 정위치 이동은 이 화면 밖(`M-01-10`)이다.
- **주요 데이터**: `logistics.putaway_task`(적치 지시의 임시 건 — 실제 위치·상태를 갱신) · `mdm.location`(`location_type_code` — 임시 Location). ⛔ 적치 사유를 담을 코드 컬럼이 없어 `remarks` text에 임시로 기록한다.
- **핵심 액션**: 임시 위치 스캔(또는 목록에서 선택) → 적치 사유 선택(값 목록 미확정 — 비활성 표시) → 임시 적치 등록(위치 확정 AND (사유 선택 또는 비고 입력) 시 활성).

## §5. 액션·상태

### §5-1. ⛔ 「적치 사유」를 담을 곳이 `remarks` text 하나뿐이다

**확정 태스크 3번이 「적치 사유 입력」이고 노트 D가 그것을 기록 항목으로 명시**하는데, `putaway_task` 20열 어디에도 사유 코드가 없다(실측).

```
putaway_task:  … priority_no, assigned_worker_id, status_code,
               completed_at, inventory_transaction_line_id,
               remarks text,  ← 여기밖에 없다
               created_at …
```

**비교** — 같은 성격의 다른 테이블은 사유 코드를 갖고 있다:

| 테이블 | 사유 컬럼 |
| --- | --- |
| `logistics.goods_receipt` | `reason_code app.code_t` ✅ |
| `logistics.goods_issue` | `reason_code app.code_t` ✅ |
| `inventory.inventory_count_line` | `variance_reason_code` ✅ |
| `logistics.shopfloor_receipt_line` | `variance_reason_code` ✅ |
| **`logistics.putaway_task`** | ⛔ **없음** |

**A-11 적용 — 물러난 수준을 명시한다.**

| 확정 | 물러난 수준 |
| --- | --- |
| 사유를 **코드로** 기록(노트 D의 기록 항목) | **자유 텍스트 `remarks`에 기록** |
| 사유별 집계·분석 | ⛔ **불가** — 「포화가 몇 번 있었나」를 셀 수 없다 |

**화면은 라디오로 사유를 고르게 하되**(값 목록 미정이라 G-2 비활성 표시) **저장은 `remarks`에 코드 문자열을 넣는 것으로 시작**하고, 컬럼이 생기면 옮긴다.

→ **§I 신규 후보** §9-1.

### §5-2. 「적치 완료(임시)」가 상태값으로 필요하다

노트 D의 상태는 **「적치 완료(임시)」**다. 정상 적치의 「적치 완료」와 **구분되어야 한다** — 구분되지 않으면 정위치 이동이 남은 건을 찾을 수 없다.

```
status_code = 적치완료      → 끝난 것
status_code = 적치완료(임시) → M-01-10 이 처리할 대기 물량
```

**`status_code`는 `code_t` 맨몸**이라 값 집합이 데이터에 없다(#64 계열). 화면은 이 값이 있다고 가정하고 만든다 — **없으면 임시 적치가 정상 적치와 섞여** 01-S-D의 복귀 경로가 끊긴다.

⚠ **이것이 이 화면의 존재 근거에 가장 가까운 미결**이나, **화면 골격은 값과 무관**하다(라디오·스캔·목록 구성이 같다) → 등급은 **조정**.

### §5-3. 「임시 Location」은 [가설]이다

프로세스 태그가 **`[가설]`(263:5804)** 로 명시돼 있다. 임시 위치를 `mdm.location`의 한 행으로 두는 것 자체가 아직 확정이 아니다.

**모델은 받아 줄 수 있다** — `location_type_code`가 있고 `parent_location_id` 자기참조도 있다. **값 하나(예: `TEMP`)면 성립**한다.

| 안 | 표현 |
| :-: | --- |
| **① `location_type_code = 임시`** *(권고)* | 기존 구조로 성립 · 마스터에 등록해 두고 씀 |
| ② 바닥 적치를 위치 없이 | ⛔ `location_id NOT NULL`이라 불가 |
| ③ 창고 단위 임시 구역 | ①의 하위 형태 |

**①로 설계**하고 값 목록(#145)에 포함되도록 §8에 남긴다.

### §5-4. 복귀 경로가 다른 화면이다

```
M-01-07  임시 적치 등록 ──→ (시간 경과) ──→ M-01-10  정위치 이동
```

01-S-D의 복귀는 **「[정위치 이동] → 01-S-G」** 다. 이 화면은 **닫히지 않는다** — 임시 상태를 만들고 끝난다.

⚠ **누가 언제 정위치로 옮기라고 알려 주나.** 프로세스에 알림·대시보드가 없고, 「미적치 예외조회(FR-IM-089)」가 `putaway_task` 주석에 언급되나 **그 화면이 인벤토리 108건에 없다.**

→ **§8-3.** `P-02-10`에서 「세션 종료 화면이 없다」를 남긴 것과 같은 종류다.

## §9. 이 장에서 나온 공유 계약 후보

1. **⛔ 확정이 「사유를 기록한다」인데 사유 코드 컬럼이 없다** — `putaway_task`만 없고 `goods_receipt`·`goods_issue`·`inventory_count_line`·`shopfloor_receipt_line`은 갖고 있다. **A-11에 따라 물러난 수준(자유 텍스트)을 명시**하고, 집계가 불가하다는 사실을 함께 적는다 (§5-1)
2. **예외 경로가 만든 상태는 정상 상태와 구분되는 값을 가져야 한다** — 「적치 완료(임시)」가 「적치 완료」와 같은 값이면 예외의 복귀 경로가 사라진다. **예외 사이드가 만드는 상태값을 스펙이 요구 목록에 넣는다** (§5-2)
3. **닫히지 않는 화면은 「누가 이어받는가」를 스펙이 명시한다** — 임시 적치는 정위치 이동이 남는데 촉구할 화면이 없다. B-9(선행 의존)의 **뒷면** — 후행 의존도 적는다 (§5-4)
