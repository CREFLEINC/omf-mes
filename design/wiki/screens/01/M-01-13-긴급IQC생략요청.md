## §0. 요약

- **개요**: 모바일(PDA) 화면. 생산(현장)담당·물류담당이 입하돼 수입검사(IQC) 대기 중인 LOT에 대해 긴급 생략을 요청한다. 요청을 **만들기만** 하며, 승인·한도승인은 관리웹 화면(`W-01-02`)에서 권한자(MES 권한 보유 관리자)가 따로 처리한다.
- **주요 데이터**: 승인 요청(`app.approval_request`) — 공통 승인 워크플로우 테이블을 그대로 쓴다(신설 0). `target_type_code`=`INBOUND_LOT`·`approval_type_code`=`IQC_SKIP` 고정, `reason`(사유)이 **NOT NULL**이라 요청자가 반드시 적어야 한다.
- **핵심 액션**: LOT 스캔 → 사유 입력 → 요청 전송(대상 LOT·사유 둘 다 있어야 활성). 수량·한도 입력은 없고(한도는 승인자가 정한다), 취소·회수·수정 액션도 없다 — 잘못 올렸으면 다시 올린다.

## §3. ⭐⭐ 이 화면이 **왜 반드시 있어야 하는가**

**「있으면 편하다」가 아니다. 데이터가 요구한다.**

```
app.approval_request.reason        text NOT NULL      (2486)   ← 사유 없이 행이 안 선다
app.approval_request.requested_by  NOT NULL FK        (2483)   ← 요청자를 적어야 한다
app.approval_step.approver_id      NOT NULL                    ← 승인자는 따로다
```

⛔ **승인 화면(`W-01-02`)에서 대신 적을 수 없다.** 대신 적으면 **`requested_by` 가 승인자가 되어** ✓확정 §재정의 #8 의 3단계(요청 → 승인 → 한도승인)가 **2단계로 무너진다.**

⭐ **`W-01-02` 스펙이 이미 그렇게 적어 뒀다** — §4 필드 표의 `reason` 행 입력 열이 **「입력(요청 화면)」**이다. **그 화면을 전제하고 쓰였는데 없었다.**

### §3-1. ⭐ 신설이 **0** 이다

`app.approval_request` 는 **공통 승인 워크플로우**(§J)가 이미 쓰는 테이블이고, `W-CO-09`(결재함)·`W-06-15`(결재선 정의)가 서 있다. **이 화면은 그 위에 요청 하나를 올릴 뿐**이다.

| 무엇 | |
| --- | :-: |
| 테이블 신설 | ⛔ **0** |
| 컬럼 신설 | ⛔ **0** |
| 계약 신설 | ⚠ **1** — `POST /trace/lots/{lotId}:request-iqc-skip`(01 계약 · 2026-08-29) §7-2 |

## §9. 이 장에서 나온 공유 계약 후보

### 9-1. ⭐⭐ **`NOT NULL` 이 화면의 존재를 요구할 수 있다**

지금까지 「데이터가 없어 화면을 못 만든다」는 여러 번 있었다. **이번은 반대다 — 데이터가 있어서 화면이 있어야 한다.**

| 신호 | 뜻 |
| --- | --- |
| `reason` **NOT NULL** | **사람이 적는 자리**가 있다 |
| `requested_by` ≠ `approver_id` | **두 사람**이 관여한다 |
| 둘을 곱하면 | ⭐ **화면이 둘이어야 한다** |

⚠ **승인 화면만 만들고 요청 화면을 빠뜨리면** `requested_by` 가 승인자로 채워지고 **절차가 조용히 2단계로 줄어든다.** 데이터는 통과한다 — **아무도 못 잡는다.**

⭐ **점검법 — 「이 `NOT NULL` 을 누가 채우나」를 사람으로 답해 본다.** 답이 **승인자**면 요청 화면이 빠진 것이다.

— `M-01-13` §3 · `W-01-02` §4·§5-3 · `omf-mes#73`

### 9-2. ⭐ **「긴급」이 붙은 화면은 오프라인에서 그 사실을 말한다**

**C-7**(저장 피드백 두 등급)의 **긴급 판**이다.

⛔ **「긴급 요청」이 큐에 담긴 것을 「요청됨」으로 보이면 안 된다** — 사람이 **기다리면 된다**고 오해하고, 실제로는 **아무에게도 안 갔다.**

```
⏳ 요청 대기 1건 — 연결되면 전송됩니다
   ⚠ 급하면 유선으로 함께 알리세요
```

⭐ **계약이 못 하는 것을 화면이 말한다** — 큐는 언제 나갈지 모른다.

— `M-01-13` §6-1 · C-7 · C-15

### 9-3. **요청 화면은 「한도」를 받지 않는다**

⭐ **승인이 「한도승인」이면 한도는 승인자가 정한다.** 요청자가 적으면 **승인이 「예/아니오」로 줄어든다.**

⚠ **요청 화면을 만들 때 「무엇까지 요청자가 정하나」를 먼저 가른다.**

— `M-01-13` §5-A · `W-01-02`
