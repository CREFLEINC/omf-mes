# P-01-02 · 출고 QR 발행

## §0. 요약

- **개요**: POP 키오스크에서 물류(창고)담당이 출고 단위(라인 또는 파렛트) QR을 발행·재발행하는 화면이다. 「보관 단위(LOT 라벨)」와 「이동 단위(출고 QR)」가 다른 것임을 데이터가 아직 구분하지 못하는 사례이며, LOT 라벨은 `P-01-01`이 담당한다.
- **주요 데이터**: 발행 기록(`app.document_issue_log`), 출고 라인(`logistics.goods_issue`·`goods_issue_line`), 이동 단위 후보(`inventory.handling_unit`), 단말 게이팅(`mdm.terminal_process.can_print_label`).
- **핵심 액션**: 출고 라인 선택 → 유형(라인 단위/파렛트 단위) 선택 → **발행·인쇄**(대상 선택 + `can_print_label` + (회차 1 또는 재발행 사유 선택) 필요). 전량 출고에도 예외 없이 항상 발행 대상이 생기며 체크박스로 끌 수 없다.

> 작성일: 2026-08-05 · 서식: `00-서식.md` v1.0 · 작성 주체: CREFLE OMF 팀 (UI/UX)
> **「보관 단위 QR」과 「이동 단위 QR」이 다른 것**임을 데이터가 구분하지 못한다.

## §5. 액션·상태

### §5-1. ⚠ 「보관 단위」와 「이동 단위」를 데이터가 구분하지 못한다

REQ-OA-0010이 **분리를 요구**한다: 「출고 QR = **보관 단위(LOT 라벨) vs 이동 단위 분리** · **명칭/디자인 구분**」.

`document_issue_log`는 **`document_type_code`(`code_t` 맨몸)** 로 둘을 가른다. 값 집합이 데이터에 없다(**`#145`** 가 소유한다 — `#64` 는 2026-08-25 닫혔고 값 목록 2건 `document_type_code`·`reissue_reason_code` 는 `#145` 본문이 명시적으로 인수했다).

| 발행 | `document_type_code` 필요 값 | 발행 화면 |
| --- | --- | --- |
| 자재 LOT 라벨 | `MLOT_LABEL` 류 | `P-01-01` |
| **출고 QR** | **`ISSUE_QR` 류** | **이 화면** |
| 생산 LOT 라벨 | `PLOT_LABEL` 류 | `P-02-07` |
| 인식표 | `ID_TAG` 류 | `P-02-05` |
| 포장 라벨 | — | `P-02-09` |

**5화면이 같은 테이블을 쓰고 값 하나로만 갈린다.** 값이 정해지지 않으면 **발행 이력 조회가 전부 섞인다** — 화면은 만들되 값은 G-2로 표시한다.

### §5-2. A-10 — 「이동 단위」가 무엇을 가리키는가

```
target_type_code   app.code_t NOT NULL
target_id          bigint NOT NULL     ← FK 없음
```

**후보 셋**:

| 후보 | 근거 | 문제 |
| --- | --- | --- |
| **`inventory.handling_unit`** *(권고)* | 「파렛트=이동 그룹핑」(✓확정 QA #16 · S8 규칙) · `handling_unit_content`가 LOT 다건을 담는다 | ⚠ 출고 시 HU를 만드는 주체가 미정 |
| `logistics.goods_issue_line` | 라인 단위 발행이면 자연스럽다 | ⚠ **파렛트 단위를 못 담는다** |
| `logistics.goods_issue` | 전표 전체 | ⚠ **너무 크다** — 부분 인계가 안 된다 |

**A-10 보완 조항 적용 — 화면이 여러 유형을 다루면 대상마다 판정한다.**

| 발행 유형 | `target_type_code` | `target_id` | `lot_id` |
| --- | --- | --- | --- |
| **라인 단위** | `GOODS_ISSUE_LINE` 류 | 라인 PK | ✅ 그 라인의 LOT |
| **파렛트 단위** | `HANDLING_UNIT` 류 | HU PK | ⛔ **NULL** — 여러 LOT이라 못 담는다 |

⚠ **`lot_id`가 nullable이라 파렛트 단위가 성립한다.** 다만 **LOT으로 발행 이력을 되짚는 조회가 파렛트 건을 놓친다** — `handling_unit_content`를 한 번 더 타야 한다. §8-2.

### §5-3. 「전량 출고도 발행」은 기본값이 아니라 **구조로** 표현한다

REQ-OA-0010과 QA #16이 **「전량 출고에도 예외 없이 항상 발행」**을 확정했다.

**G-4 그대로다** — 확정이 「끌 수 없다」일 때 화면이 on/off 기본값으로 구현하면 확정이 무너진다.

| 잘못된 표현 | 옳은 표현 |
| --- | --- |
| `[✓] QR 발행` 체크박스(기본 켬) | **체크박스 없음** — 출고 확정 시 발행 대상이 항상 생긴다 |

**G-5 적용** — 사용자가 「전량인데 왜 찍나」를 물으면 근거가 보여야 한다:

```
전량 출고에도 QR을 발행합니다 (2026-07 확정 QA #16 · REQ-OA-0010)
```

### §5-4. ⚠ F-1 게이팅이 걸리지 않는다 — 창고 POP

> *(기존 서술 폐기 — v0.1 §5-4의 「기본값이 `false`라 명시적 허용이 없으면 막힌다」·「이 화면이
> **5번째 실증**이다」 및 「⚠ 창고 스테이션 POP이 `terminal_process`에 등록돼 있어야 한다 …
> 창고 작업에 대응하는 「공정」이 있는가가 미정이다」. 이 장은 2026-08-05에 쓰였고, 공유계약 F-1의
> **적용 범위 정정은 2026-08-06(v0.9)**이다 — 이 장이 하루 앞서 쓰여 정정을 반영하지 못했다.
> omf-mes#245)*

`mdm.terminal_process`는 (단말 × **공정**) 매핑이고 `mdm.process`는 **생산 공정 마스터**다.
확대 6차가 전수 실측했다(공유계약 F-1 · `W-CO-06` §5-1) — `mdm.process` 참조 14곳에 **창고 작업
(입하·적치·피킹·이동·재고조사) 0건**, `terminal_id` 컬럼 7곳에 **`logistics` 0 · `inventory` 0**.

**창고 전용 단말은 이 표에서 공정 행 0건으로 남는 것이 정상이다.** 조회 경로를 새로 만들어도 0건이
돌아온다 — **읽을 경로가 없는 것이 아니라 읽을 행이 없다.** 공유계약 F-3(게이트는 판정 근거의
실재를 확인해야 성립한다)이 여기서 미충족이므로 게이트를 세우지 않는다.

**⛔ 그러면 아무나 찍는가 — 아니다. 게이트는 서버가 갖는다.**

```
POST /app/document-issues  →  403 「이 단말에 출력 권한이 없다」
```

공유계약 **F-5**(게이트를 만드는 화면과 집행하는 화면을 나눈다)의 배치다. 근거 화면은 `W-CO-06`,
집행은 서버, 이 화면은 **둘 다 아니다.** 그래서 **F-6 위반이 아니다** — F-6은 게이트를 소유한
화면이 판정에 실패했을 때의 조항인데, 이 화면은 판정하지 않는다.

### §5-5. K-4 — 인쇄는 트랜잭션 밖

```
① document_issue_log INSERT   (issue_seq 채번 · UNIQUE 로 경합 차단)  ─┐ 트랜잭션
                                                                        ┘
② 렌더링 요청 → 프린터 전송                                    트랜잭션 밖
```

**프린터가 죽어도 발행 기록은 남는다.** 인쇄 실패로 회차를 롤백하면 같은 대상에 회차를 다시 매겨야 하고, 그사이 다른 단말이 가져갈 수 있다.

**프린터 상태를 헤더에 상시 표시**한다(K-4 규칙).

⚠ **인쇄 실패 후 다시 찍으면 회차가 또 오른다.** K-2가 사유를 요구하므로 **「인쇄 실패」 값이 사유 목록에 있어야 한다** — `P-02-09`가 「정상 업무 흐름」을 요구한 것과 같은 종류다. §8-4.

## §9. 이 장에서 나온 공유 계약 후보

1. **한 테이블을 여러 화면이 쓰는 코드 축은 값 목록이 「그 화면 하나의 미결」이 아니다** — `document_type_code` 하나에 발행 화면 **5건**이 걸린다. **미결의 파급 화면 수를 스펙이 함께 적는다** — 우선순위가 달라진다 (§5-1)
2. **A-10 다형 참조 7번째 · 대상이 「한 건」과 「묶음」으로 갈릴 때 `lot_id`가 비는 것을 계약이 인정한다** — 파렛트 단위 발행은 LOT이 여럿이라 `lot_id`를 못 채운다. **되짚는 조회가 한 단계 더 필요하다는 사실을 스펙이 명시**한다 (§5-2)
3. **K-2 재발행 사유 목록에 「인쇄 실패」가 필요하다** — 「정상 업무 흐름」(`P-02-09`)에 이은 두 번째 누락. **재발행 사유는 「왜 다시 찍나」가 아니라 「무엇이 회차를 올렸나」를 담아야** 통계가 선다 (§5-5)
