# W-03-05 · 검사실적·검사결과 조회 (불량률·불량코드 분포 집계 포함)

## §0. 요약

- **개요**: 관리웹에서 품질담당·관리자가 검사 의뢰-결과-측정치 **3계층을 통합 조회**하고 불량률·불량코드 분포 **집계 뷰 2종**을 보는 화면. 도식 앵커가 없는 **추정** 신뢰도 화면이며, 구 `W-03-08`(품질 대시보드) 집계분을 흡수해 범위가 확대됐다(v1.3).
- **주요 데이터**: `quality.inspection_request`(검사 의뢰) · `inspection_result`(결과·회차·재검) · `inspection_measurement`(측정치) · `defect_record`(불량 실적). 필터는 **기간(필수)**·검사유형·품목·공정·판정.
- **핵심 액션**: 기간 필수 입력 후 조회(요약 카드는 필터 전체 기준) → 목록/불량률 추이/불량코드 분포 보기 전환 → 검사 선택 시 드로어에서 측정치 항목별 요약 확인(측정치 전체는 별도 페이지) → 교정 만료 장비 측정 건이 있으면 분리해 보기. 검사 결과 수정 없음(조회 전용), 정렬은 지정된 열만, 자동 갱신 없음.

## §5. 액션·상태

### §5-1. 3계층은 **페이지네이션 축이 다르다**

결정 01의 3계층은 건수가 층마다 자릿수가 다르다:

```
의뢰      412건
결과      ~450건   (재검 포함)
측정치    ~135,000건   (검사당 항목 10 × 샘플 30)
```

**L-1(요약은 필터 전체·목록은 페이지)을 층마다 따로 적용한다**:

| 층 | 화면 | 페이지 |
| --- | --- | --- |
| 의뢰 + 결과 | **목록**(합쳐서 한 행 + 재검을 들여쓰기) | ✅ 50건 |
| **측정치** | ⛔ **목록에 내리지 않는다** — 드로어에서 **항목별 요약** | 전체 보기는 **별도 페이지** |

⚠ **측정치를 목록에 join하면 412행이 135,000행이 된다.** 3계층을 「통합 조회」라 부르는 것이 위험한 지점이다 — **한 화면에 세 층이 있는 것이지 한 표에 있는 것이 아니다.**

→ **§L 신규 조항 후보** §9-1.

### §5-2. ✅ 결정 09의 「뷰 레벨 원천 필터」 — **`sourceCode` 축을 신설해 되살렸다**(2026-08-30)

결정 09가 불량 중복 집계 방지 **4원칙**을 세웠고 넷째가 **「뷰 레벨 원천 필터」**다. S6 태스크 1이 **원천 축을 명시**했다:

```
현장 / PQC / OQC / 수리 / 클레임        ← 5축
```

2단 조인·NOT NULL 제약으로 유도하던 방식을 버리고 **`defect_record.sourceCode`를 명시 축으로 신설**한다(값 5종 그대로) — 조인·제약 우회가 필요 없어진다.

⚠ **`work_order_id`는 NULL을 허용해야 한다** — 클레임 원천은 W/O가 없다. 지금 `NOT NULL`인 것은 원칙 위반(모델 제약으로 화면을 제약)이었다 — 데이터 모델 담당에게 통지한다, 기다리지 않는다.

⚠ **수리는 M-02-02(수리 왕복 투입·반출)가 아직 화면으로 서지 않아 지금은 0건이다** — 축은 있고 데이터가 아직 안 채워진다. M-02-02가 서면 자동으로 채워진다(별건 — 레이아웃 필요).

QA #15가 「클레임 반품 입고 = 불량창고 반품입고 통일 + **입고 원천 구분**(내부 판정 vs 외부 클레임) 속성」을 확정했다 — `sourceCode = CLAIM`이 그 속성이다. `work_order_id`가 NULL을 허용하면 계보 없이도 등록된다.

**→ 이 화면은 5축 전부를 가른다**(수리는 M-02-02 착수 전까지 0건).

**되살렸다(2026-08-30)** — 축은 확정대로 온전히 그린다. `sourceCode`·`work_order_id` NULL 허용은 데이터 모델 담당에게 통지한다(A-11) — 기다리지 않는다.

### §5-3. 재검을 어떻게 세나 — **결정 09 ①「판정 이벤트 1회」**

```
IR-…0412  1회차   30 / 28 / 2   불합격
          2회차   30 / 30 / 0   합격     ← previous_result_id = 1회차
```

**같은 30개를 두 번 셌다.** 그대로 더하면 검사 수량이 60이 되고 불량률이 반토막 난다.

**결정 09 ①이 「판정 이벤트 1회 + 원천 축」이라 했다.** 재검은 **판정 이벤트가 하나**다.

| 규칙 | |
| --- | --- |
| **검사 건수·수량** | **최종 회차만** 센다 — `previous_result_id`로 이어진 사슬의 끝 |
| **불량 실적**(`defect_record`) | **B-10 적용** — 재검은 **정정이 아니라 재검**이므로 1회차 불량 2건은 **그대로 남는다** |
| 화면 표시 | **사슬을 들여쓰기로 보인다**(§3) — 숨기면 「왜 합격인데 불량이 있나」가 된다 |

⚠ **「검사 불량률」과 「불량 실적 건수」가 다른 수가 된다.** 이것을 오류로 보지 않도록 **둘의 정의를 화면에 적는다**:

```
불량률       최종 회차 기준 (재검 합격분은 합격으로 센다)
불량 실적    발생한 대로 (재검으로 합격해도 1회차 불량은 남는다)
```

### §5-4. 불량률의 **분모가 무엇인가**

인벤토리가 「불량률 집계 뷰」를 요건으로 못박았는데 **분모를 정하지 않았다.**

| 분모 | 뜻 | 데이터 |
| --- | --- | :-: |
| **검사 수량**(`inspected_qty`) | 「검사한 것 중 몇 %가 불량인가」 | ✅ 이 화면 안에 있다 |
| **생산 수량** | 「만든 것 중 몇 %가 불량인가」 | ⚠ `production_result` — **다른 도메인** |

**검사 수량으로 시작한다** — 이 화면의 데이터로 닫힌다. **화면이 분모를 명시한다**(§3).

⚠ **QA #13의 3원(양품/불량/**손실**)이 여기서 갈린다.** 손실(퍼징·시작불량)은 `production.material_loss`에 있고 **불량이 아니다.** 「수율에서 손실 분리」가 확정이므로 **이 화면은 손실을 세지 않는다.** 생산 수량 기준 수율은 **`W-02-08`(생산 실적 집계) 소관**이다.

→ 두 화면이 **다른 수를 보이는 것이 정상**이고, 그 이유를 양쪽에 적는다.

### §5-5. 공정별 분포는 **중복 계상될 수 있다** — §I-10

결정 12가 「공정—불량코드 **N:M** 매핑 채택」을 승인했는데(2026-07-06) **물리 모델은 조정 전 형태**다:

```
quality.defect_code
    process_id  bigint REFERENCES mdm.process     ← N:1
```

**결정서가 피해까지 명시했다** — 「**동일 불량이 공정 수만큼 복제 등록**」.

**집계에 그대로 나타난다**:

```
스크래치(사출)   142건
스크래치(조립)    38건      ← 같은 현상인데 코드가 둘
```

**분포를 대분류로 묶으면 가려지지만**(`parent_defect_code_id`), **공정별로 나누는 순간 드러난다.**

**규칙**: 공정별 보기에 **경고를 상시 붙인다**(§3). 숨기지 않는다 — **분포를 보고 개선 대상을 정하는 화면**이라 왜곡이 곧바로 잘못된 판단이 된다.

⚠ **`defect_record`는 `occurrence_process_id`·`detection_process_id`를 따로 갖는다**(둘 다 NOT NULL). **공정별 분포를 낼 때 어느 쪽으로 묶는지 화면이 밝힌다** — 발생 공정으로 묶어야 개선 대상이 나온다.

### §5-6. ⭐ 교정 만료 장비의 측정치를 **분리할 수 있다**

WF03 **예외 E-9 ①**: 「검교정 만료 계측기로 검사 → **결과 소급 무효화 여부 [확인]**」 — 정책이 **미정**이다.

**⛔ 그렇다고 섞어서 보이면 안 된다.** §L-8(판정 불가 ≠ 정상).

**판별에 필요한 것이 전부 있다**:

```
inspection_measurement.inspection_equipment_id  →  mdm.equipment
                                                      calibration_due_date
                                                      calibration_required
inspection_measurement.measured_at              ←  이 시점에 유효했나
quality.equipment_calibration                   ←  교정 이력(유효기간)
```

**화면이 하는 일**:

| | |
| --- | --- |
| 요약 | ⚠ **「검교정 만료 장비로 측정된 8건이 포함돼 있습니다」** + **[ 분리해 보기 ]** |
| 측정치 상세 | ⚠ 항목 옆에 **「캘리퍼 CAL-03 교정 만료 07-28」** |
| ⛔ 하지 않는 것 | **자동 제외·무효 처리** — 정책이 미정이다(A-9 ⓒ 표시만) |

**`W-01-07` §5-5(유효기간 경과는 표시만)와 같은 형태다** — 정책이 없으면 **보이되 자동으로 처분하지 않는다.**

→ **§L 신규 조항 후보** §9-3.

## §9. 이 장에서 나온 공유 계약 후보

1. **3계층 조회는 「한 화면」이지 「한 표」가 아니다 — 층마다 페이지네이션 축을 따로 둔다** — 의뢰 412 / 결과 450 / 측정치 **135,000**으로 자릿수가 다르다. 측정치를 목록에 join하면 표가 터진다. **L-1을 층마다 적용**하고, 가장 깊은 층은 **요약만 드로어에 · 전체는 별도 페이지**로 낸다 (§5-1)
2. ⚠ **이 교훈은 폐기됐다(2026-08-30)** — 「컬럼이 없어서 못 센다」는 원칙 위반이었다. 결정 09의 5축은 `sourceCode` 명시 축 신설로 전부 되살렸다 — 수리만 M-02-02 착수 전까지 0건(별건) (§5-2)
3. **정책이 미정인 「의심스러운 데이터」는 섞지도 지우지도 않는다 — 표시하고 분리 보기를 준다** — 교정 만료 장비 측정치는 무효화 여부가 [확인]인데, 섞으면 잘못된 집계이고 빼면 없는 정책을 만드는 것이다. **경고 + 분리해 보기**가 정답이다. `W-01-07`의 유효기간(표시만)과 같은 형태이며 **L-8의 집계 화면 판**이다 (§5-6)
4. **같은 낱말을 쓰는 두 화면이 다른 수를 보이면 양쪽에 정의를 적는다** — 이 화면의 「불량률」은 **검사 수량 기준**이고 `W-02-08`의 수율은 **생산 수량 기준에 손실 분리**(QA #13)다. **다른 수가 나오는 것이 정상**인데, 적어 두지 않으면 「어느 쪽이 맞나」로 시간을 쓴다 (§5-4)
