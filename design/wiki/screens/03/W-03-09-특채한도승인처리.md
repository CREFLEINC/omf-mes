# W-03-09 · 특채·한도승인 승인 처리

## §0. 요약

- **개요**: 관리웹에서 MES 권한 보유 관리자(품질책임자 등)가 특채·한도승인 요청을 검토해 조건부로 승인·반려하는 화면. 3분할 레이아웃(왼쪽 요청 목록 · 가운데 대상·조건 상세 · 오른쪽 승인 진행)이다.
- **주요 데이터**: 승인 요청(`app.approval_request`), 특채 조건(`quality.concession` — 20컬럼, 부적합 선행 강제), 부적합(`quality.nonconformance`), 결과 상태(`inventory.inventory_balance.quality_status_code`). 한도승인은 전용 테이블 없이 `approval_request` 하나로 성립한다(범위를 한정할 축이 없기 때문).
- **핵심 액션**: 요청 선택 → 대상·조건 확인(특채는 수량·기간·W/O·공정·고객 5축, 한도승인은 범위 축 자체를 감춤) → 사유 입력 후 승인 또는 반려(내 차례여야 활성, 조건 자체는 이 화면에서 고치지 않고 반려로 되돌린다).

> ⭐ **보류가 풀린 첫 화면이다.** 2026-08-07 에 회신 E-3(판정유형 값 목록)이 종결되고 J-3(승인자 유형)이 확정되며 **차단 2건이 동시에 사라졌다.**
>
> ⭐⭐ **그리고 화면의 성격이 바뀌었다.** 보류 중에는 「상태 값 화면」으로 보였다 — 한도승인·특채가 Lot Status 값 후보였기 때문이다. **값에서 빠지면서 이 화면이 무엇인지가 오히려 분명해졌다: 조건 승인 화면이다.**

### §4-C. 조건 — 한도승인

| --- | --- |

| `concession` 전용 테이블 | `approval_request` 만 |

### §5-2. ⭐ 결재는 순차다 — **내 차례가 아니면 못 누른다**

`app-공통.json` 승인 실행 계약이 **`400 NOT_YOUR_TURN`** 으로 강제한다. 화면은 그 전에 `isMyTurn` 으로 비활성한다.

**1차 범위 셋이 그대로 걸린다**(§J) — 승인자는 **`USER` 만** · **값 구간 미사용** · **대리·위임 없음**(승인자 부재 시 결재가 멈추는 것을 감수한다 · A-11 로 화면이 명시).

### §5-3. ⚠ 「비었다」가 「제한 없음」이다 — 화면이 그것을 말해야 한다

허용 3축이 nullable 이라 **빈칸이 가장 넓은 허용**이다. 승인자가 「아직 안 정했다」로 읽으면 **의도보다 넓게 승인**한다.

**규칙**: 빈 축을 **「제한 없음」으로 명시 표기**한다. 회색 빈칸으로 두지 않는다(G-9 — 모르는 값 ≠ 없는 값의 역방향).

```
허용 W/O    WO-SAMPLE-3
허용 공정    5공정
허용 고객    제한 없음        ← 빈칸이 아니라 이렇게
```

### §5-4. ⛔ 조건은 이 화면에서 고치지 않는다

승인자가 「100개 말고 50개만」으로 **깎고 싶을 수 있다.** 두지 않는다.

| 왜 | |
| --- | --- |
| **J-10** 결재 ≠ 판정 | 결재는 **예/아니오**다. 값을 바꾸는 것은 판정이고 그건 요청자 몫이다 |
| **감사** | 결정 10 이 「승인 행위 자체가 감사 대상」이라 했다. **요청된 조건과 승인된 조건이 달라지면 무엇을 승인했는지가 흐려진다** |
| **되돌림** | 반려하고 다시 올리면 된다. 회차가 남는다 |

**반려 사유에 「수량 조정 요망」을 쓰게 한다.**

### §5-5. ⭐ 승인이 나면 무엇이 바뀌나 — **상태는 `정상`이 된다**

```
검사 불합격  →  LOT 상태 = 불량
                    ↓  특채 승인
             승인 수량만큼 → LOT 상태 = 정상
                              + concession 이 범위를 건다
```

⚠ **상태만 바뀌는 것이 아니다** — `concession` 행이 살아 있어야 출고 시점에 범위 검사가 걸린다(`allowed_*`·`valid_to`·`approved − consumed > 0`). **A-14**(상태와 조건의 분리)가 여기서 실제로 작동한다.

⛔ **부분 전이다** — 500 중 100 만 `정상`이 되므로 재고 행이 **둘로 갈린다**. `quality_status_code` 가 유니크 차원이라 이것이 자연히 표현된다(§I-46).

> ⭐ **보류 사유 2건이 오늘 둘 다 사라졌다** — 회신 E-3(값 목록·**상태 수 유동**)은 **종결**됐고, #72 의 J-3 충돌은 **`USER` 만 연다**로 확정돼 `app-공통.json` 이 정본을 담았다.

## §9. 공유 계약 후보

1. **「비었다」가 「제한 없음」인 필드는 그것을 명시한다** — nullable 이 「미정」이 아니라 「무제한」을 뜻하면 빈칸으로 두면 안 된다. G-9(모르는 값 ≠ 없는 값)의 **역방향**이다 (§5-3)
2. **결재 화면은 조건을 고치지 않는다** — J-10 보강. 값을 바꾸면 「무엇을 승인했는가」가 흐려진다. 반려 사유로 돌려보낸다 (§5-4)
3. **유형마다 있는 축이 다르면 구획을 감춘다** — 비활성이 아니라 **미표시**다. 한도승인에는 범위 축이 **없어야 정상**이라 비활성으로 두면 「곧 생긴다」로 읽힌다 (§3 · G-13 보강)
