# W-06-06 · 공통코드·조직·작업자 마스터 (다국어)

> 작성일: 2026-08-03 · 서식: `00-화면스펙서식.md` v1.0 · 작성 주체: CREFLE OMF 팀 (UI/UX)
> 나머지 마스터가 참조하는 **공통코드 값의 원천**이고, 동시에 **ERP 수신본 편집 규칙의 원형**이다. `W-06-07`은 MES 정본 마스터라 이 축을 만나지 않았다(`공유계약.md` B-4 ⚠).

## §0. 요약

- **개요**: 관리웹에서 전산담당·운영자(표준화 TFT)가 공통코드·조직(부서)·작업자·거래처 역할을 관리하는 탭 4개짜리 마스터 화면. 공통코드는 MES 정본이라 전면 편집 가능하지만, 조직·작업자 기본정보·거래처 기본정보는 ERP 수신본이라 읽기 전용이고 MES 확장 속성(작업자 자격·인증, 거래처 역할)만 편집한다.
- **주요 데이터**: 공통코드(`mdm.code_group`·`mdm.code_value`) · 부서(`mdm.department`, ERP 수신) · 작업자 기본정보(`mdm.worker`, ERP 수신·읽기 전용) + 자격·인증(`mdm.worker_qualification`, MES 확장·편집) · 거래처(`mdm.partner`, ERP 수신·읽기 전용) + 거래처 역할(`mdm.partner_role`, MES 확장·편집).
- **핵심 액션**: 코드그룹/코드값 추가·저장·정렬 재배치, 자격 추가/삭제(부여·회수 — 즉시 반영), 거래처 역할 편집·저장(집합 통째 교체 `PUT /mdm/partners/{partnerId}/roles`), 사용 중지, 변경 이력 조회, 수신 동기화 상태 보기(`W-06-10`으로 이동).

**⚠ 자격 만료는 다른 화면을 통제한다.** SQL 512~513 주석: 「공정 수행 자격(FR-WO-009/022), **검사자 자격**(FR-QM-014, **NFR-QM-008 자격 만료 시 확정 제한**)」. 즉 이 표의 `valid_to`가 지나면 `W-01-01`·`W-04-03` 등의 **판정 확정 버튼이 막힌다** → §9-3.

**인증자 입력 규칙** — 자격을 인정한 사용자 계정의 AppUser.appUserId. 선택 입력이며 null 허용. 실제 입력자 createdBy는 서버 인증 주체의 감사정보로 별개다. 자격 대상 작업자의 계정 연결은 요구하지 않는다. 외부 인증기관 식별자·사원번호를 넣지 않으며 알 수 없으면 비운다. 기존 맨 정수를 다른 식별자로 자동 변환하지 않는다. 신규 인증자는 GET /app/users?includeInactive=false에서 선택하며 isActive=true인 유효 계정만 지정한다. 전체 치환 시 기존 자격의 비활성 인증자 참조를 그대로 보존할 수 있지만 새로 지정한 잘못된 ID 또는 비활성 계정은 400으로 거부한다. certifiedBy 선택으로 권한을 얻지 않으며 실제 인증 주체의 자격 편집 권한을 검증한다. 기존 비활성 인증자가 신규 선택 목록에 없어도 그 참조를 임의로 지우지 않는다. 작업자↔계정 연결 편집 소관(§8-3)은 별도 미결이다.

W-06-06의 인증자 선택에도 기존 조회를 사용한다. 권한 범위를 넓히지 않으며 조회 403·실패이면 새 인증자 선택만 불가로 안내한다. W-06-06 전체 진입을 차단하지 않고 기존 참조 보존·선택 입력 빈값을 유지한다. 자격 저장 권한은 기존 자격 PUT에서 별도로 검증한다.

## §9. 이 장에서 나온 공유 계약 후보

1. **ERP 수신본 편집 게이트 — B-4에 축을 하나 더 세운다.**
   `공유계약.md` B-4가 예고한 「ERP 정본 ↔ MES 정본」 축이 이 화면에서 실물로 나왔다. **규칙**: ① 수신본 필드는 **비활성 + 사유 상시 표시**(감추지 않는다) ② **MES 확장 속성만 편집** ③ 「참조 건수 0일 때만 코드 수정」(B-4)은 **MES 정본에만** 적용 — 수신본은 참조 건수와 무관하게 항상 읽기 전용 ④ 재동기화 경로를 화면이 안내하되 **실행은 `W-06-10`이 소유**(중복 구현 금지). ⚠ **수신 대상은 5종**(품목·BOM·조직·작업자·P/O, WF06 S7) — **공통코드는 2026-08-22 확정으로 제외**됐다(B-4-3).
2. **선택 목록의 유효성 판정 규약** — 유효기간(`effective_from`/`to`)과 `is_active`가 **함께 있는 코드**를 선택 목록에 넣을지 판정하는 규칙. 전 화면의 모든 `Select`가 여기 걸린다. **권고**: 판정은 **서버**가 하고 화면은 받은 목록을 그대로 그린다(화면마다 다르게 구현되는 것을 막는다). **과거 데이터 표시는 예외** — 이미 저장된 값은 만료·비활성이어도 그대로 보이고 「(사용 중지됨)」 표식을 붙인다.
3. **자격 만료가 다른 화면의 확정 버튼을 막는다.**
   `worker_qualification.valid_to`가 **검사 확정의 선행조건**이다(SQL 513 주석 — NFR-QM-008). 공유계약 **B-2**(입력/확정 2단계 분리)의 「확정」 버튼 활성 조건에 **자격 유효성**을 넣어야 한다. 판정·승인 13건 공통.
4. ~~정본이 외부인데 등록은 내부에서 일어나는 마스터의 처리 규약.~~ ✅ **공통코드는 해소** — MES가 정본이라 「임시 코드 vs 정식 수신본」을 구분할 필요 자체가 없어졌다(구분 컬럼도 필요 없다). ⚠ **다만 이 형태가 다른 마스터에서 또 나오면 이 규약은 여전히 필요하다** — 지금은 품목·BOM·조직·작업자·P/O 다섯 모두 ERP 정본으로 남아 해당 사례가 없다(공유계약 B-4-3).
