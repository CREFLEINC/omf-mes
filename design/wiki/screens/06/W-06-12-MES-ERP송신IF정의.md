# W-06-12 · MES→ERP 송신 I/F 정의 (항목 on/off)

> 작성일: 2026-08-03 · 서식: `00-서식.md` v1.0 · 작성 주체: CREFLE OMF 팀 (UI/UX)
> I/F 3장의 둘째. **송신 스펙이 확정 문서에서 가장 촘촘하게 정해진 화면**인데(QA #1·#4·#6·#35 넷이 걸린다), **저장할 곳이 없다**(§8-1).

## §0. 요약

- **개요**: 관리웹 화면. 전산담당이 MES→ERP 송신 항목(생산 실적·G/R·출하(PGI)·반품·실사조정)을 항목별로 on/off 설정하는 설정·마스터 유형 화면이다. 확정 스펙 넷(QA #1·#4·#6·#35)이 걸려 근거는 촘촘하지만, 담을 테이블이 물리 모델에 없어 신설 요청으로 다룬다(§3).
- **주요 데이터**: 송신 항목 5종 중 생산 실적은 끌 수 없고(개발품 제외) 검사 결과는 목록 자체에 없다(§3-1) — 「필수」·「비연계」는 토글이 아니다. 「개발품 제외」의 판정 축은 **품목**으로 확정됐으나(`Item.developmentItem`, §4-B) 아직 컬럼이 없어 서버는 전건 송신으로 물러나 있다.
- **핵심 액션**: 항목별 on/off 토글(잠긴 항목 제외) → 명시적 저장 + 끄기 확인 다이얼로그, 송신 현황 보기(`W-06-10`으로 이동만), 변경 이력 조회. 2026-08-18 계약 체결(`/integration/outbound-item-settings`)로 「데이터 모델링은 설계 결정을 앞설 수 없다」가 실증됐다(§8-1).

## §3. 이 화면이 정하는 것 — 확정 스펙의 표로 옮김

### §3-1. 송신 항목 5종 (WF06 S7 Rule 원문 그대로)

| 송신 항목 | on/off | 확정 조건 | 근거 |
| --- | :-: | --- | --- |
| **생산 실적** | ⛔ **끌 수 없다(필수)** | **개발품은 제외** | QA #35 · QA #4 |
| **G/R**(입고) | ✅ 선택 | **IQC 합격 직후 건별** — 배치 아님 | QA #1 |
| **출하(PGI)** | ✅ 선택 | | REQ-PR-0030 |
| **반품** | ✅ 선택 | | QA #6 |
| **실사조정** | ✅ 선택 | | QA #6 |
| ~~검사 결과~~ | ⛔ **비연계** | **항목 자체가 없다** — 목록에 두지 않는다 | QA #4 |

**⚠ 「필수」와 「비연계」는 토글이 아니다.** 생산 실적은 **끄는 조작 자체를 제공하지 않고**(비활성 + 사유), 검사 결과는 **목록에 나타나지 않는다**. 둘을 「기본값이 켜짐/꺼짐」으로 구현하면 확정이 무너진다 → §9-1.

### §3-2. `app.operation_policy`로 대신할 수 있나

`app.operation_policy`(SQL 2541~)는 「**소스 수정 없이 설정**」 파라미터를 `policy_code` + 범위(사업부·공장·품목·공정) + `value_boolean`으로 담는 범용 테이블이다. 형태상 on/off를 넣을 수는 있다.

**그러나 두 가지가 걸린다.**

1. **관리 화면이 없다** — `W-06-05` §8-6에서 이미 확인했다(인벤토리 108건에 `operation_policy` 화면 없음).
2. **범위 축이 맞지 않는다** — `operation_policy`의 범위는 **사업부·공장·품목·공정**인데, 송신 on/off의 범위는 **I/F 정의 단위**다. `policy_code`에 문자열로 욱여넣으면 **유일 인덱스(`COALESCE(...,0)` 4축 + `effective_from`)가 의미를 잃는다.**

**→ 전용 테이블이 필요하다**(§8-1).

### §3-3. 「부속 항목」이 무엇인지 불명

인벤토리 근거란의 「**부속 항목**」이 무엇을 가리키는지 WF06·도식스펙 원문에서 확인되지 않았다. 송신 건에 딸리는 상세 필드(예: 실적 송신 시 불량 내역 포함 여부)로 **추정**되나 근거가 없다 `[추정]` — **검증: 도식스펙06 §2.4 B13·B14 원문 확인 또는 리더 확인** → §8-4.

### §4-B. ⚠ 「개발품 제외」를 판정할 수 없다

QA #35가 「생산 실적 송신 **필수 — 개발품 제외**」로 확정했다. 이 화면은 그 규칙을 **설정**할 뿐이고, 실행 시 판정은 **`mdm.item`의 개발품 여부**를 봐야 한다.

**그런데 `mdm.item`에 개발품 플래그가 없다**(`W-06-05` §4-B 실측 — 인벤토리가 `W-06-05` 근거로 든 「개발품 플래그(실적 송신 제외)」가 물리 모델 미착지). **W/O 유형에는 개발품이 있다**(결정 14 「W/O 유형(양산/긴급/**개발품**)」 — 개념모델 v2.0)나, **송신 제외의 기준이 품목인지 W/O인지 확정 문구가 갈린다**:

| 근거 | 기준 |
| --- | --- |
| QA #35 · WF06 S7 | 「**개발품** 제외」 — 주어 불명 |
| 인벤토리 `W-06-05` 근거란 | 「**개발품 플래그**(실적 송신 제외)」 — **품목** 속성으로 읽음 |
| 결정 14 · 개념모델 v2.0 | 「W/O **유형**(양산/긴급/개발품)」 — **W/O** 속성 |

**→ §8-2.** 어느 쪽이든 **화면이 판정 근거를 갖지 못하는 것은 같다**(품목 플래그 없음 · W/O 유형 컬럼은 대조).

> ⭐ **확정 2026-08-24 (사용자 · `omf-mes#70`) — 「개발품 구분은 «품목»이다.」**
>
> 위 표의 갈림이 닫혔다. **판정 축은 품목**이고, 실행 시 서버는 **품목의 개발품 여부**를 보고 제외한다. 계약에 자리를 앉혔다 — `Item.developmentItem`(참/거짓) · 편집은 `ItemUpdate` 를 통해 `W-06-05` 가 한다.
>
> ⛔ **값을 셋 이상으로 늘리지 않았다** — 확정 문구가 가르는 것은 「개발품인가 아닌가」 하나뿐이고, 늘릴 근거가 어느 문서에도 없다(공유계약 `A-14` — 있는 것으로 답이 나면 값을 늘리지 않는다).
>
> ⚠ **작업지시 유형의 「개발품」을 지우지 않았다** — 이번 확정이 정한 것은 「**ERP 송신 제외를 무엇으로 판정하는가**」이지 「작업지시 유형에서 개발품을 뺀다」가 아니다. 다만 계약의 현재 `workOrderTypeCode` 설명이 이미 「NORMAL 기본 · 긴급·재작업」이라 개발품이 없어(실측) 이번 확정과 어긋나지 않는다.
>
> 📨 **아직 컬럼이 없다 — 작업 통지이지 회신 대기가 아니다.** `mdm.item` 에 담을 컬럼 신설을 데이터 모델 담당에게 통지했다. **그때까지는 서버가 이 값을 늘 거짓으로 내리고 이 화면은 §8-2 대로 전건 송신으로 물러나 있다**(`A-11`). 축이 정해졌으므로 **컬럼이 서는 즉시 판정이 살아난다** — 화면·계약을 다시 고치지 않는다.

## §5. 액션·상태

### §5-1. 액션

| 액션 | 활성 조건 |
| --- | --- |
| 항목별 on/off 토글 | 편집 권한 · **잠긴 항목 제외** — 생산 실적은 조작 자체를 열지 않는다 |
| 저장 / 취소 | 변경분 존재 — ⚠ **토글이 곧바로 반영되지 않는다**(§9-2) |
| 끄기 확인 | 끄려는 항목이 있을 때 — 결과를 문장으로 보인다(§6) |
| 송신 현황 보기 | 항상 — ⛔ **이 화면이 실행하지 않는다**. `W-06-10` 으로 이동만 한다 |
| 변경 이력 | 항상 — `audit.audit_event`(B-5) · 기간 필수 |

⛔ **「생산 실적 토글」은 액션이 아니다** — 끌 수 없는 것은 선택지가 아니라 결정 사항이다(§9-1). 비활성 컨트롤 + 사유로 그린다.

⭐ **v0.2 에서 액션 표를 신설했다.** 초안은 「on/off 테이블이 없어 API 를 정의할 수 없다」는 판단으로 골격 표 한 칸에 액션을 뭉쳐 적었다. **그 판단의 근거가 2026-08-18 사용자 확정으로 뒤집혔다** — 데이터 모델링은 설계 결정을 앞설 수 없다. → §8-1

### §5-2. 상태·잠금·게이트

| 항목 | 내용 |
| --- | --- |
| **비활성 컨트롤** | **생산 실적 토글** — 끌 수 없다. 비활성 + 사유(「생산 실적 송신은 필수입니다(QA #35)」) |

**⚠ 토글의 즉시성**: 송신 on/off는 **운영에 즉시 영향**한다(끄면 ERP에 실적이 안 간다). 부여·회수 형태(즉시 반영)가 아니라 **명시적 저장 + 확인 다이얼로그**로 둔다 → §9-2.

## §9. 이 장에서 나온 공유 계약 후보

1. **「필수」·「비연계」는 기본값이 아니라 구조로 표현한다.**
   확정이 「끌 수 없다」(생산 실적)·「연계하지 않는다」(검사 결과)일 때, 화면이 이를 **기본값 on/off로 구현하면 확정이 무너진다** — 누군가 끄거나 켤 수 있기 때문이다. 규약: **「필수」는 비활성 컨트롤 + 확정 번호를 담은 사유** · **「비연계」는 목록에서 제외**(끈 상태로 보이지 않게). F-1·G-2가 세운 「감추지 않는다」의 **예외**이며, 예외인 이유는 **선택지가 아니라 결정 사항**이기 때문이다.
2. **운영에 즉시 영향하는 설정은 부여·회수(즉시 반영)로 두지 않는다.**
   `W-CO-02`·`W-06-03`의 매핑 토글은 즉시 반영이 자연스러웠지만, 송신 on/off는 **끄는 순간 ERP 전표가 끊긴다.** 규약: **영향 범위가 화면 밖(외부 시스템·현장 작업)으로 나가는 설정은 명시적 저장 + 결과를 문장으로 보이는 확인**을 거친다. 판정 기준은 「되돌리면 원상 복구되는가」 — 매핑은 되고, 미송신 기간은 안 된다.
3. **확정 번호를 사용자 문구에 넣는다.**
   「생산 실적 송신은 필수입니다」보다 「**생산 실적 송신은 필수입니다(2026-07-04 확정 QA #35)**」가 낫다. 현장·고객이 「왜 못 바꾸나」를 물을 때 **추적 가능한 근거**가 화면에 있어야 재확인 요청이 정상 경로로 간다. 대상: 필수·비연계·차단처럼 **사용자가 바꿀 수 없는 것 전부**.
