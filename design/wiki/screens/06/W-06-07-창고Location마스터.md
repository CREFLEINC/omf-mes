# W-06-07 · 창고·Location 마스터

> 작성일: 2026-07-31 · 서식: `00-서식.md` v0.1 · 작성 주체: CREFLE OMF 팀 (UI/UX)
> 유형 「설정·마스터」(19건) 대표 · 폼팩터 관리웹. 이 장의 목적은 화면 확정이 아니라 **서식 검증과 공유 계약 도출**이다.

## §0. 요약

- **개요**: 관리웹에서 물류담당·전산담당이 창고와 Location(창고 내 보관 위치)을 마스터로 등록·관리하는 화면. 좌우 2단 마스터-디테일 구조로, 좌측 창고 목록에서 창고를 고르면 우측이 그 창고의 상세와 Location 계층 목록으로 바뀐다. Location 코드 라벨 이미지 생성까지 이 화면이 담당하며, 물리 인쇄는 개발 범위 밖이다.
- **주요 데이터**: 창고(`mdm.warehouse` — 공장·사업부·창고코드/명·창고유형·관리수준·외부창고 여부·거래처·불량창고 여부·사용여부)와 Location(`mdm.location` — 상위 위치 자기참조 계층·위치코드/명·위치유형·품질구역·보관조건·품목/LOT 혼적 허용·수용량+단위).
- **핵심 액션**: 창고 추가 → 저장/취소, 사용 중지(물리 삭제 없음), Location 추가/하위 추가, 라벨 이미지 생성(1건 이상 선택 시 다중 선택 일괄 · 서버 렌더링), 변경 이력 조회.

### §5-2. 화면 상태

`초기(창고 미선택 — EmptyState)` → `조회` → `편집(변경 있음)` → `저장 중(버튼 비활성·Skeleton 아님)` → `저장 성공(Toast)` / `검증 실패(필드 인라인 + AlertBanner)` / `충돌(§5-3)`

### §5-3. 낙관적 잠금 충돌

`version_no`가 있으므로 **다른 사용자가 먼저 저장한 경우**를 반드시 처리한다. 저장 실패 시 「다른 사용자가 이 창고를 먼저 수정했습니다. 최신 내용을 불러온 뒤 다시 저장해 주세요.」 + [최신 불러오기] 제공. **덮어쓰기 강제는 제공하지 않는다.**

> ⚠ 이 처리는 `version_no`를 가진 **모든 마스터 화면에 동일**하게 적용돼야 한다 → **공유 계약 후보**.

### §7-2. ⚠ 갭 — 계층(트리) 표시

**`mdm.location`은 `parent_location_id` 자기참조 계층인데 DS에 트리 컴포넌트가 없다.** `Table`의 `groupBy`·`renderGroupHeader`는 **1단 그룹 헤더**만 제공하므로 다단 계층을 표현하지 못한다. 어떤 prop으로도 안 되므로 **b가 아니라 d(새 원시 요소)** 다.

**「세 곳 규칙」 충족 여부 — 이미 충족할 가능성이 높다.** 물리 모델 실측으로 자기참조 계층이 최소 3곳:

| 테이블 | 컬럼 | 대응 화면(추정) |
| --- | --- | --- |
| `mdm.location` | `parent_location_id` | **`W-06-07`** (이 화면) |
| `mdm.department` | `parent_department_id` | `W-06-06` 공통코드·조직·작업자 마스터 |
| `mdm.production_line` | `parent_line_id` (LINE / WORK_AREA) | 라인·작업구역 마스터 «귀속 확인 필요» |

여기에 `W-06-03` 불량코드 **2계층** 마스터도 후보다.

**처리 방침**: 전 화면 매핑을 마친 뒤 사용처를 확정해 **DS 이슈(d → 승격)** 로 낸다. 그전까지는 `ds-candidates/`에 제품 로컬 구현. **단, Location 계층이 실제로 2단 이내면 `Table`+`groupBy`로 충분하므로 갭이 아니다 → §8-5 선행 확인 필요.**

`ds-gap.md`에 등재 완료.

| 6 | 참조 중인 창고·Location의 사용 중지 규칙 — 재고 보유 중 비활성화 허용 여부 | 규칙 | 결정 필요 |

## §9. 이 장에서 나온 공유 계약 후보

파일럿의 목적 ②. 전 프로그램 공통으로 정해야 할 것들:

1. **낙관적 잠금 충돌 처리** — `version_no`를 가진 모든 화면 공통 (§5-3)
2. **유일 제약 검사 시점** — blur 선검사 + 저장 시 서버 재검증 (§6)
3. **조건부 필수·짝 제약의 오류 표시 규칙** — CHECK 제약을 사용자 문구로 옮기는 방식 (§4)
4. **마스터 공통 규칙** — 물리 삭제 금지(`is_active`) · 코드 필드 수정 정책 · 변경 이력 (§5-1·§8-4·§8-7)
5. **감사 컬럼·`version_no`는 화면에 노출하지 않는다** (§4 머리)
