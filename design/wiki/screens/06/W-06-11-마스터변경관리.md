# W-06-11 · 마스터 변경관리 (신규 Rev 발행)

> 작성일: 2026-08-03 · 서식: `00-화면스펙서식.md` v1.0 · 작성 주체: CREFLE OMF 팀 (UI/UX)
> **자기 테이블이 없는 첫 화면.** 앞의 4장은 저장할 테이블이 분명했는데 이 화면은 그렇지 않다. §8-1에서 **소관 경계를 정면으로 다룬다.**

## §0. 요약

- **개요**: 관리웹 화면. 생산관리자·품질담당·전산담당(+운영자)이 마스터(Routing/BOM)의 변경 이력과 Rev 현황을 조회하는 화면이다. 자기 테이블이 없다 — 조회 전용이며, 「신규 Rev 발행」 실행은 각 마스터 화면(`W-06-01`·`W-06-05`)으로 넘긴다(§8-1 확정).
- **주요 데이터**: `audit.audit_event`(변경 이력 횡단 조회, 파티션 키 `occurred_at`)와 `planning.routing`·`planning.bom`의 상태·버전 합성 뷰(Rev 현황)다. 전용 테이블은 없다(§2 데이터 면).
- **핵심 액션**: 변경 이력 조회(기간 필수)·행 펼침(before/after 비교)·내보내기·Rev 현황에서 마스터 화면 이동·ERP 정본 행 재동기화 안내. 편집 폼은 없다(§5-2).

## §3. 레이아웃 (관리웹 — 구조 기술)

**「무엇이 바뀌었나」와 「무엇을 바꿀 수 있나」 두 축**이다. 조회가 주고 실행은 각 마스터 화면으로 넘긴다(§8-1).

> ⚠ **Rev 현황은 품목을 고른 뒤에 그린다** — 개정 목록 조회가 품목을 필수로 받는다. 상태 필터는 서버가 거르지 않으므로 받은 목록을 화면이 거른다. 두 목록 응답 모두 페이지네이션이 없고 계약이 스스로 「품목당 소수라 페이지네이션을 두지 않는다」고 적어 두었으므로 잘릴 위험이 구조적으로 없다.

- **이 화면은 편집 폼을 갖지 않는다.** 「신규 Rev 발행」 버튼조차 **`W-06-01`로 이동**시킨다 — 같은 행위를 두 화면이 각자 구현하면 규칙이 갈린다(§8-1).
- **`[⛔ERP]` 행이 이 화면의 존재 이유 중 하나**다. WF06 S8 Exception ①이 「잔존 연계분을 현장에서 수정 시도 → 차단(**의도된 동작**)」이고 「우회로(엑셀·별도 메모)가 존재한다」를 문제로 든다. **차단 사실과 정규 경로를 한곳에서 보여 주는 자리**가 있어야 우회가 줄어든다.

### §5-2. 화면 상태

`초기(조회 전 — EmptyState)` → `조회 중(Skeleton)` → `결과 있음` / `결과 없음(EmptyState)` / `조회 실패(AlertBanner)`

**편집 상태가 없다.** 저장·충돌(B-1)·낙관적 잠금 모두 해당 없음.

### §5-3. ⚠ 이력의 불변성

`audit.audit_event`에는 `updated_at`·`version_no`가 없고 파티션 테이블이다 — **쌓기만 하는 구조**(B-3 이력 불변). 화면은 **어떤 편집 수단도 제공하지 않는다.** 삭제·정정 버튼을 두지 않는 것이 규칙이다.

### §7-2. ⚠ 신규 갭 후보 — 변경 전/후 비교 표시(diff)

`before_value` / `after_value`가 **jsonb**다. 두 객체를 나란히 놓고 **바뀐 키만 강조**하는 표시가 필요하다.

- **조합 시도**: `Table` 2개를 좌우로 놓고 값이 다른 행에 `--semantic-warning-container` 배경 → **성립한다.** 키 정렬·누락 키 처리(한쪽에만 있는 키)는 제품 로직.
- **판정: `c`(조합)** — 새 원시 요소가 아니다. `Dialog`+`Table`(G-3 변경 이력 뷰어)의 **심화형**이며 같은 항목으로 본다.
- 다만 **전 마스터가 같은 diff 표시를 쓴다**(§9-2) — 제품 내부 공용 컴포넌트 1순위. `ds-gap.md` **G-3에 사용처 추가**.

## §9. 이 장에서 나온 공유 계약 후보

1. **조회 전용 화면의 「할 수 없음」 표시도 해결 경로를 담는다.**
   `W-06-01` §9-1이 편집 화면에서 세운 규칙인데, 이 화면은 **실행을 남에게 넘기는 것이 기본 동작**이라 더 강하게 적용된다. `[⛔ERP]` 행은 「불가」가 아니라 **「ERP에서 개정 → 재동기화(`W-06-10`)」**를 보여야 한다. WF06 S8이 우려한 **엑셀 우회**를 줄이는 것이 이 표시의 목적이다.
2. **변경 전/후 비교(diff) 표시 규약 — 전 마스터 공통.**
   ① 바뀐 키만 강조 ② 한쪽에만 있는 키는 **추가/삭제로 표시** ③ 모르는 키도 **원문 그대로 보인다**(파싱 실패로 감추지 않는다) ④ 값이 코드면 **코드+표시명 병기**. 마스터 화면 전부의 「변경 이력」 버튼이 같은 컴포넌트를 쓴다.
3. **감사 기록은 어떤 화면도 편집·삭제 수단을 제공하지 않는다.**
   B-3(이력 불변)이 「이전 회차·이전 실적」을 대상으로 말한 것을 **감사 이벤트까지** 확장한다. `audit.audit_event`에 `updated_at`·`version_no`가 없는 것이 그 의도의 증거다(실측).
4. **파티션 테이블 조회는 기간 조건을 필수로 한다.**
   `audit.audit_event`는 `occurred_at` RANGE 파티션이다. 기간 없는 조회는 전 파티션 스캔이 되므로 **화면이 기간을 강제**한다. 앞으로 나올 로그성 조회 화면(`W-06-10` 연계 로그 등)에 같은 규칙을 적용한다.
