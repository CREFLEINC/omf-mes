# W-06-05 · 수신본 확장속성 편집 (품목·BOM)

> 작성일: 2026-08-03 · 서식: `00-화면스펙서식.md` v1.0 · 작성 주체: CREFLE OMF 팀 (UI/UX)
> **ERP 수신본 편집 게이트의 본진.** `W-06-06`이 게이트 규칙을 세웠다면 이 화면은 **확장 속성이 실제로 무엇인지**를 정한다. 화면명 자체가 「수신본 **확장속성** 편집」이다.

## §0. 요약

- **개요**: 관리웹에서 전산담당·생산관리자가 ERP 연계 수신본(품목·BOM)의 **MES 확장 속성만 편집**하는 화면. 「원본 / 확장」의 세로 분할이 뼈대다 — ERP 원본 구획은 읽기 전용, MES 확장 구획만 저장 버튼을 가진다.
- **주요 데이터**: 품목 ERP 원본(`mdm.item` 읽기 전용) + MES 확장 속성(LOT 관리 여부(boolean)·시리얼 관리유형·유효기한 관리+일수·선출 정책·개봉 후 사용가능시간·입고검사 필수·마이너스 재고 허용·보관조건) + 부속(단위환산·외부코드) + BOM 헤더(`planning.bom` ERP 원본, 읽기 전용) · BOM 구성품(`planning.bom_component` — ERP 열과 MES 확장 열 4개가 한 행에 섞임) + 대체 자재.
- **핵심 액션**: 확장 속성 저장/취소, 부속 행(단위환산·외부코드) 추가/삭제, BOM 구성품 확장 열 편집, 변경 이력 조회. **품목 추가는 없다**(ERP 정본 수신본) — BOM Rev 발행도 이 화면이 아니라 `W-06-11` 소관이다.

## §5. 액션·상태

### §5-1. 액션

| 액션 | 위치 | 활성 조건 | 비고 |
| --- | --- | --- | --- |
| 저장 / 취소 | 확장 속성 폼 | 변경 있음 + 검증 통과 | **원본 구획에는 저장 버튼이 없다** |
| 부속 행 추가 / 삭제 | 단위환산·외부코드 | 항상 / 행 선택됨 | 부여·회수 — 즉시 반영 |
| 구성품 확장 열 편집 | BOM 탭 | 변경 있음 + 검증 통과 | 헤더 상태로 막지 않는다 — §8-5 결정 반영 |
| 변경 이력 | 각 폼 | 저장 이력 있음 | `audit.audit_event`(`W-CO-02` §8-1) |
| **품목 추가** | — | ⛔ **없다** | 품목은 ERP 정본 수신본이라 이 화면이 만들지 않는다 |

### §5-2. 화면 상태

`초기(미선택 — EmptyState)` → `조회` → `편집(변경 있음)` → `저장 중(버튼 비활성)` → `저장 성공(Toast)` / `검증 실패(인라인)` / `충돌(B-1)`

### §5-3. 낙관적 잠금

`item`·`bom`·`bom_component`에 `version_no`가 있으므로 **B-1 적용**. **특히 이 화면은 충돌이 잦을 구조**다 — ERP 재동기화가 같은 행의 `updated_at`을 건드릴 수 있다 → §8-3.

## §9. 이 장에서 나온 공유 계약 후보

1. **저장 충돌의 원인을 구분해 알린다 — B-1 확장.**
   `version_no` 충돌의 원인은 두 가지다: **다른 사용자**(B-1 현행 문구) / **ERP 재동기화 배치**. 수신본을 다루는 화면에서는 후자가 더 흔하고, 「다른 사용자가 먼저 수정했습니다」는 **거짓말이 된다.** API가 충돌 원인을 구분해 내려주고 화면이 문구를 갈라야 한다. **API 파급**(A-1·B-4·G-1·C-2에 이어 **5번째**).
2. **비율(0~1) 컬럼의 입력 단위 규약.**
   `scrap_rate`·`standard_yield_rate`가 `numeric(9,6) CHECK BETWEEN 0 AND 1`이다 — **퍼센트가 아니라 비율**. 화면이 `%`로 보이면서 저장을 비율로 하면 **100배 오입력**이 조용히 통과한다(0.05 입력 → 5% 의도인데 0.05% 저장, 혹은 그 반대). **전 화면 공통으로 표기 단위와 저장 단위를 못박고**, 입력란에 단위를 표시한다. 해당 컬럼은 최소 3곳(`bom_component.scrap_rate` · `routing_operation.standard_yield_rate` · 검사 샘플 비율).
3. **부분 유일 인덱스(`WHERE` 조건부)의 「하나만 참」 전환 규약.**
   `uq_bom_default ON (parent_item_id) WHERE is_default` 같은 제약은 **동시에 둘을 막을 뿐 자동 전환을 해 주지 않는다.** 화면이 해제→설정 2회 호출하면 중간에 0개 상태가 생긴다. **「하나만 참」 전환은 서버가 한 트랜잭션으로** 처리하고, 화면은 단일 액션으로 노출한다. 같은 형태가 다른 마스터에도 나온다(기본 BOM·기본 Routing·대표 단위 등).
4. **ERP 원본 열과 MES 확장 열이 한 행에 섞이는 표의 표현 규약.**
   열 헤더에 **소유 표식**을 붙이고, 잠긴 열은 「왜 잠겼는가」를 보인다(F-1·G-2와 같은 원리). `W-06-06`의 §5-4 게이트가 **구획 단위**였다면 이것은 **열 단위**다 — 게이트 규칙에 두 입도를 함께 적는다.
