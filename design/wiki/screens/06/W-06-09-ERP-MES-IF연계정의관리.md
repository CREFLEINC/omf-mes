# W-06-09 · ERP-MES I/F 연계정의 관리

> 작성일: 2026-08-03 · 서식: `00-서식.md` v1.0 · 작성 주체: CREFLE OMF 팀 (UI/UX)
> I/F 3장(`W-06-09` 정의 · `W-06-12` 송신 항목 · `W-06-10` 현황·재처리)의 첫 장. **이 장에서 앞선 두 화면(`W-06-05`·`W-06-06`)의 편집 게이트가 실행 불가임이 드러난다**(§8-2).

## §0. 요약

- **개요**: 관리웹 화면. 전산(ERP 연계)담당이 ERP(UNIERP)-MES 간 I/F 연계정의(연계대상·트리거·DB 중계 테이블 매핑)를 등록·관리하는 설정·마스터 유형 화면이다. 연계 「정의」와 「실행 현황」은 별개 화면(현황=`W-06-10`)이며, 물리 모델에 정의 테이블 자체가 없어(`interface_definition` 부재, `interface_code`는 FK 없는 맨 `code_t`) §4는 신설 요청 명세로 작성됐다. 이 장에서 'Legacy 출처' 플래그 부재로 `W-06-05`·`W-06-06`의 수신본 편집 게이트가 실행 불가함이 드러난다(§8-2).
- **주요 데이터**: 기본 정보(I/F 코드·방향·연계대상·외부 시스템·명칭)·트리거(Time Schedule/Event)·DB 중계 테이블 매핑(Temp 컬럼↔MES 컬럼, 변환 규칙은 근거 없음) 3분할 구성(§4). 연계대상은 수신 6종(품목·BOM·거래처·조직·작업자·P/O)이 고정 축이고 — QA §3.2 원문에서 공통코드가 빠지고 거래처가 들어왔다(§2 주 참조), 외부 시스템은 UNIERP·추적관리시스템·설비 표준 I/F 3종이다.
- **핵심 액션**: 연계정의 추가 → 저장/취소, 사용 중지(물리 삭제 없음), 연결 시험(Temp Table 접근 가능 여부만 확인, 실제 동기화는 미실행), 매핑 행 추가·삭제, 동기화 현황 보기(`W-06-10`으로 이동), 변경 이력 조회(§5). 2026-08-18 계약 체결(`/integration/interface-definitions` 다섯 오퍼레이션)로 액션 표가 신설됐다(§8-1).

## §3. 레이아웃 (관리웹 — 구조 기술)

**연계 「정의」와 「실행 현황」은 다른 화면이다**(현황 = `W-06-10`). 이 화면은 정의만 다룬다.

```
┌ PageHeader  기준정보 > 연계·변경 > I/F 연계정의                             ┐
│  [방향 ▾ 수신/송신] [연계대상 ▾] [사용 ▾]              [＋ 연계정의 추가]  │
├──────────────────┬──────────────────────────────────────────────────────────┤
│ 좌 (1/3)         │ 우 (2/3)                                                  │
│ ┌ 연계정의 목록┐ │  《기본 정보》 §4-A                                       │
│ │ 코드 대상    │ │   I/F 코드 · 명칭 · 방향(수신/송신) · 연계대상            │
│ │ 방향 트리거  │ │   외부 시스템(UNIERP / 추적관리시스템 / 설비)             │
│ │ 사용         │ │  ──────────────────────────────────────────────────────  │
│ │ ...(선택)    │ │  《트리거》 §4-B                                          │
│ └──────────────┘ │   ○ Time Schedule → 주기·시각                            │
│                  │   ○ Event        → 촉발 조건                             │
│                  │  ──────────────────────────────────────────────────────  │
│                  │  《DB 중계 테이블 매핑》 §4-C — 편집 그리드               │
│                  │   ┌──────────────────────────────────────────────────┐   │
│                  │   │ Temp 컬럼 │ MES 대상 테이블 │ MES 컬럼 │ 변환 │  │   │
│                  │   └──────────────────────────────────────────────────┘   │
│                  │                            [연결 시험] [취소] [저장]     │
└──────────────────┴──────────────────────────────────────────────────────────┘
```

- **수신 6종은 고정 축**이다(QA §3.2 확정). 화면은 임의 추가를 막지 않되 **확정 목록 밖은 표식**한다(`W-06-03` §9-3의 고정 축 경고와 같은 성격).
- **「연결 시험」**은 Temp Table 접근 가능 여부만 본다 — 실제 동기화 실행은 `W-06-10`.

## §4. 필드 — **신설 요청 명세** (테이블 부재)

물리 모델에 정의 테이블이 없으므로 **컬럼을 지어내지 않는다**(`00-서식.md` 원칙 2). 아래는 **확정 근거가 있는 항목만** 모은 것이다 — `W-06-08` §4의 3분할 방식을 따른다.

**⚠ 중계 테이블 스키마 상세가 미정이다**(WF06 S1 Open-Issue 「ERP-MES I/F 연계대상(코드·조직 — **중계 테이블 스키마 상세**)」). 매핑 그리드는 **자리만 두고** 열 구성은 스키마 확정 후 → §8-3.

### §4-D. ⚠ 확정됐으나 담을 곳이 없는 것 — **Legacy 출처 플래그**

WF06 S7 **Result**가 명시적으로 요구한다:

> 연계분에 **'Legacy 출처' 플래그(수정/삭제 불가)** + **MES 원천 등록분과 연계분의 구분 플래그**(공정·툴 등 MES 정본 마스터 등장에 따른 **신규 설계** — 충돌①③)

**대상 마스터의 물리 모델에 그런 컬럼이 없다** — 실측:

| 마스터 | 출처 구분 컬럼 | 확인 |
| --- | :-: | --- |
| `mdm.item` | ⛔ 없음 | SQL 363~385 전건 확인 |
| `mdm.code_value` | ⛔ 없음 | SQL 91~109 |
| `mdm.department` | ⛔ 없음 | SQL 213~227 |
| `mdm.worker` | ⛔ 없음 | SQL 495~510 |
| `planning.bom` | ⛔ 없음 | SQL 589~610 |

**→ §8-2.** 이것이 이 장의 핵심 발견이다.

## §9. 이 장에서 나온 공유 계약 후보

1. **⚠ 확정된 규칙에 「판정 근거 컬럼」이 없으면 그 규칙은 구현되지 않는다 — 게이트 규약의 전제 점검.**
   `W-06-06` §9-1이 세운 ERP 수신본 편집 게이트는 **「이 행이 수신본인가」를 아는 것**이 전제인데, 그 컬럼이 없다(§8-2). 공유계약에 게이트를 적을 때 **「무엇을 보고 판정하는가」를 함께 적고, 그 컬럼의 실재를 확인**한다. 같은 형태의 게이트가 이미 넷이다 — 수신본 여부(**근거 없음**) · 상태=확정(`status_code` 실재) · 참조 건수 0(FK 있으면 산출 가능·아니면 불가) · 권한(회신 대기).
2. **연계 「정의」와 「실행」을 화면이 섞지 않는다.**
   정의(`W-06-09`·`W-06-12`)는 마스터 성격이고 실행·현황(`W-06-10`)은 로그 성격이라 **저장 방식·조회 규약·권한이 다르다**(전자는 B-1 낙관적 잠금, 후자는 B-3 이력 불변·기간 필수 조회). 정의 화면에 「지금 동기화」 버튼을 두면 두 성격이 섞이므로, **정의 화면은 현황으로 이동만** 시킨다.
3. **외부 시스템이 3종임을 화면 구조가 반영한다.**
   UNIERP(마스터 연계) · 추적관리시스템(제품 바코드 이력) · 설비 표준 I/F(생산 실적·측정값)는 **성격이 전혀 다른데 같은 「연계」로 불린다.** 화면·용어가 이를 구분하지 않으면 설정이 뒤섞인다. 용어사전(§H-5)에 3종을 분리 등재한다.
