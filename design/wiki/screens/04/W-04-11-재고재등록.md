# W-04-11 · 재고 재등록

## §0. 요약

- **개요**: 관리웹에서 완제품창고담당이 판정이 끝난 반품품을 판매 가능한 재고로 되돌리는 화면. 원 LOT을 그대로 유지한 채 상태와 위치만 옮기며(genealogy 보존), B-10(정정·교체·대체) 어디에도 속하지 않는 네 번째 유형 "상태 복귀"로 다룬다. 반품 입고(`W-04-06`)·판정(`W-03-02`)과는 「작업이 끊긴다」는 기준으로 범위를 나눈 신설 화면(v1.2)이다.
- **주요 데이터**: `quality.disposition_decision`(처분 결정 — `approval_request_id` late FK 실재)·`trace.lot_hold`(보류 등록·해제)·`inventory.inventory_balance`(`blocked_qty`)·`inventory.inventory_transaction`(창고 이동)·`logistics.stock_transfer`.
- **핵심 액션**: 재등록 대기 목록에서 판정 완료 항목을 선택 → 판정 이력(시간순)과 잔여 유효기간을 확인 → 대상 창고·위치·수량을 입력 → **재등록 확정** 한 번으로 Lot Status를 Hold에서 Release로 전이하고 재고를 불량창고에서 완제품창고로 옮긴다(한 트랜잭션 안에서 동시에 일어난다).

> ⭐ **되돌아온 물건을 다시 팔 수 있게 만드는 화면**이다. 반품 입고(`W-04-06`)와 **사이에 판정·재작업이 끼어** 다루는 재고 상태가 다르다.

## §5. 액션·상태

### §5-1. ⭐ B-10 의 어디에도 안 들어맞는다 — **「상태 복귀」다**

B-10 이 **정정 · 교체 · 대체**를 갈랐는데 이 화면은 셋 다 아니다.

| 유형 | 뜻 | 이 화면 |
| :-: | --- | :-: |
| **정정** | 잘못 적은 것을 고친다 | ❌ 잘못 적지 않았다 |
| **교체** | 같은 것으로 바꾼다 | ❌ 물건이 그대로다 |
| **대체** | 다른 것으로 바꾼다 | ❌ |
| **⭐ 상태 복귀** | **같은 물건이 다시 팔 수 있게 된다** | ✅ |

**규칙** — **LOT 을 새로 만들지 않는다.** 새 LOT 을 만들면 **genealogy 가 끊기고** 「이 물건이 한 번 반품됐다」는 사실이 사라진다.

```
⛔ 새 LOT 발번        →  반품 이력이 끊긴다
✅ 원 LOT + 상태 전이  →  이력이 이어진다
```

⚠ **이름이 「재등록」이라 새로 만드는 것으로 읽힌다** — 화면이 「**원 LOT 을 그대로 씁니다**」를 적는다.

### §5-2. 「판정 완료」의 근거 — **처분 결정과 보류 해제 둘 다 본다**

```
quality.disposition_decision   반품품을 어떻게 할 것인가 (재작업·폐기·정상)
trace.lot_hold                 보류 등록·해제
```

| 조건 | |
| --- | --- |
| 처분 결정이 **정상** 또는 **재작업 완료** | ✅ 재등록 대상 |
| 처분 결정이 **폐기** | ⛔ 대상 아님 — `W-01-06` 폐기 품의로 |
| 처분 결정 **없음** | ⛔ **판정 대기** — 「판정이 나면 재등록할 수 있습니다」(G-3) |

⚠ **판정 이력을 시간순으로 보인다** — 「반품 입고 → 재작업 필요 → 재작업 완료 → 정상」. **한 번에 정상이 된 것과 재작업을 거친 것은 다르다**(고객 통보 여부가 갈릴 수 있다).

⚠ **`disposition_decision` 에 `approval_request_id` late FK 가 실재한다** — 처분이 승인을 탈 수 있다. 그 승인은 `W-CO-09` 결재함에서 처리된다.

### §5-3. ⭐ 재등록은 **두 가지를 동시에 한다** — J-7 로 보인다

```
① Lot Status   Hold  →  Release      (결정 10 — 차단이 풀린다)
② 재고 위치    불량창고 → 완제품창고  (수불 원장 · 결정 08)
```

**J-7 그대로다** — 「이 전이가 무엇을 막고 무엇을 푸는가」를 확정 전에 보인다.

```
⚠ 재등록하면 이 LOT 이 출하 가능해집니다
   Lot Status: Hold → Release
   재고: 불량창고 200 EA → 완제품창고 200 EA
   ⛔ 되돌리려면 다시 판정·보류를 걸어야 합니다
```

⚠ **전이는 `W-03-02` 소관이 아닌가** — 결정 10이 Lot Status 전이를 **단일 지점**으로 만들었다. 그런데 이 화면이 전이를 일으킨다.

**모순이 아니다** — **판정은 `W-03-02` 가 하고**, 이 화면은 **판정 결과를 재고에 반영**한다. 「Release 로 만들 것인가」를 여기서 정하지 않고, **이미 정상 판정이 난 것만** 목록에 온다.

⛔ **그래도 두 화면이 같은 컬럼을 건드린다** — 규칙을 계약이 정본으로 가져야 한다 → §9-1.

### §5-4. ⚠ 되돌아오는 동안 **유효기간이 줄었다**

반품 → 판정 → 재작업 → 재등록 사이에 **시간이 흐른다.** `expiry_date` 는 그대로인데 **잔여 기간이 짧아졌다.**

**화면이 잔여 일수를 보인다.**

```
유효기간 2027-02-01  ⚠ 잔여 178일
```

⚠ **고객이 잔여 유효기간을 요구할 수 있다**(`shipment_request_line.minimum_remaining_shelf_life_days`). 재등록한 재고가 **그 조건에 못 미치면 피킹에서 막힌다**(`M-04-01`). **재등록 시점에 그것을 알려야** 헛된 재등록을 막는다.

⛔ **유효기간이 `null` 인 LOT 은 판단 근거가 없다**(`W-04-08` §8-1과 같은 건) — 잔여 일수를 「⚠ 없음」으로 보인다(G-9).

### §5-5. ⛔ 재등록 사유를 담을 자리가 **없다**

「왜 다시 넣는가」는 판정 결과로 설명되지만, **재등록 행위 자체의 사유**(누가 언제 왜 결정했는가)는 남지 않는다.

| 후보 | 실측 |
| --- | :-: |
| `stock_transfer.reason_code` | ⛔ **없다** — #84가 이미 요청 중 |
| `inventory_transaction` | ⛔ 사유 컬럼 없음 |
| `lot_hold.release_condition` | ⚠ 해제 **조건**이지 재등록 사유가 아니다 |

**A-11로 물러난다** — **판정 이력이 사유를 대신한다**(§5-2). 재등록 자체의 사유는 남지 않는다.

⚠ **#84(`stock_transfer.reason_code` 부재)가 이 화면에도 걸린다** — 자재창고의 불량 반출·분실과 같은 컬럼이다. **같은 이슈의 세 번째 사용처**다.

## §9. 이 장에서 나온 공유 계약 후보

1. ⭐ **한 컬럼을 두 화면이 바꾸면 「누가 정하고 누가 반영하는가」를 계약이 가른다** — 결정 10이 Lot Status 전이를 단일 지점으로 만들었는데 이 화면도 `Hold → Release` 를 일으킨다. **모순이 아니라 역할이 다르다**(판정은 `W-03-02`, 반영은 여기). 그러나 **그 구분이 문서에만 있으면 API 직접 호출로 뚫린다** — 계약이 「어느 경로에서 어느 전이가 허용되는가」를 갖는다 (§5-3)
2. ⭐ **B-10 에 네 번째 유형이 필요하다 — 「상태 복귀」** — 정정·교체·대체 셋으로는 「같은 물건이 다시 팔 수 있게 되는 것」을 부를 수 없다. **새 LOT 을 만들면 genealogy 가 끊기므로** 원 LOT 을 그대로 쓰는 것이 핵심이고, 그 판단이 셋 중 어디에도 없다 (§5-1)
3. **시간이 흐르는 동안 줄어드는 값은 되돌릴 때 다시 보인다** — 유효기간은 그대로인데 **잔여 기간이 짧아졌다.** 고객이 잔여 기간을 요구하면 재등록해도 피킹에서 막히므로, **되돌리는 시점에 하류 조건을 미리 알린다.** `W-01-13` 의 「실행 시점 재판정」과 같은 취지 — **시간이 지나면 전제가 바뀐다** (§5-4)
