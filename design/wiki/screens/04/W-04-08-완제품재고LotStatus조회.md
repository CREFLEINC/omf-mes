# W-04-08 · 완제품 재고·Lot Status 조회

## §0. 요약

- **개요**: 관리웹에서 물류 출하담당·품질담당이 완제품 재고와 LOT 상태를 조회하는 화면(조회·상세, 신뢰도 추정 — 도식 앵커 밖). 창고·품목·LOT 단위로 보유·가용·예약·차단 수량을 보고, 보류 중인 LOT의 사유·해제 조건을 확인한다. **조회만** 한다 — 상태 전이는 `W-03-02`, 재고 재등록은 `W-04-11`이 맡는다.
- **주요 데이터**: `inventory.inventory_balance`(보유·예약·피킹·차단 수량과 **`available_qty`**(GENERATED 컬럼) · 위치별로 행이 갈린다) · `trace.lot`(`manufactured_at`·`expiry_date` 둘 다 nullable) · `trace.lot_hold`(사유·해제 조건·상태, 읽기 전용).
- **핵심 액션**: 창고 선택(필수) 후 조회 → 품목·가용만·유효기간 임박·보류만 필터, 품목/LOT/위치로 묶기 → 목록에서 LOT 선택 시 하단에 보류 상세 표시 → 보류 중이면 **Lot Status 화면(`W-03-02`)으로 이동** 링크만 제공. 상태 전이·재고 재등록 버튼은 두지 않는다.

## §5. 액션·상태

### §5-1. ⭐ 가용 수량은 **DB가 이미 계산해 두었다** — 아무도 다시 빼지 않는다

```sql
available_qty  numeric(20,6)
  GENERATED ALWAYS AS (on_hand_qty - reserved_qty - picked_qty - blocked_qty) STORED
```

`W-04-01` §9-2가 「여러 화면이 같은 파생 수량을 보이면 계약이 계산해 내려 준다」를 계약 후보로 올렸는데, **실측하니 계약보다 더 아래에서 이미 정해져 있었다.**

| 층 | 무엇이 정하나 |
| --- | --- |
| **물리 모델** | ⭐ `available_qty` GENERATED — **정의가 여기 있다** |
| 계약 | 그 값을 그대로 내린다 |
| 화면 | 그대로 보인다 |

> ⭐ **「계약이 정해야 한다」고 적기 전에 모델을 봐야 했다.** `W-06-14`가 「계약에 없다」고 적었다가 01 계약에 있던 것과 같은 형태다 — **한 층 아래를 먼저 본다.**

**규칙**: 세 화면(`W-04-01` 편성 · **이 화면** · `M-04-01` 피킹)이 **같은 컬럼을 보인다.** 화면이 빼지 않는다.

⚠ **그런데 「출하 가능」은 가용만으로 정해지지 않는다** — Lot Status 가 Release 여야 한다(결정 10). **가용 > 0 이고 Release 인 것**이 출하 가능이다. 그 판정은 §5-2.

### §5-2. 「출하 가능」 판정 — **가용 ∧ Release**

```
가용 수량 > 0        →  재고가 있다
Lot Status = Release →  차단이 풀렸다
```

**둘 다여야 출하할 수 있다.** 목록에 두 값을 **따로 보인다** — 합쳐 「출하가능 300」 한 숫자로 만들면 **왜 못 나가는지**를 알 수 없다.

| 상태 | 가용 | 화면 |
| --- | :-: | --- |
| Release · 가용 500 | 500 | 정상 |
| **Hold** · 보유 300 | **0** | ⛔ `blocked_qty`에 잡혀 가용이 0이다 — **일관된다** |
| Release · 전량 예약 | 0 | 예약 열에 300 — **왜 0인지 옆에서 읽힌다** |

⭐ **`blocked_qty`가 Hold 를 이미 반영한다면 가용 하나로 충분해 보이지만, 그렇지 않다** — **누가 왜 0으로 만들었는지**가 예약·피킹·차단 세 열에 갈려 있어야 운영자가 다음 행동을 정한다.

### §5-3. ⛔ 제조 일시·유효기간이 **둘 다 nullable** 이다 — FEFO 가 흔들린다

```
trace.lot.manufactured_at   timestamptz   nullable
trace.lot.expiry_date       date          nullable
```

`M-04-01` 피킹이 **FEFO(유효기간 빠른 것 먼저)** 를 쓰는데, **유효기간이 비면 정렬 축이 없다.**

**G-9를 적용한다 — 「없는 값」과 「모르는 값」을 같은 모양으로 그리지 않는다.**

| 상황 | 표시 |
| --- | --- |
| 유효기간이 있다 | `2027-02-06` · 임박이면 ⚠ |
| **유효기간이 없다** | **⚠ 「없음」** — 빈칸이 아니다 |
| 제조 일시가 없다 | **⚠ 「없음」** — Aging 을 못 센다 |

**A-11도 함께 적용한다** — 유효기간 임박 필터를 걸면 **값이 없는 LOT 은 판정 불가**다. 필터 결과 위에 그 수를 적는다.

```
⚠ 유효기간이 없는 LOT 4건은 이 필터로 판정할 수 없습니다
```

**L-8 그대로다** — 「판정 불가」를 「정상」으로 보이지 않는다.

### §5-4. 보류 상세는 **읽기만** 한다 — 전이는 `W-03-02`

결정 10이 Lot Status 전이를 **단일 지점**으로 못박았다. 이 화면은 조회이므로 **전이 버튼을 두지 않는다.**

**규칙**: 보류 사유·해제 조건을 **보이고**, 전이는 `W-03-02` 로 링크한다. **J-10(결재 ≠ 판정)과 같은 형태** — 대상을 보아야 정해지는 것은 그 화면이 소유한다.

⚠ **해제 조건이 비어 있으면 그것을 표시한다** — A-12가 「비어 있으면 보류가 영구히 안 풀린다」고 적었다. 조회 화면이 **비어 있음을 드러내는 자리**다(G-12의 형태).

## §9. 이 장에서 나온 공유 계약 후보

1. ⭐ **「계약이 정해야 한다」고 적기 전에 한 층 아래를 본다** — `W-04-01`이 「가용 수량은 계약이 계산해 내려 준다」를 후보로 올렸는데, 실측하니 **`available_qty`가 GENERATED 컬럼**이라 **물리 모델이 이미 정의를 갖고 있었다.** `W-06-14`가 「계약에 없다」고 적었다가 01 계약에 있던 것과 **같은 형태의 두 번째**다 (§5-1)
2. **한 숫자로 합치면 「왜 못 하는가」가 사라진다** — 가용 하나만 보이면 0인 이유(예약·피킹·차단)를 모른다. **판정 결과와 그 구성 요소를 함께 보인다.** G-3(비활성 사유는 「어떻게 풀 것인가」)의 **수치 판** (§5-2)
3. **정렬 축이 nullable 이면 그 정렬은 정책이 아니라 최선 노력이다** — 유효기간이 비어 있는 LOT 이 섞이면 FEFO 가 성립하지 않는다. **필터·정렬 결과 위에 「판정할 수 없는 건수」를 적는다** — L-8의 확장이고, 하류(`M-04-01` 피킹)에 그대로 파급된다 (§5-3)
