# M-04-01 · 제품LOT 피킹 스캔

> 작성일: 2026-08-07 · 서식: `00-화면스펙서식.md` v1.0 · 작성 주체: CREFLE OMF 팀 (UI/UX)
> **`M-01-08`(자재 출고 피킹)의 대칭**이고, 다른 것은 **고객이 LOT 에 조건을 건다**는 점이다.
> ⭐ **`W-04-08` 이 남긴 「선출 정책이 마스터에 있는가」가 실측으로 닫혔다** — `mdm.item.fifo_policy_code` 가 **NOT NULL DEFAULT 'FIFO'** 로 실재한다.

## §0. 요약

- **개요**: 물류 출하담당이 모바일(PDA)에서 오늘 출하분 피킹 목록에 진입해 제품LOT을 스캔하고 피킹을 확정하는 스캔형 화면이다. `M-01-08`(자재 출고 피킹)의 대칭이며, 고객이 LOT에 조건을 건다는 점이 다르다. v1.2에서 구 `M-04-02`(목록)를 흡수해 목록 진입까지 이 화면이 담당한다.
- **주요 데이터**: 출하요청 라인(`shipment_request_line` — `allocated_qty`·`minimum_remaining_shelf_life_days`·`customer_lot_requirement`), 품목 선출 정책(`mdm.item.fifo_policy_code`), LOT 유효기한(`trace.lot.expiry_date`)·Release 상태(`trace.lot_hold`), 재고 예약(`inventory.inventory_reservation`)·가용 수량(`inventory_balance.available_qty` GENERATED).
- **핵심 액션**: 피킹 목록 조회(온라인) → 대상 선택 → 권장 LOT(FEFO/FIFO) 확인 → 제품LOT 스캔 → 수량 입력 → 피킹 확정(Release 아니면 거부, 오프라인이면 진입 자체를 차단).

## §5. 액션·상태

### §5-1. ⭐ 선출 정책이 **마스터에 있다** — `W-04-08` 미결 해소

`W-04-08` §8-4가 「FEFO/FIFO 를 무엇이 정하나」를 미결로 남겼다. **실측하니 품목 마스터가 갖고 있다.**

```
mdm.item.fifo_policy_code   app.code_t NOT NULL DEFAULT 'FIFO'
```

| | |
| --- | --- |
| 정하는 곳 | **품목마다** — 전사 고정이 아니다 |
| 기본값 | `FIFO` — 유효기간이 없어도 성립하는 쪽이 기본이다 |
| 값 목록 | ⚠ 미정 — `FIFO`·`FEFO` 외에 무엇이 있는지 |

**규칙**: 화면이 정책을 **읽어서 정렬**하고, **무슨 정책인지 보인다** — 「FEFO 권장」/「FIFO 권장」. 운영자가 순서를 의심할 때 근거를 알 수 있어야 한다.

⚠ **정책은 `W-06-05`(수신본 확장속성 편집)가 편집한다** — 이 화면은 읽기만 한다.

### §5-2. ⛔ FEFO 인데 유효기간이 없는 LOT — **순서를 정할 수 없다**

`W-04-08` §8-1이 예고한 파급이 여기서 실현된다.

```
trace.lot.expiry_date   date   nullable
```

**FEFO 정책인데 값이 없으면 그 LOT 을 어디에 놓을지 정해지지 않는다.**

**세 갈래로 처리한다.**

| 상황 | 처리 |
| --- | --- |
| 유효기간 있음 | 정렬에 들어간다 |
| **유효기간 없음 · 정책 = FEFO** | ⚠ **목록 맨 뒤에 별도 묶음** + 「순서를 정할 수 없습니다」 — **섞지 않는다** |
| 유효기간 없음 · 정책 = FIFO | 입고일 순으로 정상 정렬 |

**L-10(정책이 미정인 데이터는 섞지도 지우지도 않고 분리 보기)의 모바일 판**이다. 지우면 재고가 사라진 것처럼 보이고, 섞으면 **잘못된 순서를 권장으로 제시**한다.

### §5-3. ⭐ 고객 LOT 요구는 **사람이 읽고 판단한다** — 화면은 판정하지 않는다

```
shipment_request_line.customer_lot_requirement   varchar(200)   자유 텍스트
```

「제조 90일 이내」·「동일 LOT 단일 구성」 같은 문장이 들어온다. **화면이 이것을 파싱해 자동 판정하지 않는다.**

| | |
| --- | --- |
| ⛔ 하지 않는 것 | 문장을 해석해 LOT 을 걸러내기 |
| ✅ 하는 것 | **문장을 크게 보이고**, 사람이 보고 고르게 한다 |

**왜** — 200자 자유 텍스트라 형식이 없다. 파싱하면 **못 알아들은 조건을 조용히 무시**하게 되고, 그것은 잘못된 LOT 이 나가는 것보다 나쁘다(무시했다는 사실조차 안 남는다).

⚠ **잔여 유효기간만은 컬럼이 따로 있어 판정한다** — `minimum_remaining_shelf_life_days` 는 integer 다. **구조화된 것만 자동 판정한다.**

### §5-4. Release 차단 — **결정 10을 여기서 실행한다**

`M-04-04`(제품 입고)가 「들어오는 것은 막지 않는다」였고, **막는 자리가 여기**다.

| 상태 | 동작 |
| --- | --- |
| Release | ✅ 집을 수 있다 |
| **Hold·보류** | ⛔ **스캔해도 거부** — 「⛔ Hold — 집을 수 없습니다」 |
| 가용 0 (전량 예약·피킹) | ⛔ 거부 — 「다른 출하에 배정됐습니다」 |

⚠ **오프라인이면 Lot Status 를 캐시하지 않는다**(C-6 — 판정값 캐시 금지). **오프라인에서는 피킹을 막는다.**

```
⚠ 오프라인입니다 — Release 상태를 확인할 수 없어 피킹할 수 없습니다
```

**C-5의 「온라인 전용」 갈래**다. `M-01-08`(자재 출고 피킹)이 같은 판정을 했다.

### §5-5. 권장과 다른 LOT 을 집으면 — **사유를 받는다**

`M-01-05`(적치)는 권장과 다르면 **차단**했다. 피킹은 다르다 — **권장은 순서 제안**이지 위치처럼 물리적으로 정해진 것이 아니다.

| | 적치(`M-01-05`) | **피킹(이 화면)** |
| --- | --- | --- |
| 권장의 성격 | **위치** — 다른 데 두면 못 찾는다 | **순서** — 다른 것을 집어도 물건은 맞다 |
| 위반 시 | ⛔ **차단** | ⚠ **사유 받고 통과** |

**⛔ 그런데 그 사유를 담을 자리가 없다.** `shipment_lot_allocation` 에 사유 컬럼이 없고 `inventory_reservation` 에도 없다(실측).

⛔ **되살리기 잔여** — 이 축소의 근거는 물리 모델 결손이었고 A-11 v4.6 이 그 근거를 철회했다. 되살리려면 계약 신설이 따르므로 별건으로 추적한다(변경 통지 판단 포함). 지금은 **경고만 하고 통과시키되**, 어느 LOT 을 집었는지는 `shipment_lot_allocation` 이 남기므로 **사후 추적은 된다.** 사유는 남지 않는다 → §8-1.

### §5-6. 오프라인 — **온라인 전용이다**

| 조항 | 이 화면 |
| :-: | --- |
| **C-5** 오프라인 허용 여부 | ⛔ **온라인 전용** — Release 판정이 필수다 |
| **C-6** 판정값 캐시 금지 | 그 근거다 |
| 진입 차단 표준형 | 「오프라인에서는 피킹할 수 없습니다」 + 재시도 |

⚠ **`M-04-04`(제품 입고)는 오프라인 허용인데 이 화면은 아니다.** 같은 창고 같은 단말인데 **화면 속성이 다르다** — C-5가 그것을 화면 속성이라 한 이유다.

### §5-7. 액션

| 액션 | 활성 조건 |
| --- | --- |
| 피킹 목록 조회 | **온라인** — 오늘 출하분 |
| 대상 선택 | 목록 행 |
| LOT 스캔 | 대상 선택됨 — **D-2 스캔 규약** |
| 직접 입력 | 항상 — **D-3 대체 경로 의무** |
| 수량 입력 | 스캔됨 — **≤ 가용 AND ≤ 배정 잔여** |
| **피킹 확정** | 수량 ≥ 1 AND Release AND 가용 충분 |
| 권장 외 선택 | ⚠ **경고 후 통과**(§5-5) — 사유는 남지 않는다 |
| 피킹 취소 | 확정 전 — 화면 이탈 |
| 확정 후 되돌리기 | ⛔ **두지 않는다** — 예약이 소진된다. 되돌림은 `W-01-13` 계열 |

## §9. 이 장에서 나온 공유 계약 후보

1. ⭐ **자유 텍스트 조건을 화면이 파싱해 자동 판정하지 않는다 — 크게 보이고 사람이 고른다** — 「제조 90일 이내」 같은 200자 문장을 해석하면 **못 알아들은 조건을 조용히 무시**하게 되고, 그것은 잘못된 LOT 이 나가는 것보다 나쁘다(무시했다는 사실이 안 남는다). **구조화된 것만 자동 판정한다** — 잔여 유효기간은 integer 컬럼이라 판정하고, 요구 문장은 보여 준다. A-12의 **읽는 쪽 판** (§5-3)
2. **「권장」의 성격이 위치면 차단, 순서면 경고다** — `M-01-05` 적치는 권장 위치를 벗어나면 **차단**했는데, 피킹의 권장은 **순서**라 다른 것을 집어도 물건은 맞다. **같은 낱말이 다른 강도를 갖는다** — 화면마다 그것을 명시한다. A-9(DB 미강제 검증의 3등급)의 적용례 (§5-5)
3. **같은 창고 같은 단말인데 화면마다 오프라인 가부가 다르다** — `M-04-04` 입고는 오프라인 허용이고 이 화면은 **온라인 전용**이다. 갈림은 **판정값을 쓰는가**이고, C-6이 판정값 캐시를 금지하므로 그 화면은 자동으로 온라인 전용이 된다. **C-5의 판정 기준을 「판정값 사용 여부」로 좁힌다** (§5-6)
