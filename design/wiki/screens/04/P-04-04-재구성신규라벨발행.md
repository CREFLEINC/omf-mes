# P-04-04 · 재구성 신규 라벨 발행

## §0. 요약

- **개요**: POP(Electron 키오스크) 화면. 완제품창고담당이 재구성(분할·합병) 이벤트에서 생긴 신규 포장을 발번하고 새 라벨을 인쇄한다. `M-04-03`(모바일 · 원 포장 스캔·구성 편집)의 짝이자 2단말 스택의 뒤쪽이며, 모바일이 넘긴 것을 받아 발번·인쇄한다. 분할 잔량은 원 번호를 유지해 발번하지 않고, 잔량 라벨 재출력은 사용자가 선택한다.
- **주요 데이터**: `inventory.handling_unit`(`handling_unit_no` UNIQUE · `status_code`), `app.document_issue_log`(`uq(문서유형, 대상유형, 대상, 회차)` · `ck_document_reissue_reason`).
- **핵심 액션**: 발행 대기 목록 조회 → 대상 선택 → 인쇄 대상 선택(신규 라벨은 기본 체크, 잔량 재출력은 선택) → 재출력이면 사유 선택 → 프린터 선택 → 미리보기(서버 렌더링) → 발번·인쇄(현재는 계약 미착지로 비활성).

> 작성일: 2026-08-07 · 서식: `00-화면스펙서식.md` v1.0 · 작성 주체: CREFLE OMF 팀 (UI/UX)
> **`M-04-03` 의 짝**이고 **2단말 스택의 뒤쪽**이다. 모바일이 구성을 바꾸고 **여기서 발번·인쇄**한다.
> ⛔ **`P-04-02` 와 같은 계약을 기다린다** — `app.document_issue_log` 계약이 아직 없다. **04 에서 세 화면이 한 계약에 묶여 있다**(`W-04-03` CoA · `P-04-02` 라벨 · 이 화면).

## §5. 액션·상태

### §5-1. 2단말 스택의 뒤쪽 — **모바일이 넘긴 것을 받는다**

```
M-04-03 (모바일)          P-04-04 (이 화면 · POP)
원 포장 스캔 · 구성 편집  →  발번 · 인쇄
```

⛔ **넘기는 상태를 담을 자리가 없다** — 재구성 이벤트 테이블이 0건이라(`M-04-03` §5-2) **`handling_unit.status_code` 값으로 물러났다.**

**화면 규칙** — ① 발행 대기 목록이 **그 상태 값으로 걸러진다.** 값 목록이 정해질 때까지 **자리표시 상수**를 쓴다(G-2).

⚠ **오프라인에서 모바일이 확정하면 여기 안 나타난다** — 동기화 뒤에 온다. **`M-04-03` 이 그 사실을 적었다.**

### §5-2. ⭐ 신규만 발번한다 — **분할 잔량은 원 번호를 유지**

**결정 13 절충안**(2026-07-06 CTO 확정):

> **신규 생성분 = 신규 발번 + 새 라벨** · **분할 잔량 = 원 단위 유지** · 라벨 재출력 = **사용자 선택**

```
CTN-2026-0091 (180)  →  분할  →  새 포장 (80)      + CTN-2026-0091 (100)
                                   ↑ 신규 발번          ↑ 원 번호 · 발번 안 함
```

**화면이 그것을 명시한다** — 잔량 행에 「ⓘ **원 번호를 그대로 씁니다 — 발번하지 않습니다**」.

⚠ **안 적으면 잔량도 발번하려 한다** — 그러면 **원 번호가 두 개 생기거나** 추적이 끊긴다.

### §5-3. ⭐ 잔량 라벨 재출력이 **선택인 이유**

결정 13 이 「라벨 재출력 = **사용자 선택**」이라 한 것은 **잔량 라벨이 아직 유효하기 때문**이다 — 번호가 그대로다.

**그런데 수량이 바뀌었다.**

| 라벨에 수량이 | 재출력 |
| --- | :-: |
| 찍혀 있다 | ⚠ **필요하다** — 180 이 찍힌 라벨이 100 에 붙어 있다 |
| 안 찍혀 있다 | 불필요 |

**화면이 판단하지 않는다** — 라벨 서식을 화면이 모른다(서버가 그린다 · 결정 18). **체크박스로 사용자가 고르고 경고만 붙인다.**

```
[ ] 잔량 라벨 재출력  (회차 2 — 사유 필요)
    ⚠ 수량이 바뀌었으면 다시 뽑아야 합니다
```

⭐ **재출력이면 회차 2 가 되고 사유가 필수**다(`ck_document_reissue_reason`). **K-7 이 여기도 걸린다** — 「인쇄 실패」 외에 **「재구성으로 수량 변경」** 값이 필요하다 → §8-2.

## §9. 이 장에서 나온 공유 계약 후보

1. ⭐ **번호를 유지하는 쪽과 새로 받는 쪽을 화면이 나란히 보인다** — 결정 13 이 「분할 잔량 = 원 단위 유지」로 정했는데, **발번 화면에서 둘이 섞여 보이면** 작업자가 잔량도 발번하려 한다. **「발번하지 않습니다」를 잔량 행에 적는다** — 하지 않는 것을 적는 것이 J-5 의 형태다 (§5-2)
2. **라벨 재출력 필요 여부를 화면이 판단하지 않는다 — 서식을 모르기 때문이다** — 결정 18 로 **라벨은 서버가 그리므로** 수량이 인쇄면에 있는지를 화면이 알 수 없다. **사용자가 고르고 화면은 경고만** 붙인다. 「모르는 것을 추측해 자동화하지 않는다」 (§5-3)
3. **한 계약을 기다리는 화면이 여럿이면 그 사실을 각 스펙이 서로 가리킨다** — `W-04-03`·`P-04-02`·`P-04-04` 셋이 `document_issue_log` 계약 하나에 묶여 있다. **묶여 있음을 적어야** 계약이 올 때 셋을 함께 열 수 있고, **하나만 보고 「이 화면만 막혔다」고 판단하지 않는다** (§5-5)
