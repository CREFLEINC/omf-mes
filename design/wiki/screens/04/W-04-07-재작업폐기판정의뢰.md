## §0. 요약

- **개요**: 관리웹 판정·승인 화면(신뢰도 **확정**). 품질담당이 반품·불량 제품의 부적합을 등록하고 재작업/폐기 판정을 의뢰한다 — ⭐ **이 화면은 판정하지 않는다.** 부적합 등록·판정 의뢰·결과 수신 후 분기만 하고, 판정 자체는 `W-03-10`(03 품질 계약)이 만든다.
- **주요 데이터**: `quality.nonconformance`(생성 — `description` NOT NULL, 판정자의 유일한 입력) · `quality.disposition_decision`(읽기 — 03 이 만든다, `approval_request_id` late FK 로 결재를 탈 수 있다) · `trace.lot_hold`.
- **핵심 액션**: ① **판정 대기 대상 목록**에서 대상 선택(반품 입고 + OQC 불합격 **두 원천**을 한 목록으로 받는다 — §5-7) → ② 부적합 등록(심각도·내용 필수) → ③ 판정 의뢰(03 품질 화면으로 넘어감) → ④ 결과 수신 후 처분별(재작업/폐기/정상)로 후속 화면 분기.

## §5. 액션·상태

### §5-1. ⭐ **이 화면은 판정하지 않는다** — 04 는 의뢰만 한다

**F04 정합 확정**(2026-07-07)이 「재작업/폐기 **판정**은 전 도메인에서 **03 소관** 통일」로 못박았다. 도식에서도 **H8 이 「판정 → 03 도식」 경계 위임**이다.

```
04 (이 화면)         03 (W-03-10)              04 (이 화면)
부적합 등록 · 의뢰  →  판정 · 처분 결정  →  결과 수신 · 분기
```

⭐ **2026-08-13 — 받는 화면이 생겼다.** 이 스펙을 쓸 때는 `W-03-02`(Lot Status 전이)를 가리켰는데 **그 화면은 처분을 저장하지 않았다.** 04 계약 트랙이 **116화면 전체에 처분을 저장하는 화면이 0건**임을 찾아냈고, **DR-008 확정 3-A** 로 **`W-03-10` 처분 판정 처리**가 신설됐다. 아래 B-13 지적이 그 확정으로 해소됐다 — **만드는 것은 `W-03-10`(03 품질 계약) · 읽는 것은 이 화면**이다.

**화면이 그 사실을 상단에 상시 적는다** — 「ⓘ 판정은 품질(03) 화면에서 합니다」. 안 적으면 **판정 버튼을 찾다가 못 찾는다.**

✅ **B-13 해소(2026-08-13)** — 처분 결정을 만드는 것은 **`W-03-10`**(03 품질 계약 `POST /quality/nonconformances/{id}/disposition-decisions`)이고 이 화면은 **읽기만** 한다. 「누가 정하고 누가 반영하는가」를 **계약이 갈랐다** — 부적합은 04 소유, 처분 결정은 03 소유.

### §5-1-1. 원천은 «묻지» 않는다

ⓐ **부적합을 만드는 화면은 이 화면 하나다**(요구서 §3-6). ⓑ **그래도 원천 축은 살아 있다** — 반품 LOT 에 대해 만든 건은 `RETURN` 이 된다. ⓒ 그 판정은 **서버가 입고 유형으로** 한다 — `Nonconformance.sourceCode`(§4-A). ⓓ ⛔ **원천 입력 위젯을 그리지 않는다** — `W-04-06` 이 라디오 버튼을 3주 그렸다가 걷어낸 것과 같은 사고다(`W-04-06` §9-2).

### §5-2. ⭐ 9일 만에 앵커를 받았다 — **#44 의 해소를 이제 반영한다**

인벤토리가 이 화면을 **「추정 · 반품입고에 흡수 가능」**으로 달고 있었다. 근거는 **「SC4 에 인접 행위 노드가 0개라 화면 매핑 규칙 §2 의 확인 필수 대조가 작동할 수 없다」**였다.

**#44 가 2026-07-29 사용자 확정으로 닫혔다** — 2택 중 **「행위 노드를 작화한다」**.

| | |
| --- | --- |
| 신설 | **B10 「판정 의뢰」**(`1008:9057`) — SC4 아래 · Desktop 단독 |
| 왜 File 이 없나 | **판정 기록은 03 소관**이라 04 에 두면 소관 침범 |
| 결과 | **`W-04-07` 이 도식 앵커를 갖는다** → 흡수 가능성 소멸 · **추정 → 확정** |

⚠ **상류가 「uiux 는 재판정할 수 있다」고 명시했는데 9일간 안 받았다.** → 인벤토리 **v1.9** 에서 정정.

### §5-3. 부적합 「내용」이 **판정의 유일한 입력**이다 — A-12

```
quality.nonconformance.description   text NOT NULL
```

**03 의 판정자가 이 문장을 읽고 재작업인지 폐기인지 정한다.** 물건을 직접 보지 않을 수도 있다.

**A-12 를 적용한다** — DB 가 NOT NULL 로 강제하지만 **형식은 화면이 유도**한다.

```
ⓘ 무엇이 · 어디가 · 얼마나 잘못됐는지 적어 주세요
   예) 외관 스크래치 · 상단 모서리 · 200개 중 40개 육안 확인
```

⚠ **「불량」 두 글자만 적히면 판정자가 판단할 수 없다** — `W-CO-09` 결재함의 `reason` 과 같은 문제다.

### §5-4. 판정 결과가 **LOT 을 가를 수 있다** — 선별

`quality.sorting_result` 가 **양품 LOT 과 불량 LOT 을 따로 만든다**(`good_lot_id`·`defect_lot_id`).

```
FG-…-0288  200 EA  →  선별  →  양품 LOT 160 · 불량 LOT 40
```

⭐ **여기서 `trace.lot_relation` 이 생긴다** — `W-04-06`(반품 입고)은 원 LOT 을 그대로 썼는데, **선별은 LOT 이 갈리므로 관계가 필요하다.**

⚠ **선별 실행 화면이 04 에 없다** — `sorting_result` 를 만드는 화면이 인벤토리에 없다(실측). **03 소관으로 보이나 03 에도 없다.** → §8-2.

### §5-5. 부분 처분이 정상이다

```
disposition_decision.decision_qty   CHECK > 0   ← 전량이 아니어도 된다
```

200 EA 중 **160 은 재작업 · 40 은 폐기**가 자연스럽다. **처분 결정이 여러 건 생긴다.**

**화면 규칙** — 결과 수신 구획이 **처분 목록**을 보이고, 각각의 후속 버튼을 따로 활성한다.

| 처분 | 후속 |
| --- | --- |
| 재작업 | `P-04-03` 재작업 실적 등록 |
| 폐기 | `W-04-10` 제품 폐기 요청 |
| 정상 | `W-04-11` 재고 재등록 |

### §5-6. 처분이 **결재를 탈 수 있다**

```
disposition_decision.approval_request_id   bigint (late FK → app.approval_request)
```

⭐ **승인 계약이 이미 있다**(`app-공통.json` · 2026-08-07). 결재는 **`W-CO-09` 결재함**에서 처리된다.

⚠ **언제 결재를 타는지는 결재선이 정한다**(`W-06-15`) — 「폐기는 결재선이 있고 재작업은 없다」 같은 운영이 가능하다. **화면이 그것을 정하지 않는다.**

## §9. 이 장에서 나온 공유 계약 후보

1. ⭐ **닫힌 이슈도 하류에 도착했는지 확인한다** — #44 가 2026-07-29 에 닫히며 도식스펙이 **「uiux 는 재판정할 수 있다」**고 명시적으로 넘겼는데 **9일간 받지 못했다.** [[contract-must-track-upstream]] 이 「계약도 상류를 따라가야 한다」였다면, 이것은 **「닫힌 이슈가 하류에 도착했는가」**다 — 열린 이슈는 보이는데 **닫힌 이슈는 안 보인다** (§5-2)
2. **소관이 다른 도메인으로 넘어가는 화면은 「여기서 하지 않는 것」을 상단에 상시 적는다** — 판정 소관이 03 인데 이 화면 이름이 「판정 의뢰」라 **판정 버튼을 찾게 된다.** J-5(승인하면 무엇이 일어나는가)의 **소관 판** — 「무엇을 여기서 하지 않는가」를 화면이 말한다 (§5-1)
3. **판정 입력이 자유 텍스트 하나뿐이면 그 형식을 등록 화면이 유도한다** — `nonconformance.description` 이 판정자의 **유일한 입력**이다. 「불량」 두 글자면 판단이 불가능하다. **A-12 의 세 번째 사용처**이고, 앞의 둘(`lot_hold.release_condition` · `approval_request.reason`)과 같은 형태다 (§5-3)
