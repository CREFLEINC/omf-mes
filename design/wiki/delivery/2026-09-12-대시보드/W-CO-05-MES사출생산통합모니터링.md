## §0. 요약

- **개요**: 관리웹에서 로그인 직후 첫 화면으로 보는 **부품사업부 사출기 전용** 통합 모니터링 대시보드. 사무실 상시 표출을 전제로 하며, 상단 KPI 5칸 · 제품군별 현황 표 · 설비 가동 현황 타일 격자를 한 화면에 담는다. 「종합 불량률」을 누르면 `W-CO-12`(제품군별 종합 불량 현황), 호기 타일을 누르면 `W-CO-13`(호기별 생산 현황)으로 간다.
- **주요 데이터**: 설비(`INJECTION_MOLDING` · 사용중 · 운용) · 작업 세션(가동·정지 판정) · 작업 계획(대기 판정) · 생산 실적 수량 5종 · 불량 실적(공정검사 PQC) · 제품군 마스터(신설) · 알림(설비·금형 대상).
- **핵심 액션**: 10분마다 자동 갱신 · 「종합 불량률」 클릭으로 `W-CO-12` 진입 · 호기 타일 클릭으로 `W-CO-13` 진입 · 미확인 알람이 있으면 팝업 1건을 띄우고 사람이 닫는다.

## §3. ⭐⭐ 설비 상태 4종은 «설비 마스터의 상태»가 아니다

이 절이 이번 재정의에서 **가장 오해받기 쉬운 자리**다. 아래 5소절로 쓴다.

#### §3-1. 상태 4종의 판정

| 상태 | 판정 | 근거 |
| --- | --- | --- |
| **가동** | 그 설비를 쓰는 작업 세션이 진행 중(`RUNNING`) | 확정 요구 §3 |
| **정지** | 가동 중 **멈춘 것**만 — 작업 세션 중단(`STOPPED`) | 확정 요구 §3 |
| **대기** | 오늘(조업일) 계획이 있으나 **아직 실행 전** | 확정 요구 §3 |
| **비가동** | 오늘 계획이 없음 · **작업 계획을 취소한 경우** · **작업이 끝난 경우**(`ENDED`) | 확정 요구 §3 |

계약(`InjectionEquipmentTile.operationStateCode` · `InjectionEquipmentSummary.operationStateCode`)은 이 네 값을 `RUNNING`·`STOPPED`·`WAITING`·`IDLE`로 코드화한다.

#### §3-2. ⛔ `Equipment.statusCode` 를 쓰지 않는다 — 계약이 그렇게 못박았다

`mdm-기준정보.json` `Equipment.statusCode` 설명 원문(주어 그대로):

> 자산 수명주기 — 운용 또는 폐기 두 값. … ⛔ **값을 늘리지 않는다 — 고장·보전중·비가동은 트랜잭션 조건이지 자산 상태가 아니다**(공유계약 `A-14` · `W-05-12` §5-2)

⇒ 이 화면의 4종은 **공유계약 `A-14`(「상태」와 「조건」을 분리한다)가 말하는 «조건»**이다. 설비 마스터는 「지금 쓸 수 있는가」(운용/폐기 · 사용/미사용)만 갖고, 「지금 돌고 있는가」는 **작업 세션·작업 계획에서 파생**한다. 계약도 `operationStateCode`에 `x-no-code-key`로 「코드 그룹이 아니다 — 저장 컬럼이 없는 파생 판정이다」를 못박아 같은 사실을 반복한다. ⛔ 설비 마스터에 상태 값을 늘려 달라고 요청하지 않는다.

#### §3-3. ⚠ 「완료」를 별도 상태로 두지 않는다 — **의도된 선택이다**

`WORK_SESSION_STATUS`에 **`ENDED`가 실재한다**(실측). 즉 「완료」를 낼 수 있는데도 **안 낸다.**

| 무엇 | 화면에 보이는 것 |
| --- | --- |
| 오늘 일을 끝낸 설비 | **비가동**(회색) |
| 오늘 일이 없던 설비 | **비가동**(회색) |

⚠ **둘이 같은 색으로 보인다. 사용자 확정이고 의도된 것이다.**
⭐ **그래서 화면이 그 사실을 밝힌다** — 범례 옆에 한 줄:
`ⓘ 비가동 = 오늘 계획 없음 · 계획 취소 · 작업 완료 (셋을 구분하지 않는다)`
⛔ 이 한 줄을 빼면 사용자가 「끝났는데 왜 회색인가」로 묻는다. `L-8`(「판정 불가」를 「정상」으로 보이지 않는다)의 역방향 적용이다 — **끝난 것과 안 한 것을 같이 보이기로 «했으면» 그렇게 했다고 적는다.**

#### §3-4. ⚠ 배정 없는 작업지시는 그 설비를 「비가동」으로 만든다 — 계획 축과 실행 축 둘 다

계획에 설비가 배정되지 않은 작업지시가 있으면, 실제로 돌고 있어도 그 설비는 **비가동**으로 보인다. **현재 작업 계획 전개 방식을 그대로 유지한다**(사용자 확정) — 배정을 필수로 바꾸지 않는다.

⚠ **같은 구멍이 실행 축에도 있다** — `WorkSession.equipmentId`가 `required`가 아니라서, 작업 세션이 실제로 `RUNNING`이어도 설비가 지정되지 않았으면 **어느 타일에도 들지 않는다.** 그러면 그 작업이 실제로 돌아가는 물리 설비 쪽에서 보면 「일이 있는데도 비가동으로 보이는」 자리가 생긴다 — 판정 근거 자체가 없는 값이다(`G-9` — 모르는 값과 없는 값을 같은 모양으로 그리지 않는다). 계약(`InjectionOverviewSummary.unassignedRunningSessionCount`)이 이 건수를 **0과 「모른다」를 같은 모양으로 그리지 않기 위해** 별도 건수로 내려준다 — 선례로 `equipment-05설비툴.json` `DowntimeSummary.sessionsWithoutEquipmentCount`가 같은 방식을 이미 쓰고 있다.

⭐ **화면이 이것을 밝힌다** — 설비 격자 아래 두 줄:
```
ⓘ 작업 계획에 설비가 배정되지 않은 작업지시는 이 화면에 나타나지 않는다
ⓘ 설비가 지정되지 않아 어느 타일에도 들지 않은 진행 중 작업 0건
```

#### §3-5. ⛔ 「교체」를 표시하지 않는다

시안 1의 범례에 `교체`(보라)가 있고 8호기·21호기가 「기종교체 26분/14분」으로 그려져 있다. ⛔ **MES가 낼 수 있는 상태가 아니다.** `WORK_SESSION_EVENT_REASON`에 `MOLD_CHANGE`(금형 교체)가 **사유**로는 있으나, 그것은 **정지 상태의 사유**이지 별도 상태가 아니다. 교체 중인 설비는 **「정지」**로 보이고 사유는 `W-CO-13` §5-6의 사유별 막대에서 보인다.

| 조업일·기준 시각 | **두 값을 함께 보인다** — `조업일 2026-06-01(08:00~) · 기준 16:46`. ⛔ 한쪽만 보이면 자정을 넘긴 시각에 날짜가 어긋나 보인다(`L-5` 「기준 시각을 항상 보인다」) |
| ① KPI | **5칸**. 시안의 6칸에서 「평균 C/T 달성」을 뺐다 ⇒ 남은 5칸이 같은 Row 안에서 폭을 나눠 넓힌다(확정 요구 §6 「빈 자리는 같은 Row의 다른 구획 너비를 키워 채운다」) |
| ① 종합 불량률 | **밑줄 + `▶`**로 클릭 가능함을 나타낸다(시안 1 관행 그대로). 나머지 4칸은 클릭 대상이 아니다 |
| ② 제품군 표 | 행 3개 고정(총생산(EA)·불량률(%)·NG(EA)) · **열은 제품군 마스터 값 수 + 합계**. ⛔ 5열로 고정하지 않는다 — `ADT`·`ESL`·`OA`·`Camdeco`·`기타`는 **예시일 뿐**이다 |
| ③ 타일 | 1칸 = `{호기}({설비명})` / 생산수량 / 품번 / 불량률 **4줄**. ⛔ **`C/T 27.8초`를 그리지 않는다**(확정 요구 §6) |
| ③ 비가동 타일 | 가동이 아닌 타일은 수치 대신 **상태 낱말**(`정지`·`대기`·`비가동`)을 크게 표시한다 |
| ③ 범례 | **4종만** — 가동·정지·대기·비가동. ⛔ **`교체`(보라)를 그리지 않는다** |
| ③ 격자 | **10칸 × 8줄 = 80칸**. 설비 수는 고정하지 않고 **남는 칸을 비운다** |
| 팝업 | 본 도면과 **겹쳐 그리지 않고** 별도 펜스로 이어 둔다 |

## §5. 필드·규칙

### §5-1. 기준 축은 「조업일」 하나다

조업일은 오전 08:00에 시작해 자정을 넘겨도 같은 날로 세며, **전사 고정**이다(확정 요구 §2). ⛔ 사용자가 고를 필터를 두지 않는다 — 상시 표출 화면이라 조작할 사람이 없다. 조회 질의는 `baseDate`(기준 조업일, 비우면 오늘)·`plantId`(선택)·`businessUnitId`(선택)를 받지만, 이 화면은 `plantId`·`businessUnitId`를 채우지 않고 호출한다 — 범위를 부품사업부 사출기 전용으로 좁히는 것은 1차 화면의 확정 범위이지(`01_scope.md` §1), 질의 조건으로 미리 거는 것이 아니다.
⚠ 옛 `W-CO-05` §5-1의 「날짜·공장 2축」을 **걷는다**(부품사업부 사출기 전용이라 공장 축이 뜻을 잃는다).

### §5-2. 설비 모수 — 세 조건의 교집합

`equipmentTypeCode = INJECTION_MOLDING`(사출기) **AND** 사용중(`isActive`) **AND** 운용(`statusCode = IN_SERVICE`). 계약(`InjectionOverviewSummary.equipmentTotalCount`)이 이 교집합을 그대로 정의한다. ⭐ 「사용중」과 「운용」이 **다른 축**임을 밝힌다 — `Equipment.statusCode` 설명이 「⚠ 사용 여부(`is_active`)와 «다른 축»이다」로 못박았다. ⛔ 대수(71)를 상수로 박지 않는다 — 실제 운영 데이터이고 계약도 고정값을 두지 않는다.

### §5-3. 지표 표

| 지표 | 분자 | 분모 | 소유 화면 |
| --- | --- | --- | --- |
| 가동 / 전체 | 가동 상태 설비 수 | 설비 모수(§5-2) | 이 화면 |
| **종합 가동률** | 가동 설비 수 | 전체 설비 수 | 이 화면 |
| 금일 총생산 | 양품 + 불량 (§5-4) | — | `W-02-08` |
| **종합 불량률** | 총 NG | 금일 총생산 | ⭐ **`W-CO-12`** — 클릭하면 간다 |
| 총 NG | 불량 = `defectQty + holdQty + reworkQty` | — | `W-CO-12` |
| 제품군별 총생산·불량률·NG | 같은 정의를 제품군 축으로 나눈 것 | — | `W-CO-12` |
| 호기별 생산수량·품번·불량률 | 설비 축 | — | ⭐ **`W-CO-13`** — 타일을 누르면 간다 |

⚠ **「소유 화면」 열의 뜻이 옛 판과 다르다** — 옛 `W-CO-05` §5-2는 「값이 이상하면 누구에게 물어야 하는가」였고, 재정의본은 **「이 값을 눌렀을 때 어디로 가는가」**다.

### §5-4. 생산 수량 3원과 「금일 총생산」의 모집단

⭐ 세 수치 자체는 공유계약 `L-10` 이 이미 확정한 정의를 그대로 쓴다 — 새로 정하지 않는다.

| 값 | 정의 |
| --- | --- |
| 양품 | `goodQty` |
| 불량 | `defectQty + holdQty + reworkQty` |
| 손실 | `scrapQty`(총생산에 **넣지 않는다**) |
| 금일 총생산 | 양품 + 불량 |

⚠ **모집단은 확정 요구 §2의 「LOT 마감 기준 전체 수량」과 셈하는 자리가 다르다** — LOT 축으로 「전체 수량」을 내려주는 자리가 계약에 없다(`LotProgress`는 양품만 낸다). 대신 계약(`InjectionOverviewSummary.totalQty`)은 생산 실적 다섯 수량의 합을 **실적 발생 시각**(`occurredAt`) 기준으로 그 조업일 경계 안에서 서버가 낸다. **결론(양품+불량, 손실 제외)은 같지만, 「LOT가 언제 마감됐는가」가 아니라 「그 실적이 언제 기록됐는가」로 자른다는 점이 다르다.** ⛔ 화면은 이 값을 다시 계산하지 않는다(`L-2`).

### §5-5. 제품군 — MES 에 없어 신설한다

⭐ **사용자 관리형 마스터**(코드 그룹 `registry` 갈래 · 공유계약 `G-31`). 값은 **`W-06-06`**(공통코드·조직·작업자 마스터)에서 고객이 채우고, 품목이 그 아래 붙는 것은 **`W-06-05`**(수신본 확장속성 편집)의 MES 확장 속성에서 지정한다. ⛔ **ERP 가 주지 않는다** — 개발품 플래그와 같은 방식.

⚠ **비슷해 보이는 축이 하나 있으나 제품군이 아니다.** 품목 마스터에 `mesCategoryCode`(과거 품목 단위 MES 구분)가 실재한다. 그러나 계약이 **「호환을 위해 보존하며 … 정본으로 사용하지 않는다」**(2026-09-08 사용자 승인)로 명시적으로 봉했다. `itemTypeCode`(원자재·반제품·제품·상품)는 계층이 다른 축이다. ⇒ **제품군을 담을 수 있는 살아 있는 축은 0건이고, 그래서 신설한다.**

⭐ 값 목록은 `GET /mdm/code-values?codeGroupCode=PRODUCT_FAMILY`로 받는다(공유계약 `G-32`). **대시보드 제품군 열의 «순서»는 `displayOrder`가 정한다** — 화면이 컬럼 수를 고정하지 않는다는 확정과 맞물리는 자리다.

### §5-6. ⛔ 시안에 있으나 그리지 않는 것 — 그리고 빈 자리를 어떻게 채우나

| 시안에 있던 것 | 왜 안 그리나 | 빈 자리 처리 |
| --- | --- | --- |
| 평균 C/T 달성 `98.6%`(상단 KPI 6칸째) | **MES 에 사이클 타임 정보가 없다** | ① KPI 가 **6칸 → 5칸**. 남은 5칸이 폭을 나눠 넓힌다 |
| 타일 안의 `C/T 27.8초` | 같은 이유 | 타일이 **5줄 → 4줄**. 타일 높이를 줄이고 격자 여백을 늘린다 |
| 「상태별 설비 현황」 패널(우측) | **설비 상태를 실시간 관리하지 않는다** | ③ 설비 격자가 **전폭으로 넓어진다** |
| 상단 `● 가동중` 배지 | 불필요 | 헤더 우측을 **조업일·기준 시각**이 채운다 |
| 「교체」 상태(범례·타일·패널) | **MES 가 낼 수 없는 상태다**(§3-5) | 범례가 **5종 → 4종** |
| 꼬리말 「전 사출기 PLC/카운터와 실시간 연동」 | **취소** — POP 실적이 올라오는 대로 반영한다 | 꼬리말을 §5-9의 「POP 실적 시점까지의 값」 한 줄로 대신한다 |

⇒ **규칙** — 빈 자리는 **같은 Row 의 다른 구획 너비를 키워** 채운다. 그렇게 하기 어려우면 **비워 둔다**(확정 요구 §6). ⛔ 빈 자리를 메우려고 **새 지표를 만들지 않는다** — `L-14`(집계는 낼 수 있는 것만 내고 이름을 빌리지 않는다).

### §5-7. 자동 갱신 **10분** — ⭐ `L-6`의 예외가 아니다

공유계약 **`L-6`**은 「**자동 갱신을 두지 않는다 — 대시보드와 구분**」이고, 본문이 대상을 「관리자 **조회** 화면」으로 못박는다. ⇒ **대시보드는 애초에 이 조항의 적용 대상이 아니다.** 예외를 만드는 것이 아니라 조항이 처음부터 갈라 둔 자리다.

| 무엇 | 값 |
| --- | --- |
| 갱신 주기 | **10분** |
| 갱신 방식 | 화면이 스스로 다시 조회한다 — 사람이 누르지 않는다(무인 상시 표출) |
| 기준 시각 표시 | **항상 보인다**(`L-5`) — `조업일 2026-06-01(08:00~) · 기준 16:46` |

⚠ **모든 수치는 「POP 실적이 올라온 시점까지」의 값이다.** 사출기 설비 직접 연동은 1차 범위 밖이다 — 실적이 올라오기 전의 생산은 화면에 없다. ⛔ **「실시간」이라고 적지 않는다.**

⚠ **갱신 주기 10분이 옛 `[추정]` 5분을 대체한다** — 옛 §5-4와 §8 미결 5(「갱신 주기 5분 · `[추정]`」)가 이 확정으로 닫힌다.

### §5-8. 알람 — **상시 영역이 아니라 팝업이다**

⛔ **알람 상시 영역을 두지 않는다**(옛 `W-CO-05` §4의 「미처리 알람」 구획을 걷는다).

| 무엇 | 확정 |
| --- | --- |
| 언제 뜨나 | 미확인 알람이 있으면 **팝업 대화상자 1개** |
| 언제 닫히나 | **사용자가 확인하고 닫을 때까지** — ⛔ 자동 닫힘을 두지 않는다 |
| 몇 건 | **가장 최근 1건만**. **교체식**이다 — 떠 있는 중에 새 알람이 오면 그것으로 교체한다(⛔ 중복 창을 만들지 않는다) |
| 대상 | **설비·금형 알람만**(`targetTypeCode` = `EQUIPMENT` · `MOLD`) |
| 위치 표기 | 알림의 **계층 텍스트**(`locationPath`)를 그대로 쓴다 — 「1공장 > A라인 > 사출기 3호」. ⭐ `REQ-PR-0036` 「알람발생 설비 위치 표시」가 **여기서 충족된다** |
| 닫으면(읽음 처리) | ⭐ **한다** — 「확인」을 누르면 화면이 공통 계약의 `POST /app/notifications/{notificationId}:read`(`app-공통.json`)를 부른다. 이 계약서(`dashboard-사출모니터링.json`) 자체는 **읽기 전용을 유지**한다. 응답 필드 `latestUnreadAlarm`의 설명이 「확인하지 않은 가장 최근 알람 한 건」이라 **미확인만 낸다**는 전제를 드러낸다 |

⚠ ⭐ **발생과 표시 사이에 최대 10분 지연이 있다.** 푸시 구조가 없어 **10분 주기 갱신 때** 새 미확인 알람이 있으면 뜬다. **이 사실을 스펙에 적는다**(사용자 확정) — 적지 않으면 현장에서 「알람이 안 뜬다」는 오해를 산다.

⚠ ⭐ **무인 상시 표출 중에는 팝업이 닫히지 않고 화면을 가린다.** 닫을 사람이 없기 때문이다. **자동 닫힘을 두지 않기로 확정했다**(사용자 확정 — 사람이 가서 닫는다). ⛔ 「N초 뒤 자동 닫힘」을 임의로 넣지 않는다. ⚠ 읽음 처리를 안 하면 다음 10분 갱신 때 같은 알람이 또 뜬다 — 그래서 「닫으면 읽음 처리」가 확정됐다.

⚠ **이 팝업은 셸이 띄우는 것이 아니라 이 화면이 띄운다.** 공유계약 **`G-14`**(현장 단말은 진입 시 미확인 공지를 먼저 보인다 — 「화면이 팝업을 그리는 것이 아니라 셸이 띄운다」)는 **POP 22화면 대상**이라 여기 걸리지 않는다. 관리웹 대시보드의 알람 팝업은 이 화면 소유다.

### §5-9. 표시 규약

백분율은 **소수점 1자리**로 낸다(계약이 서버에서 이미 반올림해 내려준다 — 화면은 다시 반올림하지 않는다). 수량은 천 단위 쉼표 + 단위 `EA`. ⚠ **`L-8`** — 그 조업일 실적이 아직 없으면 **0%가 아니라 「아직 없음」**으로 그린다(0%로 그리면 「가동 안 함」으로 읽힌다).

### §5-10. 액션·상태

| 액션 | 활성 조건 · 결과 |
| --- | --- |
| **자동 갱신** | 상시 — **10분마다** 스스로 다시 조회한다(§5-7) |
| **「종합 불량률」 클릭** | 항상 활성 → **`W-CO-12`**(종합 불량 현황 · 제품군별) |
| **호기 타일 클릭** | 항상 활성(상태 무관 — 비가동 호기도 누를 수 있다) → **`W-CO-13`**(호기별 생산 현황). 선택한 설비를 넘긴다 |
| **알람 팝업 「확인」** | 팝업이 떠 있을 때 — 닫고 그 알람을 읽음 처리한다(§5-8) |

⛔ **이 화면에 «만드는» 액션이 없다 — 조회 전용이다.**
⛔ **필터·기간 선택·수동 갱신 버튼을 두지 않는다** — 무인 상시 표출이라 조작할 사람이 없다.
⛔ **위젯 편집·배치 저장을 만들지 않는다**(옛 §5-5의 판단을 그대로 유지 — `G-24` 목록).

**상태**: `초기 조회 중` → `표시 중`(10분마다 재조회) / **`아직 없음`**(조업일 실적 0 — `L-8`: 0%로 그리지 않는다) / `갱신 실패`(직전 값 + 「HH:MM 기준(갱신 실패)」 — `G-23`)

| 설비 모수가 0대 | 「대상 사출기가 없습니다」 — ⛔ 종합 가동률을 **0%로 그리지 않는다**(분모 0 · `G-15`) |
| 제품군 마스터가 비어 있다 | ② 표를 「합계」 한 열만 두고 그린다 + 「제품군이 아직 등록되지 않았습니다」. ⛔ 예시 값(ADT·ESL…)을 화면이 만들어 채우지 않는다 |
| 품목에 제품군이 지정되지 않았다 | **「미지정」 열**로 묶어 보인다 — ⛔ 합계에서 빼지 않는다(`G-9` — 모르는 값과 없는 값을 다르게) |
| 설비가 80대를 넘는다 | ③ 격자가 **줄을 늘려** 받는다. ⛔ 잘라 내지 않는다 |
| 설비에 금형·품번이 없다 | 그 줄을 **비워 둔다** — ⛔ `-`나 `0`으로 채우지 않는다 |
| 설비가 지정되지 않은 진행 중 작업 세션이 있다 | 타일에는 나타나지 않고 **건수로 요약에 보인다**(`unassignedRunningSessionCount`) — ⛔ 0과 「모른다」를 같은 모양으로 그리지 않는다(`G-9`) |
| 갱신 실패 | ⚠ **직전 값 + 「HH:MM 기준(갱신 실패)」**(`G-23` — 회색만 두지 않는다 · 다음 주기에 재시도) |
| 알람이 0건 | ✅ **정상 상태** — 팝업이 뜨지 않는다. ⛔ 「알람 없음」 창을 띄우지 않는다 |
| 오프라인 | **해당 없음** — 관리웹 온라인 전제(`C-5`) |

## §9. 이 장에서 나온 공유 계약 후보

| # | 후보 | 요지 |

| 9-1 | **무인 상시 표출 화면은 「조작할 사람이 없다」를 전제로 컨트롤을 뺀다** | 필터·수동 갱신·페이지 이동을 두면 아무도 누르지 않아 화면이 굳는다. 대신 **자동 갱신 주기와 기준 시각을 화면이 스스로 밝힌다.** `L-6`이 「대시보드와 구분」으로 갈라 둔 자리에 «무인» 축을 더한다 |
