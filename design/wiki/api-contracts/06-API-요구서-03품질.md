- ⭐ **실행 경로를 화면이 고르지 않는다** *(2026-08-24 · `omf-mes#190` 질문2)* — 전이 응답에 **`actionCode`**(`RELEASE_HOLD`·`CREATE_HOLD`)가 실린다. ⚠ **목표 상태만으로는 못 가른다** — 「불량」이 **두 경로에서 도달**한다(재판정 불합격 C8 = 해제 · 클레임·리콜 재Hold C9 = 신규 보류). 현재 상태로 추론할 수는 있으나 **그 분기가 곧 전이표**라, 전이가 하나 늘면 세 셸을 다시 배포해야 한다(G-8 위반).
- ⭐ **어느 보류를 풀지는 사용자가 고른다** *(같은 이슈 질문5)* — `actionCode` 는 「무엇을 하는가」까지만 말한다. 부분 보류가 여럿일 수 있고 **사유가 건마다 다르며 재판정도 건별**이라, 서버가 임의로 고르거나 전체를 한 번에 풀지 않는다. 그래서 `lotHoldId` 를 전이 응답에 싣지 않았다.
- ⭐ **저장 충돌 토큰의 원천** *(같은 이슈 질문4)* — `:release` 의 `If-Match` 는 `GET /quality/lot-holds/{lotHoldId}` 의 `ETag` 를 그대로 싣는다. ⚠ **그 `ETag` 는 보류 «행»이 아니라 그 보류가 걸린 «LOT»의 판 번호다** — 잠그는 대상이 LOT 이기 때문이다. 계약 설명이 「이 행의 판 번호」로 잘못 적혀 있던 것을 2026-08-24 에 정정했다.
- ⭐ **대량 보류의 토큰은 본문으로 간다** *(같은 이슈 질문3 · `W-03-03`)* — `GET /quality/lot-statuses` 가 **`versionNo`** 를 함께 내리고, `POST /quality/lot-holds` 의 `lots[].versionNo` 에 그대로 싣는다. 헤더 `If-Match` 하나로는 여러 LOT 의 토큰을 표현할 수 없다(공유계약 **A-4-1** 신설). ⛔ **화면에 표시하지는 않는다**(A-4).
