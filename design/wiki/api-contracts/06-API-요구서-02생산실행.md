### 3-5. `W-02-05` W/O 마감·ERP 실적 송신 *(관리웹)*

| 액션 | API | 비고 |
| --- | --- | --- |
| 조회 · W/O 선택 | `GET /production/work-orders` · `/{id}` — `withProgress` 로 **실적 누계**를, `withPreIssuedLots` 로 **선발행 슬롯 집계**를 함께 받는다 | ⭐ 쪽 합산이 아니라 전체 합계다 |
| 선발행 슬롯 「보기」 | `GET /trace/lots?workOrderId=…` | 집계는 건수만, 목록은 필터로 |
| 잔량 처분 선택(이월/소멸) | `POST /production/work-orders/{workOrderId}:close` 본문 `remainderDispositionCode` | ⭐ **미달일 때만** 보낸다 |
| 사유 선택 | 동상 — `reasonCode` | ⭐ **미달·초과일 때만** |
| 송신 항목 토글 | 동상 — `erpSendItems` | ⭐ 축이 둘이다 — 이 칸은 «생산 실적 부속 항목»(투입자재·공수·설비시간·비가동 · 도식스펙-02 E2-b)이고, 최상위 송신 항목 켜고 끄기는 06 연계 계약(`W-06-12`) 소관이다. ⚠ 부속 항목의 코드 표기는 미정 |
| 마감 | `POST /production/work-orders/{workOrderId}:close` — `If-Match` **필수** | 미달 슬롯 자동 폐번(R27·R82) · ⛔ 열린 세션이 있으면 409 `OPEN_SESSION_EXISTS` 로 거부된다 — 화면은 그 문구를 띄운다(화면 §6) |

- ⭐ **실적 누계가 응답에 앉았다** *(2026-08-24 · `omf-mes#207`)* — `WorkOrder.progress` 가 양품·불량·보류·스크랩·재작업 **다섯 수량**과 **달성률**·**마감 3분류 판정**(`completionJudgmentCode` = `UNDER`·`NORMAL`·`OVER`)·**잔량**을 내린다. ⚠ **`withProgress` 는 원래 있었는데 담길 칸이 없었다** — 약속만 있고 물건이 없었다.
- ⛔ **판정은 서버가 한 곳에서 낸다** — `W-02-08` §5-2 가 이미 정했다. 「조회에서 95%인데 마감에서 미달 판정이 다르게 나오면 신뢰를 잃는다」. 그래서 마감 본문 검증도 **서버가 스스로 낸 판정**과 대조한다. ⚠ 「정상」의 폭(허용 오차)이 정해지면 **서버 한 곳**만 고치면 된다 — 계약도 화면도 그대로다(§5-1·§8-1).
- ⛔ **「손실」을 계약이 만들지 않는다** — 5컬럼을 그대로 내리고 줄이는 것은 화면이 한다. **`#60` 은 2026-08-25 종료**(PR `#236` · 계약 완전 흡수) — 5컬럼을 그대로 내리는 판정이 그 답이다.
- ⭐ **마감 본문 400 규칙** *(`omf-mes#209`)* — 미달인데 `remainderDispositionCode` 가 없으면 400 · 정상·초과인데 있으면 400 · 미달·초과인데 `reasonCode` 가 없으면 400 · 정상은 두 칸을 다 비운다. ⛔ **정상·초과용 세 번째 값을 만들지 않았다** — R81 이 정한 것은 「미달 잔량 = 이월/소멸」 둘뿐이라 없는 업무 개념을 만들게 된다(A-21).
- ⭐ **마감에 `If-Match` 가 필수다** *(`omf-mes#208`)* — 토큰은 `GET /production/work-orders/{workOrderId}` 의 `ETag` 다. §6 이 「저장 충돌 → `409` + 다시 불러오기」를 이미 확정했는데 **토큰을 실을 자리가 없었다.** 형제 전이 `:hold`·`:resume` 가 «선택»인 것은 그 둘이 **POP 오프라인 대상**이라 큐가 토큰을 싣지 못해서다(C-9) — 마감은 관리웹 온라인 전제이고 **되돌릴 수 없다**(재오픈 금지 · R83).
