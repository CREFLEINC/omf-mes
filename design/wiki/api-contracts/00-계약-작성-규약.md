# 계약 작성 규약 — **JSON 이 정본이다**

> 확정: 2026-08-18 (사용자) · 대상: `design/wiki/api-contracts/openapi/*.json` **일곱**(2026-08-29 실측 — 확정 당시는 여섯이었다)

---

## 한 줄

> ### ⭐ **OpenAPI JSON 파일 자체가 정본이다. 계약을 만들어 내는 프로그램을 두지 않는다.**

---

## 왜 이렇게 정했나

2026-08-18 이전까지 **한 폴더 안에 두 방식이 섞여 있었다.**

| 계약 | 그때 정본 |
| --- | --- |
| 02 생산실행 · 03 품질 · 04 제품출하 | **생성기**(`build-0N-openapi.py`) — JSON 은 산출물 |
| 기준정보 · 01 자재창고 · 공통 | **JSON 자체** |

⛔ **그 섞임이 사고를 냈다.** 저장 충돌 토큰(`ETag`) 선언을 JSON 에 직접 넣었는데 생성기에는 안 넣었고, 그 상태로 **누가 재생성하면 조용히 사라지는** 상태가 됐다. 실측:

```
build-02  재생성 →  "ETag" 2 → 0 · If-Match 17 → 15 · x-internal-note 16 → 11
build-03  재생성 →  "ETag" 2 → 0 · If-Match 10 →  8 · x-internal-note 26 → 14
build-04  재생성 →  "ETag" 2 → 0 · If-Match  5 →  3 · x-internal-note 12 →  9
```

⭐ **뿌리는 「어느 쪽이 정본인지 안 정한 것」이었다.** 그래서 한쪽으로 정했다.

### 생성기를 버린 근거

| | |
| --- | --- |
| **여섯 중 셋뿐이었다** | 나머지 셋은 이미 JSON 을 직접 다루며 잘 돌아간다. **소수를 다수에 맞춘다** |
| **이점이 이미 소진됐다** | 생성기는 「길게 반복되는 것을 짧게 쓰기」가 값어치인데, **계약은 이미 다 쓰였다.** 앞으로는 고치는 일이지 짓는 일이 아니다 |
| **두 벌을 맞춰야 했다** | 고칠 때마다 생성기와 JSON 을 함께 손대야 하고, **한쪽만 고치면 조용히 갈린다** |
| **읽는 쪽이 JSON 이다** | 구현팀은 JSON 을 읽어 타입을 만든다. **정본과 소비물이 같은 것이 단순하다** |

---

## ⛔ 하지 말 것

| | |
| --- | --- |
| **계약 생성기를 다시 만들지 않는다** | 같은 사고가 되풀이된다. 반복이 지겨우면 **패치 스크립트**를 쓴다 |
| **JSON 을 「산출물」로 다루지 않는다** | 지우고 다시 만드는 대상이 아니다 |

## ✅ 계약을 고치는 방법

1. **작은 수정** — JSON 을 직접 고친다.
2. **여러 자리를 한 규칙으로** — **패치 스크립트**를 쓴다(`patch-*.py`). 반드시 **멱등**(같은 것을 여러 번 돌려도 결과가 같다)하게 쓰고, **원본 들여쓰기와 정렬 여부를 되짚어** 서식이 통째로 바뀌지 않게 한다.

   ⛔ **들여쓰기는 파일마다 다르다 — `json.dump` 의 기본값을 그냥 쓰면 파일 하나가 통째로 다시 쓰인다.**
   2026-08-29 API 재정리 회차에서 실제로 일어났다: `indent=2` 로 두 파일을 다시 써
   `equipment-05` 가 4,975행, `shipment-04` 가 2,998행 바뀐 것으로 잡혔다(내용 변경은 수십 행뿐).
   diff 규모를 보고 되돌렸으나, **알아채지 못했으면 리뷰가 불가능한 PR 이 나갔다.**

   실측(2026-08-29):

   | 파일 | `indent` |
   | --- | :-: |
| `equipment-05설비툴.json` | **1** |
| `logistics-01자재창고.json` | **1** |
| `production-02생산실행.json` | **1** |
| `quality-03품질.json` | **1** |
| `shipment-04제품출하.json` | **1** |
| `app-공통.json` | **2** |
| `mdm-기준정보.json` | **2** |

   고치기 «전»에 확인한다 — `sed -n '2p' <파일> | awk '{match($0,/^ */); print RLENGTH}'`.
   ⚠ 파일 끝 개행도 갈린다(`logistics-01`·`quality-03` 은 개행 없이 `}` 로 끝난다) — `tail -c 1` 로 본다.
3. **고친 뒤** — 검사기를 돌린다.

```
python3 design/schema/generators/openapi/check-structure.py            계약으로 성립하는가
python3 design/schema/generators/openapi/check-public-safe.py          공개돼도 되는가
python3 design/schema/generators/openapi/check-lock-token-source.py    잠금 토큰을 받을 곳이 있는가
python3 design/schema/generators/openapi/check-enum-narrowing.py       값 목록이 좁아졌는가(통지 대상)
python3 design/schema/generators/openapi/check-worker-no.py            귀속 헤더를 받을 자리가 있는가
python3 design/schema/generators/openapi/check-code-group-pointer.py   그룹 포인터가 등록부 안의 이름인가
python3 design/schema/generators/openapi/check-offline-consistency.py  오프라인 표기가 화면 판정과 같은가
python3 design/schema/generators/openapi/check-query-envelope.py       목록·요약 응답이 표준형인가
python3 design/schema/generators/verify-doc-citations.py               요구서의 경로 인용이 실재하는가
```

⚠ **패치 스크립트는 정본이 아니다** — 한 번 돌리고 나면 **JSON 이 사실**이다. 스크립트는 「그때 무엇을 왜 바꿨나」를 남기는 기록으로 저장소에 둔다.

⛔ **그런데 그 스크립트를 두던 자리가 지금은 쓰기가 막혀 있다.** 기존 패치 38개가 있는 `design/raw/process/openapi-patches/` 는 `.claude/settings.json` 의 `deny`(`Write(design/raw/**)`·`Edit(design/raw/**)`)와 `.claude/hooks/protect_readonly.py`(`RAW_DIR`)가 **쓰기를 차단한다.** 그 38개는 훅이 들어오기 전에 놓인 것이다. ⇒ **새 패치 스크립트를 그 폴더에 만들지 않는다** — 작업 런 디렉터리(`.design-runs/<런>/patches/`)에 쓰고 거기서 돌린다. 바로 위 「패치 스크립트는 정본이 아니다 — 돌리고 나면 JSON 이 사실이다」가 이미 못박은 대로 **결과는 같고**, 「무엇을 왜 바꿨나」의 기록은 런 디렉터리에 남는다(2026-08-29 API 재정리 회차가 그렇게 했다 — `.design-runs/api-realign-20260828/patches/` 29개). ⚠ **규약과 훅 중 어느 쪽을 고칠지는 여기서 정하지 않는다 — 별건이다.** 이 문단은 지금 무엇을 해야 하는지만 적는다.

## ⭐ 예시도 계약의 일부다 **[2026-09-01 신설]**

`example` 은 문서 장식이 아니다. **생성 타입에 들어가고, 구현팀이 그것을 근거로 만든다.**
설명이 맞아도 예시가 틀리면 **설명을 안 읽는 사람은 못 잡는다** — 실제로 두 번 오도했다(`omf-mes#191`).

| 상태 | 무엇을 쓰나 |
| --- | --- |
| 값 목록이 **확정됐다** | 그 목록의 **실제 값**을 쓴다 |
| 값 목록이 **아직 없다** | ⛔ `example` 을 **지우고** `x-no-example` 에 **왜 없는지**를 적는다 |
| 인스턴스 식별자·자유 텍스트 | 합성값을 쓴다 — 실 사번·실 LOT 번호는 금지(공개 안전) |

⛔ **자리채움 상수를 남기지 않는다** — `"STANDARD"` · `"값"` 처럼 **아무것도 안 말하는 값**이
가장 위험하다. 틀린 값은 눈에 띄지만 자리채움은 「일단 맞는 것 같은」 모양이라 그대로 구현된다.

```
⛔  "statusCode": { "example": "값" }
⛔  "managementLevelCode": { "example": "STANDARD" }        ← 확정 목록에 없는 값이었다
✅  "managementLevelCode": { "example": "WAREHOUSE" }        ← 확정된 값
✅  "statusCode": { "x-no-example": "값 목록 미확정 — omf-mes#213" }
```

### 검사기가 이 절을 가리킨다

`generators/openapi/check-example-placeholder.py` 가 발견을 낼 때마다 말미에 **이 규약을 안내한다.**
그 검사기가 보는 것은 ① 자리채움 상수 ② 확정 그룹 밖의 값 ③ 설명은 「미확정」이라 적었는데 예시는
값을 단 자기모순이다.

⚠ **검사기가 못 보는 것** — 「예시가 그 필드의 «뜻»과 어긋나는가」는 기계가 다 못 본다.
수입검사를 뜻하는 `IQC` 가 LOT 상태 필드에 들어가 있어도 문자열로는 멀쩡하다(`omf-mes#191`
확인 4곳). **뜻은 사람이 본다.**

⭐ **한 이름이 두 계약에 있으면 둘 다 본다** — `omf-mes#176` 에서 품질 계약의 `LotHold` 를
고쳤는데 **자재창고 계약에도 같은 이름이 있는 것을 못 봤다.** 한 번에 안 잡히는 형태다.
