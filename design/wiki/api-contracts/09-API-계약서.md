### 1-1. 계약 파일 일곱 — 도메인이 아니라 **소유**로 갈린다

| 파일 | 무엇 |
| --- | --- |

| `logistics-01자재창고.json` | 입하 · 재고 · 출고 · 실사 |
| `production-02생산실행.json` | 작업지시 · 작업 세션 · 생산 실적 |
| `quality-03품질.json` | 검사 요청·결과 · 부적합 · 특채 |

## 3. ⭐ 계약을 읽을 때 알아야 하는 것 넷

### 3-1. `x-internal-note` 는 공개되지 않는다 — `description` 은 공개된다

클라이언트 저장소가 이 계약으로 타입을 만들고 **그 생성물을 공개 저장소에 커밋한다.** `description` 은 주석으로 그대로 옮겨진다.

```
python3 design/schema/generators/openapi/check-public-safe.py
```

⛔ **그래서 내부 서술은 `x-internal-note` 에 둔다.** 비공개 문서 경로 · 설계 진행 상태 · 조항 요약이 여기 해당한다.
⭐ **판정은 위 명령이 한다** — 화면 ID(`W-06-02 §4-A`) · 조항 번호(`공유계약 B-1`) · 이슈 번호(`omf-mes#147`)는 **잡지 않는다.** 비공개 문서 경로를 지울 때 이슈 번호로 대체하는 것이 규약이 지정한 처방이다(`check-public-safe.py` 37·47·56행).

### 3-2. 저장 충돌 토큰은 **받을 곳까지가 한 세트**

`If-Match` 를 필수로 받아 놓고 **그 값을 어디서 받는지 선언하지 않으면 구현이 막힌다.** 실제로 19곳이 그랬다.

```
python3 design/schema/generators/openapi/check-lock-token-source.py
```

**토큰은 같은 자원의 상세 조회가 내려주는 `ETag` 응답 헤더**에서 받는다. 본문 필드로는 내리지 않는다 — 화면에 표시하지 않되 전달해야 하기 때문이다.

### 3-3. 「없음」에는 다섯 갈래가 있다

요구서 §3 이 액션에 「없음」이라 적었을 때 **이유가 다르면 대응이 다르다.**

| 갈래 | 뜻 |
| --- | --- |
| **API 불필요** | 엔드포인트가 없는 것이 **정상**이다 |
| **소관 이동** | 다른 화면이 이미 갖고 있다 — 중복 구현을 막는다 |
| **의도적 부재** | 만들지 않기로 **정한** 것이다 |
| **선행 미결** | 규칙 자체가 안 정해져 의미를 정의할 수 없다 |
| **범위 밖** | 이 트랙이 다루지 않기로 했다 |

⛔ **빈칸은 누락이다.** 「없음」이면 이유를 함께 적는다.

### 3-4. 한 칸이 상황에 따라 여러 표를 가리키는 자리가 있다

참조 무결성 제약이 없어 **대응표가 유일한 근거**다.

⚠ **이 대응표를 검사하던 `verify-polymorphic-mapping.py`는 은퇴했다(2026-08-25)** — 물리 모델
소관이 백엔드팀으로 넘어가면서 이 저장소 안에는 그 검사기가 참조할 물리 모델 원본이 없다
(`docs/research/2026-07-23-데이터모델링/` 삭제, `schema/data-model-boundary.md` 참조). 대응표
결손 확인은 백엔드팀 소관 저장소에서 한다.

## 4. 계약을 고치는 방법

| 무엇 | 어떻게 |
| --- | --- |
| **작은 수정** | JSON 을 직접 고친다 |
| **여러 자리를 한 규칙으로** | **패치 스크립트**(`openapi/patch-*.py`) — 같은 것을 여러 번 돌려도 결과가 같아야 한다 |
| ⛔ **생성기** | **다시 만들지 않는다** |

고친 뒤 검사 넷을 돌린다 — 성립 · 공개 안전 · 잠금 토큰 · 값 목록 협착.

⛔ **값 목록이 좁아지면 「이미 만든 것이 틀린다」** — 넓어지는 것과 다르다. 자유 문자열이 값 목록이 되거나 값이 빠지면 **변경 통지 대상**이다.

## 5. ⭐ 사람이 판단한 것

### 5-1. 요구서를 계약과 따로 둔 이유

계약은 **무엇을 주고받나**만 말하고 **왜 그런가**를 말하지 않는다. 둘을 한 파일에 넣으면 계약이 읽히지 않고, 근거를 계약 안에 적으면 **그것이 공개된다.**

> **필드 정의는 계약에만 · 근거는 요구서에만 · 화면 문구는 스펙에만.** 셋이 서로 다른 것을 담으므로 중복이 아니다.

### 5-2. ⚠ 계약이 화면보다 넓은 자리가 있다

**「경로는 있는데 부르는 화면이 없다」**가 05 에서 둘 나왔다(보전 실적 수정 · 비가동 수정). ⛔ **지우지 않았다** — 현장이 잘못 적은 것을 사무가 고치는 길이 필요하고, **그 화면이 인벤토리에 없는 것이 결손일 수 있다.**

### 5-3. ⚠ 판정을 바꾸면 그 판정을 인용한 자리를 센다

05 에서 「계측기 전용 경로를 두지 않는다」로 판정을 바꾸고 **그 이름을 인용한 다섯 곳을 안 고쳤다.** 가리킬 자원이 없는 이름이 계약에 남았고, 적합성 되짚기에서 겨우 잡혔다 — 저장 충돌 토큰 19곳과 **같은 형태**다.

## 6. ⚠ 못 센 것 · 확신이 낮은 것

| 무엇 | 왜 |
| --- | --- |
| **공유계약 조항 ↔ 계약 필드 대조표** | `06-API-요구서.md` §4-1 이 **기준정보 편만** 덮는다. 나머지 여덟 편은 없다 |
| **한 칸이 여러 표를 가리키는 자리의 대응표** | 검사기 은퇴(§3-4) — 백엔드팀 소관 저장소에서 확인 |
| **`M-01-13` 의 계약** | 화면은 있는데 요구서 §3 소절도 계약도 없다 — 진도표가 유일한 구멍으로 잡는다 |
| **목 서버로 화면이 실제로 그려지는가** | 계약이 성립하는 것과 화면이 그려지는 것은 다르다. **한 번도 돌려 보지 않았다** |
