### 5-5. ⚠ `P-04-03` — 「재작업 완료」가 반쪽

⭐ **화면은 선다** — 실적 저장이 주 기능이고 완료는 `W-02-05`(W/O 마감) 소관일 수 있다. → **후속 확인.**

### 5-6. ⚠ `W-04-07` — 진입 목록의 출처가 갈린다

`W-04-07` §5-7 은 「대상 선택(목록 행 클릭)」 뒤에 「부적합 등록」을 두는데, §3-7 의 「조회·필터」 행이 매핑하는 경로는 `GET /quality/nonconformances` — **이미 만들어진 부적합**이다. 부적합을 만드는 화면이 `W-04-07` 하나(§3-6 · §3-7 절 끝)로 확정되면서, **아직 부적합이 없는 반품 LOT 은 이 목록에 뜰 수 없고 아무도 부적합을 만들 수 없는 순환**이 생긴다(`omf-mes#303` 에서 드러남).

⭐ **막힌 것은 아니다** — 대체 경로가 계약에 이미 있다.

```
GET /logistics/goods-receipts   params: receiptTypeCode · warehouseId · statusCode · receiptDateFrom/To · q · page · size
```

`receiptTypeCode=RETURN` + `warehouseId` 로 반품 입고를 목록할 수 있다. ⚠ **다만 「부적합을 아직 안 만든 건만」을 서버에서 거를 축이 없다.**

⛔ **이 건은 `#303` 이 물은 범위 밖이고 답을 만들지 않는다.** 진입 목록의 출처는 `W-04-07` §8 미결에 세운다. **§6 의 착수 판정(「✅ 그릴 수 있다 12장」— `W-04-07` 포함)은 이 절에서 바꾸지 않는다 — 재확인이 필요하다는 사실만 여기 남긴다.**
