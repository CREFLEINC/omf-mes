## §2. 읽는 법

§3이 **화면 액션 20건 전건**을 엔드포인트에 대응시킨다. 엔드포인트가 없는 액션도 **「없음 + 이유」로 한 행을 차지한다** — 빈칸은 누락이다.

**대조를 기계로 한다** — `verify-ui-coverage.py --domain app`이 만든 `openapi/ui-요구목록-app공통승인.md`의 모든 행이 §3 매핑표 **첫 열**에 있어야 하고, `verify-mapping-coverage.py --domain app`이 그것을 검산한다.

**계약이 정본으로 갖는 것 셋**

1. **결재선 선택 규칙**(B-12) — ① 사업부 지정본이 전 사업부 공통본을 이긴다 ② 그러고도 둘 이상이면 상신이 **400 `ROUTE_AMBIGUOUS`**다. **서버가 임의로 하나를 고르지 않는다**
2. **`USER` 외 거부** — `approverTypeCode`가 `ROLE`·`DEPARTMENT`면 **400 `APPROVER_TYPE_NOT_SUPPORTED`**
3. **단계 치환의 낙관적 잠금은 마스터 토큰** — `approval_route_step`에 `version_no`가 없다(B-11)

⚠ **`inProgressCount`를 목록·상세에 함께 내린다** — 결재선을 고쳐도 진행 중인 요청은 **옛 결재선으로 끝나기 때문**이다(J-9). 이 숫자가 없으면 운영자는 소급된다고 믿는다. **스키마에서 `required`다** — 선택 필드로 두면 화면이 기대할 수 없다.

**계약이 정본으로 갖는 것 셋**

1. ⭐ **승인은 자물쇠를 풀 뿐 실행하지 않는다**(J-8) — `:approve`는 상태만 바꾼다. 전기는 대상 화면의 `:post`가 하고, 그 `:post`는 **승인 전이면 400**이다(01 계약 실측)
2. **순차 결재를 서버가 강제한다** — 앞 단계가 전부 승인이 아니면 **400 `NOT_YOUR_TURN`**. 물리 모델에 이 제약이 없으므로 **화면 검증만으로는 API 직접 호출에 뚫린다**
3. **대상은 표시명·화면 ID·열 수 있는지까지 서버가 내려 준다**(A-10 보강) — 프런트가 「유형 → 화면」 표를 갖지 않는다

⚠ **`isMyTurn`·`currentStepNo`를 목록 행에 내린다** — 상단 대기 건수와 「내 결재 대기」 탭이 이 값으로 선다. 화면이 단계 배열을 받아 스스로 계산하면 **서버 규칙과 갈린다**(§5-4의 순차 판정이 서버에 있다). **셋 다 `required`다.**

> ⭐ **화면이 의존한다고 적은 파생 필드는 `required` 여야 한다** — `inProgressCount`·`isMyTurn`·`currentStepNo`·`isCurrent`·`approverIsActive`. 선택 필드로 두면 **문서는 「내려 준다」고 하는데 타입은 「없을 수도 있다」**가 되어 프런트가 방어 코드를 쓰게 된다.

## §5. 미착지가 무엇을 막는가

### 5-1. ⛔ 목록 요약을 만들 수 없다 — **계약이 아니라 모델의 한계다**

`approval_request`에 **수량·금액·품목 컬럼이 0건**이다(실측). 계약이 아무리 잘 써도 **없는 값을 내릴 수는 없다.**

| 무엇이 막히나 | |
| --- | --- |
| 「폐기 품의 12건 · 3,400 EA」 같은 목록 요약 | ⛔ **불가** |
| 대신 무엇을 하나 | **`reason` 첫 줄**이 요약 자리에 온다(A-12 보강) |

⚠ **그래서 상신 화면의 사유 형식 유도가 결정적이다.** 「폐기」 두 글자짜리 요청은 결재함에서 아무 정보가 아니다. 상신 쪽 화면(`W-01-06`·`W-01-11`·`W-01-12`·`W-01-13`)이 자리표시자·예시를 갖는다.

### 5-2. ⛔ 변경 이력을 보일 수 없다 — **#68**

`audit_event`의 `target_type_code` ↔ 테이블 규약이 없어 결재선 변경 이력을 조회할 키를 만들 수 없다. **두 화면 어디서도 주 기능이 아니라 차단은 아니다.**

### 5-3. ⚠ 값 목록 3종이 미정이다

`approval_type_code` · `status_code` · `decision_code`. **전부 공통코드 소관**(`W-06-06`)이고 계약은 값을 강제하지 않는다(`type: string`).

⚠ **`approval_type_code`가 특히 중요하다** — 결재선 선택 키이고, **업무 화면 ↔ 승인 유형 대응**이 정해져야 「이 결재선을 끄면 무엇이 막히나」를 화면이 보일 수 있다(G-12). 지금은 **계약이 그 대응을 갖지 않는다**.

⚠ **아래 ⛔ 문단은 «2026-08-29 시점»의 판정이고 네 축 중 둘에서 뒤집혔다** «(구표기 보존)». **2026-09-04 실측**(`app-공통.json`) —

| 축 | 지금 | 언제·왜 |
| --- | --- | --- |
| `approvalTypeCode` | ⛔ **enum 이 닫혔다 — 8값 → 2026-09-04 로 9값** | 사용자 확정 2026-09-01(`omf-mes#336` · `W-CO-09` §4 · 코드 사전 `CD-APPROVAL-TYPE`). `ApprovalRoute`·`ApprovalRouteCreate`·`ApprovalRequest` 세 스키마가 같은 목록을 갖는다 |
| `decisionCode` | ⛔ **enum 이 닫혔다 — `APPROVED`·`REJECTED` 2값** | `ApprovalStep` |
| `statusCode` | ✅ **열려 있다**(`type: string`) | 아래 문단이 지금도 그대로 걸린다 |
| `ApprovalTarget.screenId` | ✅ **열려 있다** | 동 |

⭐ **값을 «더하는» 것은 협착이 아니다**(⚠ 등급) — 아래 문단이 막는 것은 **자유 문자열을 값 목록으로 좁히는 것**(⛔ 등급)이다. 2026-09-04 의 `PRODUCTION_RESULT_CORRECT` 추가는 앞쪽이라 걸리는 화면이 없다.

~~⛔ **네 값을 계약에서 enum 으로 좁히지 않는다**~~ — `approval_type_code`·`status_code`·`decision_code` 와
`ApprovalTarget.screenId`. 자유 문자열→enum 은 계약 변경 등급표상 ⛔ 이고 `check-enum-narrowing.py` 가
잡으며(기준선 EXIT=0 · 2026-08-29 재현), 이 축의 구현 완료 화면 8장이 한꺼번에 걸린다 —
`W-06-15`(client#31) · `W-CO-09`(#32) · `W-01-02`(#33) · `W-01-06`(#34) · `W-01-11`(#35) ·
`W-01-12`(#36) · `W-01-13`(#38) · `W-03-09`(#123). 값은 `W-06-06` 공통코드가 갖고 계약은
`type: string` 을 유지한다(G-2 — 값이 미확정이면 비활성 + 사유).

⭐ **`approval_type_code` 후보는 상신 경로에서 기계적으로 나온다**(2026-09-04 재실측 · §1-2 전수표) —
기타출고 품의(폐기) · 재고조정 · 신규 P/O · 입하 취소 · 입고 취소 · 출고 취소 · 출하 취소 ·
**긴급 IQC 생략**(`M-01-13` §5-A 가 고정값으로 못박았다) · ⭐ **실적 정정**(`W-02-05` · 2026-09-04 신설) ·
특채(발의 화면 미특정).
⚠ **「한도승인」은 두 뜻이 병존한다** — ① 의심자재 판정 유형(`W-03-09`) ② 긴급 IQC 생략 한도
(`W-01-02`·`M-01-13`). **값을 확정할 때 이 둘을 가른다.**

| 1 | **`:activate`를 두었다** | 기준정보 계약의 마스터에는 `:deactivate`만 있었다. 그러나 **`W-06-15`·`W-06-14` 둘 다 「사용 / 사용 안 함」 토글**을 갖고 목록에 「사용 안 함」 행을 보인다 — 다시 켜는 것이 정상 운용이다. **같은 이유로 `putaway-rules`에도 더했다.** ⚠ **2026-08-29 정정** — 당시에는 「나머지 mdm 마스터에는 두지 않는다 · 그 화면들이 요구하지 않았다」로 닫았으나, 전수로 세어 보니 「사용 중지」만 있고 「다시 사용」이 없는 자원이 **15개**였다. 되돌릴 수단이 없는 것은 화면이 요구하지 않아서가 아니라 **아무도 세지 않아서**였다. 그 15자원에 `:activate` 를 세웠다 |
