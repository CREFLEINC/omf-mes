## 2. ⛔ 패턴을 신설하지 않는다 — **`concession` 이 신설 후보였는데 선례가 있었다**

### 2-1. 후보였던 이유 — 「한도 형」

`quality.concession` 을 **라. 업무 문서 형**에 넣어 보면 **네 곳이 어긋나 보인다.**

| 업무 문서 형 | **`concession`** |
| --- | --- |
| 만들고 → 확정하고 → 끝난다 | ⚠ **승인 후에 계속 소진된다**(`consumed_qty`) |
| 상태가 컬럼에 있다 | ⚠ **「쓸 수 있나」가 3항 논리곱**이다 |
| 확정 후 in-place 수정 금지 | ⚠ **`consumed_qty` 가 계속 갱신된다** |
| 조회 = 기간 필터(L-3) | ⚠ **「지금 유효한 것」이 기본 조회**다 |

```
쓸 수 있나 =  status_code 가 유효  AND  valid_to 가 지나지 않음
              AND  approved_qty − consumed_qty > 0
```

**어긋나는 개수가 02 의 「구간 형」과 같은 4곳이라 신설 후보로 올렸다.**

### 2-2. ⭐⭐ 그런데 **01 트랙이 같은 형태에 이미 판정을 냈다**

**관문 ②(이미 판정이 있는가)를 걸었더니 걸렸다.** 실측:

```
inventory.inventory_reservation (1205)
    reserved_qty  NOT NULL CHECK (> 0)
    released_qty  NOT NULL DEFAULT 0
    consumed_qty  NOT NULL DEFAULT 0
    status_code · version_no
    CONSTRAINT ck_reservation_qty CHECK (released_qty + consumed_qty <= reserved_qty)
```

**`concession` 과 같은 모양이다** — 승인·예약된 양이 있고, 소진되며, `status_code` + `version_no` 를 갖는다.

**01 트랙의 배정**(`01-리소스도출.md:131`):

```
| inventory_reservation | 라 | M-01-08 피킹 | 조회 · 예약/해제 |
```

⭐ **「라. 업무 문서 형」이다.** 소진 축이 있다고 패턴이 갈리지 않는다는 판정이 **이미 서 있었다.**

### 2-3. 그래서 무엇이 달라지나 — **패턴이 아니라 조회 기본값이다**

어긋나 보였던 넷 중 **셋은 계약 표현으로 흡수**된다.

| 어긋남 | 계약이 흡수하는 방법 |
| --- | --- |
| 소진이 계속된다 | **`consumedQty` 를 읽기 전용 필드로** 낸다 — 출고·투입이 올린다(03 이 쓰지 않는다) |
| 3항 논리곱 | ⭐ **서버가 `usable: boolean` 을 파생해 내린다**(**L-2**) — 화면이 세 조건을 계산하지 않는다 |
| in-place 갱신 | `consumed_qty` 는 **03 소관 밖**이다. 03 은 조건만 읽는다(`W-03-09` §4-B) |
| **「지금 유효한 것」이 기본 조회** | ⭐ **`?usableOnly=true`** 를 기본으로 — **구간 형의 `?open=true` 와 같은 형태** |

⚠ **마지막 하나는 남는다** — 「지금 유효한 것을 먼저 본다」는 **구간 형과 같은 성질**이고, 이것만으로 패턴을 가르지는 않는다.

⭐ **소진 축을 가진 테이블은 저장소에 4곳뿐이다**(실측 `grep -nE '(consumed|used|remaining)_qty'`) — `inventory_reservation`(01) · `material_consumption`(02) · **`concession`(03)** · `subcontract_*`(화면 0건). **셋이 이미 서로 다른 패턴에 배정돼 있어** 「소진」이 패턴 축이 아님이 확인된다.

## 3. ⭐⭐ 「사. 구간 형」이 **처음 남의 테이블에 쓰인다** — `trace.lot_hold`

**02 가 신설하면서 형만 판정하고 넘겼다**(`02/01-리소스도출.md:94`):

```
| trace.lot_hold (2101) | 홀드 시작 | 해제 | ⚠ 01 계약 소관 — 형만 빌려온다 |
```

⚠ **그런데 01 은 배정하지 않았다** — 쓰기를 03 으로 미뤘기 때문이다(`01/01-리소스도출.md:140`). **형은 02 가, 경로는 03 이 낸다.**

### 3-1. 실측이 구간 형과 정확히 맞는다

```
trace.lot_hold
    held_at      timestamptz NOT NULL          ← 시작 시각 필수
    released_at  timestamptz                   ← 끝 시각 없을 수 있다
    ck_lot_hold_release  CHECK (released_at IS NULL OR released_at >= held_at)
    ⛔ version_no 없음                          ← 기록 전용
```

**「진행 중」이 상태 컬럼이 아니라 끝 시각의 부재로 판정된다** — 구간 형의 정의 그대로다.

### 3-2. 구간 형이 강제하는 것 넷 — 03 에서 어떻게 서나

| # | 구간 형 규칙 | `lot_hold` 에서 |
| :-: | --- | --- |
| 1 | 열린 것 조회가 **기본** | **`?open=true`** — ⛔ `?status=` 아님 |
| 2 | 닫는 것은 **`:동사`** | ⭐ **`:release`** — ⛔ `PUT released_at` 아님 |
| 3 | 중복은 **409** | ⭐ **전량 보류가 이미 있으면 409** — `W-03-03` §5-5 가 요구한 것과 같다 |
| 4 | 한 부모에 여럿 | ✅ **부분 보류가 여럿 설 수 있다** — `W-03-03` §5-5 |

⭐ **3번이 특히 잘 맞는다.** `W-03-03` §5-5 는 「⛔ 중복 보류를 막는 제약이 없다 — **화면이 진다**」고 물러났는데, **구간 형은 그것을 409 로 계약에 올린다.** 화면이 계산하지 않고 서버가 판정한다(A-9 ⓑ).

⚠ **다만 판정 규칙이 구간 형보다 복잡하다** — `work_session` 은 「열린 것이 있으면 409」 단순이지만, `lot_hold` 는 **전량이면 막고 부분이면 합계를 본다**.

```
기존 전량 보류(hold_qty IS NULL) 미해제 → 409  DUPLICATE_HOLD
부분 보류 합계 + 신규 > 보유 수량        → 409  HOLD_QTY_EXCEEDED
```

→ **`ConflictResponse.code` 에 2값을 더한다**(4단계).

### 3-3. ⛔ `version_no` 가 없다 — 잠금 토큰을 무엇으로 대표하나

`lot_hold` 는 기록 전용이라 낙관적 잠금 대상이 아니다. **`W-03-02` §4-B 가 이미 답했다** — **`lot.version_no` 로 대표한다**.

⭐ **B-8 이 그것을 가능하게 한다** — 보류 등록·해제는 `lot.status_code` 갱신과 **한 트랜잭션**이므로, `lot` 의 토큰이 곧 이 오퍼레이션의 토큰이다.

## 4. ⭐ `lot.status_code` 전이에 **독립 경로를 두지 않는다**

**전이 9건이 어디서 일어나는지 전수로 갈랐다**(`W-03-01` §5-1 · `W-03-02` §5-1).

| 전이 | 라벨 | 무엇의 부수 효과인가 |
| :-: | --- | --- |
| C4 ⊕ → Release | 합격 | **검사 결과 확정** |
| C5 ⊕ → 보류 | 보류 | 동 |
| C6 ⊕ → Hold | 불합격 | 동 |
| C14 ⊕ → PQC 검사 필요 | 합격판정개수 초과 | 동 |
| C7 보류 → Release | 재판정 합격 | **보류 해제**(`:release`) |
| C8 보류 → Hold | 재판정 불합격 | 동 — **도착 상태만 다르다** |
| C9 Release → Hold | 클레임·리콜 | **보류 등록**(사용 중지) — `W-03-02` §5-6 채택안 |
| C10 의심자재등록 → 보류 | 트리거 | **보류 등록** — `W-03-03` |
| C15 PQC → Release | 전수 재검 양품 | ⚠ **귀속 미정** — `W-03-02` §8-3 |

⭐ **셋으로 수렴한다 — 검사 결과 확정 · 보류 등록 · 보류 해제.** `PUT /trace/lots/{id}` 로 상태를 직접 바꾸는 경로는 **만들지 않는다.**

**근거**: ✓설계확정 **결정 10** 「Lot Status = **결과 상태**(상태 이중 보유 없음)」 · 공유계약 **B-8**(트랜잭션 경계).

⚠ **C9 와 C10 은 같은 오퍼레이션이 도착 상태만 다르게 쓰는 것**으로 보인다. **2단계가 버튼을 세어 확정한다** — 한 경로인지 둘인지는 **테이블이 아니라 화면이 정한다**.

## 5. `inspection_result` 는 **라인이 아니라 문서다**

의뢰의 자식이라 라인으로 보이지만 **네 가지가 라인이 아님을 말한다.**

| 라인이라면 | **`inspection_result` 실측** |
| --- | --- |
| 자체 번호가 없다 | ⛔ **`inspection_result_no` `business_no_t` NOT NULL UNIQUE** |
| 자체 상태가 없다 | ⛔ **`status_code` NOT NULL** |
| 잠금 토큰이 없다 | ⛔ **`version_no`** |
| 자식이 없다 | ⛔ **`inspection_measurement` 를 갖는다** |

**게다가 멱등키를 자기가 갖는다** — `idempotency_key varchar(150) NOT NULL UNIQUE`(실측 1856). ⭐ **오프라인 큐가 직접 겨냥하는 리소스라는 뜻이다**(3단계).

⚠ **`uq_inspection_round UNIQUE(inspection_request_id, inspection_round)`** — `work_session` 의 `session_no` 와 같은 형태다. **한 의뢰에 결과가 여럿**이고 `previous_result_id` 로 **재검 사슬**을 잇는다(**B-10** — 정정이 아니라 재검).

## 6. `inspection_measurement` — **부속이되 경로를 갖는다**

**02 의 `work_session_event`·`work_session_worker` 와 같은 자리다.**

| | |
| --- | --- |
| **쓰기** | ⛔ **자체 경로 없음** — 결과 저장에 함께 실린다(한 검사의 측정치는 한 번에 들어온다) |
| **읽기** | ✅ **경로가 필요하다** — `W-03-05` §5-1 이 「**전체 보기는 별도 페이지**」를 요구한다 |

⭐ **volume 이 경로를 만든다** — 실측 근거는 `W-03-05` §5-1 의 층별 자릿수다:

```
의뢰      412건
결과     ~450건
측정치  ~135,000건      ← 목록에 join 하면 412행이 135,000행이 된다
```

**L-1 을 층마다 따로 적용한다** — 「한 화면」이지 「한 표」가 아니다.

⚠ **`version_no` 가 없다**(실측) — 3계층 중 가장 깊은 층이 기록 전용이다. 잠금은 `inspection_result` 로 대표한다.

## 7. `defect_record` — **나. 부여·회수 형**

```
created_at · created_by 만        ⛔ status_code 없음 · version_no 없음
```

**01 의 `inbound_variance`·`lot_relation` 과 같은 형태다** — 만들어지고 갱신되지 않는다.

⚠ **`ck_defect_source`**(`production_result_id` **또는** `inspection_result_id`)가 **원천 2갈래**를 강제한다. 결정 09 의 **5축**과 어긋나는 지점이며 **§8 에서 드러낸다**(00-설계 §8-3·4).

### 8-1. ⭐ 교정 만료 판별을 **05 계약 없이 낸다**

`W-03-05` §5-6 이 「교정 만료 장비로 측정된 8건이 포함돼 있습니다」를 요구한다. 판별에 필요한 것은 **05 소관 테이블**이다.

⛔ **05 계약을 기다리지 않는다.** **L-2**(파생은 서버 계산)를 적용해 **측정치 응답에 서버가 판정한 플래그를 싣는다**:

```
InspectionMeasurement.calibrationExpiredAtMeasurement : boolean
```

⭐ **화면이 두 계약을 조인하지 않는다.** 03 이 05 의 테이블을 **읽어서 판정만** 하고, **경로는 05 가 나중에 낸다.**

⚠ **자동 제외는 하지 않는다** — 정책이 [확인] 대기다(예외 E-9 ①). **분리 조회 파라미터만** 낸다(`?calibrationExpired=only|exclude`).

### 8-2. ⛔ `W-03-09` 의 「부적합 열기」는 **갈 곳이 없다**

`concession.nonconformance_id` 가 **NOT NULL**(실측 2035)인데 **부적합은 04 가 만든다**(`W-04-07`).

**03 계약이 할 수 있는 것**: 특채 응답에 **`nonconformanceNo` 를 함께 내려** 화면이 번호는 보이게 한다. **상세로 가는 경로는 04 트랙**이다.

→ **5단계 적합성에서 「그릴 수 있나」로 묻는다.** `P-02-02`(05 계약 부재)와 같은 형태다.
