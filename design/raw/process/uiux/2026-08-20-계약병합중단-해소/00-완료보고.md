## 무엇

**계약 7벌을 한 문서로 합칠 때 멈추던 「같은 이름 · 다른 형태」 4건을 없앴다**(4 → 0). 그 김에 05설비툴 계약의 **저장 충돌 보호 0건**을 메웠다(갱신 4 · 상태 전이 4).

## 어떻게

### 실측이 먼저였다 — 이슈가 말한 3건이 아니라 4건이었다

구현팀 병합기와 **같은 기준**(설명 · 예시 · 제목을 뺀 형태 비교)으로 계약 7벌을 전수 대조했다.

| 스키마 | 형태 | 구현팀 보고 대비 |
| --- | :-: | --- |
| `ConflictResponse` | **4갈래** | 「두 계열」이라 했으나 뒤 계열 셋이 서로 또 달랐다 |
| `ErrorItem` | **3갈래** | 05설비툴이 축소형을 더해 2 → 3 |
| `ErrorResponse` | **2갈래** | ⛔ **보고에 없던 것** — 05설비툴만 다른 오류 봉투 |
| `LotHold` | 2갈래 | 일치 |

⭐ **구현팀이 적게 센 이유는 병합기가 앞의 둘에서 멈추기 때문**이고, 세는 방식 자체는 정확했다.

### 판단의 근거 — 두 계열은 서로 다른 것을 말하고 있었다

| 축 | 무엇 | 값 | 근거 |
| --- | --- | --- | --- |
| **원인**(`conflictCause`) | 저장 충돌이 **왜** 났나 | 고정 3값 · 전 도메인 공통 | 공유계약 `B-1` |
| **업무 사유**(`code`) | **왜 거부**됐나 | 도메인마다 다름 | 각 화면 스펙 |

두 축은 **직교**하고 겹치는 지점은 「저장 충돌 ↔ 다른 사용자」 하나뿐이다.

### 고친 것 — 다섯 갈래

| # | 무엇 | 어느 계약 |
| :-: | --- | --- |
| 1 | `ConflictResponse` 를 도메인별로 개명 + `conflictCause` 선택 추가 | 생산실행 · 품질 · 제품출하 |
| 2 | `ErrorItem` 에 `uniqueScope` 선택 추가 | 생산실행 · 품질 · 제품출하 |
| 3 | 오류 봉투를 여섯 벌 형태로 교체 | 05설비툴 |
| 4 | `LotHold` 를 모델 착지 정의로 통일 — **빈 값 허용 7칸 회복** | 자재창고 · 품질 |
| 5 | 저장 충돌 보호 신설 — `If-Match` 8곳 · `ETag` 5곳 | 05설비툴 |

**정본 스크립트**: `deliverables/openapi/patch-166-schema-clash.py` (재실행해도 같은 결과)

## 왜 — 택하지 않은 안과 그 이유

### ⛔ 한 형태로 통일하지 않았다

`ConflictResponse` 하나에 `code` 를 전 도메인 공통 필수로 두는 안을 검토했다.

| 얻는 것 | 잃는 것 |
| --- | --- |
| 이름이 하나 | ⛔ **값 목록이 전 도메인 합집합이 된다** — 출하 화면이 품질 전용 값을 받을 수 있는 타입이 된다 |
| | ⛔ **앞 계열 3벌에 `code` 가 새로 필수** — 구현팀이 이미 만든 코드가 틀린다(⛔ 등급) |

**도메인별 값 목록의 정밀도가 타입의 값어치**라고 봤고, 이미 만든 것을 깨지 않는 쪽을 택했다.

### ⛔ 뒤 계열을 앞 계열 형태로 맞추지 않았다

업무 사유를 표현할 자리가 사라진다. `B-1` 이 요구한 원인 축은 앞 계열에만 있고, 업무 사유 축은 뒤 계열에만 있어 **어느 한쪽으로 접으면 반드시 손실이 난다.**

### ⛔ 저장 충돌 보호를 전수 부착하지 않았다

05설비툴 오퍼레이션 35개에 일괄로 달지 않았다. **잠그는 대상과 버전 축이 일치하는 곳**에만 단다 — 갱신 4곳 · 상태 전이 4곳. 신규 생성은 아직 자원이 없어 버전 축이 없다.

### ⚠ 물리 모델에 보전 표가 없는 것을 이유로 물러서지 않았다

고장 · 보전오더 · 보전실적 · 비가동 · 툴사용 표가 물리 모델에 없다(있는 것은 `quality.equipment_calibration` 하나 — 이슈 `#67`). **계약은 화면대로 쓰고 결손은 `#67` 이 들고 있다**(사용자 확정 2026-08-18 — 데이터 모델링은 설계 결정을 앞설 수 없다).

## 함정 — 다음에 또 밟는다

### ⚠ 계약마다 직렬화 형식이 다르다

들여쓰기가 **1칸·2칸으로 갈리고 끝 개행도 다르다.** 형식이 어긋난 채 한 번 돌렸을 때 손대지 않은 자리까지 **28,000줄**이 diff 에 들어왔다. 검토가 불가능해지고, 구현팀이 생성물을 재현 대조하는 절차도 헛돈다.

→ 패치 스크립트에 **왕복 검사**를 세웠다. 7벌이 바이트 동일하게 왕복되는지 **먼저 확인한 뒤에** 고친다.

### ⚠ 내부 주석이 달라도 병합이 멈춘다

병합기가 걷어내는 것은 설명 · 예시 · 제목뿐이라 **`x-internal-note` 만 달라도 「형태가 다르다」로 잡힌다.** 같은 이름을 여러 계약에 둘 때는 주석까지 같게 하거나, 애초에 이름을 가른다. → 공유계약 **`B-28`** 에 등재.

### ⚠ 검사기가 「있어야 할 곳에 없는 것」은 못 본다

`check-lock-token-source.py` 는 **선언된 토큰이 받을 곳을 갖는가**만 본다. 05설비툴처럼 **처음부터 0건**이면 92곳 검사 · 전건 통과로 나온다. **검사기 통과가 결손 없음을 뜻하지 않는다.**
