### 3-1. ⛔ **못 잡는 것을 먼저 적었다**

**만들면서 실측으로 확인했다 — 이 검사기는 13차 건을 못 잡는다.**


⭐ **13차 리뷰에 「이번 건은 걸린다」고 적었던 것이 틀렸다** — 검사기 docstring 과 이 보고서에 그렇게 기록했다.

## 5. ⭐ 13차 이월 「`Progress` 100% 초과」 — 실측 해소

**고정 커밋 `a554d11` 소스를 열었다.**

```ts
clampValue(v, min, max) = Math.min(max, Math.max(min, v))    // 100 에서 잘린다
thresholds?: { upTo: number; tone: ProgressTone }[]          // 구간별 색
```

| 물음 | 답 |
| --- | --- |
| 100% 를 넘겨 그리나 | ⛔ **아니다** |
| 초과를 **구분**할 수 있나 | ✅ **`thresholds` 로 색이 갈린다** |

⭐ **13차 판정 「조합(`c`)」이 절반만 맞았다** — **막대 + 색 구분은 `a`** 이고 **초과 숫자만 `c`** 다. `W-05-02` §7-1 을 갱신했다.

### 7-1. ⭐ L-14 — **「OEE」를 쓰지 않았다** *(리뷰로 근거 정정)*

```
OEE = 시간가동률 × 성능가동률 × 양품률
      05 설비툴    02 생산실행   03 품질     ← 소유가 셋으로 갈린다
```

⛔⛔ **초안은 「이론 C/T 저장처가 없다」를 근거로 들었고 틀렸다** — `routing_operation.standard_cycle_time_sec`(SQL 648)·`standard_yield_rate`(650)·`production_result` 수량 5종(1625~)이 **전부 실재**한다. **A-13 을 안 돌리고 단정했다 — 이 세션 다섯 번째다.**

⭐ **결론은 유지되고 근거가 바뀌었다** — **가르는 것은 「재료가 있는가」가 아니라 「소유가 하나인가」**다. 세 도메인이 각자 분모를 정의하고 각자 예외를 다루므로, **한 화면이 곱하면 틀렸을 때 아무도 책임지지 못한다.** OEE 는 **통합 대시보드(`W-CO-05`)** 가 후보다.

⚠ **L-14 조항도 그렇게 고쳤다** — 「재료가 없어서 못 낸다」로 적지 말라는 경고를 조항에 넣었다.

### 7-2. ⭐ B-19 보완 — **확인하면 되는 경우도 있다**

13차가 B-19 를 세울 때는 **DR-001 의 근거가 틀린 사례**였다. **14차는 반대 결과**다 — `operation_policy` 를 단계별로 확인했더니 **6항목 중 5개가 맞았고 나머지 하나(툴 축)는 필요 없었다.**

→ **결과를 셋으로 나눴다.** 셋째(**안 맞는 것이 필요 없다**)를 안 적으면 **「빠뜨렸다」로 읽힌다.**
