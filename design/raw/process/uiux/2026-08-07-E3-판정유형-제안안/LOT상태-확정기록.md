## 1. 확정 — 상태 4개

**`정상` · `불량` · `검사 대기` · `폐기`**

| 상태 | 뜻 | 쓸 수 있나 |
| --- | --- | :-: |
| **정상** | 쓸 수 있다 | ✅ |
| **불량** | 검사 불합격 | ❌ |
| **검사 대기** | 아직 판정이 없다 | ❌ |
| **폐기** | 폐기 결정됨 | ❌ |

**LOT 종류와 무관한 공통 값이다** — 자재LOT · 생산LOT · 제품LOT 이 같은 목록을 쓴다.

### 1.1 검사 대기 진입 경로 둘

```
생산 완료 · 입하 완료  ──▶  검사 대기        (아직 검사 안 함)
불량 ──▶ 재작업 완료  ──▶  검사 대기        (재검사 필요)
```

### 1.2 ⭐ 「PQC 검사 필요」를 쓰지 않는 이유

**상태 목록이 LOT 종류 공통인데 이름에 검사 종류를 박으면 안 된다.**

| LOT 종류 | 받는 검사 |
| --- | --- |
| 자재LOT | **IQC** |
| 생산LOT | **PQC** |
| 제품LOT | **OQC** |

무슨 검사를 할지는 **LOT 종류와 검사기준이 정한다.** 상태는 「**검사가 필요하다**」만 말한다.

> 구 「PQC 검사 필요」(2026-07-15 신설)와 구 「보류」는 **둘 다 「판정 없음 · 못 쓴다」**라 하나로 합친다. 전수 재검이냐 샘플이냐는 **검사기준이 정하는 것**이지 상태가 아니다.

## 2. ⭐⭐ 상태와 조건을 분리한다

**한도승인도 · 특채도 · 검사 합격품도 최종 상태는 전부 `정상`이다.** 다른 것은 **그렇게 된 과정·조건**이다.

| 어떻게 `정상`이 되었나 | 뜻 |
| --- | --- |
| 검사 합격 | 기준을 통과했다 |
| **한도승인** | 검사 기준에는 못 미치지만 **고객사와 협의해 일시적으로 정상품으로 받기로** 승인됐다 |
| **특채** | 규격을 벗어났으나 **범위를 한정해** 쓰기로 승인됐다 |

⚠ **한도승인품은 정상품이다.** 예외적으로 그렇게 된 것일 뿐 「정상품이 아니다」라고 말할 수 없다.

### 2.1 그래서 정보를 두 갈래로 관리한다

| | 무엇 | 어디에 |
| --- | --- | --- |
| **상태** | 지금 쓸 수 있는가 | **LOT 상태 4값** |
| **조건** | 어떻게 그렇게 됐고 · **어디까지 쓸 수 있는가** | **전용 테이블 + 이력** |

```
quality.concession           특채 — approved_qty · valid_to
                                    allowed_work_order_id / _process_id / _customer_id
app.approval_request         한도승인 — 결재선 · 승인자 · 시각
quality.disposition_decision 폐기 판정 — decision_qty · reason(NOT NULL)
inventory_transaction_line   상태 전이 이력 — from_/to_quality_status_code + 잔량 스냅샷
```

⭐ **조건은 값 한 칸에 담기지 않는다.** 「W/O 3번 · 5공정 · 고객 A · 100개까지 · 8월 말까지」를 상태 코드로 쓸 수 없다.

### 2.2 ⚠ 「정상」이어도 아무 데나 쓸 수 있는 것은 아니다

**출고·출하 판정은 두 단계다.**

| 순서 | 무엇을 보나 |
| :-: | --- |
| ① | 상태가 **`정상`인가** |
| ② | 특채분이면 **`concession` 의 범위 안인가** — 공정·고객·수량·기간 |

## 3. 저장 위치 — 실측

| 축 (결정 10) | 착지처 | 값 |
| --- | --- | --- |
| ① 수명주기 | `trace.lot.status_code` (DEFAULT `'ACTIVE'`) | 활성 / 소진 / **폐번**(#46) |
| ② **품질 판정** | **`inventory.inventory_balance.quality_status_code`** | **정상 / 불량 / 검사 대기 / 폐기** |
| ③ 작업 홀드 | `trace.lot_hold` | — |

**②가 이 확정의 대상이다.** `uq_inventory_balance_dim` 유니크 인덱스가 이 컬럼을 **차원으로 포함**하므로, 같은 LOT 이라도 상태가 다르면 재고 행이 갈린다 — **부분 보류·부분 특채가 자연히 표현된다.**

**변경이력은 이미 있다** — `inventory_transaction_line.from_quality_status_code` → `to_quality_status_code` + 잔량 스냅샷.

## 4. ⛔ 상류 문서 정정 3건

이 확정이 기존 서술 셋과 어긋난다. **전부 상류를 고친다.**

| # | 어긋나는 것 | 어떻게 고치나 |
| :-: | --- | --- |
| **1** | 도식스펙-01 「**한도승인 ≠ 합격품**」 · G/R 「합격품 한정」이 한도승인을 자동 제외 | ⛔ **폐기.** 한도승인품은 정상품이다. G/R 이 걸러야 할 것이 있다면 **상태가 아니라 승인 기록**으로 판정 |
| **2** | 결정 08 「**재고 행에 가용/Hold 상태 축을 두지 않는다**」 | 물리 모델이 반대이고 **하류가 맞다**(부분 보류·분산 LOT 표현). ⚠ 「단일 지점」 원칙은 유지 — `trace.lot` 에 품질 컬럼이 없어 **복제가 아니다** |
| **3** | 결정 10 「**LOT당 현재 1행**」 | `quality_status_code` 가 유니크 차원이라 **LOT당 N행**. 부분 특채(`concession.approved_qty`)를 1행 모델로는 못 담는다 |

**셋 다 `[uiux→docs]`.** 03 도식의 미확정 3박스(한도승인·특채·폐기 별표)도 함께 정리한다 — **폐기만 확정 값으로 남고 둘은 삭제**다.
