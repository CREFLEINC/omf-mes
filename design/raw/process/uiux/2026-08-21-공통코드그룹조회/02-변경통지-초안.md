## 무엇이 바뀌었나

**공통코드 값 목록을 「그룹 이름」으로 부를 수 있게 됐습니다.**

```
GET /mdm/code-values?codeGroupCode=INSPECTION_RESULT_OVERALL_JUDGMENT
```

| | |
| --- | --- |
| `codeGroupCode` | **신설** — 문자열. 그룹 코드와 정확히 일치 |
| `codeGroupId` | **필수 → 선택** — 기존 호출은 **그대로 됩니다** |
| **400** | **신설** — 둘 다 주거나 둘 다 안 주면 400 |

⚠ **등급 ⚠ 인 이유** — 기존 `codeGroupId` 호출은 안 깨집니다. **쓸 수 있는 방법이 하나 늘었을 뿐**입니다.

⛔ **그런데 기존 방법은 애초에 화면이 쓸 수 없는 것이었습니다.** `codeGroupId` 는 채번 값이라 **개발·검증·운영이 서로 다른 정수**를 갖습니다. 하드코딩하면 다른 환경에서 **조용히 빈 목록**이 옵니다 — 오류가 나지 않아 눈에 안 띕니다.

## 코드에 무엇을 해야 하나

### 1. 코드값 조회는 **`codeGroupCode`** 로 바꿉니다

⛔ **`codeGroupId` 정수를 코드에 박지 않습니다.** 이미 박아 두신 자리가 있으면 이름으로 바꿔 주세요.

### 2. 검사 판정은 그룹이 **둘**입니다

| 쓰는 곳 | `codeGroupCode` | 값 |
| --- | --- | --- |
| 종합 판정 `overallJudgmentCode` | `INSPECTION_RESULT_OVERALL_JUDGMENT` | `ACCEPTED` · `REJECTED` · `HELD` |
| 항목 판정 `judgmentCode`(측정치) | `INSPECTION_MEASUREMENT_JUDGMENT` | `ACCEPTED` · `REJECTED` |

⛔ **항목 판정에는 「보류」가 없습니다.** 한 그룹으로 묶어 쓰면 항목 선택칸에 보류가 떠서 **설계와 어긋난 값**을 저장하게 됩니다.

⛔ **측정값이 규격 밖이어도 자동 불합격이 아닙니다** — 표시하고 **사람이 판정**합니다.

### 3. 측정치 데이터 유형도 확정됐습니다 — **값 이름이 곧 칸 이름**입니다

`InspectionItemSpec.dataTypeCode` 는 측정치 그리드의 **입력 종류**와 **저장할 칸**을 정합니다.

| | |
| --- | --- |
| `codeGroupCode` | `INSPECTION_ITEM_SPEC_DATA_TYPE` |
| 값 | `NUMERIC` · `TEXT` · `BOOLEAN` |

```
NUMERIC  →  numericValue     (상하한·단위가 의미를 갖는 유일한 유형)
TEXT     →  textValue
BOOLEAN  →  booleanValue
```

⛔ **세 칸 중 하나만** 채웁니다. ⚠ **셋 다 비어도 됩니다** — 육안 항목은 판정만으로 성립합니다. 판정(`judgmentCode`)은 언제나 필수입니다.

⛔ **값의 모양으로 유형을 추론하지 마세요.** 「상하한·단위가 있으면 수치, 없으면 텍스트」로 가르면 **불리언 항목이 텍스트로 떨어져** 사용자가 `OK`/`NG` 를 `textValue` 에 적게 되고 **자료의 모양이 틀어집니다.**

⚠ **`booleanValue` 와 판정은 다른 축입니다** — 그 칸은 **측정 결과**이고 판정은 그것을 보고 **사람이** 정합니다.

⛔ **모르는 값이 오면 그 항목 입력을 「비활성 + 사유」로** 두세요. 담을 칸을 고를 수 없으니 추측해서 그리지 않습니다.

### 4. ⛔ 예시값이 틀려 있었습니다 — `"IQC"`(수입검사)는 판정이 아닙니다

`overallJudgmentCode` 의 `example` 에 수입검사를 뜻하는 `"IQC"` 가 들어 있었습니다. 그건 검사 **유형**이지 판정 값이 아닙니다. `ACCEPTED` 로 고쳤습니다. **그 값을 참고해 만드신 자리가 있으면 확인해 주세요.**

### 5. 목록이 비면 감추지 말고 **비활성 + 사유**

시드가 아직 안 들어가 조회가 빌 수 있습니다. 그때 필드를 감추면 나중에 화면 구조가 바뀝니다 — **비활성 + 사유 표시**로 두세요.

## ⚠ 아직 이름이 안 정해진 그룹이 있습니다

창고유형 · 관리수준 · Location유형 · 품질구역 · 보관조건 · 상태코드.
