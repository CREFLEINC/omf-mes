## 3. ⛔ 2단계의 「42경로」가 **52** 가 됐다 — 세 갈래

| # | 무엇 | 2단계 | 실제 |
| :-: | --- | :-: | :-: |
| ① | **설비 자체에 쓰기 경로가 없었다** | 0 | **+3** |
| ② | **점검 항목 「부여」 경로** | 0 | **+2** |
| ③ | **캘린더 일자·적용 경로** | 0 | **+3** |
| ④ | 엑셀 올리기 둘 · 정책 해석 하나 · 사용 중지 둘 | 0 | **+5** |
| ⑤ | 계측기 전용 경로를 **뺐다** | 4 | **−4** |

⭐ **①이 가장 무겁고, 1단계가 0단계에 대해 잡은 것과 «같은 형태» 다.**

2단계 §11-4 는 `/mdm/equipments` 를 「기존 자원을 그대로 부른다 — 신설 0」으로 셌다. **있던 것은 선택 목록용 조회 하나뿐**이었고, 설비·설비그룹 마스터 화면은 「설비 추가 · 저장 · 사용 중지」를 요구한다.

> **「있다」와 「내가 쓸 수 있는 형태로 있다」는 다르다.**

⚠ **1단계가 그 교훈을 §1 에 적었는데 2단계가 다시 밟았다.** 「기존 자원」이라 적을 때 **메서드까지 보지 않은 것**이 원인이다.

## 4. ⛔ 판정을 하나 되돌렸다 — 계측기 전용 경로를 두지 않는다

2단계는 `/mdm/gauges` 넷을 두기로 했다. **근거는 11차 계측기 마스터 §3-2 자신이다** — 계측기는 설비의 한 종류이고 유형 코드가 가른다.

```
⛔ /mdm/gauges + /mdm/equipments    한 행 · 한 version_no · 쓰기 두 벌
✅ /mdm/equipments 하나              계측기 화면은 유형으로 «거른다»
```

⭐ **「같은 테이블을 다른 눈으로 본다」는 필터이지 자원이 아니다.** 두 경로에 쓰기를 두면 한 행을 두 계약이 쓰고(B-13 정면) 폐기 처리가 두 벌이 된다.

⚠ **이 판정이 5단계에서 정정 하나를 낳았다** — 계측기 이력이 `gaugeId` 를 받고 있었는데 **가리킬 자원이 사라졌다.** 판정을 바꾸면 **그 판정을 인용한 자리를 세야 한다**(5단계 §3-1).

## 5. ⭐ 파일 올리기 경로를 처음 두었다

2단계 §12 와 3단계 §7 이 「첨부와 같은 자리인지 못 정했다」로 남긴 자리다. **다른 자리로 정했다.**

| | |
| --- | --- |
| **첨부** | 보관되는 파일 — 나중에 다시 본다 |
| **엑셀 올리기** | **읽고 버리는 입력** — 만드는 것은 마스터 행뿐이다 |

⭐ **결과 스키마를 새로 만들지 않았다** — 기존 일괄 처리 결과를 그대로 쓴다. 「부분 실패를 허용하고 거부 건만 사유와 함께 돌려준다」가 이미 같은 뜻이라, 두 벌을 두면 갱신이 두 곳에 필요해진다.

⛔ **툴·예비품에만 두고 설비에는 두지 않았다** — 툴 엑셀 대장은 「엑셀 관리·기간계 미사용」이 확정이고 설비 대장은 **매체가 미검증**이다. **근거가 다르므로 판단이 다르다.**

## 6. ⛔ 값 목록을 좁힐 때 조심한 것

`check-enum-narrowing.py` 가 **새로 만든 스키마까지 ⛔ 로 울었다.** 없던 필드로는 아무도 코드를 만들지 않아 깨질 것이 없다 — 가르는 기준은 **「그 필드가 기준에 있었는가」**다.

⚠ **거짓 경보가 쌓이면 검사기를 무시하게 되고, 그러면 진짜 협착이 지나간다.** 검사기를 고쳤다.
