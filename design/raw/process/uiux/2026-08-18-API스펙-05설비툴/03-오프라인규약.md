## 2. ⛔⛔ 저장 측이 **하나도 없다** — 앞 트랙과 결정적으로 다르다

03 품질은 이렇게 시작했다 —

> 실측 — `quality.inspection_result` : `idempotency_key varchar(150) NOT NULL UNIQUE` · `version_no` … **저장 측이 이미 준비돼 있다.**

**05 는 그 표가 통째로 없다.** 점검 기록 · 고장 기록 · 툴 사용실적 · 비가동 기록 **넷 다 물리 모델에 0건**이다(0단계 §2 실측).

⭐ **그래도 계약이 먼저 요구한다.**

> **물리 데이터 모델은 설계 결정을 앞설 수 없다**(사용자 확정 2026-08-18 · `00-서식.md` v1.1).

| 무엇 | 계약이 요구한다 |
| --- | --- |
| **멱등키** | 네 생성 경로에 `Idempotency-Key` **필수** — 앞 트랙과 같은 파라미터 형태 |
| 저장 충돌 보호 | ⛔ **넷 다 붙이지 않는다**(2단계 §7) — 한 건을 만들고 끝난다 |

📨 **모델 쪽은 작업 통지다** — 「이 넷에 **멱등키**(같은 요청을 여러 번 보내도 결과가 한 번 보낸 것과 같게 만드는 열쇠) 컬럼과 유일 제약이 필요하다」를 6단계에서 `#67` 에 코멘트로 낸다. **기다리지 않는다.**

## 3. ⭐ 화면별 판정 — 넷이 각각 다르다

### 3-1. `M-05-01` 설비 점검 — ⛔ **자기가 만드는 것이 남의 판정 근거다**

```
M-05-01 점검 입력  ──(점검 이력)──▶  P-02-02 작업 전 점검 통제
                                      「주기 내 점검 이력이 있는가」로 차단·경고·통과
```

**오프라인으로 점검하면 서버에 이력이 없고, 통제 화면은 「점검을 안 했다」와 「했는데 아직 안 올라왔다」를 구분할 수 없다.** 통제 수준이 「차단」이면 **점검을 했는데 작업이 막힌다.**

| | 확정 |
| --- | --- |
| 오프라인 입력 | ✅ **허용** — 막으면 종이로 적고 나중에 옮긴다(현행 그대로다) |
| **C-7 등급** | ⓑ **미확정 표식** — 전송 전까지 「점검 완료」로 그리지 않는다 |
| 계약이 할 일 | ⭐ **점검 이력 조회에 「미전송분은 포함되지 않는다」를 계약이 말한다** — 통제 화면이 그것을 근거로 문구를 가른다 |

⚠ **통제 화면(`P-02-02`)은 02 도메인이다** — 계약을 고치지 않는다. **05 가 내는 것은 「미전송이 있을 수 있다」는 사실뿐**이고, 그것을 어떻게 쓸지는 그쪽이 정한다.

### 3-2. `M-05-02` 설비고장 — ⛔ **사람이 기다린다 · 그리고 한 건이 «둘로» 간다**

**첫째 — 미전송이면 설비담당이 오지 않는다.**

| | 확정 |
| --- | --- |
| 오프라인 보고 | ✅ **허용** — **고장이 날 때가 통신이 끊길 때일 수 있다**(REQ-OA-0005) |
| 알림 체크 | ⛔ **자동으로 끄지 않는다** — 끄면 보고자가 **알린 줄 안다.** 켜 두고 **아직 못 갔음을 보인다** |
| **C-7 등급** | ⓑ **미확정 표식** + 「**호출이 전송되지 않았습니다**」 명시 |

**둘째 — ⭐⭐ 본문과 사진이 따로 간다.** 사진 3장이면 수 MB 라 큐가 커진다. 그 화면 §6-2 가 「**본문 먼저, 사진 나중**」으로 정했다.

> ⚠ 그 화면 §9-2 가 남긴 것 — 「**한 건이 부분 전송되는 경우를 계약이 다루지 않는다**」. **여기서 답한다.**

**확정 — 사진에 별도 멱등키를 두지 않는다.**

```
① POST /maintenance/breakdowns              Idempotency-Key 필수   ← 본문
      ↓ 성공하면 breakdownId 가 정해진다
② POST /maintenance/breakdowns/{id}/attachments                    ← 사진 (0~3회)
```

| 왜 | |
| --- | --- |
| **부모가 정해진 뒤에 붙는다** | 사진은 고장 건에 속한다. 부모 없이 떠 있는 사진을 만들지 않는다 |
| **재전송이 단순해진다** | 사진 한 장이 실패해도 **그 장만** 다시 보낸다. 본문을 다시 보내지 않는다 |
| **키를 나누면 짝을 맞춰야 한다** | 사진에 자체 키를 주면 「본문은 갔는데 사진 키가 고아」인 상태를 서버가 청소해야 한다 |

⚠ **2단계 경로 목록이 하나 는다** — `POST /maintenance/breakdowns/{breakdownId}/attachments`. **40 → 41 경로**이고 2단계 §11-3 에 반영했다.

⛔ **그래서 본문이 실패하면 사진은 큐에 남는다** — 화면이 「사진 2장 대기 중」을 보인다. **사진만 먼저 보내는 경로를 두지 않는다.**

### 3-3. `P-05-01` 툴 사용실적 — ⛔ **누계를 보이지 않는다**

누계는 **다른 POP 도 동시에 더하고 있다.** 오프라인에서 캐시 누계 + 내 입력으로 계산해 보이면 **틀린 「사용 가능」이 나온다.**

| | 온라인 | **오프라인** |
| --- | --- | --- |
| 누계 | 값 + 기준 시각 | 값 + **「이후 다른 단말 입력분 미반영」** |
| 저장 후 누계 | 보인다 | ⛔ **보이지 않는다** |
| 사용 가능 | 값 + 진행 표시 | ⛔ **「연결 후 확인」** · 진행 표시를 **그리지 않는다** |

⭐ **계약이 할 일 — 누계를 «응답에» 담고 기준 시각을 함께 낸다.** 화면이 더하지 않는다(2단계 §9).

### 3-4. `P-05-02` 비가동 — **집계를 「내 단말 입력분만」으로 줄인다**

**오프라인 저장 결과 표시 조항(C-7) 등급 ⓐ 즉시 성공** — 실물이 안 움직이고 남의 게이트 근거도 아니다.

| | 온라인 | **오프라인** |
| --- | --- | --- |
| 입력·저장 | 그대로 | 그대로 |
| **「오늘 이 설비」 집계** | 서버 집계 | ⭐ **「내 단말 입력분만」** · 「다른 단말·관리웹 입력분 미반영」 |

---

## 4. ⭐⭐ 넷을 관통하는 규칙 하나

> **여러 단말이 동시에 기여하는 «합계»를 오프라인에서 재계산해 보이지 않는다.**

툴 사용실적 화면(`P-05-01`) 누계 · 비가동 실적 화면(`P-05-02`) 오늘 집계가 같은 규칙이고, 설비 점검 화면(`M-05-01`) 의 「점검 이력이 있는가」도 **같은 형태의 다른 얼굴**이다 — 셋 다 **내 단말이 모르는 남의 기여**가 있다.

⭐ **「산출 불가를 그대로 말한다」 조항(G-15)·「모르는 값을 비워 둔다」 조항(G-9) 와 한 줄기다** — **모르는 값을 그럴듯한 숫자로 그리지 않는다.**

## 5. 계약 표현 — 앞 트랙 그대로

| 무엇 | 표현 |
| --- | --- |
| 멱등키 | `Idempotency-Key` 헤더 **필수**(uuid) — 기존 `IdempotencyKey` 파라미터 재사용 |
| 저장 충돌 | 이 넷은 **안 붙인다**(2단계 §7) |
| ⛔ **오프라인 `202`** | **쓰지 않는다** — 오프라인이면 요청 자체가 일어나지 않아 서버가 `202` 를 보낼 수 없다(2026-08-12 철회) |

⚠ **`202` 를 다시 넣지 않도록 조심한다** — 통지 두 건(`client#86`·`client#74`)에서 이미 「무효」로 정정한 이력이 있다.

## 6. 오프라인에서 **못 하는 것**

| 화면 | 못 하는 것 |
| --- | --- |
| `M-05-01` | 점검 항목 마스터가 바뀐 것을 모른다 — **앱 시작 시 선행 적재**(C-11·C-13) |
| `M-05-02` | 「이 설비에 처리 중인 고장 N건」을 **캐시 시점 기준**으로만 보인다 |
| `P-05-01` | 저장 후 누계·사용 가능(§3-3) |
| `P-05-02` | 「진행 중 비가동이 이미 있다」를 **다른 단말 것까지는** 못 본다 — ⚠ 겹침이 늘 수 있다. **겹침은 원래 막지 않는다**(경고만)이라 성립한다 |

## 7. 남긴 것 — 4단계로

| 무엇 | 왜 |
| --- | --- |
| **첨부 경로의 정확한 모양** | `app.attachment` 의 다형 참조 대상에 **「고장 기록」을 더해야** 한다(A-16 — 계약이 먼저 값을 갖는다) |
| `W-05-13` 엑셀 업로드 | 오프라인 대상이 아니라 여기서 다루지 않는다. **파일 업로드 경로가 전 계약에 0건**인 것은 그대로 남는다 |
| 선행 적재 목록의 크기 | 설비·점검 항목·툴·사유 코드를 **앱 시작 시** 받는다. 실제 건수는 값 목록 확정 뒤에 잰다 |
