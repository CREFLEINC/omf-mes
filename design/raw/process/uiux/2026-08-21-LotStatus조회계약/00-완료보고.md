## 무엇

**Lot Status 현황·변경이력 조회(`W-03-01`)가 계약만으로 완결되게 했다.**

## 어떻게

### ① #175 — 어긋남이 **양방향**이었다

구현팀은 **요약에 셋이 없다**고 짚었다. 맞았다. 그런데 반대로 **목록에만 없는 축**도 있었다.

| | 목록 | 요약 |
| --- | :-: | :-: |
| `lotStatusCode`·`locationId`·`q`·`heldOnly`·`excludeFullyHeld` | ✅ | ⛔ **없었다** |
| `plantId` | ⛔ **없었다** | ✅ |

⇒ 「요약에 셋을 더한다」로 끝나지 않는다. **양쪽을 맞췄다** — 이제 `page`·`size`·`sort` 만 빼면 질의가 같다. 패치가 그것을 **자동으로 검산**한다.

⭐ **왜 같아야 하나** — `L-1`(요약은 필터 전체·목록은 페이지)이 성립하려면 **두 요청이 같은 모집단**을 봐야 한다. 한쪽에만 필터가 있으면 **카드와 목록이 서로 다른 것을 센다.**

### ② #176 ① — 뜻은 확정돼 있었고 **식별자가 없었다**

| | 상태 |
| --- | --- |
| **뜻** | ✅ 확정 — 정상·불량·검사 대기·폐기(회신 E-3 종결 2026-08-07) · 자재·생산·제품(결정 10) |
| **코드 문자열** | ⛔ **어디에도 없었다** |

⭐ **뜻과 식별자는 다른 산출물이다.** `#179` 가 판정에서 겪은 것과 **같은 형태**다.

물리 모델이 부르는 이름이 없어(판정은 수량 세 칸이 있었다) **표기 규약**을 따랐다 — 영문 대문자 SNAKE(시드 선례 `AVAILABLE`·`IN_TRANSIT` · 1차 제안안 §5).

```
정상       NORMAL              자재  MATERIAL
불량       DEFECTIVE           생산  PRODUCTION
검사 대기  INSPECTION_PENDING  제품  PRODUCT
폐기       SCRAPPED            ← 「폐기」의 기존 표기 SCRAP(issueTypeCode)을 따랐다
```

⚠ **`lot.status_code` 와 `lot_hold.status_code` 는 다른 축이다**(§5-3). 이 그룹은 앞의 것이다.

### ③ #176 ② — 정렬을 계약이 **제한**한다

`sort` 를 `enum` 으로 뒀다 — 허용 키 셋(LOT 번호·품목·최근 전이) × 방향, 기본 최근 전이 내림차순.

⚠ **코드 필드에는 `enum` 을 안 넣는데 여기는 넣었다.** 새 파라미터라 **좁힐 기존 값이 없고**, `#176` 의 완료 조건이 「생성 타입만 읽어도 모호하지 않다」를 요구한다.

⛔ **왜 서버가 정렬해야 하나** — 현재 페이지만 다시 정렬하면 **서버 전체를 정렬한 것처럼 보이면서 결과가 틀린다.** 구현팀이 그대로 짚었다.

### ④ #176 ③④ — **화면이 이미 사건별 행으로 그려져 있었다**

Lot Status 현황·변경이력 조회 화면(`W-03-01`) §3 「이력으로 찾기」 모드가 이렇게 그려져 있다.

```
일시           LOT      전이            행위자   사유
08-03 14:02    …0012    → 보류          김품질   수입검사 대기
08-02 11:30    …0007    보류 → (해제)   박품질   —
```

⛔ **보류 「문서」 목록으로는 이 표를 만들 수 없다** — 한 행에 등록과 해제가 함께 있어 **「기간 전에 등록되고 기간 안에 해제된 보류」를 기간으로 못 집는다.** 구현팀이 짚은 그대로다.

⇒ **사건 목록을 신설했다.** ⚠ **새 테이블을 요구하지 않는다** — `trace.lot_hold` 한 행이 `held_by`/`held_at` 와 `released_by`/`released_at` 를 **둘 다** 가지므로 **서버가 한 행을 최대 두 사건으로 편다**(`L-2` — 파생(저장하지 않고 그때그때 계산해 낸다)은 서버가 한다). `heldQty`·`latestTransitionAt` 이 이미 같은 방식이다.

⭐ **행위자 이름을 실었다**(`actorName`) — 화면이 「김품질」을 보여야 하는데 `heldBy` 는 번호뿐이었다. 선례가 있다(`requestedByName`·`issuedByName`).

## 왜

### ⛔ 이름을 `lot-status-events` 가 아니라 **`lot-hold-events`** 로 했다

Lot Status 현황·변경이력 조회 화면(`W-03-01`) §5-1 실측 — **전이 9건 중 2건만 온전히 남고 2건은 반쪽, 5건은 사라진다.** 변경이력 테이블이 물리 모델에 없어서다.

⇒ **「보류 등록·해제」만 낸다는 것을 이름이 말하게 했다.** 전체 전이 이력으로 읽히면 **화면이 거짓을 그린다**(`A-11` — 없는 것을 있는 것처럼 그리지 않는다). 설명문과 내부 주석에도 못박았다.

### ⛔ `lot-holds` 에 해제 쪽 필터를 더하지 않았다

`#176` 은 두 설계를 열어 뒀다(문서 목록 유지 + 필터 명시 / 사건 목록 신설). **사건 목록을 택했으므로 문서 목록에 같은 질의를 또 두지 않는다** — 두 곳에 두면 **어느 것이 정본인지 갈린다.** 대신 `open=false` 가 **「해제된 것만」이 아니라 「전체」**임을 못박았다(구현팀이 모호하다고 짚은 자리다).

### ⛔ 곁가지로 찾은 것 — 예시값이 뜻과 어긋난다

LOT 상태·유형 자리 **6곳**을 고쳤다.

| 자리 | 틀린 예시 | 정정 |
| --- | --- | --- |
| `LotHold.lotStatusCode` · `LotHoldCreate`·`LotHoldRelease.targetLotStatusCode` · `LotQualityStatus.lotStatusCode` | `"IQC"` — 검사 **유형**이다 | `NORMAL` |
| `LotStatusCount.lotTypeCode` | `"IQC"` | `MATERIAL` |
| `LotStatusCount.statusCode` | **`"정상"`** — 한글이다 | `NORMAL` |

⚠ **이것은 이 화면만의 문제가 아니다.** 전수로 훑으니 `example` 이 `"IQC"`·`"STANDARD"` 인 자리가 **74곳**이다. 대부분은 인스턴스 식별자(`routingCode`·`bomCode`…)라 「STANDARD」가 그냥 자리채움이지만, **값 목록이 정해진 자리**에 들어가면 구현팀이 생성 타입에서 그 값을 보고 만든다. `#179` 에서 실제로 그렇게 드러났다.

⇒ ⬜ **후속으로 남긴다** — 이 건의 범위 밖이다.
