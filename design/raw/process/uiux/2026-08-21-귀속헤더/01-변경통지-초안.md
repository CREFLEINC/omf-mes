## 무엇이 바뀌었나

현장 단말(`P-`)·모바일(`M-`) 화면이 부르는 **쓰기 요청 36건**에 요청 헤더 하나가 계약에 선언됐다.

```http
X-Worker-No: 100001
```

값은 **현재 작업자의 사번**이다. ⚠ **인증이 아니라 귀속**이다 — 「이 작업을 누가 한 일로 기록하나」를 정한다. 인증은 지금처럼 단말 토큰이 한다.

⭐ **원래 필수였는데 계약에 선언이 없었다.** 규약은 「현장 단말·모바일의 쓰기 요청에 사번 필수 — 없으면 서버가 거부」로 정해 두었는데 계약이 그 헤더를 선언하지 않아, **보낼 자리가 없는 상태**였다.

⚠ **등급 ⚠ 인 이유** — 요청 본문·경로·질의는 **하나도 안 바뀐다.** 이미 만든 코드는 깨지지 않고, **헤더를 더 싣는 일만 는다.**

## 코드에 무엇을 해야 하나

### 1. 현장 단말·모바일의 **모든 쓰기 요청**에 헤더를 싣는다

`POST`·`PUT`·`PATCH`·`DELETE` 전부다. 읽기(조회·기준정보)에는 **필요 없다.**

**30건은 필수** — 없으면 서버가 거부한다.

### 2. ⚠ **6건만 선택**이다 — 관리웹도 같은 경로를 부르기 때문이다

| 경로 | 메서드 |
| --- | :-: |
| `/app/document-issues` | POST |
| `/inventory/counts/{inventoryCountId}/lines` | PUT |
| `/logistics/goods-issues` | POST |
| `/logistics/goods-receipts` | POST |
| `/logistics/stock-transfers` | POST |
| `/quality/inspection-results` | POST |

- **현장 단말·모바일에서 부를 때는 실어야 한다** — 서버가 다른 방법으로 작업자를 알 길이 없다
- **관리웹에서 부를 때는 싣지 않는다** — 서버가 계정 토큰에서 행위자를 푼다. 관리웹 화면에는 사번 입력 자리가 없다

⛔ **「계약에 선택」이 「안 보내도 된다」가 아니다.** 계약이 선택인 것은 **한 경로를 두 셸이 나눠 쓰기 때문**이고, 현장 단말·모바일에서는 위 여섯도 필수와 같이 다룬다. 서버는 **단말 토큰으로 온 요청에 헤더가 없으면 거부**한다.

### 3. 값의 출처는 「현재 작업자」다 — 매 요청에 싣는다

사번 경량 인증 화면(`P-CO-01`)·기기 등록 화면(`M-CO-01`)이 들고 있는 값이다.

⚠ **서버는 사번 세션을 갖지 않는다.** 한 번 로그인해 두고 서버가 기억하는 구조가 아니라, **단말이 매 쓰기마다 실어 보낸다.**

### 4. ⛔ 교대하면 **즉시** 바꾼다

사번이 남아 있으면 **다음 사람이 그 사번으로 기록된다.** 값이 그럴듯한 숫자라 나중에 아무도 못 잡는다.

- 교대는 **사람이 명시적으로 누른다** — 유휴 시간으로 자동 해제하지 않는다(작업 중 화면을 떠나는 일이 흔하다)
- ⛔ **미전송 큐에 이미 쌓인 요청의 사번은 바꾸지 않는다** — 그 요청을 만든 사람의 기록이다
- 화면은 **현재 작업자를 항상 크게 보인다**(이미 화면 상세 스펙에 있다)

### 5. 형식

| | |
| --- | --- |
| 이름 | `X-Worker-No` |
| 형 | 문자열 |
| 최대 길이 | 50 |

⛔ **사번에 비밀번호·실패 잠금·세션 만료를 붙이지 않는다.** 붙이면 현장에서 로그인을 없애기로 한 설계가 우회로 무너진다 — **귀속을 인증으로 올리지 않는다.** 인증은 단말 토큰이 하고, 사번은 「누구의 기록인가」만 정한다.
