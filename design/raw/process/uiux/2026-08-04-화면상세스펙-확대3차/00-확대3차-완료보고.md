## §1. 긴급 W/O를 만들 수 없다 — ⚠ 등급 정정 (차단 → 조정)

**`P-02-12` §5-2 — 이번 차수에서 가장 무거운 발견이나, 화면 스펙을 막지는 않는다.**

> ⚠ **2026-08-04 정정** — 초안에서 이것을 **차단**으로 판정한 것은 오류였다. 차단 기준은 「**화면의 골격이 바뀐다**」인데, 아래 해석 3안은 **셋 다 화면이 동일하다.** 「데이터가 만들어지지 않으면 보여줄 것이 없다」와 「화면 골격이 걸린다」를 섞어서 판정했다(사용자 지적).
>
> **#76은 그대로 둔다** — 확정↔모델 불일치는 사실이고 데이터 모델 쪽에서 풀어야 한다. 다만 **화면 설계가 대기하지는 않는다.**

**확정**(02-S-D) — 「긴급 W/O 발행(**P/O 비귀속** · 발행자 직접 전개 · 별도 승인 없음)」

**실측**

```
production.work_order
    production_plan_id   bigint NOT NULL  →  planning.production_plan
planning.production_plan
    production_order_id  bigint NOT NULL  →  P/O
    bom_id · routing_id  둘 다 NOT NULL
```

**체인이 전부 `NOT NULL`이라 P/O 없이는 W/O를 만들 수 없다.** `P-02-12`가 보여줄 긴급 W/O가 **존재할 수 없다.**

### 해석 3안

| 안 | 뜻 | 대가 |
| --- | --- | --- |
| **가** | 긴급용 더미 P/O·계획을 자동 생성 | **R07**(「P/O = ERP 발행 · MES 수정 불가」)과 충돌 — 정본 오염 |
| **나** | `production_plan_id`를 nullable로 | 데이터 모델 변경 |
| **다** | MES가 만드는 「긴급 생산계획」 허용 | `production_order_id`가 여전히 NOT NULL이라 P/O가 필요 |

**셋 다 데이터 모델 담당의 판단**이라 화면이 정할 수 없다 → **#76**. 다만 **어느 쪽이 되어도 화면은 바뀌지 않는다**(위 정정 주).

## §2. 나머지 §I 2건 — 우회하며 쓸 수 있는 것

### §I-16. 생산LOT별 BOM 스냅샷 자리가 없다 (`P-02-11`)

**R42** 「W/O 무분할 · **생산LOT만 BOM 스냅샷별 분할**」 · **R43** 「투입 Validation = **해당 LOT BOM 기준**」

```
work_order.operation_settings_snapshot   jsonb   ✅ 있다
trace.lot                                        ⛔ 대응 컬럼 없음
```

**결과** — `P-02-03`의 오투입 판정이 **W/O BOM 기준으로 후퇴**한다. 러닝체인지 후 LOT마다 BOM이 달라도 구분하지 못한다.

**A-11(v0.6 신설)을 적용해 「물러난 수준」을 스펙에 명시**했다.

### §I-17. 선발행 「실물 미귀속」을 수량 0으로 담을 수 없다 (`W-02-04`)

**R26** 「번호 슬롯 예약 · **완료 전 실물 미귀속**」인데 `trace.lot`에 `CHECK (initial_qty > 0)`이 있다.

**결과** — 계획 수량으로 채우고 **상태로 구분**한다. 「폐번」 값은 **#46**이 이미 요청 중이고, **이 화면이 그 근거 화면**이다.

## §5. `P-02-01` 보류(#67)의 파급이 커졌다

**세션을 여는 화면이 3차에 없다.**

| 화면 | 세션 참조 | 결과 |
| --- | --- | --- |
| `P-02-03` 자재 투입 | `work_session_id` **nullable** | ✅ 세션 없이도 기록 |
| **`P-02-10` 작업 중단** | `work_session_id` **NOT NULL** | ⛔ **세션 없으면 진입 불가** |
| `P-02-06` LOT 완료 | 세션 참조 없음 | ✅ 성립(어느 세션인지 안 남을 뿐) |

**B-9(v0.6 신설)가 이 관찰에서 나왔다.**

> #67 코멘트(2026-08-04)에서 파급을 17 → 19화면으로 갱신했는데 **실질 파급은 그보다 크다** — 3차 10장 중 **4장**이 영향을 받고 그중 1장은 못 쓴다. 두 번째 코멘트로 알렸다.
>
> **함께 제안한 것** — `05` S5 태스크가 「2. **W/O 선택**(`P-02-01`) / 3. **점검 기록 확인**(`P-02-02`)」로 **이미 나뉘어 있다.** `P-02-01`에서 점검 부분을 떼면 **W/O 선택 + 세션 개시**만 남아 점검 데이터 없이도 성립한다. 이것이 받아들여지면 **3차 4장이 온전히 돌고** `P-02-02`만 #67 해소를 기다린다.
