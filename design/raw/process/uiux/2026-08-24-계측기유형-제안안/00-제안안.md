# `EQUIPMENT_TYPE` — 계측기 세부유형 값 목록 제안안

> 작성일: 2026-08-24 · 작성 주체: CREFLE OMF 팀 (UI/UX)
> 근거: **DR-011 확정 3-A**(E-3 방식으로 우리가 제안안을 만든다) · 이슈 **`omf-mes#145`**(공통코드 값 목록 미확정) · **`omf-mes#195`**(회신 대기)
> 결정 주체: **팀 리더**
> 상태: ✅ **확정 — 2026-08-24 팀 리더 결정: 제안 3값 그대로**(`CALIPER`·`MICROMETER`·`GAUGE`)

---

## 0. 요약 — 세 줄

1. **계측기 마스터 관리(`W-05-11`)가 `equipmentTypeCode` 값이 하나도 없어 막혀 있다.** 다른 화면과 달리 이 값이 **필드 하나가 아니라 화면 전체를 거르는 조건**이라, 값이 없으면 목록이 항상 빈다(`#195`).
2. **고객 회신을 기다리지 않고 우리가 제안안을 만든다** — `E-3`·`DR-011` 선례와 같은 방식이다. 근거가 있는 값(캘리퍼스·마이크로미터)만 확정 취급하고, 나머지는 **[추정]**으로 표시해 팀 리더 확인을 받는다.
3. **적게 시작하는 것이 의도된 설계다.** 값은 시드 데이터일 뿐 스키마가 아니라서(`mdm.code_value`), 실제 배포 시점에 고객사가 쓰는 계측기 종류가 다르면 **공통코드 관리(`W-06-06`)에서 값만 추가·수정**하면 된다 — 구조 변경이 필요 없다.

---

## 1. 무엇을 제안하는가

`mdm.equipment.equipment_type_code`(공통코드 그룹명 제안 `EQUIPMENT_TYPE` — 컬럼명에서 `_code`를 뺀 대문자 표기, 공유계약 `G-32` 규칙)는 **두 화면이 값 하나로 갈리는 축**이다(`W-05-11` §3-2).

```
mdm.equipment
   ├── equipment_type_code = 계측기 계열   → 웹-계측기-마스터관리 (W-05-11)
   └── equipment_type_code = 그 밖         → 웹-설비·설비그룹-마스터 (W-05-12)
```

이 제안은 **계측기 계열의 세부 유형**(캘리퍼스·마이크로미터 등)만 다룬다. 설비 계열(프레스·컨베이어 등, `W-05-12` 몫)은 범위 밖이다 — 이유는 §5.

계측기 마스터 관리 화면(`W-05-11`) 스펙 §4-A 원문:

> 계측기 유형 — `equipment_type_code` — **이 화면에서는 「계측기」 계열로 고정**(§3-2) · **세부 유형(캘리퍼스·마이크로미터…) 값 목록은 `W-06-06` · G-2**

값을 정하는 주체는 우리(설계)이고, 등록부는 이미 있다(§4). **정할 사람에게 막혀 있는 것이지 구조가 막혀 있는 것이 아니다.**

---

## 2. 실측 — 사용처 세 관문

값·필드를 만들기 전에 사용처를 센다(우리 하네스 §2-2 · `DISPOSAL_SITE` 건에서 세운 관문).

| 관문 | 확인 | 결과 |
| --- | --- | :-: |
| ① 이 값을 넣는 화면이 있나 | `W-05-11` — 목록 필터·등록 시 필수 선택(§4-A `equipment_type_code` 필수 ✅) | ✅ |
| ② 요구·업무 문서가 부르나 | 개념모델 §4 계측기(Instrument) 속성 명시 · `W-05-11` §4-A 원문이 「캘리퍼스·마이크로미터」를 예시로 직접 든다 · `W-CO-03`(알림센터) 목업이 실제 알림 예시로 「CAL-0042 **버니어캘리퍼스**」를 쓴다 | ✅ |
| ③ 담을 마스터·등록 화면이 있나 | `W-06-06` 공통코드 관리 — `W-05-11` §8 미결 7번이 **이미 소관을 그리로 명시**했다 | ✅ |

**셋 다 있다 — 값을 만드는 것이 맞다.**

---

## 3. 제안 — `EQUIPMENT_TYPE`(계측기 계열) 3값

> 표기 규약(선례 준용) — 코드 문자열은 영문 대문자 SNAKE. 화면에는 `code_name`(한국어)만 보이고 코드는 안 보인다.
> **[추정]** 표시 — 근거가 화면 스펙 원문에 직접 없고 업무 상식으로 세운 것. 확정 때 특히 봐 주십시오.

| 코드 | 이름 | 근거 |
| --- | --- | --- |
| `CALIPER` | 캘리퍼스 | `W-05-11` §4-A 원문 예시 · `W-CO-03` 알림센터 목업 "CAL-0042 버니어캘리퍼스" |
| `MICROMETER` | 마이크로미터 | `W-05-11` §4-A 원문 예시 |
| `GAUGE` | 게이지 | **[추정]** — 원문 예시의 「…」이 더 있다는 신호이고, 현장 QC에서 캘리퍼스·마이크로미터와 나란히 가장 흔하게 쓰이는 계열이라 업무 상식으로 더했다. 원문에 직접 근거는 없다 |

⛔ **저울·온도계·경도계 등은 넣지 않았다.** 업계에서 흔하다는 것만으로는 §2 관문 ②(문서가 부르나)를 통과하지 못한다 — 이 저장소 어디에도 언급이 없다. **지어내지 않는다**(#182 선례 — "값도 이름도 지어내지 않았다").

---

## 4. 값이 3개뿐인 것은 결함이 아니다 — 확장 경로가 이미 있다

```
mdm.code_group   (group_code, group_name, description)
mdm.code_value   (code_group_id, code, code_name, display_order,
                  effective_from, effective_to, is_active)
```

**등록부가 이미 있고, 값은 시드 데이터라 스키마가 아니다**(`#64`와 `#145`를 가른 근거와 동일). 실제 배포 시점에 고객사가 쓰는 계측기가 이 3종과 다르면, **`W-06-06` 공통코드 관리에서 값만 추가·비활성화**하면 된다 — 컬럼·계약·화면 어느 것도 다시 바꿀 필요가 없다.

⚠ **그래서 이 제안안은 "정답 목록"이 아니라 "막힌 것을 푸는 최소 시작값"이다.** 확정 후에도 언제든 늘어날 수 있다는 전제로 봐 주십시오.

---

## 5. 범위 밖 — 설비 계열(`W-05-12`)은 다루지 않는다

같은 코드 그룹(`equipment_type_code`)을 `W-05-12`(설비·설비그룹 마스터)도 쓰고, 그쪽 스펙 §8-3도 값 목록 미정 상태다. **다만 막힌 정도가 다르다:**

| | `W-05-11`(계측기) | `W-05-12`(설비) |
| --- | --- | :-: |
| 값의 역할 | 목록 전체를 거르는 **조건** | 표시·편집 **필드 하나** |
| 값이 없으면 | 목록이 **항상 빈다** (`#195`) | 그 칸만 「선택지 준비 중」 — 화면은 정상 동작 |
| 구현팀 조치 | ⛔ 막혀서 `#195` 회신 요청 | ✅ 자리표시로 이미 구현 완료(`#195` 본문) |

`#195`가 실제로 막고 있는 것은 계측기 계열뿐이라, **이 제안안도 그만큼만 다룬다.** 설비 계열 세부값(프레스·컨베이어 등)은 급하지 않으므로 별도 제안으로 미룬다 — `W-05-12` §8-3을 그대로 남겨 둔다.

---

## 6. 확정되면 무엇이 풀리는가

- `#195`의 (a)/(b)/(c) 필터 논쟁 자체가 필요 없어진다 — 값이 있으니 `equipmentTypeCode` 필터가 정상 작동한다.
- `#195`의 남은 질문("계측기 마스터" 메뉴를 지금 세울지 미룰지)도 같이 풀린다 — 화면이 빈 목록이 아니라 정상 목록을 보이므로 메뉴를 바로 세울 수 있다.
- `W-05-11` §4-A `equipment_type_code` 필드가 자리표시에서 실제 선택 목록으로 바뀐다.

## 7. 이 제안의 약점

| # | 무엇 |
| :-: | --- |
| 1 | `GAUGE`는 원문 근거 없이 업무 상식으로 더한 것 — **[추정]** 그대로 확정하지 말고 한 번 더 봐 주십시오 |
| 2 | 3종이 실제 현장 계측기 종류를 다 담지 못할 가능성이 크다 — 다만 §4에 적었듯 **구조적 위험은 아니다**(언제든 추가 가능) |
| 3 | 설비 계열(`W-05-12` 몫)은 범위 밖으로 남겨 뒀다 — 후속 제안이 필요하다 |

## 8. 확정 후 절차 (참고)

1. 팀 리더 확정

3. `#195`에 회신 — 값 목록 확정 반영 + 메뉴 노출 여부(§6과 함께) 확정 통보
