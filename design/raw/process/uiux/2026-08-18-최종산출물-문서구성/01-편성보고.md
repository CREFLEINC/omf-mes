## 2. ⭐⭐ 설계에 없던 것 하나를 더 만들었다 — `verify-counts.py`

설계 §4-1 은 서식을 이렇게 정했다.

> **숫자 + 실측일 + 세는 명령.** 셋이 다 있으면 **낡아도 낡은 것이 보인다.**

⛔ **「보인다」가 사람의 눈에만 걸려 있었다.** 편람 8종이 3주 만에 낡은 것도 「보였는데 아무도 안 봤기」 때문이다.

⭐ **그래서 「보인다」를 기계로 만들었다** — 등록부의 수치를 실물과 대조한다.

```
python3 deliverables/verify-counts.py      등록 22건 전부 실물과 같다
```

⚠ **이 검사기가 못 보는 것을 함께 적었다** — **등록되지 않은 숫자**는 못 잡는다. 그래서 **숫자를 아예 안 박는 것이 여전히 제일 낫고, 이 검사기는 차선**이다.

## 3. ⭐⭐ 색인을 만들자 **커버리지 게이트의 구멍**이 드러났다

진도표를 처음 돌리자 「요구서 §3 이 다루지 않은 화면 **11건**」이 떴다. 그중 아홉이 공통 화면이었다.

**실제로는 요구서가 다뤘다.** 공통 요구서만 매핑 절이 **§2** 였고, 나머지 여덟 편은 **§3** 이었다.

```
요구서 여덟 편        ### 3-N. `화면 ID` …        ← 게이트가 본다
공통 요구서 한 편      ### 2-N. `화면 ID` …        ← 게이트가 «못» 본다
```

⛔ **그래서 공통 10화면이 커버리지 게이트 «밖» 이었다.** 화면 액션 47건이 한 번도 기계 대조를 받은 적이 없다.

⭐ **절을 §3 으로 맞추고 게이트에 등록하자 곧바로 빨개졌다 — 다루지 않은 액션 13건.** 전부 채우고 초록으로 만들었다.

| 무엇 | 전 | 후 |
| --- | :-: | :-: |
| 커버리지 게이트 도메인 | 8 | **9** |
| 요구서 §3 이 다룬 화면 | 106 | **116** |
| 기계 대조를 받는 화면 액션 | — | **+47** |

> ⭐ **서식이 하나만 달라도 두 기계가 동시에 못 본다.** 진도표와 게이트가 같은 소절 인식을 쓰기 때문이고, **그것이 이 색인을 만든 값이다.**

## 4. ⭐ 설계가 「못 셌다」로 남긴 것 하나를 풀었다

설계 §9 는 결정 대장의 **「142행」**을 「세는 기준을 못 찾았다」로 남겼다. §7 구간의 표 행을 세면 197 이 나왔기 때문이다.

⭐ **기준은 문서에 이미 있었다** — §7.2 머리의 검산식.

⛔ **틀린 것은 값이 아니라 「어디까지 세는가」였다.** §7 에는 계열 안내표(§7.1)와 계보 체인표(§7.3)도 있어 함께 세면 부푼다. **`§7.2.N` 소절의 데이터 행만** 세면 142 가 정확히 재현된다.

```
python3 deliverables/count-decisions.py --check    ✅ 문서 머리 표기(142행)와 같습니다
```

⚠ **용어 사전의 「27항목」은 다르다** — 실측 **23**이고, 옛 편람 표기가 낡은 것이었다. 세트 표지를 실측값으로 고쳤다.

## 5. ⛔ 걷어낸 낡은 수치

| 어디 | 무엇이 낡았나 |
| --- | --- |
| 세트 표지(옛 `README.md`) | 화면 **113** · 계약 경로 **78** · 용어 **27항목** · 검산 스크립트 **7종** |
| 통합 정보구조 §1 산문 | 화면 **112건** · 확정 82 · 추정 24 |
| 설계 사양서 상호 참조 | 「화면 113」 |
| 용어 사전 | 「113화면 = 확정 84 · 추정 27」 |
| 기준정보 요구서 | 「화면 113건」 · 「인벤토리 113건」 |

⭐ **고친 방식이 중요하다 — 새 숫자로 바꾸지 않고 «명령» 으로 바꿨다.** 새 숫자를 넣으면 같은 자리가 3주 뒤에 또 낡는다.

## 6. ⛔ 구현 «일정» 은 짜지 않았다

설계 §0-5 가 「구현 계획을 05 계약 뒤에 짠다」로 남겼고 그 조건이 충족됐다. **그런데 계획의 절반은 우리 소관이 아니다.**

| 무엇 | 누가 |
| --- | :-: |
| **작업 분해 · 선행 관계 · 재작업 위험** | ⭐ **우리** — 이미 다 나가 있다 |
| **일정 — 마감 · 주차 · 간트** | ⛔ **사용자 소관**(2026-07-31 지시) |

⭐ **작업 분해와 순서는 이미 개발 손에 있다.** 착수 가능 통지 **106장**이 화면마다 §5 「선행·순서 — 먼저 끝나야 하는 것과 재작업 위험」을 담고 있다. 그것이 곧 구현 순서다 — **여기서 다시 쓰면 이중 기록이 된다.**

⚠ **남은 화면 11장은 순서에 못 들어간다** — 발행 금지 2 · 상류 차단 5 · 계약 결손 1 · **발행 가능해진 3**(06 §6 이 사라져 풀렸다).

## 8. ⚠ 못 센 것 · 확신이 낮은 것

| 무엇 | 왜 |
| --- | --- |
| **낡은 수치가 이 다섯 자리로 끝인가** | 걷어낸 것은 **눈에 띈 것**이다. `verify-counts.py` 는 **등록된 22건만** 본다 — 등록 안 된 숫자는 여전히 안 보인다 |
| **진도표의 「계약」 열이 정확한가** | 요구서 머리에 적힌 계약 파일을 읽는다. **요구서가 다른 계약을 함께 쓰면 머리에 안 적혀 있을 수 있다** |
| **공통 요구서 절 번호를 바꾼 파급** | 외부 인용을 찾아 0건을 확인했으나, **저장소 밖 인용은 볼 수 없다** |
