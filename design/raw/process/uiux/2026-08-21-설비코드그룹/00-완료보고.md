## 어떻게

### ① #185 — **뜻은 정해 놓고 식별자를 안 만들었다**

화면 스펙 `W-05-12` §8 미결 3 에 저희가 이렇게 적어 두었다.

> `status_code` 는 §5-2 에서 **우리가 2값을 정했으므로 그 2값을 등록 요청한다**

**요청하겠다고 적어 놓고 넉 달을 안 했다.** `#176`·`#179` 와 **같은 형태**다 — 뜻은 확정(운용/폐기 · A-14 적용), 식별자가 없음.

⛔ **예시값 `ACTIVE` 가 함정이었다.** 계약 자신이 「사용 여부(`is_active`·`includeInactive`)와 **다른 축**이다」라고 적어 두었는데, 예시가 `ACTIVE` 라 **정확히 그 혼동**을 부른다.

⇒ **`IN_SERVICE`(운용) · `DISPOSED`(폐기).** ⭐ `DISPOSED` 는 이미 있는 액션 이름(`:dispose`)과 짝이 맞는다 — 이름을 둘로 만들지 않는다.

### ② #186 — **범위는 맞았고 착수 이슈가 덜 적었다**

| 근거 | 점검 항목이 |
| --- | :-: |
| 화면 스펙 §4-C·§5-1·§7 | ✅ 있다 |
| 계약 6경로 | ✅ 있다 |
| **요구서 05 §4** | ✅ **「점검 항목 마스터 CRUD — `W-05-12` 가 쓴다」** |
| 착수 이슈(`client#210`) | ⛔ **없다** |

⇒ **범위가 맞다.** 착수 이슈 안의 「점검」 한 번은 **작업 전 점검 «통제 수준»**(정책) 얘기지 점검 항목 마스터가 아니다 — 구현팀이 정확히 갈라 읽었다.

⛔ **우리 착수 이슈가 화면을 덜 적었다.** 시점 기록이라 본문을 고치지 않고 **통지로 바로잡는다.**

### ⭐ 값 이름을 지어내지 않았다 — 새로 정한 것은 하나뿐

```
일상   DAILY        ← 계약 설명 「일상(DAILY) 또는 정기(MONTHLY)」 · 확정 QA #10 · WF05 S2
정기   MONTHLY      ←  같은 자리
보전   MAINTENANCE  ← 새로 정했다
육안   VISUAL       ← 계약의 example 이 이미 VISUAL 이었다
측정값 MEASUREMENT  ← 새로 정했다
```

⚠ **「정기 = MONTHLY」가 어색해도 바꾸지 않았다** — 확정 문서와 계약이 이미 그렇게 부른다. 여기서 갈면 **어휘가 두 벌** 생긴다.

⭐ **보전이 셋째 값인 근거 — 실제로 쓰인다.** `W-05-12` §4-C 가 「점검·**보전** 항목 마스터」 하나로 정의했고, **`W-05-05`(보전지시발행) §4 가 그 마스터를 FK 로 참조**한다 — 「보전 항목이 부여돼 있지 않다 → ⛔ 발행 불가」. 사용처가 실재한다(uiux-design §2-2).

⚠ 점검 **입력** 화면(`M-05-01`)은 앞 둘만 보인다 — 보전 항목은 보전 흐름이 쓴다.

### ⚠ 판정 방식은 **짝 제약**을 몰고 있었다

계약이 「측정값이면 단위·상하한이 함께 필요하다」고 정해 놓고 **「측정값」의 코드값을 안 줬다.** 화면이 그 제약을 걸 수 없어 등록·수정이 **반드시 실패하는 경로**가 된다 — 구현팀이 그대로 짚었다.

## 왜

### ⛔ 같은 «이름»이 다른 «값 집합»을 갖는다 — 그룹을 갈랐다

`inspectionTypeCode` 가 두 도메인에 있는데 **값이 겹치지 않는다.**

| 어디 | 값 | 그룹 |
| --- | --- | --- |
| 품질 검사 | 수입·공정·출하 | `QUALITY_INSPECTION_TYPE` |
| 설비 점검 | 일상·정기·보전 | `EQUIPMENT_INSPECTION_TYPE` |

⛔ **묶으면 설비 점검 선택칸에 「수입검사」가 뜬다.** `B-28`(같은 이름 다른 **형태**)의 **값 집합 판**이라 `G-32` 에 못박았다.

⚠ **품질 쪽은 구현팀이 묻지 않았는데 함께 붙였다** — 안 붙이면 그 화면군을 만들 때 **같은 것을 또 묻는다.**

### ⛔ 계수기가 적게 세고 있었다 — **46 → 50**

계수기가 「`enum` 이 **하나라도** 붙어 있으면 확정」으로 봤다. 그런데 위처럼 **같은 이름이 도메인마다 다른 값 집합**을 갖는 자리가 실재한다. **한 자리에 값 목록을 넣었다고 나머지가 정해진 것이 아니다.**

⭐ **드러난 방식이 좋았다** — 제가 `#176` 에서 `LotHoldEvent.eventTypeCode` 에 값 목록을 넣자 미확정이 **46 → 45 로 «줄었다».** 줄 리가 없는 자리라 계수기를 의심했다.

⇒ **자리마다 세도록 고쳤다.** 옛 46 도 이미 적게 센 값이었다 — **실측 50**.

⭐ **「일부 자리만 값 목록을 갖는 이름」을 따로 알리게 했다** — 지금 **8종**이고, `statusCode` 는 값 목록 없는 자리가 **57**이다.

⚠ **인계대장은 생성물이었다** — 손으로 고치려다 파일 머리의 「손으로 고치지 마라」를 보고 되돌렸다. **설명은 생성기에 넣어** 다음 재생성에도 남게 했다.

### ⛔ `enum` 을 넣지 않았다

좁히면 ⛔ 등급 통지가 되고 이미 만든 코드가 틀린다(G-2·G-6). 다른 코드와 같다.
