## ✅ 확정 (2026-08-13)

> **MES 에서는 품의서를 기안하지 않는 것이 원칙이다.**
> **외부에서 승인 받는 품의서는 MES 에 가져오지 않으며, MES 에서 실제 품의서 승인을 득했는지 관심갖지 않는다. 사용자에게 맡긴다.**
> **그럼 MES 에서는 작업자가 요청하고 승인하는 방식으로 정리한다.**

**함께 확정** — **폐기 계정도 MES 밖이다.** MES 는 「무엇을 몇 개 폐기했다」까지만 기록하고 회계 계정은 ERP 가 전표를 만들 때 정한다.

| 무엇 | 어디에 |
| --- | --- |
| **화면 2장 정정** | `W-01-06` · `W-04-10` — 「품의」 → 「요청」 · **폐기 계정 필드 삭제** |
| ⛔ **클라이언트 ⛔ 통지** | **client #124** — `W-01-06` 이 **구현 중**이라 즉시 발행(PR ④ 전) |
| ⭐ **회신 E-4 종결** | 폐기 계정 항목 — **더 기다릴 것이 없다** |

| **신설** | ⛔ **0** — 승인 4테이블·결재선·결재함이 그대로 선다 |

## 1. 무엇을 결정했는가

**폐기·재고조정 같은 「내부 품의」를 MES 가 기안·결재까지 하는가**입니다.

```
지금 설계   MES 안에서  품의 기안 → 결재 → 승인 확인 → 기타출고
확정        MES 안에서  요청 → 승인 → 기타출고        ← 「품의서」가 아니다
            MES 밖에서  (품의서가 필요하면 사용자가 알아서)
```

## 2. 왜 이 질문이 나왔는가

### 2-1. 「MES 가 품의서를 만든다」는 확정이 **없었습니다**

화면이 품의 작성을 갖게 된 경로를 추적했습니다.

| # | 근거 | 무엇을 확정했나 |
| :-: | --- | --- |
| 1 | **REQ-PR-0028**(고객 원문) | 「제품 폐기 시 **내부 품의 후** 기타 출고로 처리될 수 있어야 함(계정 항목 요청)」 |
| 2 | **D21 확정**(2026-07-01) | 「불량창고 입고 → 판정 → **품의** → 기타 출고」 — **프로세스 서술** |
| 3 | **확정 #9**(2026-07-27) | 「승인주체 = MES 권한 보유 관리자 · 기록/승인 매체 = **관리웹**」 |
| 4 | 화면 설계 | → **「품의 상신」을 MES 안에 넣었다** |

⛔ **3번이 4번을 덮지 않습니다.** 확정 #9 의 범위는 **「03 미확정 3상태(한도승인·특채·폐기)의 승인주체·기록매체」**이고 맥락은 **단말 확정**(어느 프로그램에서 하는가)입니다. **「품의서를 기안한다」는 말이 아닙니다.**

⭐ 그 확정이 나온 실제 장면은 `W-01-01` §5-1 의 **「긴급승인 → 한도승인 · 작업자 요청 → 권한자 승인」**입니다 — **현장 흐름을 막지 않으려 MES 안에 두는 종류**입니다.

### 2-2. 요구 원문이 두 갈래로 읽혔습니다

**REQ-PR-0028** 「제품 폐기 시 내부 품의 **후** 기타 출고로 **처리될 수 있어야 함**」

| 읽기 | |
| :-: | --- |
| (a) | MES 가 **품의서를 만들고 결재까지** 받는다 |
| ⭐ (b) | 품의는 **밖에서** 하고 MES 는 **기타출고를 처리**한다 — **문장의 주어가 「기타 출고 처리」다** |

### 2-3. ⚠ 우리 대장이 이미 경고하고 있었습니다

`deliverables/01-요구사항명세서.md` REQ-PR-0028:

> ⚠ 폐기는 **부분 편입 상태** — **C6 폐기 트랜잭션 신설·재고손익 계정 처리는 미설계** — **「폐기 처리 완비」로 읽지 말 것**

### 2-4. ⛔ 「테이블이 있으니 업무가 우리 것」을 또 했습니다

`app.approval_request`·`approval_step`·`approval_route`·`approval_route_step` **4테이블이 실재**하고 `W-06-15`·`W-CO-09` 화면까지 있어서 **「결재는 MES 것」을 전제로 설계**했습니다.

⚠ **이 저장소가 반복해 온 「테이블이 있으니 경로를 만든다」의 변형**입니다(02 의 `material-losses` · 04 의 `sorting_result`).

## 3. 확정이 무엇을 바꾸는가

### 3-1. 바뀌는 화면 — **둘뿐**

| 화면 | 무엇이 바뀌나 |
| --- | --- |
| **`W-01-06`** 폐기 품의·기타출고 *(01)* | 탭 「품의 발의」 → **「폐기 요청」** · 「품의 상신」 → **「승인 요청」** · **폐기 계정 삭제** · 「재상신」 → 「재요청」 |
| **`W-04-10`** 제품 폐기 품의 *(04)* | 동상 |

⭐ **골격은 그대로입니다** — 요청 → 승인 → 처리 3단과 「승인 완료 후에만 기타출고」 잠금이 **MES 내부 승인 기준으로 그대로 성립**합니다.

### 3-2. 안 바뀌는 것 — **승인 축 전부**

| | |
| --- | --- |
| `W-06-15` 결재선 정의 · `W-CO-09` 결재함 | ✅ **유지** — MES 내부 승인의 결재선이다 |
| `W-03-09` 특채·한도승인 · `W-01-02` 한도승인 · `W-01-12` 재고조정 | ✅ **원래 MES 내부 승인**이라 무관 |
| `app.approval_*` 4테이블 · 공통 승인 계약 | ✅ **유지** — `approval_request` 를 쓰는 **23화면이 안 흔들린다** |

⭐ **`approval_request` 의 뜻이 「품의서」가 아니라 「MES 내부 승인 요청」으로 확정**된 것이 실질입니다.

### 3-3. ⛔ 만들지 않는 것

```
외부 품의서 번호·첨부·링크          ⛔ 가져오지 않는다
외부 결재 완료 여부 확인 게이트      ⛔ 확인하지 않는다 — 사용자에게 맡긴다
폐기 계정 선택                      ⛔ MES 밖 — 화면에서 뺀다
```

### 3-4. ⭐ 폐기 계정을 뺀 근거 — **담을 자리가 애초에 없었다**

```
물리 모델 전체에서 account 컬럼   ⛔ 0건 (실측)
goods_issue 에 계정 컬럼          ⛔ 없다
계정 목록 마스터                  ⛔ 없다
```

⭐ **계정은 회계 축이고 MES 는 물류·품질 축**입니다. 품의서가 밖이면 **계정은 그 품의서에 붙는 항목**입니다.

⚠ **남는 것 하나** — MES 가 ERP 로 폐기 실적을 보낼 때 **계정을 실어 보내야 하는지**는 별개입니다(고르진 않아도 전달은 할 수 있다). → **#66 ERP 송신 항목** 건으로 넘깁니다.
