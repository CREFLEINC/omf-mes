## 1. 무엇을 결정해야 하는가

**설비와 금형·지그를 관리하는 화면 19장을 지금 설계할 것인가, 그리고 그 범위를 어디까지로 할 것인가.**

결정할 항목은 **셋**입니다.

| # | 결정 항목 | 선택지 |
| :-: | --- | --- |
| **1-A** | **19장 설계에 착수하는가** | 착수한다 / 미룬다 |
| **1-B** | **예비품(부품 재고) 출고를 MES가 기록하는가** | 기록한다 / 기록하지 않는다 |
| **1-C** | **계측기(측정 장비) 검교정을 설비 보전과 같은 화면군에서 다루는가** | 같이 다룬다 / 분리한다 |

⚠ **1-A 는 「할 것인가」가 아니라 「지금 할 것인가」입니다.** 하기로 한 것은 이미 확정돼 있습니다(아래 2-1).

## 2. 왜 결정해야 하는가

### 2-1. 「한다」는 이미 확정됐고, 「무엇을」이 확정되지 않았습니다

2026-07-04 현장검증 문답 10번이 이렇게 확정했습니다.

> ① **보전 계획·지시 경량 보유 필요**(공백 ≠ 불요)
> ② 범위 = **점검(Daily/Monthly) + 고장 수집 + 보전 계획·지시·실적**
> 예비품 사용–보전이력 연동은 미포함. **경계는 내부 설계.**

**「경계는 내부 설계」가 이 요청서의 근거입니다.** 확정 기록이 경계를 우리에게 넘겼고, 그 경계가 아직 정해지지 않았습니다.

### 2-2. 지금 19장이 전부 멈춰 있습니다

물리 데이터 모델이 자기 적용 범위를 머리말에 이렇게 선언했습니다.

```
-- Scope: MDM, Production, Inventory, Quality, Traceability, Logistics,
--        Integration, Audit
```

**설비 보전(Maintenance)이 이 목록에 없습니다.** 그래서 2026-08-03 에 이슈 #67 을 발행하고 19장을 동결했습니다.

설비·금형 관련 테이블은 **3개뿐**입니다.

| 실재하는 것 | 무엇 |
| --- | --- |
| `mdm.equipment` | 설비 마스터 |
| `mdm.mold` | 금형 마스터 |
| `quality.equipment_calibration` | 계측기 검교정 |

**없는 것** — 점검 기록 · 고장 기록 · 보전 계획 · 보전 지시 · 보전 실적 · 예비품 마스터 · 설비–예비품 매핑. 검색 결과 **전부 0건**입니다.

### 2-3. ⭐ 그런데 이 이유가 2026-08-10 부로 사라졌습니다

**「데이터 모델은 UI/UX 설계 결정에 맞춰 따라온다」**를 원칙으로 정했습니다(2026-08-10 팀 리더 확정).

그러면 **「모델에 없어서 못 쓴다」는 더 이상 동결 사유가 아닙니다.** 우리가 화면을 설계하면 모델이 그것을 받습니다.

⚠ **그래서 이 요청서가 필요합니다.** 동결을 풀려면 「푼다」는 결정이 있어야 하고, 푸는 김에 **경계도 같이 정해야** 17장을 일관되게 쓸 수 있습니다.

### 2-4. 남은 화면의 76%가 여기 있습니다

### 3-1. 현장에서 쓰는 것 (모바일·POP 4장 + POP 2장)

| 화면 | 무엇을 하는가 | 단말 |

| **모바일-설비점검-입력** (`M-05-01`) | 작업자가 설비를 점검하고 합격·불합격을 입력한다 | 모바일 |
| **모바일-설비고장-현장보고** (`M-05-02`) | 가동 중 고장이 나면 현장에서 즉시 보고한다 | 모바일 |

## 4. 결정 항목별 상세

### 4-A. 19장 설계에 착수하는가

**착수하지 않으면** 화면 설계가 **6장 남기고 멈춥니다.** 그 6장도 각각 별도 결정을 기다리므로, 결정이 늦으면 **설계 트랙 전체가 정지**합니다.

**착수하면** 데이터 모델에 **최소 6개 테이블군**이 새로 필요합니다.

| 필요한 것 | 어느 화면이 요구하는가 |
| --- | --- |
| 설비 점검 기록 | 모바일-설비점검-입력 · POP-작업전점검-이력확인통제 |
| 고장 기록 | 모바일-설비고장-현장보고 · 웹-설비고장-상세처리 |
| 보전 지시 | 웹-보전지시-발행 |
| 보전 실적 | 웹-보전실적-예비품출고등록 · 웹-툴PM실적-등록 |
| 비가동 기록 | POP-비가동실적-입력 · 웹-비가동집계-조회 |
| 툴 사용 누계 | POP-툴사용실적-타발수입력 · 웹-툴보전오더-생성 |

⚠ **이것은 「모델을 이렇게 만들어 달라」가 아닙니다.** 화면을 쓰면서 필요한 항목이 확정되고, 그 결과를 데이터 모델 담당에게 넘깁니다. **순서가 뒤바뀐 것이 원칙 1)의 뜻입니다.**

### 4-B. 예비품 출고를 MES가 기록하는가

**이것이 경계선입니다.**

| 근거 | 무엇을 말하는가 |
| --- | --- |
| 확정 문답 10번 | 「**예비품 사용–보전이력 연동은 미포함**」 |
| 화면 인벤토리 | 웹-보전실적-**예비품출고등록** — 화면 이름에 예비품 출고가 들어 있다 |
| 기준정보 도메인 | **웹-예비품-마스터**(`W-06-08`) 화면 스펙이 **이미 작성돼 있다**(2026-08-03) |

⛔ **셋이 서로 어긋납니다.** 확정 기록은 「미포함」이라 했는데 화면은 둘 다 있고, 그중 하나는 이미 썼습니다.

**세 갈래로 읽을 수 있습니다.**

| 안 | 뜻 | 결과 |
| :-: | --- | --- |
| **가** | 예비품 **마스터만** MES가 갖고, 출고는 기록하지 않는다 | 웹-보전실적 화면에서 예비품 구획을 **뺀다**. 이미 쓴 웹-예비품-마스터는 그대로 |
| **나** | 예비품 **출고까지** MES가 기록한다 | 「연동 미포함」은 **자동 차감을 안 한다는 뜻**으로 읽는다. 사람이 「무엇을 몇 개 썼다」를 손으로 적는다 |
| **다** | 예비품을 **일반 자재와 같은 출고**로 다룬다 | 이미 있는 자재 출고 경로를 쓰고 보전 실적이 그것을 참조한다 |

### 4-C. 계측기 검교정을 설비 보전과 같이 다루는가

**계측기는 설비가 아닙니다.** 생산 설비가 아니라 **검사에 쓰는 측정 장비**입니다.

| 근거 | 내용 |
| --- | --- |
| 이력 | 원래 **품질관리 도메인**에 있었고 2026-07-20 재정의에서 **설비툴관리로 이관**됐다 |
| 데이터 | `quality.equipment_calibration` 이 **품질 스키마에 실재한다** — 이관됐는데 테이블은 품질에 남아 있다 |
| 쓰임 | 검교정 유효 여부가 **검사 실적을 막는 게이트**다 — 수입검사·공정검사·출하검사 세 화면이 이것을 본다 |

**두 갈래입니다.**

| 안 | 뜻 |
| :-: | --- |
| **가** | 설비툴관리에 **그대로 둔다** — 「장비를 관리한다」는 점이 같다 |
| **나** | 품질관리로 **되돌린다** — 테이블이 품질에 있고, 쓰는 쪽이 검사 화면이다 |

## 6. 권고안

### 6-A. 착수한다 — **지금**

**이유 셋입니다.**

1. **확정이 이미 있다** — 문답 10번이 「경량 보유 필요(공백 ≠ 불요)」로 못박았습니다. 우리가 새로 정하는 것이 아니라 **미뤄 둔 것을 실행**하는 것입니다.
2. **동결 사유가 사라졌다** — 「모델에 없다」가 유일한 동결 근거였는데, 원칙 1)이 그것을 뒤집었습니다.
3. **여기가 마지막 큰 덩어리다** — 이것을 미루면 남은 6장을 쓰고 **설계가 끝나 버립니다.** 19장이 미완인 채로 구현에 들어갑니다.

### 6-B. 예비품 — **「다」안**(일반 자재 출고와 같이 다룬다)

**이유 셋입니다.**

1. **확정 문답과 부딪치지 않습니다.** 「예비품 사용–보전이력 **연동** 미포함」은 **자동 차감을 안 한다**는 뜻으로 읽힙니다. 보전 실적이 출고 건을 참조만 하고, 재고를 자동으로 깎지 않으면 그대로 지켜집니다.
2. **이미 있는 것을 씁니다.** 자재 출고 경로(출고 요청 → 출고 → 수불 기록)가 완성돼 있고 API 계약도 있습니다. **예비품 전용 출고를 새로 만들면 같은 일을 두 번 만듭니다.**
3. **웹-예비품-마스터 화면이 살아납니다.** 이미 쓴 화면인데 「가」안이면 등록만 하고 쓰지 않는 마스터가 됩니다.

⚠ **다만 확인할 것이 하나 있습니다** — 예비품이 **일반 재고와 같은 창고 체계**에 있는지입니다. 별도 부품 창고를 쓴다면 창고 마스터에 유형이 하나 늘어납니다. **17장을 쓰면서 확인해 별도 요청서로 올리겠습니다.**

### 6-C. 계측기 — **「가」안**(설비툴관리에 그대로 둔다)

**이유 둘입니다.**

1. **2026-07-20 에 이미 옮기기로 확정했습니다.** 되돌리면 그 확정을 뒤집는 것이고, 뒤집을 만한 새 근거가 없습니다.
2. **사용자가 같습니다.** 계측기 마스터와 검교정 이력을 관리하는 사람은 설비 담당이고, 설비·금형 마스터를 관리하는 사람과 같습니다. **메뉴가 갈리면 한 사람이 두 곳을 오갑니다.**

⚠ **테이블이 품질 스키마에 있는 것은 문제가 아닙니다** — 화면의 메뉴 위치와 테이블의 스키마 소속은 다른 축입니다. 검사 화면들이 검교정 유효 여부를 보는 것도 그대로 유지됩니다.
